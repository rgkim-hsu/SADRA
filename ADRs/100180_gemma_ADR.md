# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 스트림 네이티브 마이크로서비스 아키텍처 채택 (Streaming Microservices Adoption)

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 본 시스템은 농장 환경(스마트팜, 스마트 축사)에서 수집되는 온도, 습도, 생체 신호 등 이질적이고 대용량인 시계열 데이터를 연속적으로 처리해야 합니다. 특히 '전처리', '이상 데이터 분석', '상관 관계 분석' 등 각 모듈이 이전 단계의 결과를 실시간으로 소비하고 다음 결과를 생산하는, 높은 결합도와 낮은 지연 시간이 요구되는 복잡한 데이터 파이프라인 구조를 가지고 있습니다. |
| **결정(Decision)** | 데이터 수집 단계부터 최종 분석 결과 저장까지 전체 프로세스를 **스트림 프로세싱(Stream Processing)** 기반의 **마이크로서비스 아키텍처(MSA)**로 구축합니다. 각 모듈(데이터 로딩, 전처리, 분석 3단계)은 독립적인 서비스로 분리하고, 각 단계 간의 통신은 메시지 브로커(Message Broker)를 통해 비동기적으로 이루어지도록 합니다. |
| **근거(Rationale)** | **1. 실시간성 확보:** 스트림 프로세싱은 대용량 데이터가 발생하는 즉시(Real-time) 분석을 시작할 수 있게 하여, 이상 데이터를 신속하게 감지하는 핵심 요구사항(Anomaly Detection)을 충족합니다. **2. 확장성(Scalability):** 각 모듈이 독립적으로 동작하므로, 트래픽이 몰리는 특정 분석 모듈(예: 상관 관계 분석)만 독립적으로 스케일 아웃(Scale Out)하여 처리량을 극대화할 수 있습니다. **3. 복원력(Resilience):** 한 모듈에 장애가 발생하더라도 전체 시스템이 다운되지 않고, 메시지 큐를 통해 이벤트를 재처리할 수 있어 높은 가용성을 보장합니다. |
| **결과(Consequences)** | **긍정적:** 대규모 데이터 변화에 유연하게 대응하며, 실시간성이 극대화되고, 시스템의 유지보수성이 각 컴포넌트별로 분리되어 높아집니다. **부정적:** 아키텍처가 매우 복잡해지며, 서비스 간의 데이터 흐름(Data Lineage) 추적 및 배포(DevOps) 과정에 전문 인력과 높은 운영 복잡도가 요구됩니다. |
| **트레이드오프(Trade-offs)** | **[복잡성 증가] vs. [실시간성 및 확장성 극대화]:** 시스템의 초기 구축 및 운영 복잡도(Complexity)를 크게 높이는 대신, 스마트팜 환경이라는 특성상 필수적인 최고 수준의 실시간 처리 성능(Performance)과 확장성(Scalability)을 확보할 수 있습니다. |

## ⚠️ 잠재적 위험 분석

### 1. 데이터 무결성 및 노이즈 오염 위험
- **설명:** IoT 환경 특성상 센서의 전송 오류, 배터리 부족으로 인한 간헐적 데이터 누락, 또는 센서 자체의 드리프트(Drift) 현상 등으로 인해 분석 모듈에 오염되거나 손실된 데이터가 유입될 수 있습니다. 이는 후속 분석 모듈의 결과값(이상 감지, 상관관계)의 신뢰성을 근본적으로 떨어뜨립니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:**
    *   **데이터 검증 계층(Data Validation Layer) 도입:** 로딩 직후 유효성 검사(Schema Validation, Range Check)를 수행하는 필터링 계층을 구성합니다.
    *   **이상치 처리 알고리즘 강화:** 통계적 방법(Z-score, IQR) 외에 시계열 분석 기반의 결측치 대체(Imputation) 및 이상치 필터링 기법을 전처리 모듈에 적용합니다.
    *   **데이터 메타데이터 관리:** 모든 데이터 포인트에 수집된 시간, 센서 ID, 데이터 처리 단계를 기록하여 출처를 추적할 수 있도록 합니다.

### 2. 보안 위협 및 데이터 유출 위험
- **설명:** 시스템이 물리적 환경(농장, 축사)에 직접 연결되는 IoT 기반 시스템이므로, 통신 프로토콜 스니핑, 인증되지 않은 기기(Spoofing)의 데이터 주입, 또는 서버 해킹을 통한 생체/농장 데이터의 민감한 유출 위험이 존재합니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:**
    *   **제로 트러스트 아키텍처(Zero Trust):** 모든 기기, 사용자, 통신 구간을 신뢰하지 않는다는 전제로 모든 접근에 대해 인증과 권한 검사를 수행합니다.
    *   **암호화 강화:** 데이터 전송(TLS/SSL) 및 저장(AES-256) 단계 모두에서 종단 간(End-to-End) 암호화를 필수적으로 적용합니다.
    *   **OT/IT 네트워크 분리:** 운영 기술(OT) 네트워크와 정보 기술(IT) 네트워크를 물리적 또는 논리적으로 분리하고, 데이터 게이트웨이에서 통제된 트래픽만 허용합니다.

### 3. 모듈 간 비동기 데이터 흐름 관리 위험
- **설명:** ADR에 따라 스트림 기반 마이크로서비스로 설계될 경우, 특정 분석 모듈(예: 전처리)이 과부하되거나 다운되었을 때, 후속 모듈(이상 데이터 분석)이 처리해야 할 메시지 브로커의 부하가 증가하거나, 상태 관리(State Management)가 복잡해져 분석의 일관성(Consistency)이 깨질 위험이 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:**
    *   **멱등성(Idempotency) 설계:** 모든 모듈의 데이터 처리 로직은 동일한 입력 데이터에 대해 여러 번 실행해도 결과가 변하지 않도록 설계해야 합니다. (재처리 시 중복 계산 방지)
    *   **Circuit Breaker Pattern 구현:** 특정 모듈의 장애 발생 시, 이를 감지하고 자동으로 요청을 차단하여(Fail-fast) 후속 모듈의 연쇄 장애를 방지합니다.
    *   **Dead Letter Queue (DLQ) 사용:** 처리 실패한 메시지는 메인 스트림에서 분리하여 별도의 큐에 보관하고, 운영자가 수동으로 재분석 및 원인을 파악할 수 있게 합니다.

### 4. 상호운용성(Interoperability) 표준 미준수 위험
- **설명:** 시스템은 스마트팜의 다양한 제조사(Camera, Sensor, Actuator)의 이질적인 기기 데이터를 로딩해야 합니다. 이 기기들이 표준화된 API나 프로토콜(예: Matter, oneM2M, ISO/IEC 30141)을 따르지 않을 경우, 데이터 로딩 및 전처리 단계에서 데이터를 연계하거나 통일된 방식으로 처리하는 데 심각한 제약이 발생합니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:**
    *   **게이트웨이 표준화 계층 구축:** 모든 이종 기기는 표준화된 게이트웨이 역할을 수행하는 중간 장치를 거치도록 강제하고, 이 게이트웨이에서 데이터 형식을 통일(Normalization)하는 게이트웨이 API 레이어를 구축합니다.
    *   **표준 프로토콜 강제 적용:** 모든 데이터 전송은 MQTT, CoAP 등의 경량 프로토콜을 사용하며, 관련 산업 표준(TTA, oneM2M) 준수 여부를 필수 요구사항으로 설정합니다.

### 5. 모델 드리프트 및 예측 정확도 저하 위험
- **설명:** 생육 정보 분석(Prediction) 및 상관 관계 분석은 머신러닝 모델에 의존합니다. 농장 환경이나 작물의 생육 단계가 변화함에 따라 데이터의 패턴 자체가 변화(Model Drift)하게 되며, 이 경우 모델의 예측 정확도가 시간이 지남에 따라 급격하게 저하되어 시스템의 핵심 가치가 상실됩니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:**
    *   **MLOps 파이프라인 구축:** 모델의 성능을 지속적으로 모니터링(Monitoring)하고, 성능 저하가 감지될 경우 자동으로 재학습(Retraining)을 트리거하는 MLOps 파이프라인을 구축합니다.
    *   **지식 그래프(Knowledge Graph) 활용:** 단순한 통계적 상관관계 분석을 넘어, 작물 생육 주기, 환경 조건, 품종 특성 등 전문가의 지식을 그래프 형태로 모델에 주입하여 모델의 해석 가능성(Interpretability)과 신뢰도를 높입니다.
