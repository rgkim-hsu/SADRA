📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 멀티 인터페이스 기반 IoT 디바이스 온보딩 및 연결 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                   |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **상황(Context)**        | 시스템은 모바일 앱을 통해 IoT 디바이스를 탐색하고 연결하는 흐름을 제공한다. 사용자는 언어 설정 후 Bluetooth, Wi-Fi, Barcode/Data Matrix 스캔을 통해 디바이스를 탐색하고, 서비스 리스트를 확인한 뒤 최종적으로 디바이스와 연결(WebView 포함)을 수행한다. 핵심 과제는 “다양한 방식으로 IoT 디바이스를 쉽고 안정적으로 연결하는 사용자 친화적 온보딩 프로세스 구축”이다. |
| **결정(Decision)**       | Bluetooth, Wi-Fi, Barcode(Data Matrix) 기반의 멀티 탐색 방식을 지원하고, 서비스 리스트를 통해 디바이스 선택 후 연결하는 단계적 온보딩 아키텍처를 채택한다.                                                                                                                            |
| **근거(Rationale)**      | IoT 환경에서는 다양한 통신 방식이 혼재되어 있으므로 단일 방식만으로는 연결성이 제한된다. 멀티 인터페이스 접근은 사용자 환경에 따라 유연한 연결을 가능하게 하며, QR/Barcode 스캔은 사용자 편의성을 높인다.                                                                                                            |
| **결과(Consequences)**   | **긍정적:** 높은 연결 성공률, 사용자 편의성 향상, 다양한 디바이스 지원 가능**부정적:** UI/UX 복잡성 증가, 구현 난이도 상승                                                                                                                                                       |
| **트레이드오프(Trade-offs)** | 연결 유연성과 확장성을 확보하는 대신, 시스템 복잡성과 유지보수 부담이 증가한다.                                                                                                                                                                                        |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. 연결 실패 및 사용자 혼란

* **설명:** 다양한 연결 방식으로 인해 사용자가 어떤 방식을 선택해야 할지 혼란 발생

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 자동 추천 연결 방식, UX 가이드 제공

### 2. Bluetooth/Wi-Fi 간섭 문제

* **설명:** 주변 환경에 따라 신호 간섭으로 연결 불안정 발생

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 재시도 로직, 신호 강도 기반 필터링

### 3. QR/Barcode 인식 오류

* **설명:** Data Matrix 또는 Barcode 스캔 실패 시 연결 지연

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 인식 정확도 개선, 수동 입력 옵션 제공

### 4. 보안 취약점

* **설명:** 인증되지 않은 디바이스 연결 또는 중간자 공격 가능성

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 디바이스 인증, 암호화 통신(TLS), 보안 토큰 사용

### 5. 플랫폼 호환성 문제

* **설명:** 다양한 모바일 OS 및 디바이스 환경에서 동작 불일치

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 크로스 플랫폼 테스트, 표준 API 사용

### 6. 서비스 리스트 불일치

* **설명:** 실제 디바이스와 서비스 리스트 정보가 다를 경우 연결 실패

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 동기화 검증, 실시간 서비스 조회

### 7. 네트워크 의존성

* **설명:** Wi-Fi 기반 연결 시 네트워크 상태에 따라 성능 저하

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 오프라인 연결 옵션(Bluetooth), 네트워크 상태 감지 및 대응
