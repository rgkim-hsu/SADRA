## 📋 ADR (Architecture Decision Record)

### ADR-001: [프로세스 중심의 상태 관리 아키텍처 도입]

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 S210(알반기)부터 S250(출하)까지의 순차적인 공정(S210~S250)을 수행해야 합니다. 각 공정은 목재 분말 공급, 젤리 투입 등 물리적인 투입과 공급 과정을 포함하며, 이는 실시간 제어가 필요한 제조/가공 라인입니다. 표준 문서에 따르면 스마트팜과 같은 IoT 시스템은 상호 운용성과 실시간 데이터 처리가 필수적입니다. |
| **결정(Decision)** | 아키텍처의 핵심은 순차적인 공정 흐름을 관리할 수 있는 **상태 관리(State Machine) 기반의 마이크로서비스 구조**를 채택합니다. 각 공정 단계 (S210~S250) 는 상태 (State) 로 정의되며, 상태 전이를 트리거하여 제어합니다. |
| **근거(Rationale)** | 1. **정합성 (Consistency):** 물리적 공정 (S210->S250) 은 순차적이고 비가역적일 수 있으므로 상태 머신으로 관리하면 데이터 무결성이 보장됩니다.<br>2. **확장성:** TTA 표준 및 oneM2M 요구사항에 따라, 새 공정 추가 시 상태 모델만 수정하면 됩니다.<br>3. **실시간 제어:** IoT 센서 데이터를 기반으로 공정이 멈췄을 때 (예: 톱밥 공급 단절) 즉시 감지하여 상태를 'Error'로 전환할 수 있습니다. |
| **결과(Consequences)** | **긍정:** 시스템 가시성이 향상되어 공정 단계를 추적하기 쉽습니다. **부정:** 상태 전이 로직이 복잡해져서 로깅과 디버깅 비용이 발생할 수 있습니다. |
| **트레이드오프(Trade-offs)** | **장점:** 유연한 공정 변경.<br>**단점:** 초기 설계를 위한 설계 비용 증가 및 상태 관리 라이브러리의 학습 곡선. |

## ⚠️ 잠재적 위험 분석

### 1. [물리적 공정 장애로 인한 전체 시스템 중단]
- **설명:** S230(톱밥 공급) 과 같은 하류 공정이나 S220(젤리 투입) 에서 장비 고장이나 공급 차단이 발생하면, 상위 공정의 결과물이 버려지거나 공정 라인이 정지될 수 있습니다. 특히 IoT 기기 (TTA 표준 적용) 의 센서가 데이터를 전송하지 않으면 상태 관리 시스템이 오류를 인지하지 못해 위험합니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** **가용성 (Availability) 패턴** 적용. 주요 센서에 백업 센서를 설치하고, MQTT 브로커 장애 시 로컬 에지 서버에서 데이터 캐싱 및 중복 저장 (S230 단계) 을 하여 네트워크 장애 시에도 로컬 상태 관리가 가능하도록 설계합니다.

### 2. [이종 장비 간 상호 운용성 부족]
- **설명:** 스마트팜 표준 (ISO/IEC 30141 등) 에 따라 다양한 디바이스가 사용될 수 있지만, 공정 단계마다 제조사별 프로토콜 (예: S210 은 Proprietary, S230 은 Zigbee 등) 이 다를 경우 통신 실패가 발생합니다. 특히 S210~S250 의 연속성을 유지하려면 데이터 포맷의 변환이 필요합니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** **API 게이트웨이 (API Gateway) 와 표준화 계층** 도입. 모든 하단 장비 데이터를 표준화한 JSON 또는 CoAP 포맷으로 변환하여 전송합니다. oneM2M 아키텍처를 참고하여 공통 인터페이스 명세를 적용합니다.

### 3. [실시간 데이터 지연에 의한 공정 오류]
- **설명:** S230(공급 및 교체) 과 같은 물리적인 피드백 루프가 느려져, 예를 들어 공급이 멈췄는데도 시스템이 "정상"으로 인식하여 다음 공정 (S240) 으로 넘어갈 수 있습니다. 이는 품질 불량 (불량품 출하 S250) 으로 이어집니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** **에지 컴퓨팅 (Edge Computing)** 적용. 모든 공정 데이터 처리와 상태 전이 판단을 클라우드가 아닌 로컬 에지 서버에서 수행하여 지연 시간을 최소화합니다. S240(절식 공정) 이 끝날 때까지 S210~S230 이 정상인지 실시간으로 검증합니다.

### 4. [보안 정책 위반으로 인한 데이터 유출]
- **설명:** IoT 기기 (TTA 표준) 가 보안 인증을 받지 않거나 암호화되지 않은 통신 (예: 평문 MQTT) 을 사용하면서, S210~S250 의 공정 데이터 (제품 정보, 생산량 등) 가 유출됩니다. 특히 S250(출하) 전에는 제품 정보가 기밀이어야 합니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** **TLS 1.3 및 mutual TLS (mTLS)** 인증 적용. 모든 트래픽에 암호화 통신을 적용하고, ISO/IEC 27030(보안 가이드라인) 에 따라 기기 인증 절차를强制执行합니다. 특히 S250 단계에서의 데이터는 암호화하여 출하합니다.

### 5. [물리적 환경 변화에 대한 시스템 적응 실패]
- **설명:** 공정 흐름 (S210-S250) 은 제어室内的 환경이 고정되어 있지만, 외부 온도나 습도 변화 (스마트팜 환경) 에 따라 S220(젤리)이나 S230(톱밥) 의 물성치가 변하여 예상과 다른 결과가 날 수 있습니다. 시스템이 이 변수를 처리하지 못하면 오류가 발생합니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
