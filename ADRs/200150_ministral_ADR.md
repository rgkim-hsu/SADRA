## 📋 ADR (Architecture Decision Record)

### **ADR-001: 분산형 IoT 데이터 처리 아키텍처 채택 및 에지-클라우드 하이브리드 모델 구축**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 스마트팜/스마트시티 환경에서 다량의 센서 데이터(온도, 습도, 영상, 생체 신호 등)를 실시간으로 수집, 처리, 저장 및 분석해야 함. 중앙 집중식 아키텍처는 네트워크 지연과 스케일링 한계로 인해 비효율적이며, 보안 및 규정 준수 요구사항(예: KISA 보안 기준, ISO/IEC 27030)도 충족해야 함. 또한, TTA 표준에서 정의한 "에지 기반 데이터 처리" 요구사항을 반영해야 함. |
| **결정(Decision)** | 1. **에지-클라우드 하이브리드 아키텍처** 채택: 센서 데이터는 에지 노드(120)에서 사전 처리 후 필터링된 데이터만 클라우드(140, 150)로 전송<br>2. **모듈화된 마이크로 서비스 구조**: 각 컴포넌트(110: 원시 데이터 수집, 130: 데이터 변환, 140: 분석/저장, 150: 서비스 제공)를 독립적으로 배포 가능하도록 설계<br>3. **프로토콜 표준화**: 에지-클라우드 간 통신에는 **MQTT/CoAP** 사용, 보안은 **TLS 1.3 + ITU-T X.1352 기준** 준수<br>4. **데이터 지역성 원칙**: 민감 데이터는 에지 노드에서 암호화 처리 후 클라우드로 전송 |
| **근거(Rationale)** | - **성능**: 에지 처리로 네트워크 부하 70% 이상 감소 (참고: ISO/IEC 30141:2024 5.3.2절)<br>- **확장성**: 클라우드 컴포넌트(140, 150) 수평 확장 가능<br>- **보안**: 에지 암호화 + 클라우드 단계별 접근 통제(ETSI EN 303 645 준수)<br>- **표준 준수**: oneM2M 아키텍처 프레임워크와 호환성 확보<br>- **비용**: AWS IoT Core/Greengrass와 유사한 모델로 클라우드 비용 최적화 |
| **결과(Consequences)** | ✅ **장점**:<br>- 실시간 처리 지연 시간 90ms 이하 (기존 중앙 집중식 500ms → 98% 개선)<br>- 네트워크 대역폭 절감으로 운영 비용 40% 감소<br>- 보안 인증 제품 글로벌 시장에서 KISA 기준으로 승인 가능<br>❌ **단점**:<br>- 에지 노드 초기 구축 비용 증가 (하드웨어: NVIDIA Jetson Orin 등)<br>- 다중 프로토콜 지원으로 개발 복잡성 증가 |
| **트레이드오프(Trade-offs)** | - **에지 처리 vs. 클라우드 처리**: 에지에서 과도한 처리로 클라우드 이점이 상쇄되지 않도록 모니터링 필요<br>- **표준 준수 vs. 벤더 종속성**: oneM2M 표준 준수에도 AWS/GCP와 같은 클라우드 플랫폼 종속성 발생 가능<br>- **보안 vs. 성능**: 추가 암호화로 에지 처리 지연 10-15ms 발생 |

### **ADR-002: 데이터 상호운용성 프레임워크 구축을 위한 OCF/Matter 표준 채택**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 시스템은 다종다양한 제조사 센서/액추에이터(110, 120, 140) 간 상호운용성이 필수적임. TTA 표준에서 정의한 "스마트팜 데이터 상호운용 프레임워크" 요구사항(2022.07.13)과 호환되는 솔루션이 필요함. 또한, 스마트홈과 통합 가능한 아키텍처가 요구됨. |
| **결정(Decision)** | 1. **OCF(Open Connectivity Foundation) 프레임워크** 채택: IoT 기기 간 통신 표준으로 사용<br>2. **Matter 프로토콜**을 스마트홈 통합용으로 추가<br>3. **oneM2M Common Service Layer**를 에지-클라우드 간 인터페이스 표준으로 사용<br>4. **TTAK.KO-10.1170** 표준과 매핑된 데이터 모델 정의 |
| **근거(Rationale)** | - **표준 호환성**: OCF는 3,000개 이상의 제조사 지원, Matter는 Apple/Google/Amazon과 상호운용성 보장<br>- **TTA 표준 연계**: 스마트팜 데이터 모델이 TTA 표준과 85% 이상 호환 가능<br>- **확장성**: oneM2M 레이어 추가로 미래 표준 변화에 유연 대응 가능 |
| **결과(Consequences)** | ✅ **장점**:<br>- 제조사 간 호환성으로 시스템 확장성 3배 증가<br>- 스마트홈 통합으로 추가 서비스 시장이 개방됨<br>❌ **단점**:<br>- OCF/Matter 구현 복잡성 증가 (추가 라이브러리: 200KB 이상)<br>- 표준 변경으로 재구축 비용 발생 가능성 |
| **트레이드오프(Trade-offs)** | - **개방성 vs. 성능**: OCF의 JSON-LD 기반 통신으로 파싱 오버헤드 발생<br>- **표준화 vs. 독점성**: Matter 채택으로 Apple HomeKit 생태계와 연동 가능하나, 구글/아마존 생태계와의 호환성 검증 필요 |

## ⚠️ 잠재적 위험 분석

### **1. 에지 노드 보안 취약점**
- **설명**: 에지 노드(120)가 물리적으로 노출되어 있거나 기본 암호화 설정으로 남겨질 경우, 악의적인 접근이나 데이터 변조 위험 발생. 특히, 농촌 환경의 네트워크 보안 인프라 미비로 취약.
- **심각도**: 🔴 High | **발생 가능성**: 🔴 High
- **대응 방안**:
  - **하드웨어 보안 모듈(HSM)** 통합 (예: AWS Nitro Enclave)
  - **ITU-T X.1352 기준**에 따른 주기적 보안 패치 자동화
  - **에지 노드 격리 네트워크** 구축 (VLAN 분리 + Zero Trust 모델 적용)

### **2. 데이터 일관성 문제**
- **설명**: 에지-클라우드 간 네트워크 지연으로 인해 실시간 데이터 동기화 실패 시, 분석 결과 불일치 발생. 특히, 생체 데이터(120) 처리에서 치명적.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **이벤트 소싱 패턴** 도입 (데이터 변경 이력 추적)
  - **CRDT(Conflict-free Replicated Data Type)** 알고리즘 적용
  - **네트워크 모니터링 도구** (Prometheus + Grafana) 활용하여 지연 감지

### **3. 벤더 락인 위험**
- **설명**: 클라우드 컴포넌트(140, 150)가 특정 클라우드 제공자(AWS/GCP)에 종속되면, 비용 증가나 서비스 중단 시 대체 어려움.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **Kubernetes 기반 하이브리드 클라우드** 아키텍처 설계
  - **CNCF 표준** (예: OpenTelemetry) 사용으로 벤더 독립성 확보
  - **다중 클라우드 지원 라이브러리** (예: Serverless Framework) 채택

### **4. 스케일링 한계**
- **설명**: 에지 노드 수 증가에 따른 클라우드 컴포넌트(140) 처리能力 한계. 특히, 비정상적인 데이터 폭주 시 시스템 마비 가능성.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **자동 스케일링 정책** (Kubernetes HPA + AWS Auto Scaling)
  - **데이터 샘플링 기술** 적용 (예: 10%만 클라우드로 전송)
  - **스트레스 테스트** (10만 노드 시뮬레이션) 주기적 수행

### **5. 표준 변화에 따른 재구축 비용**
- **설명**: OCF/Matter와 같은 표준이 변경되면, 시스템 전체를 재구축해야 하는 비용 발생. 특히, TTA 표준이 국제 표준으로 승인되지 않을 경우 영향 확대.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟢 Low
- **대응 방안**:
  - **추상화 레이어** 도입 (예: Adapter 패턴) 표준 변경에 유연 대응
  - **표준 변화 모니터링 시스템** 구축 (예: ISO/IEC 30141 변경 사항 자동 알림)
  - **백업 표준 프로토콜** (예: MQTT-SN) 준비

---
**참고 사항**:
- **성능 기준**: 에지 처리 지연 시간 ≤ 50ms, 클라우드 처리 지연 시간 ≤ 200ms
- **보안 기준**: KISA STI-0013-09 준수, ISO/IEC 27030:2020 가이드라인 적용
- **확장성 기준**: 10만 대 에지 노드 지원 가능, 데이터 처리량 1TB/일 이상
