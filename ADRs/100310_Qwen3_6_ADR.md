## 📋 ADR (Architecture Decision Record)

### ADR-001: 중앙 서버 기반 양액 통합 제어 및 원격 모니터링 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                                                                                        |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 환경에서 다수의 식물 센서(100) 및 상태 표시등(110, 120)을 통해 작물의 상태를 모니터링하고, 이를 기반으로 양액 크(400)의 양액 농도 및 공급을 제어(600)해야 함. 동시에 재배 농장 정보 및 사용자 양액 정보를 서버(300)에서 통합 관리하여 사용자 모바일 앱(200)으로 실시간 제공해야 하는 아키텍처적 과제가 존재함.                                                                                                                       |
| **결정(Decision)**       | **중앙 집중식 서버(300) 아키텍처**를 채택함. 서버(300)를 시스템의 허브로 설정하여 양액 크 제어부(600)와의 통신을 통해 물리적 제어를 수행하고, 동시에 모바일 앱(200)으로 재배 및 양액 정보를 전송하는 통합 데이터 허브 역할을 하도록 설계함.                                                                                                                                                                        |
| **근거(Rationale)**      | 1. **데이터 일관성:** 서버(300)가 '재배 양액 정보'와 '사용자 양액 정보'를 단일 소스(SSOT)로 관리함으로써, 제어부(600)의 실제 작동 상태와 사용자 앱(200)의 표시 정보 간 불일치를 방지함.<br>2. **복잡한 제어 로직 처리:** 센서 데이터(100)와 상태 신호(110, 120)를 종합 분석하여 양액 탱크(400)의 최적 농도를 계산하는 고도화된 로직을 서버에서 처리하여 엣지 디바이스의 부담을 줄임.<br>3. **원격 접근성:** 사용자가 언제 어디서나 모바일 앱(200)을 통해 농장 상태를 확인하고 관리할 수 있도록 함. |
| **결과(Consequences)**   | 시스템의 통합 관리가 용이해지며, 사용자에게 정확한 양액 정보를 실시간으로 제공할 수 있음. 반면, 서버(300)가 단일 장애점(SPOF)이 될 수 있으며, 서버-제어부(600) 간 통신 지연 시 양액 공급 타이밍이 늦어질 수 있음.                                                                                                                                                                                        |
| **트레이드오프(Trade-offs)** | 데이터 일관성 확보 및 중앙 집중식 제어 용이성 vs. 서버 의존도 증가로 인한 시스템 가용성 리스크 및 네트워크 지연 가능성.                                                                                                                                                                                                                                                   |

---

## ⚠️ 잠재적 위험 분석

### 1. 양액 제어부(600) 통신 두절로 인한 공급 실패

- **설명:** 서버(300)와 양액 제어부(600) 간 네트워크 연결이 끊어지거나 지연될 경우, 서버의 제어 명령이 크(400)에 전달되지 않아 작물에 필요한 양액 공급이 중단되거나 잘못된 농도의 양액이 공급될 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 제어부(600)에 엣지 컴퓨팅 로직을 도입하여 서버 연결 두절 시 미리 설정된 기본 양액 공급 모드로 자동 전환(Fail-safe mode), 통신 상태 모니터링 및 자동 재연결(Retry) 메커니즘 구현.

### 2. 센서 데이터(100, 110, 120) 왜곡에 의한 잘못된 양액 제어

- **설명:** 식물 센서(100) 또는 상태 표시등(110, 120)에서 수집된 데이터에 오류가 발생하거나 노이즈가 섞일 경우, 서버(300)가 잘못된 판단을 내려 양액 탱크(400)에 부적절한 농도의 양액을 투입할 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 다중 센서 데이터의 교차 검증(Cross-Validation) 알고리즘 적용, 이상치 탐지(Anomaly Detection)를 통한 오류 데이터 필터링, 정기적인 센서 캘리브레이션(Calibration) 일정 수립.

### 3. 서버(300) 장애로 인한 전체 시스템 마비

- **설명:** 모든 제어 명령과 데이터 수집이 서버(300)를 통해 이루어지므로, 서버에 하드웨어 고장이나 소프트웨어 오류가 발생할 경우 양액 제어(600) 및 사용자 모니터링(200) 서비스가 동시에 중단됨.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 서버 이중화(HA, High Availability) 구성, 클라우드 기반 백업 서버 운영, 정기적인 시스템 헬스 체크 및 재해 복구(DR) drills 수행.

### 4. 사용자 모바일 앱(200) 데이터 보안 위협

- **설명:** 사용자 앱(200)과 서버(300) 간에 '사용자 양액 정보' 및 '재배 농장 정보'가 전송되는 과정에서 데이터가 탈취되거나 변조될 경우, 농장의 핵심 운영 데이터가 유출될 수 있음.
- **심각도:**  High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 통신 구간 TLS/SSL 암호화 적용, 사용자 인증 시 다중 인증(MFA) 도입, 앱 내 저장 데이터 암호화 및 정기적인 보안 취약점 진단 실시.

### 5. 전원 공급부(500) 불안정으로 인한 제어부(600) 오작동

- **설명:** 양액 제어부(600)에 전원을 공급하는 전원부(500)에 전압 불안정이나 순간 정전이 발생할 경우, 제어부 리셋 또는 오작동이 발생하여 양액 탱크(400)의 밸브가 열리거나 닫히는 등 물리적 제어가 패할 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 전원부(500)에 UPS(무정전 전원 장치) 또는 서지 프로텍터(Surge Protector) 설치, 전원 상태 모니터링 센서 도입으로 전압 강하 시 즉시 알림 전송.
