📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: NFC 태깅 기반 위치정보 연계 지하시설물 통합 관리 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                             |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 시스템은 지하 매설물(관로 등)에 NFC 태그를 부착하고, 스마트폰을 통해 태깅하여 관로 정보를 조회·입력한다. 수집된 데이터는 위치정보(GPS)와 결합되어 통합 서버로 전송되며, 웹 및 모바일 앱을 통해 시설물 관리기관, 긴급 대응 기관(119 등)에서 활용된다. 핵심 과제는 “현장 중심의 정확한 시설물 정보 수집과 위치 기반 통합 관리 및 신속한 정보 제공”이다. |
| **결정(Decision)**       | NFC 기반 태깅 시스템을 활용하여 현장 데이터 입력 및 조회를 수행하고, GPS 기반 위치정보와 결합하여 중앙 매설관로 통합서버에서 관리하는 구조를 채택한다. 또한 모바일 앱과 웹 시스템을 통해 다중 사용자(관리기관, 재난 대응 기관 등)가 실시간으로 정보에 접근할 수 있도록 설계한다.                                              |
| **근거(Rationale)**      | 지하시설물은 육안 식별이 어렵기 때문에 정확한 위치와 식별 정보가 중요하다. NFC는 근거리에서 빠르고 정확한 식별이 가능하며, GPS와 결합 시 위치 정확도를 보완할 수 있다. 중앙 서버 기반 구조는 데이터 일관성과 공유를 보장하며, 긴급 상황 대응 속도를 향상시킨다.                                                        |
| **결과(Consequences)**   | **긍정적:** 현장 데이터 정확성 향상, 위치 기반 관리 가능, 긴급 대응 효율성 증가, 데이터 통합 관리**부정적:** NFC 태그 유지관리 필요, GPS 오차 문제, 네트워크 의존성 증가                                                                                                    |
| **트레이드오프(Trade-offs)** | 현장 기반 정확성과 실시간 정보 공유를 얻는 대신, 인프라 유지 비용 및 위치 정확도 한계를 감수해야 한다.                                                                                                                                                   |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. NFC 태그 손상 또는 인식 실패

* **설명:** 외부 환경(습기, 충격 등)으로 NFC 태그가 손상되거나 인식되지 않을 수 있음

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 내구성 높은 태그 사용, 정기 점검 및 교체, 대체 식별 수단(QR 등) 병행

### 2. 위치정보 정확도 문제

* **설명:** GPS 오차로 인해 실제 매설 위치와 시스템 정보 간 불일치 발생

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 보정 기술(DGPS), 지도 기반 보정, 다중 센서 융합

### 3. 중앙 서버 장애

* **설명:** 매설관로 통합서버 장애 시 데이터 조회 및 활용 불가

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 클라우드 기반 이중화, 백업 및 장애 복구 시스템 구축

### 4. 보안 취약점 (시설 정보 유출)

* **설명:** 중요 인프라 정보가 외부에 유출될 경우 보안 위협 발생

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 데이터 암호화, 접근 권한 관리, 보안 인증 체계 적용

### 5. 네트워크 의존성

* **설명:** 현장에서 네트워크 연결이 불안정할 경우 데이터 전송 지연 또는 실패

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 오프라인 저장 후 동기화 기능, 네트워크 이중화

### 6. 데이터 입력 오류

* **설명:** 현장 작업자가 잘못된 정보를 입력할 경우 데이터 신뢰성 저하

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 입력 검증 로직, 표준 입력 템플릿, 교육 및 UI 개선

### 7. 시스템 확장성 제한

* **설명:** 매설물 및 사용자 증가 시 서버 및 데이터 처리 성능 저하

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 클라우드 기반 확장 구조, 분산 데이터 처리, API 게이트웨이 도입🏗️ 아키텍처 분석 보고서
