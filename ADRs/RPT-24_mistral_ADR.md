📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: **태그 기반 통합 작업 추적 시스템 구축**

| 항목                     | 내용                                                                                                                                                                                                              |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 시스템에서 작업자(`sf_worker`), 기계(`sf_machine`), 작업 계획(`sf_workplan`), 이벤트(`sf_msevent`), 태그(`sf_tag`) 등 다양한 엔티티가 유기적으로 연동되어야 함. 기존 시스템에서는 각 엔티티 간 연결성이 약해 작업 추적 및 자원 관리가 비효율적임.                                  |
| **결정(Decision)**       | **TAG CODE**를 중심으로 `sf_tag`, `sf_machine`, `sf_msevent`를 연결하는 **태그 기반 통합 추적 시스템**을 구축. 모든 물리적/논리적 자원(기계, 작업자, 작업 계획)에 태그를 할당하여 실시간으로 상태와 이력을 추적할 수 있도록 설계.                                                      |
| **근거(Rationale)**      | 1. **유연성**: 태그를 통해 동적으로 자원 그룹화 및 재배치 가능<br><br>2. **확장성**: 새로운 자원(예: 센서, IoT 디바이스) 추가 시 태그만 확장하면 시스템 수정 최소화<br><br>3. **통합성**: `sf_msevent`의 `MCCODE`와 `TAG CODE`를 연동하여 이벤트 발생 시 해당 태그로 연결된 모든 자원의 상태를 즉시 확인 가능 |
| **결과(Consequences)**   | **장점**: 실시간 모니터링 및 추적 효율성 향상, 자원 관리 자동화<br><br> **단점**: 태그 관리 시스템의 복잡성 증가, 태그 중복 또는 오류 시 전체 추적 시스템에 영향을 미칠 수 있음                                                                                                 |
| **트레이드오프(Trade-offs)** | 태그 시스템의 유연성을 얻는 대신, 태그 데이터의 정확성과 일관성을 유지하기 위한 추가적인 검증 메커니즘이 필요                                                                                                                                                  |

### ADR-002: **작업 유형 표준화 및 계층적 작업 계획 연동**

| 항목                     | 내용                                                                                                                                                         |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | `sf_workplan`(작업 계획)과 `sf_wtype`(작업 유형) 간의 연결(`WTCODE`)이 있지만, 작업 유형이 표준화되어 있지 않아 작업 계획의 일관성이 떨어지고, 작업자(`sf_worker`)와 기계(`sf_machine`) 간 협업이 비효율적임.         |
| **결정(Decision)**       | **WTCODE**를 통해 `sf_workplan`과 `sf_wtype`을 강제 연동하고, 작업 유형을 **스마트팜 표준 작업 코드(예: 재배, 수확, 환경 모니터링 등)**로 표준화. 또한, `WKCODE`를 통해 작업자와 작업을 연결하여 책임 추적성 확보.          |
| **근거(Rationale)**      | 1. **표준화**: 작업 유형의 표준화로 작업 계획의 일관성 및 재사용성 향상<br><br>2. **추적성**: 작업자-작업-기계 간 연결성을 통해 작업 이력의 추적 및 분석 용이<br><br>3. **자동화**: 표준화된 코드로 인공지능 기반 작업 스케줄링 및 최적화 가능 |
| **결과(Consequences)**   | **장점**: 작업 효율성 및 품질 관리 개선, 데이터 분석을 통한 인사이트 도출 용이<br><br> **단점**: 표준화 프로세스 도입 시 초기 학습 곡선 및 시스템 마이그레이션 비용 발생                                                 |
| **트레이드오프(Trade-offs)** | 표준화로 인한 유연성 저하 vs. 장기적인 운영 효율성 향상                                                                                                                          |

### ADR-003: **이벤트 기반 실시간 모니터링 시스템**

| 항목                     | 내용                                                                                                                                                                                               |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **상황(Context)**        | `sf_msevent`(기계 이벤트)가 `MCCODE`(기계 코드)와 `TAG CODE`로 연결되어 있지만, 이벤트 발생 시 실시간으로 알림 또는 조치를 취하는 메커니즘이 없음.                                                                                              |
| **결정(Decision)**       | **이벤트 구독-발행(Pub/Sub) 아키텍처** 도입. `sf_msevent`에 이벤트가 등록되면 해당 `TAG CODE` 또는 `MCCODE`를 구독하는 모든 시스템(예: 모니터링 대시보드, 알림 시스템)에게 실시간으로 전달.                                                                 |
| **근거(Rationale)**      | 1. **실시간성**: 스마트팜에서 발생하는 비정상 이벤트(예: 기계 고장, 환경 이상)에 즉각 대응 가능<br><br>2. **확장성**: 새로운 이벤트 소비자(예: AI 기반 진단 시스템) 추가 시 아키텍처 수정 없이 구독만 추가 가능<br><br>3. **신뢰성**: Kafka 또는 MQTT와 같은 메시지 브로커를 통해 이벤트 손실 방지 |
| **결과(Consequences)**   | **장점**: 실시간 문제 대응 및 예방 유지보수 가능<br><br> **단점**: 메시지 브로커 운영을 위한 인프라 비용 및 복잡성 증가                                                                                                                    |
| **트레이드오프(Trade-offs)** | 실시간성 확보를 위한 인프라 투자 vs. 시스템 신뢰성 및 효율성 향상                                                                                                                                                          |

⚠️ 잠재적 위험 분석
------------

### 1. **태그 중복 및 일관성 저하**

* **설명:** 여러 `sf_tag`가 동일한 물리적 자원에 할당되거나, `TAG CODE`가 중복되어 발생하는 데이터 오류. 예를 들어, 같은 기계에 서로 다른 태그가 할당되어 작업 추적 시 혼란 발생.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:**
  * **태그 관리 시스템** 도입: 태그 할당 시 유효성 검사 및 중복 방지 로직 구현.
  * **정기적 감사**: 주기적인 태그 데이터 검토 및 정리 프로세스 수립.

* * *

### 2. **이벤트 스톰(Event Storm) 발생**

* **설명:** `sf_msevent`에서 짧은 시간 내에 대량의 이벤트가 발생(예: 센서 오작동)하여 시스템 과부하 및 성능 저하 발생.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:**
  * **이벤트 필터링**: 비정상적인 이벤트 패턴 감지 시 자동 필터링 또는 그룹화.
  * **_rate limiting_ 적용**: 이벤트 처리율 제한을 통해 시스템 보호.

* * *

### 3. **작업 계획과 실제 작업의 불일치**

* **설명:** `sf_workplan`에 정의된 작업(`WKCODE`)과 실제 `sf_worker` 또는 `sf_machine`의 작업이 불일치하는 경우(예: 작업자 미준수, 기계 고장). 이로 인해 작업 추적 데이터의 신뢰성 저하.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:**
  * **실시간 검증**: IoT 센서 또는 작업자 모바일 앱을 통해 실제 작업 진행 상황과 계획 대조.
  * **알림 시스템**: 불일치 감지 시 관리자에게 즉시 알림.

* * *

### 4. **보안 취약점: 태그 스푸핑(Tag Spoofing)**

* **설명:** 악의적인 사용자가 `TAG CODE`를 위조하여 시스템에 접근하거나, 잘못된 이벤트를 주입하는 공격.
* **심각도:** 🔴 High
* **발생 가능성:** 🟢 Low
* **대응 방안:**
  * **태그 인증 메커니즘**: 물리적 태그(예: RFID)에 디지털 서명 또는 암호화 적용.
  * **액세스 제어**: 태그별로 권한 수준 정의 및 인가된 엔티티만 접근 허용.

* * *

### 5. **데이터베이스 성능 병목**

* **설명:** `sf_worker`, `sf_machine`, `sf_tag` 등 다수의 테이블이 `TAG CODE` 또는 `WKCODE`로 연결되어 있는 관계형 데이터베이스에서 복잡한 조인 쿼리 수행 시 성능 저하.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:**
  * **인덱스 최적화**: 자주 조회되는 컬럼(`TAG CODE`, `WKCODE`, `MCCODE`)에 인덱스 추가.
  * **캐시 레이어** 도입: Reddis를 활용한 캐싱으로 조회 성능 향상.
  * **데이터베이스 샤딩**: 대용량 데이터 처리 시 샤딩을 통한 수평 확장.

* * *

### 6. **작업 유형 표준화 실패로 인한 데이터 파편화**

* **설명:** `sf_wtype`의 표준화가 제대로 이루어지지 않아, 동일한 작업을 서로 다른 `WTCODE`로 등록하는 경우 데이터 분석 시 일관성 저하.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:**
  * **마스터 데이터 관리(MDM)**: 작업 유형을 중앙에서 관리하는 시스템 도입.
  * **자동화 검증**: 작업 계획 등록 시 `WTCODE`의 유효성 자동 검사.
