# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 하이브리드 클라우드-엣지 아키처 및 로컬 데이터 이중화 채택

| 항목                     | 내용                                                                                                                                                                                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 통합 제어 시스템(10)은 농장 내의 실시간 환경 제어(액추에이터 제어)와 원격 모니터링(관리자 단말), 그리고 중앙 집중식 데이터 관리(클라우드 서버)를 동시에 수행해야 함. 농장 환경은 네트워크 연결이 불안정할 수 있으며, 네트워크 단절 시에도 농작물 보호를 위한 제어가 중단되어서는 안 되는 아키텍처적 과제가 존재함.                                                                   |
| **결정(Decision)**       | `농장 제어기(100)`를 엣지 게이트웨이로 활용하여 `액추에이터(30)`에 대한 직접적인 실시간 제어와 `농장 데이터 저장, 관리`(로컬 저장소)를 수행하는 **하이브리드 클라우드-엣지 아키텍처**를 채택함. 네트워크 연결 시에만 `클라우드 서버(200)`와 데이터를 동기화하고, `관리자 단말(20)`의 원격 제어 요청을 중계하도록 설계함.                                                            |
| **근거(Rationale)**      | 1. **가용성 및 신뢰성:** 네트워크 장애 시에도 `농장 제어기(100)`의 로컬 저장소 루프와 제어 로직이 작동하여 농장 환경 유지를 보장함.<br>2. **실시간성:** `액추에이터(30)` 제어에 클라우드 왕복 지연시간(RTT)을 배제하고 로컬에서 직접 처리하여 즉각적인 환경 대응이 가능함.<br>3. **원격 접근성:** `클라우드 서버(200)`를 통해 `관리자 단말(20)`이 언제 어디서나 농장 상태를 모니터링하고 제어할 수 있음. |
| **결과(Consequences)**   | 시스템의 견고성(Robustness)이 크게 향상되며, 네트워크 불안정성에 의한 농작물 피해 위험이 줄어듦. 반면, 로컬 데이터와 클라우드 데이터 간의 동기화(Synchronization) 로직이 복잡해지며, 데이터 불일치 해결을 위한 추가 개발 노력이 필요함.                                                                                                          |
| **트레이드오프(Trade-offs)** | 로컬 자율성 및 실시간 제어 성능 확보 vs. 데이터 일관성 유지의 복잡성 증가 및 엣지 디바이스(농장 제어기)의 하드웨어 사양 요구사항 상승.                                                                                                                                                                            |

---

## ⚠️ 잠재적 위험 분석

### 1. 네트워크 단절 시 데이터 동기화 실패 및 유실

- **설명:** `농장 제어기(100)`가 네트워크 장애 동안 로컬에 데이터를 저장하다가 네트워크가 복구되었을 때, `클라우드 서버(200)`와의 대용량 데이터 동기화 과정에서 타임아웃이 발생하거나 데이터가 유실될 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 증분 동기화(Incremental Sync) 메커니즘 도입, 네트워크 대역폭을 고려한 데이터 전송 스케줄링, 동기화 실패 시 재시도(Retry) 및 알림 로직 구현.
  
  ### 2. 원격 제어 명령의 보안 취약점 및 무단 접근
- **설명:** `관리자 단말(20)`이 네트워크를 통해 `농장 제어기(100)`로 `재배 환경 원격 제어` 명령을 전송하는 경로가 해킹이나 무단 접근에 노출될 경우, 악의적인 제어(예: 난방 차단, 관수 과다)로 농작물에 치명적 피해가 발생할 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 통신 구간 TLS/SSL 암호화 적용, 다중 인증(MFA) 및 디바이스 인증서 기반 접근 제어, 비정상적인 제어 패턴(예: 한겨울 환기 개방) 감지 시 자동 차단 로직 구현.
  
  ### 3. 농장 제어기(100)의 단일 장애점(SPOF)화
- **설명:** `액추에이터(30)` 제어와 로컬 데이터 저장이 `농장 제어기(100)`에 집중되어 있음. 이 제어기에 하드웨어 고장이나 소프트웨어 크래시가 발생하면, 농장 내 모든 자동화 제어와 데이터 로깅이 즉시 중단됨.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** `농장 제어기`에 Watchdog Timer 도입 및 자동 재부팅 로직 적용, 핵심 제어 기능에 대한 이중화(Redundancy) 구성(예: 보조 제어기 대기), 정기적인 자가 진단(Self-diagnosis) 기능 탑재.
  
  ### 4. 로컬 저장소 용량 초과로 인한 데이터 오버라이드
- **설명:** 네트워크가 장기간 연결되지 않아 `농장 제어기(100)`의 로컬 저장 공간이 포화될 경우, 새로운 데이터를 저장하기 위해 오래된 데이터를 덮어씌우게 되면, 동기화 시점 이전의 중요 데이터가 영구적으로 손실될 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 저장 용량 임계치 도달 시 `클라우드 서버` 연결 시도 강제화 또는 관리자에게 긴급 알림 전송, 중요 데이터 우선 보존 정책 적용, 로컬 저장소의 주기적인 정리(Archiving) 로직 구현.
  
  ### 5. 액추에이터 제어 루프의 오작동 (Runaway Control)
- **설명:** `농장 제어기(100)`와 `액추에이터(30)` 간의 제어 신호가 센서 피드백(도시되지 않았으나 암묵적)과 불일치하거나 제어 로직에 버그가 있을 경우, 액추에이터가 무한정 작동(예: 밸브 잠금 실패)하여 시설 파괴나 작물 손상이 발생할 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low
- **대응 방안:** 제어 명령에 시간 제한(Time-out) 및 최대 작동 횟수 제한 설정, 물리적 안전 장치(Manual Override Switch, 퓨즈 등) 병행 설치, 제어 로직에 대한 시레이션 기반 검증 절차 필수화.
