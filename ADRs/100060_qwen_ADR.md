# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 블록체인 기반의 데이터 무결성 및 신뢰성 확보

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 서버(30)에서 수집된 작물 데이터(91, 작물 품질, 재배 비용 등)는 재배자와 구매자(97) 간의 거래에 필수적입니다. 기존 서버 중심 구조에서는 데이터가 중앙집중화되어 있을 경우, 데이터 유출, 조작, 가짜 데이터 생성 등의 리스크가 존재합니다. 특히 농산물 유통 과정의 투명성을 강조하는 요구사항과 ISO/IEC 30141:2024 및 ITU-T X.1352 표준의 보안을 만족시키기 위해서는 별도의 검증 메커니즘이 필요합니다. |
| **결정(Decision)** | 서버(30)에서 생성된 핵심 거래 데이터는 블록체인 네트워크(300) 에 분산 기록을 수행합니다. 이는 모든 거래 내역을 불변성(Unalterability)과 투명성을 가지도록 보장하며, 중앙집중형 서버의 단일 장애점(SPOF) 리스크를 분산하는 역할을 수행합니다. 거래 내역(93) 은 블록체인에 의해 보증됩니다. |
| **근거(Rationale)** | 1. **신뢰성:** ITU-T X.1352 표준 및 IoT 보안 요구사항을 충족하기 위해 중앙관리자뿐만 아니라 분산 네트워크가 검증하는 구조가 필요합니다.<br>2. **투명성:** 구매자(구매자)와 재배자(재배자) 간의 거래(93) 과정을 모두 참여자가 검증 가능하도록 하여, 농산물의 품질과 가격 공정을 증명합니다.<br>3. **스마트 컨트랙트 가능성:** 향후 자동화된 거래 조건(스마트팜 서버 내의 구매 조건)을 코드화하여 자동 실행할 수 있는 기반을 마련합니다. |
| **결과(Consequences)** | **긍정적:** 데이터 조작 방지, 거래 이력의 영구 보존, 참여자 간 상호신뢰 증대.<br>**부정적:** 블록체인 네트워크(300) 의 트랜잭션 처리 속도가 느려질 수 있음, 네트워크 구축 및 유지 비용 증가. |
| **트레이드오프(Trade-offs)** | **장점:** 무방조성 보장을 위한 거래 처리 시간 지연을 감수하여 확실한 신뢰를 얻습니다.<br>**단점:** 실시간 대용량 데이터 처리에는 적합하지 않으므로, 비핵심 로그나 원시 데이터만 서버에 보관하고 핵심 거래 데이터만 블록체인으로 보낼 수 있는 필터링 전략이 필요합니다. |

## ⚠️ 잠재적 위험 분석

### 1. 블록체인 네트워크 트랜잭션 처리 병목 현상
- **설명:** 블록체인 네트워크 (300) 는 분산 합의 프로세스 (PoW, PoS 등) 를 통해 거래를 검증하므로, 스마트팜 서버 (30) 에서 대량으로 전송되는 작물 데이터 (91) 가 실시간으로 처리되지 않을 경우, 시스템 응답 지연이 발생할 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 
  - **오프체인 데이터 저장:** 고해상도 이미지, 원시 센서 데이터는 스마트팜 서버의 데이터베이스에 저장하고, 블록체인에는 데이터의 해시값 (Hash) 만 기록하는 'Light Client' 아키텍처를 적용합니다.
  - **스케일링 솔루션:** 샤딩 (Sharding) 또는 레이어 2 (Layer 2) 솔루션을 도입하여 트랜잭션 처리량을 증가시킵니다.

### 2. 개인 정보 보호 및 규제 준수 (GDPR/개인정보보호법)
- **설명:** 스마트팜 서버에서 수집된 '재배 비용', '품질' 데이터나 '작물 이미지'에는 특정 농가 (재배자 97) 를 식별할 수 있는 정보가 포함될 수 있습니다. 블록체인에 한번 기록된 데이터는 수정이 어렵기 때문에, 규제 기관이 요청한 삭제를 수행하기 어려운 문제가 발생할 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 
  - **프라이빗 데이터 채널:** 민감한 개인 식별정보 (PII) 는 오프체인으로 보관하거나, 공개 블록에 들어가기 전 탈식별화 (익명화) 처리를 거칩니다.
  - **접근 제어:** 구매자 (구매자) 와 재배자 (재배자) 간의 거래 기록에는 최소 권한 원리에 따라 접근이 제어되도록 스마트 컨트랙트 정책을 수립합니다.

### 3. IoT 디바이스 및 게이트웨이 보안 취약점
- **설명:** 국내 표준 (TTA) 및 국제 표준 (ITU-T) 에 따라 IoT 기기는 최소한의 보안 요구사항을 충족해야 하지만, 현장에 배포되는 수많은 센서 및 게이트웨이 중 일부가 해킹 당하거나 악성 코드를 포함하여 가짜 데이터 (예: 고의적인 작물 손상 이미지) 를 블록체인 네트워크 (300) 로 전송할 경우, 시스템 전체의 신뢰가 무너질 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 
  - **하드웨어 보안 모듈 (HSM):** 모든 IoT 디바이스에는 TPM 또는 HSM을 내장하여 키를 안전하게 보관합니다.
  - **멀티싱니처:** 블록 생성에 여러 개의 인증서 (재배자, 관리자 등) 서명이 필요하도록 스마트 컨트랙트를 설계하여 단일 디바이스 해킹을 방어합니다.

### 4. 네트워크 연결 불확실성 (네트워크 분할)
- **설명:** 재배 현장 (스마트팜) 은 인터넷 연결이 불안정할 수 있습니다. 네트워크 분할 (Network Partitioning) 이 발생하여 일부 노드만 동기화될 경우, 블록체인의 일관성이 깨지고 잘못된 상태가 유지될 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 
  - **오프라인 모드 지원:** 재배자가 네트워크가 끊긴 상태에서도 로컬 서버에 데이터를暂存 (Staging) 하고, 연결이 복원될 때 자동으로 동기화되도록 로직을 구현합니다.
  - **로버스트한 합의 알고리즘:** 네트워크 분할 상황에서도 전체 노드의 약 2/3 만 동의하면 블록을 유효하게 인정하는 BFT (Byzantine Fault Tolerance) 방식 합의 알고리즘을 사용합니다.

### 5. 데이터 일관성 및 동기화 지연
- **설명:** 스마트팜 서버 (30) 와 블록체인 네트워크 (300) 간 데이터 동기화가 지연되거나, 두 시스템 간 데이터 버전이 불일치하면, 구매자가 보기에与实际不符한 정보 (예: 이미 판매된 작물이 재고에 남아있는 상태) 가 노출될 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low
- **대응 방안:** 
  - **마이크로서비스 아키텍처:** 서버 내부를 마이크로서비스로 분할하여, 블록체인과 관련된 서비스만 해당 부분과 통신하도록 격리하여 연착오를 방지합니다.
  - **데이터 재해 복구 전략:** 정기적인 백업을 수행하고, 동기화 오류가 발생한 경우를 감지하여 자동으로 수습하는 모니터링 시스템을 운영합니다.
