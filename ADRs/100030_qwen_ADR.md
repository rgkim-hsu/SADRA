## 📋 ADR (Architecture Decision Record)

### ADR-001: 모듈라이즈된 다단계 처리 파이프라인 아키텍처 도입

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 단순히 이미지를 받아서 결과를 내는 것이 아니라, '이미지 입력 → 분류 → 보정 → 산출'이라는 엄격한 프로세스 흐름을 따르고 있다. 이는 AI 모델의 신뢰성을 높이기 위해 각 단계 (Input, Classification, Correction, Estimation) 가 분할되어 관리될 필요가 있었기 때문이다. 또한, '생육정보산출모듈(200)' 내부에 7 개의 기능 블록이 세밀하게 정의되어 있음. |
| **결정(Decision)** | **'세그멘테이션 기반의 처리 파이프라인 (Segmented Processing Pipeline)' 아키텍처**를 결정함. 즉, 메인 처리 모듈 (200) 을 하나의 거대한 블랙박스 대신, 기능별로 분리된 서브 모듈 (입력, 분류, 보정, 산출 등) 로 구성하여 관리할 것임. |
| **근거(Rationale)** | 1. **관측 가능성 (Observability) 향상:** 각 단계 (예: 이미지 보정부 230) 에서 오류가 발생했을 때 원인을 파악하기 쉬움.<br>2. **유연한 확장성:** '기관별 계측치 산출부(240)'와 같은 특정 기능만 독립적으로 업데이트하거나 개선 가능.<br>3. **성능 최적화:** 이미지 처리량이 많을 때 병렬 처리가 필요한 단계 (예: 분류부) 와 순차 처리가 필요한 단계 (예: 매칭부 270) 를 명확히 구분 가능. |
| **결과(Consequences)** | **긍정적 결과:** 시스템 유지보수 용이, 특정 AI 모델 개선 시 전체 시스템 다운 방지.<br>**부정적 결과 (트레이드오프):** 모듈 간 통신 오버헤드 발생, 전체 시스템 설계가 복잡해질 수 있음. |

### ADR-002: 이원화된 데이터 소스 통합 전략 (Standard DB & Agri DB Convergence)

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 '기준정보 데이터베이스(300)'와 '영농정보 데이터베이스(400)' 두 개의 독립된 데이터 소스를 사용한다. 이는 표준화된 기본 데이터 (종, 품명 등) 와 실제 농장/환경 데이터 (위성영상, 기후 등) 를 구분하여 저장해야 하는 요구 사항에서 기인함. |
| **결정(Decision)** | **소스 별 분리 저장 및 통합 뷰 아키텍처** 채택. DB(300) 와 DB(400) 를 물리적으로 분리하되, 내부 처리 모듈 (200) 270 번 '영농정보 매칭부'를 통해 논리적으로 통합하는 방식.<br>API 를 통해 두 DB 간의 동기화를 관리할 것임. |
| **근거(Rationale)** | 1. **데이터 무결성:** 기준정보는 변경 빈도가 낮고 엄격한 규정이 필요한 반면, 영농정보는 실시간/빈번하게 변경됨. 분리 관리 시 충돌 방지.<br>2. **규정 준수:** 기준정보는 표준 (ISO/IEC 등) 을 준수해야 하지만, 영농정보는 현지 농업 정책 데이터에 따라 유연해야 함. |
| **결과(Consequences)** | **긍정적 결과:** 데이터 관리 정책의 유연성 확보, 표준 오류 최소화.<br>**부정적 결과 (트레이드오프):** 양쪽 DB 간의 레거시 데이터 연결 시 복잡도 증가, 트랜잭션 관리 비용 증가. |

## ⚠️ 잠재적 위험 분석

### 1. 이미지 처리 파이프라인 병목 (Pipeline Latency Bottleneck)
- **설명:** 모듈 (200) 내부의 7 단계 (입력→분류→보정→산출 등) 가 모두 동기적으로 연결되어 있을 경우, 처리 시간이 가장 느린 단계 (예: '이미지 기본 기관분류부'나 '과중산출부'의 AI 연산) 에서 전체 시스템의 응답 시간이 급격히 늘어날 수 있음. 특히 실시간 모니터링이 필요한 사물인터넷(IoT) 환경에서 심각한 문제.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 느린 단계 (AI 모델 연산 등) 에 대해 **Asynchronous Processing (비동기 처리)** 를 도입하거나, 이미지 크기를 단계별로 축소하는 단계별 최적화를 적용.

### 2. 모듈 간 통신 신뢰성 저하 (Inter-Module Communication Failure)
- **설명:** '이미지 제공모듈(100)'에서 '생육정보산출모듈(200)'로 데이터가 흐르는 과정에서 네트워크 불안정이나 큐 오버플로우가 발생하면 데이터 손실 또는 처리 중단이 발생. 특히 '이미지 전송부(120)'와 '이미지 입력부(210)' 간 연결이 끊어질 경우.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** **MQTT**나 **Kafka** 같은 메시지 브로커를 도입하여 모듈 간 통신을 해고성으로 변경. 큐 기반의 이니셔티브 (Initiative) 를 사용하여 일시적 장애 시 데이터를 임시 저장.

### 3. 데이터베이스 동기화 불일치 (Data Inconsistency)
- **설명:** '기준정보 데이터베이스(300)'와 '영농정보 데이터베이스(400)'가 독립되어 관리되므로, 한쪽에서 데이터가 업데이트되면 다른 쪽의 변화가 즉시 반영되지 않을 수 있음. 이로 인해 산출된 '생육정보'가 실제 상태와 맞지 않는 오류 발생.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** **CDC (Change Data Capture)** 기술을 활용하여 DB 간 실시간 데이터 복제. 또는 CQRS 패턴을 도입하여 읽기/쓰기 워크로드를 분리하고 이벤트 소싱 방식으로 상태 관리.

### 4. 보안 취약점 및 데이터 유출 (Security & Data Leakage)
- **설명:** '이미지 촬영모듈(110)'이나 '이미지 입력부(210)'를 통해 수집되는 이미지나 '기준정보'에 포함된 민감한 농가 정보가 무단으로 외부로 유출될 위험 존재. 특히 외부로 전송하는 '정보전송부(280)' 경로가 해킹 대상이 될 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** **TLS 1.3** 암호화 통신 적용. 전송 데이터에 **Digital Signature** 추가. 민감도 분석을 통해 '유출 시 피해가 큰 데이터'만 필터링하여 압축/가상화 처리.

### 5. AI 모델 편향성 및 정확도 저하 (AI Model Bias & Drift)
- **설명:** '이미지 기본 기관분류부(220)'나 '과중산출부(250)'와 같은 AI 모델이 특정 조명, 각도, 환경에서 학습되지 않았을 경우, 오류가 발생. 이는 데이터 편향성 (Bias) 또는 개념 이주 (Concept Drift) 로 인해 발생할 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low (초기에는 낮으나 시간이 지남에 따라 증가)
- **대응 방안:** **Continuous Learning** 시스템 구축. 실시간 피드백 (사용자 수정) 을 바탕으로 모델 재학습 주기 설정. 다양하고 풍부한 테스트 데이터셋 (Edge Case) 을 확보.
