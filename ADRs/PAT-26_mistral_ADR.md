📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 중앙 집중식 데이터 관리 아키텍처 채택

| 항목                     | 내용                                                                                                                                                   |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 시스템은 실시간으로 환경 데이터(온도, 습도, 조도 등)를 수집, 분석, 제어해야 하며, 여러 하위 시스템(예: 재배 환경, 수확 관리, 에너지 관리)이 상호 연동되어야 함. 분산된 데이터 소스와 제어 장비를 통합 관리할 필요성이 있음.            |
| **결정(Decision)**       | 중앙 집중식 **스마트팜 중앙관제시스템**을 핵심으로 하여 모든 하위 시스템(재배 환경, 수확 관리, 에너지 관리 등)과 연결하는 아키텍처 채택.                                                                    |
| **근거(Rationale)**      | 실시간 데이터 동기화 및 일관성 유지, 시스템 전체의 상태 모니터링과 제어의 단순화, 확장성 확보를 위해 중앙 집중식 구조가 가장 적합함. 또한, 스마트팜에서 요구되는 빠른 의사결정과 자동화 제어를 지원하기 위해 데이터 처리와 명령 전달의 지연을 최소화할 수 있음. |
| **결과(Consequences)**   | **장점**: 데이터 일관성 보장, 시스템 관리 및 유지보수 용이, 실시간 모니터링과 제어 가능. **단점**: 중앙 시스템 장애 시 전체 시스템 마비 가능성, 네트워크 병목 현상 발생 가능성.                                         |
| **트레이드오프(Trade-offs)** | 중앙 집중식 구조로 인해 시스템의 단일 장애점(Single Point of Failure)이 발생할 수 있지만, 백업 시스템과 이중화 구성을 통해 위험을 완화할 수 있음.                                                      |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. 중앙 시스템 장애로 인한 전체 시스템 마비

* **설명:** 중앙관제시스템이 장애를 일으키면 모든 하위 시스템(재배 환경, 수확 관리, 에너지 관리 등)이 제어 불가능한 상태가 됨.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 중앙 시스템의 이중화(Active-Active 또는 Active-Standby) 구축, 정기적인 백업 및 장애 복구 테스트 수행.

* * *

### 2. 네트워크 병목 현상 발생

* **설명:** 모든 데이터가 중앙 시스템으로 집중되다 보니, 네트워크 트래픽이 과도하게 증가하여 데이터 전송 지연 또는 패킷 손실 발생 가능.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 네트워크 대역폭 확충, 데이터 압축 및 우선순위 기반 전송 프로토콜(QoS) 적용, 엣지 컴퓨팅을 활용한 로컬 데이터 처리 도입.

* * *

### 3. 보안 취약점으로 인한 데이터 유출 또는 조작

* **설명:** 중앙 시스템이 해킹당하거나, 네트워크 상에서 데이터가 가로채어지면 민감한 농장 데이터(예: 재배 환경 설정, 수확량 등)가 유출되거나 조작될 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 암호화된 통신 프로토콜(TLS/SSL) 적용, 접근 제어 및 인증 시스템(예: OAuth 2.0, MFA) 구축, 정기적인 보안 패치 및 감사 수행.

* * *

### 4. 하위 시스템 호환성 문제

* **설명:** 각 하위 시스템(예: 재배 환경, 에너지 관리)이 서로 다른 프로토콜이나 데이터 포맷을 사용할 경우, 중앙 시스템과의 통합 시 호환성 문제가 발생할 수 있음.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 표준화된 API 및 데이터 포맷(예: JSON, MQTT 프로토콜) 정의, 어댑터 패턴을 활용한 인터페이스 통합.

* * *

### 5. 실시간 데이터 처리 지연

* **설명:** 중앙 시스템에서 실시간으로 대량의 데이터를 처리해야 할 경우, 데이터 처리 지연이 발생하여 제어 명령이 지연될 수 있음.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟠 High
* **대응 방안:** 스트림 처리 기술(예: Apache Kafka, Apache Flink) 도입, 엣지 컴퓨팅을 활용한 로컬 데이터 처리 및 필터링.
