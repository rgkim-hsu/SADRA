## 📋 ADR (Architecture Decision Record)

### ADR-001: 다원적 데이터 소스를 통합한 AI 기반 학습 모델 도입

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 온도, 습도, CO2 등 '재배환경 데이터'와 '수확물 저하요인 분석', '기타 재배 노하우' 등 이질적인 데이터 소스를 통합해야 한다. 단순한 센서 제어뿐만 아니라, 곰팡이 발생과 같은 미시적인 생물학적 현상을 예측하기 위해서는 다양한 데이터의 교집합이 필요하다. |
| **결정(Decision)** | 입력 데이터(환경 데이터, 분석 결과, 노하우)를 모두 중앙 집중식 **AI 학습 엔진**으로 흘려보내어 하나의 통합된 지식 베이스를 구축한다. 이 학습된 모델이 실제 스마트팜 제어 장치에 배포되어 실시간 판단을 수행한다. |
| **근거(Rationale)** | 이미지 및 관련 문서를 통해 IoT 시스템의 핵심 아키텍처 표준인 ISO/IEC 30141:2024(참조 아키텍처) 및 TTA의 스마트팜 환경 데이터 모니터링 시스템 요구사항을 고려할 때, 단순 규칙 기반 (Rule-based) 이 아닌 머신러닝/딥러닝 기반의 예측 제어 (Predictive Control) 가 필수적이다. '수확물 저하요인 분석'을 AI로 학습시키는 것은 데이터 기반의 최적화된 환경 제어를 실현하는 핵심 전략이다. |
| **결과(Consequences)** | **긍정적:** AI 가 다양한 변수를 고려하여 최적의 환경을 유지하므로, 곰팡이 발생 등 수확물 저하를 방지하고 동물 축사 효율 (동종호조) 을 극대화할 수 있다.<br>**부정적:** 초기에는 고품질 데이터를 위한 학습 기간 (Training Phase) 이 필요하며, 데이터 수집 초기에는 시스템 성능이 불안정할 수 있다. |
| **트레이드오프(Trade-offs)** | 실시간 제어의 지연 시간을 감수하여도, 더 정확한 예측 모델을 확보하는 것을 우선시한다. 대신 에지 컴퓨팅 (Edge Computing) 을 도입하여 응답 속도를 높이는 방안을 병행한다. |

### ADR-002: 데이터 경계의 안전한 암호화 및 보안 프로토콜 적용

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 이미지 중앙에 위치한 '데이터 암호화' 로크 아이콘과 이를 통과하는 화살표는 플랫폼 구축 단계와 실제 적용 단계 (곰팡이 ZERO 보급) 사이의 데이터 이동을 보호해야 함을 시사한다. 또한, 관련 문서에서는 ITU-T X.1352(보안요구), ETSI EN 303 645(사이버보안) 등의 국제 표준이 언급되어 있다. |
| **결정(Decision)** | 플랫폼 구축 (학습) 단계에서 수집된 데이터와 실제 농가/축사에서 전송되는 제어 명령어 및 모니터링 데이터는 암호화 프로토콜 (예: TLS/DTLS) 을 사용하여 보안 경계를 통과한다. |
| **근거(Rationale)** | IoT 환경은 공격 표면이 넓기 때문에 ISO/IEC 30141:2024 및 TTA 표준에서 강조하는 보안을 필수로 적용해야 한다. 특히 '수확물 저하요인 분석' 데이터를 외부로 유출되지 않도록, 데이터가 AI 학습 서버로 이동할 때 암호화 처리가 선행되어야 함. 문서에 언급된 ITU-T X.1352(보안요구) 를 준수하는 것이 시스템 신뢰성의 기초가 된다. |
| **결과(Consequences)** | **긍정적:** 데이터 유출 및 불법 제어 명령어 주입 위험이 줄어들어 농가 신뢰도가 향상된다.<br>**부정적:** 암호화 오버헤드로 인한 처리 속도 저하 및 시스템 부하 발생 가능성 (대역폭 감소). |
| **트레이드오프(Trade-offs)** | 암호화 강도를 높이기 위해 처리 속도가 약간 느려지더라도, 데이터 무결성과 기밀성을 최우선으로 확보한다. |

## ⚠️ 잠재적 위험 분석

### 1. [비교적 환경 데이터 수집의 불완전성 및 편향]
- **설명:** 온도, 습도, CO2 등의 센서 데이터와 곰팡이 발생 데이터가 완벽하게 수집되지 않거나, 특정 농가의 특수한 환경 (예: 축사 구조 차이, 지역 기후 특성) 이 학습 모델에 반영되지 않으면 AI 가 잘못된 제어 명령을 내릴 수 있다. 이는 실제 농업 현장에서 모델의 일반화 성능이 떨어지는 결과를 초래한다.
- **심각도:** 🔴 High (모델이 잘못된 판단을 내릴 경우 작물 손실 또는 동물 사망 위험)
- **발생 가능성:** 🟡 Medium (데이터 부족 또는 노이즈로 인해 발생할 수 있음)
- **대응 방안:** 초기 데이터 수집 시 다중 센서 보정 및 외부 참조 데이터 (Weather API 등) 를 결합하여 데이터 품질을 높이고, TTA 표준 중 '스마트 축사환경 데이터 모니터링 시스템' 규격에 맞춰 데이터 품질 관리를 강화한다.

### 2. [네트워크 연결 불안정성 (Edge Latency)]
- **설명:** 이미지에서 AI 학습이 플랫폼 단계에서 수행되고, 실제 제어는 스마트팜 보급 단계를 거친다는 점을 고려할 때, 농가/축사의 네트워크 연결이 불안정하면 AI 가 실시간 제어를 할 수 없게 된다. 이는 '동종호조 (Feed Conversion Ratio) UP' 같은 실시간 최적화 기능을 마비시킬 수 있다.
- **심각도:** 🟡 Medium (제어 실패로 인한 환경 악화 가능성)
- **발생 가능성:** 🔴 High (농촌/축사 지역 인터넷 통신 불안정성)
- **대응 방안:** 에지 노드 (AI 기어) 로 오프라인에서도 로컬 모델이 일정 시간 동안 제어를 수행하도록 로컬 캐싱 및 오프라인 AI 추론 기능을 도입한다. 관련 문서는 TTA의 '에지 기반 스마트 온실 서비스' 표준을 참고하여 로컬 처리 능력을 강화한다.

### 3. [사이버 보안 침해 및 외부 조작]
- **설명:** 이미지 상의 '데이터 암호화'와 'AI' 장치를 공격하여 제어 권한 (이동, 급수, 급료 등) 을 탈취하거나, 센서 데이터를 조작하여 AI 가 잘못된 상태를 인식하게 만들 수 있다. 이는 '곰팡이 ZERO' 목표에 치명적인 위협이다.
- **심각도:** 🔴 High (농가 손실 및 시스템 붕괴)
- **발생 가능성:** 🟡 Medium (IoT 보안 위협 증가)
- **대응 방안:** ITU-T X.1352 및 ETSI EN 303 645 표준을 준수하여 디바이스 인증, 네트워크 분할, 그리고 '데이터 암호화'를 통한 보안 채널 구축을 강력히 시행한다. 하드웨어层面的 인증 (Authenticity) 기능을 도입한다.

### 4. [센서 노화 및 오작동으로 인한 오제어]
- **설명:** 이미지에서 센서 (온도계, 습도계 등) 가 입력 데이터의 원천이다. 축사 환경 (먼지, 고습도, 진동) 에 노출된 센서는 수명을 다하거나 오작동하여 거짓 데이터를 AI 에 제공할 수 있다. 이는 '수확물 저하요인 분석'의 정밀도를 떨어뜨린다.
- **심각도:** 🟡 Medium (일시적 제어 오류)
- **발생 가능성:** 🔴 High (물리적인 장치 고장 가능성)
- **대응 방안:** 센서 교정 주기 자동화 및 다중 센서 센서 퓨전 (Sensor Fusion) 기술을 적용하여 특정 센서 오류를 자동 필터링한다. 표준화 지침 (예: KSP.etri) 에 맞춰 센서 설치 및 유지보수 규격을 명시한다.

### 5. [AI 학습 결과의 실제 환경 적용 난이도 (Deployment Gap)]
- **설명:** 이미지 하단에 언급된 '빅데이터를 활용한 동종호조 전 주기 제어'는 복잡한 과정이다. 플랫폼에서 학습된 모델이 실제 다양한 규모의 스마트팜 환경에 적용될 때, 스케일링 문제 (하드웨어 용량, 에너지 소비) 가 발생할 수 있다.
- **심각도:** 🟡 Medium (시스템 확장성 문제)
- **발생 가능성:** 🟡 Medium (규모가 커질수록 발생 가능성 증가)
- **대응 방안:** 컨테이너화를 통해 AI 모델 배포를 용이하게 하고, 하드웨어 사양을 표준화하여 호환성을 확보한다. TTA의 '스마트 축사 환경 제어 인터페이스' 표준화를 준수하여 시스템의 확장성을 확보한다.
