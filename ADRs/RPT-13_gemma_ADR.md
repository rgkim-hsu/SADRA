# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 이기종 데이터 통합을 위한 표준화된 시맨틱 모델링 계층 도입

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 디지털 트윈 시스템은 **GIS/BIM/3D-CAD** (정적 공간 구조), **Simulation Model** (동적 행위 로직), **Operation Data** (실시간 물리 데이터)라는 세 가지 근본적으로 다른 이기종(Heterogeneous) 소스의 데이터를 통합해야 합니다. 이들 데이터는 시간 단위, 데이터 형식, 지오메트리 표현 방식에서 큰 차이를 보이므로, 단순 데이터 결합을 넘어선 '의미적(Semantic)' 통합이 필수적입니다. |
| **결정(Decision)** | 시스템의 중앙 통합 게이트웨이(Gateway) 역할을 수행하는 **표준화된 시맨틱 모델링 계층(Semantic Modeling Layer)**을 핵심 컴포넌트로 정의하고, 모든 입력 데이터는 이 계층의 공통 데이터 모델(Canonical Data Model)을 통해 변환(Transformation)되어야 합니다. 또한, 데이터 수집 단계에서는 표준 프로토콜(MQTT, OPC UA 등) 및 산업 참조 아키텍처(ISO/IEC 30141) 준수를 의무화합니다. |
| **근거(Rationale)** | 1. **데이터 이질성 해소:** 시맨틱 계층은 '온도'와 같은 물리량을 단순히 전달하는 것을 넘어, 해당 온도가 '어느 장비', '어느 공간', '어떤 시간'에 측정된 것인지의 **의미와 맥락(Context)**을 부여합니다. 2. **재사용성 및 표준화:** 표준 모델을 사용함으로써, 향후 시스템에 새로운 센서나 기능을 추가할 때 전체 아키텍처를 재설계할 필요 없이 모듈 형태로 확장할 수 있습니다. 3. **모델링 기반 설계:** 이는 궁극적으로 `DT Formalism`의 역할을 소프트웨어 아키텍처 레벨에서 구현하여, 시스템의 견고성과 확장성을 보장합니다. |
| **결과(Consequences)** | **긍정적:** 시스템의 상호운용성(Interoperability)이 극대화되고, 예측 모델의 신뢰성이 높아집니다. 표준화된 데이터셋은 ML 기반 검증(Validation)의 학습 효율을 높입니다. **부정적:** 초기 아키텍처 설계 및 통합 과정에 막대한 시간과 비용(데이터 매핑 및 표준 정의 작업)이 요구됩니다. |
| **트레이드오프(Trade-offs)** | **장점:** 매우 높은 수준의 시스템 유연성, 확장성, 그리고 이종 산업 간의 지식 공유가 가능합니다. **단점:** 초기 구축 난이도가 매우 높고, 모든 데이터 소스가 표준 모델을 준수하도록 강제하여 레거시 시스템과의 연결에 추가적인 커스텀 인터페이스 레이어(Adapter)가 필요할 수 있습니다. |

## ⚠️ 잠재적 위험 분석

### 1. 실시간 데이터 지연(Latency) 및 동기화 불일치
- **설명:** 물리적 시스템에서 발생한 실시간 오퍼레이션 데이터(Operation Data)가 시맨틱 모델링 계층을 통과하고 시뮬레이션 엔진에 도달하는 과정에서 네트워크 지연(Jitter)이나 데이터 처리 병목 현상이 발생하여, DT가 물리적 현실을 실시간으로 반영하지 못하는 상황. (예: 장비가 이미 고장 난 후, DT가 이를 몇 초 뒤에 감지함.)
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 에지 컴퓨팅(Edge Computing) 아키텍처를 도입하여, 고빈도/저지연 데이터 처리 및 이상 탐지 로직을 클라우드(Cloud)가 아닌 현장(Field)의 엣지 게이트웨이에서 처리합니다. 데이터 스트리밍 플랫폼(예: Kafka)을 활용하여 백프레셔(Backpressure)를 관리하고, QoS(Quality of Service) 기반의 우선순위 할당을 적용합니다.

### 2. 데이터 보안 취약점 및 사이버 공격 노출 (OT/IT 융합)
- **설명:** DT 시스템은 공정 제어 시스템(OT: Operational Technology)과 정보 시스템(IT: Information Technology)이 연결되므로, 한쪽의 보안 취약점이 전체 시스템을 마비시킬 수 있습니다. 외부 네트워크를 통해 물리적 장비의 제어 신호가 악용될 위험이 존재합니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 망 분리(Network Segmentation)를 최우선 원칙으로 하며, OT와 IT 영역 간의 통신은 반드시 산업용 방화벽(Industrial Firewall)을 통해 게이트웨이로만 허용합니다. 모든 데이터 교환 지점에는 무결성 검증 및 암호화(TLS/DTLS)를 의무 적용하고, 접근 통제 시스템(IAM)을 강화합니다.

### 3. 모델링 데이터의 해석적 불일치 (Semantic Ambiguity)
- **설명:** 서로 다른 분야의 전문 엔지니어(건축가, 기계 엔지니어, 데이터 과학자)가 각자의 관점에서 모델링한 데이터(BIM vs. Simulation Model)가 공통 시맨틱 모델에서 충돌하거나 모호하게 해석될 수 있습니다. (예: 한 모델은 '최대 허용 온도'를 규정하지만, 다른 모델은 '측정된 최대 온도'만 보고하는 경우).
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 아키텍처 초기에 공학 및 도메인 전문가를 포함한 **'데이터 거버넌스 위원회(Data Governance Committee)'**를 조직하여, 모든 모델링 및 용어 정의(Ontology)를 사전에 검토하고 최종 승인하는 프로세스를 구축해야 합니다. 국제 표준(ISO/IEC 30141)의 개념 정의를 적극적으로 차용해야 합니다.

### 4. 시스템 확장성 및 기술 부채 누적
- **설명:** 시스템이 성공적으로 운영됨에 따라 새로운 기능과 데이터 소스가 지속적으로 추가될 경우, 처음 정의된 아키텍처 틀을 벗어나는 비정형적 커스터마이징(Ad-hoc Integration)이 증가하여 시스템의 유지보수 비용이 기하급수적으로 증가하는 기술 부채가 발생합니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low (시간 경과에 따라 증가)
- **대응 방안:** 모든 기능 추가 요청 시, 반드시 중앙화된 서비스 메시(Service Mesh)를 통해 기존 API 게이트웨이를 경유하도록 강제하고, 아키텍처 변화 관리(Architecture Change Management) 프로세스를 의무화합니다. 마이크로서비스 아키텍처(MSA) 패턴을 채택하여 기능 단위의 독립적 배포를 보장해야 합니다.

### 5. 시뮬레이션 모델과 물리 현실 간의 괴리 (Model Drift)
- **설명:** 환경 변화, 설비 노후화, 운영 조건 변화 등으로 인해 사전에 정의된 Simulation Model의 가정(Assumption)이 실제 물리적 환경(Operation Data)과 괴리되는 '모델 드리프트'가 발생하여, 시스템이 출력하는 예측 데이터(Simulation Data)의 신뢰성이 떨어지는 현상.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 예측 데이터가 실제 물리적 상태에 미치는 영향을 지속적으로 측정하는 **지속적 검증 루프(Continuous Validation Loop)**를 설계해야 합니다. 머신러닝 기반 검증(ML-based Validation)에 휴리스틱 검사(Heuristic Check) 및 도메인 지식 기반의 이상치 탐지 알고리즘을 필수로 결합하여, 예측 결과가 물리적으로 말이 되는지(Plausibility Check)를 상시 확인합니다.
