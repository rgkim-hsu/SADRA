### ADR-001: 스마트팜 원격 제어 기반 중앙 관제 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                          |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 이미지의 시스템은 스마트팜 재배 환경(100), 환경 센서 및 제어 장치(110, 120), 게이트웨이(400), 서버(300), 사용자 모바일 단말(200), 제어 시스템(500, 600)으로 구성된다. 시스템은 재배 농장 정보를 수집하고, 이를 서버와 사용자 단말로 전달하며, 원격 환경 제어까지 수행해야 한다. 스마트팜 환경 특성상 실시간 모니터링과 안정적인 원격 제어가 핵심 과제이다. |
| **결정(Decision)**       | 중앙 서버 기반 스마트팜 통합 관제 구조를 채택한다. 현장 센서 및 제어 장치는 게이트웨이(400)를 통해 데이터를 수집하며, 서버(300)는 데이터 저장·분석·제어 정책 관리를 담당한다. 사용자 모바일 단말(200)은 서버 API를 통해 상태 조회 및 원격 제어 명령을 수행한다.                                                               |
| **근거(Rationale)**      | 중앙 서버 구조는 다수 농장 및 다수 장비를 통합 관리하기에 적합하며, 데이터 분석 및 AI 기반 환경 최적화 기능을 확장하기 쉽다. 또한 사용자 단말은 직접 농장 장치에 연결하지 않고 서버를 경유함으로써 보안성과 관리 효율을 높일 수 있다.                                                                                     |
| **결과(Consequences)**   | 통합 데이터 관리 및 원격 운영 효율성이 향상된다. 사용자 접근성이 높아지고 데이터 기반 자동화가 가능해진다. 반면 서버 장애 시 전체 서비스 영향 범위가 커질 수 있으며, 네트워크 의존성이 증가한다.                                                                                                            |
| **트레이드오프(Trade-offs)** | 중앙 집중형 관리와 데이터 분석 효율성을 얻는 대신, 서버 인프라 비용 및 고가용성(HA) 설계 부담이 증가한다.                                                                                                                                                             |

### ADR-002: 센서 기반 자동 환경 제어 구조 적용

| 항목                     | 내용                                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 재배 시설 내부에는 다수의 작물과 환경 제어 장치가 존재하며, 온도·습도·조도·토양 상태 등에 따라 자동 제어가 필요하다. 수작업 기반 관리 방식은 생산성과 품질 편차 문제를 초래할 수 있다. |
| **결정(Decision)**       | 환경 센서(110)와 제어 장치(120)를 연동한 자동 제어 구조를 채택한다. 제어 시스템(600)은 센서 데이터를 기반으로 환기, 급수, 조명, 냉난방 장치를 자동 제어한다.          |
| **근거(Rationale)**      | 스마트팜은 데이터 기반 환경 최적화가 핵심이며, 실시간 센서 기반 제어를 통해 작물 생육 환경을 안정적으로 유지할 수 있다. 이는 생산량 향상과 품질 균일화에 효과적이다.             |
| **결과(Consequences)**   | 작물 생육 품질이 향상되고 인력 의존도가 감소한다. 자동화 수준이 높아지며 운영 효율성이 증가한다. 그러나 센서 오작동 시 잘못된 제어가 발생할 수 있다.                      |
| **트레이드오프(Trade-offs)** | 자동화와 생산성 향상을 얻는 대신, 센서 유지보수 및 보정 비용이 증가한다.                                                                  |

### ADR-003: 모바일 기반 원격 사용자 인터페이스 채택

| 항목                     | 내용                                                                                                       |
| ---------------------- | -------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 농장 관리자는 현장 상주 없이 스마트폰을 통해 재배 상태를 확인하고 제어할 필요가 있다. 특히 다수 농장을 운영하는 경우 원격 접근성이 중요하다.                        |
| **결정(Decision)**       | 모바일 단말(200)을 중심으로 한 원격 모니터링 및 제어 인터페이스를 제공한다. 서버(300)는 REST API 또는 MQTT 기반 Push 서비스를 통해 실시간 상태 정보를 제공한다. |
| **근거(Rationale)**      | 모바일 기반 운영은 사용자 접근성과 실시간 대응 능력을 향상시킨다. 또한 알림 기반 이벤트 관리가 가능해져 장애 대응 속도를 높일 수 있다.                           |
| **결과(Consequences)**   | 사용자 편의성과 운영 효율이 향상된다. 실시간 알람 및 상태 모니터링이 가능해진다. 반면 모바일 앱 보안 및 인증 관리 중요성이 증가한다.                            |
| **트레이드오프(Trade-offs)** | 운영 편의성을 얻는 대신, 모바일 보안 및 API 관리 복잡성이 증가한다.                                                                |

### ADR-004: 게이트웨이 기반 Edge 수집 구조 채택

| 항목                     | 내용                                                                                      |
| ---------------------- | --------------------------------------------------------------------------------------- |
| **상황(Context)**        | 농장 내부 장비는 다양한 프로토콜과 센서 인터페이스를 사용하며, 이를 직접 서버와 연결할 경우 네트워크 및 관리 복잡도가 증가한다.               |
| **결정(Decision)**       | 게이트웨이(400)를 Edge 수집 계층으로 사용하여 현장 장치 데이터를 집계하고 전처리 후 서버로 전달한다.                           |
| **근거(Rationale)**      | 게이트웨이 계층은 프로토콜 변환, 로컬 캐싱, 장애 완충 역할을 수행할 수 있어 시스템 안정성을 향상시킨다.                            |
| **결과(Consequences)**   | 네트워크 부하 감소 및 장치 관리 효율이 향상된다. 현장 장애 격리가 가능해진다. 그러나 게이트웨이 장애 시 해당 농장 전체 데이터 수집이 중단될 수 있다. |
| **트레이드오프(Trade-offs)** | 확장성과 안정성을 확보하는 대신, Edge 장비 운영 및 유지보수 비용이 추가된다.                                          |

⚠️ 잠재적 위험 분석
------------

### 1. 중앙 서버 장애 위험

* **설명:** 서버(300) 장애 발생 시 전체 농장 모니터링 및 제어 기능이 중단될 수 있음

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 이중화(HA) 서버 구성, 클러스터링 및 자동 Failover 구조 적용

### 2. 센서 데이터 오류 위험

* **설명:** 환경 센서(110)의 오작동이나 보정 실패로 인해 잘못된 제어 명령이 수행될 수 있음

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 센서 이중화, 주기적 Calibration 수행, 이상치 탐지 알고리즘 적용

### 3. 모바일 원격 제어 보안 취약점

* **설명:** 인증 우회 또는 계정 탈취 발생 시 외부 공격자가 농장 환경을 조작할 수 있음

* **심각도:** 🔴 High

* **발생 가능성:** 🔴 High

* **대응 방안:** MFA 인증, OAuth2 기반 인증 체계, TLS 암호화 및 접근 로그 감사 적용

### 4. 게이트웨이 네트워크 단절 위험

* **설명:** 게이트웨이(400)와 서버 간 통신 장애 시 데이터 수집 및 제어 전달이 중단될 수 있음

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 로컬 캐시 및 Store-and-Forward 구조 적용, 이중 네트워크 회선 구성

### 5. 환경 제어 장치 오작동 위험

* **설명:** 급수 장치나 환기 시스템이 오작동하면 작물 피해 또는 에너지 낭비가 발생할 수 있음

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** Fail-safe 릴레이 적용, 수동 Override 기능 제공, 상태 모니터링 강화

### 6. 데이터 저장소 과부하 위험

* **설명:** 장기간 센서 데이터 축적 시 서버 저장소 및 DB 성능 저하가 발생할 수 있음

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 시계열 DB 적용, 데이터 압축 및 보관 주기 정책 수립

### 7. 스마트팜 현장 환경으로 인한 장비 손상 위험

* **설명:** 습기, 고온, 먼지로 인해 게이트웨이 및 센서 장비의 수명이 단축될 수 있음

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 산업용 등급 하드웨어 적용, 방수·방진(IP65 이상) 설계 및 정기 점검 수행
