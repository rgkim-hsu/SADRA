📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: DDPG 기반 강화학습 에이전트를 활용한 온실 환경 자율 제어 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                             |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 토마토 온실 환경(온도, 습도, CO₂, 광량 등)은 기상 변화와 작물 생육 단계에 따라 연속적으로 변화하는 복잡한 동적 시스템이다. 기존 인간 전문가(Human experts) 의존 방식은 24시간 모니터링 한계와 의사결정 지연으로 인해 최적 환경 유지가 어렵고, 규칙 기반 제어는 비선형적 환경 변화에 대응하기 어렵다. 이에 따라 연속적 행동 공간(action space)에서 최적 제어 정책을 학습할 수 있는 알고리즘 선택이 핵심 과제로 도출되었다. |
| **결정(Decision)**       | 강화학습 알고리즘으로 DDPG(Deep Deterministic Policy Gradient)를 채택하고, Actor-Critic 이중 DNN 구조를 통해 온실 환경 제어 Agent를 구현한다. 실제 온실 대신 Greenhouse Library KR 기반의 시뮬레이션 가상 환경(Virtual Learning Environment)을 구축하여 Agent를 사전 훈련한다. 기상 예보(Weather Forecast) 데이터를 외부 입력으로 통합한다.     |
| **근거(Rationale)**      | DDPG는 연속적 행동 공간을 직접 다루는 Actor-Critic 방식으로, 온도 설정값·환기량 등 연속형 제어 출력에 최적화되어 있다. DQN 계열 대비 연속 제어 정밀도가 높으며, 시뮬레이션 기반 사전 학습은 실제 작물 피해 위험 없이 충분한 탐색(exploration)을 가능하게 한다. Greenhouse Library KR은 국내 온실 환경 특성이 반영된 표준 시뮬레이터로 도메인 적합성이 높다.                             |
| **결과(Consequences)**   | (긍정) 인간 전문가 없이 24시간 자율 최적 제어 가능, 에너지 효율 향상, 작물 품질 균일성 증가. (부정) 시뮬레이션과 실제 환경 간 도메인 갭(Sim-to-Real Gap) 발생 가능성 존재, Actor/Critic 두 네트워크의 하이퍼파라미터 튜닝 복잡도 증가, 초기 훈련 수렴까지 장기간 소요.                                                                                     |
| **트레이드오프(Trade-offs)** | (얻는 것) 연속 공간 제어 정밀도, 안전한 오프라인 사전 학습, 확장 가능한 정책 구조. (감수할 것) 시뮬레이터 정확도에 대한 높은 의존성, 실환경 미세 조정(fine-tuning) 필수, 블랙박스 모델 특성으로 인한 제어 결정의 해석 가능성(explainability) 저하.                                                                                                  |

⚠️ 잠재적 위험 분석
------------

### 1. Sim-to-Real 도메인 갭으로 인한 제어 성능 저하

* **설명:** Greenhouse Library KR 시뮬레이터에서 학습한 정책이 실제 온실의 센서 노이즈, 열 전달 비선형성, 외부 기상 변동 등 미모델링(unmodeled) 요소로 인해 실환경 배포 시 예측과 다른 제어 출력을 생성하여 작물 생육에 직접적 피해를 야기할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** Domain Randomization 기법을 시뮬레이터에 적용하여 다양한 환경 파라미터 변동 학습; 실환경 소량 데이터를 활용한 Transfer Learning 및 Online Fine-tuning 파이프라인 구성; 실환경 초기 배포 시 Human-in-the-loop 감독 모드 운영.

### 2. Agent 오작동 시 안전 장치(Safety Mechanism) 부재

* **설명:** DDPG Agent가 비정상적인 보상 신호(reward)나 상태 공간 이탈로 인해 과도한 난방·환기·관개 명령(action)을 실행할 경우, 온실 내 극단적 온도 변화나 과습으로 작물 전체가 고사하는 치명적 사고가 발생할 수 있다. 개념도에 안전 제한 레이어가 명시적으로 표현되어 있지 않다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 각 제어 출력(action)에 물리적 상한/하한 클리핑(action clipping) 레이어 추가; 독립적인 Rule-based Safety Monitor를 Agent와 Actuator 사이에 삽입하여 이상 명령 차단; 이상 탐지 시 자동으로 전문가 규칙 기반 폴백(fallback) 모드 전환.

### 3. 기상 예보 데이터 품질 및 연결 장애

* **설명:** Weather Forecast 데이터가 Agent의 상태(state) 입력으로 활용되는 구조에서, 외부 기상 API 장애·예보 오차·통신 단절이 발생할 경우 Agent가 불완전한 상태 정보를 기반으로 잘못된 제어 정책을 실행하거나 시스템 전체가 정지될 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 기상 데이터 결측 시 로컬 기상 센서 데이터로 자동 대체하는 Fallback 데이터 파이프라인 구성; 예보 불확실성을 상태 입력의 추가 피처로 인코딩; 기상 데이터 없이도 작동 가능한 축소 정책(degraded policy) 사전 학습.

### 4. Actor-Critic 네트워크 학습 불안정성(Training Instability)

* **설명:** DDPG는 off-policy 학습 특성상 Replay Buffer 구성, 타깃 네트워크 업데이트 주기, 탐색 노이즈(Exploration Noise) 설정에 민감하여 학습 중 Q값 과대 추정(overestimation) 및 정책 붕괴(policy collapse)가 발생할 수 있다. 특히 온실 환경처럼 보상 신호가 희소(sparse reward)한 경우 수렴 실패 가능성이 높아진다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** TD3(Twin Delayed DDPG) 또는 SAC(Soft Actor-Critic)로 알고리즘 업그레이드 검토; Reward Shaping을 통한 밀집 보상 신호 설계; 학습 곡선 모니터링 대시보드 구축 및 체크포인트 기반 롤백 자동화.

### 5. 센서 데이터 위변조 및 사이버 보안 취약성

* **설명:** 온실 내 IoT 센서에서 Agent로 전달되는 state(온도·습도·CO₂ 등) 데이터가 네트워크 구간에서 위변조되거나, 외부 공격자가 악의적인 센서 값을 주입(Adversarial Input Attack)할 경우 Agent가 의도적으로 조작된 환경 인식을 바탕으로 작물에 피해를 주는 제어 명령을 실행할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟢 Low
* **대응 방안:** 센서-Agent 통신 구간 TLS 암호화 및 디바이스 인증 적용; 다중 센서 교차검증(Cross-validation)을 통한 이상 센서값 탐지 로직 구현; OWASP IoT 보안 가이드라인 및 IEC 62443 산업제어시스템 보안 표준 준수; 정기적인 침투 테스트 수행.

### 6. 모델 드리프트(Model Drift)로 인한 장기 운영 성능 저하

* **설명:** 작물 생육 단계 변화, 계절적 환경 패턴 변화, 온실 구조 노후화 등으로 인해 초기 학습 시점의 환경 분포와 실제 운영 시점의 환경 분포가 점진적으로 달라지면서 Agent의 정책 성능이 시간이 지남에 따라 지속적으로 저하될 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 제어 성능 KPI(작물 수율, 에너지 소비량) 지속 모니터링 및 드리프트 감지 알고리즘 도입; 주기적 온라인 재학습(Continual Learning) 스케줄 수립; 생육 단계별 특화 정책 앙상블 운용 및 자동 정책 전환 로직 구현.

* **심각도:** 🔴 High
* **발생 가능성:** 🟢 Low
* **대응 방안:** 센서-Agent 통신 구간 TLS 암호화 및 디바이스 인증 적용; 다중 센서 교차검증(Cross-validation)을 통한 이상 센서값 탐지 로직 구현; OWASP IoT 보안 가이드라인 및 IEC 62443 산업제어시스템 보안 표준 준수; 정기적인 침투 테스트 수행.
