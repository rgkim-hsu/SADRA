## 📋 ADR (Architecture Decision Record)

### **ADR-001: 중앙 집중형 데이터 처리 아키텍처 채택 및 모듈화 설계**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 **스마트팜/축산 환경 모니터링 및 생육 정보 제공**을 목적으로 하며, 이미지 제공 모듈(100), 생육정보 산출 모듈(200), 사용자 단말(400), 영농정보 데이터베이스(400), 기반정보 데이터베이스(300)로 구성된 **데이터 중심 아키텍처**가 요구됨. 현재 시스템은 **이미지 기반 생육 데이터 추출 및 분석**을 핵심 기능으로 하며, **실시간 데이터 처리**와 **이력 관리**가 필수적임. |
| **결정(Decision)** | 1. **모듈화 아키텍처** 채택: 이미지 제공 모듈, 생육정보 산출 모듈, 데이터베이스 계층을 **독립적 모듈**로 분리하여 **재사용성**과 **유지보수성**을 높임.<br>2. **중앙 집중형 데이터 처리**: 모든 생육정보를 **영농정보 데이터베이스(400)**에 집중 처리하여 **일관성**과 **신뢰성**을 보장함.<br>3. **기반정보 데이터베이스(300)**를 참조 데이터로 활용하여 **정합성**을 유지함.<br>4. **사용자 단말(400)**과 **생육정보 산출 모듈(200)** 간의 **API 기반 통신**을 도입하여 **확장성**을 확보함. |
| **근거(Rationale)** | - **ISO/IEC 30141:2024** 표준에 따라 **모듈화**와 **데이터 중심 아키텍처**가 권장됨.<br>- **oneM2M** 및 **ETSI EN 303 645** 표준에 따라 **중앙 집중형 데이터 처리**가 보안과 일관성을 보장하는 대표적인 패턴임.<br>- **TTA 단체 표준**에서 정의한 **스마트팜 데이터 상호운용 프레임워크** 요구사항에 부합함.<br>- **IEEE 2413** 표준에 따라 **모듈 간 API 표준화**가 시스템 확장성을 높임. |
| **결과(Consequences)** | ✅ **장점**:<br>- 모듈화로 인한 **유지보수 용이성** 및 **재사용성** 향상.<br>- 중앙 집중형 데이터 처리로 **데이터 일관성**과 **신뢰성** 강화.<br>- API 기반 통신으로 **확장성**과 **상호운용성** 보장.<br>- 기반정보 데이터베이스 활용으로 **정합성** 및 **성능** 향상.<br>❌ **단점**:<br>- 중앙 집중형 처리로 인한 **단일 장애점(SPOF) 위험** 발생 가능.<br>- 모듈 간 통신 지연으로 **실시간 처리 성능**에 영향을 줄 수 있음. |
| **트레이드오프(Trade-offs)** | - **모듈화 vs. 성능**: 모듈화로 인한 **유지보수성** 향상 vs. **통신 오버헤드** 발생.<br>- **중앙 집중형 vs. 분산 처리**: **데이터 일관성** 보장 vs. **단일 장애점(SPOF) 위험**.<br>- **API 표준화 vs. 구현 복잡성**: **상호운용성** 향상 vs. **추가 개발 노력** 필요. |

### **ADR-002: 실시간 데이터 처리 및 캐싱 전략**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 **이미지 기반 생육 정보 추출**을 실시간으로 수행해야 하며, **사용자 단말(400)**이 **저지연 응답**을 요구함. 현재 **생육정보 산출 모듈(200)**은 **이미지 처리**와 **데이터 분석**을 병렬로 수행해야 함. |
| **결정(Decision)** | 1. **생육정보 산출 모듈(200)**에 **실시간 처리 엔진** 도입 (예: **Kafka** 또는 **Apache Flink**).<br>2. **영농정보 데이터베이스(400)**에 **캐싱 계층** 추가 (예: **Redis**)하여 **반복적인 데이터 접근** 성능 향상.<br>3. **이미지 제공 모듈(100)**과 **생육정보 산출 모듈(200)** 간 **비동기 처리**를 도입하여 **응답 시간** 최적화. |
| **근거(Rationale)** | - **IETF CoAP/MQTT** 프로토콜을 활용한 **경량 실시간 통신**이 IoT 시스템에서 표준으로 사용됨.<br>- **ISO/IEC 30141:2024**에서 **실시간 데이터 처리**가 **스마트팜 시스템**의 핵심 요구사항으로 명시됨.<br>- **TTA 스마트팜 데이터 관리 요구사항**에서 **캐싱 및 비동기 처리**가 성능 최적화에 필수적임. |
| **결과(Consequences)** | ✅ **장점**:<br>- **실시간 데이터 처리**로 **사용자 응답 시간** 단축.<br>- **캐싱 계층**으로 **데이터베이스 부하** 감소.<br>- **비동기 처리**로 **시스템 확장성** 향상.<br>❌ **단점**:<br>- **캐싱 일관성** 관리 복잡성 증가.<br>- **실시간 처리 엔진** 운영 및 모니터링 비용 발생. |
| **트레이드오프(Trade-offs)** | - **실시간 처리 vs. 복잡성**: **저지연 응답** vs. **운영 복잡성** 증가.<br>- **캐싱 vs. 데이터 일관성**: **성능 향상** vs. **캐싱 관리 비용**. |

### **ADR-003: 보안 아키텍처 및 데이터 암호화**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 **스마트팜 환경**에서 **기밀성**, **무결성**, **가용성**을 보장해야 하며, **IoT 보안 표준** (예: **ITU-T X.1352**, **ETSI EN 303 645**) 준수 필요. |
| **결정(Decision)** | 1. **모듈 간 통신**에 **TLS 1.3** 적용.<br>2. **영농정보 데이터베이스(400)**에 **데이터 암호화** (예: **AES-256**) 적용.<br>3. **사용자 인증**에 **OAuth 2.0** 및 **JWT** 도입.<br>4. **로그 관리**를 위한 **KISA 보안 기준** 준수. |
| **근거(Rationale)** | - **ITU-T X.1352** 및 **ETSI EN 303 645** 표준에서 **TLS 암호화**와 **인증 메커니즘**이 필수적임.<br>- **ISO/IEC 27030:2020**에서 **IoT 기기 보안**에 대한 **암호화 및 인증** 요구사항 명시.<br>- **KISA**가 제안한 **IoT 보안 시험 기준**에 따라 **로그 관리**가 필수적임. |
| **결과(Consequences)** | ✅ **장점**:<br>- **데이터 보안** 강화.<br>- **규제 준수** 확보.<br>- **사용자 인증** 강화.<br>❌ **단점**:<br>- **암호화 처리**로 인한 **성능 오버헤드** 발생.<br>- **인증 관리** 복잡성 증가. |
| **트레이드오프(Trade-offs)** | - **보안 vs. 성능**: **암호화 적용** vs. **처리 속도 저하**.<br>- **규제 준수 vs. 구현 복잡성**: **표준 준수** vs. **추가 개발 노력**. |

## ⚠️ 잠재적 위험 분석

### **1. 중앙 집중형 데이터베이스 단일 장애점(SPOF) 위험**
- **설명**: **영농정보 데이터베이스(400)**가 **중앙 집중형**으로 운영되면, 데이터베이스 장애 시 **전체 시스템 마비** 발생 가능. 특히 **스마트팜 환경**에서 **실시간 데이터 처리**가 중단되면 **생육 정보 손실** 및 **재해 발생** 위험 증가.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **데이터베이스 복제(Replication)** 및 **클러스터링** 도입 (예: **PostgreSQL Streaming Replication**).
  - **백업 데이터베이스**를 **지리적으로 분산** 배치.
  - **자동 장애 복구(Automatic Failover)** 메커니즘 구현.

### **2. 모듈 간 통신 지연으로 인한 실시간 처리 성능 저하**
- **설명**: **이미지 제공 모듈(100)**과 **생육정보 산출 모듈(200)** 간 **API 통신 지연**으로 인해 **실시간 데이터 처리** 지연 발생. 특히 **고해상도 이미지** 처리 시 **네트워크 병목** 발생 가능.
- **심각도**: 🟡 Medium | **발생 가능성**: 🔴 High
- **대응 방안**:
  - **비동기 처리** 및 **이벤트 드리븐 아키텍처** 도입 (예: **Kafka**).
  - **지역 캐싱**을 통해 **반복적인 데이터 접근** 최적화.
  - **이미지 전처리** (예: **Edge Computing**)를 통해 **데이터 크기 감소**.

### **3. 데이터 일관성 관리 복잡성 증가**
- **설명**: **캐싱 계층**과 **중앙 데이터베이스** 간 **일관성 관리**가 복잡해질 수 있으며, **캐시 무효화(Cache Invalidation)** 오류로 **부정합 데이터** 발생 가능.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **강 일관성(Strong Consistency)** 모델 채택 (예: **Redis Cluster**).
  - **분산 트랜잭션 관리** 도구 도입 (예: **Saga Pattern**).
  - **데이터 버전 관리**를 통한 **일관성 검증**.

### **4. 보안 취약점 및 규정 불이행 위험**
- **설명**: **IoT 보안 표준** (예: **ETSI EN 303 645**) 미준수로 인해 **사이버 공격** 또는 **규제 위반** 발생 가능. 특히 **인증/암호화** 미구현 시 **데이터 유출** 위험 증가.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **정기 보안 감사** 및 **취약점 스캔** 수행.
  - **KISA 보안 기준** 준수 **인증** 획득.
  - ** zero-trust 아키텍처** 도입.

### **5. 확장성 제한으로 인한 시스템 과부하**
- **설명**: **중앙 집중형 처리**로 인해 **시스템 확장성**이 제한될 수 있으며, **사용자 증가** 시 **성능 저하** 발생 가능. 특히 **스마트팜 확산**으로 **데이터 처리량** 급증 시 **시스템 콜라ps** 위험.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **마이크로 서비스 아키텍처**로 **수평 확장** 지원.
  - **클라우드 네이티브 기술** (예: **Kubernetes**) 도입.
  - **로드 밸런싱** 및 **오토 스케일링** 구현.
