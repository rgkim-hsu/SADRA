📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 클라우드 기반 순환형 스마트팜 제어(Closed-loop Control) 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                         |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **상황(Context)**        | 시스템은 Smart Sensing & Monitoring → Smart Analysis & Planning → Smart Control로 이어지는 순환 구조를 가지며, 중앙에는 Cloud 기반 이벤트 및 데이터 관리가 존재한다. 핵심 과제는 “데이터 수집–분석–제어가 반복되는 자동화 루프를 통해 스마트팜 운영을 최적화하는 것”이다. |
| **결정(Decision)**       | 클라우드를 중심으로 데이터 관리 및 이벤트 처리를 수행하고, 센싱 → 분석 → 제어가 반복되는 폐루프(Closed-loop) 구조의 스마트팜 아키텍처를 채택한다.                                                                                                 |
| **근거(Rationale)**      | 스마트팜은 환경 변화에 실시간 대응이 중요하므로, 데이터 기반 자동 제어 루프가 필수적이다. 클라우드는 데이터 통합과 확장성을 제공하며, 지속적인 분석과 피드백을 가능하게 한다.                                                                                        |
| **결과(Consequences)**   | **긍정적:** 자동화된 운영, 실시간 대응, 데이터 기반 최적화, 확장성 확보**부정적:** 네트워크 의존성 증가, 시스템 복잡성 증가                                                                                                               |
| **트레이드오프(Trade-offs)** | 높은 자동화와 효율성을 얻는 대신, 클라우드 및 네트워크 의존성과 시스템 복잡성이 증가한다.                                                                                                                                        |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. 네트워크 의존성

* **설명:** 클라우드 기반 구조로 인해 네트워크 장애 시 시스템 전체 기능 저하

* **심각도:** 🔴 High

* **발생 가능성:** 🔴 High

* **대응 방안:** 엣지 컴퓨팅 도입, 오프라인 제어 fallback 제공

### 2. 데이터 지연(latency)

* **설명:** 클라우드 처리 지연으로 실시간 제어 성능 저하

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 실시간 처리 시스템, 로컬 캐싱 및 엣지 분석

### 3. 분석 모델 오류

* **설명:** 잘못된 분석 결과로 인해 부적절한 제어 수행

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 모델 검증, Human-in-the-loop 적용

### 4. 센서 데이터 오류

* **설명:** 잘못된 입력 데이터로 인해 전체 제어 루프 왜곡

* **심각도:** 🔴 High

* **발생 가능성:** 🔴 High

* **대응 방안:** 데이터 검증 시스템 연계, 센서 이중화

### 5. 보안 문제

* **설명:** 클라우드 및 IoT 환경에서 해킹 및 데이터 유출 가능성

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 암호화, 접근 제어, 보안 모니터링

### 6. 시스템 복잡성 증가

* **설명:** 센싱, 분석, 제어, 클라우드 통합으로 인해 운영 복잡성 증가

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 모듈화 설계, 표준 인터페이스 적용

### 7. 확장 시 비용 증가

* **설명:** 데이터 증가 및 사용자 확대 시 클라우드 비용 상승

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 비용 최적화 전략, 데이터 라이프사이클 관리
