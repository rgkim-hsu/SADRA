### ADR-002: 순환형(Closed-Loop) 피드백 제어 흐름 설계

| 항목                     | 내용                                                                                                                                                                          |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜의 핵심 가치는 단순 모니터링이 아닌 자율 제어(Autonomous Control)이다. Sensing → Analysis → Control → Sensing으로 이어지는 폐루프(Closed-Loop)가 성립해야 하며, 각 단계 간 데이터 포맷과 트리거 조건을 표준화해야 한다.             |
| **결정(Decision)**       | 이벤트 드리븐(Event-Driven) 아키텍처를 기반으로 순환 흐름을 구성한다. Sensing이 임계값 이벤트를 발행(Publish)하면, Analysis가 구독(Subscribe)하여 제어 계획을 수립하고, Control이 실행 후 결과를 다시 Sensing 레이어에 피드백하는 3단계 루프를 정의한다. |
| **근거(Rationale)**      | ① 폴링(Polling) 방식 대비 이벤트 기반 구조는 불필요한 네트워크 트래픽 절감 ② 비동기 처리로 각 도메인의 독립적 처리 속도 보장 ③ 이벤트 로그 보존으로 사후 분석 및 모델 재학습 데이터 확보                                                           |
| **결과(Consequences)**   | (+) 실시간 대응성 향상 및 자동화율 제고 / (+) 각 단계의 처리 이력 추적 가능 / (-) 이벤트 순서 보장(Ordering) 및 중복 처리(Idempotency) 설계 복잡도 증가 / (-) 루프 내 한 단계 지연이 전체 제어 사이클에 영향                                 |
| **트레이드오프(Trade-offs)** | **얻는 것:** 자율 제어 실현, 낮은 커플링, 확장 용이성 / **감수할 것:** 이벤트 브로커(Kafka, MQTT Broker 등) 추가 인프라 필요, 디버깅 복잡성 증가, 이벤트 스톰(Event Storm) 발생 가능성                                             |

⚠️ 잠재적 위험 분석
------------

### 1. 클라우드 단일 장애점(Single Point of Failure)으로 인한 전체 시스템 마비

* **설명:** Cloud-based Event and Data Management가 모든 도메인의 허브 역할을 수행하므로, 클라우드 플랫폼 장애(AWS/Azure 리전 다운, 네트워크 단절) 발생 시 Sensing 데이터 수집 중단, Analysis 불가, Control 명령 전달 불가가 동시에 발생한다. 특히 폭염·한파 등 기상 이변 시 농작물 피해가 즉각적으로 발생할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 엣지 게이트웨이(Edge Gateway)에 로컬 룰 기반 자율 제어 로직(Fallback Mode) 탑재, 클라우드 멀티리전 또는 Active-Active 이중화 구성, 오프라인 시에도 최소 제어(온도·습도 임계 제어)가 동작하는 엣지 컴퓨팅 레이어 추가

### 2. 농장 현장 네트워크 불안정으로 인한 실시간 제어 지연

* **설명:** 농촌 지역 특성상 LTE/5G 및 유선망 품질이 불안정하여 Sensing 데이터가 클라우드에 도달하지 못하거나, Control 명령이 현장 액추에이터에 늦게 전달될 수 있다. 예를 들어 온실 온도가 임계치를 초과했음에도 환기 팬 제어 명령이 수 분간 지연되면 작물 고사로 이어진다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 엣지-클라우드 하이브리드 아키텍처 도입(Edge Computing Layer 추가), 로컬 MQTT 브로커를 현장에 배치하여 클라우드 연결과 무관하게 Sensing↔Control 간 직접 통신 경로 확보, QoS 레벨 설정 및 메시지 큐 버퍼링으로 재전송 보장

### 3. 센서 데이터 무결성 및 오염 데이터로 인한 오제어(False Control)

* **설명:** 온도·습도·CO₂ 등 물리 센서는 노후화, 오염, 보정 오류로 인해 비정상 값을 전송할 수 있다. Smart Analysis & Planning이 이 오염 데이터를 정상으로 판단하여 Smart Control에 잘못된 명령(예: 이미 충분히 관개된 상태에서 추가 관개 명령)을 내리면 작물 피해 또는 자원 낭비가 발생한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 수집 단계에서 이상치 탐지(Z-score, IQR 기반 실시간 필터링) 적용, 동일 측정 항목에 대한 다중 센서 교차 검증(Sensor Fusion), 주기적 센서 교정(Calibration) 스케줄 관리 시스템 구축, 제어 명령 실행 전 유효성 검증 게이트(Validation Gate) 추가

### 4. 클라우드 저장 데이터 및 제어 명령에 대한 사이버 보안 위협

* **설명:** 클라우드 중앙 허브가 공격받을 경우, 공격자는 ① 전체 농장의 환경 데이터 탈취(농업 경쟁 정보 유출), ② 위조된 제어 명령 주입(살충제 과다 살포, 온도 조작)이 가능하다. IoT 디바이스는 펌웨어 업데이트가 불규칙하여 취약점 노출 기간이 길다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 디바이스-클라우드 간 상호 인증(Mutual TLS, X.509 인증서) 적용, 제어 명령에 디지털 서명 및 무결성 검증 의무화, 네트워크 세그멘테이션(OT/IT 분리), 디바이스 취약점 관리를 위한 OTA(Over-The-Air) 펌웨어 업데이트 체계 구축, SIEM 기반 이상 행위 탐지

### 5. AI/ML 분석 모델의 편향 및 과적합으로 인한 의사결정 오류

* **설명:** Smart Analysis & Planning의 예측 모델이 특정 계절·품종·지역 데이터에 과적합될 경우, 새로운 환경 조건(신규 병해충, 기후변화 패턴)에서 오판을 내릴 수 있다. 예를 들어 여름 데이터로만 학습된 모델이 봄철 저온 피해 징후를 정상으로 분류하는 상황이 발생할 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 모델 학습 데이터의 계절·품종·지역 다양성 확보(Data Augmentation), MLOps 파이프라인 구축으로 모델 드리프트(Model Drift) 자동 모니터링 및 재학습 트리거 설정, 고위험 제어 결정(예: 농약 살포)에 대한 Human-in-the-Loop 승인 프로세스 적용, A/B 테스트 기반 점진적 모델 배포(Canary Release)

### 6. 데이터 거버넌스 부재로 인한 개인정보 및 농업 데이터 주권 침해

* **설명:** 클라우드에 집중되는 농장 생산 데이터(생산량, 생육 패턴, 자원 사용량)는 농가의 민감한 경영 정보를 포함한다. 클라우드 사업자의 약관 변경, 데이터 국외 이전, 또는 플랫폼 종속(Vendor Lock-in)으로 인해 농가가 자신의 데이터에 대한 통제권을 상실할 위험이 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 데이터 소유권 명시적 계약화(DPA, Data Processing Agreement), 표준 데이터 포맷(예: FIWARE NGSI-LD) 채택으로 플랫폼 이식성 확보, 국내 클라우드 또는 온프레미스 하이브리드 옵션 제공, 농가별 데이터 접근 권한 관리(RBAC) 및 데이터 수출(Export) 기능 의무 제공

### 1. 클라우드 단일 장애점(Single Point of Failure)으로 인한 전체 시스템 마비

* **설명:** Cloud-based Event and Data Management가 모든 도메인의 허브 역할을 수행하므로, 클라우드 플랫폼 장애(AWS/Azure 리전 다운, 네트워크 단절) 발생 시 Sensing 데이터 수집 중단, Analysis 불가, Control 명령 전달 불가가 동시에 발생한다. 특히 폭염·한파 등 기상 이변 시 농작물 피해가 즉각적으로 발생할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 엣지 게이트웨이(Edge Gateway)에 로컬 룰 기반 자율 제어 로직(Fallback Mode) 탑재, 클라우드 멀티리전 또는 Active-Active 이중화 구성, 오프라인 시에도 최소 제어(온도·습도 임계 제어)가 동작하는 엣지 컴퓨팅 레이어 추가

### 2. 농장 현장 네트워크 불안정으로 인한 실시간 제어 지연

* **설명:** 농촌 지역 특성상 LTE/5G 및 유선망 품질이 불안정하여 Sensing 데이터가 클라우드에 도달하지 못하거나, Control 명령이 현장 액추에이터에 늦게 전달될 수 있다. 예를 들어 온실 온도가 임계치를 초과했음에도 환기 팬 제어 명령이 수 분간 지연되면 작물 고사로 이어진다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 엣지-클라우드 하이브리드 아키텍처 도입(Edge Computing Layer 추가), 로컬 MQTT 브로커를 현장에 배치하여 클라우드 연결과 무관하게 Sensing↔Control 간 직접 통신 경로 확보, QoS 레벨 설정 및 메시지 큐 버퍼링으로 재전송 보장

### 3. 센서 데이터 무결성 및 오염 데이터로 인한 오제어(False Control)

* **설명:** 온도·습도·CO₂ 등 물리 센서는 노후화, 오염, 보정 오류로 인해 비정상 값을 전송할 수 있다. Smart Analysis & Planning이 이 오염 데이터를 정상으로 판단하여 Smart Control에 잘못된 명령(예: 이미 충분히 관개된 상태에서 추가 관개 명령)을 내리면 작물 피해 또는 자원 낭비가 발생한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 수집 단계에서 이상치 탐지(Z-score, IQR 기반 실시간 필터링) 적용, 동일 측정 항목에 대한 다중 센서 교차 검증(Sensor Fusion), 주기적 센서 교정(Calibration) 스케줄 관리 시스템 구축, 제어 명령 실행 전 유효성 검증 게이트(Validation Gate) 추가

### 4. 클라우드 저장 데이터 및 제어 명령에 대한 사이버 보안 위협

* **설명:** 클라우드 중앙 허브가 공격받을 경우, 공격자는 ① 전체 농장의 환경 데이터 탈취(농업 경쟁 정보 유출), ② 위조된 제어 명령 주입(살충제 과다 살포, 온도 조작)이 가능하다. IoT 디바이스는 펌웨어 업데이트가 불규칙하여 취약점 노출 기간이 길다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 디바이스-클라우드 간 상호 인증(Mutual TLS, X.509 인증서) 적용, 제어 명령에 디지털 서명 및 무결성 검증 의무화, 네트워크 세그멘테이션(OT/IT 분리), 디바이스 취약점 관리를 위한 OTA(Over-The-Air) 펌웨어 업데이트 체계 구축, SIEM 기반 이상 행위 탐지

### 5. AI/ML 분석 모델의 편향 및 과적합으로 인한 의사결정 오류

* **설명:** Smart Analysis & Planning의 예측 모델이 특정 계절·품종·지역 데이터에 과적합될 경우, 새로운 환경 조건(신규 병해충, 기후변화 패턴)에서 오판을 내릴 수 있다. 예를 들어 여름 데이터로만 학습된 모델이 봄철 저온 피해 징후를 정상으로 분류하는 상황이 발생할 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 모델 학습 데이터의 계절·품종·지역 다양성 확보(Data Augmentation), MLOps 파이프라인 구축으로 모델 드리프트(Model Drift) 자동 모니터링 및 재학습 트리거 설정, 고위험 제어 결정(예: 농약 살포)에 대한 Human-in-the-Loop 승인 프로세스 적용, A/B 테스트 기반 점진적 모델 배포(Canary Release)

### 6. 데이터 거버넌스 부재로 인한 개인정보 및 농업 데이터 주권 침해

* **설명:** 클라우드에 집중되는 농장 생산 데이터(생산량, 생육 패턴, 자원 사용량)는 농가의 민감한 경영 정보를 포함한다. 클라우드 사업자의 약관 변경, 데이터 국외 이전, 또는 플랫폼 종속(Vendor Lock-in)으로 인해 농가가 자신의 데이터에 대한 통제권을 상실할 위험이 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 데이터 소유권 명시적 계약화(DPA, Data Processing Agreement), 표준 데이터 포맷(예: FIWARE NGSI-LD) 채택으로 플랫폼 이식성 확보, 국내 클라우드 또는 온프레미스 하이브리드 옵션 제공, 농가별 데이터 접근 권한 관리(RBAC) 및 데이터 수출(Export) 기능 의무 제공
