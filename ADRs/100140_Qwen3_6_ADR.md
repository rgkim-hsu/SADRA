# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 클라우드 연동형 무선 IoT 기반 엣지-서버 분산 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                      |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 현장 장치군(10) 내 `센서 측정장치(200)`와 `모니터링 장치(300)`에서 생성된 물리적 환경 데이터를 원격 `정보 제공 서버(400)`로 수집하고, 클라우드 인프라를 경유하여 다수의 `사용자 기기(20)`에 실시간으로 제공해야 함. 유선 배선의 물리적 제약, 유지보수 비용 증가, 그리고 모바일/원격 모니터링 요구사항 확대에 대응할 아키텍처적 방안이 필요함.                           |
| **결정(Decision)**       | 현장 데이터 수집 및 1차 가시화는 `모니터링 장치(300)`와 `센서 측정장치(200)`로 구성된 엣지 레이어(100)에서 수행하고, 무선 통신 프로토콜을 통해 `정보 제공 서버(400)`로 데이터를 집계함. 서버는 클라우드 환경과 연동하여 데이터 저장/처리 파이프라인을 구축하며, `사용자 기기(20)`에는 표준화된 RESTful API 및 WebSocket 기반 인터페이스를 제공하여 플랫폼 종속성을 제거함. |
| **근거(Rationale)**      | 무선 IoT 통신은 설치 유연성과 대규모 센서 확장성을 제공하며, 엣지 장치의 로컬 처리는 네트워크 대역폭 절약 및 단절 시 로컬 모니터링 지속을 보장함. 클라우드 연동 서버는 탄력적인 컴퓨팅 자원 할당과 글로벌 접근성을 가능하게 하며, 다양한 `사용자 기기(20)` 폼팩터(PC, 태블릿, 스마트폰)를 단일 코드베이스로 지원할 수 있는 기술적 타당성이 높음.                               |
| **결과(Consequences)**   | 원격 실시간 모니터링 및 제어의 접근성이 획기적으로 향상되며, 신규 센서나 사용자 단말 추가 시 시스템 재구성 없이 확장 가능함. 반면, 무선 통신 환경의 불안정성, 클라우드 의존도에 따른 지연(Latency) 및 운영 비용(OPEX) 증가, 엣지 장치의 분산 보안 관리 부담이 수반됨.                                                                        |
| **트레이드오프(Trade-offs)** | 설치 유연성, 시스템 확장성, 다중 클라이언트 접근성 확보 vs. 무선 통신 신뢰성 의존도 증가, 클라우드 인프라 운영 비용 상승, 엣지-클라우드 간 데이터 동기화 복잡도 심화.                                                                                                                                     |

## ⚠️ 잠재적 위험 분석

### 1. 무선 통신 간섭 및 연결 불안정으로 인한 데이터 손실

- **설명:** `센서 측정장치(200)`와 `모니터링 장치(300)`가 무선 환경에서 `정보 제공 서버(400)`와 통신하므로, 전자기 간섭, 물리적 장애물, 또는 기상 조건 변화로 인해 패킷 손실 또는 연결 끊김이 빈발할 수 있음. 이는 실시간 모니터링 데이터의 공백 또는 왜곡으로 이어짐.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 엣지 장치에 로컬 버퍼링 및 Store-and-Forward 메커니즘 내장, 통신 프로토콜에 자동 재전송(ARQ) 및 순서 보장 로직 적용, 필요 시 메시 네트워크(Mesh Network) 구성으로 통신 경로 다중화.
  
  ### 2. 정보 제공 서버 및 클라우드 의존성에 의한 단일 장애점(SPOF)
- **설명:** 모든 데이터 집계와 `사용자 기기(20)`로의 제공이 `정보 제공 서버(400)`와 클라우드에 집중되므로, 서버 장애 또는 클라우드 리전 장애 발생 시 전체 모니터링 서비스가 중단되고 사용자 접근이 불가능해짐.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 서버 다중 가용 영역(Multi-AZ) 배포 및 자동 페일오버(Failover) 구성, CDN 및 엣지 캐싱을 통한 정적 데이터 분산 제공, 클라우드 장애 시 로컬 네트워크 내 직접 접근 가능한 비상 모니터링 모드 활성화.
  
  ### 3. 엣지 장치 물리적 접근 및 웨어 변조 위협
- **설명:** 현장에 배치된 `센서 측정장치(200)` 및 `모니터링 장치(300)`는 물리적 보안이 취약할 수 있음. 악의적인 접근으로 인한 펌웨어 변조, 무단 데이터 주입, 또는 장치 탈취 시 전체 시스템 데이터 무결성이 훼손될 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:**  Medium
- **대응 방안:** 하드웨어 보안 모듈(HSM) 또는 TPM  탑재, Secure Boot 및 암호화된 OTA 펌웨어 업데이트 적용, 통신 구간 Mutual TLS(mTLS) 인증 강제, 이상 동작 감지 시 원격 격리(Remote Wipe/Lock) 기능 구현.
  
  ### 4. 엣지-서버-클라이언트 간 데이터 비동기화 및 순서 왜곡
- **설명:** 무선 네트워크 지연 또는 서버 처리 큐잉으로 인해 `사용자 기기(20)`에 표시되는 데이터가 실제 현장 상태보다 뒤처지거나, 다중 센서 데이터의 타임스탬프 순서가 뒤바뀔 경우 의사결정 오류가 발생할 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 데이터 패킷에 전역 동기화 타임스탬프(NTP/PTP 기반) 및 시퀀스 번호 필수 첨부, 서버 측 메시지 브로커(Kafka/RabbitMQ) 도입을 통한 순차적 처리 보장, 클라이언트 측 데이터 재정렬(Reordering) 및 지연 경고 UI 구현.
  
  ### 5. 대용량 센서 데이터 유입에 의한 대역폭 및 서버 처리 병목
- **설명:** `센서 측정장치(200)`의 개수 증가 또는 고주파 샘플링 설정 시, 무선 대역폭 포화와 `정보 제공 서버(400)`의 Ingress 트래픽 급증으로 인해 처리 지연이 발생하고, 클라우드 비용이 예측 불가능하게 상승할 수 있음.
- **심각도:**  Medium
- **발생 가능성:**  Medium
- **대응 방안:** 지 장치에서 1차 데이터 필터링 및 집계(Aggregation) 수행, 변화 감지 시에만 데이터 전송하는 변화 임계값(Change Threshold) 기반 전송 정책 적용, 서버 측 오토스케일링(Auto-scaling) 및 트래픽 쉐이핑(Traffic Shaping) 구성.
