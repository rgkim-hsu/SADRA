## 📋 ADR (Architecture Decision Record)

### **ADR-001: 중앙 집중형 데이터 통합 플랫폼 채택 및 이벤트 기반 통신 모델 적용**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 제공된 시스템 개념도는 IoT 기반 스마트팜/축산 시스템을 위한 **데이터 통합 및 제어 플랫폼**을 나타내고 있습니다. 각 모듈은 센서 데이터 수집, 환경 제어, 보안 인증, 상호운용성 보장을 위한 독립적 기능 블록으로 구성되어 있으며, **중앙 집중형 아키텍처**를 통해 실시간 데이터 처리와 제어가 요구됩니다. 특히, TTA 표준과 ISO/IEC 30141:2024의 요구사항에 따라 **모듈화, 확장성, 보안성**이 필수적입니다. |
| **결정(Decision)** | 1. **중앙 집중형 데이터 통합 플랫폼**을 채택하여 모든 모듈(센서, 액추에이터, 보안, 제어)이 중앙 노드(421)로 데이터를 수집/전송하는 구조를 적용합니다.<br>2. **이벤트 기반 통신 모델**(예: MQTT, CoAP 프로토콜)을 사용하여 실시간 데이터 스트리밍과 이벤트 처리 효율성을 높입니다.<br>3. **API 게이트웨이 패턴**을 통해 모듈 간 상호운용성을 보장하고, **OAuth 2.0/JWT** 기반 인증을 적용합니다.<br>4. **미들웨어 계층**(428)을 도입하여 데이터 변환, 캐싱, 로깅 기능을 중앙에서 관리합니다. |
| **근거(Rationale)** | - **중앙 집중형 아키텍처**: TTA 스마트팜 표준과 ISO/IEC 30141의 요구사항에 부합하며, **단일 진입점 관리**를 통해 보안과 모니터링을 강화합니다.<br>- **이벤트 기반 통신**: IoT 환경의 **저 지연성**과 **고 확장성**을 요구하는 스마트팜 시스템에 적합합니다.<br>- **API 게이트웨이**: oneM2M 표준과 Matter 프로토콜의 상호운용성 요구사항을 충족합니다.<br>- **미들웨어 계층**: 데이터 일관성과 성능 최적화를 위해 필요하며, ETSI EN 303 645의 보안 요구사항을 지원합니다. |
| **결과(Consequences)** | ✅ **장점**:<br> - 중앙 관리로 인한 **보안 강화**와 **모니터링 용이성**<br> - 모듈화로 인한 **확장성**과 **재사용성**<br> - 이벤트 기반 통신으로 인한 **실시간 처리**<br> - 표준 프로토콜 지원으로 인한 **상호운용성**<br>❌ **단점**:<br> - 중앙 노드 **단일 장애점(SPOF)** 위험<br> - 대규모 데이터 처리 시 **성능 병목** 가능성<br> - 네트워크 지연으로 인한 **실시간성 저하** 위험 |
| **트레이드오프(Trade-offs)** | - **중앙 집중형 vs 분산형**: 중앙 집중형은 관리 용이성을 제공하지만, 분산형보다 **고가용성**이 떨어집니다.<br>- **이벤트 기반 vs 요청-응답**: 이벤트 기반은 실시간성이 우수하지만, **복잡한 에러 핸들링**이 필요합니다.<br>- **모듈화 vs tightly-coupled**: 모듈화는 확장성을 높지만, **모듈 간 통신 오버헤드**가 발생할 수 있습니다. |

### **ADR-002: 보안 인증 및 접근 제어 모델**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 **IoT 기기, 사용자, 서비스** 간의 보안 인증을 요구하며, ITU-T X.1352와 ETSI EN 303 645 표준에 따라 **기기 인증, 데이터 암호화, 접근 제어**가 필수적입니다. 특히, 스마트팜 환경에서는 **사이버 공격에 대한 저항성**이 중요합니다. |
| **결정(Decision)** | 1. **기기 인증**: 각 IoT 기기에 **X.509 인증서**를 배포하고, **TLS 1.3**을 사용하여 통신 암호화합니다.<br>2. **사용자 인증**: **OAuth 2.0 + JWT**를 적용하여 API 접근 제어를 수행합니다.<br>3. **접근 제어**: **RBAC(역할 기반 접근 제어)** 모델을 도입하여 사용자/기기별 권한을 관리합니다.<br>4. **보안 미들웨어**: 중앙 노드(421)에서 **DDoS 보호**와 **이상행위 감지** 기능을 제공합니다. |
| **근거(Rationale)** | - **X.509 인증서**: ITU-T X.1352 표준과 호환되며, **기기 간 신원 확인**을 강화합니다.<br>- **OAuth 2.0/JWT**: API 보안을 위한 산업 표준이며, **토큰 기반 인증**으로 성능을 최적화합니다.<br>- **RBAC**: 스마트팜 시스템의 **다중 사용자 환경**에 적합합니다.<br>- **TLS 1.3**: 최신 암호화 표준으로 **데이터 기밀성**을 보장합니다. |
| **결과(Consequences)** | ✅ **장점**:<br> - **고급 보안 인증**으로 인한 **사이버 공격 방어**<br> - **표준 준수**로 인한 **글로벌 상호운용성**<br>❌ **단점**:<br> - **인증서 관리 복잡성**<br> - **성능 오버헤드** (암호화/복호화) |
| **트레이드오프(Trade-offs)** | - **인증서 기반 vs 토큰 기반**: 인증서는 보안성이 우수하지만, 토큰 기반이 **스케일링**에 유리합니다.<br>- **RBAC vs ABAC**: RBAC은 관리 용이성을 제공하지만, ABAC이 **세분화된 정책**을 지원합니다. |

### **ADR-003: 데이터 관리 및 상호운용성 프레임워크**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 **다양한 센서/액추에이터**로부터 데이터를 수집하고, **상호운용성**을 통해 외부 시스템(예: 스마트시티 플랫폼)과 연동해야 합니다. TTA의 "스마트팜 데이터 상호운용 프레임워크" 표준과 oneM2M 요구사항에 따라 **데이터 포맷, API, 프로토콜**이 표준화되어야 합니다. |
| **결정(Decision)** | 1. **데이터 포맷**: **JSON/Protobuf**를 표준 포맷으로 채택하여 **轻量화**와 **호환성**을 보장합니다.<br>2. **API 표준화**: **OpenAPI 3.0**을 사용하여 API 명세를 제공하고, **RESTful + WebSocket**을 지원합니다.<br>3. **프로토콜**: **MQTT v5.0**과 **CoAP**를 기본 프로토콜로 채택하여 **IoT 통신**을 최적화합니다.<br>4. **데이터 변환 미들웨어**(428): **ETL 프로세스**를 통해 데이터 변환과 정합성을 관리합니다. |
| **근거(Rationale)** | - **JSON/Protobuf**: IoT 환경의 **저 용량**과 **고 속도** 처리에 적합합니다.<br>- **OpenAPI 3.0**: **문서화**와 **자동화**를 지원하여 개발 효율성을 높입니다.<br>- **MQTT/CoAP**: **저 대역폭**과 **실시간성**을 요구하는 스마트팜 시스템에 최적화되어 있습니다.<br>- **ETL 미들웨어**: **데이터 일관성**을 보장합니다. |
| **결과(Consequences)** | ✅ **장점**:<br> - **표준화된 데이터 포맷**으로 인한 **상호운용성**<br> - **프로토콜 다양성**으로 인한 **유연성**<br>❌ **단점**:<br> - **데이터 변환 오버헤드**<br> - **프로토콜 선택에 따른 성능 차이** |
| **트레이드오프(Trade-offs)** | - **REST vs MQTT**: REST는 **유연성**이 우수하지만, MQTT이 **실시간성**에 강합니다.<br>- **JSON vs Protobuf**: JSON은 **인간 가독성**이 우수하지만, Protobuf이 **성능**에 우수합니다. |

## ⚠️ 잠재적 위험 분석

### **1. 중앙 노드 단일 장애점(SPOF) 위험**
- **설명**: 중앙 노드(421)가 다운되면 **전체 시스템이 마비**될 수 있습니다. 특히, 스마트팜 시스템에서는 **실시간 제어**가 critical path입니다.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **고가용성 클러스터**를 도입하여 중앙 노드를 **Active-Standby** 또는 **Active-Active**로 구성합니다.
  - **자동 failover 메커니즘**을 구현하여 장애 시 **최대 30초 이내** 복구합니다.
  - **지역 분산 노드**를 배포하여 **지역 네트워크 장애**에도 대응합니다.

### **2. 대규모 데이터 처리 성능 병목**
- **설명**: 센서 데이터가 급격히 증가할 경우, 중앙 노드(421)와 미들웨어(428)에서 **CPU/Memory 병목**이 발생할 수 있습니다.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **수평 확장(Horizontal Scaling)**을 지원하여 **로드 밸런싱**을 적용합니다.
  - **데이터 캐싱**을 도입하여 **반복적인 쿼리**를 최적화합니다.
  - **스트리밍 처리 프레임워크**(예: Apache Kafka, Flink)를 도입하여 **실시간 데이터 처리**를 강화합니다.

### **3. 보안 취약점 및 사이버 공격 위험**
- **설명**: IoT 기기 간 통신에서 **중간자 공격(MITM)**이나 **DDoS 공격**이 발생할 경우, 시스템이 **조작**될 수 있습니다.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **TLS 1.3**과 **IPsec**를 사용하여 **통신 암호화**를 강화합니다.
  - **WAF(Web Application Firewall)**와 **DDoS 보호**를 중앙 노드에 적용합니다.
  - **정기적인 보안 패치**와 **취약점 스캔**을 수행합니다.
  - **블록체인 기반 로깅**을 도입하여 **데이터 무결성**을 보장합니다.

### **4. 프로토콜 및 API 호환성 문제**
- **설명**: 외부 시스템(예: 스마트시티 플랫폼)과의 **프로토콜 불일치**로 인해 **데이터 연동 실패**가 발생할 수 있습니다.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **프로토콜 어댑터**를 구현하여 **MQTT ↔ CoAP ↔ REST** 변환을 지원합니다.
  - **OpenAPI 기반 API 게이트웨이**를 통해 **백워드 호환성**을 보장합니다.
  - **표준화된 데이터 스키마**를 정의하고, **스키마 레지스트리**를 운영합니다.

### **5. 네트워크 지연 및 실시간성 저하**
- **설명**: 원격 센서와 중앙 노드 간의 **네트워크 지연**으로 인해 **실시간 제어**가 불가능해질 수 있습니다.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟢 Low (네트워크 환경에 의존)
- **대응 방안**:
  - **에지 컴퓨팅**을 도입하여 **지역 처리**를 강화합니다.
  - **우선순위 기반 큐**를 사용하여 **Critical 데이터**를 우선 처리합니다.
  - **5G 네트워크**를 활용하여 **저 지연 통신**을 지원합니다.

### **6. 데이터 일관성 및 중복 처리 문제**
- **설명**: 분산 시스템에서 **데이터 중복**이나 **일관성 violation**이 발생할 경우, **제어 오류**가 발생할 수 있습니다.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **이벤트 소싱 패턴**을 도입하여 **데이터 변경을 추적**합니다.
  - **분산 트랜잭션 관리**(예: Saga 패턴)을 적용합니다.
  - **데이터 버전 관리**를 통해 **일관성**을 보장합니다.

### **7. 운영 및 유지보수 복잡성**
- **설명**: 모듈화된 시스템의 **운영 복잡성**으로 인해 **유지보수 비용**이 증가할 수 있습니다.
- **심각도**: 🟢 Low | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **DevOps 자동화**를 도입하여 **CI/CD 파이프라인**을 구축합니다.
  - **모니터링 도구**(예: Prometheus, Grafana)를 사용하여 **시스템 상태**를 실시간으로 확인합니다.
  - **문서화 표준**을 적용하여 **지식 공유**를 강화합니다.
