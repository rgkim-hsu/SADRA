### ADR-001: **블록체인 기반 스마트팜 데이터 신뢰성 및 투명성 보장**

| 항목                     | 내용                                                                                                                                                                                                   |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 시스템에서 생산된 작물 데이터(이름, 재배 기간, 이미지 등)의 위변조를 방지하고, 재배자와 구매자 간 신뢰성을 확보해야 하는 필요성이 있음. 기존 중앙집중식 데이터베이스만으로는 데이터 조작 가능성 및 중앙 서버의 단일 장애점(single point of failure) 문제가 존재함.                                |
| **결정(Decision)**       | **블록체인 네트워크(300개 노드) 도입**하여 작물 데이터를 분산 저장하고, 모든 거래(작물 등록, 구매 등) 내역을 블록체인에 기록. 스마트팜 서버는 블록체인 네트워크와 연동하여 데이터를 전송 및 검증(91번 인터페이스)하며, 사용자(재배자, 구매자)는 블록체인 네트워크를 통해 데이터를 조회(93번 인터페이스) 또는 등록(92번 인터페이스)함. |
| **근거(Rationale)**      | 블록체인의 **탈중앙화**, **불변성**, **투명성** 특성을 활용하여 데이터 위변조 방지 및 모든 참여자 간 신뢰성 확보. 특히, 스마트팜 분야에서 데이터 무결성이 생산부터 유통까지의 전체 프로세스에 critical함. 또한, 300개 노드로 구성된 블록체인 네트워크는 분산 합의 알고리즘을 통해 데이터 일관성을 유지할 수 있음.          |
| **결과(Consequences)**   | **정적 결과**: 데이터 조작 방지, 신뢰성 향상, 유통 투명성 확보. **부정적 결과**: 블록체인 네트워크의 지연 시간(latency)으로 인해 실시간 데이터 처리에 제한이 있을 수 있으며, 노드 유지보수 비용 증가.                                                                         |
| **트레이드오프(Trade-offs)** | **장점**: 데이터 무결성 보장, 중앙 서버 의존도 감소, 참여자 간 신뢰성 향상. **단점**: 트랜잭션 처리 속도 저하, 블록체인 노드 운영 비용 증가, 초기 구축 복잡성.                                                                                                  |

⚠️ 잠재적 위험 분석
------------

### 1. **블록체인 네트워크의 성능 병목 현상**

* **설명:** 300개 노드로 구성된 블록체인 네트워크에서 트랜잭션 수가 증가할 경우, 합의 알고리즘(예: PoW, PoS)의 지연으로 인해 데이터 등록 및 조회가 지연될 수 있음. 특히, 스마트팜 서버에서 블록체인으로 데이터를 전송(91번)하는 과정에서 대기 시간이 발생할 경우, 실시간 모니터링에 장애가 발생할 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** **오프체인(Off-chain) 솔루션** 도입을 통해 자주 사용되는 데이터는 중앙 데이터베이스에 캐싱하고, 블록체인에는 해시 값만 저장. 또한, **샤딩(Sharding)** 기법을 통해 네트워크를 분할하여 처리 속도 향상.

* * *

### 2. **데이터 사생활 침해 위험**

* **설명:** 블록체인에 저장된 작물 데이터(예: 재배 위치, 이미지)가 공공으로 노출될 경우, 재배자의 사생활이나 영업 비밀이 유출될 수 있음. 특히, 블록체인의 투명성 특성으로 인해 모든 노드가 데이터를 접근할 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** **개인정보 보호를 위한 암호화** 적용. 민감한 데이터는 **제로 지식 증명(ZKP)** 또는 **프라이빗 블록체인**을 통해 접근 권한을 제한. 또한, GDPR 등 관련 규정을 준수하여 데이터 익명화(anonymization) 처리.

* * *

### 3. **스마트팜 서버와 블록체인 간 데이터 동기화 실패**

* **설명:** 스마트팜 서버에서 블록체인 네트워크로 데이터를 전송(91번)하는 과정에서 네트워크 장애 또는 블록체인 노드의 오프라인 상태로 인해 데이터가 동기화되지 않을 경우, 재배자 또는 구매자가 최신 데이터를 확인할 수 없음.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** **이중 쓰기(Dual Write) 패턴** 적용. 스마트팜 서버는 데이터베이스와 블록체인에 동시에 데이터를 기록하고, **주기적 동기화 검증**을 통해 일관성을 유지. 또한, **리트라이(Retry) 메커니즘**을 통해 실패한 트랜잭션을 재시도.

* * *

### 4. **블록체인 노드의 비잔틴 공격(Byzantine Attack)**

* **설명:** 블록체인 네트워크 내 악의적인 노드가 거짓 데이터를 퍼뜨려 네트워크의 합의를 방해할 경우, 데이터의 무결성이 훼손될 수 있음. 특히, 300개 노드 중 일정 비율 이상이 악의적일 경우, 네트워크가 분열될 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟢 Low
* **대응 방안:** **PBFT(Practical Byzantine Fault Tolerance)**와 같은 비잔틴 내성 합의 알고리즘 도입. 또한, **노드 가입 시 엄격한 인증** 절차(예: KYC)를 통해 악의적인 노드의 참여를 방지.

* * *

### 5. **사용자 간 데이터 불일치로 인한 분쟁**

* **설명:** 재배자와 구매자 간에 작물 데이터(예: 품질, 수량)에 대한 불일치가 발생할 경우, 블록체인에 기록된 데이터가 증거로 사용되지 못하면 분쟁이 발생할 수 있음. 특히, 이미지 데이터의 경우 위변조 여부를 입증하기 어려울 수 있음.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** **스마트 계약(Smart Contract)**을 통해 작물 데이터의 등록 및 거래 프로세스를 자동화. 예를 들어, 작물 이미지는 **IPFS(InterPlanetary File System)**에 저장하고, 해당 해시 값을 블록체인에 기록하여 데이터의 무결성을 입증. 또한, **제3자 검증 기관**을 통해 주기적으로 데이터의 정확성을 검증.
