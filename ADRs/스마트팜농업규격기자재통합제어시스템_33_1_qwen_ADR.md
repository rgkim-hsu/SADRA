## 📋 ADR (Architecture Decision Record)

### ADR-001: IoT 참조 아키텍처 및 상호운용성 표준 준수 결정

| 항목 | 내용 |
|------|------|
| **상황 (Context)** | **시스템:** Kubota의 정밀 농업 시스템 (FMIS/KSAS)<br>**문제:** 시스템은 외부 회사로부터의 센싱 데이터, 농업 데이터 플랫폼, 그리고 농장 주인 소유의 정보 시스템 등 여러 출처에서 데이터를 수집하고 처리해야 합니다.<br>**문제:** 다양한 공급자와 장비 (트랙터, 드론, 센서) 가 연결될 때, 각기 다른 프로토콜과 데이터 형식으로 인해 발생하는 상호운용성 및 데이터 통합의 어려움이 있습니다. 또한, 글로벌 확장 (아시아) 을 염두에 두고 있습니다. |
| **결정 (Decision)** | **결정:** ISO/IEC 30141:2024 (IoT 참조 아키텍처) 및 oneM2M 표준을 기반으로 한 분산형 엣지 컴퓨팅 아키텍처를 채택합니다.<br>**구체적 내용:**<br>1. **프로토콜 표준화:** 기기 간 통신에는 경량 프로토콜 (MQTT, CoAP) 을 사용합니다.<br>2. **데이터 형식:** 농장 데이터 플랫폼의 데이터 모델은 표준화된 JSON Schema 또는 Protocol Buffers 를 따릅니다.<br>3. **데이터 흐름:** 중앙 집중식 클라우드만 의존하지 않고, 현장 (field) 에 엣지 노드를 배치하여 '지시 (Instruction)'가 내려올 때의 지연 시간을 최소화합니다. |
| **근거 (Rationale)** | **기술적 근거:** 이미지 하단에 제시된 "Kubota's smart agricultural machinery"가 실시간으로 "Variable pesticide", "variable fertilization" 등을 수행하기 위해서는 네트워크 지연 시간을 최소화해야 합니다.<br>**표준화 근거:** 제공된 문서에 언급된 "ISO/IEC 30141:2024"는 IoT 시스템 구축의 공통 용어와 설계 패턴을 제공하며, "oneM2M"는 M2M 요구사항과 API 명세를 다룹니다. 이를 따름으로써 향후 아시아 확장 시 글로벌 표준과의 호환성을 확보할 수 있습니다.<br>**보안 근거:** ETSI EN 303 645 및 ITU-T X.1352와 같은 보안 가이드라인을 준수하여 사물인터넷 기기의 안전한 설계와 개발을 보장합니다. |
| **결과 (Consequences)** | **긍정적:** 다양한 공급자의 장비 (Kubota 외 다른 회사의 기계) 와의 연동이 용이해지며, 데이터 통합 비용이 절감됩니다. 시스템의 확장성이 보장됩니다.<br>**부정적:** 초기 표준화 작업과 통합 비용이 발생할 수 있습니다. 표준 프로토콜 구현 시 유연성이 다소 제한될 수 있습니다 (예: 특정 비표준 기능 추가 제한). |
| **트레이드오프 (Trade-offs)** | **장점:** 높은 상호운용성 및 유지보수 용이성.<br>**단점:** 초기 개발 주기 (Dev Cycle) 의 연장 및 표준 준수를 위한 지속적인 검증 노력 필요. |

### ADR-002: AI 기반 의사결정 루프 및 인간 개입 (Human-in-the-loop) 전략

| 항목 | 내용 |
|------|------|
| **상황 (Context)** | **시스템:** KSAS 레이어 맵 -> 분석/처리 (Big data AI) -> 농업 비즈니스 계획 개발 -> 지시 (Instruction)<br>**문제:** "Analysis/processing Big data AI"가 "Planting plan", "Work plan", "Business plan" 및 실제 농장 작업 (비료 살포, 경운 등) 을 자동화합니다. 농업은 생명 활동이므로 100% 자동화된 결정이 위험할 수 있으며, 특히 "비용 분석"이나 "비즈니스 계획"과 같이 복잡한 판단이 필요한 영역에서 오작동 시 막대한 손실이 발생합니다. |
| **결정 (Decision)** | **결정:** 고위험/고비용 작업 영역에 대해서는 "Human-in-the-loop" 검증 프로세스를 강제로 적용합니다.<br>**구체적 내용:**<br>1. **위험도 분류:** 시스템은 "작업 경로", "비료 살포", "작물 성장" 데이터를 기반으로 계획을 수립하지만, 최종 실행 (Instruction) 단계에서 특정 임계값 이상의 비용 변동 시나리오를 감지하면 농장주인에게 확인을 요구하도록 설계합니다.<br>2. **지식 베이스:** KSAS 레이어 맵의 역사적 데이터 (과거 수확량, 토질) 를 학습하여 AI 모델의 신뢰도 (Confidence Score) 를 계산합니다. 신뢰도가 낮을 경우 자동으로 전문가 검토 모드로 전환합니다. |
| **근거 (Rationale)** | **논리적 근거:** 이미지에서 "Analysis/processing Big data AI"가 "Agricultural business plan development"로 이어지고 다시 "Instruction"으로 내려옵니다. 이는 단순 자동화가 아니라 '지식 기반 시스템'임을 시사합니다.<br>**실무적 근거:** "변동비 비료 시비 (variable base fertilization)"와 같이 농작물 상태에 따라 실시간으로 변수가 발생하는 작업은 AI 가 예측하지만, 실제 토양 상태 (습도, 온도 등) 에 따라 즉각적인 판단이 필요한 상황이 발생할 수 있습니다. 이때 인간 농사지의 경험적 지식을 AI 가 보완해야 합니다.<br>**비즈니스 근거:** "Business plan" 및 "Cost analysis"에 정확도를 높여 농장의 수익성 확보를 도모합니다. |
| **결과 (Consequences)** | **긍정적:** AI 오류에 의한 재배 비용 손실 (과비/과소비료 등) 을 방지하고, 농민이 시스템을 신뢰하고 수용하는 속도 (Adoption) 를 높입니다.<br>**부정적:** 완전 자동화 (Fully Autonomous) 수준은 달성되지 않아, 일부 작업에서 인간의 개입이 필요해지므로 효율성 (throughput) 이 이론적 최대치보다는 낮아질 수 있습니다. |
| **트레이드오프 (Trade-offs)** | **장점:** 높은 정확도와 안전성 확보.<br>**단점:** 시스템의 자동화율 한계 및 응답 속도 저하 (인간 확인 소요 시간). |

## ⚠️ 잠재적 위험 분석

### 1. 데이터 통합 및 호환성 리스크

- **설명:** 시스템의 왼쪽 영역 "Sensing data by other companies", "External data including market data", "Information system owned by farmers" 는 서로 상이한 프로토콜과 데이터 포맷을 사용할 가능성이 매우 높습니다. Kubota 의 "Kubota layer map"와 다른 회사의 데이터를 실시간으로 결합할 때 데이터 패싱 및 변환 오류가 발생할 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 
  1. ** 엣지 게이트웨이 (Edge Gateway) 도입:** 외부 데이터가 들어오는 모든 인터페이스에 표준화된 변환 레이어 (Adapter Pattern) 를 적용합니다.
  2. **상호운용성 프레임워크 적용:** TTA 가 제안하는 "스마트팜 데이터 상호운용 프레임워크" 및 oneM2M 표준을 따르며, API 게이트웨이를 구축하여 데이터 일관성을 관리합니다.

### 2. 네트워크 지연으로 인한 제어 지연 (Latency Risk)

- **설명:** "Analysis/processing Big data AI"는 클라우디 기반일 가능성이 높으며, "Instruction"은 "Kubota's smart agricultural machinery" (트랙터, 드론 등) 로 즉시 전달되어야 합니다. 만약 농작물 병해충 발생 등 긴급 상황 시 클라우드 연결이 불안정하면, AI 가 "Variable pesticide"를 지시하는 지시가 늦어지면 작물 수확량이 급격히 떨어질 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 
  1. ** 엣지 컴퓨팅 활성화:** Kubota 의 스마트 농업 기기에 로컬 AI 처리 능력을 탑재하여 (On-device AI), 지시 전달 시 클라우드 의존도를 줄입니다.
  2. **네트워크 중복성:** 4G/LTE 및 LoRaWAN 등 이차 네트워크를 병행하여 연결 안정성을 확보합니다.

### 3. 사이버 보안 취약점 및 외부 공격

- **설명:** 제공된 문서에 따르면 IoT 표준의 핵심은 "보안" (ITU-T X.1352, ETSI EN 303 645) 입니다. 시스템은 수많은 IoT 기기 (센서, 트랙터, 드론) 를 네트워크에 연결합니다. 해커가 이 기기들을 해킹하여 "Water management system" (관수/배수) 을 조작하거나, 비료 살포 시점을 조작하여 농가에 큰 피해를 줄 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 
  1. **제로 트러스트 (Zero Trust) 아키텍처:** 모든 기기 연결 시 무조건적인 인증 및 암호화 (TLS/SSL) 를 적용합니다.
  2. **보안 모뎀:** 기기 단말 자체에 보안 모듈을 탑재하고, 주기적인 펌웨어 업데이트를 강제하는 OTA 프로세스를 구축합니다.

### 4. 제 3 자 센서 데이터의 신뢰성 및 오류 전파

- **설명:** 시스템은 "Sensing data by other companies" 및 "Farmland/map", "Soil", "Weather" 등 다양한 외부 데이터를 활용합니다. 만약 외부 회사의 센서가 고장 나거나, 잘못된 날씨 데이터를 제공하면 KSAS 레이어 맵의 분석 결과가 왜곡되고, 결과로 내려간 "Instruction"이 농사를 망칠 수 있습니다 (예: 가뭄인데 물이 들어감, 폭우인데 물이 안 들어감).
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 
  1. **데이터 융합 (Sensor Fusion):** 단일 소스 의존도를 낮추기 위해 외부 데이터와 자체 내장 센서 데이터를 융합하여 신뢰도를 높이는 알고리즘을 개발합니다.
  2. **실시간 검증:** 외부 데이터가 들어오면 자체 기준 (예: 물리적 가능성 검증, 과거 데이터 패턴 매칭) 을 통해 이상치 여부를 필터링합니다.

### 5. 데이터 프라이버시 및 소유권 분쟁

- **설명:** 시스템은 "Information system owned by farmers" 데이터를 포함하며, 동시에 "Data coordination" 을 통해 외부로 데이터가 나갑니다. 농민은 "Farmland", "Yield", "Cost analysis" 등의 민감한 데이터를 공유할 의사가 없을 수 있습니다. 또한, 농업 데이터의 소유권에 대한 법적 이슈 (특히 일본/아시아 지역) 가 발생할 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 
  1. **데이터 소유권 명시 계약:** 외부 데이터 제공 시, 데이터 소유권, 사용 범위, 공유 범위 등에 대한 명확한 라이선스 계약을 체결합니다.
  2. **데이터 익명화:** 외부로 나가는 데이터 (Market data 등) 는 개인 식별 정보 (PII) 를 제거하고, 집계된 데이터 형태로만 공유합니다.
