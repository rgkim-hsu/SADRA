## PAT-05

# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 순차적 데이터 정제 및 인간-기계 협력(Human-in-the-Loop) 기반 작물 모델링 파이프라인 채택

| 항목                     | 내용                                                                                                                                                                                                                                                                                          |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 운영 환경에서 IoT 센서 및 제어 데이터(S21)를 실시간으로 수집해야 하며, 수집된 데이터의 신뢰성을 확보(S22)하고 현장 전문가의 경험적 판단(S23)을 결합하여 정확한 작물 모델링(S24)을 수행해야 함. 또한, 단순 생육 관리를 넘어 마케팅 및 출하 전략(S25) 수립과 지역별 관제(S26)로 이어지는 비즈니스 가치 사슬을 구현해야 하는 과제가 있음.                                                                            |
| **결정(Decision)**       | 데이터 수집(S21)부터 오류 탐지(S22), 사용자 입력 통합(S23), 모델링 생성(S24)까지의 과정을 **엄격한 순차적 파이프라인(Sequential Pipeline)**으로 구성하고, 최종 결과물을 비즈니스 로직(S25)과 관제 데이터(S26)로 분기시키는 아키텍처를 채택함. 특히, 자동화 데이터 흐름 중간에 사용자 입력 단계(S23)를 삽입하여 **Human-in-the-Loop** 구조를 명시적으로 구현함.                                                |
| **근거(Rationale)**      | 1. **데이터 품질 보증:** 오류 데이터 탐지(S22)를 모델링(S24) 이전에 배치함으로써 'Garbage In, Garbage Out' 문제를 원천 차단.<br>2. **정확도 향상:** 센서 데이터만으로는 파악하기 어려운 미세한 작황 변화를 사용자 입력(S23)으로 보완하여 모델링의 정확도를 극대화.<br>3. **비즈니스 연계:** 기술적인 생육 데이터(S24)를 마케팅 및 출하(S25)와 직접 연결하여 데이터 기반 의사결정(Data-Driven Decision Making)을 가능하게 함. |
| **결과(Consequences)**   | 데이터 처리의 논리적 흐름이 명확해지며, 모델링 결과의 신뢰도가 크게 향상됨. 또한, 생산 데이터가 곧바로 경영 전략으로 연결되는 구조가 됨. 반면, 사용자 입력(S23) 단계에서의 지연이 전체 파이프라인의 처리 속도를 저하시킬 수 있는 병목 요인이 될 수 있음.                                                                                                                                         |
| **트레이드오프(Trade-offs)** | 데이터 신뢰성 및 비즈니스 통합성 확보 vs. 사용자 개입에 의한 처리 지연(Latency) 가능성 및 파이프라인의 유연성(Flexibility) 저하.                                                                                                                                                                                                       |

## ️ 잠재적 위험 분석

### 1. 오류 데이터 탐지(S22) 알고리즘의 탐/미탐으로 인한 모델링 왜곡

- **설명:** S22 단계에서 센서의 일시적 노이즈를 정상 데이터로 판단(미탐)하거나, 정상적인 급변 데이터를 오류로 판단(오탐)할 경우, 후속 단계인 작물 모델링(S24)의 입력값이 왜곡되어 전체 생육 예측이 틀어질 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 다중 센서 데이터 교차 검증(Cross-Validation) 로직 도입, 이상치 탐지(Anomaly Detection) 알고리즘의 정기적인 재학습(Retraining) 및 임계값 동적 조정.
  
  ### 2. 사용자 입력(S23) 지연에 의한 실시간 관제 병목 현상
- **설명:** S23 단계가 시스템 자동화가 아닌 사용자(농장주/전문가)의 수동 입력에 의존하므로, 입력이 지연될 경우 후속 작업인 모델링 생성(S24) 및 지역별 관제 데이터 생성(S26)이 대기 상태에 빠질 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 사용자 입력이 없을 경우 센서 데이터 기반의 '자동 임시 모델'을 생성하여 파이프라인이 중단되지 않도록 하는 Fallback 메커니즘 구현, 모바일 알림(Push Notification)을 통한 입력 촉구.
  
  ### 3. 작물 모델링(S24) 연산 부하 증가 및 리소스 고갈
- **설명:** S24 단계에서 고도화된 작물 생육 시뮬레이션 또는 AI 모델 추론이 수행될 경우, 데이터 양이 많아질수록 컴퓨팅 리소스(CPU/GPU)가 급격히 소모되어 시스템 전반의 응답 속도 저하가 발생할 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 모델링 작업을 비동기 큐(Asynchronous Queue)로 처리하여 메인 파이프라인의 블로킹 방지, 클라우드 기반 오토스케일링(Auto-scaling) 인프라 도입.
  
  ### 4. 마케팅 및 출하 전략 데이터(S25)의 기밀성 유출
- **설명:** S25 단계에서 생성되는 출하 시기, 목표 가격, 판매처 등의 데이터는 농장의 핵심 경영 기밀임. 이 데이터가 무단으로 유출될 경우 경쟁 우위 상실 및 경제적 손실이 발생함.
- **심각도:** 🔴 High
- **발생 가능성:**  Low
- **대응 방안:** S25 데이터 저장 및 전송 시 강력한 암호화(AES-256) 적용, 역할 기반 접근 제어(RBAC)를 통한 접근 권한 최소화, 데이터 유출 방지(DLP) 솔루션 도입.
  
  ### 5. 센서/제어 데이터(S21) 유입량 급증에 의한 수신 모듈 과부하
- **설명:** 기상 이변이나 특정 생육 단계에서 센서 데이터 전송 빈도가 급증하거나, 제어 명령이 폭주할 경우 S21 수신 모듈의 버퍼가 초과되어 데이터 손실(Packet Loss)이 발생할 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 데이터 수신부에 메시지 큐(Message Queue, 예: Kafka/RabbitMQ) 도입하여 트래픽 피크 흡수, 데이터 압축 전송 프로토콜 적용, 엣지 게이트웨이에서의 1차 필터링 구현.
