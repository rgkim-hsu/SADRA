## 📋 ADR (Architecture Decision Record)

### **ADR-001: 모듈화된 제어 및 모니터링 아키텍처 채택**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 실시간 설비 모니터링, 제어량 분석, 알람 처리 및 리포트 제공 등 다중 기능이 요구되며, 각 기능이 독립적으로 확장/유지보수 가능해야 함. 또한 IoT 표준 준수와 상호운용성을 고려한 아키텍처가 필요함. |
| **결정(Decision)** | 1) **모듈별 기능 분할**: 실시간 모니터링(120a), 제어량 분석(120b), 알람 처리(120c), 리포트 제공(120f) 등 4개 핵심 모듈로 분할하여 독립적 개발/유지보수 가능하게 함.<br>2) **통합 제어부(120)**: 모듈 간 데이터 통합 및 제어 로직 처리 중심으로 설계.<br>3) **표준 프로토콜 기반 I/O 인터페이스(130)**: CoAP/MQTT 등 경량 프로토콜을 활용한 송수신부(140) 구현.<br>4) **데이터베이스(150) 및 응신출력장치(160) 분리**: 데이터 영속성 및 출력 장치 독립화. |
| **근거(Rationale)** | - **모듈화**: ISO/IEC 30141:2024 표준의 재사용성 원칙과 oneM2M 아키텍처의 모듈별 확장성 요구사항에 부합.<br>- **통합 제어부**: ITU-T X.1352 보안 요구사항과 ETSI EN 303 645의 중앙 집중식 제어 로직 처리 원칙을 적용.<br>- **표준 프로토콜**: IETF CoAP/MQTT가 IoT 환경의 경량 통신 요구사항을 충족.<br>- **데이터베이스 분리**: IEEE 2413 표준의 데이터 관리 계층 분리 원칙에 기반. |
| **결과(Consequences)** | - **장점**: 모듈별 독립적 업데이트 가능, 표준 준수로 글로벌 상호운용성 확보, 보안 및 확장성 강화.<br>- **단점**: 초기 모듈 간 통합 테스트 비용 증가, 표준 프로토콜 구현 복잡성. |
| **트레이드오프(Trade-offs)** | - **모듈화 vs. 통합 복잡성**: 모듈화로 유연성 얻지만, 모듈 간 통신 오버헤드 발생.<br>- **표준 프로토콜 vs. 성능**: 경량 프로토콜로 자원 효율성 높지만, 실시간 처리 요구사항에 제약 가능성 존재. |

### **ADR-002: 실시간 데이터 처리 아키텍처**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 실시간 설비 모니터링(120a)과 제어량 분석(120b)은 밀리초 단위의 응답 시간이 요구되며, 데이터 손실 없이 처리해야 함. |
| **결정(Decision)** | 1) **에지 컴퓨팅 기반 처리**: 제어부(120)에서 실시간 데이터 전처리 및 필터링 수행.<br>2) **이중 버퍼링 메커니즘**: 송수신부(140)에서 데이터 중복 저장 및 재처리 지원.<br>3) **우선순위 기반 스케줄링**: 알람 모듈(120c)이 제어량 분석(120b)보다 높은 우선순위 할당. |
| **근거(Rationale)** | - **에지 컴퓨팅**: ITU-T X.1352의 로컬 처리 요구사항과 ISO/IEC 27030:2020의 실시간 보안 처리 원칙에 기반.<br>- **이중 버퍼링**: ETSI EN 303 645의 데이터 신뢰성 요구사항 충족.<br>- **우선순위 스케줄링**: IEEE 2413의 리소스 관리 원칙 적용. |
| **결과(Consequences)** | - **장점**: 실시간 응답 시간 보장, 데이터 손실 최소화.<br>- **단점**: 에지 장비의 하드웨어 요구사항 증가, 복잡한 스케줄링 로직 필요. |
| **트레이드오프(Trade-offs)** | - **에지 처리 vs. 클라우드 처리**: 로컬 처리로 지연 시간 줄이지만, 클라우드 처리보다 높은 초기 비용 발생.<br>- **버퍼링 vs. 메모리 사용**: 데이터 중복으로 메모리 사용량 증가. |

### **ADR-003: 보안 아키텍처**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 IoT 기기 보안(ETSI EN 303 645), 데이터 암호화(ISO/IEC 27030:2020), 및 접근 통제(KISA 기준)를 충족해야 함. |
| **결정(Decision)** | 1) **송수신부(140) 암호화**: TLS 1.3 또는 DTLS를 사용한 통신 암호화.<br>2) **제어부(120) 접근 통제**: OAuth 2.0 기반 API 게이트웨이 도입.<br>3) **데이터베이스(150) 보안**: 필드 수준 암호화 및 접근 로그 기록.<br>4) **노이즈 모니터링(120d)**: 이상행위 감지용 머신러닝 모델 통합. |
| **근거(Rationale)** | - **암호화**: ITU-T X.1352의 보안 요구사항과 ISO/IEC 27030:2020의 데이터 보호 원칙에 기반.<br>- **접근 통제**: oneM2M의 보안 프레임워크와 KISA의 인증 기준 준수.<br>- **이상행위 감지**: ETSI EN 303 645의 사이버 보안 요구사항 충족. |
| **결과(Consequences)** | - **장점**: 글로벌 보안 표준 준수, 데이터 유출 위험 최소화.<br>- **단점**: 암호화 처리로 성능 저하 가능, 복잡한 인증 인프라 필요. |
| **트레이드오프(Trade-offs)** | - **보안 vs. 성능**: 암호화로 성능 저하 발생但 보안 강화.<br>- **머신러닝 모델 vs. 정확성**: 이상행위 감지 모델의 오류 가능성 존재. |

## ⚠️ 잠재적 위험 분석

### **1. 모듈 간 통신 지연**
- **설명**: 모듈화로 인한 네트워크 오버헤드 또는 표준 프로토콜(CoAP/MQTT)의 처리 지연으로 실시간 응답 시간 초과 발생 가능.
- **심각도**: 🟡 Medium
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - 에지 장비에서 로컬 캐싱 및 전처리 강화.
  - MQTT QoS Level 1 이상 사용 및 네트워크 latency 모니터링 도구 도입.
  - ADR-002의 이중 버퍼링 메커니즘을 통해 지연 데이터 재처리 지원.

### **2. 보안 취약점**
- **설명**: IoT 기기 간 통신 암호화 취약점(예: DTLS 취약 버전 사용) 또는 API 게이트웨이의 인증 오류로 데이터 유출 위험.
- **심각도**: 🔴 High
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - KISA의 보안 인증 기준에 따른 정기적인 취약점 스캔 수행.
  - OAuth 2.0의 PKCE 확장 프로토콜 사용으로 토큰 탈취 방지.
  - ADR-003의 노이즈 모니터링 모듈(120d)을 통해 이상행위 실시간 감지.

### **3. 데이터 일관성 문제**
- **설명**: 분산된 모듈(예: 실시간 모니터링 vs. 리포트 제공)에서 데이터 동기화 지연으로 일관성 손실 발생.
- **심각도**: 🟡 Medium
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - 데이터베이스(150)에서 트랜잭션 로그 기반의 ACID 준수 강화.
  - 제어부(120)에서 데이터 버전 관리 및 Conflict-Free Replicated Data Types(CRDT) 적용.
  - 정기적인 데이터 일관성 검증 테스트 수행.

### **4. 확장성 제한**
- **설명**: 모듈별 독립적 확장 가능하지만, 중앙 제어부(120)의 병목 현상으로 시스템 전체 성능 저하 발생.
- **심각도**: 🟡 Medium
- **발생 가능성**: 🟢 Low (단기적으로)
- **대응 방안**:
  - 마이크로 서비스 아키텍처로 제어부(120) 분할 고려.
  - Kubernetes 기반 오토스케일링 도입으로 리소스 동적 할당.
  - ADR-001의 모듈화 원칙을 통해 수평적 확장성 지원.

### **5. 표준 준수 복잡성**
- **설명**: 다수의 글로벌 표준(ISO, ITU-T, ETSI 등) 준수를 위한 구현 복잡성 증가로 개발 지연 및 오류 발생 가능.
- **심각도**: 🟡 Medium
- **발생 가능성**: 🔴 High
- **대응 방안**:
  - 표준 준수에 특화된 개발 도구(예: oneM2M Reference Implementation) 활용.
  - TTA의 스마트팜 표준 가이드북(별표 26) 참조하여 국외 표준과의 연계성 강화.
  - 정기적인 표준 업데이트 모니터링 및 조기 대응 계획 수립.

**참고 사항**:
- **IoT 표준 준수**: 시스템은 ISO/IEC 30141:2024, ITU-T X.1352, oneM2M 등 5개 이상의 글로벌 표준을 준수하여 국제 시장에서의 상호운용성을 보장함.
- **국내 표준 연계**: TTA의 스마트팜 데이터 상호운용 프레임워크(2022년 표준)와 연계하여 국내외 시장에서의 경쟁력 강화.
