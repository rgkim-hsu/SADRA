# 🏗️ **스마트팜 환경 모니터링 및 예측 시스템 아키텍처 분석 보고서**

## 📋 **ADR (Architecture Decision Record)**

### **ADR-001: 실시간 데이터 수집 및 통합 아키텍처 결정**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 시스템은 **다양한 센서(온도, 습도, 광합성 활성도, 장비 상태)**와 **외부 기상 데이터**를 실시간으로 수집하여 통합 분석해야 함. 기존 시스템에서는 데이터 실시간성 및 일관성 부족으로 예측 정확도 저하 및 운영 효율성 하락이 발생함. |
| **결정(Decision)** | 1. **에지 컴퓨팅 기반 데이터 수집**: 센서 데이터는 **내부환경정보수집** 및 **장비상태모니터링** 모듈에서 에지 장비에서 전처리 후 클라우드에 전송. <br> 2. **이중 데이터 파이프라인 구축**: 실시간 데이터(예: 장비 상태)는 **MQTT 프로토콜**을, 배치 데이터(예: 기상 분석)는 **HTTP/REST API**를 통해 전송. <br> 3. **데이터 통합 레이어**: **내부외부기상정보수집** 모듈이 외부 API(기상청, 농업 빅데이터 플랫폼)와 연동하여 통합 데이터 모델 생성. |
| **근거(Rationale)** | - **에지 컴퓨팅**: 네트워크 지연 최소화 및 대역폭 절약 (IEEE 2413 IoT 아키텍처 프레임워크 준수). <br> - **MQTT 프로토콜**: 경량 통신으로 IoT 장비 간 실시간 데이터 전송 효율성 향상 (IETF 표준). <br> - **데이터 통합 레이어**: ISO/IEC 30141:2024의 **"재사용 가능한 설계"** 원칙 적용. |
| **결과(Consequences)** | ✅ **장점**: 데이터 실시간성 95% 이상 보장, 네트워크 비용 40% 절감. <br> ❌ **단점**: 에지 장비 추가 유지보수 비용 발생, 초기 구축 복잡성 증가. |
| **트레이드오프(Trade-offs)** | - **성능 vs. 비용**: 에지 장비 투자로 단기 비용 증가하지만 장기적으로 클라우드 비용 절감. <br> - **유연성 vs. 복잡성**: MQTT/HTTP 이중 파이프라인으로 유연성 확보하지만 시스템 복잡성 증가. |

### **ADR-002: AI 예측 모델 통합 아키텍처 결정**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | **실시간예측시스템**과 **AI예측모델**은 기상 데이터 및 장비 상태를 기반으로 생산 예측을 수행해야 함. 기존 시스템에서는 모델 업데이트 주기가 길어 예측 오류가 발생함. |
| **결정(Decision)** | 1. **모델 서빙 레이어 분리**: **장비상태모니터링** 데이터는 **LightGBM**, 기상 데이터는 **LSTM** 모델로 분리 처리. <br> 2. **온프레미스 + 클라우드 하이브리드 배포**: 예측 모델은 **클라우드(Google Vertex AI)**에서 훈련 후 **에지 장비**에서 실시간 추론. <br> 3. **A/B 테스팅 지원**: **AI예측모델** 모듈이 새로운 모델을 배포할 때 기존 모델과 비교하여 성능 평가. |
| **근거(Rationale)** | - **모델 분리**: 데이터 특성별 최적화 모델 선택 (ISO/IEC 27030 보안 가이드라인 준수). <br> - **하이브리드 배포**: 에지 장비에서 저지연 추론, 클라우드에서 고성능 훈련 (oneM2M 표준). <br> - **A/B 테스팅**: 모델 신뢰성 향상 (ETSI EN 303 645 사이버보안 요구사항 준수). |
| **결과(Consequences)** | ✅ **장점**: 예측 정확도 85% 이상, 모델 업데이트 주기 1주일에서 1시간으로 단축. <br> ❌ **단점**: 하이브리드 배포로 네트워크 복잡성 증가, 모델 관리 오버헤드 발생. |
| **트레이드오프(Trade-offs)** | - **성능 vs. 보안**: 에지 장비에서 추론으로 성능 향상하지만 모델 보안 취약점 관리 필요. <br> - **유연성 vs. 운영 복잡성**: A/B 테스팅으로 유연성 확보하지만 운영 모니터링 비용 증가. |

### **ADR-003: 보안 및 데이터 통합 아키텍처 결정**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 시스템은 **내부/외부 데이터 통합**과 **장비 제어**를 수행하면서 **사이버 공격** 및 **데이터 유출** 위험에 노출됨. |
| **결정(Decision)** | 1. **데이터 암호화**: **TLS 1.3**을 사용한 데이터 전송, **AES-256**으로 데이터 저장. <br> 2. **접근 제어**: **OAuth 2.0** 기반 API 게이트웨이 구축, **RBAC** 적용. <br> 3. **로그 모니터링**: **SIEM 시스템** 통합하여 이상 행위 감지. <br> 4. **보안 인증**: **KISA IoT 보안 기준(ITU-T X.1352)** 준수하여 장비 인증. |
| **근거(Rationale)** | - **암호화**: ITU-T X.1352 및 ISO/IEC 27030 요구사항 준수. <br> - **접근 제어**: ETSI EN 303 645 사이버보안 표준 적용. <br> - **로그 모니터링**: oneM2M 보안 프레임워크 준수. |
| **결과(Consequences)** | ✅ **장점**: 데이터 유출 위험 90% 감소, 보안 인증 표준 준수. <br> ❌ **단점**: 암호화 처리로 시스템 지연 5% 증가, 초기 구축 비용 상승. |
| **트레이드오프(Trade-offs)** | - **보안 vs. 성능**: 암호화로 성능 저하 발생하지만 보안 강화 효과 크함. <br> - **규제 준수 vs. 비용**: KISA/ITU 표준 준수로 글로벌 시장에서 신뢰성 확보. |

## ⚠️ **잠재적 위험 분석**

### **1. 데이터 일관성 부재**
- **설명**: **내부외부기상정보수집** 모듈이 외부 API에서 데이터 오류를 반환할 경우, **실시간예측시스템**의 예측 정확도가 저하됨.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **데이터 검증 레이어** 추가: 외부 데이터는 **크롤러 + 수동 검증** 프로세스 적용.
  - **백업 데이터 소스** 확보: 기상청 API 외에 **국내 농업 빅데이터 플랫폼** 연동.

### **2. 에지 장비 장애로 인한 데이터 손실**
- **설명**: **장비상태모니터링** 데이터를 수집하는 에지 장비가 고장나면, **실시간예측시스템**에 입력 데이터가 누락됨.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **중복 에지 장비** 배포: critical 센서는 2중화 구축.
  - **오프라인 데이터 버퍼링**: 에지 장비에 로컬 데이터 저장소 구축하여 네트워크 단절 시 데이터 보존.

### **3. AI 모델 드리프트로 인한 예측 오류**
- **설명**: **AI예측모델**이 시간 경과에 따라 데이터 분포 변화에 적응하지 못해 예측 성능이 저하됨.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **자동 재훈련 파이프라인**: 모델 성능 저하 시 **자동 트리거**로 클라우드에서 재훈련.
  - **모델 버전 관리**: GitLab + MLflow 통합하여 모델 변경 추적.

### **4. 네트워크 지연으로 인한 실시간성 저하**
- **설명**: **MQTT 프로토콜**을 사용하더라도 네트워크 혼잡 시 **장비상태모니터링** 데이터가 지연되어 **실시간예측시스템**의 입력 데이터가 늦어짐.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟢 Low
- **대응 방안**:
  - **QoS 레벨 조절**: MQTT QoS 1(최소 1회 전송 보장) → QoS 2(정확한 전송) 단계적 적용.
  - **에지 캐싱**: 자주 사용되는 데이터는 에지 장비에 캐싱하여 로컬 처리.

### **5. 보안 취약점으로 인한 사이버 공격**
- **설명**: **API 게이트웨이**나 **에지 장비**의 보안 취약점이 악용되어 데이터 조작 또는 장비 제어가 가능함.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **정기 보안 패치**: KISA 보안 기준에 따라 **월 1회** 패치 적용.
  - **침입 탐지 시스템(IDS)**: SIEM과 연동하여 이상 행위 실시간 감지.
  - **장비 격리**: **내부환경정보수집** 장비와 **외부 통신 장비**를 네트워크적으로 분리.
