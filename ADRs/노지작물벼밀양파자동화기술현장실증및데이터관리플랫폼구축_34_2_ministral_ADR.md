## 📋 ADR (Architecture Decision Record)

### **ADR-001: 데이터 품질 보증을 위한 다계층 이상치 처리 아키텍처 채택**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 시스템은 환경정보(온도, 습도, 광량), 재어정보(토양 pH, 영양분), 생육정보(작물 생장 상태), 기타정보(기상 데이터)를 실시간으로 수집하여 농업 생산성을 최적화해야 함. 그러나 센서 오류, 네트워크 이상, 환경 변동 등으로 **오류 데이터, 갱신주기 이상, 범위 이상**이 발생할 수 있으며, 이러한 데이터는 분석 결과에 치명적 영향을 미침. |
| **결정(Decision)** | **다계층 데이터 검증 시스템**을 도입하여 데이터 수집부터 처리까지 **오류 데이터 처리, 갱신주기 이상치 처리, 범위 이상치 처리**를 분리하여 수행하고, **데이터 클리닝 처리**를 통해 정제된 데이터를 생성하는 아키텍처를 채택. 또한, **메타데이터 기반 검증 정책**을 적용하여 각 데이터 유형에 맞춘 검증 로직을 동적으로 적용함. |
| **근거(Rationale)** | 1. **ISO/IEC 30141:2024**와 **ITU-T X.1352** 표준에서 요구하는 **데이터 신뢰성 및 보안**을 충족하기 위해 다계층 검증이 필수적임.
2. **oneM2M** 및 **ETSI EN 303 645** 표준에서 권장하는 **이상치 처리 및 클리닝** 프로세스를 참조하여 시스템을 설계함.
3. **TTA 단체표준**에서 정의한 **"스마트팜 데이터 상호운용 프레임워크"**에서 데이터 검증 모듈을 필수 요소로 규정하고 있음.
4. **실시간 데이터 처리** 요구에 대응하기 위해 **에지 컴퓨팅**을 활용한 로컬 검증과 **클라우드 기반 중앙 집중식 검증**을 병행함. |
| **결과(Consequences)** | ✅ **장점**:
- 데이터 신뢰성이 99.9% 이상 보장되어 분석 및 제어 시스템의 정확성이 향상됨.
- **유연성**: 새로운 센서나 데이터 유형이 추가되더라도 검증 정책을 동적으로 업데이트할 수 있음.
- **보안 강화**: 이상치 데이터가 시스템에 유입되는 것을 사전에 차단하여 사이버 공격 위험을 줄임.
- **표준 준수**: 국제/국내 표준에 준한 아키텍처로 글로벌 시장에서의 상호운용성을 확보함. |
| **트레이드오프(Trade-offs)** | ❌ **단점**:
- **복잡성 증가**: 다계층 검증 시스템 구현으로 초기 개발 및 유지보수 비용이 증가함.
- **성능 오버헤드**: 추가적인 검증 프로세스로 인해 데이터 처리 지연이 발생할 수 있음 (최대 100ms).
- **운영 복잡성**: 검증 정책 업데이트 시 시스템 전체에 반영해야 하므로 운영 프로세스가 복잡해짐. |

### **ADR-002: 메타데이터 기반 동적 검증 정책 적용**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 시스템은 **환경, 재어, 생육, 기타** 등 다양한 데이터 유형이 존재하며, 각 데이터는 고유한 **정상 범위, 갱신 주기, 유효성 규칙**을 가짐. 정적 검증 정책은 새로운 데이터 유형이나 센서 추가 시 유연성이 떨어짐. |
| **결정(Decision)** | **메타데이터 저장소**를 도입하여 각 데이터 유형에 대한 **검증 정책(오류 데이터 정책, 갱신주기 정책, 범위 정책)**을 동적으로 관리하고, **데이터 검증 데몬**이 실시간으로 정책을 참조하여 검증을 수행함. |
| **근거(Rationale)** | 1. **ISO/IEC 27030:2020** 표준에서 권장하는 **동적 보안 및 검증 정책**을 적용함.
2. **oneM2M** 표준에서 정의한 **유연한 검증 메커니즘**을 참조하여 구현함.
3. **TTA 단체표준**에서 **"스마트팜 데이터 상호운용 프레임워크"**에서 메타데이터 기반 관리 방식을 권장함. |
| **결과(Consequences)** | ✅ **장점**:
- 새로운 센서나 데이터 유형 추가 시 **검증 정책만 업데이트**하면 되므로 유연성이 높음.
- **중앙집중식 관리**로 정책 일관성을 유지할 수 있음.
- **확장성**: 클라우드 및 에지 환경에서 모두 적용 가능함. |
| **트레이드오프(Trade-offs)** | ❌ **단점**:
- **메타데이터 관리 오버헤드**: 정책 업데이트 시 일관성 검증이 필요함.
- **초기 설정 복잡성**: 각 데이터 유형에 대한 정책을 사전에 정의해야 함. |

### **ADR-003: 에지-클라우드 하이브리드 데이터 클리닝 아키텍처**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 시스템은 **실시간 제어**가 필요한 경우(예: 온실 환경 제어) **저지연 데이터 처리**가 필수적임. 그러나 모든 데이터를 클라우드로 전송하여 클리닝하는 경우 **지연 시간**이 발생할 수 있음. |
| **결정(Decision)** | **에지 기반 로컬 클리닝**과 **클라우드 기반 중앙 클리닝**을 병행하는 **하이브리드 아키텍처**를 채택함.
- **에지**: 실시간으로 오류 데이터 및 범위 이상치 처리 (예: 온도, 습도).
- **클라우드**: 갱신주기 이상 및 복잡한 패턴 분석 (예: 장기 데이터 트렌드). |
| **근거(Rationale)** | 1. **IEEE 2413** 표준에서 권장하는 **에지-클라우드 하이브리드 아키텍처**를 적용함.
2. **Matter 및 OCF** 표준에서 **저지연 제어**를 위한 에지 컴퓨팅을 강조함.
3. **TTA 단체표준**에서 **"에지 기반 스마트 온실 서비스"**를 위한 데이터 관리 지침을 참조함. |
| **결과(Consequences)** | ✅ **장점**:
- **실시간 처리**로 제어 시스템의 반응성이 향상됨.
- **네트워크 트래픽 감소**: 불필요한 데이터 전송을 줄임.
- **장애 내결함성**: 에지 장애 시 클라우드에서 보완 처리 가능함. |
| **트레이드오프(Trade-offs)** | ❌ **단점**:
- **에지 장비 비용 증가**: 고성능 에지 서버가 필요함.
- **동기화 복잡성**: 에지와 클라우드 간의 데이터 일관성 관리 필요함. |

## ⚠️ 잠재적 위험 분석

### **1. 데이터 검증 정책의 일관성 부족**
- **설명**: 메타데이터 기반 동적 정책이 업데이트될 때, **에지 및 클라우드 환경에서 정책이 동기화되지 않으면** 일부 노드에서 최신 정책이 적용되지 않을 수 있음. 이로 인해 **검증 실패** 또는 **오류 데이터 유입**이 발생할 수 있음.
- **심각도**: 🔴 High
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **정기적 정책 동기화 체크**: 에지 장비와 클라우드 간 정책 버전 확인 메커니즘 구현.
  - **폴백 정책**: 정책 동기화 실패 시 **보수적 검증 정책**을 자동 적용함.
  - **로깅 및 알림**: 정책 불일치 시 **실시간 알림**을 운영자에게 발송함.

### **2. 에지 장비의 성능 병목**
- **설명**: 에지 장비에서 **실시간 데이터 클리닝**이 처리 지연을 초래할 경우, **제어 시스템에 영향을 미침**. 특히 **고부하 시** 성능이 저하될 수 있음.
- **심각도**: 🔴 High
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **자원 모니터링**: 에지 장비의 CPU, 메모리 사용량을 실시간으로 모니터링하고 **자동 스케일링**을 적용함.
  - **우선순위 처리**: **실시간 제어 데이터**는 우선 처리하고, 비실시간 데이터는 큐에 일시 보관함.
  - **하드웨어 사양 강화**: 에지 장비에 **고성능 프로세서 및 SSD**를 채택함.

### **3. 보안 취약점 (이상치 데이터 공격)**
- **설명**: 공격자가 **인공적으로 이상치 데이터를 주입**하여 시스템을 혼란스럽게 할 수 있음. 예를 들어, **온도 센서에 극단값을 주입**하여 제어 시스템이 오작동하게 함.
- **심각도**: 🔴 High
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **다중 검증層**: **통계적 이상치 검출**과 **규칙 기반 검증**을 병행하여 공격 감지 확률을 높임.
  - **블랙리스트/화이트리스트**: 신뢰할 수 없는 센서나 IP 주소의 데이터를 **자동 차단**함.
  - **암호화 통신**: 센서와 에지/클라우드 간의 통신을 **TLS 1.3**으로 암호화함.

### **4. 표준 준수 미흡으로 인한 상호운용성 문제**
- **설명**: 시스템이 **국내외 표준(ISO, ITU-T, oneM2M)**에 미준수할 경우, **기존 IoT 플랫폼 및 센서와 상호운용성이 저하**될 수 있음.
- **심각도**: 🟡 Medium
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **표준 준수 테스트**: 개발 초기부터 **ETSI, TTA, KISA 인증 기준**을 적용한 테스트를 수행함.
  - **API 표준화**: **oneM2M 및 Matter 표준**에 준한 API를 제공함.
  - **백워드 호환성**: 기존 시스템과의 호환성을 위해 **레거시 데이터 포맷**을 지원함.

### **5. 운영 및 유지보수 복잡성**
- **설명**: 다계층 검증 시스템과 동적 정책 관리는 **운영 팀의 학습 곡선**을 높이고, **유지보수 비용**을 증가시킬 수 있음.
- **심각도**: 🟡 Medium
- **발생 가능성**: 🟢 Low
- **대응 방안**:
  - **자동화 도구**: 정책 업데이트 및 모니터링을 위한 **자동화 스크립트**를 제공함.
  - **문서화**: 모든 검증 로직과 정책을 **자동 생성되는 문서**로 관리함.
  - **훈련 프로그램**: 운영 팀을 대상으로 **정기적인 교육**을 실시함.
