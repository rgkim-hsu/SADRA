## 📋 ADR (Architecture Decision Record)

### ADR-001: Edge-Cloud 분리 구조 및 실시간 데이터 동기화 구현

| 항목 | 내용 |
|------|------|
| **상황 (Context)** | 스마트팜 환경에서의 사료 잔량 모니터링 시스템은 현장의 센서 데이터 (원격 센서부, 제어부) 를 실시간으로 처리해야 하며, 동시에 관리자 단말을 통해 중앙 서버에서 통합 분석 및 제어 (사료 공급기 제어) 를 수행해야 함. |
| **결정 (Decision)** | **에지-클라우드 분리 아키텍처 채택**. 현장 장치는 데이터 수집 및 초기 로직 처리, 중앙 서버는 데이터 집계, 분석, 장기 저장 및 관리자 UI 연동을 담당. <br> **프로토콜 표준화**: TTA 표준 (TTAK.KO-10.1170 등) 과 ISO/IEC 30141 기준에 맞춰 통신 인터페이스 및 API 를 정의. |
| **근거 (Rationale)** | - **지연 시간 최소화**: 현장 제어 (사료 공급) 는 에지 장치가 담당하여 네트워크 지연을 줄임.<br>- **보안성**: 관리자 단말과 모니터링 서버가 별개의 생명선 (Lifeline) 으로 분리되어 있으며, S200/S202 단계에서 장치 등록 및 인증 과정을 거치므로 권한 분리가 명확함.<br>- **확장성**: S200, S202 단계를 통해 많은 수의 장치를 등록 및 관리하는 표준 프로세스를 갖춰 시스템 확장성 확보. |
| **결과 (Consequences)** | - **긍정적**: 고가용성 제공, 다양한 IoT 기기 간 상호운용성 보장 (Matter, oneM2M 등 표준 준수).<br>- **부정적**: 초기 시스템 설정 및 표준화 작업이 복잡할 수 있음. |
| **트레이드오프 (Trade-offs)** | - **장점**: 시스템의 안정성과 보안성 극대화.<br>- **단점**: 하드웨어 및 소프트웨어 구현의 초기 복잡도 증가. |

### ADR-002: 표준화된 장치 등록 및 생명주명 관리 (Device Lifecycle Management)

| 항목 | 내용 |
|------|------|
| **상황 (Context)** | 수많은 사료 잔량 감시 장치 (10) 와 사료 공급기 (30) 를 시스템에 추가하고 제거하는 과정이 빈번하게 발생할 수 있음. 또한 관리자 단말 (40) 을 통해 제어 지점 등록/변경 (S212, S210) 이 이루어짐. |
| **결정 (Decision)** | **등록/해제 중앙 집중화**. 모든 장치 등록, 제어 지점 설정, 사료 공급기 정보 갱신은 중앙 `사료 잔량 모니터링 서버 (20)` 를 경유하여 진행. <br> **상태 머신 사용**: 장치가 `등록됨`, `운영중`, `오작동` 등 명확한 상태를 가지도록 상태 관리 로직 구현. |
| **근거 (Rationale)** | - **일관성 유지**: S225, S232 등의 흐름처럼 측정명령과 결과를 중앙 서버가 중재하여 일관된 데이터 유지.<br>- **관리 효율성**: ETSI EN 303 645 등 사이버보안 표준을 준수하여 등록 시 보안 인증 (S202) 절차 필수화.<br>- **유지보수 용이**: 표준화된 등록/해제 인터페이스 (API) 를 통해 TTA 표준과 연동. |
| **결과 (Consequences)** | - **긍정적**: 시스템 내 장치 상태의 투명성 확보, 관리자 작업 용이.<br>- **부정적**: 중앙 서버 부하 관리 필요 (등록 요청 폭주 대비). |
| **트레이드오프 (Trade-offs)** | - **장점**: 중앙 집중적 관리는 오작동 방지.<br>- **단점**: 서버 장애 시 전체 시스템 등록 불가. |

### ADR-003: 다계층 보안 및 권한 분리 구조

| 항목 | 내용 |
|------|------|
| **상황 (Context)** | 시스템은 `원격 센서부/제어부` (에지), `모니터링 서버` (클라우드/중계), `관리자 단말` (사용자) 로 구성됨. IoT 보안 표준 (ITU-T X.1352 등) 에 따라 보안을 강화해야 함. |
| **결정 (Decision)** | **세그먼트화된 보안 계층 설계**. <br>1. **인증 계층**: 장치 등록 단계 (S202) 에서 장치 인증. <br>2. **인가 계층**: 관리자 단말이 서버에 접근할 때 권한 확인. <br>3. **데이터 보호 계층**: 측정 결과 전송 (S234) 시 암호화 전송 (비표시 가정). |
| **근거 (Rationale)** | - **공격 표면 축소**: 관리자 단말이 직접 장치를 제어하지 않고 서버를 경유하도록 함 (S245, S240 흐름).<br>- **규정 준수**: ISO/IEC 27030 가이드라인을 따르며, 특히 사료 공급기 제어 (S270) 와 같은 중요 기능은 서버 인증을 통해만 허용.<br>- **데이터 무결성**: 측정이 결과 처리 (S270) 와 공급 정보 갱신 (S275) 은 서버에서 일괄 처리하여 조작 방지. |
| **결과 (Consequences)** | - **긍정적**: 사료 공급 및 제어 관련 리스크 감소, 외부 해킹 위협 저하.<br>- **부정적**: 네트워크 성능에 따른 약간의 오버헤드. |
| **트레이드오프 (Trade-offs)** | - **장점**: 높은 보안 수준 달성.<br>- **단점**: 처리 속도가 미세하게 감소할 수 있음. |

## ⚠️ 잠재적 위험 분석

### 1. [네트워크 연결성 단절 및 데이터 손실 위험]
- **설명:** 사료 잔량 감시 장치 (10) 와 사료 공급기 (30), 모니터링 서버 (20) 간 통신 경로 (S230, S234) 에서 네트워크 장애가 발생하여 실시간 데이터 전송이 정지될 경우.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** - **에지 로직 로컬 실행**: 네트워크가 끊어졌을 때라도 제어부 (140) 가 로컬 로직으로 일시적인 사료 공급 중단/통지 로직 구현.<br>- **재시도 메커니즘**: S225, S232 요청 시 네트워크 재연결을 위한 지체 시간 (Back-off) 로직 적용.

### 2. [센서 오작동 및 측정 데이터 왜곡 위험]
- **설명:** 원격 센서부 (120) 가 오작동하거나 외부 간섭 (전자파, 이물질) 을 받아 `변 급이기동 측정명령` (S225) 결과와 실제 잔량이 다르면, 공급기 (30) 가 부적절하게 사료를 공급할 경우.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** - **데이터 필터링 및 중복 측정**: S232 측정 결과가 서버에서 S234 를 통해 검증받는 과정에서 이력 데이터와 비교하여 이상치 필터링.<br>- **백업 센서**: 주요 센서 부가 고장 시 예비 센서로 자동 전환하는 하드웨어 설계.

### 3. [관리자 권한 남용 및 무단 접근 위험]
- **설명:** 관리자 단말 (40) 에서 비인가 사용자가 `관리지점 등록/초기화` (S212) 나 `변경관리` (S240, S245) 를 수행하여 시스템 설정을 조작할 경우.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** - **서버-클라이언트 권한 분리**: S212 흐름처럼 서버가 관리자 권한을 엄격히 검증.<br>- **보안 로그 및 감사**: 모든 S204, S210 접근이 감사 로그로 기록되고, 이상 징후 시 자동으로 관리자를 차단.

### 4. [시스템 확장성 한계 및 서버 과부하 위험]
- **설명:** 초기화 (S212) 와 등록 (S202) 을 통한 장치 수가 급격히 증가하면 서버 (20) 가 S220, S234 같은 처리 요청을 감당하지 못해 처리 지연 발생.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low (단, 급성확장 시)
- **대응 방안:** - **메시지 큐 도입**: S225 등 요청을 직접 처리하지 않고 메시지 큐 (MQTT, Kafka 등) 를 통해 비동기 처리.<br>- **마이크로서비스 아키텍처**: 사료 공급, 모니터링, 데이터 분석 기능을 분리하여 독립적인 확장성 확보.

### 5. [데이터 일관성 및 동기화 문제]
- **설명:** S260, S265 같은 흐름에서 `사료 잔량 측정명령요` 와 실제 측정 결과 간의 시간차를 두고 데이터가 동기화되지 않아 사료 공급 계산 오류 발생.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** - **최종 데이터 버전 관리**: S275 공급 정보 갱신 시 데이터 버전 (Timestamp, Version) 을 함께 관리하여 충돌 감지.<br>- **트랜잭션 안전성**: 중요한 제어 명령 (S270) 에는 ACID 특성이 확보된 트랜잭션 처리 적용.
