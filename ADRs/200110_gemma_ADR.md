# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 다단계 비파괴적 데이터 품질 검증 파이프라인 구축

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 환경에서 수집되는 데이터(환경, 제어, 생육 등)는 센서 노이즈, 통신 지연, 물리적 이상(오류), 시간적 변동(갱신주기 오류), 그리고 시스템적 결함(범위 이탈)을 포함하고 있어 데이터 신뢰도가 극히 낮습니다. 단순 필터링 방식으로는 근본 원인 분석이 불가능하며, 데이터의 투명성과 추적 가능성(Auditability)이 핵심 과제입니다. |
| **결정(Decision)** | 데이터 검증 시스템을 **Error $\to$ Temporal $\to$ Range $\to$ Cleaning**의 순차적, 비파괴적(Non-destructive) 다단계 파이프라인으로 설계합니다. 각 단계의 검증 결과와 적용 로직은 별도의 *처리결과이력*에 기록하여 데이터 출처 및 신뢰성을 완벽하게 보존합니다. |
| **근거(Rationale)** | 1. **신뢰성 확보:** 각 단계별로 전문화된 검증기(Module)를 적용하여 데이터의 결함을 다각도로 검출합니다. (오류 $\to$ 시간/범위 $\to$ 클리닝). 2. **추적 가능성(Traceability):** 데이터를 폐기하는 것이 아니라, '어떤 오류가 발견되었고, 어떤 로직으로 수정되었는지'를 이력으로 남겨 과학적 근거를 마련합니다. 3. **복잡성 관리:** 표준화(Standardization)와 검증(Validation) 로직을 분리하여 유지보수성과 확장성을 높입니다. |
| **결과(Consequences)** | **긍정적:** 데이터 품질이 극대화되어 AI/ML 기반의 의사결정 시스템에 높은 신뢰도의 원천 데이터를 제공합니다. 시스템의 감사(Audit) 기능이 완벽하게 구현됩니다. **부정적:** 파이프라인 처리 과정 자체가 복잡하고, 여러 단계를 거치므로 전체 처리 지연 시간(Latency)이 증가할 수 있습니다. |
| **트레이드오프(Trade-offs)** | **[신뢰도와 비용]** : 데이터의 신뢰도와 추적 가능성(높은 품질)을 최우선 가치로 두고, 이를 위해 시스템 복잡도 증가 및 처리 지연 시간(Latency)이라는 운영적 비용을 감수한다. |

## ⚠️ 잠재적 위험 분석

### 1. 실시간 결정 지연 및 운영 병목 현상 (System Latency Bottleneck)
- **설명:** 데이터 검증 과정이 '오류 $\to$ 시간 $\to$ 범위 $\to$ 클리닝'의 다단계 순차 구조로 설계되었기 때문에, 데이터가 시스템에 유입되는 순간부터 최종 '정제 데이터'가 나오기까지의 전체 처리 시간이 길어질 수 있습니다. 이는 실시간 환경 제어(예: 급작스러운 환경 변화에 대한 자동 대응)에 치명적인 지연을 초래합니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 처리 파이프라인 중 Time-Critical 데이터를 식별하여, 필수 핵심 데이터(예: 현재 온도, 습도)에 대해서는 일부 검증 단계(가장 기본적인 범위 및 오류 검출)만 통과시키는 Fast Path를 구축하여 지연 시간을 최소화해야 합니다.

### 2. 데이터 드리프트(Data Drift) 및 미지의 패턴 오류 감지 실패
- **설명:** 현재 아키텍처는 명확하게 정의된 오류(Outlier, 범위 초과)를 처리하는 데 초점을 맞추고 있습니다. 하지만 시간이 지나면서 작고 점진적으로 변화하는 센서의 교정 오차(Sensor Drift)나, 새로운 농작물/환경 조건으로 인해 기존 검증 로직으로는 포착할 수 없는 패턴의 이상치(Novel Anomaly)가 발생할 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 검증 파이프라인에 통계적 모델 기반의 **행동 분석(Behavioral Analysis)** 또는 **머신러닝 기반 이상 감지(ML-based Anomaly Detection)** 모듈을 추가적으로 통합하여, 정해진 규칙 외의 데이터 패턴 이상을 지속적으로 모니터링하고 룰을 자동 업데이트할 수 있는 기능을 구현해야 합니다.

### 3. 검증 로직 오염 및 위변조 위험 (Logic Corruption/Tampering)
- **설명:** '오류데이터 처리'나 '데이터 클리닝 처리' 같은 핵심 모듈은 데이터가 최종적으로 '정제 데이터'가 되기 직전에 가장 강력한 변환을 가하는 지점입니다. 만약 이 로직(예: 필터링 알고리즘, 정규화 상수) 자체가 해킹되거나 오염될 경우, 악의적인 주체가 시스템을 통해 완전히 허위의 데이터를 생성하고 전파할 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 모든 검증 로직 및 파라미터는 반드시 **읽기 전용(Read-Only)**으로 관리하고, GitOps 기반의 강력한 형상 관리 및 변경 승인 프로세스를 의무화해야 합니다. 또한, 주요 검증 로직의 실행 결과를 불변의 원장 데이터베이스(Ledger Database)에 기록하여 무결성을 보장해야 합니다.

### 4. 데이터 출처의 상호운용성 및 메타데이터 부족 (Heterogeneity & Metadata Deficiency)
- **설명:** '환경정보', '제어정보', '생육정보', '기타정보'는 각기 다른 프로토콜, 시간 간격, 데이터 모델을 가지고 수집됩니다. 이러한 이질적인 데이터가 파이프라인에 진입할 때, 각 데이터가 어느 기기에서, 언제, 어떤 방식으로 측정되었는지에 대한 충분한 메타데이터가 부족하면 검증 작업의 정확도가 떨어지고 데이터의 통합 분석 자체가 불가능해집니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 데이터 수집 계층(Ingestion Layer)에서 **강력한 표준화 게이트웨이**를 구축하고, 모든 데이터에 대해 다음 메타데이터를 필수로 태깅해야 합니다: (1) 측정 시점 (Timestamp), (2) 측정 주체/장비 ID, (3) 사용된 측정 단위 및 프로토콜 버전, (4) 데이터 타입/출처 유형.

### 5. 데이터 이력 관리의 비용 및 복잡성 증가 (Storage and Management Complexity)
- **설명:** 아키텍처 결정에 따라 모든 검증 과정과 오류 발생 내역(처리결과이력)을 보존하는 것은 데이터 무결성을 높이지만, 이는 엄청난 양의 데이터 스토리지(처음 원본 데이터 + 각 단계의 임시 데이터 + 최종 이력 데이터)를 필요로 합니다. 이로 인해 저장 비용과 데이터 관리(Data Governance) 복잡성이 급격히 증가합니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 데이터의 라이프사이클 단계별로 보관 정책을 명확히 수립해야 합니다. 단기적인 '실시간 검증 결과'는 고성능 메모리/저장소에 유지하되, 오래된 '처리결과이력' 데이터는 비용 효율적인 장기 아카이브 스토리지(예: AWS S3 Glacier)로 단계적으로 이동시키는 아카이빙 전략을 적용해야 합니다.
