# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 클라우드 기반 스마트 팜 학습 및 모니터링 통합 아키텍처 적용

| 항목                     | 내용                                                                                                                                                                                                                                                                                |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트 팜 환경에서 다수의 사용자(User 1 ~ User n)가 농장을 모니터링하면서 동시에 관련 학습 정보(LMS)를 제공받아야 합니다. 단순 모니터링 시스템과 학습 관리 시스템(LMS)이 분리되어 있을 경우, 사용자의 실시간 농장 상황(Farming Information)에 맞는 최적화된 학습 콘텐츠를 제공하기 어렵고 데이터 연계가 복잡해지는 문제가 있습니다.                                                                     |
| **결정(Decision)**       | 사용자 단의 **모니터링 기능(Monitoring Function)**과 클라우드 단의 **스마트 팜 관리 기능(Smart Farming Management Function)**을 분리하되, **학습 선별 기능(Learning Screening Function)**과 **학습 정보 연결 기능(Learning Information Connection Function)**을 통해 양자를 연결하는 **하이브리드 통합 아키텍처**를 채택합니다.                            |
| **근거(Rationale)**      | 이미지에서 볼 수 있듯이, 사용자는 로컬 또는 엣지 수준의 모니터링 기능과 직접 상호작용하며, 여기서 선별된 학습 요구사항이 학습 정보 연결 기능을 통해 클라우드의 LMS 및 FMCF(Farming Management Control Function)와 연동됩니다. 이는 실시간성 요구사항이 높은 모니터링과 대용량 데이터 처리가 필요한 학습/관리 기능을 물리적으로 분리하여 성능을 최적화하면서, 논리적으로는 'Farming Information'을 통해 통합된 서비스를 제공하기 위함입니다. |
| **결과(Consequences)**   | **긍정적:** 사용자는 실시간 모니터링에 집중할 수 있으며, 클라우드 기반의 LMS를 통해 농장 상태에 맞는 맞춤형 학습 콘텐츠를 제공할 수 있습니다. 시스템 확장이 용이합니다.<br>**부정적:** 클라우드와의 통신이 끊길 경우 학습 정보 제공 및 원격 관리 기능이 제한될 수 있으며, 로컬 모니터링 기능과 클라우드 기능 간 데이터 동기화 지연이 발생할 수 있습니다.                                                                   |
| **트레이드오프(Trade-offs)** | **장점:** 모니터링 실시간성 확보 및 클라우드 기반의 고도화된 분석/학습 콘텐츠 활용.<br>**단점:** 네트워크 의존도 증가 및 로컬-클라우드 간 데이터 정합성 유지에 대한 복잡성 증가.                                                                                                                                                                      |

---

## ️ 잠재적 위험 분석

### 1. 네트워크 단절 시 학습 및 관리 기능 마비 (Network Dependency Risk)

- **설명:** 'Learning Information Connection Function'이 클라우드의 LMS 및 Smart Farming Management Function과 통신하여 'Farming Information'을 주고받습니다. 네트워크 연결이 불안정하거나 끊길 경우, 사용자는 모니터링은 가능할지 몰라도 학습 콘텐츠 연결과 원격 농장 관리 기능을 상실하게 됩니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 학습 정보 연결 기능에 **오프라인 캐싱(Offline Caching)** 메커니즘을 도입하여, 네트워크断开 시에도 최근 학습 콘텐츠나 관리 명령을 로컬에서 일시적으로 처리할 수 있도록 해야 합니다.

### 2. 다중 사용자 동시 접속 시 모니터링 지연 (Scalability & Latency Risk)

- **설명:** 'User 1'부터 'User n'까지 다수의 사용자가 'Monitoring Function'에 동시에 접속하여 데이터를 요청할 경우, 모니터링 서버의 부하가 급증하여 실시간 데이터 조회에 지연(Latency)이 발생하거나 서비스가 다운될 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 모니터링 기능 서버에 **로드 밸런서(Load Balancer)**를 적용하고, 사용자 세션 관리를 효율화하며, 데이터 전송 시 **MQTT**와 같은 경량 프로토콜을 사용하여 대역폭 사용을 최적화해야 합니다.

### 3. 학습 선별 알고리즘의 부정확성 (Relevance Risk)

- **설명:** 'Learning Screening Function'이 모니터링 데이터를 기반으로 적절한 학습 콘텐츠를 선별해야 합니다. 만약 선별 로직(알고리즘)이 부정확하거나 농장 상태 데이터(Farming Information)의 품질이 낮다면, 사용자에게 부적절한 학습 정보를 제공하여 오히려 혼선을 줄 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 학습 선별 로직에 **머신러닝 기반 추천 엔진**을 적용하고, 지속적인 피드백 루프(User Feedback)를 통해 선별 정확도를 개선해야 합니다. 또한 데이터 전처리 단계에서 이상치 제거 로직을 강화해야 합니다.

### 4. 클라우드 데이터 보안 및 개인정보 유출 (Security Risk)

- **설명:** 클라우드 내부에는 LMS(학습 기록)와 FMCF(농장 제어 정보), Smart Farming Management Function(농장 데이터)가 저장됩니다. 이는 사용자의 개인정보와 농장의 중요한 운영 데이터를 포함하므로, 해킹이나 내부자에 의한 유출 위험이 존재합니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 클라우드 저장소 및 통신 구간(Learning Information Connection Function <-> Cloud)에 대해 **종단 간 암호화(End-to-End Encryption)**를 적용하고, 접근 제어(IAM)를 통해 권한이 없는 사용자의 데이터 접근을 차단해야 합니다.

### 5. LMS와 FMCF 간 데이터 불일치 (Data Consistency Risk)

- **설명:** 클라우드 내에서 LMS(학습 관리)와 FMCF(농장 관리 제어)가 상호 연동됩니다. 만약 농장 제어 데이터(FMCF)가 업데이트되었는데 LMS의 학습 콘텐츠 매핑 정보가 즉시 업데이트되지 않으면, 사용자가 현재 농장 상황에 맞지 않는 구버전 학습 정보를 받게 될 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** LMS와 FMCF 간 데이터 연동에 **이벤트 드리븐 아키텍처(Event-Driven Architecture)**를 적용하여, 농장 상태 변경 시 즉시 학습 관리 시스템에 알림을 전송하고 데이터를 동기화하는 트리거(Trigger) 로직을 구현해야 합니다.
