📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 다단계 직렬 신호 처리 파이프라인 기반 AI-TMS 보정 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 환경의 굴뚝 자동측정기기(TMS)는 x1(9.999) → 1차 보정 블록(-0.001) → x2(8.999)/x3(1.001) 분기 → 2차 처리 블록(0.000) → x4(3.999)/x5(5.000) 분기 → 3차 보정 블록(0.002) → x6(5.999) 출력의 다단계 연산 흐름을 가진다. 각 단계에서 미세한 수치 보정(오차 범위 ±0.001~0.002 수준)이 누적되며, 최종 출력값의 정밀도가 환경 규제 적합성 판단에 직결된다. |
| **결정(Decision)**       | 입력 신호를 직렬 파이프라인 구조로 처리하되, 각 처리 블록 간 분기(x2/x3, x4/x5)를 통해 병렬 경로를 구성하고 AI 기반 미세 보정 계수(-0.001, 0.000, 0.002)를 각 노드에 독립적으로 적용하는 계층형 신호 보정 아키텍처를 채택한다.                                                                                                           |
| **근거(Rationale)**      | 굴뚝 배출가스 측정의 특성상 단일 측정값이 아닌 복수 물리량(온도, 유속, 농도 등)의 교차 보정이 필수적이며, 각 단계별 보정 계수를 AI 모델이 독립 학습·갱신할 수 있도록 모듈화함으로써 유지보수성과 정확도를 동시에 확보할 수 있다. 스마트팜 적용 시 농약 잔류, CO₂, NH₃ 등 복합 가스 측정에서 단일 보정으로는 충분한 정밀도를 달성할 수 없다.                                                     |
| **결과(Consequences)**   | (긍정) 각 블록이 독립적으로 보정 계수를 보유하므로 특정 센서 이상 시 해당 블록만 재학습·교체 가능. 출력값 x6(5.999)의 최종 오차가 원본값 대비 0.001 수준으로 억제됨. (부정) 파이프라인 단계 증가에 따라 지연시간(latency)이 누적되고, 중간 노드(x3: 1.001, x4: 3.999) 장애 시 전체 체인에 영향을 미침.                                                           |
| **트레이드오프(Trade-offs)** | 【획득】고정밀 다중 보정, 모듈별 독립 업데이트, 단계별 감사 로그 확보 가능 / 【감수】파이프라인 깊이에 비례한 처리 지연, 중간 분기점의 데이터 동기화 복잡도 증가, 각 블록 AI 모델의 개별 학습 데이터 확보 부담                                                                                                                                  |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. 중간 분기 노드 데이터 불일치(Data Skew) 위험

* **설명:** x2(8.999)와 x3(1.001)로 분기된 신호가 2차 처리 블록(0.000)에서 재결합될 때, 두 경로의 처리 지연이 상이할 경우 타임스탬프 불일치로 인해 0.000 보정 블록이 잘못된 입력 쌍을 연산할 수 있다. 스마트팜 환경에서 네트워크 지연이 발생하는 경우 더욱 빈번히 나타난다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 각 분기 노드에 타임스탬프 기반 동기화 버퍼(Synchronization Buffer)를 적용하고, 최대 허용 스큐(skew) 임계값 초과 시 해당 측정 주기를 무효화하는 데이터 품질 게이트(Data Quality Gate)를 구현한다.

### 2. AI 보정 계수 드리프트(Model Drift) 위험

* **설명:** 1차 블록(-0.001), 2차 블록(0.000), 3차 블록(0.002)의 보정 계수는 학습 시점의 환경 조건을 반영한다. 스마트팜의 계절적 변화(온습도, 작물 밀도 변화)나 굴뚝 내부 오염 누적으로 센서 특성이 점진적으로 변화하면 기존 보정 계수가 오히려 오차를 증폭시킬 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 각 보정 블록에 온라인 학습(Online Learning) 또는 주기적 재학습(Scheduled Retraining) 파이프라인을 연결하고, 보정 계수 변화량이 설정 임계치(예: ±0.005)를 초과할 경우 자동 알림 및 수동 검증 프로세스를 트리거한다.

### 3. 단일 장애점(SPOF) — 1차 보정 블록 집중 위험

* **설명:** 입력 x1(9.999)이 단일 1차 보정 블록(-0.001)을 반드시 통과한 후 하위 파이프라인으로 전달되는 직렬 구조이므로, 해당 블록의 연산 오류 또는 장애 발생 시 전체 측정 체계가 중단된다. 규제 목적의 TMS에서 측정 공백은 법적 문제를 야기한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 1차 보정 블록을 Active-Standby 이중화 구성으로 배치하고, 장애 감지 즉시 패스스루(Pass-through) 모드로 전환하여 보정 없이도 원시값 기록이 가능하도록 폴백(Fallback) 메커니즘을 설계한다.

### 4. 보정 계수 위변조 및 사이버 보안 위협

* **설명:** 각 AI 보정 블록의 가중치 파라미터(-0.001, 0.000, 0.002)가 외부 공격자 또는 내부 관계자에 의해 무단 변경될 경우, 측정값이 환경 기준치를 의도적으로 충족하는 것처럼 조작될 수 있다. 이는 환경 규제 위반 은폐 또는 스마트팜 작물 안전성 데이터 왜곡으로 이어진다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟢 Low
* **대응 방안:** 보정 계수 저장소에 대한 접근 제어(RBAC)를 강화하고, 파라미터 변경 이력을 변경 불가능한 감사 로그(Immutable Audit Log, 블록체인 또는 Append-only 스토리지)에 기록한다. 주기적인 무결성 해시 검증을 자동화한다.

### 5. 누적 부동소수점 연산 오차(Floating-Point Accumulation Error) 위험

* **설명:** 9.999 → -0.001 보정 → 8.999 → 0.000 보정 → 5.000 → 0.002 보정 → 5.999의 다단계 연산 과정에서 IEEE 754 부동소수점 표현의 한계로 인해 각 단계마다 미세한 표현 오차(약 10⁻¹⁵~10⁻¹⁶ 수준)가 발생하고, 이것이 3단계에 걸쳐 누적될 경우 환경 측정 기준의 유효 자릿수(소수점 3자리)에서 오차가 관측될 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 각 보정 연산에 고정밀 십진 연산 라이브러리(예: Python `decimal`, Java `BigDecimal`)를 적용하고, 파이프라인 최종 출력 전 반올림 정책(Rounding Policy)을 명시적으로 정의하여 일관된 유효 자릿수를 보장한다.

### 6. x4/x5 분기 불균형으로 인한 하위 파이프라인 부하 편중 위험

* **설명:** 2차 블록 출력 이후 x4(3.999)와 x5(5.000)의 값 차이(약 1.001)가 발생하는데, 만약 두 경로가 서로 다른 처리 자원(CPU/메모리)을 소비하는 연산을 수행할 경우, 스마트팜의 엣지 컴퓨팅 환경(저사양 IoT 게이트웨이)에서 x5 경로의 처리 지연이 집중되어 3차 보정 블록의 입력 준비 시간이 불균등해질 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 엣지 디바이스에서의 실제 처리 부하 프로파일링을 수행하여 x4/x5 경로별 처리 시간을 측정하고, 필요 시 경량 스케줄러(Lightweight Task Scheduler)를 도입하여 우선순위 기반 자원 할당 및 큐 깊이 모니터링 대시보드를 운영한다.
