## 200130

# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 물리적 식물 공장(Plant Factory)의 디지털 트윈(Digital Twin) 구축 및 머신러닝 기반 검증 아키텍처 도입

| 항목                     | 내용                                                                                                                                                                                                                                                                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 식물 공장(Plant Factory)과 같은 복잡한 물리적 시스템은 공간적 구조(GIS/BIM), 거동(시뮬레이션), 실시간 운영 데이터가 유기적으로 결합되어야 정밀한 환경 제어가 가능합니다. 기존 모니터링 시스템은 실시간 데이터 시각화에 그쳐, 시스템의 미래 상태를 예측하거나 최적화하는 데 한계가 있었습니다. 특히 공기 흐름(Air Flow)과 같은 환경 요인의 정밀한 제어가 생육에 직결되므로, 이를 가상 공간에서 모사하고 검증할 수 있는 아키텍처가 필요합니다.                                                                                               |
| **결정(Decision)**       | 물리적 시스템의 **공간 복사(Spatial copy)**, **거동 복사(Behavior copy)**, **데이터 복사(Data copy)**를 통합한 **디지털 트윈(Digital Twin, DT)** 아키텍처를 구축합니다. 구체적으로 GIS/BIM/3D-CAD 데이터와 시뮬레이션 모델을 결합하여 **공기 흐름 모델(Air Flow Model)**을 형식화(Formalism)하고, 실시간 운영 데이터(Operation Data)와 시뮬레이션 데이터(Simulation Data)를 **머신러닝(Machine Learning)** 기법으로 비교·검증(Validation)하는 폐쇄 루프(Closed-loop) 구조를 채택합니다. |
| **근거(Rationale)**      | 이미지에서 볼 수 있듯이, 디지털 트윈은 단순한 3D 모델링을 넘어 시뮬레이션 모델과 실시간 운영 데이터를 포함합니다. 'DT Formalism for Air Flow Model'을 통해 물리적 현상을 수학적으로 모델링하고, 'Machine Learning based DT Validation' 단계에서 실제 운영 데이터와 시뮬레이션 결과를 비교함으로써 모델의 정확도를 지속적으로 보정할 수 있습니다. 이는 정적 모델의 한계를 넘어 동적이고 예측 가능한 트윈을 구현하기 위한 필수적인 결정입니다.                                                                               |
| **결과(Consequences)**   | **긍정적:** 실제 공장 운영 전 시뮬레이션을 통해 공기 흐름 최적화 및 에너지 효율을 예측할 수 있으며, 머신러닝 기반 검증으로 모델의 신뢰도가 시간이 지남에 따라 향상됩니다.<br>**부정적:** GIS, BIM, 실시간 IoT 데이터, 시뮬레이션 엔진 등 이기종 기술의 통합 복잡도가 매우 높으며, 머신러닝 학습 및 시뮬레이션 실행을 위한 막대한 컴퓨팅 리소스가 요구됩니다.                                                                                                                                               |
| **트레이드오프(Trade-offs)** | **장점:** 높은 정밀도의 환경 제어 가능 및 예측 유지보수(Predictive Maintenance) 실현.<br>**단점:** 초기 시스템 구축 비용 및 유지보수 복잡도 증가, 실시간 데이터 처리 지연(Latency) 시 트윈의 정확도 저하 위험.                                                                                                                                                                                                                       |

---

## ⚠️ 잠재적 위험 분석

### 1. 실시간 운영 데이터와 시뮬레이션 모델 간의 동기화 지연 (Data Synchronization Latency)

- **설명:** 'Operation Data'가 물리적 시스템에서 수집되어 'Machine Learning based DT Validation'으로 전달되는 과정에서 네트워크 지연이나 데이터 처리 병목이 발생할 수 있습니다. 이로 인해 시뮬레이션 결과(Simulation Data)와 실제 데이터 간의 비교 검증이 실시간으로 이루어지지 못해, 디지털 트윈의 상태가 실제 물리적 시스템과 불일치(Divergence)할 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 엣지 컴퓨팅(Edge Computing)을 도입하여 현장에서 1차 데이터 필터링 및 전처리를 수행하고, 시뮬레이션 엔진과 데이터 파이프라인 간의 통신 프로토콜을 최적화(예: MQTT, gRPC 사용)하여 지연 시간을 최소화해야 합니다.

### 2. 머신러닝 검증 모델의 과적합 및 일반화 실패 (ML Validation Overfitting)

- **설명:** 'Machine Learning based DT Validation' 단계에서 학습 데이터가 부족하거나 편향되어 있을 경우, ML 모델이 특정 계절이나 특정 운영 조건에만 과적합(Overfitting)될 수 있습니다. 이 경우 예상치 못한 환경 변화(예: 설비 노후화, 외부 기후 급변)가 발생했을 때 검증 로직이 실패하여 잘못된 시뮬레이션 결과를 신뢰하게 만들 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 다양한 운영 시나리오와 예외 상황을 포함한 학습 데이터셋을 구성하고, 정기적인 모델 재학습(Retraining) 파이프라인을 구축해야 합니다. 또한 ML 모델의 예측에 대한 신뢰 구간(Confidence Interval)을 함께 제공하여 불확실성을 관리해야 합니다.

### 3. 이기종 데이터 통합의 복잡성 및 표준화 부재 (Heterogeneous Data Integration Complexity)

- **설명:** 디지털 트윈 구축을 위해 GIS/BIM(공간 데이터), Simulation Model(수학/물리 모델), Operation Data(시계열 센서 데이터) 등 서로 다른 포맷과 주기를 가진 데이터를 통합해야 합니다. 이들 간의 데이터 매핑 오류나 좌표계 불일치는 'DT Data Visualization' 및 'DT Simulation'의 정확도를 심각하게 저하시킬 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 산업 표준(예: IFC for BIM, SensorML for IoT)을 준수하는 데이터 미들웨어를 도입하고, 모든 데이터 소스에 대한 통합 메타데이터 관리 체계(Data Dictionary)를 구축하여 데이터 정합성을 확보해야 합니다.

### 4. 시뮬레이션 모델의 물리적 정확도 부족 (Simulation Model Fidelity Risk)

- **설명:** 'Behavior copy' 역할을 하는 'Simulation Model'이 실제 식물 공장 내의 복잡한 공기 흐름(난류, 열교환 등)을 정확히 반영하지 못할 경우, 'DT Simulation' 결과는 무용지물이 됩니다. 특히 'DT Formalism for Air Flow Model' 단계에서 과도한 단순화(Simplification)가 이루어지면 검증 단계에서 지속적인 오차가 발생할 수 있습니다.
- **심각도:**  Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** CFD(Computational Fluid Dynamics) 등 정밀한 물리 엔진을 활용하여 모델의 초기 정확도를 높이고, 머신러닝 검증 결과를 피드백하여 시뮬레이션 파라미터를 자동으로 보정하는(Self-Correction) 메커니즘을 도입해야 합니다.

### 5. 보안 취약점으로 인한 물리적 시스템 조작 위험 (Security & Physical Manipulation Risk)

- **설명:** 디지털 트윈이 물리적 시스템(Plant Factory)과 양방향으로 연결되어 제어 신호를 전달할 경우, 사이버 공격으로 인해 디지털 트윈이 해킹당하면 실제 공장의 환경 제어 장치(환기팬, 냉난방기 등)가 오작동하여 작물에 치명적인 피해를 줄 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 디지털 트윈 시스템과 물리적 제어 시스템(OT 네트워크) 사이에 방화벽 및 데이터 디오드(Data Diode)를 설치하여 단방향 통신을 원칙으로 하되, 제어 명령 전달 시에는 강력한 인증(Authentication) 및 무결성 검증(Integrity Check)을 수행해야 합니다.
