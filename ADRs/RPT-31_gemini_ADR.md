# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 클라우드 기반 지능형 데이터 서비스 및 머신러닝 피드백 루프 아키텍처 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 분산된 다수의 스마트팜(User 1~n)으로부터 수집되는 대규모 농업 데이터를 실시간으로 모니터링하고, 이를 기반으로 지능형 영농 의사결정을 지원하기 위한 고도화된 분석 모델의 지속적인 갱신 및 연동 체계가 필요함. |
| **결정(Decision)** | Monitoring Function을 통해 사용자 데이터를 통합하고, Learning Screening(학습 선별)과 Learning Information Connection(학습 정보 연동) 기능을 분리하여 Cloud의 Smart Farming Management Function(LMS, FMCF)과 유기적으로 결합하는 '비동기적 지능형 피드백 루프' 구조를 채택함. |
| **근거(Rationale)** | 실시간 모니터링 데이터 중 유의미한 데이터만을 선별(Screening)하여 학습에 활용함으로써 클라우드 저장 및 연산 비용을 최적화하고, 검증된 학습 정보를 다시 현장에 전달하는 체계를 통해 모델의 정확도를 지속적으로 향상시킬 수 있음. |
| **결과(Consequences)** | (긍정적) 데이터 수집-학습-적용의 전 과정이 자동화되어 개별 농가에 최적화된 영농 지침 제공 가능. (부정적) 클라우드와 로컬 관리 기능 간의 통신 의존도가 높아지며 전체 시스템 복잡도가 증가함. |
| **트레이드오프(Trade-offs)** | 고성능 지능형 서비스를 위해 아키텍처의 복잡성과 초기 구축 비용을 감수하는 대신, 운영 효율성과 장기적인 예측 모델의 신뢰성을 확보함. |

---

## ⚠️ 잠재적 위험 분석

### 1. 데이터 병목 현상 및 동기화 지연
- **설명:** 수많은 사용자(User n)로부터 동시에 데이터가 유입될 때 Monitoring Function에서 Cloud로 전달되는 과정에서 지연이 발생하여 실시간 제어 타이밍을 놓치는 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 메시지 큐(Kafka/RabbitMQ)를 도입하여 트래픽 부하를 분산하고, 엣지 컴퓨팅을 강화하여 긴급한 로컬 제어는 현장에서 즉시 처리하도록 설계.

### 2. 학습 데이터 편향 및 모델 품질 저하
- **설명:** Learning Screening Function에서 특정 조건의 데이터만 과도하게 선별되어 Cloud의 학습 모델(LMS)이 왜곡되거나 실제 농사 현장과 괴리된 결과를 도출하는 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 데이터 샘플링 알고리즘에 다양성 지표를 포함하고, 모델 업데이트 전 스테이징 환경에서 성능을 검증하는 A/B 테스트 프로세스 구축.

### 3. 클라우드 서비스 가용성 위기
- **설명:** 외부 클라우드 인프라 장애 시 Smart Farming Management Function이 중단되어 현장의 Farming Information 연동이 차단되고 지능형 서비스가 마비되는 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 멀티 리전(Multi-region) 배포 전략을 수립하고, 클라우드 연결 단절 시에도 기본 기능을 유지할 수 있는 로컬 '서바이벌 모드' 로직 구현.

### 4. 데이터 보안 및 사용자 프라이버시 침해
- **설명:** 다수 사용자의 농업 데이터가 클라우드로 집중되는 과정에서 민감한 영농 노하우나 개인 정보가 외부로 유출되거나 타 사용자에게 노출되는 보안 사고 시나리오.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 전송 구간 TLS 암호화 적용, 테넌트(Tenant)별 데이터 격리 저장소 구축 및 엄격한 IAM(Identity and Access Management) 정책 시행.

### 5. 컴포넌트 간 인터페이스 호환성 문제
- **설명:** 시스템 업데이트 시 Learning Information Connection Function과 Cloud 내부의 FMCF 간 인터페이스 규격이 불일치하여 데이터 연동이 실패하는 시나리오.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** API 버저닝 전략을 수립하고, 마이크로서비스 간의 계약 테스트(Contract Testing)를 자동화하여 배포 전 호환성을 상시 확인.
