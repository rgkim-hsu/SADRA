📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 처방 지도(Prescription Map) 기반 VRI(Variable Rate Irrigation) 제어 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                                                                       |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 노지 스마트팜 환경에서 기상 스테이션(Weather Station), 캐노피 온도 센서(Canopy Temp. Sensors), 토양 수분 센서(Soil Water Sensors) 등 이기종 다중 센서로부터 실시간 데이터가 수집된다. 필지 내 공간적 편차(토양 수분 분포, 작물 생육 상태)가 존재함에도 단일 관개량을 적용할 경우 용수 낭비 및 작물 스트레스가 발생하는 구조적 한계가 있다. 이를 해결하기 위해 공간 가변 제어가 가능한 센터 피벗(VRI-Center Pivot) 시스템과 연동되는 지능형 제어 아키텍처가 필요하다. |
| **결정(Decision)**       | ARSP(Adaptive Real-time Sensing Platform) 서버-클라이언트 이중 구조를 채택하고, 다중 센서 데이터를 ARSP Server에서 집계·분석하여 처방 지도(Prescription Map)를 동적으로 생성한다. ARSP Client는 처방 지도를 기반으로 VRI-Center Pivot에 구역별 차등 관개 명령을 전달하며, 사용자(User)는 ARSP Server를 통해 전체 시스템을 모니터링·수동 개입할 수 있는 양방향 인터페이스를 제공한다.                                 |
| **근거(Rationale)**      | 센서 데이터의 공간적 해상도를 처방 지도로 추상화함으로써 VRI 제어 명령의 복잡도를 줄이고 재사용성을 높인다. 서버-클라이언트 분리는 연산 집약적 맵 생성 로직을 서버에 집중시켜 엣지 디바이스(Client)의 부하를 최소화한다. 또한 사용자 인터페이스를 서버 레이어에서 제공함으로써 원격 모니터링 및 의사결정 개입이 가능해진다.                                                                                                                 |
| **결과(Consequences)**   | ✅ 필지 내 공간 가변 관개 실현으로 용수 효율 향상 및 균일한 작물 생육 도모. ✅ 처방 지도 이력 저장을 통한 시계열 분석 및 농업 의사결정 지원 가능. ❌ ARSP Server가 단일 장애점(SPOF)으로 기능하여 서버 장애 시 전체 제어 체계 마비 위험 존재. ❌ 실시간 처방 지도 생성을 위한 서버 측 고성능 연산 자원 요구.                                                                                                              |
| **트레이드오프(Trade-offs)** | **얻는 것:** 공간 해상도 기반의 정밀 관개, 중앙 집중식 모니터링, 사용자 개입 유연성. **감수해야 할 것:** 서버 의존성 증가로 인한 가용성 리스크, 센서-서버-클라이언트 간 네트워크 지연(Latency)이 제어 실시간성에 영향, 다중 센서 데이터 동기화 복잡도 상승.                                                                                                                                             |

### ADR-002: 이기종 센서 네트워크의 단방향 데이터 수집 및 폐루프(Closed-loop) 피드백 제어 구조 채택

| 항목                     | 내용                                                                                                                                                                                                                               |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 기상 스테이션, 캐노피 온도 센서, 토양 수분 센서는 각기 다른 측정 원리와 통신 프로토콜을 가진 이기종 장치다. 센서 데이터가 ARSP Client로 집계된 후 작물/토양(Crop/Soil)에 관개가 이루어지고, 그 결과가 다시 토양 수분 센서로 피드백되는 폐루프 구조가 개념도 상에서 확인된다. 이 피드백 루프를 명시적으로 아키텍처에 반영하지 않으면 제어 안정성과 과·부족 관개 방지가 불가능하다. |
| **결정(Decision)**       | 토양 수분 센서를 Crop/Soil 출력단과 Sensing Systems 입력단 사이의 피드백 경로로 명시적으로 정의하고, ARSP Client가 관개 후 센서 재측정값을 수신하여 처방 지도를 갱신하는 폐루프 제어 사이클을 구성한다. 센서별 수집 주기와 데이터 포맷을 표준화하는 데이터 수집 계층(Data Acquisition Layer)을 ARSP Client 하위에 배치한다.             |
| **근거(Rationale)**      | 폐루프 피드백은 관개 과잉/부족을 자동 보정하여 시스템 자율성을 높인다. 데이터 수집 계층의 분리는 향후 신규 센서 추가 시 상위 제어 로직 변경 없이 드라이버만 추가하면 되는 확장성을 보장한다.                                                                                                                    |
| **결과(Consequences)**   | ✅ 자동 보정을 통한 관개 정확도 향상. ✅ 센서 추가/교체 시 아키텍처 변경 최소화. ❌ 피드백 루프의 제어 주기(Control Cycle) 설계 오류 시 헌팅(Hunting) 현상 발생 가능. ❌ 센서 고장이 잘못된 피드백으로 이어져 오작동 관개를 유발할 수 있음.                                                                           |
| **트레이드오프(Trade-offs)** | **얻는 것:** 자율 보정 능력, 센서 확장성. **감수해야 할 것:** 제어 루프 튜닝 복잡도 증가, 센서 신뢰성에 대한 시스템 의존도 상승.                                                                                                                                                |

⚠️ 잠재적 위험 분석
------------

### 1. ARSP Server 단일 장애점(SPOF) 장애

* **설명:** ARSP Server가 하드웨어 오류, 소프트웨어 크래시, 또는 네트워크 단절로 인해 다운될 경우, 처방 지도 생성이 중단되고 ARSP Client가 VRI-Center Pivot에 유효한 제어 명령을 전달하지 못한다. 이 상황에서 피벗이 기본값(고정 관개)으로 동작하거나 완전히 멈추면 대규모 작물 피해로 이어질 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** Active-Standby 이중화 서버 구성(HA Clustering) 도입. ARSP Client에 최후 처방 지도를 로컬 캐싱하여 서버 장애 시에도 최소 시간 동안 자율 운영 가능하도록 Fallback 로직 구현. 서버 헬스체크 및 자동 재시작 스크립트(watchdog) 적용.

### 2. 무선 센서 네트워크(WSN) 통신 두절 및 데이터 손실

* **설명:** 노지 환경 특성상 기상 악화(낙뢰, 강풍), 장거리 무선 통신 간섭, 또는 센서 배터리 방전으로 인해 캐노피 온도 센서 또는 토양 수분 센서의 데이터 전송이 간헐적으로 두절될 수 있다. 불완전한 센서 데이터로 처방 지도가 생성될 경우, 특정 구역에 과잉 또는 과소 관개가 발생한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 센서 데이터 수신 누락 감지 로직 및 결측값 보간 알고리즘(공간 크리깅, 시계열 보간) 적용. 중요 센서에 이중 통신 경로(LoRa + LTE) 구성. 센서 배터리 잔량 모니터링 및 저전력 경보 알림 시스템 구축.

### 3. 사이버 보안 취약점 및 무단 제어 명령 주입

* **설명:** ARSP Server와 ARSP Client 간 통신, 또는 사용자-서버 간 인터페이스에 암호화 및 인증이 부재할 경우, 공격자가 네트워크에 침입하여 위조된 처방 지도 또는 관개 명령을 VRI-Center Pivot에 주입할 수 있다. 이는 작물 고사, 용수 자원 낭비, 또는 피벗 장비 손상으로 이어질 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 모든 통신 구간에 TLS 1.3 암호화 적용. ARSP Client의 VRI 제어 명령 수신 시 디지털 서명 검증 필수화. 사용자 인터페이스에 역할 기반 접근 제어(RBAC) 및 다중 인증(MFA) 도입. 정기적인 침투 테스트 및 OT/IT 네트워크 분리(DMZ 구성).

### 4. 처방 지도 연산 지연으로 인한 실시간 제어 실패

* **설명:** 다수의 센서로부터 수집된 고해상도 공간 데이터를 처방 지도로 연산하는 과정에서 ARSP Server의 처리 지연이 발생할 경우, VRI-Center Pivot이 이미 해당 구역을 통과한 후에 관개 명령이 도달하여 제어 타이밍을 놓치게 된다. 센터 피벗의 이동 속도와 처방 지도 갱신 주기가 동기화되지 않으면 정밀 관개의 의미가 상실된다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 처방 지도 사전 연산(Pre-computation) 및 피벗 이동 스케줄과의 시간 동기화 설계. 실시간 스트리밍 처리 엔진(Apache Kafka, Flink 등) 도입으로 지연 최소화. 피벗 위치 센서(GPS)와 처방 지도 구역 인덱스를 연동하여 위치 기반 명령 트리거 방식으로 전환.

### 5. 토양 수분 센서 고장으로 인한 폐루프 피드백 오동작

* **설명:** 피드백 루프의 핵심 입력값인 토양 수분 센서가 물리적 손상(경운 작업 중 파손), 교정 오류, 또는 센서 드리프트로 인해 비정상적인 측정값을 지속 출력할 경우, ARSP 시스템은 이를 정상 데이터로 인식하여 잘못된 처방 지도를 반복 생성한다. 특히 건조 상태로 오인한 경우 과잉 관개가 지속되어 작물 침수 피해 및 용수 낭비가 장기화될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 동일 구역 내 다중 센서 교차 검증(Voting Logic) 도입. 측정값의 통계적 이상치 감지 알고리즘(3-sigma, IQR 기반) 적용 및 이상 감지 시 해당 센서 자동 격리. 정기적인 현장 교정(In-situ Calibration) 스케줄 운영 및 센서 교체 이력 관리 시스템 구축.

### 6. 사용자-ARSP Server 간 의사결정 충돌 및 휴먼 에러

* **설명:** 사용자가 ARSP Server 인터페이스를 통해 자동 생성된 처방 지도를 수동으로 과도하게 수정하거나, 시스템 경보 상황에서 잘못된 파라미터를 입력할 경우, 자동 제어 시스템의 최적 판단을 무력화하는 휴먼 에러가 발생할 수 있다. 특히 야간 또는 비상 상황에서의 긴급 수동 개입 시 위험이 높다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 수동 명령 입력 시 시스템 권고값과의 편차 경고 팝업 및 2단계 확인(Double Confirmation) UI 설계. 모든 수동 개입 이력에 대한 감사 로그(Audit Log) 자동 기록. 수동 제어 모드와 자동 제어 모드 간 명확한 전환 절차 및 자동 복귀 타임아웃 메커니즘 구현.
