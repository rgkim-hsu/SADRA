📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 스마트팜 작물 거래 플랫폼의 블록체인 기반 신뢰 레이어 도입

| 항목                     | 내용                                                                                                                                                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 서버(30)는 작물 품질, 재배 비용(예: 12,345원), 작물 이미지 등의 민감한 작물 데이터(91)를 중앙 집중식으로 관리한다. 재배자와 구매자 간의 직거래(93) 환경에서 중간자 없이 데이터의 진위성과 거래 무결성을 보장해야 하는 구조적 문제가 존재한다. 특히 작물 품질 정보의 위변조 가능성과 거래 분쟁 발생 시 신뢰할 수 있는 기록의 부재가 핵심 과제다. |
| **결정(Decision)**       | 스마트팜 서버와 재배자·구매자 간의 모든 트랜잭션(작물 데이터 91, 구매 조건 92, 거래 내역 93)을 퍼블릭/컨소시엄 블록체인 네트워크(300)에 기록하는 분산 원장 아키텍처를 채택한다. 스마트팜 서버는 오프체인 데이터 원천으로 유지하고, 해시 또는 메타데이터만 온체인에 기록하는 하이브리드 구조를 적용한다.                                   |
| **근거(Rationale)**      | 블록체인의 불변성(Immutability)은 작물 데이터 및 거래 내역의 사후 위변조를 방지한다. 스마트 컨트랙트를 통한 구매 조건(92) 자동 실행은 중개자 없는 신뢰 실행 환경을 제공한다. 다수의 노드가 참여하는 분산 네트워크 구조는 단일 장애점(SPOF)을 제거하며, 농산물 이력 추적(Traceability) 요구사항을 충족하는 표준적 접근법이다.            |
| **결과(Consequences)**   | (긍정) 재배자-구매자 간 직거래 신뢰도 향상, 작물 데이터 무결성 보장, 분쟁 발생 시 불변 증거 확보, 중개 수수료 절감. (부정) 블록체인 네트워크 운영에 따른 인프라 복잡성 증가, 스마트팜 서버와 블록체인 간 동기화 레이턴시 발생, 온체인 데이터 기록 비용(Gas Fee) 발생 가능.                                               |
| **트레이드오프(Trade-offs)** | 【획득】데이터 투명성, 거래 신뢰성, 탈중앙화된 감사 추적 / 【감수】시스템 복잡도 증가, 블록 확정 시간에 따른 실시간성 저하, 컨소시엄 노드 관리 운영 부담, 스마트 컨트랙트 버그 발생 시 수정 불가                                                                                                 |

### ADR-002: 스마트팜 서버의 오프체인 중앙 데이터 허브 역할 유지

| 항목                     | 내용                                                                                                                                                      |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 작물 이미지, 센서 데이터 등 대용량 바이너리 데이터를 블록체인에 직접 기록하는 것은 비용 및 성능 측면에서 비현실적이다. 스마트팜 서버(30)는 고해상도 작물 이미지와 실시간 재배 환경 데이터를 지속적으로 생성하며, 이를 효율적으로 저장·관리할 별도 레이어가 필요하다. |
| **결정(Decision)**       | 스마트팜 서버(30)를 오프체인 데이터 레이크로 운영하고, 블록체인 네트워크(300)에는 데이터의 해시값, 타임스탬프, 메타데이터(품질 등급, 가격 등)만 기록하는 이중 레이어 아키텍처를 채택한다. 작물 이미지는 IPFS 또는 분산 스토리지 연계를 권고한다.        |
| **근거(Rationale)**      | 온체인 저장 비용 최소화와 블록체인 네트워크 부하 감소. 작물 데이터의 검증은 해시 비교만으로 충분하여 전체 데이터의 온체인 기록이 불필요하다. 스마트팜 서버의 기존 인프라를 재활용하여 전환 비용을 절감한다.                                    |
| **결과(Consequences)**   | (긍정) 시스템 처리 성능 최적화, 저장 비용 절감, 기존 서버 인프라 활용 가능. (부정) 오프체인 데이터의 가용성이 중앙 서버에 의존하여 탈중앙화 수준이 제한됨. 스마트팜 서버 장애 시 원본 데이터 접근 불가 위험 존재.                           |
| **트레이드오프(Trade-offs)** | 【획득】비용 효율성, 처리 성능, 운영 단순성 / 【감수】완전한 탈중앙화 미달성, 서버 가용성에 대한 신뢰 의존, 데이터 원본 접근을 위한 중앙 서버 단일 경로                                                               |

⚠️ 잠재적 위험 분석
------------

### 1. 스마트팜 서버(30) 단일 장애점(SPOF) 위험

* **설명:** 스마트팜 서버가 다운될 경우, 블록체인에 기록된 해시값은 유효하더라도 실제 작물 데이터(이미지, 재배 이력 등)에 접근이 불가능해진다. 재배자가 작물 데이터(91)를 블록체인에 업로드하는 유일한 진입점이 서버에 집중되어 있어, 서버 장애 시 전체 거래 프로세스가 중단된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** Active-Active 이중화 서버 구성 및 자동 페일오버(Failover) 적용. 작물 이미지 및 원본 데이터를 IPFS 또는 분산 오브젝트 스토리지(예: AWS S3 다중 리전)에 백업. RTO/RPO 목표를 명확히 정의하고 재해복구(DR) 계획 수립.

* * *

### 2. 스마트 컨트랙트 취약점 및 로직 버그

* **설명:** 구매 조건(92)을 실행하는 스마트 컨트랙트에 코드 취약점이 존재할 경우, 블록체인의 불변성으로 인해 배포 후 수정이 불가능하다. 재진입 공격(Reentrancy Attack), 정수 오버플로우 등의 보안 취약점이 악용되면 거래 자금 탈취 또는 잘못된 조건 실행이 발생할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 배포 전 전문 보안 감사(Audit) 필수 수행. 업그레이드 가능한 프록시 패턴(Proxy Pattern) 적용으로 로직 수정 경로 확보. 스테이징 환경에서의 충분한 테스트넷 검증. 긴급 일시정지(Circuit Breaker) 기능을 컨트랙트에 내장.

* * *

### 3. 작물 데이터 입력 신뢰성 문제 (Oracle Problem)

* **설명:** 스마트팜 서버가 블록체인에 기록하는 작물 품질(상/중/하), 재배 비용(12,345원) 등의 데이터는 현실 세계의 정보를 디지털로 변환한 값이다. 재배자가 이 데이터를 조작하거나 스마트팜 서버의 센서가 오작동할 경우, 블록체인은 잘못된 데이터를 불변으로 기록하게 된다. "쓰레기가 들어오면 쓰레기가 나온다(GIGO)" 문제로, 블록체인의 신뢰성이 오프체인 데이터 품질에 완전히 종속된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** IoT 센서 데이터와 AI 기반 작물 이미지 분석을 통한 자동 품질 검증 파이프라인 구축. 제3자 검증 기관(공인 농업 기관) 또는 분산 오라클 네트워크(Chainlink 등) 연계. 데이터 입력 시 디지털 서명(전자 인증)을 통한 재배자 책임 귀속 강화.

* * *

### 4. 블록체인 네트워크 확장성 및 성능 병목

* **설명:** 다수의 재배자와 구매자가 동시에 거래를 시도할 경우, 블록체인 네트워크(300)의 TPS(초당 처리 건수) 한계로 인해 거래 처리 지연이 발생할 수 있다. 특히 농산물 수확 시즌에 거래가 집중될 경우 네트워크 혼잡으로 인한 가스비 급등 및 확정 시간 지연이 거래 경험을 심각하게 저해할 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 퍼블릭 블록체인 대신 허가형(Permissioned) 컨소시엄 블록체인(Hyperledger Fabric, Besu 등) 채택으로 TPS 확보. Layer 2 솔루션(롤업, 상태 채널) 적용 검토. 거래 내역(93)의 배치 처리(Batch Processing)를 통한 온체인 트랜잭션 수 최소화.

* * *

### 5. 개인정보 및 거래 기밀 노출 위험

* **설명:** 블록체인의 투명성은 장점이지만, 재배자의 재배 비용(12,345원), 거래 내역(93), 구매 조건(92) 등 민감한 상업적 정보가 네트워크 참여자 전원에게 공개될 수 있다. 특히 퍼블릭 블록체인 채택 시 경쟁 재배자에게 원가 구조가 노출되거나, 구매자의 구매 패턴이 분석되어 개인정보 침해 및 영업 기밀 유출로 이어질 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 영지식 증명(Zero-Knowledge Proof, ZKP) 기술을 활용한 거래 검증(데이터 노출 없이 유효성만 증명). 채널(Channel) 또는 프라이빗 트랜잭션 기능을 지원하는 컨소시엄 블록체인 채택. 온체인에는 해시값만 기록하고 민감 데이터는 암호화된 오프체인 저장소에 보관하는 아키텍처 강화.

* * *

### 6. 재배자·구매자의 키 관리 실패 위험

* **설명:** 블록체인 거래의 주체인 재배자와 구매자는 각자의 개인키(Private Key)로 트랜잭션에 서명해야 한다. 농업 종사자 특성상 IT 친숙도가 낮을 수 있으며, 개인키 분실 시 계정 접근이 영구적으로 불가능해지고, 키 유출 시 자산 및 거래 권한 전체가 탈취된다. 스마트팜 플랫폼의 실제 현장 확산에 있어 가장 현실적인 장벽이다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 하드웨어 보안 모듈(HSM) 또는 MPC(다자 연산) 기반 키 관리 서비스 도입. 소셜 로그인 연계 또는 계정 추상화(Account Abstraction, ERC-4337) 기술 적용으로 UX 개선. 다중 서명(Multisig) 지갑을 통한 단일 키 의존도 분산. 재배자·구매자 대상 정기적인 보안 교육 프로그램 운영.
