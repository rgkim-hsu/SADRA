## 📋 ADR (Architecture Decision Record)

### ADR-001: [다양한 소스 데이터의 융합 및 동기화 전략 수립]

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템(팜커넥트)은 1단 계 '센서수집'과 2단 계 '외부기상정보'라는 이질적인 데이터 소스를 처리해야 한다. 센서 데이터는 실시간 IoT 데이터인 반면, 외부 기상 정보는 주기적 API 데이터다. 또한 3단 계 '내부환경정보예측' 단계에서 이 두 가지 데이터를 결합해 정확한 예측을 제공해야 하는 아키텍처적 과제가 있다. |
| **결정(Decision)** | 시스템 내부는 센서 데이터를 에지/로컬에서 정규화하고, 외부 기상 정보 API 데이터를 매칭하여 중앙 데이터 레이크에 통합하는 표준화 레이어(ETL)를 구축한다. <br> **핵심:** 데이터 소스별 타이밍 차이(실시간 센서 vs 주기적 기상 정보)를 해결하기 위해 시간 동기화 및 데이터 변환 로직을 표준화한다. |
| **근거(Rationale)** | TTA 및 ISO/IEC 30141 등 국제 표준에서 강조하는 '상호운용성'과 '재사용 가능한 설계' 원칙을 따름. <br> 다양한 소스의 데이터를 통합하지 않으면 3단 계의 '기상정보예측'과 '내부환경정보예측'이 정확하지 않아 4단 계의 '병충해 심박 이상 예측' 및 '실시간 배육 시스템'의 신뢰성이 떨어진다. |
| **결과(Consequences)** | **긍정:** 시스템은 더 많은 데이터 소스를 추가함에 따라 확장성이 향상되고, 예측 모델의 정확도가 높아진다. <br> **부정:** 초기 데이터 파이프라인 구축 비용과 유지보수 복잡도가 증가할 수 있다. |
| **트레이드오프(Trade-offs)** | **장점:** 데이터 기반 의사결정의 정확성 향상. <br> **단점:** 데이터 처리 비용 증가와 초기 구현 시간 소모. |

### ADR-002: [예측 및 분석을 위한 AI/ML 모델 계층화 및 에지 컴퓨팅 적용]

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 3단 계 '내부알고리즘분석', 4단 계 '실시간배육시스템', 5단 계 'AI 예측시뮬레이션' 등 복잡한 분석 과정이 존재한다. 특히 4단 계의 '병충해 심박 이상 예측'이나 5단 계의 '온라인 컨설팅'은 실시간성이나 정밀성이 요구된다. 또한 2단계 분석 근거에 따르면 국내 TTA 표준화 작업(스마트 축사 환경 모니터링 등)이 진행 중이므로 표준 모델 적용도 고려해야 한다. |
| **결정(Decision)** | 분석 로직을 계층화한다. <br> 1. **에지/로컬 수준:** '실시간배육시스템', '작물 성태 및 중 분석'처럼 빠른 응답이 필요한 로직은 로컬 디바이스나 서버에서 가볍게 실행한다. <br> 2. **클라우드/중앙 수준:** '전세계물량가격 예측시스템', 'AI 예측시뮬레이션'처럼 대규모 학습 데이터가 필요한 모델은 중앙 서버에 배치한다. |
| **근거(Rationale)** | IoT 환경에서 '상호운용성'과 '보안'을 강조하는 IEEE 2413 등 국제 표준을 따르는 것이 필요하다. 농가 현장에서의 네트워크 불안정성을 고려하여, 핵심 분석 로직의 분산 처리가 필수적이다. <br> TTA 개발 중인 '스마트 축사 환경 데이터 모니터링 시스템' 표준과 연계하여 로직의 재사용성을 확보한다. |
| **결과(Consequences)** | **긍정:** 네트워크 지연 상황에서도 기본 기능(실시간 배육 등)은 정상 작동하며, 고부가가치 분석(가격 예측 등)은 클라우드에서 처리될 수 있어 안정성을 확보한다. <br> **부정:** 모델 배포와 버전 관리를 위한 복잡도가 상승한다. |
| **트레이드오프(Trade-offs)** | **장점:** 시스템 가용성(Availability) 및 응답 속도 개선. <br> **단점:** 모델 관리 및 버전 컨트롤에 필요한 추가 인력 및 도구 투자 필요. |

### ADR-003: [다단계 예측 체인을 통한 데이터 가치 연쇄 구축]

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 1~2단 계의 원시 데이터를 거쳐 3, 4단 계에서 구체적인 '정보예측', '실시간 시스템', '알고리즘 분석'으로 가공되고, 최종 5단 계에서 '시뮬레이션', '컨설팅', '가격 예측'으로 전환된다. 이는 단순한 데이터 수집이 아닌, 비즈니스 가치를 창출하는 가치 사슬(Value Chain)이다. |
| **결정(Decision)** | 시스템 아키텍처를 '파이프라인(Pipeline)' 기반으로 설계한다. <br> 입력 데이터(센서, 기상) -> 가공 로직 (예측, 분석) -> 출력 애플리케이션 (컨설팅, 시뮬레이션) 구조를 명확히 정의한다. 각 단계 간 인터페이스(API)는 표준화되며, 특히 5단 계의 '온라인 컨설팅시스템'과 '전세계물량가격 예측시스템'은 별도의 미들웨어 층을 통해 연동되도록 설계한다. |
| **근거(Rationale)** | '스마트 온실 서비스를 위한 데이터 관리 요구 사항' 등의 TTA 표준 과제를 참고할 때, 데이터의 흐름(Flow)을 관리하는 것이 핵심이다. <br> 사용자에게 'AI 예측시뮬레이션'처럼 복잡한 결과를 보여주기 전에, 중간 단계인 '내부 환경 정보 예측'과 '실시간 배육 시스템'이 충분히 검증된 데이터 기반을 제공해야 신뢰할 수 있다. |
| **결과(Consequences)** | **긍정:** 시스템은 단순한 모니터링 도구를 넘어, 농가를 위한 종합 솔루션(컨설팅, 가격 예측)으로 진화할 수 있다. <br> **부정:** 각 단계의 로직 수정이 연쇄적으로 영향을 미쳐 유지보수 비용이 발생할 수 있다. |
| **트레이드오프(Trade-offs)** | **장점:** 전사적인 데이터 가시화 및 비즈니스 인사이트 제공. <br> **단점:** 단일 데이터 소스의 오류가 전체 시스템 연쇄 오류로 이어질 가능성. |

## ⚠️ 잠재적 위험 분석

### 1. [데이터 정확성 및 예측 신뢰성 저하]
- **설명:** 3단 계의 '기상정보예측', '내부환경정보예측'과 4단 계의 '실시간배육시스템', '작물 성태 및 중 분석'이 기대치에 못 미칠 경우, 최종 5단 계의 '온라인 컨설팅'이나 '병충해 심박 이상 예측'이 잘못된 방향으로 유도할 수 있음. 특히 농업 환경은 변수가 많아 센서 오차가 커질 경우 예측 모델의 신뢰도가 급격히 떨어질 수 있음.
- **심각도:** 🔴 High / **발생 가능성:** 🟡 Medium
- **대응 방안:** 
    - **다중 센서 퓨전:** 단일 센서 의존도를 낮추고 여러 센서 값을 평균하거나 가중치 부여하여 정확도 향상.
    - **인수적 검증 (Human-in-the-loop):** 5단 계 '온라인 컨설팅시스템' 출력 결과에 대한 농가의 피드백 루프를 추가하여 모델 지속적으로 학습 및 개선.

### 2. [네트워크 불안정성 및 데이터 손실]
- **설명:** 농업 현장(특히 1단 계 '센서수집' 단계)은 통신 인프라가 약한 경우가 많음. 4단 계의 '실시간배육시스템'과 같은 실시간 데이터 분석이 지연되거나, 3단 계 '내부환경정보예측' 데이터가 클라우드로 전송되지 못하면 시스템 고장이 발생할 수 있음.
- **심각도:** 🟡 Medium / **발생 가능성:** 🔴 High
- **대응 방안:** 
    - **에지 컴퓨팅 도입:** 핵심 로직 (예: 4단 계의 일부 분석) 을 로컬 서버에서 처리하도록 배치.
    - **오프라인 모드 지원:** 네트워크 차단 시에도 센서 데이터를 로컬에 저장하고, 네트워크 연결이 복원된 후 동기화하도록 로직 설계.

### 3. [시스템 통합 및 상호운용성 문제]
- **설명:** 2단 계의 '외부기상정보'는 외부 API를 사용하고, 1단 계 '센서'는 다양한 제조사 제품을 사용할 경우, 호환성 문제가 발생할 수 있음. TTA 표준화 가이드북 내용과도 연관이 있어, 내부 표준과 외부 표준 간의 충돌 가능성이 있음.
- **심각도:** 🟡 Medium / **발생 가능성:** 🟡 Medium
- **대응 방안:** 
    - **표준 프로토콜 준수:** IoT 관련 국제 표준 (ISO/IEC 30141, MQTT, CoAP 등) 이나 국내 TTA 표준을 우선적으로 적용.
    - **모듈화 설계:** 외부 기상 정보 등 변동성이 큰 구성 요소를 독립된 모듈로 분리하여 관리.

### 4. [보안 및 사생활 침해 위험]
- **설명:** 3단 계 '내부환경정보예측' 단계에는 내부 환경에 대한 모니터링이 포함될 수 있고, 4단 계 '실시간배육시스템'은 민감한 농장 데이터나 동물의 이미지를 처리할 수 있음. '스마트 축사' 등의 표준화 가이드북에서 강조하는 보안 요건 (ITU-T X.1352 등) 을 위반할 경우, 법적 문제나 농가 신뢰도 하락이 있을 수 있음.
- **심각도:** 🔴 High / **발생 가능성:** 🟡 Medium
- **대응 방안:** 
    - **데이터 암호화:** 전송 및 저장 시 end-to-end 암호화 적용 (AES-256 등).
    - **접근 제어 (RBAC):** 농장 관리자, 기술 지원자 등 역할별 데이터 접근 권한을 명확히 분리.

### 5. [사용자 수용성 및 UI/UX 부재]
- **설명:** 5단 계 'AI 예측시뮬레이션', '온라인 컨설팅시스템', '전세계물량가격 예측시스템'은 복잡하고 직관적인 정보로 제공되어야 함. 농촌 현장의 연령대 사용자나 기술 숙련도가 낮은 경우, 복잡한 '시스템' 화면을 이해하지 못하고 시스템을 폐기할 수 있음.
- **심각도:** 🟡 Medium / **발생 가능성:** 🟡 Medium
- **대응 방안:** 
    - **간소화된 인터페이스:** 복잡한 데이터 시각화 대신 농가에게 필요한 핵심 정보 (예: '수확 시기', '병충해 경고') 만 강조.
    - **교육 및 지원:** 시스템 도입 시 농가 사용자를 위한 교육 프로그램 운영 및 원격 지원 체계 마련.
