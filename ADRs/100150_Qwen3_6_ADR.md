# 🏗️ 아키텍처 분석 보고서

## ADR (Architecture Decision Record)

### ADR-001: 다중 소스 데이터 융합 기반 재배 방법 추천 파이프라인 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                      |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 운영 환경에서 작물의 최적 생육을 위해 토양 및 기상 정보(S1001)와 같은 환경 데이터뿐만 아니라, 작업 시간 및 기존 재배 방법(S1002)과 같은 운영 데이터를 통합적으로 분석해야 함. 단편적인 정보만을 기반으로 할 경우 실제 현장 조건(예: 인력 부족, 일정 충돌)과 맞지 않는 비현실적인 추천이 발생할 수 있는 아키텍처적 과제가 존재함. |
| **결정(Decision)**       | 환경 데이터(S1001)와 운영 데이터(S1002)를 순차적으로 수집하여 단일 추천 엔진(S1003)으로 입력하고, 그 결과를 최종 사용자에게 전송(S1004)하는 **직렬 데이터 처리 파이프라인(Sequential Data Processing Pipeline)** 아키텍처를 채택함.                                         |
| **근거(Rationale)**      | 재배 방법 결정은 단순히 '날씨가 좋으니 물을 준다'는 것을 넘어, '누가 언제 작업할 수 있는지(S1002)'와 '현재 토양 상태(S1001)'를 종합적으로 고려해야 함. 직렬 파이프라인은 데이터 수집부터 추천 생성까지의 흐름을 명확하게 제어할 수 있으며, 각 단계(S1001~S1003)의 입력값 검증이 용이하여 시스템의 논리적 안정성을 높일 수 있음. |
| **결과(Consequences)**   | 데이터 기반의 과학적이고 현실적인 재배 방법을 추천할 수 있어 농작업의 효율성과 작물 품질이 향상됨. 반면, 특정 단계(예: 기상 정보 수집 실패)에서 오류가 발생할 경우 후속 단계 전체가 중단되거나 부정확한 결과를 을 수 있는 연쇄 실패 위험이 있음.                                                           |
| **트레이드오프(Trade-offs)** | 논리적 흐름의 명확성 및 종합적 의사결정 지원 vs. 단계 간 결합도(Coupling)로 인한 부분 장애 시 전체 프로세스 영향 및 데이터 수집 지연에 따른 추천 시점 늦어짐.                                                                                                      |

---

## ⚠️ 잠재적 위험 분석

### 1. 토양/기상 데이터(S1001) 수집 지연으로 인한 추천 시점错失

- **설명:** 기상 정보나 토양 센서 데이터는 실시간성이 중요함. 데이터 수집 단계(S1001)에서 네트워크 지연이나 센서 오류가 발생할 경우, 급변하는 기상 조건에 대한 대응 추천(S1003)이 제때 이루어지지 못하여 작물에 피해가 발생할 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 엣지 컴퓨팅 도입을 통한 로컬 데이터 캐싱, 데이터 수집 실패 시 최근 유효 데이터 기반의 '안전 모드' 추천 로직 적용, 통신 상태 모니터링 및 자동 재시도(Retry) 메커니즘 구현.
  
  ### 2. 추천 알고리즘(S1003)의 과적합 및 현장 적용성 부족
- **설명:** 추천 재배 방법 결정 단계(S1003)에서 학습된 모델이 특정 환경이나 작물에 과적합(Overfitting)될 경우, 새로운 품종이나 이상 기후 상황에서는 잘못된 추천을 할 수 있음. 또한, 이론적으로 최적이어도 현장의 작업 시간(S1002)과 맞지 않으면 무용지물이 됨.
- **심각도:** 🟡 Medium
- **발생 가능성:**  Medium
- **대응 방안:** 다양한 환경 시나리오를 포함한 데이터셋으로 모델 학습, 추천 결과에 대한 '현장 적합성 점수' 산출 및 사용자 피드백 루프(Feedback Loop)를 통한 모델 지속적 개선(Retraining).
  
  ### 3. 작업 시간 정보(S1002)와의 충돌로 인한 실행 불가 추천
- **설명:** S1003에서 이상적인 재배 방법을 결정하더라도, S1002에서 획득한 '작업 시간 정보'가 부족하거나 인력이 없는 시간대라면 해당 추천은 실행될 수 없음. 데이터 융합 로직이 부족할 경우 실행 불가능한 명령이 하달됨.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** S1003 결정 로직에 S1002(작업 가능 시간)를 제약 조건(Constraint)으로 강력하게 적용, 추천 방법 결정 시 '행 가능 여부'를 우선적으로 필터링하는 로직 도입.
  
  ### 4. 추천 방법 송신(S1004) 실패 및 알림 누락
- **설명:** 농장주는 모바일 기기나 제어판을 통해 추천 정보를 받아야 함. S1004 단계에서 서버-클라이언트 간 통신 오류가 발생할 경우, 중요한 농사 지침이 전달되지 않아 작업이 지연되거나 잘못된 방식으로 진행될 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 송신 실패 시 대체 채널(SMS, 푸시 알림, 이메일 등)을 통한 중복 전송(Redundant Transmission), 수신 확인(ACK) 프로토콜 적용 및 미수신 시 재전송 스케줄링.
  
  ### 5. 데이터 소스 간 불일치(Data Inconsistency)
- **설명:** S1001(기상청 API 등 외부 데이터)와 S1002(현장 센서 및 일정 관리 DB)의 데이터 업데이트 주기가 다를 경우, 추천 엔진(S1003)이 서로 다른 시점의 데이터를 조합하여 분석하는 '시간 여행(Teleportation)' 오류가 발생할 수 있음.
- **심각도:**  Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 데이터 수집 단계에서 타임스탬프 동기화(Time Synchronization) 강제, 분석 직전 데이터의 유효 기간(TTL) 검증 및 최신 데이터로 갱신하는 Pre-processing 단계 도입.
