# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 파이프라인 기반 생육 분석 엔진 및 통합 결과 저장 구조 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트 팜 또는 농업 데이터 분석 시스템에서 발생하는 대량의 로우 데이터(Raw Data)를 정제하고, 이상치 제거, 상관관계 도출, 생육 상태 판별까지 이어지는 복잡한 단계를 체계적으로 처리해야 함. |
| **결정(Decision)** | 데이터 로딩부터 생육 정보 분석(33)까지 단계별 모듈화된 직렬 파이프라인 아키텍처를 구축하고, 각 단계의 산출물을 '상관 분석 결과 저장(27)' 모듈로 통합 수집하는 구조를 채택함. |
| **근거(Rationale)** | 전처리(35), 이상 분석(37), 상관 분석(31), 생육 분석(33)은 상호 의존성이 높으므로 순차적 처리가 필수적임. 또한, 각 단계의 중간 결과물을 독립적으로 저장함으로써 분석의 투명성과 재현성을 확보할 수 있음. |
| **결과(Consequences)** | 각 분석 단계가 독립된 모듈로 분리되어 유지보수와 기능 확장이 용이해짐. 통합 저장소(27)를 통해 분석 이력을 일원화하여 관리할 수 있음. |
| **트레이드오프(Trade-offs)** | 파이프라인 중 앞 단계에서 지연이 발생할 경우 전체 분석 프로세스가 대기하는 직렬 구조의 병목 현상이 발생할 수 있으나, 데이터 정합성 보장 측면에서 이득이 더 큼. |

---

## ⚠️ 잠재적 위험 분석

### 1. 전처리 모듈(35)의 데이터 왜곡 위험
- **설명:** 데이터 로딩 직후 수행되는 전처리 과정에서 과도한 필터링이나 잘못된 보간법이 적용될 경우, 후속 분석 모델(37, 31, 33) 전체에 잘못된 결과가 전파됨.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 전처리 전후의 데이터 분포를 비교하는 모니터링 대시보드를 구축하고, 데이터 유실율에 대한 임계값 알람 설정.

### 2. 이상 데이터 분석(37)의 오탐(False Positive)으로 인한 데이터 손실
- **설명:** 정상적인 생육 변화를 이상 데이터로 오인하여 삭제하거나 격리할 경우, 실제 상관관계 분석(31) 시 유의미한 변수가 누락될 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 이상치 탐지 알고리즘의 민감도를 조정 가능한 파라미터로 관리하고, 확정 전 전문가 검토(Human-in-the-loop) 단계 도입 고려.

### 3. 분석 모듈 간 높은 결합도에 따른 파이프라인 중단
- **설명:** 이미지를 보면 모듈이 수직으로 연결되어 있어, 특정 분석 모듈(예: 31번)에서 런타임 에러 발생 시 최종 생육 정보 분석(33)까지 도달하지 못함.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 각 모듈 사이에 메시지 큐(Message Queue)를 도입하여 비동기 처리를 구현하고, 개별 모듈의 장애가 전체 시스템 다운으로 이어지지 않도록 격리(Isolate).

### 4. 통합 저장소(27)의 쓰기 병목 및 경합
- **설명:** 모든 분석 모듈(35, 37, 31, 33)이 동시에 '상관 분석 결과 저장(27)'으로 데이터를 전송할 경우, 저장소 성능 저하 및 데이터 유실 발생 가능.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 저장소 앞단에 버퍼링 레이어를 구축하고, 대용량 쓰기에 최적화된 NoSQL 또는 시계열 데이터베이스(TSDB) 활용.

### 5. 생육 분석 모델(33)의 성능 저하(Drift) 위험
- **설명:** 시간이 지남에 따라 재배 환경이나 품종 변화로 인해 초기 설정된 생육 분석 알고리즘의 정확도가 떨어지는 현상 발생.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 정기적인 모델 재학습 파이프라인(MLOps)을 구축하고, 실제 수확량/성장 지표와 시스템 예측치를 비교하여 정확도를 상시 검증.
