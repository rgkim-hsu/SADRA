# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 작업자-기기-계획 간의 통합 식별 및 이벤트 로깅 구조 설계

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 환경에서 작업자(sf_worker)의 생산성을 측정하고, 특정 작업(sf_wtype)이 계획(sf_workplan)대로 이행되었는지 확인하기 위해 작업기(sf_machine)와 태그(sf_tag) 데이터의 실시간 동기화 및 이력 관리가 필수적임. |
| **결정(Decision)** | `WKCODE`(작업자 코드), `WTCODE`(작업유형 코드), `TAG CODE`(태그 코드)를 중심으로 한 관계형 데이터 모델을 구축하고, 모든 현장 이벤트를 `sf_msevent` 테이블로 집중시켜 비즈니스 로직과 물리적 이벤트를 분리함. |
| **근거(Rationale)** | 작업자의 정보와 기기의 물리적 움직임을 분리하여 관리함으로써 기기 교체 시에도 작업 이력을 보존할 수 있으며, 태그 기반의 이벤트 관리는 자동화된 데이터 수집(IoT) 확장에 용이함. |
| **결과(Consequences)** | 작업 계획 대비 실제 작업 결과의 정확한 매칭이 가능해지며, 특정 시점에 어떤 작업자가 어떤 기기를 통해 어떤 작업을 수행했는지에 대한 완벽한 추적성(Traceability)을 확보함. |
| **트레이드오프(Trade-offs)** | 데이터 무결성은 높아지나, 현장의 센서 데이터(TAG)가 누락되거나 지연될 경우 전체 작업 계획(Workplan) 데이터의 신뢰도가 동시에 하락하는 의존성 위험이 존재함. |

---

## ⚠️ 잠재적 위험 분석

### 1. 센서 데이터 및 태그 인식 부정합
- **설명:** `sf_msevent` 발생 시 `sf_tag` 정보를 실시간으로 읽지 못하거나, 잘못된 태그 값이 입력되어 실제 작업 내용과 DB 기록이 일치하지 않는 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 태그 리더기에 대한 주기적인 보정 작업(Calibration) 및 데이터 입력 단계에서의 Validation 로직 강화.

### 2. WKCODE 공유 및 도용에 따른 데이터 오염
- **설명:** 현장 작업자가 본인의 `WKCODE`가 아닌 타인의 정보를 사용하여 기기를 가동하거나 작업을 대행할 경우, 성과 지표(KPI) 및 보상 시스템의 신뢰도가 붕괴됨.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 생체 인식 또는 모바일 OTP 기반의 2차 인증 도입을 통해 작업자 본인 확인 절차 강화.

### 3. 실시간 이벤트 수집 서버의 가용성 이슈
- **설명:** `sf_msevent`는 현장의 모든 물리적 이벤트를 수집하므로 트래픽이 집중될 수 있음. 서버 장애 시 전체 스마트팜의 작업 현황 파악이 불가능해짐.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 메시지 큐(Kafka, RabbitMQ 등)를 활용한 비동기 처리 및 로컬 엣지 컴퓨팅을 통한 1차 데이터 캐싱 처리.

### 4. 작업 유형(sf_wtype) 분류의 모호성
- **설명:** 수확, 적엽, 방제 외에 정의되지 않은 복합적인 작업이 발생할 경우 `sf_workplan`과 연동된 결과 리포트가 실제 상황을 반영하지 못함.
- **심각도:** 🟢 Low
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 작업 유형 코드의 유연성을 확보하고, '기타' 항목 선택 시 작업자가 특이사항을 텍스트나 음성으로 기록할 수 있는 필드 추가.

### 5. 데이터 관계 복잡성에 따른 조회 성능 저하
- **설명:** 시스템 사용자가 늘어남에 따라 `sf_workplan`에서 `sf_worker`, `sf_wtype`, `sf_machine`을 Join하여 대량의 리포트를 조회할 때 응답 속도가 급격히 느려짐.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 조회용 읽기 전용 DB(Read Replica)를 구성하거나, 일별/월별 통계 데이터를 미리 집계하는 요약 테이블(Summary Table) 운영.
