## 📋 ADR (Architecture Decision Record)

### **ADR-001: 블록체인 네트워크 기반 분산형 거래 처리 아키텍처 채택**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템 개념도는 **블록체인 네트워크(300)**를 중심으로 한 분산형 거래 처리 시스템을 보여줍니다. 사용자(93)와 거래 내역이 블록체인 네트워크에 기록되고, 네트워크 내 노드(1~4)가 데이터 검증 및 동기화를 수행하는 구조입니다. 주요 과제는 **데이터 무결성, 중앙화된 단일 실패 지점 제거, 보안 강화, 그리고 IoT/스마트팜과 같은 응용 분야에서의 신뢰성 있는 거래 처리**입니다. |
| **결정(Decision)** | 1. **퍼블릭/프라이빗 하이브리드 블록체인 네트워크** 채택: IoT 장비와 스마트팜 시스템의 보안 요구사항을 충족하기 위해 프라이빗 블록체인 네트워크(내부 노드 간 통신)를 기본으로 하며, 퍼블릭 블록체인과의 상호운용성을 위한 인터페이스(310)를 구축합니다.<br>2. **PoA(Proof of Authority) 합의 알고리즘** 채택: 에너지 효율성과 빠른 거래 처리 속도를 위해 PoA를 기본 알고리즘으로 사용합니다.<br>3. **스마트 컨트랙트 기반 거래 처리**: 스마트팜 데이터 상호운용 프레임워크(TTA 표준)와 연계하여, 자동화된 거래 및 데이터 검증 로직을 스마트 컨트랙트로 구현합니다. |
| **근거(Rationale)** | - **IoT/스마트팜 표준 준수**: ISO/IEC 30141:2024와 oneM2M 표준의 요구사항 중 **데이터 무결성 및 분산 처리**를 충족하기 위해 블록체인이 적합합니다.<br>- **보안 강화**: ITU-T X.1352와 ETSI EN 303 645의 보안 요구사항을 만족하기 위해 프라이빗 네트워크와 PoA를 사용합니다.<br>- **성능 최적화**: 스마트팜의 실시간 데이터 처리 요구사항을 위해 PoA의 빠른 블록 생성 속도를 활용합니다.<br>- **기존 시스템 연계**: TTA의 스마트팜 데이터 상호운용 프레임워크와 API를 통해 기존 시스템과 통합 가능합니다. |
| **결과(Consequences)** | ✅ **장점**:<br>1. 중앙화된 시스템의 단일 실패 지점 제거로 시스템 안정성 향상.<br>2. 블록체인 기반의 데이터 무결성으로 스마트팜 데이터 신뢰성 강화.<br>3. PoA 알고리즘으로 에너지 효율성 및 처리 속도 향상.<br>4. 스마트 컨트랙트를 통해 자동화된 거래 및 데이터 검증 가능.<br>5. TTA/ISO 표준과 호환되어 글로벌 시장에서의 상호운용성 확보.<br><br>❌ **단점**:<br>1. 초기 네트워크 구축 및 노드 관리 비용 증가.<br>2. PoA의 중앙화된 검증자 의존성으로 네트워크 보안에 대한 추가 관리 필요.<br>3. 스마트팜 데이터의 실시간 처리 요구사항에 대한 네트워크 확장성 도전.<br>4. 블록체인 네트워크의 복잡성으로 개발 및 운영 인력 교육 필요. |
| **트레이드오프(Trade-offs)** | - **보안 vs. 성능**: PoA는 중앙화된 검증자를 사용함으로써 보안을 강화하지만, 검증자 노드의 신뢰성 관리가 필요합니다.<br>- **비용 vs. 신뢰성**: 블록체인 네트워크 구축 비용이 증가하지만, 중앙화된 시스템에 비해 장기적으로 데이터 무결성과 신뢰성 향상으로 비용 효율성을 확보할 수 있습니다.<br>- **확장성 vs. 처리 속도**: PoA는 빠른 처리 속도를 제공하지만, 네트워크 노드 수가 증가할 경우 처리 속도 저하 위험이 존재합니다. |

### **ADR-002: 네트워크 노드 구조 및 데이터 동기화 메커니즘**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 블록체인 네트워크 내 노드(1~4)는 **데이터 검증, 블록 생성, 네트워크 동기화** 역할을 수행합니다. 스마트팜 시스템의 경우, **에지 노드(장비 현장)와 클라우드 노드(중앙 서버)** 간의 데이터 동기화가 필수적입니다. |
| **결정(Decision)** | 1. **하이브리드 노드 구조**:<br>   - **에지 노드**: IoT 센서 및 장비와 직접 연결되어 실시간 데이터 수집 및 전처리 수행.<br>   - **클라우드 노드**: 블록 생성 및 네트워크 동기화 담당.<br>   - **검증자 노드(PoA)**: 네트워크 내 블록 검증 및 합의 과정 수행.<br>2. **Lightweight Sync Protocol**: 에지 노드와 클라우드 노드 간의 데이터 동기화를 위해 **MQTT-SN(ISO/IEC 20922)** 프로토콜을 채택하여 경량화된 통신을 지원합니다.<br>3. **블록 크기 및 주기**: 블록 크기를 **1MB로 제한**하고, 블록 생성 주기를 **최대 5초**로 설정하여 실시간 처리 요구사항을 충족합니다. |
| **근거(Rationale)** | - **에지 컴퓨팅 표준 준수**: TTA의 "에지 기반 스마트 온실 서비스의 데이터 관리" 표준과 연계하여 에지 노드 구축.<br>- **경량 프로토콜 사용**: IETF의 CoAP/MQTT 표준과 호환되는 MQTT-SN을 통해 IoT 장비와의 상호운용성 확보.<br>- **실시간 처리 요구사항**: 스마트팜의 데이터 처리 지연 시간을 최소화하기 위한 블록 크기 및 주기 설정. |
| **결과(Consequences)** | ✅ **장점**:<br>1. 에지 노드를 통해 네트워크 트래픽 감소 및 실시간 데이터 처리 가능.<br>2. MQTT-SN 프로토콜로 IoT 장비와의 낮은 latency 통신 지원.<br>3. 블록 크기 및 주기 조절로 네트워크 확장성 확보.<br><br>❌ **단점**:<br>1. 에지 노드 구축 및 유지 관리 비용 증가.<br>2. MQTT-SN 프로토콜의 보안 취약성으로 추가 암호화 필요.<br>3. 블록 크기 제한으로 대용량 데이터 처리 시 네트워크 병목 가능성. |
| **트레이드오프(Trade-offs)** | - **에지 컴퓨팅 비용 vs. 중앙 집중식 처리**: 에지 노드를 통해 네트워크 효율성을 높이지만, 초기 구축 비용이 증가합니다.<br>- **프로토콜 선택**: MQTT-SN은 경량화된 통신을 지원하지만, 보안 강화가 필요합니다.<br>- **블록 크기 vs. 처리 속도**: 블록 크기를 줄이면 처리 속도가 향상되지만, 네트워크 효율성이 저하될 수 있습니다. |

### **ADR-003: 보안 및 데이터 무결성 메커니즘**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 블록체인 네트워크는 **사이버 공격, 데이터 변조, 권한 없는 접근** 등 다양한 보안 위협에 노출될 수 있습니다. 스마트팜 시스템의 경우, **데이터 무결성과 인증/인가**가 critical합니다. |
| **결정(Decision)** | 1. **암호화 메커니즘**:<br>   - **데이터 암호화**: AES-256을 사용하여 블록 내 데이터 암호화.<br>   - **통신 암호화**: TLS 1.3을 사용하여 노드 간 통신 암호화.<br>2. **디지털 서명**: ECDSA 알고리즘을 사용하여 블록 및 거래의 무결성 검증.<br>3. **접근 제어**: RBAC(Role-Based Access Control)를 도입하여 노드 및 사용자 권한 관리.<br>4. **보안 감사 로그**: 모든 거래 및 블록 생성 이력을 블록체인에 기록하고, 별도 감사 로그를 유지합니다. |
| **근거(Rationale)** | - **국내외 표준 준수**: KISA의 ITU-T X.1352 및 ISO/IEC 27030 보안 가이드라인 준수.<br>- **스마트팜 보안 요구사항**: TTA의 "스마트팜 데이터 상호운용 프레임워크"에서 요구하는 데이터 무결성 및 접근 제어 메커니즘 적용.<br>- **공격 방어**: ETSI EN 303 645의 사이버보안 요구사항을 충족하기 위한 암호화 및 접근 제어 정책 도입. |
| **결과(Consequences)** | ✅ **장점**:<br>1. AES-256 및 TLS 1.3을 통해 데이터 및 통신 보안 강화.<br>2. 디지털 서명으로 데이터 변조 방지.<br>3. RBAC를 통해 권한 관리 및 감사 가능성 향상.<br><br>❌ **단점**:<br>1. 암호화 및 디지털 서명 처리로 네트워크 처리 속도 저하 가능성.<br>2. RBAC 구축 및 유지 관리 복잡성 증가.<br>3. 감사 로그 관리 비용 증가. |
| **트레이드오프(Trade-offs)** | - **보안 vs. 성능**: 암호화 및 디지털 서명으로 보안을 강화하지만, 네트워크 처리 속도가 저하될 수 있습니다.<br>- **접근 제어 복잡성 vs. 보안**: RBAC를 통해 보안을 강화하지만, 시스템 복잡성이 증가합니다. |

## ⚠️ 잠재적 위험 분석

### **1. 네트워크 확장성 저하**
- **설명**: 블록체인 네트워크의 노드 수가 증가함에 따라 블록 생성 속도 저하 및 네트워크 지연 발생. 특히 스마트팜 시스템의 경우, 대량의 IoT 장비 데이터 처리 요구로 네트워크 병목 현상 발생 가능성 높음.
- **심각도**: 🟡 Medium
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  1. **Sharding 기술 도입**: 네트워크를 작은 샤드 단위로 분할하여 병렬 처리 능력을 향상시킵니다.
  2. **동적 블록 크기 조절**: 네트워크 부하에 따라 블록 크기를 자동으로 조절합니다.
  3. **에지 노드 최적화**: 에지 노드에서 데이터 전처리를 통해 클라우드 노드 부하를 줄입니다.
  4. **모니터링 시스템 구축**: 네트워크 성능을 실시간으로 모니터링하고, 부하가 발생할 경우 자동으로 리소스를 재할당합니다.

---

### **2. PoA 검증자 노드의 중앙화 위험**
- **설명**: PoA 알고리즘은 중앙화된 검증자 노드에 의존하므로, 검증자 노드가 해킹되거나 악의적으로 작동할 경우 네트워크 보안이 위협받습니다. 또한, 검증자 노드의 단일 실패로 네트워크 전체가 영향을 받을 수 있습니다.
- **심각도**: 🔴 High
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  1. **다중 검증자 클러스터**: 최소 5개 이상의 검증자 노드를 클러스터로 구성하여 단일 실패 지점 제거.
  2. **검증자 노드 보안 강화**: 하드웨어 보안 모듈(HSM)과 네트워크 격리 정책을 적용합니다.
  3. **정기적 감사 및 교체**: 검증자 노드를 정기적으로 감사하고, 필요 시 교체합니다.
  4. **비즈니스 연속성 계획(BCP)**: 검증자 노드 장애 시 대체 검증자를 자동으로 활성화하는 메커니즘 구축.

---

### **3. 데이터 프라이버시 침해**
- **설명**: 블록체인 네트워크에 기록되는 스마트팜 데이터는 민감한 정보(예: 농작물 상태, 환경 데이터)를 포함할 수 있습니다. 블록체인의 투명성 특성으로 인해 데이터가 공개적으로 노출될 위험이 존재합니다.
- **심각도**: 🔴 High
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  1. **제로-노위스트 프로토콜**: 민감한 데이터는 해시 값만 블록체인에 기록하고, 실제 데이터는 암호화된 별도 저장소에 보관합니다.
  2. **접근 제한 정책**: RBAC를 통해 민감한 데이터에 대한 접근을严格하게 통제합니다.
  3. **데이터 마스킹**: 블록체인에 기록되는 데이터의 일부를 마스킹하여 개인 정보 노출 방지.
  4. **국내외 규제 준수**: KISA 및 GDPR과 같은 규제를 준수하여 데이터 처리 및 보관 정책을 설정합니다.

---

### **4. 스마트 컨트랙트 취약성**
- **설명**: 스마트팜 시스템의 자동화된 거래 및 데이터 검증 로직은 스마트 컨트랙트로 구현됩니다. 스마트 컨트랙트 코드에 버그나 취약점이 존재할 경우, 재정적 손실 또는 시스템 장애가 발생할 수 있습니다.
- **심각도**: 🔴 High
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  1. **코드 오픈 리뷰 및 테스트**: 스마트 컨트랙트 코드를 전문가 팀이 리뷰하고, 자동화된 테스트 도구(예: MythX, Slither)를 사용하여 취약성 분석 수행.
  2. **업그레이드 가능한 컨트랙트**: 스마트 컨트랙트의 업그레이드 메커니즘을 구축하여 버그 패치 및 기능 개선 가능.
  3. **다중 서명 요구**: 중요한 거래는 다중 서명을 요구하여 단일 오류로 인한 손실을 방지합니다.
  4. **보안 오디트**: 정기적으로 제3자 보안 오디트를 수행합니다.

### **5. 네트워크 분할(Network Partitioning) 및 가용성 저하**
- **설명**: 네트워크 분할 또는 노드 장애로 인해 블록체인 네트워크가 분할될 경우, 네트워크 가용성이 저하되고 데이터 동기화에 실패할 수 있습니다. 특히 스마트팜 시스템의 경우, 실시간 데이터 처리 요구로 인해 네트워크 분할이 치명적인 영향을 미칠 수 있습니다.
- **심각도**: 🔴 High
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  1. **Byzantine Fault Tolerance(BFT) 알고리즘**: 네트워크 분할 시에도 합의를 유지할 수 있는 BFT 알고리즘(예: PBFT)을 도입합니다.
  2. **자동 재동기화 메커니즘**: 네트워크가 재연결될 경우, 자동으로 데이터 동기화를 수행합니다.
  3. **오프라인 처리 및 동기화**: 에지 노드가 오프라인 상태에서도 데이터를 임시 저장하고, 네트워크가 재연결될 때 동기화합니다.
  4. **중복 네트워크 구조**: 주요 네트워크와 백업 네트워크를 중복 구축하여 가용성 향상.

- **심각도**: 🟡 Medium
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  1. **규제 모니터링 시스템**: 정기적으로 규제 변경 사항을 모니터링하고, 시스템에 반영합니다.
  2. **준수성 평가**: 정기적으로 제3자 준수성 평가를 수행합니다.
  3. **문서화된 정책**: 모든 보안 및 데이터 처리 정책을 문서화하고, 규제 기관에 제출 가능하게 유지합니다.
  4. **법적 자문**: 블록체인 및 스마트팜 시스템의 법적 전문가를 상주시킵니다.
