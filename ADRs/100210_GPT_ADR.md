📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: IoT-클라우드-AI 통합 기반 스마트팜 데이터 중심 아키텍처

| 항목                     | 내용                                                                                                                                                                                                                                                                   |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 시스템은 농장 내 센서(G/W, 온도, 습도, EC, pH 등)를 통해 데이터를 수집하고, 이를 클라우드 기반 농업데이터 관제시스템 및 스마트 농업기반 시스템에서 처리한다. 데이터는 환경정보, 내부환경, 양액정보 등으로 구분되며, AI 분석을 통해 생육 예측 및 병해 발생 예측에 활용된다. 또한 관리자 웹 서비스와 농가용 모바일 앱을 통해 사용자에게 제공된다. 핵심 과제는 대규모 IoT 데이터의 실시간 수집, 정제, 분석, 그리고 사용자 맞춤형 서비스 제공이다. |
| **결정(Decision)**       | IoT 게이트웨이(G/W) → 데이터 수집 플랫폼 → 클라우드 데이터 레이크 → AI 분석 → 사용자 서비스로 이어지는 데이터 파이프라인 중심 아키텍처를 채택한다. 데이터 수집 계층과 분석 계층을 분리하고, AI 분석 모듈을 독립 서비스로 구성하여 확장성과 유연성을 확보한다.                                                                                                           |
| **근거(Rationale)**      | 스마트팜은 센서 데이터의 양이 방대하고, 실시간 처리와 장기 분석이 모두 필요하다. 계층 분리 구조는 데이터 처리 부하를 분산시키고, AI 모델을 독립적으로 발전시킬 수 있게 한다. 또한 모바일/웹 서비스와의 연계를 통해 사용자 접근성을 높인다.                                                                                                                            |
| **결과(Consequences)**   | 데이터 기반 의사결정이 가능해지고, 병해 예측 및 생산성 향상 효과를 기대할 수 있다. 그러나 데이터 품질 관리와 AI 모델 정확도 유지가 중요한 과제로 남는다.                                                                                                                                                                           |
| **트레이드오프(Trade-offs)** | 데이터 활용 극대화(장점) vs 데이터 관리 복잡성 증가(단점), AI 기반 고도화(장점) vs 모델 유지 비용 증가(단점)                                                                                                                                                                                                |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. 데이터 품질 저하

* **설명:** 센서 오류 또는 통신 장애로 인해 부정확한 데이터가 수집되어 분석 결과 왜곡

* **심각도:** 🔴 High

* **발생 가능성:** 🔴 High

* **대응 방안:** 데이터 정제 파이프라인 구축, 이상치 탐지, 센서 교정 및 이중화

### 2. AI 모델 예측 오류

* **설명:** 병해 예측 또는 생육 분석 모델의 정확도가 낮아 잘못된 의사결정 유도

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 지속적인 모델 재학습, 검증 데이터셋 확보, 모델 성능 모니터링

### 3. 네트워크 장애 및 데이터 손실

* **설명:** 농장-클라우드 간 네트워크 장애로 데이터 전송 실패

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 로컬 버퍼링, 재전송 메커니즘, 다중 네트워크 구성

### 4. 보안 취약점 (데이터 및 제어 권한)

* **설명:** 클라우드 및 IoT 구간에서 해킹 발생 시 데이터 유출 또는 제어권 탈취

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 데이터 암호화, 인증/인가 강화, IoT 보안 정책 적용

### 5. 시스템 확장성 한계

* **설명:** 농장 수 증가에 따라 데이터 처리 및 저장 용량 한계 도달

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 클라우드 오토스케일링, 분산 데이터 처리(Spark, Kafka) 도입

### 6. 사용자 서비스 장애

* **설명:** 모바일 앱 또는 관리자 웹 서비스 장애로 사용자 접근 불가

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 서비스 이중화, CDN 적용, 장애 모니터링 및 자동 복구 시스템 구축
