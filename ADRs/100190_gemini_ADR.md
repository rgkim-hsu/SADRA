# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 메시징 게이트웨이 기반의 하이브리드 풀필먼트 통합 아키텍처 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 내부 창고 관리 시스템(119)뿐만 아니라 다수의 제3자 풀필먼트(121A~C)와 협력해야 하는 환경에서, 각기 다른 프로토콜과 데이터 규격을 가진 외부 시스템들을 유연하게 통합하고 확장해야 하는 과제에 직면함. |
| **결정(Decision)** | **풀필먼트 메시징 게이트웨이(115)**를 중앙 허브로 배치하여 배송 기관 기술 시스템(101) 및 풀필먼트 최적화 시스템(113)과 하부 실행 시스템 간의 통신을 표준화하고 추상화함. |
| **근거(Rationale)** | 직접적인 점대점(Point-to-Point) 연결은 시스템 복잡도를 기하급수적으로 증가시킴. 게이트웨이를 통한 메시지 라우팅은 신규 제3자 파트너 확장을 용이하게 하며, 공급 체인 관리 시스템(117)과의 데이터 동기화를 중앙 집중화할 수 있음. |
| **결과(Consequences)** | **(긍정적)** 파트너사 추가 시 기존 로직 수정 최소화, 메시지 포맷의 단일화로 인한 유지보수성 향상. **(부정적)** 게이트웨이 계층 추가에 따른 네트워크 지연 시간(Latency) 미세 증가 및 해당 컴포넌트의 가용성 의존도 상승. |
| **트레이드오프(Trade-offs)** | 초기 게이트웨이 구축 및 표준화 비용이 발생하나, 장기적인 운영 확장성과 파트너사 관리의 유연성을 확보함. |

---

## ⚠️ 잠재적 위험 분석

### 1. 풀필먼트 메시징 게이트웨이의 단일 장애점(SPOF) 위험
- **설명:** 모든 주문 및 재고 메시지가 게이트웨이(115)를 통과하므로, 해당 시스템 장애 시 전체 풀필먼트 프로세스가 중단됨.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 다중 가용 영역(Multi-AZ) 배포, 로드 밸런싱 적용 및 서킷 브레이커 패턴을 도입하여 장애 전파 차단.

### 2. 실시간 재고 데이터의 불일치(Data Inconsistency)
- **설명:** 제3자 풀필먼트(121)와 내부 시스템 간의 데이터 동기화 지연으로 인해 품절 상품에 대한 주문이 발생하는 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 이벤트 기반 아키텍처(EDA)를 통한 실시간 상태 업데이트 및 주기적인 재고 대조(Reconciliation) 배치 프로세스 운영.

### 3. 모바일 기기(107, 119)의 현장 통신 불안정성
- **설명:** 운송 시스템(107) 및 창고 관리(119)에서 사용하는 모바일 디바이스가 네트워크 음영 지역 진입 시 데이터 유실 또는 처리 지연 발생.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 로컬 스토리지 기반의 '오프라인 우선(Offline-first)' 동기화 전략 및 메시지 큐를 활용한 재시도 메커니즘 구현.

### 4. 제3자 풀필먼트 파트너의 보안 취약점 노출
- **설명:** 외부 파트너 시스템(121A~C)과의 API 연동 과정에서 인증 정보 유출 또는 비정상적인 접근 권한 획득 위험.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 풀필먼트 센터 인증 시스템(123)을 통한 엄격한 OAuth2.0/mTLS 기반 인증 적용 및 파트너별 API 쿼터 제한(Throttling) 설정.

### 5. 급격한 주문량 증가에 따른 시스템 확장성 병목
- **설명:** 프로모션이나 성수기 시 배송 및 주문 트래킹 시스템(111)에 트래픽이 몰려 조회가 지연되거나 시스템이 다운되는 상황.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 읽기/쓰기 분리(CQRS) 및 캐시 레이어(Redis 등) 도입, 주요 컴포넌트의 오토 스케일링(Auto-scaling) 정책 강화.
