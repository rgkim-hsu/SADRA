📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: **데이터 파이프라인 중앙 집중화 및 실시간 처리 아키텍처 채택**

| 항목                                                                         | 내용                                                                                                                                                                                                                                                                |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**                                                            | 스마트팜 시스템은 센서, IoT 기기, 외부 데이터 등 다양한 소스에서 데이터가 유입됩니다. 시스템 개념도에서 데이터 수집, 처리, 라벨링, AI 모델 개발, 활용으로 이어지는 데이터 흐름이 확인됩니다. 각 단계(데이터 수집, 처리, 라벨링, AI 모델 개발)는 서로 유기적으로 연결되어 있으며, 특히 외부 데이터(기상데이터, 환경데이터, 라벨링데이터)를 통합해야 합니다. 기존 분산형 데이터 처리 방식은 데이터 일관성, 실시간성, 확장성에서 한계가 있습니다. |
| **결정(Decision)**                                                           | 데이터 파이프라인을 **중앙 집중화**하고, **실시간 데이터 처리**를 위해 스트리밍 아키텍처(예: Apache Kafka, Apache Flink)를 도입합니다. 또한, 외부 데이터를 통합하기 위해 **API 게이트웨이**를 통해 표준화된 인터페이스를 제공합니다.                                                                                                             |
| **근거(Rationale)**                                                          | 스마트팜은 실시간으로 환경 데이터를 모니터링하고, 즉각적인 조치를 취해야 합니다(예: 온도/습도 조절, 병해충 예방). 중앙 집중화된 데이터 파이프라인은 데이터의 일관성을 보장하며, 실시간 처리는 신속한 의사결정을 가능하게 합니다. 또한, 외부 데이터(기상, 라벨링 등)를 통합함으로써 AI 모델의 정확성을 높일 수 있습니다.                                                                            |
| **결과(Consequences)**                                                       | **장점**: 데이터 일관성 향상, 실시간 분석 가능, 외부 데이터 통합 용이, 확장성 보장.                                                                                                                                                                                                              |
| **단점**: 중앙 집중화로 인한 단일 장애점(Single Point of Failure) 위험, 실시간 처리 인프라의 복잡성 증가. |                                                                                                                                                                                                                                                                   |
| **트레이드오프(Trade-offs)**                                                     | **장점**: 실시간성, 일관성, 확장성.                                                                                                                                                                                                                                           |
| **단점**: 인프라 비용 증가, 시스템 복잡도 상승, 장애 시 전체 시스템에 미치는 영향.                        |                                                                                                                                                                                                                                                                   |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. **데이터 일관성 손실**

* **설명:** 중앙 집중화된 데이터 파이프라인에서 네트워크 지연 또는 장애로 인해 데이터가 동기화되지 않을 경우, AI 모델 학습 또는 실시간 의사결정에 오류가 발생할 수 있습니다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 데이터 동기화를 위한 **분산 트랜잭션(2PC, Saga 패턴)** 도입, **데이터 백업 및 복구 메커니즘** 구축, **모니터링 시스템**을 통해 실시간으로 데이터 일관성 검증.

* * *

### 2. **실시간 처리 지연**

* **설명:** 스트리밍 데이터 처리 시, sudden burst(예: 센서 데이터 폭주)로 인해 처리 지연이 발생하면, 스마트팜의 실시간 제어 시스템(예: 자동 관수 시스템)이 제때 동작하지 않을 수 있습니다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** **오토스케일링**을 지원하는 클라우드 인프라(예: AWS Kinesis, Azure Stream Analytics) 사용, **우선순위 기반 큐**를 통해 중요 데이터(예: 온도/습도 경보) 우선 처리.

* * *

### 3. **외부 데이터 통합 장애**

* **설명:** 외부 API(기상청, 라벨링 서비스 등)에서 장애가 발생하면, 시스템이 의존하는 외부 데이터가 유실되어 AI 모델의 예측 정확도가 떨어질 수 있습니다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** **fallback 메커니즘** 구축(예: 캐싱된 과거 데이터 사용), **다중 외부 데이터 소스** 연동, **API 헬스 체크** 및 자동 재시도 로직 구현.

* * *

### 4. **보안 취약점(데이터 유출)**

* **설명:** 중앙 집중화된 데이터 저장소는 해커의 표적이 될 수 있으며, 특히 농업 데이터(예: 작물 생산량, 토양 데이터)는 민감한 정보로 분류될 수 있습니다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟢 Low
* **대응 방안:** **데이터 암호화**(At Rest & In Transit), **접근 제어(IAM, RBAC)** 강화, **로그 감사(Audit Log)** 시스템 도입, **Zero Trust 아키텍처** 적용.

* * *

### 5. **AI 모델 편향성(Bias)**

* **설명:** 라벨링 데이터의 질이 낮거나, 특정 환경(예: 특정 지역/시기)에 편중되어 있으면, AI 모델이 실제 농장 환경에서 잘못된 예측을 할 수 있습니다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** **다양한 데이터 소스**를 통해 라벨링 데이터의 편향성 최소화, **모델 설명 가능성(XAI)** 도구(예: SHAP, LIME)을 통해 모델 결정 과정 투명성 확보, **정기적인 모델 재학습** 및 검증.

* * *

### 6. **시스템 확장성 한계**

* **설명:** 스마트팜 시스템이 대규모로 확장될 경우(예: 100개 이상의 농장 연동), 중앙 집중화된 아키텍처가 병목 현상을 일으킬 수 있습니다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** **마이크로서비스 아키텍처**로 전환, **지리적 분산**을 위한 에지 컴퓨팅(Edge Computing) 도입, **로드 밸런싱** 및 **캐싱** 메커니즘 최적화.
