### ADR-001: **All-in-One 플랫폼 중심의 통합 스마트팜 아키텍처 채택**

| 항목                     | 내용                                                                                                                                                                                                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **상황(Context)**        | 스마트팜 시스템은 실시간으로 다양한 센서(온도, 습도, EC, pH, 영상, 음성 등)와 제어 장비(조명, 환기, 수분 공급 등)를 통합하여 농작물 재배 환경을 최적화해야 함. 기존 시스템은 이기종 장비와 플랫폼 간의 상호운영성 부족으로 데이터 통합 및 제어에 어려움이 있음.                                                                                                         |
| **결정(Decision)**       | **All-in-One 플랫폼**을 중심으로 **데이터 수집 모듈**, **AI/ML 분석 모듈**, **제어 프로그램**, **외부 연동 모듈**, **DBMS**를 통합하는 중앙 집중식 아키텍처를 채택. 특히, **UV/UX 디자인 모듈**과 **데이터 분석 모듈**을 통해 사용자 친화적인 인터페이스와 고급 분석 기능을 제공.                                                                          |
| **근거(Rationale)**      | 1) **통합성**: 단일 플랫폼에서 모든 데이터를 수집·처리·제어하여 시스템 복잡성을 감소시킴. 2) **확장성**: Open API/Service 기능을 통해 타 시스템(예: 기상청 데이터, IoT 플랫폼)과 연동 가능. 3) **실시간성**: Edge 디바이스(예: 라즈베리파이, Arduino)에서 수집된 데이터를 클라우드로 전송하여 실시간 모니터링 및 제어 가능. 4) **사용자 편의성**: 웹/SW, 모바일, 서비스 애플리케이션을 통해 접근성 향상. |
| **결과(Consequences)**   | ✅ **장점**: 데이터 일관성 보장, 중앙 집중식 관리 용이, AI 기반 예측 분석(예: 질병 진단, 성장 예측) 가능. ❌ **단점**: 단일 장애점으로 인해 플랫폼 전체가 다운될 경우 시스템 마비 위험.                                                                                                                                               |
| **트레이드오프(Trade-offs)** | **장점**: 통합 관리 및 실시간 데이터 처리로 생산성 향상. **단점**: 플랫폼 의존도 증가로 인한 유연성 저하, 초기 구축 비용 증가.                                                                                                                                                                                    |

### ADR-002: **Edge-Cloud 하이브리드 데이터 처리 모델 적용**

| 항목                     | 내용                                                                                                                                         |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **상황(Context)**        | 실시간 제어가 필요한 스마트팜 환경에서 모든 데이터를 클라우드로 전송할 경우 지연 시간(latency)으로 인해 제어 반응이 느려질 수 있음.                                                            |
| **결정(Decision)**       | **Edge 디바이스**(예: 라즈베리파이, Arduino)에서 실시간 데이터 수집 및 간단한 제어 로직을 처리하고, **클라우드 플랫폼**에서는 고급 분석(예: AI 모델 학습, 빅데이터 처리)을 담당하는 하이브리드 모델 채택.           |
| **근거(Rationale)**      | 1) **지연 시간 최소화**: Edge에서 즉각적인 제어(예: 온도 조절, 습도 유지) 수행. 2) **대역폭 최적화**: 클라우드로 전송되는 데이터 양 감소. 3) **오프라인 동작**: 네트워크 장애 시 Edge 디바이스에서 기본 기능 유지. |
| **결과(Consequences)**   | ✅ **장점**: 실시간성 보장, 네트워크 부담 감소. ❌ **단점**: Edge 디바이스의 처리 능력 한계로 복잡한 분석 불가능, 데이터 동기화 이슈 발생 가능.                                                |
| **트레이드오프(Trade-offs)** | **장점**: 빠른 응답 속도와 안정성. **단점**: Edge 디바이스의 하드웨어 비용 증가, 분산 시스템 관리 복잡성.                                                                       |

### ADR-003: **표준화된 Open API/Service 인터페이스 제공**

| 항목                     | 내용                                                                                                                           |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 시스템은 다양한 외부 시스템(예: 기상청, 농업 관리 플랫폼)과 연동되어야 하며, 미래 확장성을 위해 인터페이스가 표준화되어야 함.                                               |
| **결정(Decision)**       | **Open API/Service**를 통해 외부 시스템과 연동 가능하도록 설계. 특히, **RESTful API**와 **MQTT 프로토콜**을 사용하여 실시간 데이터 교환 지원.                        |
| **근거(Rationale)**      | 1) **호환성**: 표준 프로토콜을 통해 다양한 디바이스와 시스템 연동 가능. 2) **유연성**: 새로운 기능 추가 시 API를 통해 쉽게 통합. 3) **보안성**: API 게이트웨이를 통해 인증 및 권한 관리 가능. |
| **결과(Consequences)**   | ✅ **장점**: 시스템 확장 용이, 타 플랫폼과의 호환성 향상. ❌ **단점**: API 관리 및 유지보수 비용 증가, 보안 취약점 노출 위험.                                            |
| **트레이드오프(Trade-offs)** | **장점**: 생태계 확장성. **단점**: API 버전 관리 및 보안 유지 비용.                                                                               |

⚠️ 잠재적 위험 분석
------------

### 1. **단일 장애점(Single Point of Failure) 발생**

* **설명:** All-in-One 플랫폼이 중앙 집중식으로 운영될 경우, 플랫폼 서버 장애 시 전체 시스템이 마비될 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** **고가용성(HA) 아키텍처** 도입(예: 클러스터링, 로드 밸런싱), **백업 시스템** 구축, **Edge 디바이스에서의 로컬 제어 모드** 활성화.

* * *

### 2. **데이터 지연 및 동기화 오류**

* **설명:** Edge와 Cloud 간 데이터 동기화 지연으로 인해 실시간 제어에 오류가 발생할 수 있음. 예를 들어, 온도 센서 데이터가 지연되어 incorrect한 제어 신호가 전송될 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** **실시간 동기화 프로토콜**(예: WebSocket, MQTT QoS 2) 사용, **타임스탬프 기반 데이터 검증** 메커니즘 도입.

* * *

### 3. **보안 취약점 노출**

* **설명:** Open API를 통해 외부 시스템과 연동할 경우, **API 인증 우회**나 **데이터 유출** 위험이 존재. 특히, 농업 데이터는 경제적 가치가 높음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** **API 게이트웨이**에 **OAuth 2.0** 및 **JWT 토큰** 기반 인증 적용, **데이터 암호화**(TLS 1.3), **정기적인 보안 감사** 수행.

* * *

### 4. **Edge 디바이스의 처리 능력 한계**

* **설명:** Edge 디바이스(예: 라즈베리파이)에서 AI 모델이나 복잡한 분석을 수행할 경우, **처리 지연**이나 **과부하**로 인해 시스템 성능 저하 발생.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** **Edge 디바이스에 최적화된 경량 AI 모델**(예: TinyML) 사용, **클라우드로 오프로딩** 가능한 작업은 클라우드에서 처리.

* * *

### 5. **시스템 확장성 한계**

* **설명:** 농장 규모가 확대될 경우, **센서 및 디바이스 수 증가**로 인해 시스템이 처리해야 할 데이터 양이 기하급수적으로 증가, 성능 병목 현상 발생.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟢 Low (초기 단계) → 🔴 High (확장 단계)
* **대응 방안:** **마이크로서비스 아키텍처(MSA)**로 시스템 분할, **오토스케일링** 기능 도입, **분산 데이터베이스**(예: Cassandra) 사용.

* * *

### 6. **데이터 품질 및 정확성 저하**

* **설명:** 센서 오류 또는 네트워크 노이즈로 인해 **정확하지 않은 데이터**가 수집될 경우, AI 분석 결과와 제어 로직에 오류 발생.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** **다중 센서 데이터 크로스 체크**, **이상치 검출 알고리즘**(예: Z-score, IQR) 적용, **정기적인 센서 교정** 수행.
