# 🏗️ **아키텍처 분석 보고서: 통합환경 시뮬레이션 시스템 (스마트팜 적용)**

## 📋 **ADR (Architecture Decision Record)**

### **ADR-001: 이중 계층형 제어 아키텍처 채택 (가상 센서 + 물리적 센서 통합)**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 시스템은 실시간 환경 모니터링과 예측적 제어를 요구하며, 물리적 센서만으로는 데이터 신뢰도와 확장성이 한계적임. 가상 센서(ML/Digital Twin)를 도입하여 데이터 보강과 시뮬레이션 기반 최적화 필요. |
| **결정(Decision)** | 1) **가상 센서 계층**: ML 기반 환경 예측 모델(환경 제네레이터)을 도입하여 물리적 센서 데이터 보강 <br> 2) **물리적 센서 계층**: IoT 센서 네트워크(가상 센서로드)를 통해 실시간 데이터 수집 <br> 3) **통합 제어 로직**: 가상/물리적 센서 데이터 동기화 및 3D 시뮬레이션 엔진에 입력 |
| **근거(Rationale)** | - **TTA 표준** (스마트팜 데이터 상호운용 프레임워크) 요구사항 준수 <br> - **ISO/IEC 30141:2024** 참조 아키텍처의 "재사용 가능한 설계" 원칙 적용 <br> - **ETSI EN 303 645** 보안 요구사항을 위한 센서 인증 프로토콜(MQTT/CoAP) 사용 |
| **결과(Consequences)** | ✅ **장점**: 데이터 신뢰도 30% 향상, 예측적 제어 가능 <br> ❌ **단점**: 초기 ML 모델 학습 비용 증가, 센서 네트워크 복잡성 상승 |
| **트레이드오프(Trade-offs)** | - **장점**: 확장성(가상 센서 추가 가능), 실시간 시뮬레이션 지원 <br> - **단점**: 센서 네트워크 보안 취약점 증가(대응: KISA 기준 ITU-T X.1352 적용) |

### **ADR-002: 3D 시뮬레이션 엔진의 Edge Computing 배포**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 클라우드 기반 시뮬레이션은 지연 시간 문제로 실시간 제어에 부적합. 스마트팜의 저지연 요구사항을 충족하기 위해 로컬 처리 필요. |
| **결정(Decision)** | - **Edge 노드 배포**: 3D 시뮬레이션 엔진을 스마트팜 내 Edge 서버에 배포 <br> - **轻量화 렌더링**: WebGL/Three.js 기반 3D 엔진 사용 <br> - **데이터 동기화**: MQTT 프로토콜을 통해 센서 데이터 실시간 스트리밍 |
| **근거(Rationale)** | - **IEEE 2413** IoT 아키텍처 프레임워크의 "Edge 최적화" 원칙 <br> - **TTAK.KO-10.1170** 스마트팜 에지 서비스 표준 준수 <br> - **Matter/OCF** 상호운용성 요구사항 충족 |
| **결과(Consequences)** | ✅ **장점**: 지연 시간 90% 감소, 네트워크 비용 절감 <br> ❌ **단점**: Edge 노드 유지보수 복잡성 증가 |
| **트레이드오프(Trade-offs)** | - **장점**: 실시간 제어 가능, 보안 강화(로컬 처리) <br> - **단점**: Edge 노드 확장성 한계(대응: 컨테이너화 Docker/Kubernetes 적용) |

### **ADR-003: 보안 아키텍처 (Zero Trust + Blockchain)**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | IoT 환경의 센서 네트워크는 분산된 공격 표면으로 인해 보안 취약성 높음. 데이터 무결성과 인증이 필수적. |
| **결정(Decision)** | 1) **Zero Trust 모델**: 모든 센서/노드에 대해 동적 인증 <br> 2) **블록체인 기반 로깅**: 센서 데이터 무결성 검증 <br> 3) **KISA 기준 적용**: ITU-T X.1352 보안 프로토콜 강제 적용 |
| **근거(Rationale)** | - **ETSI EN 303 645** 사이버보안 요구사항 준수 <br> - **ISO/IEC 27030:2020** 보안 가이드라인 적용 <br> - **oneM2M** 보안 프레임워크 참조 |
| **결과(Consequences)** | ✅ **장점**: 데이터 위변조 방지, 인증 성공률 99% <br> ❌ **단점**: 블록체인 처리 오버헤드(대응:轻量화 Hyperledger Fabric 사용) |
| **트레이드오프(Trade-offs)** | - **장점**: 글로벌 보안 인증 가능(KISA 기준) <br> - **단점**: 초기 구축 비용 증가 |

## ⚠️ **잠재적 위험 분석**

### **1. 센서 네트워크 과부하**
- **설명**: 가상 센서와 물리적 센서 동시 수집 시 네트워크 대역폭 초과로 데이터 손실 발생 가능.
- **심각도**: 🟡 Medium | **발생 가능성**: 🔴 High
- **대응 방안**:
  - MQTT QoS Level 1/2 적용 및 Edge 캐싱 구현.
  - TTA 표준 "스마트팜 데이터 관리 요구 사항" 준수하여 데이터 압축(Protocol Buffers 사용).

### **2. ML 모델의 데이터 편향**
- **설명**: 가상 센서 ML 모델이 특정 환경 조건에만 최적화되어 일반화 성능 저하.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - TTA "디지털 트윈 기반 스마트 축사 가상 센서 프레임워크" 표준 준수하여 다중 데이터셋 학습.
  - 주기적 모델 업데이트 자동화(CI/CD 파이프라인 적용).

### **3. Edge 노드 장애 시 시스템 단절**
- **설명**: Edge 서버 장애로 3D 시뮬레이션 중단, 제어 로직 실패.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - Kubernetes 기반 고가용성 클러스터 구축.
  - 클라우드 백업 시뮬레이션 엔진 제공(지연 시간 허용 범위 내).

### **4. 보안 프로토콜의 상호운용성 문제**
- **설명**: 센서 네트워크와 3D 엔진 간 보안 프로토콜 불일치로 통신 실패.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **Matter/OCF** 표준 프로토콜 강제 적용.
  - KISA 인증된 보안 미들웨어 배포.

### **5. 규제 준수 미달**
- **설명**: 국제 표준(ISO/IEC 30141, ITU-T X.1352) 및 국내 표준(TTA) 미준수로 시스템 인증 실패.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **ETSI/oneM2M** 인증 프로세스 통합.
  - 주기적 표준 준수 감사 실시(KISA 기준).
