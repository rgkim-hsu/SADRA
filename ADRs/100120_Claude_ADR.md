📋 ADR (Architecture Decision Record)

### ADR-001: 가상 센서/제어 레이어를 통한 디지털 트윈 기반 통합 환경 시뮬레이션 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 환경에서는 실제 물리적 센서 및 제어 장치의 오작동, 환경 변수의 복잡성, 그리고 제어 로직 검증을 위한 실험적 테스트가 필요하다. 실제 환경에서 직접 실험할 경우 작물 피해, 장비 손상, 높은 비용이 발생한다. 개념도상 '가상 센서로드 ↕ 가상 센서'와 '가상 제어로드 ↕ 가상 제어기'라는 이중 레이어 구조가 물리 환경과 제어 시스템 사이에 위치하며, 환경 제너레이터가 시뮬레이션 입력을 공급한다. |
| **결정(Decision)**       | 물리적 스마트팜 인프라와 스마트팜 통합제어시스템(SCADA) 사이에 가상 센서/가상 제어기 레이어를 독립 배치하는 디지털 트윈(Digital Twin) 아키텍처를 채택한다. 환경 제너레이터가 온도·습도·CO₂·광량 등 환경 파라미터를 생성하고, 가상 센서가 이를 수집·변환하며, 가상 제어기가 제어 명령을 시뮬레이션한다. 3D 환경 뷰어는 시각화 레이어로 분리 운영한다.                       |
| **근거(Rationale)**      | ① 실제 장비 투입 없이 제어 알고리즘 사전 검증 가능 → 운영 리스크 최소화. ② 가상/실물 센서 데이터 병렬 비교를 통한 이상 탐지(Anomaly Detection) 구현 가능. ③ 3D 환경 뷰어의 시각화 분리로 HMI 레이어의 독립적 확장 용이. ④ IEC 61499(분산 제어 시스템 표준) 및 ISO 11783(농업 전자제어 표준) 준수 관점에서 가상화 레이어가 인터페이스 표준화에 유리.       |
| **결과(Consequences)**   | 긍정적: 신규 제어 로직의 무중단 검증 환경 확보, 실물 센서 고장 시 가상 센서로 부분 대체 운영 가능, 3D 뷰어를 통한 관리자 직관적 모니터링 향상. 부정적: 가상-실물 간 동기화 복잡도 증가, 시뮬레이션 정확도가 실제 물리 환경 모델링 품질에 강하게 종속, 시스템 컴포넌트 수 증가로 인한 운영 오버헤드 발생.                                                     |
| **트레이드오프(Trade-offs)** | 얻는 장점: 안전한 실험 환경, 빠른 제어 로직 이터레이션, 장애 시나리오 사전 대응 훈련 가능. 감수할 단점: 가상 모델과 실제 환경 간 피델리티(Fidelity) 격차로 인한 시뮬레이션 결과 신뢰성 한계, 이중 레이어 유지보수 비용 증가, 실시간 동기화를 위한 네트워크 대역폭 및 레이턴시 요구 수준 상승.                                                         |

### ADR-002: 스마트팜 통합제어시스템과 3D 환경 뷰어의 독립 서브시스템 분리 아키텍처

| 항목                     | 내용                                                                                                                                                       |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 개념도에서 스마트팜 통합제어시스템(좌측)과 3D 환경 뷰어(우측)는 통합 환경 시뮬레이션 시스템으로부터 각각 독립적인 화살표로 데이터를 수신한다. 두 시스템은 서로 다른 사용자(현장 운영자 vs. 관리자/의사결정자)와 서로 다른 목적(제어 vs. 시각화)을 가진다.     |
| **결정(Decision)**       | 통합제어시스템(SCADA/HMI)과 3D 환경 뷰어를 별도의 독립 서브시스템으로 분리하고, 시뮬레이션 엔진으로부터 공통 데이터 버스(메시지 브로커 또는 공유 데이터 스토어)를 통해 각각 데이터를 구독하는 Pub/Sub 패턴을 적용한다.                      |
| **근거(Rationale)**      | ① 제어 시스템과 시각화 시스템의 장애 격리(Fault Isolation) — 3D 뷰어 장애가 실제 제어에 영향을 주지 않아야 함. ② 각 시스템의 독립적인 배포 및 업그레이드 주기 확보. ③ 3D 뷰어는 고사양 렌더링 자원이 필요하므로 별도 컴퓨팅 자원 할당이 효율적. |
| **결과(Consequences)**   | 긍정적: 제어 경로의 가용성(Availability) 보장, 시각화 레이어의 독립적 고도화 가능. 부정적: 데이터 일관성(Consistency) 관리 복잡도 증가, 중간 데이터 버스 인프라 추가 필요.                                         |
| **트레이드오프(Trade-offs)** | 얻는 장점: 높은 시스템 복원력(Resilience), 관심사 분리(SoC). 감수할 단점: 메시지 브로커 단일 장애점(SPOF) 가능성, 데이터 동기화 지연(Lag) 발생 시 3D 뷰어와 실제 상태 간 시각적 불일치.                               |

⚠️ 잠재적 위험 분석
------------

### 1. 가상-실물 환경 동기화 실패로 인한 잘못된 제어 명령 실행

* **설명:** 환경 제너레이터가 생성한 가상 환경 데이터와 실제 스마트팜 물리 환경 간 동기화가 지연되거나 끊길 경우, 가상 센서 기반으로 생성된 제어 명령이 실제 환경 상태와 불일치하여 냉난방, 관수, 차광막 등 구동기에 잘못된 제어 신호가 전달될 수 있다. 예: 실제 기온이 급등했으나 가상 센서 데이터가 구버전 값을 유지 → 냉방 미가동 → 작물 피해.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 가상 센서와 실물 센서 데이터의 실시간 편차(Deviation) 임계값 모니터링 알람 구현. 편차 초과 시 자동으로 실물 센서 우선 모드로 폴백(Fallback) 전환. 워치독(Watchdog) 타이머로 동기화 상태 주기적 점검.

* * *

### 2. 통합제어시스템 단일 장애점(SPOF)으로 인한 전체 팜 제어 불능

* **설명:** 개념도상 스마트팜 통합제어시스템이 시뮬레이션 시스템과 현장 제어를 중재하는 단일 허브 역할을 수행한다. 해당 시스템의 소프트웨어 크래시, 하드웨어 장애, 또는 네트워크 단절 발생 시 온실 내 모든 자동 제어(관수, 환기, 온도 조절 등)가 중단되어 대규모 작물 손실이 발생할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** Active-Standby 이중화 구성(HA) 적용. 로컬 PLC(Programmable Logic Controller) 수준에서 최소한의 안전 제어 로직(Safe State Logic)을 독립 실행 가능하도록 엣지 컴퓨팅 레이어 추가. 장애 시 수동 제어 전환 절차 및 운영자 교육 의무화.

* * *

### 3. 사이버 보안 취약점을 통한 제어 시스템 침해

* **설명:** 스마트팜 통합제어시스템과 시뮬레이션 시스템이 네트워크로 연결된 구조에서, 외부 공격자가 가상 센서 데이터를 위변조하거나 가상 제어로드를 통해 악의적인 제어 명령을 주입할 경우 실제 구동기(액추에이터)의 오작동을 유발할 수 있다. ICS/SCADA 시스템은 전통적으로 보안 업데이트가 느려 알려진 취약점 노출 기간이 길다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** OT/IT 네트워크 분리(에어갭 또는 DMZ 구성). 가상 센서/제어 인터페이스에 상호 인증(Mutual TLS) 및 명령 서명(Command Signing) 적용. IEC 62443(산업용 사이버보안 표준) 기반 보안 아키텍처 설계. 이상 명령 패턴 탐지를 위한 OT-IDS(침입탐지시스템) 도입.

* * *

### 4. 시뮬레이션 모델 피델리티 부족으로 인한 검증 신뢰성 저하

* **설명:** 환경 제너레이터가 생성하는 가상 환경이 실제 스마트팜의 미기후(Microclimate), 작물 증산량, 토양 수분 변화, 장비 노화 특성 등 복잡한 물리 현상을 충분히 반영하지 못할 경우, 시뮬레이션에서 검증된 제어 알고리즘이 실제 환경에서 예측과 다른 결과를 초래한다. 즉, "시뮬레이션에서는 성공, 실제에서는 실패"하는 Sim-to-Real Gap 문제가 발생한다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 물리 기반 모델(Physics-Based Model)과 데이터 기반 모델(ML 모델)의 하이브리드 시뮬레이션 엔진 구성. 실제 운영 데이터를 주기적으로 수집하여 시뮬레이션 모델 재학습(Model Update) 파이프라인 구축. 신규 제어 로직의 실제 환경 소규모 A/B 테스트 단계 의무화.

* * *

### 5. 3D 환경 뷰어 렌더링 지연으로 인한 운영자 상황 인식 오류

* **설명:** 3D 환경 뷰어가 대용량 3D 렌더링 처리 부하로 인해 실제 팜 상태를 수 초~수십 초 지연하여 표시할 경우, 관리자가 현재 상태를 오판하고 불필요한 수동 개입을 수행하거나 긴급 상황 대응이 지연될 수 있다. 특히 다수 센서 이벤트가 동시 발생하는 피크 타임에 렌더링 병목이 심화된다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 3D 뷰어에 데이터 타임스탬프 및 지연 경고 UI 상시 표시. Level-of-Detail(LOD) 렌더링 기법 적용으로 부하 감소. 긴급 알람은 3D 뷰어와 독립된 별도 알람 채널(SMS, 전광판, 경보음)로 이중화. 고성능 GPU 서버 또는 클라우드 렌더링 팜 활용 검토.

* * *

### 6. 가상 제어 명령의 실제 구동기 오적용(Shadow Mode 미분리)

* **설명:** 시뮬레이션 시스템이 "검증 모드(Shadow Mode)"와 "실제 제어 모드"를 명확히 분리하지 않을 경우, 테스트 목적으로 생성된 가상 제어 명령이 실제 구동기(펌프, 밸브, 히터 등)에 전달되는 사고가 발생할 수 있다. 개발·운영 환경 미분리, 설정 오류, 또는 운영자 실수가 트리거가 된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 시뮬레이션 출력과 실제 제어 출력 간 하드웨어적 게이트(물리적 인터록) 적용. 소프트웨어 레벨에서 실행 모드(Simulation/Production) 플래그를 이중 확인하는 Command Validation 미들웨어 구현. 운영 모드 전환 시 관리자 이중 승인(Two-Person Integrity) 절차 적용.

| **트레이드오프(Trade-offs)** | 얻는 장점: 안전한 실험 환경, 빠른 제어 로직 이터레이션, 장애 시나리오 사전 대응 훈련 가능. 감수할 단점: 가상 모델과 실제 환경 간 피델리티(Fidelity) 격차로 인한 시뮬레이션 결과 신뢰성 한계, 이중 레이어 유지보수 비용 증가, 실시간 동기화를 위한 네트워크 대역폭 및 레이턴시 요구 수준 상승.                                                         |

* * *

### ADR-002: 스마트팜 통합제어시스템과 3D 환경 뷰어의 독립 서브시스템 분리 아키텍처

| 항목                     | 내용                                                                                                                                                       |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 개념도에서 스마트팜 통합제어시스템(좌측)과 3D 환경 뷰어(우측)는 통합 환경 시뮬레이션 시스템으로부터 각각 독립적인 화살표로 데이터를 수신한다. 두 시스템은 서로 다른 사용자(현장 운영자 vs. 관리자/의사결정자)와 서로 다른 목적(제어 vs. 시각화)을 가진다.     |
| **결정(Decision)**       | 통합제어시스템(SCADA/HMI)과 3D 환경 뷰어를 별도의 독립 서브시스템으로 분리하고, 시뮬레이션 엔진으로부터 공통 데이터 버스(메시지 브로커 또는 공유 데이터 스토어)를 통해 각각 데이터를 구독하는 Pub/Sub 패턴을 적용한다.                      |
| **근거(Rationale)**      | ① 제어 시스템과 시각화 시스템의 장애 격리(Fault Isolation) — 3D 뷰어 장애가 실제 제어에 영향을 주지 않아야 함. ② 각 시스템의 독립적인 배포 및 업그레이드 주기 확보. ③ 3D 뷰어는 고사양 렌더링 자원이 필요하므로 별도 컴퓨팅 자원 할당이 효율적. |
| **결과(Consequences)**   | 긍정적: 제어 경로의 가용성(Availability) 보장, 시각화 레이어의 독립적 고도화 가능. 부정적: 데이터 일관성(Consistency) 관리 복잡도 증가, 중간 데이터 버스 인프라 추가 필요.                                         |
| **트레이드오프(Trade-offs)** | 얻는 장점: 높은 시스템 복원력(Resilience), 관심사 분리(SoC). 감수할 단점: 메시지 브로커 단일 장애점(SPOF) 가능성, 데이터 동기화 지연(Lag) 발생 시 3D 뷰어와 실제 상태 간 시각적 불일치.                               |

⚠️ 잠재적 위험 분석
------------

### 1. 가상-실물 환경 동기화 실패로 인한 잘못된 제어 명령 실행

* **설명:** 환경 제너레이터가 생성한 가상 환경 데이터와 실제 스마트팜 물리 환경 간 동기화가 지연되거나 끊길 경우, 가상 센서 기반으로 생성된 제어 명령이 실제 환경 상태와 불일치하여 냉난방, 관수, 차광막 등 구동기에 잘못된 제어 신호가 전달될 수 있다. 예: 실제 기온이 급등했으나 가상 센서 데이터가 구버전 값을 유지 → 냉방 미가동 → 작물 피해.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 가상 센서와 실물 센서 데이터의 실시간 편차(Deviation) 임계값 모니터링 알람 구현. 편차 초과 시 자동으로 실물 센서 우선 모드로 폴백(Fallback) 전환. 워치독(Watchdog) 타이머로 동기화 상태 주기적 점검.

* * *

### 2. 통합제어시스템 단일 장애점(SPOF)으로 인한 전체 팜 제어 불능

* **설명:** 개념도상 스마트팜 통합제어시스템이 시뮬레이션 시스템과 현장 제어를 중재하는 단일 허브 역할을 수행한다. 해당 시스템의 소프트웨어 크래시, 하드웨어 장애, 또는 네트워크 단절 발생 시 온실 내 모든 자동 제어(관수, 환기, 온도 조절 등)가 중단되어 대규모 작물 손실이 발생할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** Active-Standby 이중화 구성(HA) 적용. 로컬 PLC(Programmable Logic Controller) 수준에서 최소한의 안전 제어 로직(Safe State Logic)을 독립 실행 가능하도록 엣지 컴퓨팅 레이어 추가. 장애 시 수동 제어 전환 절차 및 운영자 교육 의무화.

* * *

### 3. 사이버 보안 취약점을 통한 제어 시스템 침해

* **설명:** 스마트팜 통합제어시스템과 시뮬레이션 시스템이 네트워크로 연결된 구조에서, 외부 공격자가 가상 센서 데이터를 위변조하거나 가상 제어로드를 통해 악의적인 제어 명령을 주입할 경우 실제 구동기(액추에이터)의 오작동을 유발할 수 있다. ICS/SCADA 시스템은 전통적으로 보안 업데이트가 느려 알려진 취약점 노출 기간이 길다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** OT/IT 네트워크 분리(에어갭 또는 DMZ 구성). 가상 센서/제어 인터페이스에 상호 인증(Mutual TLS) 및 명령 서명(Command Signing) 적용. IEC 62443(산업용 사이버보안 표준) 기반 보안 아키텍처 설계. 이상 명령 패턴 탐지를 위한 OT-IDS(침입탐지시스템) 도입.

* * *

### 4. 시뮬레이션 모델 피델리티 부족으로 인한 검증 신뢰성 저하

* **설명:** 환경 제너레이터가 생성하는 가상 환경이 실제 스마트팜의 미기후(Microclimate), 작물 증산량, 토양 수분 변화, 장비 노화 특성 등 복잡한 물리 현상을 충분히 반영하지 못할 경우, 시뮬레이션에서 검증된 제어 알고리즘이 실제 환경에서 예측과 다른 결과를 초래한다. 즉, "시뮬레이션에서는 성공, 실제에서는 실패"하는 Sim-to-Real Gap 문제가 발생한다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 물리 기반 모델(Physics-Based Model)과 데이터 기반 모델(ML 모델)의 하이브리드 시뮬레이션 엔진 구성. 실제 운영 데이터를 주기적으로 수집하여 시뮬레이션 모델 재학습(Model Update) 파이프라인 구축. 신규 제어 로직의 실제 환경 소규모 A/B 테스트 단계 의무화.

* * *

### 5. 3D 환경 뷰어 렌더링 지연으로 인한 운영자 상황 인식 오류

* **설명:** 3D 환경 뷰어가 대용량 3D 렌더링 처리 부하로 인해 실제 팜 상태를 수 초~수십 초 지연하여 표시할 경우, 관리자가 현재 상태를 오판하고 불필요한 수동 개입을 수행하거나 긴급 상황 대응이 지연될 수 있다. 특히 다수 센서 이벤트가 동시 발생하는 피크 타임에 렌더링 병목이 심화된다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 3D 뷰어에 데이터 타임스탬프 및 지연 경고 UI 상시 표시. Level-of-Detail(LOD) 렌더링 기법 적용으로 부하 감소. 긴급 알람은 3D 뷰어와 독립된 별도 알람 채널(SMS, 전광판, 경보음)로 이중화. 고성능 GPU 서버 또는 클라우드 렌더링 팜 활용 검토.

* * *

### 6. 가상 제어 명령의 실제 구동기 오적용(Shadow Mode 미분리)

* **설명:** 시뮬레이션 시스템이 "검증 모드(Shadow Mode)"와 "실제 제어 모드"를 명확히 분리하지 않을 경우, 테스트 목적으로 생성된 가상 제어 명령이 실제 구동기(펌프, 밸브, 히터 등)에 전달되는 사고가 발생할 수 있다. 개발·운영 환경 미분리, 설정 오류, 또는 운영자 실수가 트리거가 된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 시뮬레이션 출력과 실제 제어 출력 간 하드웨어적 게이트(물리적 인터록) 적용. 소프트웨어 레벨에서 실행 모드(Simulation/Production) 플래그를 이중 확인하는 Command Validation 미들웨어 구현. 운영 모드 전환 시 관리자 이중 승인(Two-Person Integrity) 절차 적용.
