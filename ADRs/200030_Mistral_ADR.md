📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: **다중 스캔 방식(바코드, 블루투스, Wi-Fi) 통합을 통한 기기 등록 및 서비스 연동 아키텍처**

| 항목                     | 내용                                                                                                                                                                                                                                           |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 환경에서 다양한 IoT 기기(블루투스, Wi-Fi, 바코드 등)를 효율적으로 등록하고 관리해야 하는 필요성이 있음. 사용자는 기기를 등록하고, 해당 기기가 제공하는 서비스를 확인 및 연동해야 함. 단일 스캔 방식만 지원할 경우, 호환성 및 사용 편의성이 떨어질 수 있음.                                                                                 |
| **결정(Decision)**       | **바코드 스캔, 블루투스 스캔, Wi-Fi 스캔**을 모두 지원하는 다중 스캔 방식을 채택. 각 스캔 방식은 독립적으로 동작하며, 스캔 결과로 얻은 기기 정보를 통해 **서비스 리스트를 조회**하고, 사용자는 **WebView**를 통해 해당 서비스를 연동할 수 있음.                                                                                      |
| **근거(Rationale)**      | 1) **호환성**: 블루투스/Wi-Fi를 지원하지 않는 기기도 바코드를 통해 등록 가능. 2) **사용 편의성**: 사용자가 익숙한 스캔 방식(예: QR 코드)을 사용할 수 있어 진입 장벽이 낮음. 3) **유연성**: 각 스캔 방식은 독립적으로 동작하므로, 특정 방식의 장애가 시스템 전체에 영향을 미치지 않음. 4) **스마트팜 표준**: 농업 환경에서 다양한 센서/기기가 사용되므로, 다중 등록 방식을 지원해야 함. |
| **결과(Consequences)**   | **장점**: 1) 다양한 기기 등록 가능. 2) 사용자 편의성 향상. 3) 시스템 장애 시 백업 방법 제공. **단점**: 1) 각 스캔 방식의 구현 및 유지보수 복잡성 증가. 2) 보안 취약점(예: 블루투스 스푸핑, Wi-Fi 스니핑) 노출 가능성.                                                                                                |
| **트레이드오프(Trade-offs)** | **장점**: 유연성, 호환성, 사용자 접근성. **단점**: 구현 비용 증가, 보안 리스크 관리 필요, 테스트 복잡성 증가.                                                                                                                                                                       |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. **블루투스 스푸핑 공격**

* **설명:** 공격자가 가짜 블루투스 기기를 생성하여 스캔 결과에 포함시켜, 사용자가 악성 기기를 등록하도록 유도하는 시나리오.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 1) 블루투스 기기 등록 시 **MAC 주소 검증** 및 **사전 등록된 기기 목록(화이트리스트)**과 대조. 2) 사용자에게 기기 등록 시 **추가 인증 단계**(예: PIN 입력) 요구.

* * *

### 2. **Wi-Fi 스캔 시 개인정보 유출**

* **설명:** Wi-Fi 스캔 시 nearby 네트워크의 SSID가 노출되어, 민감한 정보(예: 회사명, 위치 정보)가 유출될 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 1) 스캔 결과에서 **SSID 마스킹** 또는 암호화. 2) 사용자에게 **스캔 결과 공유 시 경고 메시지** 표시.

* * *

### 3. **바코드/QR 코드 악성 코드 주입**

* **설명:** 악성 코드가 포함된 바코드/QR 코드를 스캔할 경우, 기기 등록 시 악성 스크립트가 실행될 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟢 Low
* **대응 방안:** 1) 스캔 결과 **검증 서버**를 통해 바코드/QR 코드의 무결성 확인. 2) **SandBox 환경**에서 코드 실행 후 안전성 확인.

* * *

### 4. **서비스 연동 시 WebView 취약점**

* **설명:** WebView를 통해 외부 서비스를 연동할 경우, **XSS(Cross-Site Scripting)** 또는 **CSRF(Cross-Site Request Forgery)** 공격에 노출될 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 1) WebView에 **CSP(Content Security Policy)** 적용. 2) **HTTPS 강제 사용** 및 인증서 검증. 3) 외부 서비스 연동 시 **OAuth 2.0** 등 안전한 인증 프로토콜 사용.

* * *

### 5. **네트워크 지연으로 인한 실시간 데이터 동기화 실패**

* **설명:** Wi-Fi/블루투스 스캔 시 네트워크 지연으로 인해 기기 목록 또는 서비스 정보가 실시간으로 업데이트되지 않을 수 있음.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 1) **캐싱 메커니즘** 도입(예: 로컬 DB에 스캔 결과 임시 저장). 2) **오프라인 모드** 지원 및 동기화 실패 시 사용자에게 알림.

* * *

### 6. **기기 호환성 문제**

* **설명:** 특정 기기(예: 오래된 센서)가 블루투스 5.0 이상을 지원하지 않아 스캔 또는 연동이 실패할 수 있음.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 1) **하위 호환성 테스트** 수행. 2) 사용자에게 **호환성 가이드** 제공(예: "이 기기는 블루투스 4.0만 지원합니다").

* * *

### 7. **Data Matrix 스캔 오류**

* **설명:** Data Matrix 코드가 손상되거나 잘못 인쇄되어 스캔 실패가 빈발할 경우, 사용자 경험이 저하됨.
* **심각도:** 🟢 Low
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 1) **오류 수정 알고리즘**(Error Correction) 도입. 2) 사용자에게 **수동 입력 옵션** 제공.
