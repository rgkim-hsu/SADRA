### ADR-001: **중앙 집중식 정보 제공 서버 아키텍처 채택**

| 항목                     | 내용                                                                                                                                                                                                        |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 환경에서 실시간 모니터링 및 센서 데이터 수집이 필요하며, 다수의 사용자 기기가 동시에 접근해야 함. 시스템은 10개의 모니터링 장치, 100개의 센서 측정장치, 1개의 정보 제공 서버, 20개의 사용자 기기로 구성됨. 각 컴포넌트 간 데이터 흐름(예: 센서 → 모니터링 장치 → 정보 제공 서버 → 사용자 기기)은 실시간성과 신뢰성이 보장되어야 함. |
| **결정(Decision)**       | 정보 제공 서버를 중앙 집중식으로 구축하여 모든 센서 및 모니터링 장치의 데이터를 수집·가공·제공하는 아키텍처를 채택.                                                                                                                                        |
| **근거(Rationale)**      | 중앙 집중식 서버는 데이터 일관성, 중앙화된 관리, 및 확장성 면에서 우수. 특히 스마트팜에서 실시간 데이터 처리 및 다중 사용자 접근을 효율적으로 지원할 수 있음. 또한, 클라우드 연동을 통해 외부 접근성 및 데이터 백업이 용이함.                                                                        |
| **결과(Consequences)**   | **장점**: 데이터 중앙 관리로 인한 일관성 향상, 실시간 처리 가능, 클라우드 연동으로 인한 유연성 증가. **단점**: 서버 단일 장애 시 시스템 전체에 영향을 미칠 수 있으며, 서버 과부하 시 성능 저하 가능성 존재.                                                                             |
| **트레이드오프(Trade-offs)** | **얻는 장점**: 데이터 일관성, 중앙 관리 용이성, 클라우드 연동 가능성. **감수해야 할 단점**: 단일 장애점(Single Point of Failure) 존재, 서버 확장 시 비용 증가.                                                                                             |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. **서버 과부하로 인한 시스템 다운**

* **설명:** 정보 제공 서버(400번 포트)가 다수의 모니터링 장치(300번 포트)와 센서 측정장치(200번 포트)로부터 동시에 대량의 데이터를 수신할 경우, 서버가 과부하 상태로 진입하여 응답 지연 또는 다운 발생.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 로드 밸런서 도입 및 서버 클러스터링을 통해 트래픽 분산. 또한, 서버 리소스 모니터링 및 자동 스케일링 정책 적용.

* * *

### 2. **센서 데이터 오류 및 손실**

* **설명:** 센서 측정장치(100개)에서 오류가 발생하거나 네트워크 문제로 인해 데이터가 손실될 경우, 실시간 모니터링에 필요한 데이터가 부정확해질 수 있음.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 센서 데이터에 체크섬(Checksum) 또는 CRC( Cyclic Redundancy Check) 적용하여 데이터 무결성 검증. 또한, 로컬 버퍼링을 통해 일시적인 네트워크 장애 시 데이터 손실 방지.

* * *

### 3. **네트워크 지연으로 인한 실시간성 저하**

* **설명:** 모니터링 장치(10개)와 정보 제공 서버 간, 또는 서버와 사용자 기기(20개) 간 네트워크 지연이 발생할 경우, 실시간 모니터링 및 제어가 불가능해질 수 있음.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 네트워크 대역폭 확충 및 QoS(Quality of Service) 정책을 통해 우선순위 트래픽 처리. 또한, Edge Computing을 도입하여 로컬에서 일부 데이터 처리 수행.

* * *

### 4. **보안 취약점으로 인한 데이터 유출**

* **설명:** 정보 제공 서버가 클라우드와 연동되어 외부에서 접근 가능할 경우, 보안 취약점으로 인해 민감한 스마트팜 데이터(예: 작물 상태, 환경 데이터)가 유출될 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟢 Low
* **대응 방안:** 데이터 암호화(End-to-End Encryption) 및 접근 제어 리스트(ACL) 적용. 또한, 정기적인 보안 감사 및 패치 관리 수행.

* * *

### 5. **사용자 기기 호환성 문제**

* **설명:** 사용자 기기(20개)가 다양한 플랫폼(예: 모바일, 데스크톱)에서 접속할 경우, 호환성 문제로 인해 일부 기기에서 시스템이 정상적으로 동작하지 않을 수 있음.
* **심각도:** 🟢 Low
* **발생 가능성:** 🟡 Medium
* **대응 방안:** API 표준화 및 플랫폼 독립적인 프로토콜(예: RESTful API, WebSocket) 사용. 또한, 사용자 기기별 테스트 및 최적화 수행.
