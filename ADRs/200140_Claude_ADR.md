### ADR-001: 스마트팜 도메인 적용을 위한 분산 신원 인증(DID) 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                                                                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 생태계에는 농장주(재배자), 농산물 유통사, 인증기관(GAP·유기농), 소비자, 정부기관 등 다수의 이해관계자가 존재한다. 기존 중앙집중식 신원 체계로는 농산물 이력 데이터의 위변조, 인증서 발급 주체의 단일 장애점(SPOF), 크로스-도메인 신뢰 문제를 해결하기 어렵다. 특히 밀(소맥) 생산부터 유통까지 다단계 공급망에서 생산자 신원 및 재배 인증 정보의 무결성이 핵심 과제이다.                                                                                                                                       |
| **결정(Decision)**       | W3C DID(Decentralized Identifier) 표준 기반의 SSI(Self-Sovereign Identity) 3자 구조를 채택한다. ① **Issuer(신원정보발행자)**: 농림축산식품부·인증기관이 농장주·농산물에 대한 Verifiable Credential(VC) 발급, ② **Holder(사용자/농장주)**: DID Wallet에 VC를 자기 보관 및 선택적 제출, ③ **Verifier(서비스 제공자)**: 유통사·소비자 플랫폼이 Presentation 검증, ④ **Verifiable Data Registry**: 블록체인 기반 분산ID 저장소로 DID Document 및 VC 상태(폐기 여부) 관리. |
| **근거(Rationale)**      | 첫째, 농산물 인증(GAP, 유기농, 이력제)은 다수 발행 주체가 존재하여 분산 신뢰 모델이 필수적이다. 둘째, GDPR·개인정보보호법 준수를 위해 Holder 중심의 최소 정보 공개(Zero-Knowledge Proof 적용 가능)가 요구된다. 셋째, 스마트팜 IoT 센서 데이터(온습도, 농약 이력, 생육 데이터)와 신원 정보를 결합한 신뢰 가능한 디지털 농업 모델 구현이 가능하다.                                                                                                                                          |
| **결과(Consequences)**   | **긍정적**: 농산물 이력 위변조 방지, 인증기관 간 상호운용성 확보, 소비자 신뢰도 향상, 수출 농산물 해외 검증 가능. **부정적**: 스마트팜 현장 농장주의 DID Wallet 운용 기술 역량 부족, 블록체인 네트워크 인프라 운영 비용 발생, 기존 농산물 이력 시스템과의 레거시 통합 복잡도 증가.                                                                                                                                                                                        |
| **트레이드오프(Trade-offs)** | **얻는 것**: 탈중앙화 신뢰, 데이터 주권, 단일 장애점 제거, 감사 추적성. **감수할 것**: 초기 구축 비용 증가(블록체인 노드 운영), UX 복잡성(농장주 디지털 리터러시 요구), 트랜잭션 처리 지연(On-chain 검증 시 수 초 소요), 표준 미성숙에 따른 상호운용성 불확실성.                                                                                                                                                                                               |

### ADR-002: 스마트팜 IoT 엣지 노드와 DID 연동을 위한 경량 VC 검증 레이어 도입

| 항목                     | 내용                                                                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 현장의 IoT 게이트웨이(라즈베리파이, ARM 기반 엣지 디바이스)는 연산 자원이 제한적이며, 농촌 지역 특성상 간헐적 네트워크 환경에서 동작한다. 센서 데이터 수집 주체(디바이스)에 대한 신원 인증 없이는 데이터 무결성을 보장할 수 없다.                         |
| **결정(Decision)**       | IoT 디바이스에 경량 DID(did:key 또는 did:web) 방식을 부여하고, 오프라인 VC 캐싱 및 로컬 서명 검증을 지원하는 엣지 검증 레이어를 구성한다. 클라우드 연결 시 Verifiable Data Registry와 동기화하여 폐기 목록(Revocation List)을 갱신한다. |
| **근거(Rationale)**      | 농촌 현장의 불안정한 네트워크에서도 센서 데이터의 신원 바인딩이 가능해야 하며, 엣지에서의 로컬 검증으로 레이턴시를 최소화하고 데이터 신뢰성을 확보할 수 있다.                                                                           |
| **결과(Consequences)**   | **긍정적**: 오프라인 환경에서도 데이터 무결성 보장, IoT-to-Cloud 데이터 파이프라인의 신뢰성 향상. **부정적**: 엣지 디바이스 펌웨어 업데이트 및 키 관리 복잡성 증가.                                                            |
| **트레이드오프(Trade-offs)** | **얻는 것**: 네트워크 독립적 인증, 실시간 데이터 신뢰성. **감수할 것**: 엣지 디바이스 보안 키 탈취 위험, 동기화 지연 구간의 폐기 정보 불일치 가능성.                                                                        |

⚠️ 잠재적 위험 분석
------------

### 1. Verifiable Data Registry 단일 블록체인 의존에 따른 가용성 위험

* **설명:** 분산ID 저장소로 채택한 블록체인 네트워크가 51% 공격, 노드 과반 장애, 또는 거버넌스 분쟁으로 인해 서비스 중단될 경우, 전체 스마트팜 인증 체계(농산물 이력 조회, 유통 검증)가 일시에 마비된다. 특히 수확기·출하기 등 트래픽 집중 시점에 발생 시 피해가 극대화된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 멀티체인 또는 앵커링(Anchoring) 방식 도입(메인 블록체인 + 백업 레지스트리 이중화), 오프체인 캐싱 레이어(Redis/IPFS) 구성으로 단기 장애 시 서비스 연속성 확보, SLA 기반 블록체인 네트워크 운영 계약 체결.

### 2. 농장주(Holder) DID Wallet 키 분실 및 복구 불가 위험

* **설명:** 스마트팜 농장주가 DID Wallet의 개인키를 분실하거나 디바이스 파손 시, SSI 구조 특성상 중앙 복구 기관이 없어 발행된 모든 VC(농산물 인증서, 재배이력 자격증명)에 접근이 영구 차단된다. 농번기 중 발생 시 출하 인증이 불가능해져 직접적 경제 손실로 이어진다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 사회적 복구(Social Recovery) 메커니즘 도입(농협·지역 농업기술센터를 Guardian으로 지정), 하드웨어 보안 모듈(HSM) 또는 생체인증 기반 키 백업, 농장주 대상 디지털 리터러시 교육 의무화 및 키 관리 매뉴얼 배포.

### 3. Issuer 기관의 악의적·실수에 의한 허위 VC 발급 위험

* **설명:** 신원정보발행자(Issuer) 역할을 수행하는 인증기관 또는 정부기관 내부자가 실제 검사를 수행하지 않고 유기농·GAP 인증 VC를 허위 발급하거나, 시스템 취약점을 통해 인증 발급 프로세스가 우회될 경우, 블록체인에 기록된 이후에는 데이터의 내용 자체를 무효화하기 어렵다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** VC 발급 프로세스에 다중 서명(Multi-sig) 요구(발급 담당자 + 감독자 이중 승인), IoT 센서 데이터(토양·농약 잔류량 측정값)와 VC 발급 조건을 자동 연동하는 스마트 컨트랙트 도입, Issuer 기관에 대한 정기 외부 감사 및 발급 로그 모니터링 체계 구축.

### 4. Verifier(서비스 제공자) 과도한 개인정보 수집에 따른 프라이버시 침해 위험

* **설명:** 유통사·소비자 플랫폼(Verifier)이 Presentation 검증 과정에서 농장주의 신원 정보(이름, 농장 위치, 재배 면적 등) 전체를 요구하고 저장함으로써, 개인정보보호법 위반 및 농장주 개인정보 집중·유출 위험이 발생한다. 특히 해외 수출 플랫폼의 경우 GDPR 위반 리스크도 존재한다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 선택적 공개(Selective Disclosure) 및 영지식 증명(Zero-Knowledge Proof) 기반 VC 설계 적용(예: "유기농 인증 여부"만 증명, 농장 위치 미공개), Verifier 등록제 도입 및 정보 요청 범위 제한 정책 수립, 개인정보 영향평가(PIA) 정기 수행.

### 5. 스마트팜 IoT 센서 데이터 위변조 및 DID 바인딩 불일치 위험

* **설명:** 농장 현장에서 수집되는 온습도, 토양 성분, 농약 살포 이력 데이터가 IoT 게이트웨이와 클라우드 전송 구간에서 중간자 공격(MITM) 또는 게이트웨이 물리적 조작으로 위변조될 경우, DID로 신원이 인증된 주체가 생성한 데이터임에도 내용 자체의 신뢰성이 훼손된다. VC에 바인딩된 재배 데이터와 실제 현장 데이터 간 불일치가 발생한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** IoT 디바이스 단에서 데이터 생성 즉시 디바이스 DID 개인키로 서명(Data Provenance) 후 전송, TLS 1.3 + 상호 인증(mTLS) 적용으로 전송 구간 보호, 물리적 탬퍼-이비던트(Tamper-evident) 센서 하우징 적용, 이상 데이터 패턴 자동 탐지 AI 모니터링 레이어 구성.

### 6. 레거시 농산물 이력관리 시스템과의 상호운용성 단절 위험

* **설명:** 국립농산물품질관리원의 기존 농산물 이력관리 시스템, 농협 ERP 등 레거시 중앙집중식 플랫폼과 DID 기반 신규 시스템 간 데이터 표준·프로토콜 불일치로 인해 이중 입력, 데이터 단절, 연동 실패가 발생할 수 있다. 전환 기간 중 이중 운영에 따른 행정 부담과 오류 발생 가능성이 높다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** DID-to-레거시 브릿지 API 게이트웨이 설계(VC ↔ 기존 인증서 포맷 변환 레이어), W3C VC Data Model 2.0 및 국내 DID 표준(TTAK.KO-12.0292) 준수, 단계적 마이그레이션 로드맵(파일럿 농장 선정 → 지역 확산 → 전국 전환) 수립 및 레거시 시스템 병행 운영 기간 최소화.

### ADR-002: 스마트팜 IoT 엣지 노드와 DID 연동을 위한 경량 VC 검증 레이어 도입

| **상황(Context)**        | 스마트팜 현장의 IoT 게이트웨이(라즈베리파이, ARM 기반 엣지 디바이스)는 연산 자원이 제한적이며, 농촌 지역 특성상 간헐적 네트워크 환경에서 동작한다. 센서 데이터 수집 주체(디바이스)에 대한 신원 인증 없이는 데이터 무결성을 보장할 수 없다.                         |
| **결정(Decision)**       | IoT 디바이스에 경량 DID(did:key 또는 did:web) 방식을 부여하고, 오프라인 VC 캐싱 및 로컬 서명 검증을 지원하는 엣지 검증 레이어를 구성한다. 클라우드 연결 시 Verifiable Data Registry와 동기화하여 폐기 목록(Revocation List)을 갱신한다. |
| **근거(Rationale)**      | 농촌 현장의 불안정한 네트워크에서도 센서 데이터의 신원 바인딩이 가능해야 하며, 엣지에서의 로컬 검증으로 레이턴시를 최소화하고 데이터 신뢰성을 확보할 수 있다.                                                                           |
| **결과(Consequences)**   | **긍정적**: 오프라인 환경에서도 데이터 무결성 보장, IoT-to-Cloud 데이터 파이프라인의 신뢰성 향상. **부정적**: 엣지 디바이스 펌웨어 업데이트 및 키 관리 복잡성 증가.                                                            |
| **트레이드오프(Trade-offs)** | **얻는 것**: 네트워크 독립적 인증, 실시간 데이터 신뢰성. **감수할 것**: 엣지 디바이스 보안 키 탈취 위험, 동기화 지연 구간의 폐기 정보 불일치 가능성.                                                                        |

⚠️ 잠재적 위험 분석
------------

### 1. Verifiable Data Registry 단일 블록체인 의존에 따른 가용성 위험

* **설명:** 분산ID 저장소로 채택한 블록체인 네트워크가 51% 공격, 노드 과반 장애, 또는 거버넌스 분쟁으로 인해 서비스 중단될 경우, 전체 스마트팜 인증 체계(농산물 이력 조회, 유통 검증)가 일시에 마비된다. 특히 수확기·출하기 등 트래픽 집중 시점에 발생 시 피해가 극대화된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 멀티체인 또는 앵커링(Anchoring) 방식 도입(메인 블록체인 + 백업 레지스트리 이중화), 오프체인 캐싱 레이어(Redis/IPFS) 구성으로 단기 장애 시 서비스 연속성 확보, SLA 기반 블록체인 네트워크 운영 계약 체결.

### 2. 농장주(Holder) DID Wallet 키 분실 및 복구 불가 위험

* **설명:** 스마트팜 농장주가 DID Wallet의 개인키를 분실하거나 디바이스 파손 시, SSI 구조 특성상 중앙 복구 기관이 없어 발행된 모든 VC(농산물 인증서, 재배이력 자격증명)에 접근이 영구 차단된다. 농번기 중 발생 시 출하 인증이 불가능해져 직접적 경제 손실로 이어진다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 사회적 복구(Social Recovery) 메커니즘 도입(농협·지역 농업기술센터를 Guardian으로 지정), 하드웨어 보안 모듈(HSM) 또는 생체인증 기반 키 백업, 농장주 대상 디지털 리터러시 교육 의무화 및 키 관리 매뉴얼 배포.

### 3. Issuer 기관의 악의적·실수에 의한 허위 VC 발급 위험

* **설명:** 신원정보발행자(Issuer) 역할을 수행하는 인증기관 또는 정부기관 내부자가 실제 검사를 수행하지 않고 유기농·GAP 인증 VC를 허위 발급하거나, 시스템 취약점을 통해 인증 발급 프로세스가 우회될 경우, 블록체인에 기록된 이후에는 데이터의 내용 자체를 무효화하기 어렵다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** VC 발급 프로세스에 다중 서명(Multi-sig) 요구(발급 담당자 + 감독자 이중 승인), IoT 센서 데이터(토양·농약 잔류량 측정값)와 VC 발급 조건을 자동 연동하는 스마트 컨트랙트 도입, Issuer 기관에 대한 정기 외부 감사 및 발급 로그 모니터링 체계 구축.

### 4. Verifier(서비스 제공자) 과도한 개인정보 수집에 따른 프라이버시 침해 위험

* **설명:** 유통사·소비자 플랫폼(Verifier)이 Presentation 검증 과정에서 농장주의 신원 정보(이름, 농장 위치, 재배 면적 등) 전체를 요구하고 저장함으로써, 개인정보보호법 위반 및 농장주 개인정보 집중·유출 위험이 발생한다. 특히 해외 수출 플랫폼의 경우 GDPR 위반 리스크도 존재한다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 선택적 공개(Selective Disclosure) 및 영지식 증명(Zero-Knowledge Proof) 기반 VC 설계 적용(예: "유기농 인증 여부"만 증명, 농장 위치 미공개), Verifier 등록제 도입 및 정보 요청 범위 제한 정책 수립, 개인정보 영향평가(PIA) 정기 수행.

### 5. 스마트팜 IoT 센서 데이터 위변조 및 DID 바인딩 불일치 위험

* **설명:** 농장 현장에서 수집되는 온습도, 토양 성분, 농약 살포 이력 데이터가 IoT 게이트웨이와 클라우드 전송 구간에서 중간자 공격(MITM) 또는 게이트웨이 물리적 조작으로 위변조될 경우, DID로 신원이 인증된 주체가 생성한 데이터임에도 내용 자체의 신뢰성이 훼손된다. VC에 바인딩된 재배 데이터와 실제 현장 데이터 간 불일치가 발생한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** IoT 디바이스 단에서 데이터 생성 즉시 디바이스 DID 개인키로 서명(Data Provenance) 후 전송, TLS 1.3 + 상호 인증(mTLS) 적용으로 전송 구간 보호, 물리적 탬퍼-이비던트(Tamper-evident) 센서 하우징 적용, 이상 데이터 패턴 자동 탐지 AI 모니터링 레이어 구성.

### 6. 레거시 농산물 이력관리 시스템과의 상호운용성 단절 위험

* **설명:** 국립농산물품질관리원의 기존 농산물 이력관리 시스템, 농협 ERP 등 레거시 중앙집중식 플랫폼과 DID 기반 신규 시스템 간 데이터 표준·프로토콜 불일치로 인해 이중 입력, 데이터 단절, 연동 실패가 발생할 수 있다. 전환 기간 중 이중 운영에 따른 행정 부담과 오류 발생 가능성이 높다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** DID-to-레거시 브릿지 API 게이트웨이 설계(VC ↔ 기존 인증서 포맷 변환 레이어), W3C VC Data Model 2.0 및 국내 DID 표준(TTAK.KO-12.0292) 준수, 단계적 마이그레이션 로드맵(파일럿 농장 선정 → 지역 확산 → 전국 전환) 수립 및 레거시 시스템 병행 운영 기간 최소화.
