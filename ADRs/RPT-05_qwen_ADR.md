## 📋 ADR (Architecture Decision Record)

### ADR-001: 중앙집중식 데이터 품질 관리 파이프라인 구축

| 항목 | 내용 |
|------|------|
| **상황 (Context)** | 축종별 생체 데이터의 신뢰성을 확보하기 위해서는 원본 데이터부터 AI 학습까지의 전 과정(획득, 정제, 라벨링)에서 일관된 품질 기준이 필수적입니다. 단순한 데이터 수집을 넘어, 데이터의 정확성이 AI 모델의 성능과 직결되므로 프로세스별 품질 관리가 필요합니다. |
| **결정 (Decision)** | 데이터를 '획득' -> '정제' -> '라벨링' -> 'AI 모델 개발'의 선형적인 품질 관리 파이프라인으로 구성하며, 각 단계마다 엄격한 품질 체크 포인트를 설정합니다. |
| **근거 (Rationale)** | 이미지 내 상단 '국축프로세스 품질관리' 영역이 이를 명확히 보여줍니다. 초기 데이터 잡음이 AI 학습 오류로 이어질 수 있으므로, 각 단계마다 '가이드라인 적용'과 '외부 전문가 점검'을 통해 품질을 보장해야 합니다. |
| **결과 (Consequences)** | **긍정적:** AI 모델의 정확도가 크게 향상되며, downstream(사용자 품질관리)의 데이터 신뢰도가 높아집니다.<br>**부정적:** 추가적인 품질 관리 단계로 인한 프로세스 지연 및 운영 비용 증가 가능성. |
| **트레이드오프 (Trade-offs)** | 데이터 처리 속도를 높이기 위한 자동화 도입은 정밀도를 일부 희생할 수 있으므로, 핵심 단계(라벨링 등)는 수동/반자동으로 유지합니다. |

### ADR-002: 하이브리드 운영 및 외부 자원의 통합 (아웃소싱 포함)

| 항목 | 내용 |
|------|------|
| **상황 (Context)** | 방대한 양의 축산 데이터(원시데이터, 원격데이터 등)를 처리해야 하므로 내부 리소스만으로는 처리가 어렵습니다. 특히 '데이터 라벨링'이나 '외주관리' 영역은 비용 대비 효율을 위해 외부 자원을 활용해야 합니다. |
| **결정 (Decision)** | 데이터 전처리 및 라벨링 일부를 외부 관리 (외주관리) 로 위임하되, 내부 '데이터 품질관리' 모듈을 통해 항상 통제 가능한 수준으로 감시합니다. |
| **근거 (Rationale)** | 이미지 중앙에 위치한 '외주관리' 박스는 '가이드라인 적용'을 통해 내부 프로세스와 연동됩니다. 이는 TTA 및 ISO/IEC 표준에서 언급되는 상호운용성 및 확장성 요구사항을 충족시키기 위한 전략입니다. |
| **결과 (Consequences)** | **긍정적:** 처리 능력 확장 및 개발 인력 절감.<br>**부정적:** 외부 업체 간 보안 리스크 증가 및 데이터 유출 가능성. |
| **트레이드오프 (Trade-offs)** | 외부 의존도를 줄이기 위해 내부 핵심 코드 및 데이터 로직은 암호화 및 격리된 환경(VPC 등) 에 구축합니다. |

### ADR-003: 데이터 자산화 및 API 중심의 사용자 품질 관리 체계

| 항목 | 내용 |
|------|------|
| **상황 (Context)** | 단순한 데이터 축적을 넘어, 개발된 AI 모델과 데이터 자체를 자산으로 활용해야 합니다. 개발된 모델을 실제 사용자가 이용할 수 있어야 하며, 그 품질을 모니터링해야 합니다. |
| **결정 (Decision)** | 최종 단계인 '사용자 품질관리' 영역을 구축하여, 개발된 모델을 '데이터 자산(APIs)' 형태로 표준화하고, 사용자에게 제공되는 서비스(기술 리포트, 레이어 등) 의 품질을 관리합니다. |
| **근거 (Rationale)** | 이미지 우측 '사용자 품질관리' 영역은 '데이터 자산 (APIs)'과 'AI 응용 모델'로 출력됩니다. 이는 표준 문서에서 언급된 oneM2M 및 ISO/IEC 30141의 상호운용성 개념과 일치하며, 표준화된 API를 통해 다양한 사용자 시나리오에 유연하게 대응할 수 있습니다. |
| **결과 (Consequences)** | **긍정적:** 서비스의 확장성이 증가하고, 사용자 경험이 일관성을 유지합니다.<br>**부정적:** API 버전 관리 및 호환성 유지에 대한 지속적인 노력이 필요합니다. |
| **트레이드오프 (Trade-offs)** | API 문서를 상세히 작성해야 하므로 초기 개발 시간이 소모될 수 있으나, 이는 장기적인 유지보수 비용을 절감합니다. |

## ⚠️ 잠재적 위험 분석

### 1. [데이터 라벨링 편향성 (Labeling Bias)]
- **설명:** 수동으로 수행되는 '데이터 라벨링' 과정에서 작업자의 주관이나 피로도 때문에 데이터에 편향성이 발생하면, 개발된 AI 모델이 특정 상황이나 특정 가축만 잘 인식하는 오류(모델 편향)를 겪을 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 라벨링 가이드라인을 명확히 정립하고, 다수의 작업자가 중복 검수(Annotation Review) 하는 과정을 도입하여 편향을 최소화합니다. 또한, AI 라벨러 (자동 라벨링 도구) 를 병행하여 객관성을 높입니다.

### 2. [외주 데이터 유출 (Data Leakage in Outsourcing)]
- **설명:** '외주관리' 및 '데이터 정제/라벨링' 과정에 외부 인력이 참여하게 되므로, 민감한 축산 데이터 (가축 식별번호, 건강 데이터 등) 가 외부로 유출될 위험이 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 외부 업체와 체결하는 NDA 및 보안 협약을 강화하고, 모든 외부 작업 환경에 DLP(데이터 유출 방지) 솔루션과 접근 로그 기록 시스템을 의무화합니다.

### 3. [원시 데이터의 양 및 품질 저하 (Data Overload & Degradation)]
- **설명:** IoT 센서나 카메라 등에서 '원시데이터'가 계속 유입될수록 저장 비용과 처리 부하가 증가합니다. 또한 노후화된 센서의 노이즈가 '원시데이터'로 포함될 경우, '정제' 단계의 부하가 급증합니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** Edge 에서 일부 필터링을 적용하거나, 압축 및 샘플링 알고리즘을 적용하여 유입 데이터 양을 최적화합니다. 노이즈 제거 알고리즘을 지속적으로 업데이트합니다.

### 4. [AI 모델의 개념 부동 (Concept Drift)]
- **설명:** 계절, 계절성 질병, 기후 변화 등으로 인해 축환경이 변하는데, AI 모델이 학습된 과거 데이터 분포와 달라져 예측 정확도가 떨어질 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 지속적인 모니터링 (Continuous Monitoring) 을 통해 모델 정확도가 떨어지면 학습 데이터를 재구성하고 모델을 재학습 (Re-training) 하는 전략을 수립합니다.

### 5. [시스템 통합 복잡성 (Integration Complexity)]
- **설명:** '국축프로세스 품질관리', '사용자 품질관리', '데이터 품질관리' 및 '외주관리' 등 여러 하위 시스템이 연동되므로, 시스템 간 API 호환성 문제 및 통신 지연이 발생할 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low
- **대응 방안:** 표준화된 API Gateway 를 사용하여 모든 내부/외부 시스템이 표준 인터페이스만 사용하면 통합 복잡성을 줄입니다. 메시지 큐 (Kafka 등) 를 사용하여 비동기 처리로 버스트 트래픽을 흡수합니다.
