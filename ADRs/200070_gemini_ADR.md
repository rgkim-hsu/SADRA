# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 클라우드 기반의 폐쇄 루프(Closed-loop) 제어 아키텍처 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 운영 시 센싱 데이터의 실시간 수집, 분석, 제어 프로세스가 파편화될 경우 작물의 생육 환경을 최적화하기 어렵고, 데이터 통합 관리가 불가능한 과제가 존재함. |
| **결정(Decision)** | **Smart sensing & Monitoring**, **Smart analysis & Planning**, **Smart Control**의 3단계 사이클을 **Cloud-based event and data management** 허브를 통해 통합 운영하는 폐쇄 루프 아키텍처를 채택함. |
| **근거(Rationale)** | 6차 산업으로의 확장을 위해 단순 자동화를 넘어 데이터 기반의 의존적 의사결정이 필요하며, 클라우드 중앙 집중식 관리를 통해 대규모 농가 및 다수의 지점을 효율적으로 오케스트레이션하기 위함. |
| **결과(Consequences)** | **(긍정)** 데이터의 일관성 확보, 분석 결과에 따른 정밀 제어 가능, 원격 모니터링 및 업데이트 용이성 확보. **(부정)** 클라우드 의존도 심화로 인한 네트워크 가용성 리스크 발생. |
| **트레이드오프(Trade-offs)** | 초기 구축 비용과 클라우드 운영 비용이 증가하나, 데이터의 확장성과 분석의 정밀도를 통해 장기적인 생산성 향상 및 6차 산업 비즈니스 모델(서비스화) 전환의 유연성을 얻음. |

---

## ⚠️ 잠재적 위험 분석

### 1. 클라우드 연결성 장애에 따른 제어 공백
- **설명:** 네트워크 장애로 인해 클라우드(Cloud-based management)와 현장 제어기(Smart Control) 간의 통신이 단절될 경우, 실시간 환경 제어가 중단되어 작물 피해가 발생할 수 있는 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 에지 컴퓨팅(Edge Computing) 기술을 도입하여 로컬 환경에서 최소한의 필수 제어 기능을 독립적으로 수행할 수 있는 Fail-safe 메커니즘 구축.

### 2. 센서 데이터 정합성 및 신뢰도 저하
- **설명:** Smart sensing 단계에서 노후화되거나 오염된 센서로부터 수집된 잘못된 데이터가 클라우드로 전송되어, 결과적으로 잘못된 분석(Smart analysis)과 오작동(Smart Control)을 유발하는 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 데이터 이상치 탐지(Outlier Detection) 알고리즘을 분석 단계에 적용하고, 주기적인 센서 보정(Calibration) 스케줄 관리 시스템 운영.

### 3. 클라우드 중앙 집중화에 따른 보안 위협
- **설명:** 클라우드 허브가 사이버 공격을 받을 경우 연동된 모든 스마트팜의 제어권이 탈취되거나 대규모 영농 데이터가 유출되는 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 종단 간 암호화(E2EE), 다요소 인증(MFA) 적용 및 클라우드 인프라에 대한 정기적인 침투 테스트와 침입 탐지 시스템(IDS/IPS) 강화.

### 4. 이벤트 폭주로 인한 분석 병목 현상
- **설명:** 기상 이변 등 특정 상황에서 수많은 센서로부터 이벤트 데이터가 클라우드로 급증할 때, Smart analysis 단계의 처리 속도가 지연되어 실시간 제어 타이밍을 놓치는 시나리오.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 클라우드 네이티브의 오토스케일링(Auto-scaling) 기능을 활성화하고, 메시지 큐(Message Queue)를 활용한 비동기 데이터 처리 아키텍처 최적화.

### 5. 데이터 처리 및 제어 로직의 동기화 불일치
- **설명:** 분석 시스템(Planning)에서 내린 명령과 실제 현장(Control)의 물리적 상태 사이의 시차(Latency)로 인해 중복 제어가 발생하거나 시스템 상태 정보가 불일치하는 시나리오.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 분산 트랜잭션 관리 및 상태 기반 제어(State-based control) 방식을 채택하여 각 컴포넌트 간의 최종 일관성(Eventual Consistency)을 보장.
