# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 분산 원장 기반의 거래 내역 무결성 보장 아키텍처 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 사용자 간의 거래 내역(93)이 발생할 때, 중앙 집중형 서버의 데이터 위변조 위험을 방지하고 다수의 참여자가 동일한 데이터를 공유하며 신뢰성을 확보해야 하는 과제에 직면함. |
| **결정(Decision)** | 피어 투 피어(P2P) 네트워크 형태의 블록체인 네트워크(300)를 구축하고, 각 노드(310)가 독립적인 원장을 보유하며 합의 알고리즘을 통해 데이터를 동기화하는 구조를 채택함. |
| **근거(Rationale)** | 단일 장애점(SPOF)을 제거하고, 블록 단위의 체이닝 구조를 통해 거래 내역의 가시성과 비가역적인 무결성을 기술적으로 강제하기 위함임. |
| **결과(Consequences)** | 거래 내역의 투명한 추적이 가능해지며 시스템의 가용성이 높아지나, 모든 노드에 데이터를 복제함에 따라 저장 공간의 효율성이 저하될 수 있음. |
| **트레이드오프(Trade-offs)** | 데이터의 즉각적인 정합성(Strong Consistency)보다는 최종 합의를 통한 가용성과 분할 내성(Partition Tolerance)을 우선시함. |

---

## ⚠️ 잠재적 위험 분석

### 1. 합의 지연 및 확장성(Scalability) 문제
- **설명:** 네트워크 참여 노드(310)가 급격히 증가하거나 거래 내역(93) 처리가 몰릴 경우, 합의 도달 시간이 길어져 전체 시스템의 트랜잭션 처리량(TPS)이 저하되는 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 샤딩(Sharding) 기술 적용 또는 레이어 2(L2) 솔루션을 도입하여 연산 부하를 분산함.

### 2. 51% 공격을 통한 데이터 위변조 위험
- **설명:** 특정 집단이 전체 네트워크 컴퓨팅 파워나 지분의 과반수 이상을 점유하여 악의적으로 거래 내역을 조작하거나 특정 거래를 승인 거부하는 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 노드 참여 자격을 검증하는 Permissioned 기반의 프라이빗/컨소시엄 블록체인을 구성하고 거버넌스 정책을 강화함.

### 3. 노드 간 데이터 동기화 불일치
- **설명:** 네트워크 통신 장애나 지연으로 인해 특정 노드의 블록(310) 높이가 다른 노드와 차이가 발생하여 일시적인 포크(Fork) 현상이 일어나는 시나리오.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 고성능 네트워크 백본을 확보하고, 동기화 오류 발생 시 즉각적인 복구를 수행하는 자동 헬스체크 및 재동기화 로직 구현.

### 4. 개인정보 보호 및 데이터 삭제 불가 위험
- **설명:** 블록체인의 비가역성 특성으로 인해 거래 내역(93)에 포함된 민감 정보가 영구 보존되어 법적 규제(GDPR 등)의 '잊혀질 권리'를 위반하게 되는 시나리오.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 실제 데이터는 오프체인(Off-chain)에 저장하고 블록체인에는 해당 데이터의 해시값만 기록하는 방식(Hashed Storage)을 채택함.

### 5. 스마트 컨트랙트 및 코드 취약점 노출
- **설명:** 거래를 처리하는 로직(스마트 컨트랙트 등)에 논리적 결함이 있을 경우, 배포 후 수정이 어려워 대규모 자산 유출이나 시스템 마비가 발생하는 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 배포 전 전문 보안 업체를 통한 코드 오딧(Audit)을 필수화하고, 샌드박스 환경에서 충분한 리그레션 테스트를 수행함.
