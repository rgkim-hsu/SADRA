📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 스마트팜 AI 학습 데이터 파이프라인의 품질 이중 관리 계층 도입

| 항목                     | 내용                                                                                                                                                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 도메인에서 AI 모델의 정확도는 센서 데이터(온습도, CO₂, 일조량 등)의 품질에 직결된다. 본 시스템은 데이터 획득 → 정제 → 라벨링 → AI 모델 개발 → 데이터 적재(AI허브)의 선형 파이프라인을 구성하며, 외주 라벨링 작업자가 개입하는 구조다. 외주 품질 편차와 원시 데이터의 노이즈가 동시에 존재하여, 단일 검수 지점만으로는 하류(downstream) AI 모델의 성능 보장이 불가능한 상황이다. |
| **결정(Decision)**       | 구축프로세스 품질관리(상위 레이어)와 데이터 품질관리(하위 레이어)를 이중 계층으로 분리하고, 외주 작업자에게는 정제 및 라벨링 단계에서만 가이드라인을 제공하는 제한적 접근 구조를 채택한다. 데이터 검수는 독립 노드로 분리하여 라벨링 완료 후 AI 모델 개발 전 단계에 위치시킨다.                                                                             |
| **근거(Rationale)**      | 스마트팜 데이터는 계절·품종·재배 환경별 도메인 특수성이 높아 범용 품질 기준 적용이 어렵다. 이중 계층 분리를 통해 원시→원천→라벨링 데이터의 계보(lineage)를 추적하고, 외주 오염이 상위 파이프라인으로 역전파되는 것을 방지한다. 또한 AI허브 제출 기준(국내 공공 AI 데이터셋 표준)을 충족하기 위해 독립 검수 노드가 필수적이다.                                            |
| **결과(Consequences)**   | ✅ 긍정적: 외주 라벨링 오류의 격리, 데이터 계보 추적 가능, AI허브 납품 품질 기준 충족 가능성 향상. ❌ 부정적: 검수 병목으로 인한 파이프라인 지연, 이중 관리 레이어에 따른 운영 복잡도 증가, 품질관리 인력 추가 소요.                                                                                                          |
| **트레이드오프(Trade-offs)** | **얻는 것:** 모델 학습 데이터 신뢰성, 외주 리스크 격리, 감사 추적성(Auditability). **감수할 것:** 파이프라인 처리 속도 저하(검수 단계 대기), 두 레이어 간 기준 불일치 발생 시 의사결정 지연, 외주 관리 오버헤드 증가.                                                                                                |

* * *

### ADR-002: 학습용 데이터셋을 원천+라벨링 복합 구조로 구성하고 AI허브 단일 적재 엔드포인트 채택

| 항목                     | 내용                                                                                                                                                         |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 AI 모델(작물 생육 예측, 병해충 탐지 등)은 정형(센서 시계열) + 비정형(이미지) 복합 데이터를 요구한다. 라벨링 데이터만 적재할 경우 원천 데이터 소실로 재학습 시 추적 불가 문제가 발생하며, AI허브 외부에 별도 스토리지를 운용하면 이중 관리 부담이 생긴다. |
| **결정(Decision)**       | 학습용 데이터셋을 '원천데이터 + 라벨링데이터'의 복합 패키지로 구성하고, AI허브를 유일한 최종 적재 엔드포인트로 지정한다. 테크니컬 리포트, 활용가이드라인, 메뉴얼을 AI 응용모델과 함께 패키징하여 배포한다.                                     |
| **근거(Rationale)**      | 국내 AI 학습용 데이터 구축사업(NIA 기준) 납품 요건상 원천-라벨 연계 패키지 제출이 의무화되어 있다. 단일 적재 엔드포인트는 데이터 버전 관리 단순화, 외부 접근 제어 집중화에 유리하다.                                               |
| **결과(Consequences)**   | ✅ 긍정적: 데이터 재현성 보장, 규정 준수, 외부 활용자의 모델 재현 가능. ❌ 부정적: AI허브 의존성 집중, 적재 포맷 변경 시 전체 파이프라인 영향.                                                                    |
| **트레이드오프(Trade-offs)** | **얻는 것:** 단일 진실 공급원(Single Source of Truth), 배포 일관성. **감수할 것:** AI허브 서비스 장애 시 전체 납품 불가, 플랫폼 종속(Vendor Lock-in) 위험.                                         |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. 외주 라벨링 품질 불균일에 의한 모델 성능 저하

* **설명:** 외주 작업자에게 가이드라인만 제공하고 실시간 모니터링이 없을 경우, 스마트팜 특화 라벨(예: 작물 생육 단계, 병해 등급)의 해석 편차가 발생한다. 검수 단계에서 대량 반려가 발생하면 납기 지연 및 재작업 비용이 급증한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 외주 착수 전 도메인 전문가 주도의 라벨링 가이드라인 사전 검증(파일럿 배치 운영), 작업자별 Inter-Annotator Agreement(IAA) 지표 측정 및 임계값 미달 시 즉시 재교육 프로세스 수립. 자동화 품질 스크리닝(규칙 기반 사전 필터)을 검수 전단에 배치.

* * *

### 2. 데이터 파이프라인 단일 장애점(Single Point of Failure) — AI허브 적재 엔드포인트

* **설명:** 모든 최종 데이터가 AI허브 단일 경로로 집중되어 있어, AI허브 서비스 점검·장애·정책 변경 시 전체 납품 및 모델 서빙이 중단된다. 특히 스마트팜 현장의 실시간 모델 추론(AI허브 연계) 중단은 재배 의사결정 공백으로 이어진다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** AI허브 외 보조 스토리지(On-premise 또는 민간 클라우드 Object Storage)에 동기 복제 구성. 적재 API의 장애 감지 및 자동 재시도(Retry with Exponential Backoff) 로직 구현. 서비스 수준 협약(SLA) 명문화 및 장애 대응 Runbook 작성.

* * *

### 3. 원시 데이터 수집 단계의 스마트팜 센서 노이즈 및 결측 처리 미흡

* **설명:** 스마트팜 IoT 센서(온도, 습도, EC, pH 등)는 네트워크 단절, 센서 고장, 계절적 이상값으로 인한 결측·이상 데이터를 빈번히 생성한다. 데이터 정제 단계에서 이를 적절히 처리하지 않으면, 이후 라벨링과 AI 모델 학습 전체에 편향이 전파된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 도메인 기반 이상값 탐지 규칙(예: 온도 -10°C 이하 플래그 처리) 및 시계열 보간(interpolation) 정책을 데이터 정제 단계에 표준화. 결측률 임계값(예: 30% 초과 시 해당 세션 폐기) 정의. 원시→원천 데이터 전환 시 품질 메타데이터(결측률, 이상값 비율) 자동 기록.

* * *

### 4. 외주 작업자의 원천 데이터 무단 유출 및 개인정보 침해

* **설명:** 외주 라벨링 작업자가 스마트팜 현장 이미지(재배 시설 내부, 작물 정보, 위치 메타데이터 등)에 접근하는 과정에서 데이터 유출이 발생할 수 있다. 특히 농가 식별이 가능한 메타데이터가 포함된 경우 개인정보보호법 위반 소지가 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 외주 작업자에게는 익명화·마스킹 처리된 데이터만 제공(위치정보, 농가 식별자 제거). 작업 환경을 망분리된 전용 라벨링 플랫폼으로 제한하고 다운로드 권한 차단. NDA 및 보안 서약서 징수, 접근 로그 전수 감사 체계 수립.

* * *

### 5. AI 모델 버전과 학습 데이터셋 버전 간 비동기화(Version Drift)

* **설명:** 라벨링 기준 변경, 데이터 추가 수집, 모델 재학습이 반복되는 과정에서 어떤 버전의 데이터셋으로 어떤 버전의 모델이 학습되었는지 추적이 끊어질 수 있다. 스마트팜 현장 배포 후 모델 성능 이슈 발생 시 원인 규명이 불가능해진다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 데이터셋-모델 간 연계를 위한 ML 메타데이터 관리 체계 도입(예: MLflow, DVC). 원천데이터·라벨링데이터·모델 아티팩트에 동일한 빌드 해시(commit hash) 태깅. AI허브 적재 시 데이터셋 버전 명세를 테크니컬 리포트에 필수 포함하도록 프로세스 표준화.

* * *

### 6. 데이터 검수 병목으로 인한 전체 파이프라인 납기 지연

* **설명:** 데이터 검수 노드가 단일 인력 또는 소규모 팀에 의존할 경우, 라벨링 완료 물량이 집중되는 시점에 검수 대기열이 폭증한다. 스마트팜 생육 주기에 맞춘 데이터 수집 일정(특정 계절 집중)과 맞물리면 납기 준수가 구조적으로 불가능해진다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 검수 작업을 자동 사전 검증(포맷·스키마·통계 기반)과 전문가 수동 검수로 2단계 분리하여 수동 검수 부하 경감. 검수 처리량 기반 WIP(Work In Progress) 한도 설정으로 파이프라인 흐름 제어. 검수 병목 발생 시 조기 경보를 위한 대시보드 및 SLA 알림 체계 구축.
