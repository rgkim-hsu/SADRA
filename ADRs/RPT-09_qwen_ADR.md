## 📋 ADR (Architecture Decision Record)

### ADR-001: [앙상블 학습 기반의 다중 의사결정 트리 구조 채택]

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 작물 데이터는 시초데이터, 기상, 토양 등 다양한 변수의 영향을 받습니다. 단일 의사결정 트리는 특정 변수의 편향 (Bias) 에 취약할 수 있어, 작물 성장 상태 (질소 부족 등) 를 정확히 판단하기 어렵습니다. 특히 스마트팜 환경에서는 신뢰할 수 있는 실시간 진단이 필수적입니다. |
| **결정(Decision)** | 여러 개의 의사결정 트리 (Tree a ~ Tree n) 를 병렬로 실행한 후, 이를 '분류/범주화' 단계로 통합하는 **앙상블 (Ensemble) 학습 아키텍처**를 채택합니다. 각 트리는 다른 데이터 전처리나 하이퍼파라미터 설정을 통해 편향을 상쇄합니다. |
| **근거(Rationale)** | 머신러닝 이론에 따르면, 독립적인 여러 모델의 예측 결과를 집계 (평균, 투표) 하면 일반화 성능이 향상됩니다. 이미지에서 보듯 Tree (a) ~ (n) 의 결과가 모두 'Class 1' 또는 'Class 2'로 분류되어, 최종 '민감도분석' 단계로 통합되는 구조는 **정확도 (Accuracy)**와 **신뢰도 (Reliability)**를 높이기 위한 결정입니다. |
| **결과(Consequences)** | - **긍정:** 단일 모델보다 예측 오류율이 감소하며, '질소 부족'과 '생육 조건 적합'과 같은 복합적인 상황을 더 잘 포착할 수 있습니다.<br>- **부정:** Tree a~n 을 모두 실행하므로 CPU/Memory 사용량이 단일 트리의 N 배 증가합니다. |
| **트레이드오프(Trade-offs)** | **정확성 vs 확장성**: 높은 정확도를 위해 여러 트리를 사용하는 것은 성능 비용 (Overhead) 을 증가시키지만, '민감도분석' 같은 고신뢰도 결과가 필요한 시스템에는 필수적입니다. |

## ⚠️ 잠재적 위험 분석

### 1. [데이터 품질 저하 전파 (Garbage In, Garbage Out)]
- **설명:** 시스템의 초기 입력인 '시초데이터'와 '작물데이터'에 노이즈나 결측치가 포함되어 있을 경우, Tree (a) ~ (n) 모두 잘못된 의사결정 (의사결정 트리 분류) 을 할 가능성이 높습니다. 이는 결과적으로 잘못된 'Class' 분류와 '민감도분석'으로 이어져 잘못된 농약/비료 제시에 오류가 발생할 수 있습니다.
- **심각도:** 🔴 High / **발생 가능성:** 🔴 High / **대응 방안:** 데이터 수집 단계에서 임베디드 필터링 알고리즘을 도입하고, 입력 데이터 정규화 (Normalization) 를 전 단계에서 수행하여 신뢰도 높은 데이터만 트리에 투입되도록 합니다.

### 2. [모형 편향 및 과적합 (Overfitting)]
- **설명:** Tree (a) ~ (n) 과 같은 각기 다른 모델이 특정 훈련 데이터에만 지나치게 맞춰져 (Overfitting) 새로운 작물 데이터나 환경 변화에 적응하지 못할 수 있습니다. 특히 스마트팜 환경은 계절, 기온 등 변수가 크게 변동하므로 학습된 트리가 현실에 적용되지 않는 위험이 있습니다.
- **심각도:** 🟡 Medium / **발생 가능성:** 🟡 Medium / **대응 방안:** 교차 검증 (Cross-Validation) 을 적용하여 트리의 일반화 능력을 테스트하고, 정규화 (Regularization) 기법을 사용하여 과적합을 방지합니다.

### 3. [실시간 처리 지연 (Latency)]
- **설명:** 이미지에서 Tree (a) ~ Tree (n) 로 표현되는 다수의 트리가 병렬로 실행됩니다. Tree 가 깊거나 데이터 양이 많아질 경우, '의사결정' -> '분류/범주화' -> '민감도분석' 전 과정에 상당한 시간이 소요되어 실시간으로 작물 상태를 보고해야 할 때 지연 (Latency) 이 발생할 수 있습니다.
- **심각도:** 🟡 Medium / **발생 가능성:** 🔴 High / **대응 방안:** 경량화된 의사결정 트리 (예: Decision Stump 또는 깊이 제한) 사용 및 엣지 컴퓨팅 환경을 구성하여 처리 속도를 최적화합니다.

### 4. [분류 결과의 불일치 (Voting Conflict)]
- **설명:** 여러 트리가 독립적으로 동작하므로, Tree (a) 와 Tree (b) 가 서로 다른 Class (예: Tree (a) 는 'Class 1', Tree (b) 는 'Class 2') 를 예측할 수 있습니다. 이때 최종 분류 단계 (Class 1 / Class 2) 에서 어떻게 집계할지 논리가 명확하지 않으면, 시스템이 혼란스러운 결과를 출력할 수 있습니다.
- **심각도:** 🟡 Medium / **발생 가능성:** 🟡 Medium / **대응 방안:** 최종 분류 모듈에 명확한 '승표 (Majority Voting)' 또는 '가중치 평균 (Weighted Average)' 알고리즘을 정의하여, 의견이 갈릴 경우 우세한 결과나 가중치가 높은 트리의 결과를 채택하도록 합니다.

### 5. [표준화 및 호환성 문제]
- **설명:** 제공된 문서에서 언급된 TTA, ETSI 등 IoT 표준과 이 시스템의 데이터 형식 (JSON, XML 등) 이 호환되지 않을 수 있습니다. 특히 '민감도분석' 단계에서 산출된 '평균값'을 외부 IoT 플랫폼에 전송할 때, 표준화된 프로토콜 (MQTT, CoAP 등) 이 지켜지지 않으면 시스템 연동이 실패할 수 있습니다.
- **심각도:** 🟡 Medium / **발생 가능성:** 🟡 Medium / **대응 방안:** 아키텍처 설계 시 초기 단계부터 ISO/IEC 30141:2024, oneM2M 등 표준에 따른 인터페이스 명세서를 준수하도록 설계합니다.
