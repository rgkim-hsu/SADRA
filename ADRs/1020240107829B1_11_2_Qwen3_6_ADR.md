# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 모듈형 모니터링-제어-결과 피드백 루프 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                                                                                                       |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 또는 정밀 농업 환경에서 환경 정보 수집(21), 병충해 판단(23), 영양 분석(24) 등 다양한 모니터링 데이터와 스케줄 관리(41), 작업 추천(42) 등 제어 로직을 통합하여 운영해야 함. 기존 단일 모놀리식 구조에서는 데이터 처리 부하 증가 시 실시간 제어 지연이 발생하고, 결과 추적(51) 및 개선(52)이 시스템 전반에 반영되기 어려운 아키텍처적 한계가 존재함.                                                                                                                  |
| **결정(Decision)**       | 시스템을 **모니터링모듈(2)**, **제어모듈(4)**, **결과관리모듈(5)**로 기능별로 명확히 분리하고, 이들 간의 상호작용을 통해 지속적인 개선을 유도하는 **모듈형 피드백 루프(Feedback Loop) 아키텍처**를 채택함. 모니터링 결과는 DB(6)를 통해 제어 모듈로 전달되고, 제어 실 결과는 결과 관리 모듈을 통해 추적 및 개선되어 다시 제어 로직에 반영되도록 설계함.                                                                                                                |
| **근거(Rationale)**      | 1. **관심사의 분리(Separation of Concerns):** 데이터 수집 및 분석(모니터링)과 의사 결정 및 실행(제어)을 분리함으로써, 각 모듈의 독립적인 개발, 테스트, 확장이 가능함.<br>2. **지속적 개선(CI/CD for Operations):** 결과관리모듈(5)의 추적부(51)와 개선부(52)를 통해 작업의 효과를 분석하고 이를 제어모듈(4)의 작업추천부(42)에 피드백함으로써 시스템의 지능화가 가능함.<br>3. **데이터 일관성:** 데이터페이스(DB)를 중앙 허브로 활용하여 모니터링 데이터와 제어 이력, 결과 데이터의 일관된 저장 및 참조를 보장함. |
| **결과(Consequences)**   | 시스템의 확장성과 유지보수성이 크게 향상되며, 운영 데이터 기반의 지속적인 알고리즘 고도화가 가능해짐. 반면, 모듈 간 통신 및 데이터 동기화를 위한 인터페이스 관리가 복잡해지고, 피드백 루프의 지연으로 인해 즉각적인 제어 반영이 어려울 수 있음.                                                                                                                                                                                               |
| **트레이드오프(Trade-offs)** | 모듈별 독립성 확보 및 지속적 개선 가능 vs. 모듈 간 통신 오버헤드 증가 및 피드백 루프 설계의 복잡성.                                                                                                                                                                                                                                                                             |

## ⚠️ 잠재적 위험 분석

### 1. 모니터링 데이터 처리 지연으로 인한 제어 타이밍错失

- **설명:** 병충해판단부(23)나 영양분석부(24)에서 고해상도 이미지 분석이나 복잡한 화학적 데이터 처리 시 시간이 소요될 경우, 제어모듈(4)로 전달되는 데이터가 지연되어 적기 방제나 영양 공급 시점을 놓칠 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 엣지 컴퓨팅(Edge Computing) 도입을 통해 모니터링모듈(2) 내에서 1차 분석 수행, 비동기 메시지 큐(Message Queue)를 활용한 데이터 파이프라인 최적화, 긴급 상황 시 빠른 제어 신호 전달을 위한 High-Priority 채널 마련.

### 2. 알고리즘 오판(False Positive/Negative)으로 인한 잘못된 작업 추천

- **설명:** 병충해판단부(23)가 정상 작물을 병충해로 오인하거나, 영양분석부(24)가 결핍 상태를 잘못 판단할 경우, 작업추천부(42)가 불필요한 농약 살포 또는 과다 시비 작업을 추천하여 경제적 손실 및 환경 오염을 유발할 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 다중 센서 데이터 융합(Data Fusion)을 통한 판단 정확도 향상, 인공지능 모델의 정기적인 재학습(Retraining) 및 검증 프로세스 도입, 작업 추천 전 관리자의 최종 승인(Human-in-the-loop) 절차 포함.

### 3. 데이터페이스(DB) 병목 현상 및 데이터 불일치

- **설명:** 모니터링모듈(2), 제어모듈(4), 결과관리모듈(5)이 모두 데이터페이스(DB)에 집중적으로读写(Read/Write) 작업을 수행할 경우, 동시성 제어 실패로 인한 데이터 충돌이나 처리 지연이 발생할 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 데이터베이스 샤딩(Sharding) 또는 읽기/쓰기 분리(Read Replica) 아키텍처 적용, 캐싱(Caching) 전략 도입으로 DB 부하 분산, 트랜잭션 관리 로직 강화를 통한 데이터 정합성 보장.

### 4. 결과 개선부(52)의 피드백 반영 실패

- **설명:** 결과관리모듈(5)에서 분석된 개선 사항이 제어모듈(4)의 작업추천부(42)나 스케줄관리부(41)에 실시간으로 반영되지 않을 경우, 시스템은 과거의 비효율적인 패턴을 반복하게 되어 스마트 팜의 효율성이 저하됨.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 이벤트 기반 아키처(Event-Driven Architecture)를 도입하여 개선 데이터 생성 시 즉시 제어 모듈로 알림 전달, 정기적인 배치(Batch) 작업을 통한 모델 파라미터 업데이트 자동화, 피드백 루프 상태 모니터링 대시보드 제공.

### 5. 객체매칭부(25)와 작업접수부(43) 간 식별자 불일치

- **설명:** 모니터링모듈의 객체매칭부(25)가 식별한 작물 또는 구역 정보와 제어모듈의 작업접수부(43)가 참조하는 식별자 체계가 다를 경우, 특정 구역에 대한 작업 지시가 잘못된 위치로 전달되거나 누락될 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 시스템 전반에 걸쳐 표준화된 식별자(SID, Standard Identifier) 체계 정의 및 적용, 객체 매칭 시 고유 ID 태깅(Tagging) 프로토콜 강제, 작업 지시 전 위치 정보 이중 검증 로직 구현.
