## 📋 ADR (Architecture Decision Record)

### ADR-001: [중앙집중형 클라우드 기반 통합 아키텍처 채택]

| 항목 | 내용 |
|------|------|
| **상황 (Context)** | 이미지와 문서에 따르면, 분산된 '농장' 및 '센서' 환경에서 수집된 데이터는 반드시 '클라우드(10)'로 모아야 '데이터 수집', '고도화', 'AI 분석' (병 발생설 예측 등) 이 가능함. 각 농장은 독립적이지만 시스템 전체의 관제와 분석을 위해 중앙 통합이 필수적임. |
| **결정 (Decision)** | 시스템의 최상위 아키텍처는 모든 엣지 노드 (센서, G/W) 가 중앙 '클라우드 플랫폼'을 공유하는 형태로 설계함. 클라우드에는 '농업데이터 관제시스템', '관리자 웹 서비스' 등 핵심 애플리케이션과 'AI 분석' 엔진을 통합 배치함. |
| **근거 (Rationale)** | 문서의 'ISO/IEC 30141:2024' (IoT 참조 아키텍처) 과 'oneM2M' 표준에서 제시하는 공통 아키텍처 모범 사례에 부합함. 또한, 문서에서 강조된 'AI 분석' (병 발생설 예측, 병 발생예측 등) 을 위해 대용량 데이터 처리와 모델 연산이 클라우드 환경에서 효율적으로 수행되어야 함. |
| **결과 (Consequences)** | **긍정적:** 확장성과 유지보수성이 우수하여, 새로운 센서 추가 시 중앙에서 쉽게 관리 가능. 데이터 품질 관리 및 분석이 일관됨.<br>**부정적:** 인터넷 연결이 불안정한 농장 환경에서 오프라인 동작 시 기능 제한 발생 가능. |
| **트레이드오프 (Trade-offs)** | **장점:** 통합 데이터 활용으로 고도화된 예측 (병 발생설 예측 등) 가능.<br>**단점:** 중앙 서버에 대한 과도한 의존도와 대역폭 비용 증가. |

### ADR-002: [경량 프로토콜 기반 상호운용성 설계]

| 항목 | 내용 |
|------|------|
| **상황 (Context)** | 농장 환경은 네트워크 인프라가 제한적일 수 있으며, 다양한 제조사의 센서와 G/W 를 사용해야 함. 문서의 'IETF CoAP, MQTT' 언급을 보면, 제한된 대역폭과 낮은 전력 소모를 고려한 통신 방식이 필요함을 시사함. |
| **결정 (Decision)** | 센서와 게이트웨이 간, 그리고 엣지-클라우드 간 통신에 'MQTT' 또는 'CoAP'와 같은 경량 프로토콜을 표준으로 채택함. 또한 TTA 표준 목록 ('스마트팜 데이터 상호운용 프레임워크') 을 준수하여 다양한 디바이스 간 호환성 확보. |
| **근거 (Rationale)** | 문서에 명시된 'Matter', 'OCF' 등의 상호운용성 표준 및 TTA 표준화 과제를 준수하여, 이기종 기기 (스마트폰 앱, 웹, 센서) 간 데이터 흐름 (그림 100 참조) 을 원활하게 보장하기 위함. |
| **결과 (Consequences)** | **긍정적:** 네트워크 효율성 극대화, 디바이스 교체 시 호환성 유지.<br>**부정적:** 일부 고가성 프로토콜 지원 디바이스와의 호환성 부족 가능성. |
| **트레이드오프 (Trade-offs)** | **장점:** 에너지 효율 및 대역폭 절감.<br>**단점:** 복잡한 대용량 데이터 처리 시 경량 프로토콜의 한계 존재. |

### ADR-003: [보안 우선 (Security-First) 아키텍처 구현]

| 항목 | 내용 |
|------|------|
| **상황 (Context)** | 문서의 'ITU-T X.1352', 'ETSI EN 303 645', 'KISA' 등 보안 표준들이 강조되고 있음. 농장 내 센서 데이터 (온도, 습도, 작물 상태 등) 와 제어 명령은 외부 공격에 매우 취약함. |
| **결정 (Decision)** | 모든 데이터 전송 (센서 -> G/W -> 클라우드) 에 암호화 (TLS 등) 를 필수로 적용하고, 클라우드 내부의 사용자 인증 (Farm, Login) 및 권한 관리 (Role 기반) 를 표준화함. 문단의 'IoT 기기 사이버보안' 관련 표준 준수. |
| **근거 (Rationale)** | 'ETSI EN 303 645'와 'ISO/IEC 27030' 등 글로벌 보안 가이드라인을 준수해야 글로벌 시장 경쟁력 (문서 언급) 을 확보할 수 있음. 데이터 유출 시 농작업 피해 방지. |
| **결과 (Consequences)** | **긍정적:** 민감한 농업 데이터 보호, 시스템 신뢰도 향상.<br>**부정적:** 보안 인증 및 암호화 키 관리로 인한 시스템 복잡도 증가. |
| **트레이드오프 (Trade-offs)** | **장점:** 법적/규제적 요건 충족 및 브랜드 신뢰도 증대.<br>**단점:** 처리 속도 미세 감소 및 인증 인프라 구축 비용 증가. |

## ⚠️ 잠재적 위험 분석

### 1. [클라우드 단일 고장 위험 (SPOF Risk)]
- **설명:** 모든 시스템이 이미지 하단의 '클라우드' 플랫폼을 절대적으로 의존하고 있으므로, 클라우드 서비스 자체가 가동 중지되거나 네트워크 연결이 끊길 경우, 전체 농장 제어 (물 분사, 제습 등) 와 모니터링이 불가능해짐.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium (클라우드 안정성은 높으나, 인터넷 회선 중단을 고려)
- **대응 방안:** 핵심 제어 기능에 대해 '엣지 컴퓨팅' 기능을 추가하여 인터넷 연결 단절 시에도 로컬 게이트웨이에서 기본 제어 알고리즘이 작동하도록 설계.
- **대응 방안:** 2 단계 백업 네트워크 (이중화) 또는 로컬 오프라인 모드 시뮬레이터 구현.

### 2. [데이터 프라이버시 및 보안 침해 위험]
- **설명:** 농장의 생체 데이터, 작물 상태 데이터 등 민감한 정보가 클라우드를 경유하며 전송되므로, 제 3 자에 의한 해킹이나 데이터 도청 시 심각한 정보 유출 사고 발생 가능. (문서의 보안 표준 준수 필요성과 연결)
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** ITU-T X.1352 및 KISA 기준에 따른 보안 인증 획득, 전송 중 암호화 (TLS 1.3) 강제 적용, 클라우드 내부 가상화 환경 분리 (Multi-tenant isolation).

### 3. [에지 노드 네트워크 불안정성]
- **설명:** 농장 내 센서 네트워크 (G/W) 가 무선 (LoRa, Zigbee 등) 으로 동작하는 경우가 많아, 농가 내 구조물 간섭, 전자기 간섭 등으로 신호가 불안정해져 데이터 수집 (고도화 전 단계) 이 중단될 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 무선 주파수 간섭 최소화 설계, G/W 의 재밍 (Jamming) 감지 기능 추가, 데이터 중복 전송 및 자동 재전송 로직 구현.

### 4. [호환성 및 상호운용성 문제]
- **설명:** 다양한 센서 (온도, 습도, 조명 등) 와 구동기가 서로 다른 통신 프로토콜을 사용할 경우, ADR-002 에서 채택한 표준을 모두 만족하지 못하는 기기들이 혼입되면 시스템 통합이 어려움.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** TTA의 '스마트팜 데이터 상호운용 프레임워크' 표준 목록 (별표 26) 에 명시된 규격만 사용하도록 제조사 협조, 게이트웨이 레벨에서 프로토콜 변환 (Gateway) 기능 강화.

### 5. [지연성으로 인한 제어 실패]
- **설명:** 고도화된 데이터 분석 (AI 병 발생설 예측) 과 자동화 제어 (물 분사 등) 간의 지연 시간이 발생하여, 급격한 기상 변화나 병해충 확산 시 제어 명령이 늦어져 농작물 피해가 발생할 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 중요한 제어 명령 (비, 물 분사 등) 에는 에지 게이트웨이의 로직을 우선적으로 활용하도록 설정, 클라우드 분석 결과를 기반으로 한 제어는 '경고' 수준으로 제한하고 즉각적 대응은 로컬 처리.
