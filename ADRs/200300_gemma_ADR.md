## 📋 ADR (Architecture Decision Record)

### ADR-001: 계층적 표준 기반의 서비스 지향 아키텍처(SOA) 채택 및 인터페이스 규격화

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 본 시스템은 물리적 환경(센서, 구동기)을 제어하는 **실시간 임베디드 제어 로직**과, 수집된 대규모 이기종 데이터를 분석하고 시각화하는 **고수준의 지능형 분석 로직**이 결합되어야 합니다. 각 계층은 독립적으로 진화하며, 다양한 제조사의 이기종 장비(Multi-Vendor) 및 변화하는 국제 표준(ISO/IEC 30141 등) 변화에 대응해야 하므로, 단일 모놀리식 아키텍처로는 유지보수성과 확장성 확보가 불가능합니다. |
| **결정(Decision)** | 아키텍처를 엣지(Edge), 플랫폼/백엔드(Platform/Backend), 애플리케이션(Application)의 3계층 구조로 분리하고, 데이터 교환 및 서비스 호출에 있어 **메시지 브로커 기반의 이벤트를 이용하는 서비스 지향 아키텍처(SOA)**를 채택합니다. 핵심 표준으로 **ISA-95/ISA-88 모델** 및 **ISO/IEC 30141 레퍼런스 아키텍처**를 준용합니다. |

## ⚠️ 잠재적 위험 분석

### 1. 이기종 장비 연동 및 데이터 상호운용성 실패 (Interoperability Failure)
- **설명:** 온실의 환경 제어기는 제조사별로 상이한 통신 프로토콜(Modbus, Zigbee, RS-485 등)과 데이터 모델을 가집니다. 이들을 백엔드 플랫폼으로 통합할 때, 프로토콜 변환 계층(Protocol Translator Layer)의 오류나, 데이터 필드의 이름/단위 불일치로 인해 시스템의 핵심 데이터가 오염되거나 제어가 중단될 수 있습니다.
- **심각도:** 🔴 High (물리적 제어 실패로 인한 작물 손실 또는 장비 파손 발생 가능)
- **발생 가능성:** 🔴 High (다수의 파트너 및 현장 장비 의존성으로 인해 필연적으로 발생)
- **대응 방안:** 모든 입력 데이터를 표준화된 공통 데이터 모델(Canonical Data Model)로 강제 변환하는 **데이터 게이트웨이 계층**을 필수적으로 구축하고, 각 프로토콜 어댑터에 대해 엄격한 단위 테스트와 실시간 이중 검증(Dual Verification)을 적용합니다.

### 2. 사이버 물리 시스템(CPS) 해킹 및 제어권 탈취 위험 (Cyber-Physical Security Breach)
- **설명:** 시스템은 센서, 밸브, 히터 등 물리적 Actuator를 원격으로 제어합니다. 만약 네트워크 보안 취약점을 통해 핵심 서버 또는 게이트웨이가 해킹되면, 공격자가 환경 제어 로직을 조작하여 작물에 치명적인 환경 변화(예: 과도한 습도, 극저온)를 유발할 수 있습니다.
- **심각도:** 🔴 High (생산물 손실, 법적 책임 문제 초래)
- **발생 가능성:** 🟡 Medium (네트워크 연결 지점이 많을수록 노출 면적 증가)
- **대응 방안:** 제어 흐름에 대해 **최소 권한 원칙(Principle of Least Privilege)**을 적용하고, 모든 제어 명령(Write Operation)은 반드시 **이중 인증 및 역할 기반 접근 통제(RBAC)**를 거치도록 합니다. 게이트웨이 단에서 트래픽 정상성 분석(Anomaly Detection)을 통해 비정상적 제어 명령을 사전에 차단하는 방화벽 솔루션을 적용해야 합니다.

### 3. 데이터 전송 지연(Latency)으로 인한 제어 로직 오작동 위험 (Real-Time Latency Failure)
- **설명:** 환경 제어는 밀리초(ms) 단위의 실시간 반응이 요구됩니다. 백엔드 분석 서버나 UI 업데이트를 위해 데이터를 지나치게 많이 처리하거나, 무거운 메시지 큐잉/API 게이트웨이를 거치게 되면, 센서 값 변화를 감지하고 구동기(Actuator)가 반응하는 데 지연이 발생하여 최적의 환경 제어가 불가능해집니다.
- **심각도:** 🔴 High (작물의 생존과 직결되는 치명적인 오류)
- **발생 가능성:** 🟡 Medium (네트워크 품질과 서버 부하에 따라 가변적)
- **대응 방안:** 환경 제어 관련 경량 데이터는 반드시 **Edge Computing 환경**에서 1차 로직 판단(Pre-processing)을 수행하도록 분리하고, 실시간 통신에 최적화된 프로토콜(MQTT QoS 2)과 고신뢰성 메시지 브로커를 사용하여 데이터 패킷의 손실 없이 낮은 지연율을 보장해야 합니다.

### 4. 데이터 모델의 비일관성 및 분석 난이도 증가 위험 (Data Model Drift)
- **설명:** 스마트팜의 데이터는 환경(온도, 습도), 농업(성장 주기, 비료), 기계(펌프 작동 시간) 등 매우 다양한 도메인 지식을 포함합니다. 각 도메인의 데이터가 표준화되지 않은 상태로 장기간 누적될 경우, 데이터 모델이 일관성을 잃고(Data Model Drift), 영농 관리 서버에서 '종합적인 패턴 분석'을 수행하는 것이 구조적으로 불가능해집니다.
- **심각도:** 🟡 Medium (시스템의 가치를 떨어뜨리지만, 즉각적인 물리적 피해는 아님)
- **발생 가능성:** 🟢 High (장기 프로젝트에서 가장 빈번하게 발생하는 문제입니다)
- **대응 방안:** 데이터 수집 초기 단계부터 **데이터 거버넌스(Data Governance)** 체계를 수립하고, **OWL 또는 온톨로지(Ontology)**를 활용하여 센서 데이터, 제어 데이터, 작물 생육 데이터를 구조적으로 통합하는 통일된 지식 모델을 정의하고, 이를 모든 분석 로직의 기준으로 활용해야 합니다.

### 5. 규격 미준수 및 국제 인증(KC) 확보 실패 위험 (Compliance Failure)
- **설명:** 시스템은 국내외 표준(예: ISO/IEC 30141, ITU-T X.1352)을 근거로 하고 제품 인증(KC)을 목표로 합니다. 만약 아키텍처 설계 단계부터 필요한 인증 요구사항(예: 보안성 검증, 전력 효율 검증, 통신 표준 준수)을 반영하지 못하거나, 문서화가 미흡할 경우, 최종 제품화 및 시장 진입 자체가 불가능해질 위험이 있습니다.
- **심각도:** 🔴 High (프로젝트 전체가 중단될 수 있는 치명적 위험)
- **발생 가능성:** 🟡 Medium (PM/PL의 표준화 이해도에 따라 달라짐)

- **발생 가능성:** 🟡 Medium (네트워크 연결 지점이 많을수록 노출 면적 증가)
- **대응 방안:** 제어 흐름에 대해 **최소 권한 원칙(Principle of Least Privilege)**을 적용하고, 모든 제어 명령(Write Operation)은 반드시 **이중 인증 및 역할 기반 접근 통제(RBAC)**를 거치도록 합니다. 게이트웨이 단에서 트래픽 정상성 분석(Anomaly Detection)을 통해 비정상적 제어 명령을 사전에 차단하는 방화벽 솔루션을 적용해야 합니다.

### 3. 데이터 전송 지연(Latency)으로 인한 제어 로직 오작동 위험 (Real-Time Latency Failure)
- **설명:** 환경 제어는 밀리초(ms) 단위의 실시간 반응이 요구됩니다. 백엔드 분석 서버나 UI 업데이트를 위해 데이터를 지나치게 많이 처리하거나, 무거운 메시지 큐잉/API 게이트웨이를 거치게 되면, 센서 값 변화를 감지하고 구동기(Actuator)가 반응하는 데 지연이 발생하여 최적의 환경 제어가 불가능해집니다.
- **심각도:** 🔴 High (작물의 생존과 직결되는 치명적인 오류)
- **발생 가능성:** 🟡 Medium (네트워크 품질과 서버 부하에 따라 가변적)
- **대응 방안:** 환경 제어 관련 경량 데이터는 반드시 **Edge Computing 환경**에서 1차 로직 판단(Pre-processing)을 수행하도록 분리하고, 실시간 통신에 최적화된 프로토콜(MQTT QoS 2)과 고신뢰성 메시지 브로커를 사용하여 데이터 패킷의 손실 없이 낮은 지연율을 보장해야 합니다.

### 4. 데이터 모델의 비일관성 및 분석 난이도 증가 위험 (Data Model Drift)
- **설명:** 스마트팜의 데이터는 환경(온도, 습도), 농업(성장 주기, 비료), 기계(펌프 작동 시간) 등 매우 다양한 도메인 지식을 포함합니다. 각 도메인의 데이터가 표준화되지 않은 상태로 장기간 누적될 경우, 데이터 모델이 일관성을 잃고(Data Model Drift), 영농 관리 서버에서 '종합적인 패턴 분석'을 수행하는 것이 구조적으로 불가능해집니다.
- **심각도:** 🟡 Medium (시스템의 가치를 떨어뜨리지만, 즉각적인 물리적 피해는 아님)
- **발생 가능성:** 🟢 High (장기 프로젝트에서 가장 빈번하게 발생하는 문제입니다)
- **대응 방안:** 데이터 수집 초기 단계부터 **데이터 거버넌스(Data Governance)** 체계를 수립하고, **OWL 또는 온톨로지(Ontology)**를 활용하여 센서 데이터, 제어 데이터, 작물 생육 데이터를 구조적으로 통합하는 통일된 지식 모델을 정의하고, 이를 모든 분석 로직의 기준으로 활용해야 합니다.
