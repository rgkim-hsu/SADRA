## 📋 ADR (Architecture Decision Record)

### ADR-001: OCF 기반 다중 전송 프로토콜 추상화 및 통합 보안 프레임워크 적용

| 항목                     | 내용                                                                                                                                                                                                                                                                                 |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | IoT 생태계는 Wi-Fi, BLE, Zigbee 등 다양한 물리적 전송 방식(Transports)과 이기종 장치들이 혼재되어 있어 상호 운용성(Interoperability)이 극히 떨어집니다. 특히 Industrial(산업) 분야에서는 보안과 안정적인 장치 검색(Discovery) 및 설정(Provisioning)이 필수적이지만, 기존에는 이를 통합하는 표준 프레임워크가 부재했습니다.                                                         |
| **결정(Decision)**       | **OCF(Open Connectivity Foundation) 컨셉츄얼 프레임워크**를 아키텍처의 핵심 표준으로 채택합니다. 하위의 이기종 전송 계층(Transports)을 추상화하고, **Core Framework** 계층에서 Resource Model 및 RESTful Interactions를 표준화하며, **Security, Identity & Permissions**를 전 계층에 걸쳐 통합 적용하는 layered architecture를 구축합니다.                 |
| **근거(Rationale)**      | 이미지에서 확인할 수 있듯이, OCF 프레임워크는 하단에 다양한 통신 규약(Wi-Fi, BLE, Zigbee 등)을 포용하면서도 중앙의 Core Framework를 통해 Discovery(검색), Provisioning(설정), Comms(통신) 기능을 일원화합니다. 이는 물리적 연결 방식과 무관하게 장치 간 통신이 가능하게 하며, 특히 'Industrial' 프로파일을 명시적으로 지원함으로써 산업용 IoT의 까다로운 요구사항을 표준화된 Resource Model로 해결할 수 있습니다. |
| **결과(Consequences)**   | **긍정적:** 이기종 장치 간의 높은 상호 운용성 확보, 보안 및 인증 기능의 일원화로 인한 보안성 강화, Industrial 분야를 포함한 다양한 수직 산업(Verticals)으로의 확장성 확보.<br>**부정적:** RESTful API 기반의 Resource Model 사용으로 인한 실시간 제어 환경에서의 오버헤드 발생 가능성, 프레임워크準守를 위한 초기 개발 비용 증가.                                                              |
| **트레이드오프(Trade-offs)** | **장점:** 표준화된 인터페이스로 인한 유지보수 용이성 및 보안 통합 관리.<br>**단점:** 범용성 확보를 위한 추상화 계층으로 인해 초저지연(Ultra-low latency)이 요구되는 극한의 실시간 제어 시나리오에서는 성능 저하가 발생할 수 있음.                                                                                                                                    |

---

## ⚠️ 잠재적 위험 분석

### 1. RESTful Interactions에 의한 실시간성 저하 (Real-time Latency Risk)

- **설명:** Core Framework에서 "Resource Model & RESTful Interactions"를 주요 통신 방식으로 채택하고 있습니다. Industrial 환경에서는 밀리초(ms) 단위의 실시간 제어가 필요할 수 있는데, RESTful HTTP/MQTT 기반의 통신은 오버헤드가 커서 실시간 응답성을 보장하기 어려울 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 실시간성이 критical한 제어 명령에는 CoAP(Constrained Application Protocol)나 UDP 기반의 경량 프로토콜을 병행 사용하도록 아키텍처를 확장하거나, Edge Computing 게이트웨이에서 프로토콜 변환 및 로컬 제어 로직을 처리해야 합니다.

### 2. 통합 보안 계층 구현의 복잡성 (Security Implementation Complexity)

- **설명:** Core Framework 하단에 "Security, Identity & Permissions"가 배치되어 모든 통신에 보안을 강제합니다. 하지만 다양한 Transports(BLE, Zigbee 등) 각각에 대해 일관된 인증서 관리(Certificate Management)와 키 교환(Key Exchange)을 구현하는 것은 매우 복잡하며, 저사양 IoT 장치에서는 리소스 부족으로 구현이 실패할 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 하드웨어 보안 모듈(HSM)이나 TrustZone을 활용한 하드웨어 기반 키 저장소를 필수 사양으로 정의하고, 경량 암호화 알고리즘을 지원하도록 디바이스 펌웨어 가이드라인을 엄격히 수립해야 합니다.

### 3. Provisioning(장치 온보딩) 과정의 사용자 경험 저하

- **설명:** Core Framework에 "Provisioning"이 명시되어 있습니다. 산업 현장에서 보안이 강화된 IoT 장치를 네트워크에 안전하게 추가(Onboarding)하는 과정은 복잡할 수 있습니다. 이 과정이 직관적이지 않으면 운영자의 실수로 보안 설정이 우회되거나 장치가 프라인 상태로 방치될 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** QR 코드 스캔, NFC 태그 탭 등 물리적 접촉을 통한 간편한 Secure Pairing 방식을 Provisioning 프로세스에 필수적으로 포함시키고, 자동화된 장치 등록 워크플로우를 제공해야 합니다.

### 4. Industrial 프로파일과 Core Framework의 괴리 (Profile Divergence)

- **설명:** 이미지 상단 Profiles 영역에서 "Industrial"이 강조되어 있습니다. 만약 Industrial 프로파일이 Core Framework의 표준 Resource Model을 따르지 않고 독자적인 데이터 모델을 사용하게 되면, OCF 프레임워크를 사용하는 타 시스템(Consumer, Enterprise 등)과의 연동이 끊어지는 데이터 사일로가 발생할 수 있습니다.
- **심각도:**  Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** Industrial 프로파일 개발 시 OCF의 표준 Resource Model(RDF)을Strictly 준수하도록 아키텍처 거버스를 수립하고, 필수 확장 필드만을 허용하는 검증 로직을 도입해야 합니다.

### 5. 이기종 Transport 간의 네트워크 단편화 (Network Fragmentation)

- **설명:** Transports 계층에 Wi-Fi, Wi-Fi Direct, BLE, Zigbee 등이 혼재되어 있습니다. 단일 게이트웨이가 모든 프로토콜을 동시에 지원하지 못할 경우, 네트워크가 단편화되어 장치 간 직접 통신(P2P)이 불가능해지고 중앙 서버 의존도가 과도하게 높아질 수 있습니다.
- **심각도:**  Medium
- **발산 가능성:**  Low
- **대응 방안:** 멀티 라디오(Multi-radio) 기능을 지원하는 게이트웨이 하드웨어를 선정하고, OCF의 Discovery 기능을 활용하여 로컬 네트워크 내에서 장치 간 직접 라우팅이 가능하도록 Mesh 네트워킹 토폴로지를 지원해야 합니다.
