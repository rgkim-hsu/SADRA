📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: **센서 기반 실시간 양액 관리 시스템 아키텍처 채택**

| 항목                     | 내용                                                                                                                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 시스템에서 원수탱크, 양액탱크, 배액탱크, 양비탱크 등 다수의 탱크를 실시간으로 모니터링하고 제어해야 함. 각 탱크는 110, 120, 130, 140, 141, 150번 포트를 통해 센서 및 제어 장치와 연결되어 있으며, 센서의 자동화 시스템과 연동되어 양액의 상태를 감시하고 조절해야 함. 기존 시스템은 수동으로 관리되어 효율성이 떨어지고 오류 발생 가능성이 높음. |
| **결정(Decision)**       | **분산형 센서 네트워크**와 **중앙 집중식 데이터 처리 시스템**을 결합한 하이브리드 아키텍처를 채택. 각 탱크에 설치된 센서(110, 120, 130, 140, 141, 150번 포트)는 실시간으로 데이터를 수집하며, 중앙 시스템에서 데이터를 통합하여 분석 및 제어 명령 전달.                                                      |
| **근거(Rationale)**      | 실시간 모니터링을 위해 센서에서 중앙 시스템으로의 데이터 전송이 필수적임. 분산형 센서 네트워크는 각 탱크의 상태를 독립적으로 모니터링할 수 있으며, 중앙 시스템은 전체 시스템의 최적화를 담당. 스마트팜 표준(ISO 21878, ISO 23237 등)에서 권장하는 실시간 데이터 수집 및 자동화 시스템과 일치.                                       |
| **결과(Consequences)**   | **장점**: 실시간 데이터 수집으로 양액 관리 효율성 향상, 오류 감지 및 조치 신속화, 자동화로 인한 인력 비용 절감. **단점**: 중앙 시스템에 의존적이며, 네트워크 지연 또는 장애 시 전체 시스템에 영향을 미칠 수 있음.                                                                                    |
| **트레이드오프(Trade-offs)** | **얻는 장점**: 실시간 모니터링, 자동화, 정확성 향상. **감수해야 할 단점**: 중앙 시스템의 단일 장애점(Single Point of Failure), 네트워크 인프라 의존성, 초기 구축 비용 증가.                                                                                                |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. **센서 데이터 오류 또는 손실**

* **설명:** 센서(110, 120, 130, 140, 141, 150번 포트)에서 잘못된 데이터를 수집하거나, 네트워크 장애로 인해 데이터가 중앙 시스템으로 전송되지 않을 경우 양액 관리에 오류 발생.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 센서 이중화(Redundancy) 구축, 데이터 검증 로직 추가, 로컬 스토리지에 임시 저장 후 재전송 메커니즘 도입.

* * *

### 2. **중앙 시스템 장애**

* **설명:** 중앙 시스템이 다운되면 실시간 데이터 분석 및 제어 명령이 중단되어 양액 관리가 비효율적으로 수행됨.
* **심각도:** 🔴 High
* **발생 가능성:** 🟢 Low
* **대응 방안:** 중앙 시스템의 고가용성(HA) 구축, 백업 시스템 운영, 자동 장애 조치(Failover) 메커니즘 도입.

* * *

### 3. **네트워크 지연 또는 장애**

* **설명:** 탱크와 센서, 중앙 시스템 간 네트워크 연결이 불안정해지거나 지연되면 실시간 제어에 지장이 발생.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 네트워크 이중화, 우선순위 기반 데이터 전송(Priority-based Routing), 로컬 제어 모드(Offline Mode) 지원.

* * *

### 4. **보안 취약점(데이터 유출 또는 무단 접근)**

* **설명:** 센서 또는 중앙 시스템에 보안 취약점이 노출되어 해커가 양액 관리 시스템을 제어하거나 데이터를 조작할 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 데이터 암호화(End-to-End Encryption), 접근 제어(ACL) 강화, 정기적인 보안 패치 및 모니터링.

* * *

### 5. **탱크 간 데이터 동기화 실패**

* **설명:** 여러 탱크(원수탱크, 양액탱크, 배액탱크 등)에서 수집된 데이터가 중앙 시스템에서 올바르게 동기화되지 않아 양액의 비율 또는 상태가 잘못 계산됨.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 데이터 동기화 프로토콜(예: Time Synchronization Protocol) 도입, 주기적인 데이터 무결성 검사.
