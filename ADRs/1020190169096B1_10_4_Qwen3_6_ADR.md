## 1020190169096B1_10_4

# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 농작물 생육 분석을 위한 모듈형 파이프라인 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | `이미지 제공모듈(100)`로부터 수신한 원본 이미지를 기반으로 작물의 기관 분류, 보정, 계측, 과중 산출 등 복잡한 다단계 처리를 수행해야 함. 단일 모놀리식 처리로는 알고리즘 교체 및 특정 단계의 최적화가 어려우며, `기준정보 데이터베이스(300)`와의 연계를 통한 정확한 분석이 요구됨.                                             |
| **결정(Decision)**       | `생육정보 산출모듈(200)` 내부에 `이미지 입력부(210)`부터 `정보전송부(280)`까지의 기능을 순차적인 파이프라인 형태로 분리 배치함. 각 단계는 독립적인 모듈로 구성하되, 데이터 흐름은 단방향(Straight-through)으로 처리하며, `기관별 계측치 산출부(240)`와 같은 핵심 연산 모듈은 `기준정보 데이터베이스(300)`를 참조하여 보정하도록 설계함. |
| **근거(Rationale)**      | 작물 생육 분석은 이미지 품질 보정(`230`) → 기관 식별(`220`) → 정밀 계측(`240`)의 순차적 의존성을 가짐. 모듈형 파이프라인은 각 단계의 알고리즘을 독립적으로 개선(예: 더 정확한 분류 모델 도입)할 수 있게 하며, 처리 과정의 투명성을 확보하여 오류 추적(Tracing)이 용이함.                                        |
| **결과(Consequences)**   | 시스템의 유지보수성과 알고리즘 고도화의 유연성이 크게 향상됨. 특정 단계(예: 이미지 보정)의 성능 개선이 전체 분석 정확도에 직접적으로 기여함. 반면, 직렬 처리 구조로 인해 고해상도 이미지 대량 처리 시 지연(Latency)이 발생할 수 있음.                                                                       |
| **트레이드오프(Trade-offs)** | 처리 단계의 명확성 및 모듈별 독립 최적화 가능 vs. 직렬 처리에 의한 전체 분석 시간 증가 및 단계 간 데이터 전달 오버헤드.                                                                                                                                         |

---

## ️ 잠재적 위험 분석

### 1. 순차적 파이프라인 병목 현상에 의한 처리 지연

- **설명:** `생육정보 산출모듈(200)` 내의 모든 하위 모듈(`210`~`280`)이 직렬로 연결되어 있어, 특정 단계(예: `이미지 기반 기관분류부(220)`의 딥러닝 추론)에서 처리 시간이 길어지면 전체 파이프라인의 처리량(Throughput)이 급격히 저하됨.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 파이프라인 내부에 비동기 큐(Asynchronous Queue) 도입, 컴퓨팅 자원이 집중되는 단계(`220`, `240`)에 대한 수평적 확장(Horizontal Scaling) 및 GPU 가속화 적용, 배치 처리(Batch Processing) 모드 지원.
  
  ### 2. 기관 분류 오류에 의한 연쇄적 분석 왜곡
- **설명:** 초기 단계인 `이미지 기반 기관분류부(220)`에서 작물의 기관(잎, 줄기, 열매 등)을 잘못 분류할 경우, 후속 단계인 `기관별 계측치 산출부(240)` 및 `과중산출부(250)`가 잘못된 기준을 적용하여 완전히 틀린 생육 정보를 산출함.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 분류 결과에 대한 신뢰도 점수(Confidence Score) 산출 및 임계값 기반 필터링, 분류 실패 시 `이미지 보정부(230)`로 피드백하여 재처리하는 루프(Feedback Loop) 구조 도입, 다중 모델 앙상블(Ensemble) 기법 적용으로 정확도 향상.
  
  ### 3. 기준 정보 데이터베이스(300) 연계 실패
- **설명:** `기관별 계측치 산출부(240)`가 정확한 계측을 위해 참조하는 `기준정보 데이터베이스(300)`의 네트워크 연결이 끊기거나 데이터 무결성이 훼손될 경우, 계측치 산출이 불가능하거나 부정확한 데이터가 downstream으로 전파됨.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 기준 정보의 로컬 캐싱(Local Caching) 메커니즘 구현으로 네트워크 단절 시 최근 데이터 기반 처리 지속, 데이터베이스 헬스 체크(Health Check) 및 자동 페일오버(Failover) 구성.
  
  ### 4. 영농 정보 매칭 및 저장 데이터 불일치
- **설명:** `영농정보 매칭부(270)`에서 산출된 생육 정보를 `영농정보 데이터베이스(400)`에 전송(`280`)하는 과정에서 네트워크 패킷 손실이나 트랜잭션 충돌이 발생하면, `사용자단말(500)`이 조회하는 실제 정보와 분석된 정보가 불일치함.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 정보 전송 시 반드시 ACK(Acknowledgement) 기반의 신뢰성 있는 전송 프로토콜(MQTT QoS 1/2 또는 REST Retry) 적용, 데이터베이스 트랜잭션 로깅 및 불일치 시 자동 재동기화(Resync) 배치 작업 스케줄링.
  
  ### 5. 이미지 전송부(120) 보안 취약점 노출
- **설명:** `이미지 제공모듈(100)`의 `이미지 전송부(120)`가 농장 현장의 엣지 디바이스인 경우, 물리적 접근이나 무선 통신 구간 탈취로 인해 원본 이미지가 유출되거나 변조된 이미지가 주입될 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low
- **대응 방안:** 전송 구간 TLS 1.3 암호화 적용, 디바이스 인증서 기반 상호 인증(Mutual Authentication) 구현, 이미지 데이터에 대한 무결성 검증(Hashing) 로직 추가.
