# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 다중 환경 요인 기반의 농기계 고장 재판정 알고리즘 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 단순 에러 카운트 기반의 진단은 농기계의 가혹한 작업 환경(진동, 습도, 부하 등)으로 인해 일시적인 센서 오류나 노이즈를 실제 고장으로 오판할 확률이 높음. 이로 인해 불필요한 유지보수 비용과 가동 중단(Downtime) 발생. |
| **결정(Decision)** | 기초 진단 결과에 대하여 '고장 여부 재 판정부(112)'를 도입하고, 환경적 요인, 부품별 특징 요인, 추가 연료 소모량 등 외부 변수를 통합 분석하여 '최종 진단 결과'를 산출하는 다중 계층 진단 아키텍처를 구축함. |
| **근거(Rationale)** | 하드웨어 교체 없이 소프트웨어 로직만으로 진단 정확도를 높일 수 있으며, 특히 연료 소모량과 같은 물리적 출력 지표를 교차 검증(Cross-validation) 수단으로 활용하여 고장의 실체성을 확보하기 위함. |
| **결과(Consequences)** | (긍정적) 오진율 감소로 인한 AS 비용 절감 및 사용자 신뢰도 향상. (부정적) 진단 모듈의 연산 복잡도 증가 및 다양한 환경 데이터를 수집/처리하기 위한 데이터 파이프라인의 관리 부하 발생. |
| **트레이드오프(Trade-offs)** | 실시간 응답성(Latency)보다는 진단 데이터의 신뢰성(Reliability)에 우선순위를 두었으며, 이를 위해 추가적인 데이터 분석 단계(재판정 로직)를 아키텍처에 포함함. |

---

## ⚠️ 잠재적 위험 분석

### 1. 외부 환경 데이터의 신뢰성 결여
- **설명:** '환경적 요인'을 수집하는 센서 자체가 오작동하거나 통신 장애가 발생할 경우, 재판정 로직이 잘못된 가중치를 적용하여 최종 진단 결과가 왜곡될 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 환경 데이터의 유효 범위(Boundary)를 설정하고, 센서 값의 급격한 변동 시 이전 데이터를 참조하거나 기본값(Default)을 사용하는 폴백(Fallback) 메커니즘 구축.

### 2. 제어 모듈(120) 피드백 루프의 불안정성
- **설명:** 최종 진단 결과가 제어 모듈로 전달되어 농기계(200)의 동작을 제한할 때, 오진으로 인한 가동 중단이나 부적절한 제어 명령이 실시간으로 수행될 위험이 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 제어 명령 수행 전 사용자 단말(300)을 통한 승인 프로세스를 도입하거나, 긴급 정지가 아닌 성능 제한(Limp-home mode) 단계별 제어 전략 수립.

### 3. 데이터 동기화 및 지연 문제
- **설명:** 농기계에서 발생한 에러 카운트와 당시의 연료 소모량, 환경 데이터 간의 타임스탬프(Timestamp)가 일치하지 않아 잘못된 시점의 데이터를 결합 분석할 위험.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 모든 컴포넌트에 대한 정밀한 시간 동기화(NTP/PTP)를 적용하고, 진단 모듈 유입 시 시계열 데이터 정렬(Data Alignment) 버퍼링 레이어 추가.

### 4. 사용자 단말(300) 통신 보안 및 가용성
- **설명:** 진단 결과가 사용자 단말로 전송되는 과정에서 데이터가 위변조되거나, 통신 음영 지역에서 중요한 고장 알림이 누락되어 대형 사고로 이어질 위험.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 종단간 암호화(E2EE) 적용 및 통신 단절 시 로컬 저장소에 결과 보관 후 재접속 시 자동 재전송(Store-and-Forward) 기능 구현.

### 5. 재판정 알고리즘의 모델 드리프트(Model Drift)
- **설명:** 특정 부품의 노후화나 신규 모델 도입 시, 고정된 재판정 로직이 변화된 부품 특징(112 관련)을 반영하지 못해 시간이 흐를수록 진단 정확도가 하락할 위험.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 주기적인 진단 결과 데이터 로깅을 통한 알고리즘 성능 모니터링 및 무선 업데이트(OTA)를 통한 진단 모델 업데이트 체계 마련.
