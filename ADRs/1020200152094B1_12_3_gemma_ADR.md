# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 이기종 데이터 통합을 위한 이벤트 기반 마이크로서비스 아키텍처 도입

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 본 시스템은 시설 설치, 재배 교육, 원격 모니터링 등 매우 다양한 기능과 역할을 수행합니다. 주요 데이터 소스는 현장 센서(환경, 생체 데이터), 기계 제어 시스템(PLC), 상업 데이터(시세), 그리고 사용자 인터페이스(VR/웹) 등 이질적(Heterogeneous)이며 비동기적인 데이터를 발생시킵니다. 단일 통합 시스템으로는 이러한 방대한 데이터 흐름, 상이한 데이터 수명 주기(실시간 센서 데이터 vs. 정적 시세 데이터), 그리고 높은 확장성을 동시에 확보하기 어렵습니다. |
| **결정(Decision)** | 시스템 백엔드 아키텍처는 **이벤트 스트리밍(Event Streaming)**을 핵심 메커니즘으로 사용하고, 각 기능별 데이터 처리/분석 로직은 **마이크로서비스(Microservices)**로 분리하여 구축합니다. 모든 서비스는 표준화된 API 게이트웨이를 통해 통신하며, 데이터 교환 포맷은 ISA-95 또는 ISO/IEC 30141 기반의 공통 데이터 모델을 채택합니다. |
| **근거(Rationale)** | **1. 확장성 및 복원력:** 마이크로서비스는 개별 기능(예: 환경 모니터링 서비스, 시세 예측 서비스, VR 콘텐츠 제공 서비스)의 독립적인 배포와 확장을 가능하게 하여 시스템 전체의 안정성을 높입니다. **2. 실시간 처리:** 이벤트 스트리밍(예: Kafka 사용)을 도입하여 센서 데이터가 발생하는 즉시(Real-time) 데이터 파이프라인을 통해 처리 및 분석되어 VR 시뮬레이션이나 원격 모니터링에 즉각적으로 반영될 수 있습니다. **3. 상호운용성:** 표준화된 이벤트 및 API 게이트웨이를 사용함으로써, 향후 새로운 스마트팜 기자재나 다른 분석 모델을 쉽게 통합할 수 있으며, 국제 표준(ISO/IEC 30141) 준수를 용이하게 합니다. |
| **결과(Consequences)** | **긍정적:** 각 모듈의 독립적인 개발 및 배포가 가능해 개발 속도(Time-to-market)와 유연성이 극대화됩니다. 센서 데이터의 지연 시간(Latency)을 최소화하여 교육의 몰입도와 모니터링의 정확도를 높일 수 있습니다. **부정적:** 시스템의 복잡성이 매우 높아져 초기 아키텍처 설계와 서비스 간의 인터페이스 정의에 막대한 노력이 필요하며, 운영 단계에서 모니터링(Observability)이 매우 어려워질 수 있습니다. |
| **트레이드오프(Trade-offs)** | **획득 장점:** 높은 확장성, 실시간 처리 능력, 시스템의 모듈성(Microservices)을 확보하여 미래의 기능 추가에 유연하게 대응 가능. **감수 단점:** 높은 초기 설계 복잡도와 운영 복잡성(OpEx) 증가. 따라서 자동화된 서비스 메시(Service Mesh)와 통합 로깅/모니터링 시스템(ELK Stack 등) 도입이 필수적입니다. |

## ⚠️ 잠재적 위험 분석

### 1. 데이터 전송 및 서버 보안 위협 (Cybersecurity Risk)
- **설명:** 현장의 수많은 센서 노드(Edge Device)와 데이터 전송 게이트웨이가 해킹 공격을 받을 경우, 핵심 농장 데이터(생체 데이터, 환경 제어 값)가 유출되거나 변조될 수 있습니다. 이는 단순한 정보 손실을 넘어 실제 농장의 재배 환경 오작동(예: 펌프/밸브 제어값 조작)을 유발할 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:**
    1. **보안 계층:** 모든 통신 구간에 TLS/SSL 암호화를 의무화하고, 펌웨어 및 OS 레벨의 보안 패치를 주기적으로 적용합니다.
    2. **접근 제어:** 역할 기반 접근 제어(RBAC)를 구현하여 원격 관리자가 필요한 범위의 데이터에만 접근하도록 제한합니다.
    3. **모니터링:** SIEM(Security Information and Event Management) 시스템을 도입하여 비정상적인 데이터 접근 및 명령을 24시간 실시간 모니터링합니다.

### 2. 이기종 데이터 표준화 및 상호운용성 실패 (Interoperability Risk)
- **설명:** 스마트팜은 온도/습도 센서(Analog), 액추에이터(Digital/PLC), 기상 관측 장비(Protocol A), 농장 관리 시스템(Database B) 등 수많은 이질적 시스템이 존재합니다. 이들이 사용하는 통신 프로토콜(Modbus, BACnet, MQTT 등)과 데이터 포맷이 표준화되지 않으면, 데이터 수집 과정에서 누락, 해석 오류, 또는 데이터 불일치(Data Drift)가 발생합니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:**
    1. **표준화:** 데이터 통합 계층(Data Ingestion Layer)에 게이트웨이 모듈을 구축하고, 반드시 ISA-95 또는 ISO/IEC 30141에 준하는 공통 데이터 모델링을 적용하여 모든 데이터 포맷을 통일합니다.
    2. **데이터 검증:** 수집된 데이터에 대해 유효성 검사(Validation) 및 시간 동기화(Time Synchronization) 프로세스를 의무화합니다.
    3. **API 계약:** 모든 데이터 흐름은 명시적인 API 계약(Contract)을 기반으로 합니다.

### 3. 실시간 처리 지연(Latency)으로 인한 교육 및 제어 오류 (Performance Risk)
- **설명:** VR 시뮬레이션이나 원격 모니터링 기능의 핵심은 '현실과 지연 없이 연결된 느낌'입니다. 만약 센서 데이터 수집 -> 서버 처리 -> VR 엔진 렌더링 과정에서 지연(Latency)이 발생한다면, 교육의 몰입도가 심각하게 떨어지고, 원격 제어 명령이 늦게 반영될 경우 작물 생육에 치명적인 오류를 초래할 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:**
    1. **엣지 컴퓨팅 도입:** 센서 데이터 전처리 및 즉각적인 제어 로직(예: 과습 감지 시 경고)은 클라우드가 아닌 현장 게이트웨이(Edge Gateway)에서 처리합니다.
    2. **최적화:** 데이터 파이프라인 전체에 대해 End-to-End 레이턴시를 측정하고, 실시간 스트리밍 기술(예: Apache Kafka, MQTT)과 고성능 메시지 브로커를 사용합니다.
    3. **QoS 보장:** 핵심 제어 명령어는 낮은 지연 시간(Low Latency)의 전송 프로토콜을 사용하도록 우선순위를 설정합니다.

### 4. VR/가상 환경과 실제 물리 환경 간의 괴리 (Cognitive Load Risk)
- **설명:** VR 교육 시스템은 사용자가 가상 세계에서 배운 지식(재배 교육)을 현실에 적용하는 과정이 필수적입니다. 만약 시뮬레이션 모델이 현실의 물리적 제약, 생물학적 반응, 또는 복잡한 농업 과정을 정확하게 반영하지 못할 경우, 사용자에게 잘못된 지식(Misconception)을 심어주거나, 시스템의 신뢰도를 잃게 만듭니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:**
    1. **Domain Expert 검토:** 교육 시나리오 및 시뮬레이션 로직 설계 단계에 반드시 농업 및 관련 산업 도메인 전문가(Domain Experts)를 참여시켜 콘텐츠의 현실성을 검증합니다.
    2. **피드백 루프:** 시뮬레이션 결과를 '최적의 가이드'가 아닌 '시뮬레이션 기반 예측 결과'로 명확히 고지하고, 실제 현장 데이터를 기반으로 검증하는 피드백 루프를 구축합니다.

### 5. 원격 관리 시스템의 사용자 인터페이스 복잡성 및 활용도 저하 (Usability Risk)
- **설명:** 원격 관리자는 모니터링 화면(Dashboard)에서 센서 데이터, 시세 데이터, 시스템 경고 알림 등 너무 많은 정보를 한 번에 받게 됩니다. 정보 과부하(Information Overload)가 발생하여, 실제 시스템 오류나 위험 신호를 파악하는 데 어려움을 겪을 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low
- **대응 방안:**
    1. **대시보드 설계:** 원격 모니터링 화면을 목적별(환경 모니터링 전용, 재정/시세 분석 전용, 설비 상태 전용)로 분리하거나, 사용자 역할에 따라 맞춤형 워크스페이스를 제공합니다.
    2. **알림 시스템:** 단순한 데이터 나열 대신, 임계치 초과, 추세 변화, 장비 고장 등 **'액션이 필요한'** 정보만을 강조하여 게이팅(Gating)합니다.
    3. **경고 우선순위:** 경고에 명확한 심각도 레벨(Critical, High, Low)과 조치 지침(Action Plan)을 포함시켜 정보 활용도를 높입니다.
