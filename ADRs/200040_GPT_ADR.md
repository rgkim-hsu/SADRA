📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 중앙 집중형 IoT 환경 제어 컨트롤러 아키텍처 채택

| 항목                     | 내용                                                                                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 시스템은 스마트팜 또는 시설 환경에서 환풍기, 스프링클러, 조명, 관수설비, 난방 등 다양한 장치를 제어해야 한다. 여러 장치를 개별적으로 제어할 경우 관리 복잡성이 증가하고 일관된 제어가 어렵다. 핵심 과제는 “다양한 환경 제어 장치를 통합적으로 관리하고 자동화하는 것”이다. |
| **결정(Decision)**       | 스마트 시스템 컨트롤러(Smart System Controller)를 중심으로 각 제어기(환풍기, 스프링클러, 조명, 관수설비, 난방)를 연결하여 중앙에서 통합 제어하는 아키텍처를 채택한다.                                                  |
| **근거(Rationale)**      | 중앙 집중형 구조는 제어 로직을 통합하여 관리할 수 있고, 자동화 및 정책 기반 제어를 쉽게 구현할 수 있다. 또한 사용자 인터페이스를 통해 전체 시스템 상태를 한눈에 파악할 수 있다.                                                     |
| **결과(Consequences)**   | **긍정적:** 통합 관리 용이성, 자동화 제어 가능, 운영 효율성 향상, 유지보수 편의성 증가**부정적:** 단일 장애점(SPOF) 발생 가능, 확장성 제한                                                                    |
| **트레이드오프(Trade-offs)** | 관리 편의성과 제어 일관성을 확보하는 대신, 시스템 장애 시 전체 영향 범위가 커지는 리스크를 감수해야 한다.                                                                   |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. 단일 장애점(SPOF)

* **설명:** 중앙 컨트롤러 장애 시 전체 제어 시스템 중단

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 이중화(HA), 장애 대응 failover 시스템 구축

### 2. 확장성 한계

* **설명:** 장치 수 증가 시 중앙 시스템 부하 증가

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 분산 제어 구조 도입, 모듈화 설계

### 3. 통신 장애

* **설명:** 컨트롤러와 장치 간 통신 문제로 제어 실패

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 네트워크 이중화, 로컬 제어 fallback

### 4. 제어 로직 오류

* **설명:** 잘못된 설정 또는 알고리즘으로 비정상 제어 수행

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 시뮬레이션 테스트, 정책 검증

### 5. 보안 취약점

* **설명:** 중앙 시스템 해킹 시 전체 장치 제어 위험

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 인증/인가 강화, 네트워크 보안 적용

### 6. 실시간 제어 지연

* **설명:** 중앙 처리 지연으로 즉각적인 제어 어려움

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 엣지 제어 병행, 실시간 처리 최적화

### 7. 유지보수 부담

* **설명:** 중앙 시스템 업데이트 시 전체 영향 발생

* **심각도:** 🟢 Low

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 단계적 배포, 롤백 전략 마련
