# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### **ADR-001: 모듈별 데이터 처리 파이프라인 구축 및 표준화**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜/농업 IoT 시스템에서 **생육 정보 분석**을 위한 데이터 처리 파이프라인이 존재하지 않음. 현존하는 TTA 표준 및 ISO/IEC 30141:2024의 요구사항에 따라 **데이터 로딩부터 생육 정보 분석까지의 일관된 처리 흐름**이 필요함. 또한, **이상 데이터 처리**와 **상관 관계 분석**을 통해 신뢰성 있는 생육 정보 추출이 필수적임. |
| **결정(Decision)** | 1. **5단계 모듈 구조** (데이터 로딩 → 전처리 → 이상 데이터 분석 → 상관 관계 분석 → 생육 정보 분석)로 파이프라인을 구축 <br> 2. **oneM2M 표준**을 기반으로 모듈 간 API 통신을 표준화 <br> 3. **ETSI EN 303 645** 보안 요구사항을 준수하여 모듈 간 데이터 전송 보안 강화 <br> 4. **ISO/IEC 27030:2020** 가이드라인에 따라 이상 데이터 분석 모듈 설계 <br> 5. **TTA 단체표준 (스마트팜 데이터 상호운용 프레임워크)**를 적용하여 생육 정보 분석 결과 표준화 |
| **근거(Rationale)** | - **ISO/IEC 30141:2024**는 IoT 시스템의 참조 아키텍처를 제공하며, **재사용 가능한 설계**를 강조 <br> - **oneM2M**은 글로벌 IoT 표준으로 모듈 간 상호운용성을 보장 <br> - **ETSI EN 303 645**는 IoT 기기 보안을 위한 필수 표준 <br> - **TTA 스마트팜 표준**은 국내 법적/산업적 요구사항을 충족 <br> - **이상 데이터 처리**는 생육 정보 신뢰성을 높이는 핵심 요소로, **ISO/IEC 27030**이 안전한 설계에 필수적임 |
| **결과(Consequences)** | ✅ **장점**: <br> - 모듈별 표준화로 시스템 확장성 및 유지보수 용이 <br> - 글로벌/국내 표준 준수로 시장 경쟁력 강화 <br> - 이상 데이터 처리 및 상관 분석으로 생육 정보 정확도 향상 <br> ❌ **단점**: <br> - 초기 구축 비용 및 복잡성 증가 <br> - 모듈 간 의존성으로 변경 시 영향 분석 필요 |
| **트레이드오프(Trade-offs)** | - **표준 준수 vs. 성능**: oneM2M 표준 준수로 성능 저하 가능성, 하지만 글로벌 시장에서 필수적 <br> - **보안 강화 vs. 복잡성**: ETSI EN 303 645 준수로 시스템 복잡도 증가, 하지만 보안 취약성 최소화 <br> - **모듈화 vs. 통합 처리**: 모듈별 처리로 유연성 향상, 하지만 통합 분석 시 지연 가능성 |

### **ADR-002: 데이터 처리 모듈의 실시간 처리 요구사항**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 시스템에서 **생육 정보**는 실시간으로 수집되어야 하며, **이상 데이터 분석**과 **상관 관계 분석**도 지연 없이 수행되어야 함. 그러나, **전처리 모듈**의 복잡성으로 인해 처리 지연이 발생할 수 있음. |
| **결정(Decision)** | 1. **이상 데이터 분석 모듈**과 **상관 관계 분석 모듈**에 **에지 컴퓨팅** 적용 <br> 2. **MQTT 프로토콜**을 사용하여 실시간 데이터 스트리밍 <br> 3. **CoAP 프로토콜**을 보조로 사용해 경량 데이터 전송 지원 <br> 4. **데이터 로딩 모듈**에 **버퍼링 메커니즘** 도입하여 일시적 지연 완화 |
| **근거(Rationale)** | - **MQTT/CoAP**: IETF 표준으로 실시간 IoT 통신에 최적화 <br> - **에지 컴퓨팅**: 중앙 서버 부하 감소 및 실시간 처리 보장 <br> - **버퍼링**: 데이터 로딩 지연을 완화하며, **TTA 스마트팜 데이터 관리 요구사항** 충족 |
| **결과(Consequences)** | ✅ **장점**: <br> - 실시간 생육 정보 분석 가능 <br> - 네트워크 부하 감소 <br> ❌ **단점**: <br> - 에지 장비 추가 비용 발생 <br> - 프로토콜 전환으로 복잡성 증가 |
| **트레이드오프(Trade-offs)** | - **실시간성 vs. 비용**: 에지 컴퓨팅으로 성능 향상, 하지만 하드웨어 비용 증가 <br> - **프로토콜 다양성 vs. 통합 관리**: MQTT/CoAP 혼용으로 유연성 향상, 하지만 네트워크 관리 복잡성 증가 |

### **ADR-003: 생육 정보 분석 결과 저장 및 공유 표준화**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 생육 정보 분석 결과는 **다양한 스테이크홀더** (농부, 연구자, 정부 기관)에게 공유되어야 하며, **Matter 표준**이나 **OCF 프레임워크**와 호환 가능한 형태로 저장되어야 함. |
| **결정(Decision)** | 1. **생육 정보 분석 결과**를 **JSON/Protobuf** 형식으로 표준화 <br> 2. **OCF 프레임워크**를 기반으로 데이터 공유 API 제공 <br> 3. **블록체인 기술**을 도입하여 데이터 무결성 보장 (선택사항) <br> 4. **TTA 스마트팜 데이터 상호운용 프레임워크**에 따라 메타데이터 표준화 |
| **근거(Rationale)** | - **JSON/Protobuf**:轻量且广泛支持的数据交换格式 <br> - **OCF 프레임워크**: 스마트홈/스마트팜 간 상호운용성 보장 <br> - **블록체인**: 데이터 위변조 방지 및 신뢰성 강화 (필요 시) <br> - **TTA 표준**: 국내 법적 요구사항 충족 |
| **결과(Consequences)** | ✅ **장점**: <br> - 글로벌/국내 표준 호환성 확보 <br> - 데이터 공유 및 재사용성 향상 <br> ❌ **단점**: <br> - 블록체인 도입 시 처리 지연 및 비용 증가 |
| **트레이드오프(Trade-offs)** | - **표준화 vs. 유연성**: OCF 표준 준수로 호환성 향상, 하지만 새로운 프로토콜 도입 시 유연성 제한 <br> - **무결성 vs. 성능**: 블록체인으로 데이터 신뢰성 강화, 하지만 처리 속도 저하 가능성 |

## ⚠️ 잠재적 위험 분석

### **1. 데이터 품질 저하 및 이상 데이터 누락**
- **설명**: 전처리 모듈에서 **이상 데이터**가 필터링되지 않거나, **상관 관계 분석**에서 오류가 발생하여 **생육 정보 분석 결과**가 왜곡될 수 있음. 특히, 센서 오류나 네트워크 지연으로 인해 **이상치**가 누락되거나 오류로 처리될 위험이 있음.
- **심각도**: 🔴 High
- **발생 가능성**: 🔴 High
- **대응 방안**:
  - **이상 데이터 분석 모듈**에 **기계 학습 기반 이상치 검출** (예: Isolation Forest, Autoencoder) 도입
  - **다중 센서 교차 검증** 메커니즘 구현 (예: 같은 환경 변수를 측정하는 센서 간 일치성 확인)
  - **ETSI EN 303 645** 준수하여 **센서 데이터 유효성 검사** 프로토콜 적용

### **2. 모듈 간 통신 지연 및 시스템 병목**
- **설명**: **데이터 로딩 → 전처리 → 이상 데이터 분석 → 상관 관계 분석**과 같은 **시퀀셜 처리**로 인해 전체 파이프라인에서 병목 현상이 발생할 수 있음. 특히, **상관 관계 분석 모듈**이 대량의 데이터를 처리해야 하는 경우 지연이 발생할 수 있음.
- **심각도**: 🟡 Medium
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **에지 컴퓨팅**을 통해 **이상 데이터 분석**과 **상관 관계 분석**을 분산 처리
  - **MQTT QoS Level 1/2**를 활용하여 실시간 데이터 스트리밍 보장
  - **로드 밸런싱**을 위한 **Kafka** 또는 **RabbitMQ** 도입 (대용량 데이터 처리 시)

### **3. 보안 취약성 및 데이터 유출 위험**
- **설명**: 모듈 간 통신에서 **ETSI EN 303 645** 표준을 준수하지 않거나, **API 인증/인가**가 약화되면 **데이터 유출**이나 **중간자 공격** 위험이 존재함. 특히, **IoT 기기**는 물리적 접근성으로 인해 보안 취약점이 높음.
- **심각도**: 🔴 High
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **TLS 1.3**을 필수적으로 적용한 **모듈 간 통신** 구현
  - **OAuth 2.0** 또는 **JWT**를 사용하여 API 인증 강화
  - **KISA IoT 보안 가이드라인**에 따라 **기기 인증** 및 **네트워크 분할** 적용
  - **정기적 보안 패치** 및 **침입 탐지 시스템 (IDS)** 배포

### **4. 표준 호환성 문제 및 글로벌 시장 진입 장애**
- **설명**: **oneM2M**, **OCF**, **Matter** 등 글로벌 표준과 **TTA 국내 표준** 간의 호환성 문제가 발생할 수 있음. 특히, **생육 정보 분석 결과**가 기존 시스템과 호환되지 않으면 **스마트팜 플랫폼**으로의 통합이 어려워질 수 있음.
- **심각도**: 🟡 Medium
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **ISO/IEC 30141:2024**를 기반으로 **아다프터層** 구현하여 표준 간 변환 지원
  - **oneM2M Common Service Layer (CSL)**을 통해 글로벌 호환성 확보
  - **TTA 스마트팜 표준**과 **OCF/Matter** 간의 **매핑 테이블** 작성 및 공유

### **5. 시스템 확장성 저하 및 유지보수 복잡성**
- **설명**: 모듈별로 **독립적인 개발**이 진행되면, **의존성 관리**가 어려워져 시스템 확장 시 **호환성 문제**가 발생할 수 있음. 또한, **생육 정보 분석 알고리즘**이 변경될 경우 전체 파이프라인에 영향을 미칠 수 있음.
- **심각도**: 🟡 Medium
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **마이크로 서비스 아키텍처**를 적용하여 모듈별 독립적 배포 및 업데이트 지원
  - **CI/CD 파이프라인** 구축하여 자동화된 테스트 및 배포 관리
  - **API 버전 관리**를 통해 후방 호환성 보장
  - **생육 정보 분석 모듈**에 **플러그인 구조** 도입하여 알고리즘 교체 용이성 향상

**※ 추가 고려사항**:
- **에지 vs. 클라우드 처리**의 트레이드오프를 명확히 정의하여 **비용/성능** 최적화
- **국내외 표준 동향**을 주기적으로 모니터링하여 **신규 표준 적용** 준비
- **스마트팜 데이터 상호운용 프레임워크**를 기반으로 **파트너사와의 협업** 강화
