📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 스마트팜 로봇팔 중심의 멀티센서 통합 제어 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                            |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 환경에서 작물 재배 최적화를 위해 가상센서, 공간센서, 지온센서, CO2센서 등 이기종 다중 센서로부터 실시간 환경 데이터를 수집하고, 이를 기반으로 로봇팔이 물리적 작업(확장/축소/회전)을 정밀 수행해야 하는 복합 제어 시스템이 요구됨. 제어부-로봇팔-센서군 간의 명령·피드백 데이터 흐름을 단일 파이프라인으로 통합 관리해야 하는 아키텍처적 과제가 존재함. |
| **결정(Decision)**       | 제어부(Controller)를 단일 중앙 오케스트레이터로 설계하고, 로봇팔을 물리적 액추에이터이자 센서 데이터 수집 허브(Gateway)로 활용하는 계층형(Hierarchical) 제어 아키텍처를 채택함. 센서군(가상·공간·지온·CO2)은 로봇팔을 통해 병렬로 데이터를 수집하며, 제어부는 확장/축소/회전 제어신호를 단방향으로 발행함.                   |
| **근거(Rationale)**      | ① 4종 센서의 이기종 프로토콜(아날로그/디지털/I2C/UART 혼재 가능성)을 로봇팔 단에서 표준화하여 제어부 복잡도를 감소시킴. ② 스마트팜 특성상 온·습도, CO2, 토양온도의 복합 환경변수를 실시간 연동해야 하므로 중앙 집중식 의사결정이 응답 지연을 최소화함. ③ 로봇팔이 물리적 도달 범위 내 센서 위치를 동적으로 조정 가능하여 공간 효율성 극대화.      |
| **결과(Consequences)**   | ✅ 긍정적: 제어 로직 단순화, 센서 데이터 일관성 확보, 중앙 집중 모니터링 용이. 단일 인터페이스로 운영자 개입 최소화. ❌ 부정적: 제어부 단일 장애점(SPOF) 리스크 증가. 로봇팔이 센서 허브 역할을 겸하므로 기구학적 결함 발생 시 센서 데이터 수집도 동시 중단됨.                                                     |
| **트레이드오프(Trade-offs)** | 🟢 얻는 장점: 시스템 통합 복잡도 감소, 배선 단순화, 단일 펌웨어 관리. 🔴 감수할 단점: 제어부·로봇팔 가용성에 전체 시스템 의존, 수평 확장(Scale-out) 시 제어부 병목 발생 가능, 센서 추가 시 로봇팔 인터페이스 재설계 필요.                                                                     |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. 제어부 단일 장애점(SPOF) 에 의한 전체 시스템 다운

* **설명:** 제어부가 유일한 오케스트레이터로 설계되어 있어, 하드웨어 결함·소프트웨어 행(Hang)·전원 이상 발생 시 로봇팔 제어신호가 완전 차단됨. 스마트팜 특성상 야간·주말 무인 운영 중 장애 시 작물 피해로 직결됨.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 제어부 이중화(Active-Standby 또는 Active-Active 구성) 도입. Watchdog Timer 기반 자동 재시작 메커니즘 구현. 제어부 장애 시 로봇팔이 마지막 안전 포지션(Home Position)으로 자동 복귀하는 Fail-Safe 로직 펌웨어에 내장.

### 2. 로봇팔 기구학적 결함에 의한 센서 데이터 수집 동시 중단

* **설명:** 로봇팔이 액추에이터와 센서 허브 역할을 겸하므로, 서보모터 소손·감속기 파손·케이블 단선 등 기구부 결함 발생 시 물리적 작업 중단과 함께 가상·공간·지온·CO2 4종 센서 데이터 수집이 동시에 불가해짐. 환경 모니터링 공백이 장기화될 경우 작물 생육 환경이 임계치를 초과할 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 센서군을 로봇팔과 독립된 고정형 보조 센서 네트워크로 이중화하여 로봇팔 결함 시에도 환경 데이터 수집을 지속. 로봇팔 관절별 전류·토크 모니터링을 통한 예지보전(Predictive Maintenance) 시스템 구축.

### 3. 실시간 제어신호와 센서 데이터 간 타이밍 동기화 실패

* **설명:** 제어부가 확장/축소/회전 제어신호를 발행하는 동시에 4종 센서로부터 비동기적으로 데이터를 수신할 경우, 로봇팔 이동 중 진동·전자기 간섭(EMI)으로 센서 샘플링 타이밍이 어긋나 잘못된 환경 측정값이 제어 피드백 루프에 유입될 수 있음. 특히 지온센서(토양 온도)와 CO2센서는 응답 지연 특성이 있어 제어 사이클과 미스매치 발생 가능.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 로봇팔 정지 상태에서만 센서 샘플링을 수행하는 Move-Stop-Sense 시퀀스 정책 도입. 제어 루프와 센서 수집 루프를 분리된 스레드/태스크로 구현하고 타임스탬프 기반 데이터 유효성 검증 로직 적용.

### 4. 센서 데이터 무결성 훼손 및 사이버 보안 위협

* **설명:** 개념도 상 제어부-로봇팔-센서 간 통신 보안 계층이 명시되어 있지 않음. 외부 네트워크 연동(클라우드 모니터링, 원격 제어) 시 중간자 공격(MITM)이나 센서 스푸핑을 통해 허위 CO2·온도 데이터가 주입될 경우, 제어부가 잘못된 환경 판단을 내려 작물에 물리적 피해를 줄 수 있음. 스마트팜 시스템은 농업 인프라 보안 취약 사례가 다수 보고됨.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 제어부-로봇팔 간 통신에 TLS/DTLS 암호화 및 디바이스 인증서 기반 상호 인증 적용. 센서 데이터에 허용 범위 기반 이상치 필터(Anomaly Filter) 구현. 네트워크 세그멘테이션을 통해 제어망과 외부 모니터링망 분리.

### 5. 스마트팜 환경 특수성에 의한 하드웨어 내구성 저하

* **설명:** 스마트팜 내부는 고습도(상대습도 80~95%), 농약·비료 에어로졸, 급격한 온도 변화 등 가혹한 환경 조건이 상시 존재함. 현재 개념도에서는 로봇팔 및 센서군의 IP 등급(방수·방진)과 내화학성 요구사항이 명시되어 있지 않아, 장기 운영 시 부식·결로·절연 파괴로 인한 오작동 및 안전사고 위험이 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 로봇팔 구동부 및 전장부 IP65 이상 등급 인증 부품 채택 의무화. 센서 모듈에 방습 코팅(Conformal Coating) 처리 적용. 정기적인 절연 저항 측정 및 케이블 피복 상태 점검 PM(예방정비) 주기 수립. 전장함(Control Box)에 항온항습 유닛 설치 검토.

### 6. 가상센서(Virtual Sensor) 모델 신뢰도 저하 위험

* **설명:** 개념도에 '가상센서'가 물리 센서(공간·지온·CO2)와 동일한 계층에 존재함. 가상센서는 물리 센서 데이터를 기반으로 소프트웨어적으로 값을 추정하는 모델인데, 학습 데이터 분포를 벗어난 극단적 환경 조건(이상 기후, 병해충 발생)에서 추정 오차가 급증할 수 있음. 제어부가 가상센서 값을 물리 센서와 동등하게 신뢰할 경우 잘못된 제어 결정으로 이어짐.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 가상센서 출력에 신뢰구간(Confidence Interval) 메타데이터를 함께 전달하고, 신뢰도가 임계치 이하일 경우 물리 센서 값을 우선 사용하는 Fallback 정책 제어부 로직에 명시적으로 구현. 정기적인 가상센서 모델 재학습(Re-training) 파이프라인 운영.
