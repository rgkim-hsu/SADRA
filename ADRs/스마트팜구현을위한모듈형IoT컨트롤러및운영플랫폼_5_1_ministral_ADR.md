## 📋 ADR (Architecture Decision Record)

### **ADR-001: IoT 기반 스마트 농업 플랫폼의 모듈형 컨트롤러 아키텍처 채택**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 **원격제어, 실시간 모니터링, 데이터 통합**을 통해 농업 생산성을 향상시키는 IoT 플랫폼을 구축해야 함. 기존 중앙집중식 아키텍처는 확장성, 유연성, 장비 다변화에 제약이 있으며, 농업 현장의 다양한 센서/액추에이터(토양, 기상, 관수장비 등)를 통합 관리해야 함. 또한, **국내외 표준 준수(ISO/IEC 30141, oneM2M, ITU-T X.1352)**와 **보안 요구사항**을 충족해야 함. |
| **결정(Decision)** | 1. **모듈형 IoT 컨트롤러 아키텍처** 채택: 각 장비(거적제어, 환기제어, 관수제어 등)에 **독립적 IoT 컨트롤러** 배치하여 분산 처리 및 실시간 제어 가능하게 함.<br>2. **통합 모니터링 플랫폼** 구축: 모든 컨트롤러로부터 수집된 데이터를 **무선공유기(로컬 네트워크)**를 통해 클라우드/에지 서버로 전송하고, **스마트폰 앱**을 통해 사용자에게 제공.<br>3. **표준 프로토콜 기반 통신**: **MQTT/CoAP**를 기본 프로토콜로 채택하여 경량 통신 및 에너지 효율성 확보.<br>4. **보안 강화**: ITU-T X.1352 및 ISO/IEC 27030 표준에 따라 **기기 인증, 데이터 암호화, 접근 통제** 구현. |
| **근거(Rationale)** | - **모듈형 아키텍처**: 장비별 독립적 제어로 **유연성**과 **확장성** 향상 (예: 새로운 센서/액추에이터 추가 시 기존 시스템 변경 최소화).<br>- **분산 처리**: 네트워크 단절 시 로컬 컨트롤러가 **장비 제어 유지** 가능.<br>- **표준 준수**: oneM2M 및 ISO/IEC 30141 표준을 통해 **상호운용성**과 **글로벌 시장에서의 경쟁력** 확보.<br>- **보안**: KISA가 제안한 ITU-T X.1352 표준을 기반으로 **기기 보안 인증** 및 **데이터 무결성** 보장. |
| **결과(Consequences)** | ✅ **장점**:<br> - 장비별 독립적 업그레이드 가능.<br> - 네트워크 장애 시 로컬 제어 유지.<br> - 표준 준수로 글로벌 시장에서의 신뢰성 향상.<br> - 보안 표준 준수로 **사이버 공격 위험 감소**.<br>❌ **단점**:<br> - 초기 구축 비용 증가 (모듈형 컨트롤러 및 네트워크 인프라).<br> - 다중 장비 관리 시 **운영 복잡성** 증가.<br> - 표준 프로토콜 사용 시 **기존 비표준 장비와의 호환성 문제** 발생 가능. |
| **트레이드오프(Trade-offs)** | - **유연성 vs. 비용**: 모듈형 아키텍처는 초기 비용 증가지만 장기적으로 확장성 및 유지보수 비용 절감.<br>- **보안 vs. 성능**: 암호화 및 인증 프로세스는 통신 지연을 유발할 수 있으나, **ITU-T X.1352 표준**을 통해 최적화된 프로토콜(예: MQTT-SN)을 활용하여 성능 저하 최소화.<br>- **표준 준수 vs. 기존 시스템**: 표준 프로토콜 채택으로 **호환성 문제** 발생 가능하나, **TTA 및 KISA가 개발한 변환 게이트웨이**를 통해 기존 시스템과 연계 가능. |

### **ADR-002: 클라우드/에지 하이브리드 데이터 처리 아키텍처**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 농업 현장의 **실시간 데이터 처리** 요구와 **네트워크 환경의 제약** (예: 농촌 지역의 저속 네트워크)을 고려할 때, **로컬 에지 처리**와 **클라우드 중앙 처리**를 통합해야 함. 또한, **사용자 위치에 따른 접근성**과 **데이터 주권**을 고려하여 지역별 데이터 처리 정책을 적용해야 함. |
| **결정(Decision)** | 1. **에지 서버**: 현장 nearby에 **로컬 게이트웨이** 배치하여 실시간 모니터링 데이터 처리 및 로컬 저장.<br>2. **클라우드 동기화**: 에지 서버에서 **요약 데이터**만 클라우드로 전송하여 네트워크 부하 최소화.<br>3. **하이브리드 접근**: 사용자는 **로컬 네트워크** 내에서는 에지 서버에 접근하여 **저지연 모니터링** 가능, 외部에서는 클라우드 플랫폼을 통해 **전체 데이터 분석** 이용.<br>4. **데이터 암호화**: **AES-256**을 사용하여 에지-클라우드 간 데이터 전송 암호화. |
| **근거(Rationale)** | - **에지 처리**: 네트워크 지연 및 대역폭 문제 해결.<br>- **클라우드 동기화**: 장기 트렌드 분석 및 AI 기반 예측 모델 활용 가능.<br>- **하이브리드 접근**: **오프라인 작업 지원** 및 **데이터 주권** 보장.<br>- **표준 준수**: ISO/IEC 27030의 **데이터 보호 가이드라인** 준수. |
| **결과(Consequences)** | ✅ **장점**:<br> - 네트워크 제약 환경에서도 **실시간 모니터링** 가능.<br> - **데이터 처리 비용** 절감 (로컬 처리로 클라우드 부하 감소).<br> - **오프라인 작업 지원**으로 농촌 지역 사용자 친화성 향상.<br>❌ **단점**:<br> - 에지 서버 유지보수 비용 증가.<br> - 데이터 동기화 지연으로 **일관성 문제** 발생 가능.<br> - 지역별 데이터 처리 정책으로 **운영 복잡성** 증가. |
| **트레이드오프(Trade-offs)** | - **성능 vs. 비용**: 에지 서버는 초기 비용 증가지만 **네트워크 효율성**과 **실시간성** 확보.<br>- **데이터 일관성 vs. 오프라인 지원**: 동기화 지연을 최소화하기 위해 **이벤트 소싱 패턴** 채택.<br>- **보안 vs. 접근성**: 지역별 암호화 키 관리로 **운영 복잡성** 증가하나, **KISA의 보안 인증 기준**을 통해 표준화. |

### **ADR-003: 스마트폰 앱 기반 사용자 인터페이스 표준화**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 사용자는 **다양한 기기(스마트폰, 태블릿)**를 통해 시스템에 접근하며, **직관적 UI/UX**와 **표준화된 API**를 통해 일관된 서비스 제공이 필요함. 또한, **국내외 농업 전문가**를 대상으로 **사용자 정의 대시보드**를 지원해야 함. |
| **결정(Decision)** | 1. **모바일 우선 디자인**: **리액티브 프레임워크(Flutter/React Native)**를 사용하여 크로스 플랫폼 지원.<br>2. **표준 API**: **RESTful API + WebSocket**을 통해 실시간 데이터 스트리밍.<br>3. **모듈형 UI**: **기본 대시보드** + **사용자 정의 위젯** 지원 (예: 비료 관리, 기상 경고, 관수 스케줄러).<br>4. **다국어 지원**: 한국어 + 영어 기본 제공, **TTA 표준 용어집** 기반. |
| **근거(Rationale)** | - **크로스 플랫폼**: 개발 비용 절감 및 **유니버설 접근성** 확보.<br>- **실시간 스트리밍**: WebSocket을 통해 **저지연 모니터링** 지원.<br>- **사용자 정의**: 농업 전문가별 **개별화된 서비스** 제공.<br>- **표준 준수**: TTA의 **스마트팜 UI 가이드라인** 준수. |
| **결과(Consequences)** | ✅ **장점**:<br> - **다양한 기기 지원**으로 사용자 접근성 향상.<br> - **실시간 알림**으로 운영 효율성 증가.<br> - **표준화된 UI**로 학습 곡선 감소.<br>❌ **단점**:<br> - 사용자 정의 기능으로 **개발 복잡성** 증가.<br> - 다국어 지원으로 **유지보수 비용** 증가.<br> - WebSocket 사용 시 **네트워크 오버헤드** 발생 가능. |
| **트레이드오프(Trade-offs)** | - **유연성 vs. 복잡성**: 사용자 정의 기능은 **개발 비용** 증가시키지만 **사용자 만족도** 향상.<br>- **실시간성 vs. 네트워크**: WebSocket은 **저지연**이지만, **MQTT와 병행**하여 안정성 확보.<br>- **표준화 vs. 혁신**: TTA 표준 준수하에 **신기술(예: AR 기반 가이드)** 도입 가능. |

## ⚠️ 잠재적 위험 분석

### **1. 네트워크 장애 및 통신 실패**
- **설명**: 농촌 지역의 **불안정 네트워크** 또는 **장비 고장**으로 인해 IoT 컨트롤러와 모니터링 플랫폼 간의 통신이 단절될 경우, **실시간 제어 및 모니터링 실패**로 이어질 수 있음. 특히, **무선공유기 장애** 시 전체 시스템 마비 위험 존재.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **로컬 백업 네트워크**: 이더넷 + 무선 중복 구성.
  - **오프라인 모드 지원**: 에지 서버에서 **로컬 데이터 로깅** 및 **장비 제어 유지**.
  - **자동 재연결 메커니즘**: MQTT의 **QoS Level 1/2** 활용하여 데이터 재전송.
  - **모니터링**: 네트워크 상태 실시간 모니터링 및 **SMS/이메일 경고** 시스템 구축.

### **2. 보안 취약점 및 사이버 공격**
- **설명**: IoT 기기 간의 **약한 인증/암호화** 또는 **표준 미준수**로 인해 **DDoS 공격, 데이터 도난, 기기 해킹** 위험 존재. 특히, **공장 초기 설정 비밀번호**가 변경되지 않은 경우 **원격 제어 침해** 가능성 높음.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **기기 인증**: ITU-T X.1352 표준에 따른 **공개키 기반 인증** 구현.
  - **데이터 암호화**: **AES-256**을 포함한 **엔드투엔드 암호화** 적용.
  - **정기 패치**: **자동 업데이트 시스템**을 통해 보안 패치 배포.
  - **네트워크 분할**: IoT 기기와 모니터링 시스템을 **별도 VLAN**에 배치.
  - **침입 탐지**: **KISA의 IoT 보안 인증 기준**을 기반으로 **행동 기반 탐지** 시스템 도입.

### **3. 데이터 일관성 및 동기화 오류**
- **설명**: 에지 서버와 클라우드 간의 **비동기 데이터 동기화**로 인해 **중복 데이터, 누락 데이터, 또는 일관성 없는 상태** 발생 가능. 특히, **네트워크 지연** 시 **트랜잭션 실패**로 이어질 수 있음.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **이벤트 소싱 패턴**: 모든 데이터 변경 사항을 **이벤트 로그**로 기록하여 재생산성 확보.
  - **체크섬 검증**: 데이터 전송 시 **SHA-256 체크섬**을 통해 무결성 확인.
  - **동기화 큐**: **RabbitMQ**와 같은 메시지 큐를 사용하여 **신뢰성 있는 전송** 보장.
  - **수동 복구 도구**: **데이터 일관성 확인 스크립트**를 정기적으로 실행.

### **4. 확장성 제한 및 성능 병목**
- **설명**: 시스템이 **대량의 IoT 기기**를 지원해야 할 경우, **클라우드 서버의 처리能力** 또는 **데이터베이스 성능**이 병목으로 작용할 수 있음. 또한, **모듈형 컨트롤러의 증가**로 인해 **네트워크 트래픽 과부하** 발생 가능성 존재.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟢 Low (단기적으로)
- **대응 방안**:
  - **마이크로 서비스 아키텍처**: 각 기능(모니터링, 제어, 분석)을 **독립적 서비스**로 분리.
  - **자동 스케일링**: **Kubernetes**를 사용하여 클라우드 리소스 동적 할당.
  - **데이터 샤딩**: **지역별 데이터베이스 샤딩**을 통해 읽기/쓰기 성능 최적화.
  - **에지 캐싱**: **Redis**를 사용하여 **자주 접근 데이터** 로컬 캐싱.

### **5. 운영 및 유지보수 복잡성**
- **설명**: **다양한 장비 및 모듈**으로 구성된 시스템은 **운영 복잡성**을 높일 수 있으며, **전문 인력 부족**으로 인해 **유지보수 지연** 또는 **오류 발생** 가능성 존재. 특히, **표준 미준수 장비**와의 통합 시 **호환성 문제** 발생 가능.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **자동화 도구**: **Ansible** 또는 **Terraform**을 사용하여 인프라 관리 자동화.
  - **문서화 표준**: **TTA 표준 문서화 가이드라인** 준수하여 운영 매뉴얼 작성.
  - **트레이닝 프로그램**: **K-OTT(농업 기술 교육)**와 협력하여 **현장 기술자 교육** 제공.
  - **호환성 레이어**: **변환 게이트웨이**를 통해 **비표준 장비 통합** 지원.
  - **SLA 기반 모니터링**: **서비스 수준 합의(SLA)**를 설정하고 **위반 시 자동 경고** 시스템 구축.
