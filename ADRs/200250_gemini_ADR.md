# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 비동기 메시징 기반의 상태 전이 모델 및 라이프사이클 관리

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 환경에서 클라우드와 현장 장치(스마트베드) 간의 명령 하달 및 실행 상태를 실시간으로 동기화해야 함. 네트워크 불안정성, 자동 제어 로직 간의 충돌, 물리적 센서의 개입 등 복합적인 이벤트 처리 프로세스가 필요함. |
| **결정(Decision)** | 명령의 생명주기를 `NEW` → `WAITING` → `SENT` → `WORKING`으로 이어지는 유한 상태 머신(FSM) 구조로 설계하고, 실행 도중 발생하는 예외 상황(A-Sensor 감지, Stop 명령, 신규 명령 유입)을 즉각적으로 반영할 수 있는 가로채기(Preemption) 로직을 적용함. |
| **근거(Rationale)** | 명령이 대기(`WAITING`) 중일 때 상위 제어 로직이나 새로운 명령에 의해 무효화(`IGNORED`)될 수 있어야 불필요한 장치 구동을 방지할 수 있음. 또한, 실제 구동(`WORKING`) 단계에서 하드웨어 센서(`A-SENSOR`)의 안전 차단 기능을 상태값에 반영하여 데이터 정합성을 확보함. |
| **결과(Consequences)** | 시스템은 모든 제어 명령의 이력을 추적할 수 있으며, 명령 실패 시 어느 단계에서 문제가 발생했는지 명확히 파악 가능함. 또한, 클라우드 기반의 FaaS(Farm as a Service) 아키텍처에서 장치 상태를 가상화하여 관리하기 용이해짐. |
| **트레이드오프(Trade-offs)** | 세밀한 상태 관리로 인해 시스템의 복잡도가 증가하며, 상태 전이 시마다 발생하는 트랜잭션 처리 비용이 발생함. 단순 명령 전달 방식보다 응답 지연(Latency)이 소폭 증가할 수 있음. |

---

## ⚠️ 잠재적 위험 분석

### 1. 분산 환경에서의 상태 불일치 (State Mismatch)
- **설명:** 네트워크 단절로 인해 클라우드에서는 명령이 `SENT` 상태이나, 실제 장치에서는 수신되지 못하거나 이미 `WORKING` 중인 경우 발생하는 불일치 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 멱등성(Idempotency) 설계 적용 및 클라우드-장치 간 주기적인 하트비트(Heartbeat)와 상태 동기화(Reconciliation) 프로세스 구축.

### 2. 센서 기반 강제 종료 시 데이터 유실 (A-Sensor Preemption)
- **설명:** `WORKING` 단계에서 하드웨어 센서(A-Sensor)에 의해 물리적 구동이 중단되었으나, 해당 이벤트가 클라우드에 전달되지 않아 명령이 영원히 `WORKING` 상태에 머무는 경우.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 장치 레벨에서 센서 이벤트를 최우선 순위 메시지로 전송하고, 일정 시간 응답이 없을 경우 클라우드 측에서 타임아웃(Timeout) 기반 자동 종료 처리.

### 3. 명령 경합 및 자원 점유 (Command Race Condition)
- **설명:** `WAITING` 단계에서 '자동 제어'와 '사용자 수동 명령'이 동시에 발생하여 `IGNORED BY NEW COMMAND`와 `SENT` 처리가 겹치며 의도치 않은 동작이 수행되는 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 각 명령에 시퀀스 번호(Sequence Number) 또는 타임스탬프를 부여하고, 장치 내 명령 큐(Queue)에서 우선순위 기반의 원자적(Atomic) 처리를 보장.

### 4. 제어 루프 교란 (Ignored Logic Loop)
- **설명:** 자동 제어 로직이 지속적으로 새로운 명령을 생성하고, 이것이 기존 명령을 `IGNORED BY NEW COMMAND` 처리하면서 실제 장치 구동은 한 번도 일어나지 않는 'Live-lock' 상황.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low
- **대응 방안:** 동일 자원에 대한 명령 생성 주기에 최소 제한(Cool-down time)을 설정하고, 무시된 명령의 비율을 모니터링하여 알림 발송.

### 5. 보안 공격을 통한 비정상 상태 전이
- **설명:** 악의적인 사용자가 메시지 브로커에 접근하여 임의로 `STOPPING BY STOP COMMAND` 메시지를 주입함으로써 스마트팜의 정상적인 작물 재배를 방해하는 행위.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 모든 상태 변경 메시지에 대해 기기별 고유 인증 키 기반의 서명(Signature) 검증을 실시하고, TLS 기반의 암호화 통신 적용.
