🏗️ 아키텍처 분석 보고서
===============

📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 멀티레이어 농업 데이터 통합 플랫폼 기반의 FMIS 중앙화 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                           |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **상황(Context)**        | Kubota KSAS 시스템은 기상/토양/생육/병해충 등 이기종 센싱 데이터와 외부 농업 데이터 조정 플랫폼(농지/지도, 재배 정책, 비료/농약, 성장 모델), 농가 소유 정보 시스템(회계, 유통, GAP 지원)을 동시에 수용해야 한다. 데이터 출처가 자사 기계(트랙터, 이앙기, 드론, 수확기, 건조기)와 타사 농업기계로 분산되어 있으며, 필지 단위 정밀 영농을 위해 토양품질→시비량→수확량→맛 품질까지 수직적 레이어 간 상관관계 분석이 필수적이다. |
| **결정(Decision)**       | KSAS를 단일 FMIS(Farm Management Information System) 허브로 설정하고, ① 데이터 수집 계층(센싱/외부 데이터 조정), ② 저장/레이어링 계층(KSAS Layer Map: 토양품질→토양비옥도→성장→시비→작업경로→수확량→맛 7계층), ③ 빅데이터/AI 분석·처리 계층, ④ 농업 경영계획 출력 계층의 4-tier 아키텍처로 구성한다. 물 관리 시스템은 현장 액추에이터와 직접 연동되는 엣지 제어 루프로 분리 운영한다. |
| **근거(Rationale)**      | 정밀 농업의 핵심인 필지별 처방(variable rate application)을 실현하려면 공간적·시계열적으로 계층화된 데이터 모델이 필요하다. 중앙 FMIS 허브 방식은 타사 기계 데이터의 표준 인터페이스 수용, 일본 내 농업 데이터 조정 플랫폼 연계, 아시아 시장 확장 시 지역별 데이터 거버넌스 대응에 유리하다. 빅데이터+AI 분석을 중앙화함으로써 모델 학습 데이터 축적과 추론 품질을 극대화한다.                           |
| **결과(Consequences)**   | (긍정) 플랜팅→작업→비용분석→시비·방제→물관리→수확까지 전주기 경영계획 자동 생성 가능. 타사 기계 포함 생태계 확장 가능. 데이터 기반 품질(맛·수확량) 예측 고도화. (부정) KSAS 허브 단일 장애점(SPOF) 위험 내재. 농촌 지역 네트워크 의존도 증가. 레이어 간 데이터 정합성 유지 비용 발생.                                                                                  |
| **트레이드오프(Trade-offs)** | 【얻는 것】전사 데이터 일관성, AI 모델 학습 효율, 경영계획 자동화, 타사 생태계 포용. 【감수할 것】중앙 허브 가용성 99.9% 이상 확보를 위한 인프라 비용 증가, 농기계-클라우드 간 실시간 통신 지연 허용 범위 설계 필요, 농가 데이터 주권과 플랫폼 종속성(vendor lock-in) 간 긴장 관계.                                                                                |

### ADR-002: 현장 액추에이터 제어를 위한 엣지-클라우드 하이브리드 제어 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                      |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 논 관개/배수 제어(Water management system)는 수분 센서 감지 후 즉각적 밸브 동작이 필요하며, 네트워크 단절 시에도 현장 제어가 지속되어야 한다. 반면 가변시비(variable rate fertilization), 가변방제(variable pesticide) 등 처방 데이터는 KSAS AI 분석 결과를 기반으로 기계에 내려져야 한다. |
| **결정(Decision)**       | 물 관리·즉시 제어 루프는 현장 엣지 컨트롤러가 자율 처리하고, 경영계획·처방 데이터는 KSAS 클라우드에서 Instruction 채널로 기계에 배포하는 하이브리드 구조를 채택한다. 센싱 데이터는 기계→KSAS 방향의 업스트림, 지시 데이터는 KSAS→기계 방향의 다운스트림으로 단방향 책임을 명확히 분리한다.                           |
| **근거(Rationale)**      | 농촌 환경의 간헐적 네트워크 환경에서 관개/배수 실패는 작물 피해로 직결되므로 엣지 자율성 확보가 필수다. 처방 데이터의 클라우드 중앙 생성은 다필지 최적화 및 AI 모델 활용을 가능케 한다. IEC 61511(기능안전) 관점에서도 안전 임계 제어(물 관리)와 비안전 임계 최적화(처방 생성)의 분리는 설계 원칙에 부합한다.                   |
| **결과(Consequences)**   | (긍정) 네트워크 장애 시 기본 농업 운영 지속 가능. 클라우드 부하 감소. 제어 지연 최소화. (부정) 엣지-클라우드 간 상태 동기화 복잡도 증가. 엣지 펌웨어 관리 및 보안 패치 부담 발생.                                                                                            |
| **트레이드오프(Trade-offs)** | 【얻는 것】현장 탄력성(resilience), 저지연 제어, 네트워크 독립성. 【감수할 것】이중 관리 포인트(클라우드+엣지), OTA(Over-the-Air) 업데이트 체계 필요, 엣지 디바이스의 물리적 보안 취약성.                                                                               |

⚠️ 잠재적 위험 분석
------------

### 1. KSAS 중앙 허브 단일 장애점(Single Point of Failure) 위험

* **설명:** KSAS가 모든 데이터 조정, AI 분석, 경영계획 생성을 단일 허브에서 처리하는 구조상, 클라우드 인프라 장애(서버 다운, DB 손상, 네트워크 분리) 발생 시 트랙터·드론·이앙기 등 전 기계의 처방 데이터 수신이 불가능해져 파종기·방제기 등 시기 임계 작업이 전면 중단될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** Active-Active 멀티 AZ(가용영역) 클라우드 배포, RPO 1시간/RTO 30분 기준의 DR(재해복구) 계획 수립. 기계 내 마지막 수신 처방 데이터 로컬 캐싱 기능 탑재. 핵심 경영계획 데이터의 일 1회 이상 오프사이트 백업 의무화.

### 2. 농촌 통신 인프라 불안정에 의한 실시간 센싱 데이터 유실 위험

* **설명:** 논·밭 환경은 LTE/5G 음영지역이 빈번하며, 트랙터·드론 작업 중 수집되는 토양비옥도·생육·수확량 센싱 데이터가 네트워크 단절 구간에서 유실될 경우 KSAS 레이어맵의 공간 데이터 결손이 발생한다. 결손된 필지 데이터는 AI 분석 정확도를 저하시켜 잘못된 시비·방제 처방으로 이어질 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 기계 탑재 엣지 게이트웨이에 Store-and-Forward 버퍼(최소 8시간 분량) 구현. 데이터 수집 시 GPS 좌표·타임스탬프·장비 ID를 포함한 패킷 단위 무결성 보장. 데이터 결손 필지에 대한 AI 보간(interpolation) 모델 적용 및 불확실성 지표(confidence score) 경영계획에 반영.

### 3. 타사 농기계 데이터 표준 미통일에 의한 데이터 품질 저하 위험

* **설명:** 개념도 하단에 "타사 농업기계와의 협조를 검토 중"으로 명시된 바와 같이, 타사 기계의 센싱 데이터 포맷·단위·좌표계·샘플링 주기가 Kubota 자사 기계와 상이할 경우, KSAS 레이어맵에 이기종 데이터가 혼재되어 토양품질-수확량 간 상관분석 신뢰도가 하락한다. 최악의 경우 잘못 파싱된 시비량 데이터가 과잉 투입 처방으로 이어져 환경 오염 및 작물 피해를 유발할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** ISO 11783(ISOBUS) 및 ADAPT(Agricultural Data and Transfer Protocol) 표준 기반 데이터 어댑터 레이어 설계. 타사 데이터 수신 시 스키마 검증(Schema Validation)→단위 변환→이상치 탐지 3단계 파이프라인 의무화. 데이터 출처별 신뢰도 태깅(provenance metadata) 및 분석 제외 임계값 설정.

### 4. 농업 데이터 주권 및 개인정보 침해 위험

* **설명:** KSAS는 농지 지도, 수확량, 토양 성분, 농가 경영계획(비용분석 포함) 등 농가의 핵심 영업 기밀을 중앙 클라우드에 집중 저장한다. 클라우드 해킹, 내부자 데이터 유출, 또는 Kubota의 데이터 활용 정책 변경 시 농가 데이터가 무단으로 경쟁사 또는 유통업체에 제공될 위험이 있다. 일본 개인정보보호법(改正個人情報保護法) 및 향후 아시아 진출 시 각국 데이터 현지화 규제와의 충돌도 예상된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 농가별 데이터 암호화(AES-256) 및 농가 소유 키 관리(BYOK) 옵션 제공. 데이터 활용 동의 범위를 세분화한 명시적 동의(granular consent) UI 구현. 국가별 데이터 레지던시(data residency) 요건 충족을 위한 리전 분리 아키텍처 설계. 제3자 보안 감사 연 1회 이상 실시.

### 5. AI 분석 모델 편향(Bias)에 의한 잘못된 농업 처방 위험

* **설명:** KSAS의 빅데이터/AI 분석 엔진이 특정 지역·품종·기후 조건 데이터에 편중된 훈련 데이터로 학습될 경우, 해당 조건과 다른 필지에 부적합한 시비량·방제 시기·수확 타이밍을 처방할 수 있다. 특히 아시아 시장 확장 시 일본 데이터 기반 모델을 그대로 적용하면 현지 토양·기후 특성을 반영하지 못해 수확량 감소 및 농약 과다 사용 문제가 발생한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 모델 예측 결과에 신뢰 구간(confidence interval) 및 근거 데이터 범위를 농가에 투명하게 제공. 지역별 전이학습(transfer learning) 파이프라인 구축 및 현지 시험 포장 데이터 우선 반영. 처방 실행 전 농가 최종 확인(human-in-the-loop) 단계 의무화. 모델 성능 지표(수확량 예측 오차율 등)를 지속 모니터링하는 MLOps 체계 수립.

### 6. 물 관리 엣지 컨트롤러 사이버 보안 취약성 위험

* **설명:** 관개/배수를 제어하는 현장 엣지 컨트롤러는 물리적으로 노출된 환경에 설치되며, KSAS 클라우드와 양방향 통신을 수행한다. 악의적 공격자가 엣지 컨트롤러를 물리적으로 탈취하거나 통신 채널을 중간자 공격(MITM)으로 가로채어 관개 지시를 위변조할 경우, 과잉 관개(침수)·관개 차단(가뭄 피해)·농약 과다 살포 등 직접적 작물 피해를 유발할 수 있다. ICS/SCADA 대상 농업 사이버 공격은 글로벌적으로 증가 추세에 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 엣지 디바이스에 TPM(Trusted Platform Module) 기반 보안 부팅(Secure Boot) 및 디바이스 인증서(X.509) 적용. KSAS↔엣지 간 통신에 상호 TLS(mTLS) 및 메시지 서명 적용. 이상 제어 명령 탐지를 위한 엣지 내 규칙 기반 안전장치(예: 1회 관개량 임계값 초과 시 자동 차단) 구현. 정기적 펌웨어 취약점 스캔 및 OTA 보안 패치 체계 운영.
