### ADR-001: 표준 기반 모듈화 아키텍처 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 개발되는 시스템이 다양한 하위 모듈(OSHP 기반 서버, 영농 관리 서버, 사용자 웹/앱)로 구성되며, 각 모듈은 별도의 로직 설계 및 기능 설계를 거쳐 개발된다. 국제/국내 표준화 요구사항(ISO/IEC, TTA 등)을 준수해야 하는 환경이다. |
| **결정(Decision)** | 전체 시스템을 독립적인 모듈(환경제어 로직, 센서 로직, UI/UX 로직)로 분리하여 병렬 개발하되, 표준 인터페이스(API)와 공통 데이터 모델을 준수하여 상호 운용성을 확보한다. |
| **근거(Rationale)** | 이미지의 흐름도를 보면 '로직 설계' 단계에서 각각 'OSHP', '영농 데이터 분석', 'UI/UX'로 분기되어 독립적인 서버와 앱 개발이 진행된다. 이는 유지보수를 용이하게 하고 기술 스택을 최적화하는 데 유리하다. 또한 관련 문서에 언급된 표준(ISO/IEC 30141 등)은 재사용 가능한 설계와 공통 용어를 강조하므로 이를 반영해야 한다. |
| **결과(Consequences)** | **긍정적:** 개별 모듈의 성능 최적화, 빠른 기능 확장, 팀별 독립적 개발 가능.<br>**부정적:** 모듈 간 연동 비용 증가, 통합 테스트의 복잡성. |
| **트레이드오프(Trade-offs)** | 모듈화를 통한 유연성 vs 통합 통합 관리 및 호환성 유지 비용 |

### ADR-002: 엣지-클라우드 협업 아키텍처 설계

| 항목 | 내용 |
|------|------|
| **상황(Context)** | '온실 내 식재 및 재배' 단계와 '온실 환경제어 적용' 단계가 포함되어 있어, 현장(엣지)과 중앙 서버(클라우드) 간의 데이터 처리와 제어 명령 전달이 필요하다. |
| **결정(Decision)** | 현장 센서 및 구동기를 위한 로직 설계를 통해 엣지 컴퓨팅 기능을 지원하되, 핵심 데이터 분석과 장기적인 영농 관리 데이터는 중앙 서버에서 처리하도록 설계한다. |
| **근거(Rationale)** | 이미지 상단 흐름에서 '환경 제어 로직 설계 (작물 재배 환경 조건 적용)'와 '센서 및 구동기 데이터 수집, 저장, 처리, 변환 로직 설계'가 초기 단계다. 이는 제한된 대역폭이나 불안정한 네트워크 상황에서도 현장 데이터가 수집되고 로컬 로직이 작동할 수 있어야 함을 의미한다. |
| **결과(Consequences)** | **긍정적:** 네트워크 불안정 시에도 현장 제어 기능 유지, 대량 데이터 처리 효율성 향상.<br>**부정적:** 엣지 디바이스 처리 성능 제한, 동기화 오버헤드. |
| **트레이드오프(Trade-offs)** | 중앙 집중식 클라우드 처리의 단순성 vs 분산 처리의 복잡성 및 리소스 분산. |

### ADR-003: 인증 및 검증 기반 제품화 프로세스 구현

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템이 단순히 기능만 구현하는 것을 넘어 '온실 내 적용'을 위한 성능평가와 '제품화 관련 인증 추진(KC 등)'을 최종 목표로 한다. |
| **결정(Decision)** | 시스템 개발의 마지막 단계로 반드시 '샘플 추출 및 생육 상태 비교 검증'과 '환경제어 시스템 성능평가' 단계를 거친다. |
| **근거(Rationale)** | 이미지 하단 흐름도는 개발이 완료된 후 실제 적용 환경(온실)에서 샘플을 추출하여 성능을 검증하는 순차적 과정을 보여준다. 이는 실제 농업 환경에서의 신뢰성을 확보하고 KC 인증 등 규제 준수를 위한 필수 과정임을 의미한다. |
| **결과(Consequences)** | **긍정적:** 신뢰할 수 있는 제품 출시, KC 인증 획득으로 글로벌 수출 용이.<br>**부정적:** 개발 주기에 인증 테스트 시간이 추가되어 출시 지연 가능성. |
| **트레이드오프(Trade-offs)** | 출시 속도 vs 제품 신뢰성과 규제 준수를 위한 철저한 검증 시간. |

## ⚠️ 잠재적 위험 분석

### 1. 네트워크 불안정성으로 인한 데이터 손실 및 제어 지연
- **설명:** 온실이나 노지 등 농업 환경은 4G/5G 또는 와이파이 커버리지가 불안정한 경우가 많다. 센서 데이터가 서버로 전송되지 않거나 명령어가 현장으로 전달되지 않을 때 생기는 문제.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** MQTT와 같은 경량 프로토콜 및 오프라인 모드 지원, 로컬 엣지에서의 데이터 큐링(Caching) 기능 구현하여 네트워크 재연결 시 백로그된 데이터 복구.

### 2. IoT 디바이스 보안 취약점
- **설명:** 다양한 센서와 구동기 디바이스가 네트워크에 연결될 경우, 해킹이나 데이터 유출 위험이 존재한다. 특히 ETSI EN 303 645 등 보안 표준 준수가 중요하나, 실제 구현 시 보안 설정이 소홀해질 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** ITU-T X.1352에 준하는 인증 및 암호화 기법 적용, 엣지 디바이스 접근 제어(MFA, API 키), 정기적인 펌웨어 보안 업데이트 자동화 시스템 구축.

### 3. 이종 시스템 간의 상호 운용성 부재
- **설명:** 개발 과정에서 특정 벤더의 전용 프로토콜만 사용할 경우, 기존 농장 시스템이나 다른 IoT 기기들과 연동할 수 없게 된다. ISO/IEC 30141 등 표준 참조 아키텍처를 따르지 않을 경우 발생하는 위험.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 표준 프로토콜(OCF, Matter 등) 우선 사용 정책 수립, 오픈 API 및 RESTful 인터페이스를 통해 이종 시스템과의 연동성 보장.

### 4. 환경적 요인에 따른 하드웨어 신뢰성 저하
- **설명:** 고온, 고습, 진동, 먼지 등 온실/노지 환경은 전자 부품 수명을 단축시킨다. '온실 내 식재 및 재배' 단계 이후 실제 적용 시 환경적 스트레스를 견디지 못하면 시스템 고장.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 산업급(IP67 등) 등급 부품 선정, 방습 및 방진 코팅 처리, 열 설계 시뮬레이션을 통한 내구성 검증.

### 5. 실시간성 부족으로 인한 작물 생육 피해
- **설명:** 환경제어 로직 설계 단계에서 지연 시간이 길다면, 급격한 온도 변화나 습도 변동을 적절히 제어하지 못해 작물 생육에 악영향을 줄 수 있다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 실시간 OS(RTOS) 적용, 지연 시간이 최소화되도록 엣지 로직 최적화, 예측 제어 알고리즘(PID, 머신러닝 기반 예측) 도입.
