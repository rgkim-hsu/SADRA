📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 엣지-클라우드 하이브리드 아키텍처 기반의 스마트팜 통합 제어 시스템 설계

| 항목                     | 내용                                                                                                                                                                                                                                                 |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 환경에서는 온실 내 온도·습도·CO₂·관개 등 재배 환경을 실시간으로 제어해야 하며, 네트워크 단절 상황에서도 액추에이터(30)의 즉각적인 동작이 보장되어야 한다. 동시에 장기 데이터 분석 및 원격 관리자 단말(20)의 모니터링을 위한 중앙화된 데이터 저장소가 필요하다. 농장 제어기(100)는 현장에 위치하며 액추에이터를 직접 제어하고, 클라우드 서버(200)는 농장 데이터의 저장·관리를 담당하는 이중 구조가 요구된다.  |
| **결정(Decision)**       | 농장 제어기(100)를 엣지 노드로 운용하여 로컬에서 재배 환경 제어 및 농장 데이터 1차 저장·관리를 수행하고, 클라우드 서버(200)를 통해 장기 데이터 아카이빙 및 관리자 단말(20)의 원격 접근을 지원하는 **엣지-클라우드 하이브리드 분산 아키텍처**를 채택한다. 네트워크(중앙 허브)를 통해 관리자 단말 ↔ 농장 제어기 간 재배 환경 원격 제어 채널과, 농장 데이터 전송 채널을 논리적으로 분리 운용한다.            |
| **근거(Rationale)**      | ① 액추에이터(30) 제어는 수ms 단위의 저지연이 요구되므로 클라우드 경유 방식은 부적합하며, 엣지(농장 제어기)에서 직접 처리해야 한다. ② 농촌·시설원예 환경의 네트워크 불안정성을 고려할 때, 엣지 로컬 처리로 가용성을 확보해야 한다. ③ 클라우드 서버는 대용량 시계열 데이터(센서 로그, 생육 데이터)의 장기 보존 및 AI 분석에 적합하다. ④ 관리자 단말의 원격 제어 요구와 현장 자율 제어 요구를 동시에 충족하는 구조이다. |
| **결과(Consequences)**   | **긍정적:** 네트워크 단절 시에도 농장 제어기가 자율적으로 재배 환경을 유지할 수 있어 작물 피해를 최소화한다. 클라우드를 통한 데이터 분석으로 생산성 향상이 가능하다. **부정적:** 엣지와 클라우드 간 데이터 동기화 정합성 관리가 복잡해지며, 농장 제어기의 로컬 저장소 용량 및 처리 성능에 대한 하드웨어 요구사항이 증가한다.                                                         |
| **트레이드오프(Trade-offs)** | **얻는 장점:** 고가용성, 저지연 제어, 오프라인 동작 보장, 확장성. **감수해야 할 단점:** 이중 저장 구조로 인한 인프라 비용 증가, 엣지-클라우드 간 데이터 동기화 충돌 가능성, 농장 제어기 단독 장애 시 현장 제어 전체 마비 위험(단일 장애점, SPOF).                                                                                            |

### ADR-002: 네트워크 경유 양방향 제어 채널 분리 설계

| 항목                     | 내용                                                                                                                               |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 관리자 단말(20)은 네트워크를 통해 농장 제어기(100)로 재배 환경 원격 제어 명령을 전송하고, 반대 방향으로 농장 데이터를 수신한다. 명령 트래픽과 데이터 트래픽이 혼재될 경우 제어 명령의 지연 또는 유실이 발생할 수 있다. |
| **결정(Decision)**       | 재배 환경 원격 제어(명령) 채널과 농장 데이터 전송(텔레메트리) 채널을 **논리적으로 분리**하여 QoS를 차별 적용한다. 제어 명령은 고우선순위·저지연 채널로, 데이터 전송은 고대역폭·배치 전송 채널로 운용한다.         |
| **근거(Rationale)**      | 재배 환경 제어(관개, 냉난방, 환기)의 오작동은 작물 손실로 직결되므로 명령 신뢰성이 최우선이다. 데이터 전송은 수초~수분 단위의 지연이 허용되므로 대역폭 효율화가 가능하다.                               |
| **결과(Consequences)**   | 제어 명령의 신뢰성과 응답성이 향상되며, 대용량 데이터 전송 시에도 제어 채널이 영향받지 않는다. 다만 채널 관리 로직의 복잡도가 증가한다.                                                   |
| **트레이드오프(Trade-offs)** | **얻는 장점:** 제어 안정성 확보, 데이터 전송 효율화. **감수해야 할 단점:** 네트워크 장비의 QoS 설정 및 유지 관리 부담 증가.                                                  |

⚠️ 잠재적 위험 분석
------------

### 1. 농장 제어기(100) 단일 장애점(SPOF) 위험

* **설명:** 농장 제어기(100)는 액추에이터(30) 직접 제어, 로컬 데이터 저장·관리, 클라우드 데이터 중계를 모두 담당한다. 해당 장비가 하드웨어 고장, 전원 이상, 소프트웨어 크래시 등으로 중단될 경우 액추에이터 제어가 전면 불가능해져 고온/저온, 과습/건조 등 재배 환경 이상으로 작물 피해가 즉시 발생한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 농장 제어기의 이중화(Active-Standby 구성) 적용; 액추에이터에 로컬 페일세이프(fail-safe) 기본값 설정(예: 전원 차단 시 환기팬 개방 유지); UPS(무정전 전원장치) 연결; 하드웨어 워치독(watchdog) 타이머 적용으로 소프트웨어 행(hang) 시 자동 재기동.

### 2. 네트워크 단절 시 원격 제어 불가 및 데이터 유실 위험

* **설명:** 농촌 시설원예 환경의 특성상 네트워크 연결이 불안정할 수 있다. 관리자 단말(20)과 농장 제어기(100) 간 네트워크가 단절되면 원격 제어 명령 전달이 불가능하며, 클라우드 서버(200)로의 데이터 전송도 중단되어 장기 단절 시 로컬 저장소 용량 초과로 데이터 유실이 발생할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 농장 제어기에 자율 제어 로직(규칙 기반 또는 경량 ML 모델) 내장; 로컬 저장소 용량 및 데이터 압축 정책 수립; 네트워크 복구 후 클라우드와 자동 재동기화(store-and-forward) 구현; LTE/5G 이중화 회선 구성으로 유선망 장애 대비.

### 3. 보안 취약점 — 무단 원격 제어 명령 주입 위험

* **설명:** 관리자 단말(20)에서 네트워크를 통해 농장 제어기(100)로 전달되는 재배 환경 원격 제어 명령이 암호화되지 않거나 인증이 미흡할 경우, 공격자가 중간자 공격(MITM) 또는 재전송 공격으로 액추에이터에 허위 명령을 주입할 수 있다. 관개 밸브 오개방, 냉난방 오작동 등 직접적 피해로 이어진다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 모든 제어 채널에 TLS 1.3 이상 암호화 적용; 관리자 단말 및 농장 제어기 간 상호 인증(mTLS 또는 디바이스 인증서) 도입; 명령 메시지에 타임스탬프·시퀀스 번호 포함하여 재전송 공격 차단; 이상 명령 패턴 탐지를 위한 제어기 측 화이트리스트 기반 명령 검증 로직 구현.

### 4. 클라우드 서버(200) 장애 시 데이터 아카이빙 및 분석 기능 중단 위험

* **설명:** 클라우드 서버(200)가 장애 또는 서비스 점검으로 중단될 경우, 농장 데이터의 장기 저장 및 관리자의 이력 데이터 기반 의사결정이 불가능해진다. 농장 제어기의 로컬 저장 용량이 한정되어 있어 장기 장애 시 데이터 유실 위험이 존재한다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 멀티 클라우드 또는 하이브리드 클라우드 전략으로 단일 클라우드 의존성 제거; 클라우드 SLA 99.9% 이상 보장 계약 체결; 농장 제어기의 로컬 버퍼 용량을 최소 7일치 데이터를 수용할 수 있도록 설계; 클라우드 장애 시 관리자 단말이 농장 제어기 로컬 API에 직접 접근할 수 있는 fallback 경로 설계.

### 5. 액추에이터(30) 제어 명령과 실제 동작 간 불일치(피드백 부재) 위험

* **설명:** 개념도상 농장 제어기(100)에서 액추에이터(30)로의 제어 신호는 단방향으로 표현되어 있다. 액추에이터의 실제 동작 상태(밸브 개폐 여부, 모터 동작 확인 등) 피드백이 없을 경우, 제어 명령이 전달되었음에도 하드웨어 고장·단선 등으로 액추에이터가 미동작하는 상황을 시스템이 감지하지 못한 채 정상 동작으로 오판할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 액추에이터에 상태 피드백 센서(전류 센서, 위치 센서, 릴레이 상태 모니터링) 추가하여 양방향 제어 루프 구성; 농장 제어기에서 명령 후 일정 시간 내 환경 변수(온도, 습도) 변화 미감지 시 알람 발생 로직 구현; 주기적 액추에이터 자가진단(self-test) 루틴 적용; 이상 감지 시 관리자 단말로 즉시 푸시 알림 전송.

### 6. 펌웨어·소프트웨어 업데이트로 인한 현장 제어 중단 위험

* **설명:** 농장 제어기(100) 및 액추에이터(30)의 펌웨어나 제어 소프트웨어를 원격 업데이트(OTA) 하는 과정에서 재기동이 발생하거나 업데이트 실패 시 제어 불능 상태에 빠질 수 있다. 작물 생육의 임계 시간대(고온기, 결실기)에 업데이트로 인한 제어 공백은 심각한 손실로 이어진다.

* **심각도:** 🔴 High

* **발생 가능성:** 🟢 Low

* **대응 방안:** OTA 업데이트는 재배 비임계 시간대(야간, 휴지기)에만 수행하도록 스케줄링; A/B 파티션 업데이트 방식 적용으로 롤백 보장; 업데이트 전 자동 백업 및 체크섬 검증; 스테이징 환경에서 사전 검증 후 순차 배포(Canary Deployment) 적용.
