===============

📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 랜덤 포레스트(Random Forest) 기반 작물 생육 상태 다중 분류 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                                         |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 노지 농업 환경에서 작물 데이터(생육 지표, 토양·기상 환경 센서값 등 시초데이터)를 실시간으로 수집하여, 작물의 생육 조건 적합 여부 및 질소 부족 등 영양 결핍 상태를 자동으로 판별해야 한다. 단일 판단 모델로는 노지 환경의 고변동성과 노이즈에 취약하며, 농업 현장의 다양한 작물·품종·재배 조건을 커버하기 어렵다.                                                                                         |
| **결정(Decision)**       | 앙상블 기법인 랜덤 포레스트(Random Forest)를 핵심 의사결정 엔진으로 채택한다. Tree(a), Tree(b) … Tree(n)의 다수 결정 트리를 병렬 구성하고, 각 트리가 작물 데이터를 독립적으로 분류한 결과를 집계(다수결 투표)하여 최종 Class(Class 1: 생육 조건 적합 / Class 2: 질소 부족)를 산출한다. 이후 민감도 분석 및 평균값 산출 단계를 통해 Class 2(질소 부족) 판정의 신뢰도를 보정하여 최종 출력한다.             |
| **근거(Rationale)**      | ① 노지 환경은 기상 변동, 센서 오류 등으로 데이터 노이즈가 크며, 랜덤 포레스트는 과적합에 강건하다. ② 다수의 트리를 통한 앙상블 투표로 단일 트리 대비 분류 정확도와 안정성이 높다. ③ 민감도 분석을 후처리로 적용함으로써 질소 부족(Class 2)과 같은 임계 판정에서 오탐(False Negative)을 줄일 수 있다. ④ 특성 중요도(Feature Importance) 산출이 용이하여 농업 현장 전문가의 해석 가능성(Explainability)을 확보할 수 있다. |
| **결과(Consequences)**   | (+) 다양한 생육 환경 조건에서도 높은 분류 일관성 유지 가능. (+) 민감도 분석을 통해 오진단으로 인한 농가 피해 최소화. (+) 트리 수(n) 조정으로 정확도와 연산 자원 간 유연한 조율 가능. (-) 트리 수 증가 시 모델 추론 지연(Latency) 발생. (-) 앙상블 모델 특성상 단일 트리 대비 모델 크기가 크고 엣지 디바이스 배포 시 제약 발생 가능.                                                              |
| **트레이드오프(Trade-offs)** | **얻는 것:** 높은 분류 정확도, 노이즈 강건성, 해석 가능성, 오탐 억제. **감수해야 할 것:** 모델 복잡도 증가로 인한 실시간 추론 지연, 엣지 배포 시 메모리·연산 부담, 모델 학습 및 재훈련 비용 증가.                                                                                                                                                  |

### ADR-002: 민감도 분석 기반 후처리 계층 분리 설계

| 항목                     | 내용                                                                                                                                                                               |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 랜덤 포레스트의 다수결 투표만으로는 Class 2(질소 부족) 경계선상의 샘플에 대해 농업적으로 치명적인 오분류가 발생할 수 있다. 질소 부족의 미탐(Miss)은 작물 수확량 손실로 직결되므로, 단순 분류 결과 외에 신뢰도 기반의 보정 단계가 필요하다.                                    |
| **결정(Decision)**       | 분류/범주화 레이어와 최종 출력 사이에 독립적인 민감도 분석·평균값 산출 계층을 분리 배치한다. 이 계층은 n개 트리의 Class 2 판정 비율 및 평균 확률값을 집계하여, 설정된 임계값 이상일 경우에만 최종 Class 2(질소 부족)를 확정 출력한다.                                    |
| **근거(Rationale)**      | 농업 도메인에서 False Negative(부족 상태를 정상으로 분류)의 비용이 False Positive보다 훨씬 크다. 후처리 계층 분리를 통해 임계값 조정만으로 도메인 전문가가 민감도를 동적으로 조정할 수 있으며, 모델 재훈련 없이 운영 정책 변경이 가능하다.                             |
| **결과(Consequences)**   | (+) 현장 농업 전문가가 임계값 파라미터 조정으로 민감도를 즉시 변경 가능. (+) 분류 파이프라인의 관심사 분리(Separation of Concerns) 실현. (-) 추가 후처리 단계로 인한 파이프라인 복잡도 증가. (-) 임계값 설정 오류 시 오히려 과잉 경보(False Positive 증가) 발생 가능. |
| **트레이드오프(Trade-offs)** | **얻는 것:** 도메인 맞춤형 민감도 제어, 운영 유연성, 오탐 억제. **감수해야 할 것:** 파이프라인 단계 증가, 임계값 튜닝 및 검증을 위한 추가 운영 비용.                                                                                    |

⚠️ 잠재적 위험 분석
------------

### 1. 학습 데이터 편향으로 인한 분류 모델 성능 저하

* **설명:** 랜덤 포레스트 모델은 학습 데이터의 분포에 강하게 의존한다. 특정 작물 품종, 지역, 계절에 편중된 시초데이터로 학습된 경우, 새로운 재배 환경이나 품종에 대해 Class 1/Class 2 분류 정확도가 급격히 저하될 수 있다. 특히 Class 2(질소 부족) 샘플이 데이터셋에서 소수인 경우 클래스 불균형 문제가 발생한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** SMOTE 등 오버샘플링 기법으로 클래스 불균형 해소, 다양한 지역·품종·계절 데이터 수집을 위한 데이터 증강 파이프라인 구축, 정기적 모델 성능 모니터링 및 재훈련(MLOps 파이프라인) 도입.

* * *

### 2. 노지 환경 센서 데이터 결측 및 품질 이상

* **설명:** 노지 환경에서는 기상 이변(폭우, 낙뢰), 센서 물리적 손상, 통신 장애로 인해 시초데이터의 일부 피처가 결측되거나 이상치(Outlier)가 발생할 수 있다. 랜덤 포레스트는 결측값 처리 방식에 따라 분류 결과가 달라지며, 입력 데이터 품질 저하 시 Tree 전체에 오류가 전파된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 데이터 수집 단계에서 이상치 탐지 및 결측값 대체(Imputation) 전처리 모듈 필수 구현, 센서 이중화(Redundancy) 구성, 데이터 품질 지표(DQI) 실시간 모니터링 대시보드 구축.

* * *

### 3. 모델 추론 지연으로 인한 실시간 생육 모니터링 실패

* **설명:** Tree(n)의 수가 증가함에 따라 앙상블 추론 시간이 선형적으로 증가한다. 노지 환경에서 엣지 게이트웨이나 저사양 현장 서버에 모델이 배포될 경우, 다수의 트리 연산이 병렬 처리되지 못해 생육 이상 감지가 지연되고, 조기 개입 타이밍을 놓칠 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 트리 수(n)와 추론 속도 간 최적값 벤치마킹 수행, 모델 경량화(Pruning, 양자화) 적용, 클라우드-엣지 하이브리드 추론 아키텍처 도입(경량 모델은 엣지, 정밀 모델은 클라우드).

* * *

### 4. 민감도 임계값 오설정으로 인한 과잉 또는 과소 경보

* **설명:** 민감도 분석·평균값 산출 계층의 임계값이 잘못 설정될 경우, Class 2(질소 부족) 판정이 과도하게 발생(False Positive 증가)하여 농가의 불필요한 비료 투입을 유발하거나, 반대로 임계값이 너무 높아 실제 질소 부족을 탐지하지 못하는(False Negative) 위험이 존재한다. 두 경우 모두 경제적 손실과 시스템 신뢰도 저하로 이어진다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 작물별·생육 단계별 최적 임계값을 도메인 전문가와 협력하여 검증, A/B 테스트 기반의 임계값 튜닝 프로세스 수립, 임계값 변경 이력 관리 및 롤백 기능 구현.

* * *

### 5. 모델 블랙박스화로 인한 현장 수용성 및 설명 가능성 부재

* **설명:** 앙상블 모델은 개별 트리의 판단이 집계되는 구조로, 농업인이나 현장 관리자가 "왜 질소 부족으로 판정되었는가"를 직관적으로 이해하기 어렵다. 시스템 판정에 대한 신뢰 부족은 현장 도입 거부 및 수동 재확인 비용 증가로 이어질 수 있으며, 오판 발생 시 책임 소재가 불명확해진다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** SHAP(SHapley Additive exPlanations) 또는 Feature Importance 시각화를 통한 판정 근거 리포트 제공, 농업인 대상 UI에 "주요 판정 요인 Top 3" 표시 기능 구현, 모델 판정 결과에 대한 전문가 피드백 루프(Human-in-the-Loop) 설계.

* * *

### 6. 시스템 단일 장애점(SPOF) — 분류 파이프라인 직렬 구조

* **설명:** 작물 데이터 → 랜덤 포레스트 → 분류/범주화 → 민감도 분석 → 최종 출력으로 이어지는 파이프라인이 직렬 구조로 설계될 경우, 중간 단계 중 하나라도 장애가 발생하면 전체 모니터링 기능이 중단된다. 특히 노지 환경에서의 네트워크 단절이나 서버 장애는 작물 이상 감지 공백으로 직결된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 파이프라인 각 단계의 장애 격리(Bulkhead 패턴) 적용, 오프라인 동작 가능한 엣지 로컬 추론 모드 구현, 헬스체크 및 자동 재시작(Auto-recovery) 메커니즘 도입, 핵심 판정 결과의 로컬 캐싱 및 배치 전송 전략 수립.
