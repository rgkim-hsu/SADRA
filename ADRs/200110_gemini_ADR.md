# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 3단계 검증 로직 기반의 비동기 데이터 정제 파이프라인 구축

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜에서 수집되는 환경, 제어, 생육 정보는 센서 오류나 통신 장애로 인해 부정확한 데이터(Outlier)가 포함될 가능성이 매우 높음. 이러한 원천 데이터가 그대로 분석 플랫폼에 적재될 경우 예측 모델의 신뢰도를 심각하게 저하시킴. |
| **결정(Decision)** | '데이터 검증 데몬'을 핵심 엔진으로 채택하여 **1)오류 데이터 처리, 2)갱신주기 이상치 처리, 3)범위 이상치 처리**의 3단계 순차 검증 레이어를 구축함. 검증 로직은 별도의 '데이터 검증 정책 DB'를 통해 런타임에 동적으로 변경 가능하도록 분리 설계함. |
| **근거(Rationale)** | 데이터 특성별(환경 vs 생육)로 검증 기준(IQR 등)이 상이하므로 하드코딩 대신 정책 기반 엔진이 유연함. 특히 IQR(Interquartile Range) 방식의 사분위수 검정을 통해 통계적 근거를 바탕으로 정밀한 이상치 식별이 가능함. |
| **결과(Consequences)** | 최종 '정제 데이터'의 무결성이 보장되어 AI/BI 서비스의 정확도가 향상됨. 또한 '처리결과이력'을 별도로 관리함으로써 데이터 유실 및 변형 과정에 대한 추적성(Traceability) 확보가 가능해짐. |
| **트레이드오프(Trade-offs)** | 다단계 검증 거치면서 실시간 데이터 처리 속도(Latency)가 다소 증가할 수 있으나, 노지 작물 데이터의 특성상 준실시간성보다 데이터의 정확성이 더 우선시됨. |

---

## ⚠️ 잠재적 위험 분석

### 1. 정책 DB 병목 및 단일 장애점(SPOF) 위험
- **설명:** 모든 검증 데몬이 단일 데이터 검증 정책 DB에 의존할 경우, 정책 조회 부하로 인한 성능 저하 또는 DB 장애 시 전체 정제 프로세스가 중단될 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 검증 정책을 인메모리 캐시(Redis 등)에 로드하여 조회 성능을 높이고, 정책 DB의 고가용성(HA) 구성을 선행함.

### 2. 이상치 과탐(Over-filtering)으로 인한 원본 훼손
- **설명:** IQR(사분위 범위) 검증 정책이 너무 엄격하게 설정될 경우, 실제 발생한 기상 이변이나 급격한 제어 변화를 '이상치'로 오인하여 삭제할 위험이 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 삭제 방식 대신 플래깅(Flagging) 방식을 도입하고, 정제 후 데이터와 원본 데이터를 비교 분석할 수 있는 모니터링 대시보드 구축.

### 3. 데이터 수집 주기 불일치에 따른 상관관계 오류
- **설명:** 이미지 하단에 언급된 '연관성 매핑' 시, 환경 정보와 제어 정보의 수집 주기가 다를 경우 잘못된 데이터 쌍이 매핑되어 검증 결과가 왜곡될 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 타임스탬프 기반의 윈도우 조인(Window Join) 알고리즘을 적용하여 시간적 정렬을 최적화함.

### 4. 확장성 저하 및 데이터 처리 지연
- **설명:** 노지 작물 현장 실증 범위가 확대되어 수집 기기가 급증할 경우, 단일 데몬 구조에서는 처리량이 수집량을 따라가지 못해 데이터 적체가 발생함.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 데이터 검증 로직을 컨테이너화(Docker/K8s)하고 메시지 큐(Kafka)를 도입하여 스케일 아웃이 가능한 분산 처리 구조로 전환함.

### 5. 처리 결과 이력 데이터의 기하급수적 증가
- **설명:** 모든 검증 과정의 이력을 기록할 경우, 정제된 데이터보다 로그 성격의 이력 데이터 용량이 커져 스토리지 비용 및 관리 효율성이 저하됨.
- **심각도:** 🟢 Low
- **발생 가능성:** 🔴 High
- **대응 방안:** 이력 데이터에 대한 데이터 보관 정책(Retention Policy)을 수립하여 일정 기간 경과 후 콜드 스토리지로 이전하거나 압축 보관함.
