### ADR-001: 농기계 고장 진단을 위한 계층형 이중 진단 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 환경에서 운용되는 농기계(200)는 다양한 원인(기계적 결함, 환경적 요인, 연료 소모 이상 등)으로 고장이 발생한다. 단순 에러 카운트만으로는 고장 원인을 특정하기 어려우며, 현장 농업인이 즉각적인 판단을 내리기 위한 정확한 진단 정보가 필요하다. 진단 모듈(110) 내 고장 여부 판정부(112)가 1차 판정을 수행하고, 이후 환경적 요인, 복수 부품 특성 요인, 연료 소모량 발생 요인 등 다차원 데이터를 추가 분석하여 최종 진단 결과를 도출하는 2단계 구조가 요구된다. |
| **결정(Decision)**       | 진단 아키텍처를 **1차 기초 진단(고장 여부 판정부 112)** 과 **2차 다요인 복합 진단(환경·부품·연료 요인 병렬 분석)** 으로 분리하는 계층형 이중 진단 구조를 채택한다. 1차 결과는 사용자 단말(300)에 즉시 전달하고, 2차 복합 분석 결과는 최종 진단 결과로 별도 출력한다. 제어 모듈(120)은 진단 결과를 피드백 루프로 수신하여 농기계(200)를 제어한다.                                                             |
| **근거(Rationale)**      | 농기계 고장 원인은 단일 변수로 설명되지 않으며, IEC 61508(기능 안전) 및 ISO 11783(ISOBUS) 표준에서도 다층적 진단 체계를 권장한다. 1차 진단의 즉시 응답성으로 현장 대응 속도를 확보하고, 2차 분석으로 오진단율을 낮춰 유지보수 비용을 절감한다. 병렬 요인 분석 구조는 향후 AI/ML 기반 예측 정비(Predictive Maintenance) 모델 통합에도 유리하다.                                                    |
| **결과(Consequences)**   | ✅ 사용자는 기초 진단 결과를 신속히 수신하여 즉각 대응 가능 / ✅ 다요인 분석으로 진단 정확도 향상 / ✅ 제어 모듈의 피드백 루프로 자동 제어 가능 / ❌ 시스템 복잡도 증가로 개발·검증 공수 상승 / ❌ 2차 분석 지연 시 최종 진단 결과 전달 지체 가능                                                                                                                              |
| **트레이드오프(Trade-offs)** | **얻는 장점:** 진단 정확도, 응답성, 확장성(AI 통합 용이) / **감수할 단점:** 모듈 간 인터페이스 복잡도 증가, 실시간 처리 리소스 부담, 2단계 진단 간 결과 불일치 시 사용자 혼란 가능                                                                                                                                                               |

### ADR-002: 피드백 루프 기반 폐쇄형 제어 아키텍처 적용

| 항목                     | 내용                                                                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 농기계(200)의 에러 카운트 횟수는 지속적으로 진단 모듈(110)에 입력되며, 진단 결과는 제어 모듈(120)로 피드백되어 농기계를 제어해야 한다. 단순 모니터링(open-loop)만으로는 고장 확산을 사전에 차단하기 어렵다. |
| **결정(Decision)**       | 제어 모듈(120)이 진단 모듈(110)의 출력을 수신하여 농기계(200)에 제어 명령을 내리는 **폐쇄형 피드백 루프(Closed-loop Feedback Control) 아키텍처**를 적용한다.                  |
| **근거(Rationale)**      | 스마트팜 자동화 표준(ISO 16119, FMIS 연계)에서 센서→분석→제어의 사이클이 핵심이며, 폐쇄형 루프는 고장 확산 방지 및 자율 복구 시나리오 구현에 필수적이다.                                 |
| **결과(Consequences)**   | ✅ 고장 징후 감지 즉시 자동 제어로 2차 피해 예방 / ✅ 원격 모니터링과 자동 제어 병행 가능 / ❌ 제어 명령 오류 시 농기계 오작동 위험 존재                                             |
| **트레이드오프(Trade-offs)** | **얻는 장점:** 자율 운영 수준 향상, 인적 개입 최소화 / **감수할 단점:** 제어 로직 오류에 대한 안전 장치(Fail-safe) 설계 필수, 사이버 공격 시 제어권 탈취 위험                         |

⚠️ 잠재적 위험 분석
------------

### 1. 진단 모듈 단일 장애점(SPOF) 위험

* **설명:** 진단 모듈(110) 및 고장 여부 판정부(112)가 단일 컴포넌트로 구성될 경우, 해당 모듈 장애 시 기초 진단 결과 및 최종 진단 결과 모두 사용자 단말(300)에 전달되지 않아 농기계 운영이 완전히 블라인드 상태가 된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 진단 모듈의 이중화(Active-Standby 또는 Active-Active) 구성 적용, 워치독(Watchdog) 타이머를 통한 자동 재시작 메커니즘 도입, 모듈 장애 시 사용자 단말에 Fail-safe 알림 전송 로직 구현

### 2. 다요인 병렬 분석 결과 불일치로 인한 오진단 위험

* **설명:** 환경적 요인, 복수 부품 특성 요인, 연료 소모량 요인이 병렬로 분석될 때, 각 분석 결과가 상충되는 결론을 도출할 경우 최종 진단 결과의 신뢰성이 저하된다. 예를 들어 환경 요인은 '정상'을 가리키지만 부품 요인은 '고장'을 가리키는 경우 판정 로직이 모호해진다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 다요인 결과를 통합하는 가중치 기반 앙상블 판정 알고리즘 설계, 불확실성 구간(Confidence Score) 출력 기능 추가, 상충 결과 발생 시 전문가 검토 요청 플래그 자동 발송

### 3. 제어 모듈(120) 오제어로 인한 농기계 물리적 손상 위험

* **설명:** 진단 결과의 오분류 또는 제어 모듈(120) 내 로직 버그로 인해 정상 동작 중인 농기계(200)에 긴급 정지 또는 잘못된 제어 명령이 전달될 경우, 작업 중단 및 농기계 물리적 손상, 나아가 운용 인력 안전사고로 이어질 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 제어 명령 실행 전 이중 검증(Dual-check) 로직 적용, IEC 61508 SIL 2 이상 수준의 기능 안전 설계 도입, 물리적 비상 정지(E-Stop) 하드웨어 회로 병행 운용, 섀도우 모드(Shadow Mode) 시뮬레이션으로 제어 로직 사전 검증

### 4. 에러 카운트 데이터 정합성 및 노이즈 취약성 위험

* **설명:** 농기계(200)에서 수집되는 에러 카운트 횟수 데이터는 센서 오작동, 전기적 노이즈, 통신 지연 등으로 인해 실제와 다른 값이 진단 모듈(110)에 입력될 수 있다. 스마트팜 환경은 고온·다습·먼지 등 열악한 환경으로 센서 신뢰도가 낮아질 가능성이 높다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 에러 카운트 데이터에 이동 평균 필터(Moving Average Filter) 또는 칼만 필터 적용, 이상값(Outlier) 자동 탐지 및 제거 로직 구현, 센서 교정(Calibration) 주기 관리 체계 수립, IP67 이상 방진·방수 등급의 센서 하드웨어 선정

### 5. 사용자 단말(300) 보안 취약점으로 인한 무단 제어 명령 삽입 위험

* **설명:** 사용자 단말(300)이 외부 네트워크와 연결된 모바일 기기나 웹 대시보드일 경우, 인증 취약점을 통해 공격자가 위조된 제어 명령을 제어 모듈(120)로 전달하거나 진단 결과를 변조할 수 있다. 농업 IoT 디바이스는 일반적으로 보안 패치 주기가 길어 취약점 노출 기간이 길다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 사용자 단말↔진단 모듈 간 상호 TLS(mTLS) 인증 및 종단간 암호화(E2EE) 적용, 역할 기반 접근 제어(RBAC) 구현, 제어 명령에 대한 디지털 서명 검증, 농업 IoT 보안 가이드라인(ETSI EN 303 645) 준수, 정기적인 펌웨어 OTA 보안 업데이트 체계 수립

### 6. 실시간 처리 지연(Latency)으로 인한 진단 타이밍 위험

* **설명:** 농기계 고속 운행 중 발생하는 연료 소모량 이상이나 부품 결함은 밀리초 단위의 빠른 감지가 필요하다. 2단계 다요인 분석 구조에서 처리 지연이 누적될 경우, 최종 진단 결과가 실제 고장 발생 시점보다 늦게 도달하여 사후 대응에 그칠 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 1차 기초 진단(112)은 엣지 컴퓨팅(Edge Computing) 방식으로 로컬 처리하여 응답 지연 최소화, 2차 복합 분석은 비동기(Asynchronous) 파이프라인으로 분리 처리, 진단 처리 시간 SLA(예: 기초 진단 ≤ 100ms) 정의 및 모니터링 체계 구축

### 1. 진단 모듈 단일 장애점(SPOF) 위험

* **설명:** 진단 모듈(110) 및 고장 여부 판정부(112)가 단일 컴포넌트로 구성될 경우, 해당 모듈 장애 시 기초 진단 결과 및 최종 진단 결과 모두 사용자 단말(300)에 전달되지 않아 농기계 운영이 완전히 블라인드 상태가 된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 진단 모듈의 이중화(Active-Standby 또는 Active-Active) 구성 적용, 워치독(Watchdog) 타이머를 통한 자동 재시작 메커니즘 도입, 모듈 장애 시 사용자 단말에 Fail-safe 알림 전송 로직 구현

### 2. 다요인 병렬 분석 결과 불일치로 인한 오진단 위험

* **설명:** 환경적 요인, 복수 부품 특성 요인, 연료 소모량 요인이 병렬로 분석될 때, 각 분석 결과가 상충되는 결론을 도출할 경우 최종 진단 결과의 신뢰성이 저하된다. 예를 들어 환경 요인은 '정상'을 가리키지만 부품 요인은 '고장'을 가리키는 경우 판정 로직이 모호해진다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 다요인 결과를 통합하는 가중치 기반 앙상블 판정 알고리즘 설계, 불확실성 구간(Confidence Score) 출력 기능 추가, 상충 결과 발생 시 전문가 검토 요청 플래그 자동 발송

### 3. 제어 모듈(120) 오제어로 인한 농기계 물리적 손상 위험

* **설명:** 진단 결과의 오분류 또는 제어 모듈(120) 내 로직 버그로 인해 정상 동작 중인 농기계(200)에 긴급 정지 또는 잘못된 제어 명령이 전달될 경우, 작업 중단 및 농기계 물리적 손상, 나아가 운용 인력 안전사고로 이어질 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 제어 명령 실행 전 이중 검증(Dual-check) 로직 적용, IEC 61508 SIL 2 이상 수준의 기능 안전 설계 도입, 물리적 비상 정지(E-Stop) 하드웨어 회로 병행 운용, 섀도우 모드(Shadow Mode) 시뮬레이션으로 제어 로직 사전 검증

### 4. 에러 카운트 데이터 정합성 및 노이즈 취약성 위험

* **설명:** 농기계(200)에서 수집되는 에러 카운트 횟수 데이터는 센서 오작동, 전기적 노이즈, 통신 지연 등으로 인해 실제와 다른 값이 진단 모듈(110)에 입력될 수 있다. 스마트팜 환경은 고온·다습·먼지 등 열악한 환경으로 센서 신뢰도가 낮아질 가능성이 높다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 에러 카운트 데이터에 이동 평균 필터(Moving Average Filter) 또는 칼만 필터 적용, 이상값(Outlier) 자동 탐지 및 제거 로직 구현, 센서 교정(Calibration) 주기 관리 체계 수립, IP67 이상 방진·방수 등급의 센서 하드웨어 선정

### 5. 사용자 단말(300) 보안 취약점으로 인한 무단 제어 명령 삽입 위험

* **설명:** 사용자 단말(300)이 외부 네트워크와 연결된 모바일 기기나 웹 대시보드일 경우, 인증 취약점을 통해 공격자가 위조된 제어 명령을 제어 모듈(120)로 전달하거나 진단 결과를 변조할 수 있다. 농업 IoT 디바이스는 일반적으로 보안 패치 주기가 길어 취약점 노출 기간이 길다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 사용자 단말↔진단 모듈 간 상호 TLS(mTLS) 인증 및 종단간 암호화(E2EE) 적용, 역할 기반 접근 제어(RBAC) 구현, 제어 명령에 대한 디지털 서명 검증, 농업 IoT 보안 가이드라인(ETSI EN 303 645) 준수, 정기적인 펌웨어 OTA 보안 업데이트 체계 수립

### 6. 실시간 처리 지연(Latency)으로 인한 진단 타이밍 위험

* **설명:** 농기계 고속 운행 중 발생하는 연료 소모량 이상이나 부품 결함은 밀리초 단위의 빠른 감지가 필요하다. 2단계 다요인 분석 구조에서 처리 지연이 누적될 경우, 최종 진단 결과가 실제 고장 발생 시점보다 늦게 도달하여 사후 대응에 그칠 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 1차 기초 진단(112)은 엣지 컴퓨팅(Edge Computing) 방식으로 로컬 처리하여 응답 지연 최소화, 2차 복합 분석은 비동기(Asynchronous) 파이프라인으로 분리 처리, 진단 처리 시간 SLA(예: 기초 진단 ≤ 100ms) 정의 및 모니터링 체계 구축
