📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 작업·장비·이벤트 통합 관리를 위한 관계형 데이터 모델 기반 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 시스템은 작업자(sf_worker), 작업계획(sf_workplan), 작업유형(sf_wtype), 장비(sf_machine), 이벤트(sf_msevent), 태그(sf_tag) 등으로 구성된 데이터 중심 구조를 가진다. 각 엔티티는 WKCODE, WTCODE, TAG CODE 등으로 연결되며, 작업 이력과 장비 상태를 통합 관리해야 하는 과제가 존재한다. 핵심 문제는 “작업, 장비, 이벤트 데이터를 유기적으로 연결하여 추적 가능하고 확장 가능한 관리 체계를 구축하는 것”이다. |
| **결정(Decision)**       | 관계형 데이터 모델(RDBMS)을 기반으로 각 엔티티를 정규화하고, 코드(WKCODE, TAG CODE 등)를 중심으로 엔티티 간 관계를 정의하는 구조를 채택한다. 특히 작업계획(sf_workplan)을 중심 허브로 설정하여 작업자, 작업유형, 장비, 이벤트를 연결하는 구조로 설계한다.                                                                                                              |
| **근거(Rationale)**      | 스마트팜 운영에서는 작업 이력, 장비 상태, 이벤트 로그를 정확하게 추적하는 것이 중요하다. 관계형 모델은 데이터 무결성과 일관성을 보장하며, 코드 기반 연결은 확장성과 유지보수성을 높인다. 또한 이벤트 기반 데이터는 향후 분석 및 자동화에 활용 가능하다.                                                                                                                               |
| **결과(Consequences)**   | **긍정적:** 데이터 일관성 확보, 작업 이력 추적 가능, 확장성 및 유지보수 용이**부정적:** 스키마 변경 시 유연성 부족, 복잡한 조인으로 인한 성능 저하 가능                                                                                                                                                                                 |
| **트레이드오프(Trade-offs)** | 데이터 무결성과 구조적 안정성을 확보하는 대신, 유연성과 성능 최적화에 추가적인 설계 노력이 필요하다.                                                                                                                                                                                                                     |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. 복잡한 조인으로 인한 성능 저하

* **설명:** 작업, 장비, 이벤트 데이터를 조회할 때 다중 테이블 조인이 발생하여 응답 속도 저하

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 인덱스 최적화, 캐싱 적용, 일부 데이터 비정규화

### 2. 데이터 무결성 오류

* **설명:** 코드(WKCODE, TAG CODE) 불일치 또는 참조 무결성 오류 발생 시 데이터 신뢰성 저하

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 외래키 제약 조건 설정, 데이터 검증 로직 강화

### 3. 스키마 변경의 어려움

* **설명:** 새로운 작업 유형 또는 장비 추가 시 기존 데이터 구조 변경 필요

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 유연한 스키마 설계(확장 필드), 마이그레이션 전략 수립

### 4. 이벤트 데이터 폭증

* **설명:** sf_msevent 테이블에 이벤트 로그가 지속적으로 쌓이며 저장소 및 성능 문제 발생

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 데이터 아카이빙, 로그 분리 저장(NoSQL 활용), 데이터 수명주기 관리

### 5. 실시간 처리 한계

* **설명:** 관계형 DB 기반 구조에서 실시간 이벤트 처리 및 분석이 지연될 수 있음

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 스트리밍 처리 시스템(Kafka 등) 도입, 이벤트 기반 아키텍처 병행

### 6. 보안 및 접근 제어 문제

* **설명:** 작업자 및 장비 데이터에 대한 무단 접근 시 운영 리스크 발생

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 역할 기반 접근 제어(RBAC), 데이터 암호화, 접근 로그 관리

### 7. 코드 관리 복잡성

* **설명:** 다양한 코드(WKCODE, WTCODE, TAG CODE 등) 관리가 어려워질 수 있음

* **심각도:** 🟢 Low

* **발생 가능성:** 🔴 High

* **대응 방안:** 코드 관리 시스템 구축, 표준 코드 체계 정의, 코드 자동 생성 정책 적용
