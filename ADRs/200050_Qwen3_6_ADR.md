## 📋 ADR (Architecture Decision Record)

### ADR-001: 계층적 데이터 품질 관리 및 외주 가이드라인 통합 아키텍처 도입

| 항목                     | 내용                                                                                                                                                                                                                                                 |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | AI 융합 모델 개발을 위해서는 방대한 양의 원시 데이터(Raw Data)를 고품질의 학습 데이터로 변환해야 합니다. 그러나 데이터 획득, 정제, 라벨링 과정에서 발생하는 노이즈와 오류, 특히 외주 작업을 통한 라벨링 시 발생하는 기준 불일치는 최종 AI 모델의 성능 저하를 초래하는 주요 아키텍처적 과제입니다.                                                                     |
| **결정(Decision)**       | 데이터 라이프사이클 전반에 걸쳐 **계층적 데이터 품질 관리(Hierarchical Data Quality Management)** 시스템을 구축합니다. 원시 데이터, 원천 데이터, 라벨링 데이터로 이어지는 단계별 검증 프로세스를 필수화하고, 외주 관리 시스템에 **가이드라인 제공 및 적용 검증 로직**을 통합하여 데이터 표준화를 강제하는 아키처를 채택합니다.                                         |
| **근거(Rationale)**      | 이미지에서 상단의 '구축프로세스 품질관리' 흐름이 하단의 '데이터 품질관리' 및 '외주관리'와 밀접하게 연결되어 있는 것을 확인할 수 있습니다. 이는 데이터의 각 단계(획득, 정제, 라벨링)가 독립적인 것이 아니라, 지속적인 품질 피드백 루프(가이드라인 적용/검수)를 통해 관리되어야 함을 의미합니다. 이를 통해 외부 리소스 활용 시 발생할 수 있는 품질 편차를 최소화하고 신뢰할 수 있는 '학습용 데이터세트'를 확보할 수 있습니다. |
| **결과(Consequences)**   | **긍정적:** AI 모델 학습에 사용되는 데이터의 정확도와 일관성이 획기적으로 향상되어 모델 성능이 안정화됩니다. 외주 작업의 효율성과 품질 통제력이 동시에 확보됩니다.<br>**부정적:** 단계별 품질 검수 및 가이드라인 관리 프로세스로 인해 데이터 처리 파이프라인의 전반적인 지연(Latency)이 발생할 수 있으며, 관리 시스템 구축 및 운영 비용이 증가합니다.                                     |
| **트레이드오프(Trade-offs)** | **장점:** 데이터 신뢰성(Data Integrity) 확보 및 AI 모델 성능 최적화.<br>**단점:** 처리 속도 저하 및 품질 관리 인력/시스템에 대한 추가 리소스 투자 필요.                                                                                                                                            |

## ️ 잠재적 위험 분석

### 1. 외주 라벨링 작업자의 가이드라인 준수도 저하

- **설명:** '외주관리' 단계에서 제공된 '가이드라인'을 외주 작업자가 정확하게 이해하지 못하거나 무시할 경우, 라벨링 데이터에 심각한 불일치(Inconsistency)가 발생합니다. 이는 'AI융합 모델개발' 단계에서 노이즈로 작용하여 모델의 예측 정확도를 떨어뜨립니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 가이드라인을 문서로만 제공하는 것이 아니라, 작업 도구 내에 **실시간 유효성 검사(Validation)** 기능을 내재화하여 규칙 위반 시 즉시 경고하고 수정을 강제해야 합니다. 또한, 작업자별 품질 점수를 매겨 하위 작업자를 필터링하는 mechanisms을 도입해야 합니다.

### 2. 데이터 단계 간 전이 시 정보 손실 (Data Loss during Transition)

- **설명:** '원시데이터'가 '원천데이터'로, 다시 '라벨링데이터'로 변환되는 과정에서 데이터 포맷 변경이나 정제 로직의 오류로 인해 중요한 특징(Feature) 정보가 손실될 수 있습니다. 특히 '데이터 라벨링' 단계에서 라벨과 원본 데이터의 매핑이 깨질 경우 치명적입니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 데이터 파이프라인의 각 단계에서 **데이터 무결성 체크(Data Integrity Check)**와 **감사 로그(Audit Log)**를 기록해야 합니다. 원본 데이터와 변환된 데이터 간의 샘플링 비교 검증 프로세스를 자동화하여 정보 손실을 조기에 감지해야 합니다.

### 3. 학습 데이터 편향 (Dataset Bias)

- **설명:** '데이터 획득' 단계에서 수집된 데이터가 특정 상황이나 그룹에 편향되어 있을 경우, 이를 기반으로 생성된 '학습용 데이터세트(훈련데이터, 테스트데이터)' 또한 편향될 수 있습니다. 이는 AI 모델이 실제 운영 환경에서 제대로 작동하지 못하는 일반화 패(Generalization Failure)로 이어집니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 데이터 획득 단계에서 **데이터 분포 분석(Distribution Analysis)**을 수행하여 편향성을 사전에 진단해야 합니다. 또한, 데이터 증강(Data Augmentation) 기술을 활용하여 부족한 클래스의 데이터를 인위적으로 보강하는 로직을 파이프라인에 포함해야 합니다.

### 4. 민감 데이터 유출 및 보안 위협 (Data Security & Privacy Breach)

- **설명:** '원시데이터'나 '라벨링데이터'에는 개인정보나 기업 비밀이 포함될 수 있습니다. 특히 '외주관리'를 통해 제3자에게 데이터가 전달되는 과정에서 접근 제어가 미흡할 경우 데이터 유출 사고가 발생할 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 외부 전달 데이터에 대해서는 **가명처리(Pseudonymization)** 또는 **암호화(Encryption)**를 필수적으로 적용해야 합니다. 또한, 외주 작업자에게는 **최소 권한 원칙(Least Privilege)**에 따라 필요한 데이터만 접근할 수 있도록 제한하고, 작업 이력을 모니터링해야 합니다.

### 5. 품질 검수 병목으로 인한 모델 개발 지연

- **설명:** '데이터 검수' 및 '품질관리' 과정이 수동으로 진행되거나 승인 프로세스가 복잡할 경우, 데이터가 'AI융합 모델개발' 단계로 전달되는 속도가 느려집니다. 이는 애자일한 모델 개발 및 개선을 저해하는 병목 현상이 됩니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 데이터 검수 프로세스에 **자동화된 품질 점수(Automated Quality Scoring)** 시스템을 도입하여, 일정 점수 이상의 데이터는 자동으로 통과시키고 의심스러운 데이터만 수동 검수하도록 하여 처리 효율성을 높여야 합니다.
