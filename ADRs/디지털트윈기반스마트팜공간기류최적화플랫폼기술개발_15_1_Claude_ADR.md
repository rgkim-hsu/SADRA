📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 식물공장 기류 최적화를 위한 디지털 트윈 기반 하이브리드 시뮬레이션-ML 검증 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 식물공장(Plant Factory) 내 기류(Air Flow) 환경은 온도, 습도, CO₂ 분포에 직접 영향을 미치며, 물리적 시스템만으로는 실시간 최적화 제어가 불가능하다. GIS/BIM/3D-CAD 기반의 공간 복제(Spatial Copy), 시뮬레이션 모델을 통한 행동 복제(Behavior Copy), 운영 데이터(Operation Data)를 통한 데이터 복제(Data Copy)라는 세 가지 이질적인 데이터 소스를 통합하여 정합성 있는 디지털 트윈을 구성해야 하는 아키텍처적 과제가 존재한다. |
| **결정(Decision)**       | 물리 시스템으로부터 세 가지 복제 채널(공간/행동/데이터)을 분리 수집하여 Digital Twin(DT) 레이어를 구성하고, DT Formalism for Air Flow Model → DT Development → DT Simulation의 순차적 파이프라인을 구축한다. 생성된 Simulation Data는 머신러닝 기반 DT 검증(ML-based DT Validation)과 DT Data Visualization의 두 출력 경로로 병렬 처리하는 하이브리드 아키텍처를 채택한다.            |
| **근거(Rationale)**      | ① 공간 복제(GIS/BIM/3D-CAD)는 CFD(전산유체역학) 시뮬레이션의 경계 조건 정의에 필수적이며, ② 행동 복제(Simulation Model)는 기류의 물리적 거동을 수학적으로 형식화하고, ③ 운영 데이터(Operation Data)는 ML 검증 모델의 실측 Ground Truth로 기능한다. 세 채널의 역할이 명확히 분리됨으로써 각 컴포넌트의 독립적 갱신 및 유지보수가 가능하다. ML 검증 루프는 시뮬레이션 결과의 물리적 신뢰도를 정량적으로 보증하는 품질 게이트 역할을 수행한다.    |
| **결과(Consequences)**   | **긍정적:** 물리 실험 없이 다양한 기류 시나리오를 가상 검증 가능, 운영 데이터와 시뮬레이션 데이터 간 편차를 ML로 자동 탐지, 3D 시각화를 통한 공간적 기류 분석 지원. **부정적:** 세 복제 채널의 동기화 지연 발생 시 DT 정합성 저하, ML 검증 모델의 재학습 주기 관리 필요, GIS/BIM 모델 갱신과 시뮬레이션 모델 갱신 간 버전 불일치 위험 내포.                                                                          |
| **트레이드오프(Trade-offs)** | **획득:** 고정밀 기류 예측 및 사전 최적화 능력, 물리 실험 대비 비용·시간 절감, ML 기반 자동 모델 검증으로 신뢰성 확보. **감수:** 아키텍처 복잡도 증가(세 채널 + 직렬 파이프라인 + 병렬 출력), 초기 BIM/3D-CAD 모델링 및 DT Formalism 정의에 높은 도메인 전문성 요구, 운영 데이터 품질에 대한 ML 검증 결과의 종속성.                                                                                 |

### ADR-002: GIS/BIM/3D-CAD ↔ DT Data Visualization 양방향 피드백 루프 설계

| 항목                     | 내용                                                                                                                                                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 개념도상 DT Data Visualization은 GIS/BIM/3D-CAD로 역방향 피드백 화살표를 갖는다. 이는 단순 시각화를 넘어 시각화 결과가 공간 모델을 갱신하는 폐루프(Closed Loop) 구조임을 의미한다. 이 피드백 경로의 트리거 조건, 갱신 범위, 버전 관리 정책이 명확히 정의되지 않으면 모델 드리프트(Model Drift)가 발생할 수 있다.       |
| **결정(Decision)**       | Simulation Data 기반 시각화 결과에서 이상 기류 패턴이 탐지될 경우, 해당 공간 영역의 BIM/3D-CAD 파라미터(덕트 위치, 팬 배치, 격벽 구조 등)를 갱신하는 이벤트 기반(Event-Driven) 피드백 정책을 채택한다. 갱신은 변경 이력 관리(Version Control)와 함께 수행되며, 주요 구조 변경은 DT Formalism 재검토를 의무화한다. |
| **근거(Rationale)**      | 식물공장의 물리적 인프라는 작물 재배 주기(수 주~수 개월)에 따라 내부 구조가 변경될 수 있다. 정적 공간 모델 유지 시 시뮬레이션 결과와 실제 기류 간 오차가 누적되므로, 피드백 루프를 통한 모델 자기갱신(Self-Update) 능력이 DT의 장기적 신뢰성을 결정짓는다.                                                         |
| **결과(Consequences)**   | **긍정적:** 공간 모델의 상시 최신성 유지, 재배 환경 변화에 대한 적응형 기류 최적화 실현. **부정적:** 피드백 루프의 잘못된 트리거로 인한 모델 오염(Model Contamination) 위험, 갱신 이력 관리 시스템의 추가 구축 필요.                                                                        |
| **트레이드오프(Trade-offs)** | **획득:** 장기 운영 시 DT 정확도 유지, 물리-디지털 동기화 자동화. **감수:** 피드백 정책 설계 복잡도 증가, 갱신 승인 프로세스(Human-in-the-loop) 도입 시 실시간성 저하.                                                                                                  |

⚠️ 잠재적 위험 분석
------------

### 1. 삼중 복제 채널 동기화 실패로 인한 DT 정합성 붕괴

* **설명:** 공간 복제(BIM 갱신), 행동 복제(시뮬레이션 모델 파라미터 변경), 데이터 복제(운영 센서 데이터)가 서로 다른 주기와 트리거로 갱신될 때, 세 채널 간 시간적 불일치(Temporal Inconsistency)가 발생한다. 예를 들어 식물공장 내 팬 교체로 BIM이 갱신되었으나 시뮬레이션 모델에 반영되지 않은 상태에서 ML 검증이 수행되면, 검증 결과 자체가 무효화된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 세 채널에 대한 통합 변경 관리 시스템(Change Management System) 구축. 채널 간 버전 해시(Hash) 비교를 통한 정합성 자동 검사 게이트 도입. 불일치 감지 시 DT Formalism 재수행 전까지 시뮬레이션 결과 배포를 자동 차단하는 Circuit Breaker 패턴 적용.

### 2. ML 기반 DT 검증 모델의 데이터 드리프트(Data Drift)

* **설명:** ML 검증 모델은 초기 운영 데이터로 학습되지만, 식물공장의 재배 품종 변경, 계절적 외기 조건 변화, 설비 노후화 등으로 인해 운영 데이터 분포가 점진적으로 변화한다. 모델 재학습 없이 검증을 지속하면 드리프트된 데이터를 정상으로 오분류하거나, 정상 시뮬레이션을 이상으로 판정하는 오검증(False Validation)이 발생한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 운영 데이터에 대한 Statistical Drift Detection(PSI, KL-Divergence 등) 모니터링 파이프라인 구축. 드리프트 임계치 초과 시 자동 재학습 트리거 및 검증 결과에 신뢰도 구간(Confidence Interval) 레이블 부착. 재학습 데이터셋의 레이블링을 위한 도메인 전문가 검토 프로세스 의무화.

### 3. CFD 기반 DT Simulation의 실시간성 한계로 인한 제어 지연

* **설명:** 식물공장 기류 시뮬레이션은 격자 해상도와 물리 방정식의 복잡도에 따라 수 분~수십 분의 연산 시간이 요구된다. 외부 기온 급변, 장비 고장 등 긴급 상황에서 시뮬레이션 완료를 기다려 제어 명령을 생성하면 작물 피해가 발생하는 임계 시간을 초과할 수 있다. DT Development → DT Simulation → Simulation Data의 직렬 파이프라인 구조는 이 병목을 심화시킨다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 고해상도 정밀 시뮬레이션과 병행하여 Reduced Order Model(ROM) 또는 Physics-Informed Neural Network(PINN) 기반 경량 대리 모델(Surrogate Model)을 운영, 긴급 상황 시 대리 모델 기반 즉시 제어 명령 생성. 시뮬레이션 연산의 GPU 클러스터 또는 엣지 컴퓨팅 오프로딩 전략 수립.

### 4. 운영 데이터(Operation Data) 단일 경로 의존에 따른 보안·무결성 위험

* **설명:** 개념도상 Operation Data는 물리 시스템에서 ML 검증 모델로 직접 연결되는 유일한 실측 데이터 채널이다. 이 채널에 대한 센서 스푸핑(Sensor Spoofing), 중간자 공격(MITM), 또는 단순 센서 고장이 발생할 경우 ML 검증 모델이 오염된 Ground Truth로 학습되어, 결함 있는 시뮬레이션을 검증 통과 처리하는 보안 사고로 이어질 수 있다. 스마트팜 IoT 환경은 네트워크 보안 성숙도가 낮아 공격 표면이 넓다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 센서 데이터 수집 레이어에 TLS 1.3 기반 암호화 전송 및 디바이스 인증(X.509 인증서) 의무화. 다중 센서 교차 검증(Cross-Validation) 로직으로 이상 센서값 자동 격리. 운영 데이터 파이프라인에 무결성 해시 체인(Hash Chain) 또는 불변 감사 로그(Immutable Audit Log) 적용.

### 5. GIS/BIM/3D-CAD 모델과 실제 시설 간 형상 괴리(Model-Reality Gap) 누적

* **설명:** 식물공장 운영 중 재배대 재배치, 배관 수정, 임시 격막 설치 등 소규모 물리적 변경이 BIM 모델에 즉시 반영되지 않는 경우가 빈번하다. 이러한 형상 괴리가 누적될수록 DT Formalism 단계에서 설정되는 기류 모델의 경계 조건이 현실과 乖離되어, 시뮬레이션 결과의 공간적 정확도가 체계적으로 저하된다. DT Data Visualization의 피드백 루프가 있더라도 비정형 변경은 자동 감지가 어렵다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 시설 내 LiDAR 또는 Structure-from-Motion(SfM) 기반 정기 자동 스캔을 통해 현재 공간 상태와 BIM 모델 간 편차를 정량화하는 As-Built Verification 프로세스 도입. 변경 발생 시 현장 작업자가 모바일 AR 앱으로 즉시 BIM 갱신을 요청하는 변경 신고 워크플로우 구축.

### 6. DT Formalism 정의의 도메인 의존성과 표준 부재 위험

* **설명:** DT Formalism for Air Flow Model은 전체 파이프라인의 핵심 허브이나, 식물공장 기류에 특화된 국제 표준 형식화 방법론이 현재 부재하다. 특정 연구팀이나 벤더에 의해 독점적으로 설계된 Formalism은 담당자 이직, 조직 변경, 외부 시스템 연동 시 블랙박스화되어 유지보수 불가 상태에 빠질 수 있다. ISO 23247(디지털 트윈 제조 프레임워크) 등 관련 표준과의 정렬이 없을 경우 확장성이 심각하게 제한된다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** DT Formalism 설계 시 ISO 23247, IEC 62264(스마트 제조 통합), FIWARE NGSI-LD 등 국제 표준 온톨로지와 정렬하여 상호운용성 확보. Formalism 명세를 기계 판독 가능한 형태(OWL/RDF, JSON-LD)로 문서화하고 형상 관리 시스템에 등록. 핵심 설계 지식의 지식 이전(Knowledge Transfer) 계획을 프로젝트 초기부터 수립.
