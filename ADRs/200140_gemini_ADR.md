# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 분산 신원 증명(DID) 기반의 자기주권 신원 모델(SSI) 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 중앙 집중형 신원 관리 시스템은 데이터 오남용 및 단일 실패 지점(SPOF)의 위험이 있으며, 사용자가 자신의 개인정보를 직접 통제하기 어려운 구조적 한계가 있음. |
| **결정(Decision)** | 탈중앙화된 식별자(DID)와 검증 가능한 자격증명(VC)을 활용한 분산 신원 관리 아키텍처를 도입함. 발행자(Issuer), 보유자(Holder), 검증자(Verifier) 간의 신뢰 모델을 구축함. |
| **근거(Rationale)** | W3C 표준인 분산 식별자(DID)를 사용하여 데이터 무결성을 보장하고, 블록체인 기반의 '분산 ID 저장소(Verifiable Data Registry)'를 통해 위변조를 원천 차단하기 위함. |
| **결과(Consequences)** | 사용자는 자신의 개인정보를 직접 관리하며(Self-Sovereignty), 서비스 제공자는 개인정보 유출 리스크 없이 필요한 정보만 선택적으로 검증(Selective Disclosure)할 수 있음. |
| **트레이드오프(Trade-offs)** | 보안성과 프라이버시는 강화되나, 블록체인 네트워크 운영 비용이 발생하며 일반적인 ID/PW 방식 대비 사용자 경험(UX)의 복잡도가 증가함. |

---

## ⚠️ 잠재적 위험 분석

### 1. 개인키(Private Key) 분실에 따른 계정 복구 불가능
- **설명:** 사용자가 자신의 단말기(Mobile Wallet)에 보관된 개인키를 분실하거나 단말기를 교체할 경우, 자신의 DID 및 연결된 자격증명에 접근할 수 없게 됨.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 소셜 복구(Social Recovery) 메커니즘이나 다중 서명(Multi-sig)을 활용한 백업 및 복구 프로세스 수립.

### 2. 분산 ID 저장소(블록체인)의 성능 및 확장성 이슈
- **설명:** 대규모 사용자가 동시에 인증 요청을 하거나 검증을 진행할 경우, 블록체인 네트워크의 TPS(초당 트랜잭션 수) 한계로 인해 서비스 지연이 발생할 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 레이어 2(Layer 2) 솔루션 도입 또는 오프체인(Off-chain) 검증 로직 최적화를 통한 부하 분산.

### 3. 발행자(Issuer)의 신뢰성 및 권한 남용 위험
- **설명:** 특정 발행자가 잘못된 정보가 담긴 Credential을 발행하거나, 발행 권한을 탈취당할 경우 시스템 전체의 데이터 신뢰도가 붕괴됨.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 발행자 승인 프로세스(Governance Framework) 강화 및 발행자의 DID 상태를 실시간으로 모니터링하고 정지할 수 있는 시스템 구축.

### 4. 개인정보 비식별화 및 데이터 연계 노출 위험
- **설명:** 검증 과정에서 제공되는 여러 파편화된 정보(Presentation)를 조합하여 특정 개인을 역추적하거나 식별해낼 수 있는 'Linkability' 위험이 존재함.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 영지식 증명(Zero-Knowledge Proofs) 기술을 도입하여 상세 값 노출 없이 사실 여부만 검증하도록 설계.

### 5. 단말기 취약점을 이용한 Credential 탈취
- **설명:** 사용자의 스마트폰이 악성코드에 감염되어 전자지갑 내부에 저장된 Verifiable Credential이나 개인키가 유출될 시 타인이 신원을 도용할 위험이 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
