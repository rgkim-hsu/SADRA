# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 모듈형 IoT 컨트롤러 아키텍처 채택 및 표준화 프로토콜 사용

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 다양한 농업 제어 장치 (거리제어, 환기제어, 관수펌프 등) 를 단일화하여 통합 관리해야 하며, 농촌 인력 부족으로 인한 원격 자동화 요구가 증가하고 있음. 기존 제어 시스템들은 상호 호환성이 떨어지는 경우가 많아 유지보수 및 확장성이 떨어짐. |
| **결정(Decision)** | 각 제어 장치마다 개별 'IoT 컨트롤러' 모듈을 탑재하고, 무선 공유기를 통해 단일 네트워크로 통합하는 모놀리틱보다는 모듈형 아키텍처를 채택함. 통신 프로토콜은 경량화된 MQTT나 CoAP 같은 표준을 기반으로 한 MQTT over TLS 등을 사용하여 상호 운용성을 확보함. |
| **근거(Rationale)** | ISO/IEC 30141:2024 등 참조 아키텍처 표준에 부합하여 재사용 가능한 설계 (Reusable Design) 를 제공함. 제어기 (IoT 컨트롤러) 를 모듈로 분리하면 특정 기능 (예: 거리제어) 만 고장 나도 나머지 (환기제어) 는 계속 작동하도록 견고성 확보. 또한 TTA 표준화 동향을 반영하여 미래 지향적인 아키텍처 구축. |
| **결과(Consequences)** | ✅ **장점:** 추가 기능 (예: 새로운 센서) 을 모듈 형식으로 쉽게 확장 가능. 제어 로직 업데이트 시 개별 장치별 로컬 설정 변경 없이 중앙 관리 가능.<br>❌ **단점:** 각 모듈에 대한 표준 통신 인터페이스 구현 노력 필요. 초기 설정이 복잡해질 수 있음. |
| **트레이드오프(Trade-offs)** | 복잡한 프로토콜 표준 준수 (유지 비용↑) ↔️ 상호 운용성 및 호환성 확보 (운영 효율성↑) |

### ADR-002: 통합 모바일 애플리케이션 (Smartphone App)을 통한 다기능 인터페이스 제공

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 농민은 농사정보, 시세정보, 귀농 지원 정보 등 다양한 정보를 제공받아야 하며, 농작물 상태 (온도, 습도, CCTV 등) 와 기기 제어 (환기, 조명, 물 주이기 등) 를 동시에 관리해야 함. |
| **결정(Decision)** | 별도의 서버 접속 페이지가 아닌 '스마트폰 앱 플랫폼'을 주된 사용자 인터페이스로 정함. 앱 내에서 모니터링, 원격제어, 정보 제공, 추가 모듈 관리를 하나의 UI 로 통합. |
| **근거(Rationale)** | 사용자가 현장에서 손쉽게 지갑만 들고 이동하며 제어를 가능하게 함. 기존에 존재하던 귀농 지원 정보, 농사 정보 등을 앱 내 통합화하여 '정보 공유' 및 '귀농 지원' 기능을 강화함. IoT 표준(oneM2M 등) 에 따른 M2M(기계 간 통신) 을 앱에서 추상화하여 단순화. |
| **결과(Consequences)** | ✅ **장점:** 농작업의 단순화 및 작업 효율성 극대화. 농업 데이터 수집 및 분석을 통한 의사결정 지원.<br>❌ **단점:** 앱 호환성 문제 (OS 버전 등) 발생 시 특정 기기 사용 불가 가능성. |
| **트레이드오프(Trade-offs)** | 다양한 OS 지원 (유연성↑) ↔️ 앱 개발 및 유지보수 비용 증가 (비용↑) |

### ADR-003: 근거리 무선통신 (Wi-Fi) 기반의 중앙 집중식 네트워크 구축

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 비닐하우스 등 농장 내부에서 각 IoT 컨트롤러와 센서, 제어기들 간의 데이터를 전송해야 하며, 외부 인터넷을 통한 클라우드 연동도 필요함. |
| **결정(Decision)** | 농장 내부 중앙에 무선 공유기를 두고, 모든 IoT 컨트롤러와 센서, CCTV 를 이 네트워크에 연결하는 스타 (Star) 토폴로지를 채택함. 외부 인터넷망은 이를 통해 클라우드와 연동. |
| **근거(Rationale)** | 설치 및 유지보수의 용이성을 위해 가장 일반적인 Wi-Fi 를 사용함. 표준 IEEE 802.11 기반이며, 상대적으로 통신 대역폭이 넓어 고화질 CCTV 와 센서 데이터 동시 전송 가능. |
| **결과(Consequences)** | ✅ **장점:** 초기 구축 비용이 낮고, 설정이 직관적.<br>❌ **단점:** 비닐하우스 내 금속 구조물, 전파 간섭 등으로 인해 통신 불안정 가능성이 있음. |
| **트레이드오프(Trade-offs)** | 구축 비용 절감 (경제성↑) ↔️ 전파 간섭 등 환경적 취약성 (신뢰도↓) |

## ⚠️ 잠재적 위험 분석

### 1. [통신 불안정성 및 신호 간섭]
- **설명:** 비닐하우스 내부나 넓은 농지에서는 전파 간섭이나 장애물 (벽, 장비) 로 인해 Wi-Fi 신호가 불안정해질 수 있으며, 이는 센서 데이터 지연이나 원격 제어 실패로 이어질 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 
  - 농장 내부에 신호 증폭기를 추가하거나 Mesh 네트워크 (LoRa, Zigbee 등) 와 병행하여 통신 안정성 확보.
  - 통신 로그를 모니터링하여 주기적 네트워크 진단 및 최적화 수행.
  - 제어 명령 시 재시도 로직 (Retry Policy) 적용.

### 2. [사이버 보안 위협 및 무단 접근]
- **설명:** IoT 컨트롤러가 노출되어 있으면 악성코드 감염이나 원격 해킹으로 농장 제어 장비를 조작받을 수 있음. 특히 관수 펌프나 환기 장비를 조작하여 농작물 피해가 발생할 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 
  - ISO/IEC 27030 및 ETSI EN 303 645 표준에 따라 IoT 기기 자체 보안 설계 적용 (암호화, 접근 제어).
  - 통신 프로토콜 (MQTT 등) 에 TLS/SSL 인증서 적용.
  - 관리자 계정 암호화 및 정기적인 보안 패치 적용.

### 3. [단일 포인트 오브 패일어 (SPoF) 위험: 무선 공유기 고장]
- **설명:** 모든 IoT 컨트롤러와 센서가 하나의 무선 공유기에 연결되어 있어, 공유기가 고장 나면 전체 시스템이 마비될 수 있음.
- **심각도:** 🟠 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 
  - 주요 제어 기능 (예: 관수) 을 로컬에서 직접 제어 가능한 '오프라인 모드' 구현.
  - 무선 공유기를 듀플리케이트하여 장애 시 자동 전환 (Failover) 기능 도입 고려.

### 4. [전원 공급 및 환경적 내구성 이슈]
- **설명:** 농업 환경은 온도, 습도, 정전 등이 빈번할 수 있음. 이는 IoT 컨트롤러나 센서의 재부팅 또는 오작동을 유발할 수 있음.
- **심각도:** 🟠 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 
  - IoT 컨트롤러 내부에 배터리 백업 (UPS) 또는 수동적 급전 회로 추가.
  - 방진, 방습 처리 및 내구성이 강한 하드웨어 선택.

### 5. [데이터 동기화 및 정보 불일치]
- **설명:** 다양한 센서와 컨트롤러가 생성하는 데이터가 클라우드 서버로 동기화되지 않거나, 네트워크 지연으로 인해 최신 상태와 앱 화면이 다르게 표시될 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low
- **대응 방안:** 
  - 엣지 컴퓨팅 기술을 적용하여 로컬에서 실시간 데이터 처리 및 동기화 로직 구현.
  - 데이터 버전 관리 (Versioning) 를 통해 최신 상태 항상 파악할 수 있도록 시스템 설계.
