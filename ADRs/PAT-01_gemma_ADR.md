# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 데이터 수집 및 제어의 신뢰성 확보를 위한 엣지 컴퓨팅 기반 이벤팅 아키텍처 채택

| 항목 | 내용 |
| :--- | :--- |
| **상황(Context)** | 스마트 농업 시스템은 온도, 습도 같은 저속 아날로그 센서 데이터부터 고해상도 비전 데이터, 복잡한 비즈니스 로직(ERP)까지, 극도로 이질적이고(Heterogeneous), 대규모이며(Volume), 초실시간(Real-time)으로 발생하는 데이터를 처리해야 합니다. 중앙 클라우드만으로는 실시간 제어 루프(Control Loop)의 지연 시간(Latency)과 대역폭(Bandwidth) 요구사항을 충족하기 어렵습니다. |
| **결정(Decision)** | 시스템의 데이터 처리 및 제어 계층을 **엣지 컴퓨팅(Edge Computing)** 기반의 **이벤트-드리븐 아키텍처(Event-Driven Architecture, EDA)**로 분리하고, 데이터 수집 계층에 OPC UA 또는 MQTT 등의 표준화된 통신 프로토콜을 필수적으로 적용합니다. |
| **근거(Rationale)** | 1. **저지연성 확보:** 환경 제어(난방/냉각/관수)와 같은 초실시간 명령은 엣지에서 즉각 처리되어야 합니다. 2. **데이터 필터링 및 전처리:** 엣지 게이트웨이에서 원천 데이터의 노이즈 필터링, 표준화(Standardization), 그리고 비필수 데이터의 경량화(Thinning)를 수행하여 클라우드로 전송되는 데이터 부하를 최소화합니다. 3. **상호운용성 (Interoperability):** OPC UA나 MQTT는 다양한 제조사의 기기(PLC, Sensor)와 상위 시스템(ML, ERP) 간의 데이터 통신 규격(Data Contract)을 명확히 정의하여 상호운용성 표준을 준수합니다 (ISO/IEC 30141 준수). |
| **결과(Consequences)** | **긍정적:** 시스템의 확장성(Scalability)과 탄력성(Resilience)이 극대화됩니다. 네트워크 장애 발생 시에도 엣지 로컬 제어 루프가 독립적으로 작동할 수 있습니다. **부정적:** 엣지 디바이스의 초기 구축 비용과 유지보수 복잡도가 증가하며, 엣지 환경에서의 보안 패치 및 업데이트 관리가 핵심 과제로 부상합니다. |
| **트레이드오프(Trade-offs)** | **획득 장점:** 극한의 낮은 레이턴시(μs~ms 단위)와 오프라인/네트워크 분리 상황에서의 운영 지속성(Business Continuity). **감수 단점:** 시스템 복잡도 증가 및 엣지 계층에서의 강력한 사이버보안 관리 체계 구축 비용 발생. |

## ⚠️ 잠재적 위험 분석

### 1. 이질적 데이터 원천의 상호운용성 실패 (Interoperability Failure)
- **설명:** 시스템 내에 카메라(Vision), 센서(Analog), ERP(Structured), ML 모델(Predictive) 등 각기 다른 데이터 포맷과 통신 프로토콜이 존재합니다. 이들이 표준화되지 않고 개별적으로 통합될 경우, 데이터 파이프라인의 특정 지점에서 데이터 계약(Data Contract)이 깨지면서 시스템 전체가 오작동할 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** **데이터 표준화 계층 도입:** 모든 데이터 입력 지점(센서, 디바이스)에 통합 게이트웨이(Edge Gateway)를 두고, 모든 데이터를 통일된 메시지 형식(예: JSON Schema, OPC UA Data Model)으로 변환하는 데이터 변환 레이어(ETL/ELT)를 의무화해야 합니다. TTA 표준 프레임워크 준수 검증 프로세스를 통합합니다.

### 2. 엣지-클라우드 통신 구간의 보안 취약점 (Network & Security Vulnerability)
- **설명:** 스마트팜 시스템은 물리적인 제어 장치(Actuator)가 포함된 사이버-물리 시스템(CPS)입니다. 통신 구간이 해킹되거나, 엣지 장치가 물리적으로 탈취될 경우, 제어권이 오염되어 장비가 오작동하거나 농작물에 치명적인 피해를 줄 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** **보안 아키텍처 적용:** 엣지 게이트웨이에 하드웨어 기반의 물리적 보안 모듈(HSM)을 적용하고, 모든 통신은 암호화 프로토콜(TLS/DTLS)을 통해 전송해야 합니다. 또한, OT(Operational Technology) 망과 IT(Information Technology) 망을 물리적/논리적으로 분리하는 DMZ 구조를 구축하고, 제어권 명령은 반드시 이중 인증(Multi-factor Authentication)을 거치도록 합니다.

### 3. 머신러닝 모델의 개념 변화에 따른 성능 저하 (Model Drift/Data Drift)
- **설명:** 농작물 재배 환경이나 생육 단계, 기후 변화 등 외부 요인이 지속적으로 변함에 따라, 훈련된 ML 모델의 예측 패턴이 실제 환경과 괴리(Drift)될 수 있습니다. 이 경우, 모델은 정확한 예측을 수행하지 못하여 컨설팅 모듈이 잘못된 제어 명령을 내릴 위험이 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** **지속적인 모니터링 파이프라인 구축 (MLOps):** 모델이 배포된 이후에도 입력 데이터의 통계적 특성(Input Data Distribution)을 상시 모니터링하고, 예측 결과와 실제 측정값 사이의 오차율(Residual Error)을 주기적으로 분석해야 합니다. 특정 임계치 초과 시 자동적으로 재학습(Retraining)을 요청하는 워크플로우를 시스템화해야 합니다.

### 4. 센싱/제어 장비의 물리적 고장 및 데이터 불일치 (Physical Failure & Data Inaccuracy)
- **설명:** 온도 센서의 드리프트(Drift), 카메라 렌즈의 오염, 액추에이터의 구동기 오류 등 물리적 결함은 데이터의 정확도를 떨어뜨립니다. 시스템이 잘못된 데이터를 기반으로 제어를 수행하면 (예: 실제 온도가 25°C인데 센서가 20°C로 보고하면 냉각 시스템이 불필요하게 가동), 에너지 낭비 및 작물 스트레스가 발생합니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** **다중 센싱 및 예측 모델 적용:** 단일 센서 값에 의존하지 않고, 인접한 다수의 센서(Redundancy)를 사용하여 값의 일관성(Consistency)을 검증하는 로직을 구현해야 합니다. 또한, 센서 측정 데이터의 물리적 범위를 벗어나거나, 시간에 따른 변화 추이가 급격하게 비정상적일 경우, 해당 데이터를 자동으로 제외하고 경보를 발생시켜 사용자에게 알립니다.

### 5. 시스템 확장성 및 부하 분산 실패 (Scalability Bottleneck)
- **설명:** 시스템이 초기 구축 단계(소규모 테스트베드)를 넘어 여러 농장, 여러 작물군(예: 하우스-노지-양식)으로 확장될 때, 데이터베이스(DB)나 중앙 처리 서버가 발생하는 총 트래픽(Throughput)과 데이터 볼륨(Volume)을 감당하지 못할 위험이 있습니다. 특정 데이터베이스나 메시지 큐가 병목(Bottleneck)이 될 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** **마이크로서비스 아키텍처 (MSA) 및 비동기 통신:** 모든 핵심 기능을 독립적인 마이크로서비스로 분리하고, 서비스 간 통신은 REST API와 같은 동기식 통신보다 메시지 큐(Message Queue, Kafka 등)와 같은 비동기적 이벤트 스트림을 통해 처리하도록 설계해야 합니다. 데이터베이스는 Time Series DB(InfluxDB 등)를 핵심으로 도입하여 시계열 데이터 처리에 최적화해야 합니다.
