# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: IoT 센서 데이터의 실시간 수집 및 플랫폼 연동 표준화 적용

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 이미지 'CROP'에서 'PLATFORM'으로의 'Sensor(s)' 경로를 통해 다양한 농업 환경 센서 데이터를 수집해야 하지만, 다양한 제조사별 센서 프로토콜 (LoRaWAN, Zigbee, MQTT 등) 이 혼재할 경우 데이터 통합 및 처리의 어려움이 발생함. 또한 TTA 및 ISO/IEC 30141 표준 문서에 제시된 데이터 수집 지침에 따라 효율적인 아키텍처 구축 필요 |
| **결정(Decision)** | 아키텍처 설계 시 IoT 참조 아키텍처 (ISO/IEC 30141:2024) 와 oneM2M 표준을 기반으로 한 **표준화된 데이터 수집 인터페이스 및 게이트웨이 계층**을 도입함. 모든 센서 데이터는 경량 프로토콜 (MQTT/CoAP) 로 수집된 후, 플랫폼 계층에서 표준화된 모델 (JSON/SVG 등) 로 변환하여 처리 |
| **근거(Rationale)** | 다양한 센서 하드웨어를 하나의 플랫폼에서 관리 가능하도록 상호운용성을 확보하여 확장성을 높임. 표준화된 데이터 모델을 통해 AI 및 분석 엔진 (DATA 블록) 에의 입력이 원활하게 이루어지도록 함. TTA의 '스마트 온실 서비스의 데이터 관리 요구 사항' 지침 준수 |
| **결과(Consequences)** | **긍정적:** 하드웨어 교체 시 소프트웨어 변경 최소화, 시스템 통합 비용 절감.<br>**부정적:** 특정 비표준 장비에 대한 호환성 테스트 필요 및 초기 표준화 노력 소요 |
| **트레이드오프(Trade-offs)** | **장점:** 높은 상호운용성 및 유지보수 용이성.<br>**단점:** 모든 데이터를 표준 포맷으로 변환하는 과정에서 발생할 수 있는 오버헤드 (일부 경우) 및 레거시 시스템 통합의 복잡성 |

### ADR-002: AI 기반 의사결정 및 자동화 액추에이터 제어 루프 최적화

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 'DATA' 블록에서 'AI'를 통해 'DECISION'으로 이어지는 과정과 'DECISION'에서 'ACTUATION'으로 이어지는 실행 프로세스 (Implements) 와의 연계 필요. 이 과정에서 네트워크 지연이나 시스템 오류로 인해 농작물 환경이 급격히 변화하면 손실로 이어질 수 있음 |
| **결정(Decision)** | **Edge AI 및 로컬 제어 우선 정책 적용.** 클라우드 의존도가 높은 'DECISION' 로직은 지연 시간을 고려하여 에지 기단 (Gateway) 또는 로컬 서버에서 처리 가능한 알고리즘을 우선 배치하고, 복잡한 모델은 백업용 클라우드 모델로 구성함. <br>또한, 'ACTUATION' 단계에서 'CROP'로 이어지는 피드백 루프는 **긴박한 환경 제어 (급수, 온도 조절 등)** 에는 지연이 없는 로컬 제어 회로를, 장기적인 전략 (일정 관리 등) 에는 클라우드 명령을 우선시하도록 계층화함 |
| **근거(Rationale)** | 네트워크 환경 (필드, 온실 등) 의 불안정성을 고려하여 시스템 가용성을 확보. TTA '스마트 축사환경 데이터 모니터링 시스템' 등 표준의 '일반 요구 사항'에서 시스템 신뢰성을 강조하고 있음. |
| **결과(Consequences)** | **긍정적:** 네트워크 장애 시에도 기본 제어 기능 유지 (Resilience).<br>**부정적:** 에지 연산 자원 (GPU 등) 증가 및 로컬 모델 버전 관리 복잡성 증가 |
| **트레이드오프(Trade-offs)** | **장점:** 끊김 없는 농작물 관리, 실시간 대응 능력.<br>**단점:** 에지 장치의 비용 증가 및 전력 소모 증가 |

## ⚠️ 잠재적 위험 분석

### 1. [IoT 장비 보안 취약점 및 해킹 위험]
- **설명:** 외부 네트워크가 노출된 IoT 센서 (CROP 블록 연동) 나 액추에이터 (ACTUATION) 가 해킹을 당하여 악성 명령이 발령되거나 데이터가 탈취될 경우, 농작물 손실이나 사기적인 데이터 조작 (예: 보험 사기 등) 이 발생할 수 있음. 특히 TTA 보안 가이드 (ITU-T X.1352 등) 에 제시된 요구사항이 제대로 준수되지 않을 경우 리스크가 큼.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** ITU-T X.1352 및 ETSI EN 303 645 표준에 준하는 암호화 프로토콜 (TLS/DTLS) 적용, 인증/인가 (IAM) 시스템 강화, 정기적인 보안 취약점 분석 (Penetration Test) 수행 및 패치 관리 체계 수립.

### 2. [네트워크 지연 및 데이터 불일치로 인한 제어 오류]
- **설명:** 데이터가 CROP 에서 PLATFORM 을 거쳐 AI 분석을 받고 DECISION 으로 이동하는 과정에서 네트워크 지연이 발생하여 ACTUATION 에 명령이 늦게 도착하면, 예를 들어 고온이 갑자기 올라와도 급수 밸브가 제대로 열리지 않아 작물이 손상될 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 실시간 제어에 필요한 핵심 로직은 에지 (Edge) 에서 독립적으로 처리하는 하이브리드 아키텍처 설계. QoS (Quality of Service) 를 고려한 네트워크 토폴로지 설계 및 지연 감지 시 대안 제어 로직 (Fail-safe mode) 즉시 실행.

### 3. [AI 모델의 편향성 및 오작동 (False Positive/Negative)]
- **설명:** DATA 블록의 AI 가 DECISION 을 내리는 과정에서 학습 데이터의 편향성이나 이상치 (Outlier) 가 존재하면, 잘못된 작물 질병 진단이나 최적 성장 조건 설정 (DECISION) 을 할 수 있음. 이는 Actuation 으로 이어져 비효율적인 농약 살포나 자원 낭비로 이어짐.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** AI 모델의 투명성 (Explainable AI, XAI) 확보 및 인간-in-the-loop (HITL) 시스템 도입 (농부나 관리자가 DECISION 을 최종 승인). 지속적인 모델 재학습 (Retraining) 및 드래그/테스트를 위한 별도의 데이터 피프라인 구축.

### 4. [데이터 무결성 손실 및 저장소 과부하]
- **설명:** CROP 의 센서 데이터가 Sensor(s) 를 거쳐 PLATFORM 으로 흐르는데, 대용량 데이터를 실시간으로 처리하다가 STORAGE 에 저장될 때 데이터 손실이 발생하거나 저장소 과부하로 인해 PLATFORM 이 다운될 경우 전체 시스템이 마비될 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 시간 기반 아카이빙 (Time-series DB) 활용, 데이터 샘플링 전략 최적화 (중요 데이터 우선 저장). 클라우드 또는 에지 기반의 분산 저장 구조 구축 및 백업/복구 (Disaster Recovery) 계획 수립.

### 5. [표준 불일치로 인한 상호운용성 문제]
- **설명:** 시스템 확장 시 새로운 센서나 액추에이터를 추가하는데, 기존 아키텍처나 다른厂商의 표준과 호환되지 않을 경우 (예: 통신 프로토콜 차이, 데이터 포맷 불일치), 시스템 통합이 지연되거나 불가능해질 수 있음. TTA 표준화 목록 (TTAK.KO-10.1170 등) 에 명시된 규격에 미준수될 경우.
- **심각도:** 🟢 Low
- **발생 가능성:** 🟢 Low (관리적 주의 필요)
- **대응 방안:** oneM2M 및 ISO/IEC 30141 참조 모델과 동일한 표준 스펙을 계약서에 명시. 개방형 API 및 미들웨어 (Adapter) 를 활용하여 프로토콜 변환을 표준화.
