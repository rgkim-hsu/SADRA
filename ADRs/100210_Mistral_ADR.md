### **ADR-001: 클라우드-에지 하이브리드 데이터 처리 아키텍처 채택**

| 항목                     | 내용                                                                                                                                                                                                                                                                                                    |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 시스템은 실시간으로 대량의 센서 데이터(온도, 습도, CO₂, 영양분 등)를 수집하고, AI 기반 분석을 통해 농작물 상태를 모니터링 및 예측해야 함. 농장 현장(200개 농장)과 클라우드 간 네트워크 지연 및 대역폭 제한으로 인해 실시간 데이터 처리가 어려움. 또한, 외부 데이터(기상청, 농촌진흥청 등)와 연동하여 종합적인 분석이 필요함.                                                                                                  |
| **결정(Decision)**       | **에지 게이트웨이(G/W)**를 통해 농장 현장에서 데이터 전처리 및 필터링을 수행하고, 실시간성이 요구되는 데이터는 로컬에서 처리한 후 클라우드로 전송. 비실시간 데이터(예: 일일 통계)는 배치로 클라우드로 전송. AI 분석은 에지에서 간단한 추론을 수행하고, 복잡한 모델은 클라우드에서 처리.                                                                                                                                |
| **근거(Rationale)**      | 1) **지연 최소화**: 에지에서 실시간 데이터(예: 급수 제어) 처리를 통해 클라우드 의존도를 낮춤. 2) **네트워크 효율성**: 에지에서 데이터 필터링/집계로 클라우드 전송 데이터 양을 70% 이상 감소시킴(이미지 상 "200개 농장 → 10개 G/W → 클라우드" 구조 참고). 3) **오프라인 동작 지원**: G/W가 로컬 스토리지를 통해 네트워크 단절 시에도 24시간 동안 데이터 저장 및 기본 제어 가능. 4) **확장성**: 클라우드에서 AI/빅데이터 분석을 통해 장기적인 트렌드 분석 및 모델 학습 수행. |
| **결과(Consequences)**   | ✅ **장점**: 실시간성 향상, 네트워크 비용 절감, 오프라인 동작 지원, 외부 데이터와 연동한 종합 분석 가능. ❌ **단점**: G/W의 하드웨어 비용 증가, 에지에서 수행 가능한 AI 모델의 제한적 복잡도.                                                                                                                                                                               |
| **트레이드오프(Trade-offs)** | **얻는 것**: 실시간 제어 및 모니터링, 네트워크 효율성, 장애 복구성. **감수하는 것**: G/W의 유지보수 복잡성, 에지 장비의 하드웨어 비용, 클라우드-에지 간 데이터 동기화 복잡성.                                                                                                                                                                                          |

### **ADR-002: 다중 외부 데이터 소스 연동 아키텍처**

| 항목                     | 내용                                                                                                                                                |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 시스템은 농업 환경 데이터를 보완하기 위해 기상청, 농촌진흥청, EC(전기전도도) 등 다수의 외부 데이터 소스를 활용해야 함. 각 소스의 데이터 포맷과 주기가 상이하여 통합이 복잡함.                                            |
| **결정(Decision)**       | **API 게이트웨이**를 통해 외부 데이터 소스를 표준화된 포맷으로 변환하여 클라우드의 **데이터 레이크**에 저장. 실시간 데이터(예: 기상청)는 **스트리밍 처리**, 배치 데이터(예: 토양 분석)는 **일일 동기화**로 처리.                |
| **근거(Rationale)**      | 1) **일관성**: 모든 외부 데이터를 표준 스키마로 변환하여 AI 분석 시 데이터 호환성 보장. 2) **유연성**: 새로운 데이터 소스 추가 시 API 게이트웨이만 수정하면 됨. 3) **비용 효율성**: 배치 동기화를 통해 불필요한 API 호출 최소화. |
| **결과(Consequences)**   | ✅ **장점**: 데이터 일관성 향상, 확장성 보장, 비용 절감. ❌ **단점**: API 게이트웨이의 단일 장애점, 데이터 지연(배치 처리 시).                                                                |
| **트레이드오프(Trade-offs)** | **얻는 것**: 데이터 통합의 단순화, 유지보수 용이성. **감수하는 것**: API 게이트웨이의 장애 시 전체 외부 데이터 접근 불가, 배치 데이터의 실시간성 제한.                                                    |

### **ADR-003: AI 기반 스마트 농업 관리 시스템**

| 항목                     | 내용                                                                                                                                                              |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 농작물 상태 예측, 병해충 진단, 수확 시기 예측 등 복잡한 AI 분석이 필요하며, 이 분석은 실시간 데이터와 외부 데이터를 모두 활용해야 함.                                                                                |
| **결정(Decision)**       | **에지 AI**: G/W에서 간단한 이미지 인식(예: 병해충 초기 감지) 및 센서 데이터 기반의 이상 감지를 수행. **클라우드 AI**: 복잡한 딥러닝 모델(예: 수확량 예측, 장기적 트렌드 분석)을 수행. AI 모델은 **MLOps 파이프라인**을 통해 지속적으로 학습 및 배포. |
| **근거(Rationale)**      | 1) **실시간성**: 에지 AI로 급한 조치(예: 급수 중지)가 필요한 경우 즉각 대응. 2) **정확성**: 클라우드 AI로 대용량 데이터를 활용한 고정확도 분석 수행. 3) **지속적 개선**: MLOps를 통해 모델을 주기적으로 재학습하여 예측 정확도 향상.            |
| **결과(Consequences)**   | ✅ **장점**: 실시간 및 고정확도 분석 동시 지원, 모델 지속적 개선. ❌ **단점**: 에지 AI의 제한적 기능, 클라우드 AI의 지연.                                                                                 |
| **트레이드오프(Trade-offs)** | **얻는 것**: 실시간성과 정확성의 밸런스, 모델의 지속적 진화. **감수하는 것**: 시스템 복잡성 증가, 에지-클라우드 간 모델 동기화 필요.                                                                              |

⚠️ 잠재적 위험 분석
------------

* * *

### 1. **에지 게이트웨이(G/W) 장애**

* **설명:** G/W가 하드웨어 고장 또는 소프트웨어 오류로 인해 동작 중지 시, 해당 농장의 실시간 데이터 수집 및 제어가 중단됨. 200개 농장 중 10개 G/W가 각 20개 농장을 담당하는 구조에서, 하나의 G/W 장애가 20개 농장의 데이터를 손실시킬 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:**
  * G/W에 **이중화(Active-Standby) 구조** 적용.
  * **로컬 백업 스토리지**를 통해 데이터 손실 방지(최소 72시간 분량 저장).
  * **자동 장애 감지 및 복구** 메커니즘 구축(예: 5분 내 재시작).

* * *

### 2. **네트워크 대역폭 포화**

* **설명:** 모든 농장에서 동시에 대량의 센서 데이터를 전송할 경우, G/W-클라우드 간 네트워크 대역폭이 포화되어 데이터 지연 또는 손실 발생.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:**
  * **데이터 압축** 및 **델타 전송**(변화된 데이터만 전송) 기법 적용.
  * **우선순위 기반 전송** (실시간 데이터 > 배치 데이터).
  * **네트워크 모니터링**을 통해 트래픽 패턴 분석 및 대역폭 동적 할당.

* * *

### 3. **외부 데이터 소스 API 제한**

* **설명:** 기상청 또는 농촌진흥청의 API 호출 한도가 초과되거나, API 서버가 장애로 인해 데이터 수신 실패.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:**
  * **API 호출 캐싱** (예: 기상 데이터는 1시간 단위로 캐시).
  * **대체 데이터 소스** 마련(예: 민간 기상 서비스와 계약을 체결).
  * **API 장애 시 로컬 예측 모델**을 통해 임시 데이터 생성.

* * *

### 4. **AI 모델 예측 오류**

* **설명:** AI 모델이 잘못된 예측(예: 병해충 오진, 수확 시기 오판)을 내릴 경우, 농장 운영에 심각한 영향을 미침(예: 불필요한 농약 사용).
* **심각도:** 🔴 High
* **발생 가능성:** 🟢 Low
* **대응 방안:**
  * **인간 검증 메커니즘** 도입(예: AI 예측 결과는 농업 전문가의 최종 확인을 거침).
  * **모델 설명 가능성(XAI)** 도구 활용하여 예측 근거 제공.
  * **지속적 모델 검증** (A/B 테스트를 통해 새로운 모델과 기존 모델의 성능 비교).

* * *

### 5. **클라우드 보안 침해**

* **설명:** 클라우드 스토리지에 저장된 농장 데이터가 해킹 또는 데이터 유출로 인해 노출될 경우, 농장의 비즈니스 민감 정보(예: 재배 기술, 수확량) 및 개인 정보가 유출됨.
* **심각도:** 🔴 High
* **발생 가능성:** 🟢 Low
* **대응 방안:**
  * **데이터 암호화** (전송 시 TLS, 저장 시 AES-256).
  * **접근 제어** (RBAC 기반으로 데이터 접근 권한 엄격 관리).
  * **정기적인 보안 감사** 및 침투 테스트 수행.

* * *

### 6. **센서 데이터 오염**

* **설명:** 센서의 오작동 또는 외부 요인(예: 먼지, 물)으로 인해 잘못된 데이터(예: 온도 100°C)가 수집될 경우, AI 분석 결과가 왜곡됨.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:**
  * **데이터 검증 로직** 구축(예: 온도 범위: 0°C~50°C 외는 필터링).
  * **다중 센서 교차 검증** (동일 위치의 여러 센서 값 비교).
  * **정기적인 센서 보정** 및 유지보수 스케줄 수립.

* * *

### 7. **클라우드 비용 초과**

* **설명:** 대량의 데이터 저장 및 AI 분석으로 인해 클라우드 사용 비용이 예산보다 급격히 증가할 수 있음.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:**
  * **비용 모니터링 대시보드** 구축 및 예산 초과 시 알림 시스템.
  * **데이터 수명 주기 관리** (예: 1년 이상된 데이터는 아카이브 스토리지로 이동).
  * **스팟 인스턴스** 활용을 통해 AI 학습 비용 절감.
