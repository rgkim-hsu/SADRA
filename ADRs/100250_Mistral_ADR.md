📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: **클라우드 기반 중앙 집중식 데이터 관리 아키텍처 채택**

| 항목                     | 내용                                                                                                                                     |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 시스템은 실시간으로 수집되는 농장 데이터(예: 환경 센서 데이터, 제어 명령)를 안정적으로 저장하고 관리해야 함. 농장 제어기에서 수집된 데이터를 중앙에서 통합 관리할 필요가 있으며, 네트워크를 통한 데이터 전송과 저장이 필수적임. |
| **결정(Decision)**       | 클라우드 서버를 중앙 집중식 데이터 저장소로 사용하고, 농장 제어기에서 수집된 데이터를 네트워크를 통해 클라우드 서버로 전송하여 저장 및 관리하도록 설계.                                                 |
| **근거(Rationale)**      | 클라우드 서버는 대용량 데이터를 효율적으로 저장하고, 필요 시 농장 제어기 또는 관리자 단말에서 접근할 수 있도록 유연성을 제공. 또한, 클라우드는 확장성이 뛰어나며, 백업 및 재해 복구 기능이 내장되어 데이터 손실을 최소화할 수 있음.   |
| **결과(Consequences)**   | **장점**: 데이터의 중앙 집중 관리 가능, 실시간 데이터 분석 및 모니터링 용이, 확장성 및 유지보수 용이성 향상. **단점**: 네트워크 의존도로 인한 지연 또는 장애 시 데이터 전송 실패 가능성.                      |
| **트레이드오프(Trade-offs)** | 클라우드 사용으로 인한 비용 증가와 네트워크 의존도가 있지만, 데이터의 안정성과 접근성을 높일 수 있음.                                                                             |

### ADR-002: **네트워크 기반 분산 제어 시스템 설계**

| 항목                     | 내용                                                                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 농장 제어기는 엑추에이터(예: 환경 제어 장비)를 실시간으로 제어해야 하며, 관리자 단말에서 원격으로 제어 명령을 내려야 함. 네트워크를 통해 각 컴포넌트가 유기적으로 연결되어야 함.                        |
| **결정(Decision)**       | 네트워크를 통해 농장 제어기, 관리자 단말, 엑추에이터가 서로 통신할 수 있도록 분산 제어 시스템을 설계. 농장 제어기는 네트워크를 통해 엑추에이터를 제어하고, 관리자 단말은 네트워크를 통해 농장 제어기에 제어 명령을 전송. |
| **근거(Rationale)**      | 분산 제어 시스템은 실시간성과 유연성을 제공하며, 각 컴포넌트가 독립적으로 운영될 수 있도록 함. 네트워크를 통해 원격 제어 및 모니터링이 가능해지며, 시스템의 확장성이 향상됨.                           |
| **결과(Consequences)**   | **장점**: 실시간 제어 및 모니터링 가능, 시스템의 유연성 및 확장성 향상. **단점**: 네트워크 장애 시 제어 실패 가능성, 보안 취약점 노출 가능성.                                      |
| **트레이드오프(Trade-offs)** | 네트워크 의존도로 인한 안정성 저하 가능성 있지만, 실시간 제어 및 원격 접근성이 향상됨.                                                                            |

### ADR-003: **관리자 단말과 농장 제어기 간의 양방향 통신 프로토콜 표준화**

| 항목                     | 내용                                                                                         |
| ---------------------- | ------------------------------------------------------------------------------------------ |
| **상황(Context)**        | 관리자 단말에서 농장 제어기로 제어 명령을 전송하고, 농장 제어기는 관리자 단말에 상태 정보를 실시간으로 피드백해야 함. 양방향 통신이 원활히 이루어져야 함.   |
| **결정(Decision)**       | 관리자 단말과 농장 제어기 사이에서 **재배 환경 제어 프로토콜**을 표준화하여 양방향 통신을 구현. 이 프로토콜은 제어 명령과 상태 정보의 실시간 전송을 지원. |
| **근거(Rationale)**      | 표준화된 프로토콜은 통신의 신뢰성을 높이고, 호환성을 보장하여 다양한 장비 및 시스템과 연동이 가능해짐.                                 |
| **결과(Consequences)**   | **장점**: 통신 신뢰성 및 호환성 향상, 실시간 피드백 가능. **단점**: 프로토콜 설계 및 구현의 복잡성 증가.                         |
| **트레이드오프(Trade-offs)** | 프로토콜 표준화로 인한 초기 개발 비용 증가지만, 장기적으로 시스템의 안정성과 호환성이 향상됨.                                      |

⚠️ 잠재적 위험 분석
------------

### 1. **네트워크 장애로 인한 데이터 전송 실패**

* **설명:** 네트워크 연결이 불안정하거나 장애가 발생할 경우, 농장 제어기에서 클라우드 서버로 데이터가 전송되지 않거나, 관리자 단말에서 농장 제어기로 제어 명령이 전달되지 않을 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 네트워크 이중화(예: 유선 및 무선 백업 네트워크 구축) 및 오프라인 모드 지원(데이터 임시 저장 후 네트워크 복구 시 전송).

* * *

### 2. **클라우드 서버 장애로 인한 데이터 손실**

* **설명:** 클라우드 서버에 장애가 발생할 경우, 저장된 농장 데이터가 손실되거나 접근이 불가능해질 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟢 Low
* **대응 방안:** 클라우드 서버의 정기적인 백업 및 재해 복구 계획 수립. 다중 클라우드 제공업체 이용을 통한 데이터 중복 저장.

* * *

### 3. **보안 취약점으로 인한 데이터 유출**

* **설명:** 네트워크를 통해 전송되는 데이터가 해킹 또는 인터셉트될 경우, 민감한 농장 데이터가 유출될 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 데이터 암호화(예: TLS/SSL 프로토콜 사용) 및 접근 제어 정책 강화. 정기적인 보안 감사 및 취약점 패치.

* * *

### 4. **농장 제어기 하드웨어 고장으로 인한 제어 실패**

* **설명:** 농장 제어기의 하드웨어 고장으로 인해 엑추에이터 제어가 불가능해질 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟢 Low
* **대응 방안:** 하드웨어 이중화(예: 예비 농장 제어기 설치) 및 정기적인 유지보수 수행.

* * *

### 5. **데이터 오염으로 인한 잘못된 제어 명령**

* **설명:** 센서 오류 또는 데이터 전송 중 오염으로 인해 농장 제어기가 잘못된 데이터를 받아 엑추에이터를 잘못 제어할 수 있음.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 데이터 검증 메커니즘 도입(예: 체크섬, 중복 데이터 검증) 및 실시간 모니터링 시스템 구축.
