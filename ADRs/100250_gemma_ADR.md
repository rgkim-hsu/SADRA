## 📋 ADR (Architecture Decision Record)

### ADR-001: 서비스 중심의 표준화된 데이터 인터페이스 계층 도입

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 시스템은 관리자 단말, 클라우드, 농장 제어기 등 이질적인(Heterogeneous) 컴포넌트와 다양한 물리적 환경 센서/액추에이터를 연결해야 합니다. 이로 인해 서로 다른 프로토콜(Modbus, Zigbee, MQTT 등)과 데이터 구조를 가진 기기들 간의 **상호운용성(Interoperability)** 확보가 가장 큰 아키텍처적 난관입니다. 단순히 장비를 연결하는 것을 넘어, '통일된 언어'로 데이터를 해석하고 제어 명령을 전달해야 합니다. |
| **결정(Decision)** | **API 게이트웨이(API Gateway)**를 중심으로 하는 **서비스 지향 아키텍처(Service-Oriented Architecture, SOA)** 및 **마이크로서비스 아키텍처(MSA)**를 채택하고, 데이터 모델링은 **업계 표준 아키텍처 프레임워크 (예: ISO/IEC 30141)**를 준수하여 추상화 계층을 설계한다. |
| **근거(Rationale)** | 1. **표준화 강제:** API Gateway는 모든 상호작용을 거대한 표준화된 게이트웨이로 통합하여, 하위 레벨의 통신 프로토콜 복잡성을 사용자에게 숨겨줍니다. 2. **느슨한 결합(Loose Coupling):** 각 기능(센서 데이터 수집, 환경 제어 로직, 사용자 인터페이스)을 독립적인 서비스(Microservice)로 분리하여, 한 컴포넌트의 오류나 변경이 시스템 전체에 영향을 미치는 것을 방지합니다. 3. **확장성:** 신규 작물, 신규 센서 등을 추가할 때 기존 시스템을 재설계할 필요 없이 새로운 마이크로서비스를 게이트웨이에 연결하기만 하면 됩니다. |
| **결과(Consequences)** | **긍정적:** 시스템의 신뢰성, 확장성, 유지보수성이 극대화됩니다. 다양한 공급업체의 장비(Vendor Agnostic)를 통합할 수 있어 글로벌 시장 대응력이 높아집니다. **부정적:** 초기 아키텍처 설계 및 구현 단계가 매우 복잡하고 높은 전문성이 요구됩니다. |
| **트레이드오프(Trade-offs)** | **장점:** 장기적인 관점에서 최고의 확장성과 안정성을 확보합니다. 표준 아키텍처(ISO/IEC 30141) 준수로 인한 국제적 신뢰성 확보가 가능합니다. **단점:** 초기 구축 비용(Time-to-Market)이 높아지며, 초기 단계에서 충분한 표준화 작업(Data Ontology 정의)이 선행되지 않으면 시스템의 복잡도만 가중될 수 있습니다. |

## ⚠️ 잠재적 위험 분석

### 1. 사이버 물리 계층(OT)의 원격 제어 취약점
- **설명:** 관리자 단말에서 전송된 원격 제어 명령(예: 펌프 작동, 환경 개폐)이 네트워크 또는 제어기 단계에서 무단 접근이나 패킷 조작을 겪을 경우, 물리적인 작물 및 장비에 심각한 피해를 입히는 사고(예: 과도한 급수, 독성 가스 누출)가 발생할 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:**
    1. **제로 트러스트 네트워크(Zero Trust Network):** 농장 제어기(100)와 클라우드(200) 간의 모든 통신을 신뢰하지 않고, 접근할 때마다 인증 및 권한 검사를 수행합니다.
    2. **물리적 안전 인터록(Physical Interlock):** 원격 제어 명령은 항상 제한 범위 내에서만 작동하도록 제어기 레벨에 안전 제한 장치(Safety PLC)를 구현하고, 비상 정지(Emergency Stop) 메커니즘을 확보합니다.
    3. **패키지 인증:** 제어 명령 페이로드(Payload)에 디지털 서명을 의무화하여 위변조 여부를 검사합니다.

### 2. 데이터 프로토콜/스키마 비호환성 및 종속성
- **설명:** 농장 현장의 센서(IoT Device)가 시간이 지나면서 교체되거나, 다른 제조사의 장비가 추가될 때, 기존의 데이터 처리 파이프라인(파싱 로직, 데이터베이스 스키마)을 대규모로 수정해야 하는 상황이 발생합니다. 이는 시스템의 확장성을 저해하는 가장 흔한 기술적 위험입니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:**
    1. **표준 온톨로지 도입:** 데이터 모델링 시, 물리적인 데이터 값(값) 자체와 이를 설명하는 의미론적 속성(Semantic Ontology)을 분리하고, 모든 컴포넌트가 이 표준 데이터 언어를 사용하도록 의무화합니다.
    2. **데이터 메시지 버스(Data Bus) 활용:** 실제 데이터 처리를 API 게이트웨이 뒤의 서비스 계층에서 처리하게 하여, 물리적 연결 변경이 상위 로직에 미치는 영향을 최소화합니다.
    3. **버전 관리 정책:** API는 항상 명시적인 버전 관리(v1, v2...)를 적용하고, 이전 버전의 데이터를 최소한의 기간 동안 처리할 수 있는 레거시 호환 레이어를 유지합니다.

### 3. 네트워크 단절에 따른 서비스 연속성 실패
- **설명:** 농장 현장의 통신 인프라(5G/LTE 게이트웨이, 근거리 백본 네트워크)가 기상 악화나 인프라 장애로 인해 장시간 단절될 경우, 원격 제어(20 $\to$ 100) 명령 전달이 불가능해지고, 실시간 데이터 수집이 중단되어 작물 관리 로직에 치명적인 공백이 생길 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:**
    1. **엣지 컴퓨팅(Edge Computing) 강화:** 농장 제어기(100) 자체에 최소한의 핵심 제어 로직(Critical Path Control Loop)을 내장하여, 클라우드 연결이 끊어져도 일정 기간 동안의 자율적인 모니터링 및 제어(Fail-Safe Mode)가 가능하도록 합니다.
    2. **백업 통신 채널 확보:** 메인 네트워크 외에 위성 통신(Satellite) 또는 전용 백업 LTE 회선 등 이원화된 통신 경로를 확보하고, 자동 장애 감지 및 전환 로직을 구현합니다.

### 4. 데이터 주권 및 개인정보보호 위반
- **설명:** 농장 데이터(수확량, 환경 제어 이력)는 농장 운영 주체의 핵심 자산이자 민감 정보입니다. 클라우드 서버(200)에서 이 데이터가 관리되면서, 국가 차원의 데이터 유출이나, 클라우드 서비스 제공자(CSP)의 정책 변경 등으로 인해 데이터 주권을 상실하거나 유출될 위험이 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:**
    1. **데이터 현지화 및 암호화:** 민감한 원본 데이터는 가능한 한 현지(Edge/On-premise)에서 전처리하고, 클라우드로 전송되는 모든 데이터는 전송 및 저장 단계에서 강력한 암호화(End-to-End Encryption)를 적용합니다.
    2. **데이터 주권 확보:** 핵심 비즈니스 로직(Decision Engine)과 데이터베이스는 특정 CSP에 과도하게 종속되지 않도록 이식성 높은 아키텍처를 채택하고, 데이터 주권(Data Sovereignty) 관련 법규를 준수합니다.

### 5. 최적화 알고리즘의 블랙박스화 및 설명 불가능성 (Explainability)
- **설명:** AI 기반의 작물 생육 최적화 로직(예: 수확 예측, 최적 관수량 결정)을 클라우드 서버에서 실행할 때, 모델의 복잡성(Deep Learning)으로 인해 왜 특정 제어 명령(예: '오늘 물을 20% 줄여라')을 내렸는지 운영자가 명확히 이해할 수 없는 '블랙박스' 현상이 발생합니다. 이는 운영자의 시스템 신뢰도 저하를 야기합니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low
- **대응 방안:**
    1. **설명 가능한 AI(XAI) 적용:** AI 모델을 사용할 때, 단순히 결과값만 제시하는 것이 아니라, 결과가 도출된 주요 근거(예: "최근 3일간의 습도 변화와 작물 질병 지표 A가 20% 증가하여...")를 함께 제시하는 인터페이스를 구축합니다.
