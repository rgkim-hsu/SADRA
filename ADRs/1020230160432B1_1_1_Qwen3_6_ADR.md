# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 다단계 문맥 인식 기반 농기계 진단 및 제어 아키처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                                                             |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 농기계(200)는 열악하고 변수가 많은 환경에서 작동하므로, 단순한 에러 카운트 횟수만으로 고장을 진단할 경우 오진(False Positive)이 빈번하게 발생함. 또한, 고장 발생 시 단순 알림을 넘어 자동화된 제어(120)가 필요하나, 잘못된 제어는 큰 안전 사고로 이어질 수 있는 아키텍처적 과제가 존재함.                                                                                                                 |
| **결정(Decision)**       | 단순 에러 감지를 넘어 **다단계 진단 파이프라인(Multi-Stage Diagnostic Pipeline)**을 채택함. `진단 모듈(110)` 내부에 `고장 여부 재 판정부(112)`를 두어, `기초 진단 결과`에 `환경적 요인`, `복수 부품 특징`, `추가 연료 소모량` 등의 복합적인 문맥(Context) 데이터를 반영하여 `최종 진단 결과`를 도출하도록 설계함.                                                                               |
| **근거(Rationale)**      | 1. **진단 정확도 향상:** 환경적 요인(예: 진동, 먼지)이나 정상적인 부하(연료 소모 증가)로 인한 일시적 에러를 걸러내고, 실제 부품 고장을 정확히 식별하기 위해 문맥 데이터가 필수적임.<br>2. **안전한 자동 제어:** `제어 모듈(120)`이 행되기 전 `최종 진단 결과`를 통해 신뢰도를 높임으로써, 오작동으로 인한 기계적 손상이나 인명 피해를 방지함.<br>3. **예지 정비(Predictive Maintenance):** 연료 소모량 변화 등을 감지하여 고장 전조 증상을 포착할 수 있음. |
| **결과(Consequences)**   | 농기계의 가동률 향상 및 유지보수 비용 절감이 가능해지며, 사용자에게 정확한 고장 정보를 제공할 수 있음. 반면, 진단 로직이 복잡해져 시스템 개발 및 유지보수 난이도가 상승하고, 다수의 데이터를 실시간으로 처리해야 하므로 컴퓨팅 리소스 요구사항이 증가함.                                                                                                                                                |
| **트레이드오프(Trade-offs)** | 높은 진단 정확도 및 안전한 자동 제어 확보 vs. 시스템 복잡도 증가 및 실시간 데이터 처리에 따른 지연(Latency) 가능성.                                                                                                                                                                                                                      |

## ️ 잠재적 위험 분석

### 1. 재 판정부(112)의 판으로 인한 치명적 고장 방치 (False Negative)

- **설명:** `고장 여부 재 판정부(112)`가 `환경적 요인`이나 `연료 소모량` 등을 과도하게 반영하여, 실제 심각한 고장임에도 불구하고 '정상' 또는 '경미한 상태'로 잘못 판단할 경우, 농기계가 고장난 상태로 계속 가동되어 복구 불가능한 손상이 발생할 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 재 판정 로직에 'Fail-Safe' 원칙 적용, 특정 치명적 에러 코드는 문맥 데이터와 무관하게 즉시 `최종 진단 결과`로 전달하도록 우선순위 규칙(Priority Rule) 설정.
  
  ### 2. 제어 모듈(120)의 오작동으로 인한 안전 사고
- **설명:** `최종 진단 결과`에 기반하여 `제어 모듈(120)`이 농기계(200)의 엔진 정지나 작동 제한을 명령할 때, 경사면이나 위험한 작업 환경에서 갑자기 기계가 멈추면 전복 등 2차 안전 사고가 발생할 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 제어 명령 실행 전 농기계의 현재 상태(기울기, 속도 등)를 확인하여 안전한 모드로 전환(예: 서서히 감속)하는 로직 구현, 긴급 정지 버튼 등 하드웨어적 안전 장치 병행.
  
  ### 3. 복합 요인 데이터 수집 지연에 의한 실시간성 저하
- **설명:** `환경적 요인`, `부품 특징`, `연료 소모량` 등 다양한 데이터를 수집하고 `재 판정부(112)`에서 분석하는 데 시간이 소요될 경우, 실시간으로 발생해야 할 `기초 진단 결과`나 `제어`가 지연되어 적기 대응이 어려울 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 엣지 컴퓨팅(Edge Computing) 도입을 통해 농기계 내부에서 1차 데이터 처리 및 진단 수행, 클라우드 기반 고도 분석과 분산 처리 아키텍처 채택.
  
  ### 4. 사용자 단말(300) 통신 두절 시 모니터링 공백
- **설명:** `최종 진단 결과`가 `사용자 단말(300)`로 전송되어야 하나, 농장 내 네트워크 사각지대나 통신 장애로 인해 전송이 패할 경우, 사용자는 고장 사실을 인지하지 못하고 방치할 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 통신 두절 시 농기계 현지(200)에 시각/청각적 경고 장치(사이렌, 램프) 작동, 통신 복구 시 미전송 데이터 일괄 전송(Store-and-Forward) 메커니즘 적용.
  
  ### 5. 연료 소모량 데이터의 노이즈로 인한 진단 왜곡
- **설명:** `농기계 주행시의 추가 연료 소모량 발생 관련 요인` 데이터가 센서 오차나 외부 환경(바람, 온도)에 의해 왜곡될 경우, 이를 고장 신호로 오인하여 불필요한 `제어 모듈(120)` 작동을 유발하거나 유지보수 비용을 증가시킬 수 있음.
- **심각도:**  Medium
- **발생 가능성:**  Medium
- **대응 방안:** 연료 데이터에 이동 평균(Moving Average) 필터 적용 등 노이즈 제거 알고리즘 도입, 다중 센서 데이터 교차 검증(Cross-Validation)을 통한 데이터 신뢰도 확보.
