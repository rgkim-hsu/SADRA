## 📋 ADR (Architecture Decision Record)

### ADR-001: [동적 랜딩 페이지 생성 및 모바일-FIRST 접근 전략]

| 항목 | 내용 |
|------|------|
| **상황(Context)** | **문제:** 기존의 생산이력 관리 시스템이나 정보화망은 접근성이 떨어지고 (문서 참조), 복잡한 소프트웨어 설치가 필요함.<br>**과제:** 농민 (생산자) 과 소비자 모두 낮은 진입 장벽으로 서비스를 사용할 수 있도록 하되, 개인화된 정보를 제공해야 함. |
| **결정(Decision)** | **결정:** 생산자마다 고유한 URL을 가진 '생산자 개별 홈페이지'를 생성하고, 이를 QR 코드로 인코딩하여 제공하는 방식 채택.<br>**구현:** 모바일 브라우저와 PC 웹 환경을 지원하며, 별도의 애플리케이션 다운로드 없이 웹페이지 접근으로 구현 (Responsive Web Design). |
| **근거(Rationale)** | **기술적 근거:** QR 코드는 URL 인코딩에 최적화되어 있음. HTTPS 보안을 적용하여 브라우저 내 신뢰성 확보.<br>**비즈니스 근거:** 문서에서 언급한 대로 스마트폰 보급률이 높아 웹 접근이 최상의 사용자 경험 (UX) 을 제공함.<br>**유연성:** 백엔드 DB 데이터를 기반으로 프론트엔드를 동적으로 렌더링하므로, 농산물 종류나 농법 정보 변경 시 실시간 반영이 가능함. |
| **결과(Consequences)** | **긍정적:** 개발 및 유지보수 비용 절감. 소비자가 별도 앱 설치 없이 스캔만 하면 정보 조회 가능.<br>**부정적:** 서버 부하 관리가 중요해짐 (동적 페이지 생성 시 캐싱 전략 필요). |
| **트레이드오프(Trade-offs)** | **장점:** 확장성 높음 (새로운 농가 추가가 빠름).<br>**단점:** 세션 유지 관리가 필요할 수 있음 (로그인 상태 등). |

### ADR-002: [중앙 집중식 통합관리시스템과의 연동 전략]

| 항목 | 내용 |
|------|------|
| **상황(Context)** | **문제:** 생산자가 직접 홈페이지를 만들면 관리가 어렵고 통일된 신뢰도 기준이 부족함.<br>**과제:** 기존 농수산물 브랜드 이미지뿐만 아니라 실제 생산 과정을 투명하게 보여줘야 함 (Trust & Transparency). |
| **결정(Decision)** | **결정:** '통합관리시스템' (Backend) 을 구축하여 모든 생산자의 데이터를 중앙에서 관리하고, 이를 '소비자 앱/웹' 측에 노출하는 계층적 아키텍처를 구축.<br>**구조:** 생산자 회원가입 -> 통합관리시스템 데이터 연동 -> 개별 홈페이지 생성 -> QR 코드 출력. |
| **근거(Rationale)** | **보안 및 신뢰:** 개별 농민들이 직접 서버를 운영할 경우 보안 정책이 분산되어 위험함. 중앙 서버에서 인증, 권한 관리 (RBAC) 를 수행.<br>**데이터 일관성:** 생산일지, 재배 농약 정보 등 핵심 데이터를 한 곳에서 관리하여 소비자에게 항상 동일한 정보를 제공.<br>**스케일링:** 수만 개의 농가 데이터를 처리할 때 데이터베이스 클러스터링 및 캐싱 기술을 적용하기 용이함. |
| **결과(Consequences)** | **긍정적:** 데이터의 정확성과 신뢰도가 높음. 시스템 장애 시 복구 관리가 중앙에서 용이함.<br>**부정적:** 초기 구축 비용 (Infra cost) 이 높을 수 있음. |
| **트레이드오프(Trade-offs)** | **장점:** 표준화된 UI/UX 제공, 보안 중앙 통제.<br>**단점:** 시스템 가용성 (Availability) 이 핵심 인프라에 의존함. |

## ⚠️ 잠재적 위험 분석

### 1. [위조 QR 코드 및 신뢰성 저하 위험]
- **설명:** 가짜 농산물 포장지에 QR 코드를 부착하거나, 악의적인 사용자가 QR 코드를 수정하여 잘못된 정보 (위장 판매 농가 등) 를 보여주는 경우, 소비자의 시스템에 대한 신뢰가 무너질 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** QR 코드 생성 시 서버-side 에서 타임스탬프와 기호 (Salt) 를 포함하여 위조 방지 (Nonce/Signature), 또는 QR 코드가 지정한 URL 의 유효성을 서버에서 재확인하는 인증 과정 도입.

### 2. [개인정보 보호 (PIPL) 및 데이터 유출 위험]
- **설명:** 생산자 (농민) 가 업로드하는 생체 데이터, 사진, 농장 내 영상 등 민감한 정보가 외부로 유출되거나, 소비자로부터 수집된 데이터가 제대로 보호되지 않을 경우 법적 문제가 발생할 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 전송 데이터 암호화 (TLS), 서버 스토리지 격리 (Encryption at Rest), 개인정보 처리 방침 준수 및 최소 권한 원칙 적용.

### 3. [실시간 데이터 동기화 지연 (Data Latency)]
- **설명:** 농민이 현장에서 촬영한 사진이나 입력한 일지 내용을 서버에 업로드하는 과정에서 네트워크 상태 (특히 농촌 지역 통신 환경) 에 의해 정보 제공 시점에 지연이 발생할 경우, 소비자가 '실시간' 정보를 원하면 불만이 생김.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 오프라인 모드 지원 (로컬 저장 후 동기화), 혹은 주요 영상/이미지는 CDN을 활용하여 지연 최소화 전략 적용.

### 4. [웹 서버 부하 과부하 위험]
- **설명:** 동적 랜딩 페이지 생성 전략 (ADR-001) 을 적용했으므로, 수많은 QR 코드 스캔 요청이 특정 시간에 집중될 경우 (예: 수확 시즌 직후), 백엔드 서버가 병목 현상을 겪을 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 로드 밸런서 활용, 이미지 및 정적 리소스 CDN 사용, 동적 페이지 렌더링 시 캐싱 (Redis 등) 을 적극 적용하여 서버 부하 분산.

### 5. [접근성 및 모바일 기종 호환성 문제]
- **설명:** 모든 스마트폰 카메라의 QR 코드 인식 성능이 다르거나, 브라우저 (Chrome, Safari 등) 환경 차이로 인해 웹페이지가 다르게 렌더링되어 정보를 제대로 볼 수 없는 경우 발생.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low (기술적 성숙도 증가)
- **대응 방안:** PWA (Progressive Web App) 방식 채택으로 오프라인 기능 및 앱 유사한 경험 제공, 다양한 디바이스 테스트를 통한 Responsive 디자인 강화.
