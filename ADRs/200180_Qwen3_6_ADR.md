## 200180

# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: IoT 기반 누에 사육 환경 원격 모니터링 및 제어 아텍처 도입

| 항목                     | 내용                                                                                                                                                                                                       |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 누에 사육은 온도, 습도, CO2 농도 등 미세한 환경 변화에 민감하게 반응하는 정밀한 관리가 필요합니다. 기존 아날로그 방식이나 단순 자동화 시스템은 실시간 데이터 시각화와 원격에서의 즉각적인 개입이 어려워, 사육 관리의 효율성과 데이터 기반의 최적화(AI 분석 등)에 한계가 있었습니다.                                       |
| **결정(Decision)**       | **IoT 기반의 원격 모니터링 및 제어 아키처**를 채택합니다. 사육 공간 내의 센서(온도, 습도, CO2) 및 영상 획득 장치를 통해 데이터를 수집하여 인터넷을 경유한 `<생육환경정보관리 시스템>`(웹/스마트폰)으로 전송하고, 역으로 제어 명령을 `<환경 제어 공간>`의 입력 모듈로 전달하는 양방향 통신 구조를 구축합니다.                  |
| **근거(Rationale)**      | 이미지에서 볼 수 있듯이, 센서 값과 영상 정보가 인터넷을 통해 상위의 관리 시스템으로 전달되고, 여기서 생성된 데이터와 제어 요청이 하위의 환경 제어 시스템으로 피드백되는 구조입니다. 이는 물리적 사육 공간과 논리적 제어 공간을 분리하여 관리자가 장소에 구애받지 않고 사육 환경을 최적화할 수 있게 하며, 축적된 데이터를 활용한 과학적 사육이 가능해집니다. |
| **결과(Consequences)**   | **긍정적:** 실시간 환경 모니터링과 원격 제어로 관리 효율성이 극대화되며, 데이터 축적을 통한 사육 패턴 분석이 가능합니다.<br>**부정적:** 인터넷 연결에 대한 의존도가 높아져 네트워크 장애 시 원격 제어가 불가능해질 수 있으며, 영상 데이터 전송으로 인한 대역폭占用 문제가 발생할 수 있습니다.                               |
| **트레이드오프(Trade-offs)** | **장점:** 관리의 편의성 및 데이터 기반 의사결정 가능.<br>**단점:** 네트워크 인프라 구축 비용 및 사이버 보안 위험 증가.                                                                                                                              |

---

## ️ 잠재적 위험 분석

### 1. 네트워크 단절 시 원격 제어 불가 (Network Dependency Risk)

- **설명:** `<생육환경정보관리 시스템>`과 하부의 `<누에 사육용 환경제어 시스템>`이 인터넷을 통해 통신합니다. 만약 농장의 인터넷 연결이 끊기거나 지연이 발생할 경우, 관리자는 실시간 모니터링은 물론이고 긴급한 환경 제어(예: 온도 급상승 시 환기 가동)를 할 수 없게 됩니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** `<환경 제어 공간>` 시스템에 **로컬 자동 제어 로직(Edge Logic)**을 내재화하여, 네트워크 단절 시에도 사전 설정된 임계값(Threshold)을 기반으로 센서 값에 따라 자동으로 입출력 모듈을 제어하는 Fail-safe 모드를 운영해야 합니다.

### 2. 센서 데이터 왜곡으로 인한 오작동 (Sensor Data Integrity Risk)

- **설명:** `온도 센서`, `습도 센서`, `CO2 센서`에서 수집된 데이터가 노이즈나 센서 고장으로 인해 왜곡될 경우, `<생육환경정보관리 시스템>`은 잘못된 상황을 인지하고 잘못된 제어 명령을 내릴 수 있습니다. 예를 들어, 실제 온도는 정상인데 센서 오류로 고온으로 감지되어 냉각 장치가 과도하게 작동할 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 단일 센서 값에 의존하지 않고, 다중 센서를 활용한 **교차 검증(Cross-Validation)** 알고리즘을 적용하거나, 데이터의 급격한 변동(Rate of Change)을 감지하여 이상치로 판별하는 **필터링 로직**을 `<환경 제어 시스템>`에 구현해야 합니다.

### 3. 영상 데이터 전송 대역폭 병목 (Bandwidth Bottleneck)

- **설명:** `영상 획득 장치`가 고해상도 영상을 실시간으로 인터넷을 통해 전송할 경우, 제어 신호(센서 값, 제어 명령)가 전송되는 대역폭을 침범하여 제어 지연(Latency)을 유발할 수 있습니다. 이는 실시간성이 중요한 환경 제어에 치명적일 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 영상 전송 프로토콜을 제어 신호와 분리하거나, **MQTT**와 같은 경량 프로토콜을 제어 신호에 우선 적용해야 합니다. 또한 영상은 이벤트 기반(이상 감지 시 전송)으로 전송하거나 해상도를 동적으로 조절하는 **Adaptive Bitrate Streaming** 기술을 도입해야 합니다.

### 4. 사이버 보안 위협 (Security Vulnerabilities)

- **설명:** `웹 제어 시스템`과 `스마트폰 제어 시스템`이 인터넷에 노출되어 있습니다. 인증 절차가 취약할 경우, 악의적인 제3자가 시스템에 접근하여 사육 환경을 의도적으로 파괴(예: 모든 환기 장치 차단)하거나 민감한 사육 데이터를 탈취할 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 모든 통신 구간에 **SSL/TLS 암호화**를 적용하고, 사용자 인증 시 **다중 인증(MFA)**을 의무화해야 합니다. 또한, 정기적인 보안 패치 적용 및 방화벽(Firewall) 설정을 통해 비인가된 접근을 차단해야 합니다.

### 5. 피드백 루프의 비동기화 문제 (Feedback Loop Asynchrony)

- **설명:** `<환경 제어 공간>`에서 `<누에 사육용 환경제어 시스템>`으로 `피드백`이 전달되는 과정이 명시되어 있습니다. 제어 명령이 실행된 후 그 결과(예: 온도 하강)가 센서를 통해 다시 상위로 전달되는 과정에 지연이 발생하면, 시스템이 현재 상태를 잘못 판단하여 과도한 제어(Overshooting)를 수행할 수 있습니다.
- **심각도:**  Medium
- **발생 가능성:**  Medium
- **대응 방안:** 제어 알고리즘에 **PID 제어**와 같은 안정화 로직을 적용하여 급격한 제어 변화를 방지하고, 피드백 데이터의 타임스프를 동기화하여 최신 상태만을 반영하도록 데이터 처리 로직을 최적화해야 합니다.
