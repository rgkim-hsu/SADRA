## PAT-20

# ️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 팜커넥트 5단계 진화형 데이터 파이프라인 및 AI 통합 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 운영 플랫폼 '팜커넥트'는 단순 센서 데이터 수집(1단계)에서 시작하여, 기상/관수 분석(2단계), AI 기반 수확 예측 및 시뮬레이션(3단계), 실시간 병충해 감지(4단계), 그리고 글로벌 물량/가액 예측(5단계)까지 점진적으로 고도화되어야 함. 이질적인 데이터 소스(센서, 외부 기상, 시장 데이터)를 통합하고 단계별 분석 결과를 상위 계층의 AI 모델에 효과적으로 공급해야 하는 아키텍처적 과제가 존재함.                                                                        |
| **결정(Decision)**       | 시스템 기능을 데이터 처리 및 분석의 성숙도에 따라 **5단계 계층(Level 1~5)**으로 명확히 분리하고, 하위 계층의 정제된 데이터를 상위 계층의 고급 분석 모델(딥러닝, 시뮬레이션)로 공급하는 **계층적 데이터 파이프라인(Hierarchical Data Pipeline) 아키처**를 채택함.                                                                                                                                          |
| **근거(Rationale)**      | 1. **데이터 품질 보증:** 1~2단계에서의 기초 분석(관수, 환기 등)을 통해 노이즈를 제거한 양질의 데이터만이 3단계의 '수확예측딥러닝'이나 4단계의 '병충해 탐지'에 입력되도록 하여 AI 모델의 정확도를 높임.<br>2. **단계적 확장성:** 사용자의 니즈와 인프라 수준에 따라 1단계 기능만 사용할 수도 있고, 5단계까지 모두 사용할 수 있도록 모듈화된 계층 구조는 유연한 서비스 제공을 가능하게 함.<br>3. **복잡성 관리:** 방대한 양의 센서 데이터와 복잡한 AI 연산을 단계별로 분리함으로써 시스템 리소스 관리를 효율화함. |
| **결과(Consequences)**   | 명확한 기술 로드맵과 기능별 독립적인 개발/배포가 가능해지며, 데이터의 신뢰성이 상위 AI 분석으로 직결됨. 반면, 데이터가 여러 계층을 통과해야 하므로 1단계에서 5단계까지의 엔드-투-엔드(End-to-End) 지연(Latency)이 발생할 수 있음.                                                                                                                                                                     |
| **트레이드오프(Trade-offs)** | 데이터 정제 및 AI 모델 성능 최적화 용이, 시스템 모듈성 확보 vs. 실시간 처리(Real-time) 요구사항(특히 4단계) 충족을 위한 파이프라인 최적화 복잡도 증가.                                                                                                                                                                                                                  |

---

## ⚠️ 잠재적 위험 분석

### 1. 하위 계층 데이터 오류로 인한 상위 AI 모델 왜곡 (Garbage In, Garbage Out)

- **설명:** 1단계 '센서수집' 또는 2단계 '관수분석정보'에서 측정된 데이터에 오류가 발생하거나 보정이 되지 않은 채 3단계 '수확예측러닝'이나 4단계 '병충해 탐지'로 전달될 경우, AI 모델이 잘못된 학습을 하거나 엉뚱한 예측(예: 병충해가 없는데 알람 발생)을 할 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 2단계 분석 모듈 내에 데이터 효성 검증(Data Validation) 및 이상치 제거(Outlier Removal) 로직을 강력하게 적용, 1단계 센서 상태 모니터링 및 자가 진단 기능 도입.
  
  ### 2. 실시간 예측 시스템(4단계)의 처리 지연 (Latency)
- **설명:** 4단계 '실시간예측시스템' 및 '병충해 탐지'는 즉각적인 조치가 필요함. 그러나 1~3단계의 복잡한 분석 파이프라인을 거치는 동안 데이터 처리 시간이 길어지면, 실제 병충해 발생 시점에 늦게 알람이 울려 작물 피해가 발생할 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 4단계 실시간 분석을 위해 1~2단계의 원본 데이터를 우회하여 직접 전달하는 'Fast-Track' 데이터 경로 마련, 지 컴퓨팅(Edge Computing) 도입을 통해现场에서 1차 분석 수행.
  
  ### 3. AI 예측 시뮬레이션(3/5단계)의 컴퓨팅 리소스 고갈
- **설명:** 3단계와 5단계의 'AI예측시뮬레이션' 및 '전세계물량가액 예측시스템'은 고사양의 연산 리소스를 필요로 함. 동다수의 농가가 동시에 시뮬레이션을 요청할 경우 서버 과부하로 인해 시스템 전체가 마비될 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 시뮬레이션 작업은 비동기 큐(Asynchronous Queue)를 통해 예약 처리하도록 설계, 클라우드 기반 오토스케일링(Auto-scaling) 인프라 도입, GPU 인스턴스 활용.
  
  ### 4. 병충해 탐지 모델의 오탐(False Positive) 과다
- **설명:** 4단계 '병충해 탐지 및 알람' 시스템이 환경 변화(그림자, 잎의 흔들림 등)를 병충해로 오인하여 빈번한 오탐지를 발생시킬 경우, 사용자가 알람에 무감각해지거나(Alarm Fatigue) 불필요한 방제 작업을 수행하여 비용이 낭비됨.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 이미지 기반 병충해 탐지 시 다중 각도 촬영 및 시간 간격 비교를 통한 검증 로직 추가, 오탐 사례를 피드백하여 모델을 지속적으로 재학습(Retraining)시키는 파이프라인 구축.
  
  ### 5. 외부 데이터 소스(기상, 시장) 연계 불안정
- **설명:** 2단계 '외부기상정보' 및 5단계 '전세계물량가액 예측'은 외부 API나 데이터베이스에 의존함. 외부 데이터 제공 업체의 장애나 API 변경 시, 팜커넥트 시스템의 예측 기능이 중단되거나 부정확한 정보를 제공할 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low
- **대응 방안:** 외부 데이터 소스를 다중화(Multi-sourcing)하여 하나의 소스 장애 시 다른 소스로 전환, 캐싱(Caching) 전략을 통해 일시적 연결 끊김에도 최근 데이터로 서비스 지속.
