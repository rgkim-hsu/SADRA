📋 ADR (Architecture Decision Record)

### ADR-001: 모니터링·제어·결과관리 분리형 스마트팜 운영 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 시스템은 모니터링모듈(2), 제어모듈(4), 결과관리모듈(5), 데이터베이스(DB)로 구성된다. 모니터링모듈은 환경정보수집부(21), 객체식별부(22), 병충해판단부(23), 음영분석부(24), 객체매칭부(25)를 포함하고 있으며, 제어모듈은 스케줄관리부(41), 작업추천부(42), 작업접수부(43), 작업관리부(44)로 구성된다. 결과관리모듈은 추적부(51), 갱신부(52)를 담당한다. 스마트팜 환경에서는 데이터 수집, AI 분석, 작업 제어, 결과 추적이 동시에 요구되므로 기능 간 결합도를 낮추고 확장성을 확보하는 것이 핵심 과제이다. |
| **결정(Decision)**       | 기능별 역할을 독립적으로 수행하는 모듈 분리형(Microservice-Oriented) 아키텍처를 채택한다. 모니터링모듈은 데이터 수집 및 AI 분석을 담당하고, 제어모듈은 운영 작업 스케줄 및 실행 제어를 수행하며, 결과관리모듈은 작업 이력 및 상태 추적을 담당한다. 모든 데이터는 중앙 데이터베이스를 통해 연계한다.                                                                                                                               |
| **근거(Rationale)**      | 스마트팜 AI 분석 기능은 데이터 처리량이 크고 연산 부하가 높기 때문에 제어 기능과 분리해야 안정적인 운영이 가능하다. 또한 기능별 독립 배포 및 확장이 가능해 유지보수성과 서비스 확장성이 향상된다.                                                                                                                                                                                                 |
| **결과(Consequences)**   | 시스템 확장성과 장애 격리성이 향상된다. AI 분석 기능 추가 및 모델 교체가 용이해진다. 반면 모듈 간 인터페이스 관리와 데이터 동기화 복잡성이 증가한다.                                                                                                                                                                                                                          |
| **트레이드오프(Trade-offs)** | 높은 유연성과 확장성을 확보하는 대신, 서비스 간 통신 및 운영 복잡도가 증가한다.                                                                                                                                                                                                                                                                   |

### ADR-002: AI 기반 병충해 및 음영 분석 구조 적용

| 항목                     | 내용                                                                                                   |
| ---------------------- | ---------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 병충해판단부(23)와 음영분석부(24)는 작물 상태와 재배 환경을 분석하여 품질 저하 및 생산성 감소를 예방해야 한다. 기존 수작업 진단 방식은 정확도와 대응 속도에 한계가 있다. |
| **결정(Decision)**       | 객체식별부(22)와 연계한 AI 기반 영상 분석 구조를 적용한다. 카메라 또는 센서 데이터를 활용하여 병충해 여부와 음영 상태를 자동 분석하고 결과를 제어모듈로 전달한다.      |
| **근거(Rationale)**      | 컴퓨터 비전 기반 분석은 대규모 농장 환경에서도 빠르고 일관된 판단이 가능하며, 조기 이상 탐지를 통해 생산 손실을 줄일 수 있다.                            |
| **결과(Consequences)**   | 병충해 대응 속도와 분석 정확도가 향상된다. 자동화된 농장 관리가 가능해진다. 그러나 AI 모델 학습 데이터 품질과 GPU 자원 요구사항이 증가한다.                  |
| **트레이드오프(Trade-offs)** | 자동 분석 효율성과 정확도를 얻는 대신, AI 모델 유지관리 및 연산 인프라 비용이 증가한다.                                                 |

### ADR-003: 작업 추천 및 스케줄 자동화 구조 채택

| 항목                     | 내용                                                                                               |
| ---------------------- | ------------------------------------------------------------------------------------------------ |
| **상황(Context)**        | 스마트팜 운영은 급수, 방제, 차광, 수확 등 다양한 작업을 일정에 따라 수행해야 하며, 환경 변화에 따라 작업 우선순위가 달라진다.                       |
| **결정(Decision)**       | 제어모듈(4)에 작업추천부(42)와 스케줄관리부(41)를 포함한 자동 작업 추천 및 스케줄링 기능을 적용한다. AI 분석 결과와 환경 정보를 기반으로 최적 작업을 추천한다. |
| **근거(Rationale)**      | 자동 스케줄링은 작업 누락을 방지하고 운영 효율성을 높인다. 또한 노동력 부족 문제를 완화할 수 있다.                                        |
| **결과(Consequences)**   | 운영 자동화 수준이 향상되고 작업 효율성이 증가한다. 그러나 잘못된 추천 알고리즘 적용 시 운영 오류 가능성이 존재한다.                              |
| **트레이드오프(Trade-offs)** | 운영 최적화와 자동화를 얻는 대신, 추천 알고리즘 검증 및 정책 관리 부담이 증가한다.                                                 |

### ADR-004: 결과 추적 및 데이터 갱신 중심 Traceability 구조 적용

| 항목                     | 내용                                                                                |
| ---------------------- | --------------------------------------------------------------------------------- |
| **상황(Context)**        | 농장 운영 결과와 작업 이력을 지속적으로 추적해야 품질 관리 및 운영 최적화가 가능하다. 특히 병충해 대응 이력과 작업 결과 분석은 중요하다.   |
| **결정(Decision)**       | 결과관리모듈(5)에 추적부(51)와 갱신부(52)를 두어 작업 결과 및 상태 정보를 지속적으로 업데이트하고 이력 데이터를 관리한다.         |
| **근거(Rationale)**      | 스마트팜에서는 데이터 기반 의사결정과 품질 관리가 중요하며, Traceability 체계는 운영 신뢰성과 규제 대응에 필수적이다.          |
| **결과(Consequences)**   | 작업 이력 기반 분석과 품질 개선이 가능해진다. 운영 상태에 대한 장기 분석 데이터가 축적된다. 그러나 데이터 저장 용량과 관리 비용이 증가한다. |
| **트레이드오프(Trade-offs)** | 데이터 기반 운영 최적화를 얻는 대신, 저장소 및 데이터 거버넌스 비용이 증가한다.                                    |

⚠️ 잠재적 위험 분석
------------

### 1. AI 병충해 분석 오탐 위험

* **설명:** 병충해판단부(23)가 정상 작물을 병충해로 오인하거나 실제 이상 상태를 탐지하지 못할 수 있음

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 지속적인 AI 모델 재학습, 전문가 검증 데이터셋 확보, 다중 센서 기반 교차 검증 적용

### 2. 모듈 간 데이터 동기화 오류 위험

* **설명:** 모니터링모듈과 제어모듈 간 데이터 전달 지연 또는 불일치가 발생할 수 있음

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 메시지 큐(Kafka, MQTT) 기반 비동기 처리, 트랜잭션 검증 로직 적용

### 3. 작업 추천 알고리즘 오류 위험

* **설명:** 작업추천부(42)가 부적절한 작업 순서를 추천할 경우 작물 품질 저하가 발생할 수 있음

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** Rule-based 검증 병행, Human-in-the-loop 승인 프로세스 적용

### 4. 데이터베이스 과부하 위험

* **설명:** 이미지 분석 데이터와 작업 로그 증가로 DB 성능 저하가 발생할 수 있음

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 시계열 DB 및 객체 스토리지 분리 적용, 데이터 아카이빙 정책 운영

### 5. 음영 분석 오차 위험

* **설명:** 조도 변화 또는 카메라 왜곡으로 인해 음영분석부(24)의 분석 정확도가 저하될 수 있음

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 조도 보정 알고리즘 적용, 멀티 카메라 기반 분석 및 캘리브레이션 수행

### 6. 결과 추적 데이터 위변조 위험

* **설명:** 작업 이력 데이터가 위변조될 경우 품질 관리 및 규제 대응 신뢰성이 저하될 수 있음

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 접근 제어 강화, 감사 로그 및 해시 기반 무결성 검증 적용

### 7. 현장 네트워크 장애 위험

* **설명:** 농장 네트워크 불안정 시 실시간 모니터링 및 제어가 중단될 수 있음

* **심각도:** 🔴 High

* **발생 가능성:** 🔴 High

* **대응 방안:** Edge Gateway 기반 로컬 제어 유지, 이중 통신망 및 Store-and-Forward 구조 적용
