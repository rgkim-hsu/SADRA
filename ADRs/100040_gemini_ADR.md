# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 중앙 집중형 생육 정보 산출 엔진 및 비동기 데이터 파이프라인 구축

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 이미지 제공 모듈(100)로부터 전달되는 대용량 영상 데이터를 실시간 또는 준실시간으로 분석하여, 기준정보 DB(300)와 대조하고 최종 영농정보 DB(400)에 저장 및 사용자 단말(400)로 피드백해야 하는 복잡한 데이터 흐름이 존재함. |
| **결정(Decision)** | 모든 데이터 처리를 '생육정보 산출모듈(200)'을 중심으로 한 Hub-and-Spoke 아키텍처로 설계하고, 이미지 분석과 DB 트랜잭션 간의 병목 현상을 방지하기 위해 메시지 큐 기반의 비동기 처리 방식을 도입함. |
| **근거(Rationale)** | 생육 정보 산출은 연산 집약적인 작업이므로, 외부 모듈(100)과 DB(300, 400) 사이에서 독립적인 스케일링이 가능해야 하며 데이터 무결성을 보장하기 위함임. |
| **결과(Consequences)** | 시스템의 확장성이 확보되고 각 모듈 간 결합도가 낮아져 유지보수가 용이해짐. 사용자 단말(400)은 산출 결과가 완료되는 즉시 업데이트를 수신할 수 있음. |
| **트레이드오프(Trade-offs)** | 시스템 복잡도가 증가하며, 데이터가 여러 모듈을 거침에 따라 네트워크 레이턴시 및 결과 반영까지의 일시적인 데이터 불일치(Eventual Consistency)가 발생할 수 있음. |

---

## ⚠️ 잠재적 위험 분석

### 1. 이미지 제공 모듈의 대역폭 및 전송 병목
- **설명:** 고해상도 이미지를 제공하는 모듈(100)에서 대량의 데이터를 산출 모듈(200)로 전송할 시 네트워크 대역폭 초과로 인해 처리가 지연되는 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 이미지 압축 알고리즘 적용, 에지 컴퓨팅을 통한 1차 전처리 도입, 및 스트리밍 프로토콜(gRPC 등) 최적화.

### 2. 기준정보 데이터베이스(300) 조회 성능 저하
- **설명:** 산출 모듈(200)이 매 분석 시점마다 기준정보 DB(300)에 접근할 경우, 분석 데이터가 급증함에 따라 DB 커넥션 풀 부족 및 응답 지연 발생.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 빈번하게 참조되는 기준 정보는 산출 모듈 내 로컬 캐시(Redis 등)를 도입하여 DB 직접 접근 횟수 최소화.

### 3. 영농정보 및 사용자 단말 간 데이터 동기화 오류
- **설명:** 영농정보 DB(400) 업데이트와 사용자 단말(400)로의 푸시 알림 간의 불일치로 인해 사용자가 잘못된 생육 정보를 기반으로 의사결정을 내리는 상황.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 분산 트랜잭션 관리 또는 이벤트 기반 상태 체크 시스템을 구축하여 데이터 저장 확인 후 단말 알림 송신.

### 4. 생육정보 산출 알고리즘의 컴퓨팅 자원 고갈
- **설명:** 분석해야 할 작물 이미지의 양이 일시에 몰릴 경우, 산출 모듈(200)의 CPU/GPU 자원이 임계치를 초과하여 시스템 전체가 다운되는 현상.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 오토스케일링(Auto-scaling) 정책 수립 및 작업 큐(Job Queue)를 통한 요청 제어(Throttling).

### 5. 데이터 엔드포인트 보안 및 위변조 위험
- **설명:** 이미지 제공 모듈에서 산출 모듈로 가는 구간이나 DB로 향하는 데이터가 가로채기 또는 위변조되어 잘못된 영농 정보가 생성되는 보안 사고.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low
