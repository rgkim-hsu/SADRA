## 📋 ADR (Architecture Decision Record)

### **ADR-001: 디지털 트윈(Digital Twin) 기반 스마트 팩토리 아키텍처의 데이터 통합 및 실시간 동기화 전략**

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트 팩토리 시스템은 **공간 복사(Spatial Copy)**, **행동 복사(Behavior Copy)**, **데이터 복사(Data Copy)**의 3가지 복사본을 통합하여 디지털 트윈(DT)을 구현해야 함. 기존 GIS/BIM/3D-CAD 데이터, 시뮬레이션 모델, 실시간 운영 데이터가 서로 독립적으로 관리되면 데이터 일관성 및 실시간 동기화 문제 발생. 또한, DT 개발 및 시뮬레이션 과정에서 데이터 형식 불일치로 인한 프로세스 중단 위험이 존재. |
| **결정(Decision)** | 1. **통합 데이터 모델 표준화**: ISO/IEC 30141:2024 및 oneM2M 표준을 기반으로 **공통 데이터 스키마**를 정의하여 GIS/BIM/3D-CAD, 시뮬레이션 모델, 운영 데이터 간의 상호운용성을 보장.
2. **실시간 동기화 엔진 구축**: MQTT 프로토콜을 활용한 **이벤트 기반 데이터 스트리밍**을 도입하여 운영 데이터와 시뮬레이션 모델 간의 지연 시간을 100ms 이하로 통제.
3. **DT Formalism 표준화**: 시뮬레이션 모델과 운영 데이터의 형식 불일치를 해결하기 위해 **JSON-LD 기반의 메타데이터 스키마**를 적용하여 데이터 변환 및 검증 프로세스를 자동화.
4. **기능 분할 아키텍처**: DT 개발, 시뮬레이션, 시각화 모듈을 **마이크로서비스 아키텍처**로 분리하여 독립적 배포 및 확장성을 확보. |
| **근거(Rationale)** | - **데이터 일관성**: ISO/IEC 30141:2024는 IoT 시스템의 참조 아키텍처를 제공하여 데이터 모델 표준화에 적합.
- **실시간성**: MQTT는 IoT 환경에서 광범위하게 채택된 경량 프로토콜로, 실시간 데이터 동기화에 최적화되어 있음.
- **자동화 변환**: JSON-LD는 링크드 데이터 표준으로, 메타데이터 기반의 데이터 변환 및 검증 프로세스를 지원.
- **확장성**: 마이크로서비스 아키텍처는 모듈별 독립적 배포 및 스케일링을 가능하게 함. |
| **결과(Consequences)** | - **장점**: 데이터 일관성 및 실시간 동기화로 시스템 신뢰성 향상, 모듈별 독립적 개발 및 배포로 유지보수 용이성 증가.
- **단점**: 초기 구축 비용 및 복잡성 증가, MQTT 및 JSON-LD 도입으로 학습 곡선 발생 가능. |
| **트레이드오프(Trade-offs)** | - **표준화 vs. 유연성**: ISO/IEC 30141 준수를 통해 상호운용성을 확보하지만, 특정 비즈니스 로직에 대한 유연성이 제한될 수 있음.
- **성능 vs. 복잡성**: 실시간 동기화를 위해 MQTT를 도입하면 네트워크 오버헤드가 발생할 수 있으나, 데이터 일관성 및 시스템 신뢰성 향상으로 상쇄됨. |

### **ADR-002: 디지털 트윈 시뮬레이션 및 검증 프로세스의 머신러닝 기반 검증 전략**

| 항목 | 내용 |
|------|------|
| **상황(Context)** | DT 시뮬레이션 결과의 정확성 검증은 수작업으로 수행되면 오류 발생 확률이 높고, 실시간 검증이 어려움. 특히, 공장 환경의 복잡한 물리적 및 행동적 모델링에서는 시뮬레이션 데이터와 실제 운영 데이터 간의 차이 분석이 필수적임. |
| **결정(Decision)** | 1. **머신러닝 기반 DT 검증 프레임워크 도입**: 시뮬레이션 데이터와 운영 데이터를 입력으로 받아 **이상치 검출 및 예측 오류 분석**을 수행하는 **강화 학습 모델**을 개발.
2. **데이터 라벨링 자동화**: 운영 데이터와 시뮬레이션 데이터 간의 차이를 기반으로 **자동 라벨링**을 수행하여 모델 학습 데이터셋 생성.
3. **실시간 피드백 루프 구축**: 검증 결과가 DT 시뮬레이션 모델에 실시간으로 피드백되어 모델을 동적으로 업데이트. |
| **근거(Rationale)** | - **자동화 검증**: 머신러닝은 대량의 데이터에서 패턴을 자동으로 학습하여 수작업 검증보다 정확도 및 속도가 우수.
- **실시간 업데이트**: 피드백 루프를 통해 DT 모델이 실시간으로 학습되어 환경 변화에 적응 가능.
- **이상치 감지**: 강화 학습은 예측 오류를 감지하고, 이를 기반으로 시뮬레이션 모델의 재학습을 유도. |
| **결과(Consequences)** | - **장점**: 검증 프로세스의 자동화로 인력 비용 절감 및 검증 속도 향상, 실시간 피드백으로 모델 정확성 지속적 개선.
- **단점**: 초기 모델 학습에 대규모 데이터 및 컴퓨팅 리소스가 필요, 모델 오류로 인한 오검증 위험 존재. |
| **트레이드오프(Trade-offs)** | - **정확성 vs. 속도**: 높은 정확성을 위해 복잡한 모델을 사용하면 학습 및 추론 속도가 저하될 수 있음.
- **데이터 의존성**: 모델 성능은 데이터 품질에 크게 의존하므로, 데이터 수집 및 정제 프로세스가 critical path가 됨. |

## ⚠️ 잠재적 위험 분석

### **1. 데이터 일관성 부재**
- **설명**: GIS/BIM/3D-CAD, 시뮬레이션 모델, 운영 데이터 간의 스키마 불일치로 인해 DT Formalism 프로세스에서 데이터 변환 실패 또는 오류 발생. 예를 들어, 시뮬레이션 모델이 사용하는 단위 시스템(미터 vs. 센티미터)과 운영 데이터의 단위가 불일치할 경우.
- **심각도**: 🔴 High
- **발생 가능성**: 🔴 High
- **대응 방안**:
  - **초기 단계에서 데이터 스키마 표준화**: ISO/IEC 30141:2024 및 oneM2M 표준을 기반으로 모든 데이터 소스의 스키마를 통일.
  - **자동 검증 도구 도입**: 데이터 변환 프로세스에 **스키마 검증 스크립트**를 통합하여 변환 전후의 데이터 일관성을 자동으로 확인.
  - **데이터 오케스트레이션 플랫폼**: Apache NiFi와 같은 도구를 사용하여 데이터 파이프라인의 일관성을 모니터링.

### **2. 실시간 동기화 지연**
- **설명**: MQTT를 사용하더라도 네트워크 지연, 서버 과부하, 또는 데이터 처리 속도의 한계로 인해 운영 데이터와 시뮬레이션 모델 간의 동기화 지연이 발생. 예를 들어, 센서 데이터가 1초에 100개 이상 수집되면 처리 지연으로 인해 DT 시뮬레이션이 실제 상태를 반영하지 못할 수 있음.
- **심각도**: 🔴 High
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **에지 컴퓨팅 도입**: 센서 데이터의 전처리를 에지 장비에서 수행하여 클라우드로 전송되는 데이터 양을 최소화.
  - **스트리밍 프로세싱**: Apache Kafka와 Flink를 사용하여 실시간 데이터 스트리밍 및 처리 능력을 강화.
  - **QoS 레벨 조정**: MQTT의 QoS(Quality of Service) 레벨을 적절히 설정하여 중요 데이터의 전송 성공률을 보장.

### **3. 보안 취약성**
- **설명**: 디지털 트윈 시스템은 실시간으로 운영 데이터와 시뮬레이션 데이터를 교환하므로, 네트워크 공격(예: MITM, DDoS), 데이터 도용, 또는 무단 접근의 위험이 높음. 특히, IoT 기기 간 통신에서 보안 프로토콜 미준수 시 취약점 발생 가능성 높음.
- **심각도**: 🔴 High
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **엔드투엔드 암호화**: MQTT 통신에 TLS 1.3을 적용하고, 데이터 저장소에 AES-256 암호화를 적용.
  - **접근 통제 강화**: OAuth 2.0 및 JWT를 사용하여 API 및 데이터 접근을 인증 및 권한 부여.
  - **보안 표준 준수**: ITU-T X.1352 및 ETSI EN 303 645를 준수하여 IoT 기기 및 통신의 보안 요구사항을 충족.

### **4. 모델 오류 누적**
- **설명**: 머신러닝 기반 DT 검증 모델이 잘못된 데이터로 학습되거나, 실시간 피드백 루프에 오류가 발생하면 시뮬레이션 모델의 오류가 누적되어 예측 정확도가 저하됨. 예를, 센서 이상치로 인해 모델이 오류를 학습하면 이후 모든 시뮬레이션 결과에 영향을 미침.
- **심각도**: 🟡 Medium
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **데이터 품질 모니터링**: 이상치 감지 알고리즘을 사용하여 센서 데이터의 이상치를 자동으로 필터링.
  - **모델 버전 관리**: 시뮬레이션 모델의 변경 사항을 버전으로 관리하고, A/B 테스트를 통해 새로운 모델의 성능을 검증.
  - **인간 감수성 유지**: 머신러닝 모델의 결정에 대해 주기적으로 수작업 검토를 수행하여 오류를 최소화.

### **5. 시스템 확장성 한계**
- **설명**: 마이크로서비스 아키텍처를 도입하더라도, DT 시뮬레이션 모델의 복잡성 증가로 인해 특정 모듈의 리소스 사용량이 급격히 증가할 수 있음. 예를, 고해상도 시뮬레이션을 수행하는 경우 GPU 리소스가 부족해질 수 있음.
- **심각도**: 🟡 Medium
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **클라우드 스케일링**: Kubernetes와 같은 오케스트레이션 도구를 사용하여 리소스를 동적으로 할당.
  - **모듈별 최적화**: 시뮬레이션 모델을 하위 모듈로 분할하여 병렬 처리를 가능하게 함.
  - **리소스 모니터링**: Prometheus와 Grafana를 사용하여 시스템 리소스 사용량을 실시간으로 모니터링하고, 사전에 스케일링 조치를 취함.
