## 📋 ADR (Architecture Decision Record)

### ADR-001: 데이터 품질 보장을 위한 오류 탐지 및 필터링 메커니즘 도입

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템 초기 단계 (S21) 에서 센서 데이터 및 제어 데이터를 수신합니다. IoT 환경 특성상 노이즈, 센서 고장, 네트워크 분실 등으로 인해 불완전한 데이터가 발생할 수 있습니다. 이를 S22 단계에서 탐지해야 하지만, 탐지된 오류 데이터가 이후의 '작물 모델링' (S24) 과 '마케팅 전략' (S25) 에 직접 반영되면 심각한 잘못된 의사결정으로 이어질 수 있는 상황이 발생합니다. |
| **결정(Decision)** | 모든 데이터 파이프라인에서 S22 단계의 오류 탐지를 강제적이고 명확한 로직으로 구현하며, 탐지된 오류 데이터는 분석 대상에서 제외되거나 별도의 로그 처리를 통해 시스템에서 자동 격리 (Exclude) 하는 정책을 수립합니다. |
| **근거(Rationale)** | 관련 문서는 ISO/IEC 30141:2024 와 IEEE 2413 등 IoT 시스템 아키텍처 표준에서 데이터 신뢰성과 보안을 강조하고 있습니다. 특히 '스마트팜 데이터 상호운용성' (TTA 표준 목록 중 제7호 참조) 을 위해 정확한 데이터 품질이 필수적입니다. |
| **결과(Consequences)** | 긍정적인 효과로 신뢰할 수 있는 '작물 모델링 데이터'를 생성할 수 있습니다. 부정적인 효과로 일부 데이터 손실이 발생할 수 있으나, 잘못된 모델링을 막는 것이 더 중요합니다. |
| **트레이드오프(Trade-offs)** | 데이터 손실 (False Negative) 위험 감수 대 잘못된 의사결정 방지 (Prevent False Positive) 의 우선순위 결정입니다. |

### ADR-002: 비즈니스 가치 극대화를 위한 데이터 기반 마케팅 전략 연동

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템이 센서 데이터를 통해 작물의 상태 (작황) 를 파악하고 사용자 입력을 통해 모델을 생성합니다 (S23-S24). 수집된 데이터의 최종 목적은 단순한 관제를 넘어 '마케팅 및 출하 전략 반영' (S25) 에 있습니다. 즉, 데이터를 비즈니스 가치로 전환하는 단계입니다. |
| **결정(Decision)** | S24 단계에서 생성된 작물 모델링 데이터를 외부 연동 인터페이스 (API) 와 연동하여, 실시간 출하 시기나 상품 가치를 자동 산출하는 로직을 적용합니다. TTA 표준 (제13호: 노지 관수·관비제어기 인터페이스) 에 맞춰 개방형 API 구조를 고려합니다. |
| **근거(Rationale)** | 스마트팜의 경제성은 생산 효율뿐만 아니라 판매 효율에 달려 있습니다. oneM2M 표준에서 다루는 M2M 요구 사항처럼 기기 간 통신뿐만 아니라 데이터의 비즈니스 활용 (Insight) 이 핵심입니다. |
| **결과(Consequences)** | 농가의 소득 증대와 자원 배분 효율성 향상. 하지만 복잡한 데이터 분석 로직이 추가되어 개발 비용이 증가할 수 있습니다. |
| **트레이드오프(Trade-offs)** | 기술적 복잡성 증가 (비용) 대 수익 증대 (효과) 간의 트레이드오프입니다. |

### ADR-003: 지역별 맞춤형 관제 데이터 생성 및 스케일링

| 항목 | 내용 |
|------|------|
| **상황(Context)** | S26 단계에서는 '지역별 관제 데이터'를 생성합니다. 이는 단일 시스템이 여러 지역 (또는 개별 농장) 에 확장될 때 필요한 단계입니다. 데이터가 중앙 집중식인지 분산 처리하는지에 따라 아키텍처가 달라집니다. |
| **결정(Decision)** | 중앙 서버의 부담을 줄이기 위해 에지 기반 처리 (Edge Computing) 의 개념을 도입하여, 각 지역별 (S26) 로 데이터 가공 로직을 수행하도록 설계합니다. 이는 TTA 표준 (제8호: 에지 기반 스마트 온실 서비스의 데이터 관리) 과 부합합니다. |
| **근거(Rationale)** | 인터넷 연결 환경이 좋지 않은 노지 환경 등에서도 제어 데이터가 정상적으로 수신되고 처리되도록 하려면 (S21 참조) 에지 컴퓨팅이 필수적입니다. |
| **결과(Consequences)** | 시스템의 확장성 (Scalability) 이 높아지고 네트워크 지연 시간 감소. 중앙 서버의 부하를 줄일 수 있습니다. |
| **트레이드오프(Trade-offs)** | 에지 디바이스의 사양을 낮출 수 없는 제약과 유지보수 복잡성 증가 등의 단점이 있습니다. |

## ⚠️ 잠재적 위험 분석

### 1. 센서 데이터 노이즈 및 고장 (Sensor Noise & Failure)
- **설명:** S21 단계에서 수신되는 센서 데이터가 외부 간섭, 전원 불안정 등으로 인해 왜곡되거나 누락될 경우, S22 단계에서 탐지되지 않고 넘어가면 S24 단계의 모델링 데이터가 비현실적이 될 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:**
    - 다중 센서 퓨전 (Sensor Fusion) 기술을 적용하여 특정 센서의 오류를 다른 센서 값으로 보정합니다.
    - S22 단계의 오류 탐지 로직에 역사적 데이터와 통계적 이상치 검출 (Outlier Detection) 알고리즘을 병행하여 사용합니다.

### 2. 사용자 입력 오류 및 조작 (User Input Error)
- **설명:** S23 단계에서 사용자가 직접 입력하는 '작황' 정보가 실제 상황과 다르게 입력되거나, 악의적으로 조작될 경우, 이는 S24 단계의 '작물 모델링 데이터 생성'에 치명적인 오류를 일으킵니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:**
    - 사용자 입력이 시스템이 분석한 센서 데이터와 크게 벗어나면 경고 및 승인 절차를 거치도록 승인 워크플로우를 설계합니다.
    - 입력된 데이터의 위변조 로그를 기록 (Audit Log) 하여 추후 추적이 가능하도록 합니다.

### 3. 작물 모델링의 불확실성 (Uncertainty in Crop Modeling)
- **설명:** S24 단계에서 생성된 모델이 다양한 환경 요인 (기온, 습도 등) 을 완벽하게 반영하지 못하거나, 학습 데이터의 편향으로 인해 특정 작물이나 환경에 맞지 않는 예측을 할 경우, S25 단계의 전략이 실패합니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High (환경 변수의 복잡성으로 인해)
- **대응 방안:**
    - 모델 예측에 '확률론적 접근 (Probabilistic Approach)'을 적용하여 신뢰 구간 (Confidence Interval) 을 함께 제공합니다.
    - AI 모델의 성능을 지속적으로 모니터링하고 (MLOps), 새로운 데이터가 입력될 때마다 모델을 재학습 (Fine-tuning) 합니다.

### 4. 실시간 데이터 처리 지연 (Latency in Real-time Processing)
- **설명:** IoT 환경에서 센서 데이터 수신 (S21) 과 제어 데이터 반영 사이에 지연이 발생할 경우, 실시간 제어 시스템에서는 큰 문제가 될 수 있습니다. 특히 '지연성'이 중요한 스마트팜 환경에서 이는 위험합니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium (네트워크 환경에 따라)
- **대응 방안:**
    - MQTT, CoAP 등 경량 프로토콜을 사용하여 네트워크 오버헤드를 줄입니다.
    - 데이터 처리 로직을 Edge 또는 Cloud-Edge 하이브리드 아키텍처로 설계하여 처리 시간을 최소화합니다.

### 5. 데이터 보안 및 프라이버시 유출 (Data Breach & Privacy)
- **설명:** S21 단계에서 수집되는 다양한 센서 데이터와 S23 단계의 사용자 입력에는 농가의 중요한 경영 정보와 위치 정보가 포함될 수 있습니다. 시스템 침투 시 이 정보가 유출될 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High (보안 위협은 지속적)
- **대응 방안:**
    - ITU-T X.1352 및 ETSI EN 303 645 등 IoT 보안 표준을 준수합니다.
    - 전송 중인 데이터와 저장된 데이터 모두 암호화 (Encryption) 처리합니다.
    - S26 단계에서 생성된 지역별 관제 데이터의 권한 접근 제어 (RBAC) 를 엄격하게 설계합니다.
