===============

📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 스마트팜 원격 컨설팅 기반 운영 자동화 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                 |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 운영자는 농업 전문 지식 부족, 복잡한 운영 스케줄 관리, 실시간 데이터 기반 의사결정의 어려움에 직면해 있다. 기존 수동 방식으로는 일/월/년 단위 점검 주기 관리와 디지털 데이터 수집의 연속성을 보장하기 어렵다. 플로우차트(S2~S14)는 운영 요청 접수부터 관리 스케줄 전송(RTS)까지의 전 과정을 자동화해야 하는 과제를 제시한다.                                                 |
| **결정(Decision)**       | 전문가 시스템(Expert System) 기반의 컨설팅 판단 분기(S4)를 핵심 허브로 삼아, 컨설팅 필요 시 전문가 자료입력(S6) → 전자계약(S8) → 다단계 점검표(S10) → 디지털 데이터 수집(S12) → 관리 스케줄 자동 전송(S14)으로 이어지는 순차적 이벤트 기반 파이프라인 아키텍처를 채택한다. 컨설팅 불필요 시 운영 요청(S2)으로 루프백하는 재진입 구조를 포함한다.                           |
| **근거(Rationale)**      | 스마트팜은 IoT 센서, 환경 제어 시스템, 전문가 지식이 융합되는 사이버-물리 시스템(CPS)이다. 전문가 판단을 조기 분기점(S4)에 배치함으로써 불필요한 자원 소모를 방지하고, 전자계약(S8)으로 법적 책임 소재를 명확히 하며, 일/월/년 다중 주기 점검(S10)으로 농작물 생육 주기에 맞는 유연한 모니터링을 구현한다. 최종 RTS(Remote Transmission System) 출력은 원격 관제 체계와의 연동을 전제한다. |
| **결과(Consequences)**   | ✅ 전문가 지식의 시스템화로 운영 일관성 확보 / ✅ 전자계약 기반 서비스 책임 구조 명확화 / ✅ 자동화된 스케줄 전송으로 운영자 개입 최소화 / ⚠️ 전문가 시스템 의존도 증가로 단일 장애점(SPOF) 위험 / ⚠️ 컨설팅 미요청 루프 구간에서 무한 루프 가능성 내포                                                                                            |
| **트레이드오프(Trade-offs)** | **얻는 것:** 운영 표준화, 원격 모니터링 효율성, 전문가 지식 재사용성, 계약 기반 서비스 신뢰도 향상 / **감수할 것:** 전문가 시스템 구축·유지 비용 증가, 분기 로직 복잡도 상승, 네트워크 의존성 심화, 오프라인 환경에서의 운영 취약성                                                                                                        |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. 컨설팅 판단 분기(S4) 단일 장애점(SPOF) 위험

* **설명:** S4의 "컨설팅 요청?" 분기는 전체 파이프라인의 게이트웨이 역할을 한다. 이 판단 로직이 오작동하거나 전문가 시스템(S6)과의 연결이 단절될 경우, 전체 운영 프로세스가 S2 루프에 갇혀 실질적인 서비스가 제공되지 않는 deadlock 상태가 발생할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** S4 분기 로직에 타임아웃 및 fallback 메커니즘 구현, 전문가 시스템 이중화(Active-Standby) 구성, 루프 카운터를 통한 무한 루프 방지 로직 추가, 회로 차단기(Circuit Breaker) 패턴 적용

### 2. 디지털 데이터 수집(S12) 구간 데이터 무결성 침해 위험

* **설명:** IoT 센서로부터 수집되는 온·습도, CO₂, 토양 수분 등의 농업 환경 데이터가 S12 구간에서 네트워크 불안정, 센서 오작동, 또는 중간자 공격(MITM)으로 인해 변조·누락될 경우, S14에서 전송되는 관리 스케줄이 잘못된 데이터를 기반으로 생성되어 작물 피해로 직결될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** TLS/DTLS 기반 전송 암호화 적용, 데이터 수집 시 해시 체크섬 검증, 이상치 탐지(Anomaly Detection) 알고리즘 도입, 엣지 컴퓨팅 노드에 로컬 버퍼 캐시 구성으로 네트워크 단절 시 데이터 보존

### 3. 전자계약(S8) 법적 효력 및 보안 취약성 위험

* **설명:** S8의 운영 전자계약 체결 시 전자서명 위조, 계약 데이터 탈취, 또는 스마트 컨트랙트 로직 버그로 인해 계약 조건이 변조될 수 있다. 특히 농업인 사용자의 디지털 리터러시 수준이 낮을 경우 피싱·사회공학 공격에 노출될 위험이 크다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 공인전자문서센터(KECA) 연동 및 PKI 기반 전자서명 적용, 계약 내용 변경 불가 처리를 위한 블록체인 또는 타임스탬프 서비스 활용, 사용자 인증 강화(MFA), 계약 체결 전 내용 요약 팝업 및 이중 확인 UI 제공

### 4. 점검표 다중 주기(S10) 관리 복잡도 및 누락 위험

* **설명:** 일/월/년 3단계 점검 주기를 하나의 스텝(S10)에서 처리하는 구조는, 각 주기별 점검 항목이 혼재되거나 특정 주기(예: 연간 대형 방역 점검)가 일간 루틴에 묻혀 누락되는 스케줄 충돌 문제를 야기할 수 있다. 점검 누락 시 병해충 조기 발견 실패로 이어져 대규모 작물 손실이 발생한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 일/월/년 주기별 독립적인 점검 큐(Queue) 분리 설계, 우선순위 기반 스케줄러 도입, 점검 항목별 완료 여부 추적을 위한 상태 머신(State Machine) 구현, 미완료 점검 항목 알림 에스컬레이션 정책 수립

### 5. 관리 스케줄 전송(S14→RTS) 네트워크 의존성 및 오프라인 운영 중단 위험

* **설명:** 농촌 지역 특성상 불안정한 네트워크 환경에서 S14의 관리 스케줄 전송이 실패할 경우, RTS(원격 전송 시스템)로의 데이터 전달이 중단되어 스마트팜 자동 제어(관개, 환기, 조명 등)가 멈추는 운영 공백이 발생한다. 특히 야간·주말에 장애 발생 시 대응 지연이 심화된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 엣지 게이트웨이에 오프라인 자율 운영 모드(Last-known-good 정책) 구현, 메시지 큐(MQTT + QoS Level 2) 기반 전송 재시도 메커니즘 적용, LTE/5G 이중화 또는 LoRaWAN 백업 통신망 구성, 장애 발생 시 온콜(On-call) 알림을 위한 SMS/Push 경보 시스템 연동
