# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 표준 기반의 계층적 모듈형 아키텍처 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 본 시스템은 실시간으로 변화하는 환경(Weather forecast, 환경 변화)과 비정형화된 전문 지식(Human experts)을 바탕으로 최적의 제어 정책을 학습해야 합니다. 동시에, 수많은 IoT 디바이스와 센서를 연결해야 하므로, 시스템은 높은 **상호운용성(Interoperability)**과 **확장성(Scalability)**, 그리고 국제 표준을 준수하는 **신뢰성**을 요구받습니다. (핵심 과제: 복잡한 이종 데이터를 RL 프레임워크로 통합하는 아키텍처 구축) |
| **결정(Decision)** | 환경(Environment)과 에이전트(Agent) 간의 상호작용을 **전략 패턴(Strategy Pattern)** 기반의 서비스 지향 아키텍처(SOA)로 분리하고, 모든 데이터 인터페이스와 통신 프로토콜을 **ISA-95 또는 ISO/IEC 30141** 표준을 따르는 계층형(Layered) 아키텍처로 구축합니다. |
| **근거(Rationale)** | 1. **상호운용성 보장:** 표준화된 인터페이스(API Gateway)를 통해, 새로운 센서나 외부 변수(Weather)가 추가되어도 핵심 제어 로직(DDPG Model)에 영향을 주지 않습니다. 2. **모듈화:** 환경 시뮬레이션(Environment)을 별도의 모듈로 분리하여, 실제 물리 환경(Simulation)과 학습 환경(Model)을 독립적으로 검증하고 업데이트할 수 있습니다. 3. **보안 및 확장:** 표준화된 접근 제어와 메시지 브로커(MQTT/Kafka)를 사용하여, 시스템의 보안성을 확보하고 병렬적인 데이터 처리(State, Reward)를 효율적으로 지원할 수 있습니다. |
| **결과(Consequences)** | **긍정적:** 시스템의 초기 구축 복잡도가 높지만, 운영 단계에서 특정 컴포넌트의 독립적인 개선(예: 센서 교체, ML 알고리즘 업데이트)이 용이하며, 국제 표준 준수성을 확보하여 글로벌 시장 진출에 유리합니다. **부정적:** 초기 설계 및 통합 단계에서 표준 준수를 위한 추가적인 설계 시간이 요구되며, 표준화를 관리할 전담 아키텍트 역량이 필수적입니다. |
| **트레이드오프(Trade-offs)** | **얻는 장점:** 최고의 신뢰성, 높은 상호운용성, 유지보수 용이성. **감수해야 할 단점:** 개발 주기 초반의 복잡성 증가(High Upfront Cost), 시스템 오케스트레이션 레이어의 추가적인 구현 및 관리 부하. |

## ⚠️ 잠재적 위험 분석

### 1. 환경 모델의 비정상성 및 드리프트 위험 (Non-Stationary Environment & Drift Risk)
- **설명:** 실제 온실 환경은 생물학적 성장 주기, 미기후 변화, 장비 노후화 등 지속적으로 변화하는 비정상성(Non-stationarity)을 가집니다. 특히, 훈련 데이터가 실제 환경의 장기적이고 미세한 변화(Drift)를 따라가지 못하면, 에이전트가 과도하게 최적화된 정책을 학습해도 실제 환경에서는 성능이 급격히 저하됩니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** **Transfer Learning 및 Continual Learning (CL)** 기법을 아키텍처에 도입합니다. 온라인 학습 모듈을 구성하여, 현장의 실시간 데이터를 주기적으로 수집하고 이를 기존 모델에 반영하는 적응 학습 루프(Adaptive Loop)를 구현해야 합니다. 환경 변화율을 모니터링하는 메트릭을 설계합니다.

### 2. 이기종 센서 및 데이터 연동 표준화 실패 위험 (Heterogeneous Data Integration Failure)
- **설명:** 온실 시스템은 온도, 습도, CO2, pH 등 수십 종류의 물리적 센서와 외부 기상 데이터(API)를 수집합니다. 각 센서 제조사나 종류별 통신 프로토콜(Modbus, Zigbee, LoRa, WiFi 등)이 다르기 때문에, 데이터를 통합하고 의미를 해석하는 과정에서 데이터 포맷 불일치(Data Inconsistency)나 프로토콜 충돌이 발생할 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 Medium
- **대응 방안:** **통합 데이터 레이어(Normalization Layer)**를 아키텍처 중앙에 배치합니다. 모든 입력 데이터는 이 레이어에 진입하기 전에 사전에 정의된 스키마(Schema)와 공통 메시지 형식(예: JSON or Protobuf)으로 강제 변환되어야 합니다. 표준화된 데이터 수집 게이트웨이(Gateway)를 필수적으로 거치도록 합니다.

### 3. 제어 정책의 지역 최적화 함정 (Local Optima Trap in RL Policy)
- **설명:** DDPG와 같은 RL 알고리즘은 주어진 보상 함수(Reward Function) 내에서 최적의 정책을 찾으려고 합니다. 만약 설계된 보상 함수가 시스템의 모든 복합적이고 장기적인 목표(예: '경제적 수익성', '생체 다양성 유지', '미생물 생태계 건강')를 완벽하게 포착하지 못한다면, 에이전트는 보상 함수를 극대화하는 단기적이고 지역적인 최적 정책(Local Optimum)에 빠질 위험이 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 보상 함수 설계에 **계층적 강화학습(HRL: Hierarchical Reinforcement Learning)** 기법을 적용합니다. 장기 목표(High-level Goal, 예: 작물 성장 주기 관리)를 상위 정책에 정의하고, 이를 여러 개의 하위 정책(Low-level Policy, 예: 특정 시간대의 냉난방 제어)으로 분할하여, 시스템이 단기적 이득에만 치우치지 않도록 강제합니다.

### 4. 사이버 물리 시스템(CPS)의 해킹 공격 위험 (Cyber-Physical Security Vulnerability)
- **설명:** 온실 시스템은 센서, 액추에이터, 제어 로직이 모두 연결된 CPS입니다. 공격자가 게이트웨이(Gateway)나 무선 통신 채널을 통해 시스템에 침입할 경우, 온도나 양액 공급 장치 등의 핵심 물리 장치에 잘못된 명령을 전송하여 작물 재배에 치명적인 피해를 입히거나 데이터를 변조할 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** **Defense-in-Depth(심층 방어)** 전략을 채택해야 합니다. 물리 계층과 IT 계층을 분리하고, 모든 제어 명령(Action)은 반드시 **양방향 인증(Two-way Authentication)** 및 **권한 기반 접근 제어(RBAC)**를 거치도록 합니다. 특히, 중요 액추에이터로의 명령어는 물리적 Fail-Safe(예: 독립적 비상 차단 스위치)를 갖추고 운영해야 합니다.

### 5. 전문 지식의 시스템 반영 실패 위험 (Failure to Formalize Human Expertise)
- **설명:** 시스템은 Human experts의 지식(Domain Knowledge)을 필요로 하지만, 이 지식은 매뉴얼이나 인터뷰를 통해 수집된 비정형적이고 암묵적인 형태(Tacit Knowledge)가 많습니다. 이 지식을 정확하게 수학적 또는 규칙 기반의 모델(Rule-Based System)로 추출하고 RL 학습에 효과적으로 통합하는 것이 매우 어렵습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 지식 공학(Knowledge Engineering) 방법론과 **규칙 기반 시스템(Rule-Based System)**을 병행하여 초기 제어 정책의 안전망(Safety Net)으로 활용합니다. 전문가의 지식을 먼저 명확한 IF-THEN 규칙 세트로 정의하여 초기 제어 알고리즘의 가이드라인으로 삼고, RL 학습을 통해 이 규칙 세트의 경계 내에서 최적화를 시도합니다.
