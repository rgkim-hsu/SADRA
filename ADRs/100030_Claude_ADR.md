### ADR-001: 이미지 기반 작물 생육정보 산출을 위한 모듈형 파이프라인 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                            |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 환경에서 작물의 생육 상태를 정량적으로 측정하기 위해 이미지 제공모듈(100)이 촬영한 영상을 수집하고, 생육정보 산출모듈(200)이 이를 처리하여 사용자단말(500)에 결과를 전달해야 한다. 기관별로 다양한 작물 기준이 존재하므로 기준정보 데이터베이스(300)와 영농정보 데이터베이스(400)를 외부 참조 데이터로 활용해야 하며, 단일 모놀리식 구조로는 확장성과 유지보수성이 떨어진다.                 |
| **결정(Decision)**       | 시스템을 이미지 제공모듈(100), 생육정보 산출모듈(200), 기준정보 DB(300), 영농정보 DB(400), 사용자단말(500)의 5개 독립 컴포넌트로 분리하고, 생육정보 산출모듈(200) 내부를 이미지 입력(210) → 기관분류(220) → 보정(230) → 계측치 산출(240) → 과중 산출(250) → 생육정보 산출(260) → 영농정보 매칭(270) → 정보전송(280)의 순차적 처리 파이프라인으로 설계한다. |
| **근거(Rationale)**      | 각 처리 단계(210~280)가 명확한 단일 책임을 가지므로 단계별 독립 테스트·교체가 가능하다. 기관별 기준(300)과 영농 데이터(400)를 외부 DB로 분리함으로써 비즈니스 로직 변경 없이 기준값 갱신이 가능하다. 이미지 촬영(110)과 전송(120)을 분리하여 네트워크 단절 상황에서도 로컬 버퍼링이 가능한 구조를 갖는다.                                                      |
| **결과(Consequences)**   | (긍정) 각 단계의 독립 배포 및 스케일아웃이 가능하고, 신규 작물 기준 추가 시 DB만 업데이트하면 된다. 이미지 기반 비파괴 측정으로 생육 데이터의 연속 수집이 가능해진다. (부정) 파이프라인 단계 수가 많아 전체 처리 지연(latency)이 누적될 수 있으며, 중간 단계 장애 시 장애 전파 범위 파악이 복잡해진다.                                                           |
| **트레이드오프(Trade-offs)** | 얻는 것: 높은 모듈성, 유지보수 용이성, 기준 데이터의 유연한 변경. 감수해야 할 것: 컴포넌트 간 통신 오버헤드, 파이프라인 전체 모니터링 복잡도 증가, 초기 통합 테스트 비용 증가.                                                                                                                                      |

### ADR-002: 이미지 기반 기관분류(220) 및 보정(230)의 선행 처리 의무화

| 항목                     | 내용                                                                                                                                  |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 동일 작물이라도 촬영 환경(조도, 각도, 카메라 기종)과 재배 기관에 따라 이미지 특성이 상이하다. 보정 없이 계측치 산출(240)을 수행하면 기관별 측정 편차가 발생하여 생육정보의 신뢰성이 저하된다.                    |
| **결정(Decision)**       | 이미지 입력(210) 직후 반드시 기관분류(220)를 먼저 수행하고, 그 결과를 기준정보 DB(300)와 대조하여 기관별 보정 파라미터를 적용한 후(230) 계측치 산출(240)로 진행하도록 파이프라인 순서를 강제한다.          |
| **근거(Rationale)**      | 기관분류 결과가 이후 모든 단계의 입력값 품질을 결정하는 핵심 전제 조건이다. 조기 분류 및 보정을 통해 오류가 하위 단계로 전파되는 것을 차단하고(Fail Fast 원칙), 기준정보 DB(300)의 기관별 파라미터를 최대한 활용한다. |
| **결과(Consequences)**   | (긍정) 측정 정확도 향상, 기관별 데이터 표준화. (부정) 기관분류 모델의 정확도가 전체 시스템 정확도의 병목이 되며, 신규 기관 추가 시 분류 모델 재학습이 필요하다.                                     |
| **트레이드오프(Trade-offs)** | 얻는 것: 높은 측정 신뢰성과 데이터 일관성. 감수해야 할 것: 기관분류 모델 관리 부담, 미분류 기관에 대한 예외 처리 로직 필요.                                                          |

### 1. 이미지 전송부(120) 네트워크 단절로 인한 생육 데이터 유실

* **설명:** 스마트팜 현장의 네트워크 불안정으로 이미지 전송부(120)에서 생육정보 산출모듈(200)의 이미지 입력부(210)로 이미지를 전송하는 과정이 중단될 경우, 해당 시간대의 생육 이미지가 영구 유실되어 연속적 생육 추이 분석이 불가능해진다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 이미지 촬영부(110) 또는 전송부(120)에 로컬 스토리지 버퍼를 구현하여 미전송 이미지를 임시 저장하고, 네트워크 복구 시 자동 재전송(Store-and-Forward) 메커니즘을 적용한다. 전송 상태 모니터링 대시보드 및 알람을 사용자단말(500)에 연동한다.

### 2. 기관분류부(220) 오분류로 인한 생육정보 산출 오류 연쇄 전파

* **설명:** 이미지 기반 기관분류부(220)가 촬영 환경 변화(역광, 안개, 계절별 색상 변화)로 인해 잘못된 기관으로 분류할 경우, 잘못된 기준 파라미터가 이미지 보정(230) → 계측치 산출(240) → 과중 산출(250) → 생육정보 산출(260) 전 단계에 오류로 전파되어 최종 영농 의사결정에 심각한 악영향을 미친다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 분류 결과에 신뢰도 점수(Confidence Score)를 부여하고, 임계값 미만 시 자동 재촬영 요청 또는 수동 검수 프로세스를 가동한다. 주기적으로 분류 모델을 재학습하고, 오분류 이력을 기준정보 DB(300)에 피드백하는 능동학습(Active Learning) 체계를 구축한다.

### 3. 기준정보 데이터베이스(300) 단일 장애점(SPOF) 위험

* **설명:** 기준정보 DB(300)는 생육정보 산출모듈(200) 전체가 참조하는 중앙 저장소이다. 이 DB가 장애 또는 데이터 손상 상태에 빠질 경우, 이미지 보정(230)과 기관분류(220)에 필요한 기준 파라미터를 조회할 수 없어 생육정보 산출 파이프라인 전체가 중단된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 기준정보 DB(300)에 Active-Standby 이중화 구성을 적용하고, 생육정보 산출모듈(200) 내부에 기준 파라미터 캐싱 레이어를 두어 DB 단기 장애 시에도 마지막으로 조회한 기준값으로 처리를 지속할 수 있도록 한다. 정기적인 DB 백업 및 복구 훈련을 실시한다.

### 4. 생육정보 및 영농정보의 비인가 접근·유출 보안 위협

* **설명:** 영농정보 데이터베이스(400)와 정보전송부(280)를 통해 사용자단말(500)로 전달되는 생육 데이터 및 영농 정보는 농가의 민감한 경영 정보를 포함한다. 전송 구간 또는 DB 접근 권한 설정 미흡 시 외부 공격자 또는 내부자에 의한 데이터 유출이 발생할 수 있으며, 농가 경쟁력 저하 및 법적 책임 문제가 발생한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 정보전송부(280)~사용자단말(500) 구간에 TLS 1.3 이상의 암호화 통신을 의무 적용한다. 각 DB에 역할 기반 접근 제어(RBAC)를 구현하고, 접근 로그를 중앙 SIEM에 수집·모니터링한다. 개인정보보호법 및 농업 데이터 관련 규정 준수 여부를 정기 감사한다.

### 5. 과중 산출부(250) 알고리즘 정확도 저하로 인한 수확량 예측 오류

* **설명:** 과중 산출부(250)는 2D 이미지로부터 3D 무게를 추정하는 고난이도 태스크를 수행한다. 작물 품종 다양성, 성장 단계별 형태 변화, 이미지 촬영 각도 편차 등으로 인해 산출 오차가 커질 경우, 농가는 수확 시기와 출하량을 잘못 판단하여 직접적인 경제적 손실을 입는다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 과중 산출 모델의 정확도를 품종별·성장 단계별로 구분하여 주기적으로 검증하고, 실측값과 산출값의 오차율을 영농정보 DB(400)에 누적 기록한다. 오차율이 임계값을 초과하는 경우 사용자단말(500)에 경고를 표시하고, 실측 보정 데이터를 수집하여 모델 재학습에 활용하는 피드백 루프를 구축한다.

### 6. 영농정보 매칭부(270)의 부적절한 영농 처방 제공 위험

* **설명:** 영농정보 매칭부(270)는 생육정보 산출 결과(260)를 영농정보 DB(400)와 매칭하여 비료·농약·관개 등의 처방을 생성한다. DB 정보가 구버전이거나 생육정보 산출 오류가 누적된 경우, 과잉 시비 또는 불필요한 농약 사용을 처방하여 작물 피해 및 환경 오염을 유발할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟢 Low
* **대응 방안:** 영농정보 DB(400)의 데이터 버전 관리 체계를 수립하고, 농촌진흥청 등 공신력 있는 기관의 최신 영농 가이드라인과 정기적으로 동기화한다. 매칭 결과에 신뢰도 등급을 표시하고, 고위험 처방(농약, 대량 시비)의 경우 전문가 확인 후 적용하는 2단계 승인 프로세스를 사용자단말(500)에 구현한다.

### ADR-002: 이미지 기반 기관분류(220) 및 보정(230)의 선행 처리 의무화

| 항목                     | 내용                                                                                                                                  |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 동일 작물이라도 촬영 환경(조도, 각도, 카메라 기종)과 재배 기관에 따라 이미지 특성이 상이하다. 보정 없이 계측치 산출(240)을 수행하면 기관별 측정 편차가 발생하여 생육정보의 신뢰성이 저하된다.                    |
| **결정(Decision)**       | 이미지 입력(210) 직후 반드시 기관분류(220)를 먼저 수행하고, 그 결과를 기준정보 DB(300)와 대조하여 기관별 보정 파라미터를 적용한 후(230) 계측치 산출(240)로 진행하도록 파이프라인 순서를 강제한다.          |
| **근거(Rationale)**      | 기관분류 결과가 이후 모든 단계의 입력값 품질을 결정하는 핵심 전제 조건이다. 조기 분류 및 보정을 통해 오류가 하위 단계로 전파되는 것을 차단하고(Fail Fast 원칙), 기준정보 DB(300)의 기관별 파라미터를 최대한 활용한다. |
| **결과(Consequences)**   | (긍정) 측정 정확도 향상, 기관별 데이터 표준화. (부정) 기관분류 모델의 정확도가 전체 시스템 정확도의 병목이 되며, 신규 기관 추가 시 분류 모델 재학습이 필요하다.                                     |
| **트레이드오프(Trade-offs)** | 얻는 것: 높은 측정 신뢰성과 데이터 일관성. 감수해야 할 것: 기관분류 모델 관리 부담, 미분류 기관에 대한 예외 처리 로직 필요.                                                          |

⚠️ 잠재적 위험 분석
------------

### 1. 이미지 전송부(120) 네트워크 단절로 인한 생육 데이터 유실

* **설명:** 스마트팜 현장의 네트워크 불안정으로 이미지 전송부(120)에서 생육정보 산출모듈(200)의 이미지 입력부(210)로 이미지를 전송하는 과정이 중단될 경우, 해당 시간대의 생육 이미지가 영구 유실되어 연속적 생육 추이 분석이 불가능해진다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 이미지 촬영부(110) 또는 전송부(120)에 로컬 스토리지 버퍼를 구현하여 미전송 이미지를 임시 저장하고, 네트워크 복구 시 자동 재전송(Store-and-Forward) 메커니즘을 적용한다. 전송 상태 모니터링 대시보드 및 알람을 사용자단말(500)에 연동한다.

### 2. 기관분류부(220) 오분류로 인한 생육정보 산출 오류 연쇄 전파

* **설명:** 이미지 기반 기관분류부(220)가 촬영 환경 변화(역광, 안개, 계절별 색상 변화)로 인해 잘못된 기관으로 분류할 경우, 잘못된 기준 파라미터가 이미지 보정(230) → 계측치 산출(240) → 과중 산출(250) → 생육정보 산출(260) 전 단계에 오류로 전파되어 최종 영농 의사결정에 심각한 악영향을 미친다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 분류 결과에 신뢰도 점수(Confidence Score)를 부여하고, 임계값 미만 시 자동 재촬영 요청 또는 수동 검수 프로세스를 가동한다. 주기적으로 분류 모델을 재학습하고, 오분류 이력을 기준정보 DB(300)에 피드백하는 능동학습(Active Learning) 체계를 구축한다.

### 3. 기준정보 데이터베이스(300) 단일 장애점(SPOF) 위험

* **설명:** 기준정보 DB(300)는 생육정보 산출모듈(200) 전체가 참조하는 중앙 저장소이다. 이 DB가 장애 또는 데이터 손상 상태에 빠질 경우, 이미지 보정(230)과 기관분류(220)에 필요한 기준 파라미터를 조회할 수 없어 생육정보 산출 파이프라인 전체가 중단된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 기준정보 DB(300)에 Active-Standby 이중화 구성을 적용하고, 생육정보 산출모듈(200) 내부에 기준 파라미터 캐싱 레이어를 두어 DB 단기 장애 시에도 마지막으로 조회한 기준값으로 처리를 지속할 수 있도록 한다. 정기적인 DB 백업 및 복구 훈련을 실시한다.

### 4. 생육정보 및 영농정보의 비인가 접근·유출 보안 위협

* **설명:** 영농정보 데이터베이스(400)와 정보전송부(280)를 통해 사용자단말(500)로 전달되는 생육 데이터 및 영농 정보는 농가의 민감한 경영 정보를 포함한다. 전송 구간 또는 DB 접근 권한 설정 미흡 시 외부 공격자 또는 내부자에 의한 데이터 유출이 발생할 수 있으며, 농가 경쟁력 저하 및 법적 책임 문제가 발생한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 정보전송부(280)~사용자단말(500) 구간에 TLS 1.3 이상의 암호화 통신을 의무 적용한다. 각 DB에 역할 기반 접근 제어(RBAC)를 구현하고, 접근 로그를 중앙 SIEM에 수집·모니터링한다. 개인정보보호법 및 농업 데이터 관련 규정 준수 여부를 정기 감사한다.

### 5. 과중 산출부(250) 알고리즘 정확도 저하로 인한 수확량 예측 오류

* **설명:** 과중 산출부(250)는 2D 이미지로부터 3D 무게를 추정하는 고난이도 태스크를 수행한다. 작물 품종 다양성, 성장 단계별 형태 변화, 이미지 촬영 각도 편차 등으로 인해 산출 오차가 커질 경우, 농가는 수확 시기와 출하량을 잘못 판단하여 직접적인 경제적 손실을 입는다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 과중 산출 모델의 정확도를 품종별·성장 단계별로 구분하여 주기적으로 검증하고, 실측값과 산출값의 오차율을 영농정보 DB(400)에 누적 기록한다. 오차율이 임계값을 초과하는 경우 사용자단말(500)에 경고를 표시하고, 실측 보정 데이터를 수집하여 모델 재학습에 활용하는 피드백 루프를 구축한다.

### 6. 영농정보 매칭부(270)의 부적절한 영농 처방 제공 위험

* **설명:** 영농정보 매칭부(270)는 생육정보 산출 결과(260)를 영농정보 DB(400)와 매칭하여 비료·농약·관개 등의 처방을 생성한다. DB 정보가 구버전이거나 생육정보 산출 오류가 누적된 경우, 과잉 시비 또는 불필요한 농약 사용을 처방하여 작물 피해 및 환경 오염을 유발할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟢 Low
* **대응 방안:** 영농정보 DB(400)의 데이터 버전 관리 체계를 수립하고, 농촌진흥청 등 공신력 있는 기관의 최신 영농 가이드라인과 정기적으로 동기화한다. 매칭 결과에 신뢰도 등급을 표시하고, 고위험 처방(농약, 대량 시비)의 경우 전문가 확인 후 적용하는 2단계 승인 프로세스를 사용자단말(500)에 구현한다.
