## 100010

# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 스마트팜 통합 관제를 위한 ERP-IoT-AI 하이브리드 아텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 식물 생산 ERP(100)를 중심으로 생산 계획, 재배 관리, 출하, 원가 관리 등 전사적 자원 관리를 수행해야 하며, 동시에 테스트베드 환경 시뮬레이션(200)의 실시간 센서 데이터 수집 및 장비 제어, 생육 분석용 카메라 모듈(300)의 고해상도 영상 데이터 처리를 통합해야 함. 기존 단일 서버 구조로는 실시간 환경 제어의 지연과 대용량 영상 처리 부하를 감당하기 어려움. |
| **결정(Decision)**       | 핵심 비즈니스 로직과 데이터 저장소를 중앙의 '식품생산 ERP' 및 '재배 컨설팅 모듈'에 집중하되, 물리적 제어 및 데이터 수집은 지 계층(200, 300)으로 분리하는 하이브리드 아키텍처를 채택. ERP와 엣지 장치 간에는 생산/작업 관리, 센싱/제어, 영상 데이터라는 명확한 인터페이스를 정의하여 느슨한 결합(Loose Coupling)을 유지함.               |
| **근거(Rationale)**      | 농업 환경은 실시간성(환경 제어)과 정확성(생육 분석, 원가 계산)이 동시에 요구됨. 중앙 집중식 ERP는 데이터 일관성과 비즈니스 로직 통합에 유리하나, 실시간 제어에는 적합하지 않음. 따라서 엣지 장치(200)가 로컬 제어를 담당하고, AI/ML 모듈(100)이 축적된 데이터를 분석하여 최적의 생육 환경을 제안하는 구조가 기술적으로 타당함.                   |
| **결과(Consequences)**   | 시스템의 확장성과 모듈성이 향상됨. 새로운 센서나 카메라 모듈 추가 시 ERP 코어 수정 없이 엣지 계층만 교체 가능. 그러나 네트워크 연결이 끊어질 경우 중앙 ERP와 엣지 장치 간 데이터 동기화 지연이 발생할 수 있음.                                                                                        |
| **트레이드오프(Trade-offs)** | 실시간 제어 안정성 및 모듈별 독립성 확보 vs. 분산 시스템으로 인한 통합 관리 복잡도 증가 및 네트워크 의존성 심화.                                                                                                                                                 |

---

## ⚠️ 잠재적 위험 분석

### 1. 엣지-중앙 통신 단절에 의한 환경 제어 실패

- **설명:** 테스트베드(200)와 식품생산 ERP(100) 간 네트워크 연결이 불안정하거나 중단될 경우, ERP의 제어 명령(에어컨, 양액 공급 등)이 현장 장비에 전달되지 않아 작물 폐사 가능성.
- **심각도:**  High
- **발생 가능성:**  Medium
- **대응 방안:** 지 컨트롤러(200)에 로컬 펌웨어 기반 자동 제어 로직(예: 온도 임계치 초과 시 냉방 가동)을 내장하여 프라인 상태에서도 기본 생존 환경 유지. 메시지 큐(Message Queue) 기반 비동기 통신 및 재전송 메커니즘 적용.
  
  ### 2. AI/ML 모델의 데이터 편향 및 오분석
- **설명:** 머신러닝 및 컴퓨터 비전 모듈이 학습한 데이터와 실제 현장 데이터(조명 변화, 카메라 오염 등) 간 차이가 발생할 경우, 생육 스트레스나 생육 크기 분석이 왜곡되어 잘못된 재배 컨팅 제공.
- **심각도:**  Medium
- **발생 가능성:**  High
- **대응 방안:** 정기적인 모델 재학습(Retraining) 파이프라인 구축. 엣지 디바이스의 자가 진단 기능(카메라 렌즈 오염 감지 등) 도입. 전문가 풀(Pool)의 인간 검증(Human-in-the-loop) 프로세스를 분석 결과 반영 전 필수 단계로 설정.
  
  ### 3. 대용량 영상 데이터 처리 병목 현상
- **설명:** 생육분석용 카메라 모듈(300)에서 수집하는 NIR, LWIR, Color 영상이 고해상도/고프레임일 경우, 컴퓨터 비전 모듈의 처리 대기열이 쌓여 실시간 모니터링 대시보드 업데이트 지연.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 엣지 측에서 1차 필터링(불필요한 프레임 제거) 수행. 스트리밍 프로토콜 최적화 및 GPU 기반 가속 서버 도입. 핵심 지표만 추출하여 전송하고 원본 영상은 로컬 저장 후 야간 배치 전송.
  
  ### 4. IoT 디바이스 보안 취약점 노출
- **설명:** 테스트베드의 센서/제어기(200)나 카메라(300)가 외부 네트워크에 직접 노출될 경우, 해킹으로 인한 악의적인 환경 조작(온도 급상승, 양액 과다 공급) 발생 가능.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 모든 엣지 디바이스는 DMZ 구역에 배치하고 방화벽 정책 적용. 디바이스 간 통신은 TLS 암호화 및 인증서 기반 Mutual Authentication 적용. 정기적인 보안 패치 및 침입 탐지 시스템(IDS) 모니터링.
  
  ### 5. 재배 컨설팅 모듈과 ERP 간 데이터 불일치
- **설명:** 재배 컨설팅 모듈에서 도출된 최적 환경 정보나 생육 정보가 ERP의 생산 계획이나 원가 관리 모듈에 실시간으로 반영되지 않을 경우, 실제 작업과 계획 간 괴리 발생.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 모듈 간 데이터 동기화를 위한 이벤트 기반 아키텍처(Event-Driven Architecture) 도입. 데이터 변경 시 즉시 이벤트 발행하여 ERP 업데이트. 트랜잭션 관리 로직을 통해 데이터 일관성 보장.
