# 🏗️ **아키텍처 분석 보고서: 분산형 신원 인증 시스템 (Decentralized Identity Architecture)**

---

## 📋 **ADR (Architecture Decision Record)**

### **ADR-001: 분산형 신원 관리 프레임워크 채택 (Self-Sovereign Identity, SSI)**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 기존 중앙집중식 인증 시스템의 단점(단일 실패점, 개인 데이터 통제 부족, 상호운용성 저하)을 해결하기 위해 **사용자가 자신의 신원 데이터를 직접 관리**할 수 있는 분산형 아키텍처가 필요함. 이미지에서 확인된 **Issuer-Issue-Verify-Present** 프로세스는 **W3C DID(Decentralized Identifier) 및 Verifiable Credential** 표준과 일치함. |
| **결정(Decision)** | 1. **DID(Decentralized Identifier) 표준**을 기반으로 신원 데이터 식별 및 관리
2. **Verifiable Credential (VC) 표준**을 사용하여 신원 정보의 발행 및 검증
3. **블록체인 또는 분산형 레지스트리**를 활용한 **신원 데이터 저장소** 구축 (예: Hyperledger Indy, Ethereum DID)
4. **OAuth 2.1 / OpenID Connect**와 연계한 **신원 프레젠테이션 프로토콜** 채택 (예: W3C DID Exchange) |
| **근거(Rationale)** | - **W3C DID Core (2023년 개정)**과 **Verifiable Credential Data Model 2.0**이 분산형 신원 관리를 위한 산업 표준으로 자리잡음.
- **ISO/IEC 27789:2023** (Self-Sovereign Identity Framework)이 분산형 인증의 보안 및 상호운용성 요구사항을 규정함.
- **KISA의 ITU-T X.1352**와 연계하여 국내외 IoT/스마트시스템에서 보안 인증 프레임워크로 활용 가능함. |
| **결과(Consequences)** | ✅ **장점**:
- 사용자가 신원 데이터를 직접 통제 (GDPR/PDPA 준수 용이)
- 중앙 서버 의존성 감소 (고가용성, 단일 실패점 제거)
- **IoT/스마트시스템**에서 디바이스 간 상호운용성 강화 (예: 스마트팜 기자재 인증)
- **TTA 표준**과 연계 가능 (스마트팜 데이터 상호운용 프레임워크 적용) |
| **트레이드오프(Trade-offs)** | ❌ **단점**:
- **초기 구축 복잡성** (블록체인/분산 레지스트리 통합 필요)
- **사용자 교육 필요성** (DID 키 관리, 백업 프로세스)
- **성능 오버헤드** (블록체인 트랜잭션 지연 가능성) |

### **ADR-002: 신원 데이터 저장소 아키텍처 (Verifiable Data Registry)**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 이미지에서 확인된 **"분산형 ID 저장소"**는 **신원 데이터의 영속성, 무결성, 검증 가능성**을 보장해야 함. 중앙 DB 대신 **분산형 레지스트리**를 사용하기로 결정함. |
| **결정(Decision)** | 1. **Hyperledger Indy** 또는 **Ethereum DID**를 기반으로 **공개-사설 하이브리드 네트워크** 구축
2. **IPFS(InterPlanetary File System)**를 사용하여 대용량 신원 데이터 저장
3. **Merkle Tree**를 활용한 데이터 무결성 검증
4. **KISA의 보안 기준**에 따라 **HSM(Hardware Security Module)**을 통해 키 관리 |
| **근거(Rationale)** | - **Hyperledger Indy**는 **IBM, Microsoft, Accenture** 등 글로벌 기업에서 채택 중임.
- **ISO/IEC 27030:2020**이 분산형 데이터 저장소의 보안 요구사항을 규정함.
- **TTA 스마트팜 표준**과 연계하여 **디바이스 인증 데이터**를 저장할 수 있음. |
| **결과(Consequences)** | ✅ **장점**:
- **데이터 무결성 보장** (불변성, 암호화)
- **규제 준수** (GDPR, PDPA, K-ISMS)
- **스마트팜/IoT 디바이스** 인증 데이터 저장 가능 |
| **트레이드오프(Trade-offs)** | ❌ **단점**:
- **네트워크 지연** (블록체인 트랜잭션 처리 속도)
- **고비용** (HSM, IPFS 노드 운영 비용) |

### **ADR-003: 신원 프레젠테이션 프로토콜 (Presentation Exchange)**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 사용자가 **신원 정보를 제3자에게 안전하게 제시**할 수 있는 프로토콜이 필요함. 이미지에서 **"Presentation"**은 **선택적 디스클로저**와 **검증 가능성**을 요구함. |
| **결정(Decision)** | 1. **W3C Verifiable Presentation** 표준 채택
2. **Selective Disclosure for Verifiable Credentials (SD-VC)**를 지원
3. **JSON Web Token (JWT) + BBS+ Signature**를 사용하여 최소한의 데이터 노출 |
| **근거(Rationale)** | - **W3C DID Exchange**가 **OAuth 2.1**과 호환됨.
- **ETSI EN 303 645**가 IoT 디바이스 인증에 **선택적 디스클로저**를 요구함. |
| **결과(Consequences)** | ✅ **장점**:
- **개인 정보 보호** (필요한 데이터만 노출)
- **스마트팜/IoT 시스템**에서 디바이스 인증에 활용 가능 |
| **트레이드오프(Trade-offs)** | ❌ **단점**:
- **복잡한 구현** (BBS+ 암호화 알고리즘) |

## ⚠️ **잠재적 위험 분석**

### **1. 블록체인 네트워크 지연 및 성능 이슈**
- **설명**: 분산형 레지스트리(예: Hyperledger Indy)는 **트랜잭션 처리 속도가 느릴 수** 있으며, **스마트팜/IoT 시스템**에서 실시간 인증이 필요한 경우 지연이 발생할 수 있음.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **오프체인 솔루션** (예: **Celo, Polygon**과 같은 Layer 2 네트워크 활용)
  - **로컬 캐싱** (사용자 디바이스에 신원 데이터 캐싱)
  - **하이브리드 아키텍처** (중앙 DB + 분산 레지스트리 병행 사용)

### **2. 사용자 키 관리 실패 (키 유실/도난)**
- **설명**: 사용자가 **DID 키를 백업하지 않거나 유출**할 경우, **영구적인 신원 데이터 손실**이 발생할 수 있음.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **다중 시그니처 키 관리** (예: **Shamir’s Secret Sharing**)
  - **비밀번호 관리 도구 연동** (예: **Bitwarden, 1Password**)
  - **KISA 보안 가이드라인**에 따른 **HSM 기반 키 저장소** 제공

### **3. 상호운용성 문제 (표준 미준수)**
- **설명**: **W3C DID 표준**이 계속 진화하고 있으며, **구현체 간 호환성 이슈**가 발생할 수 있음.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **W3C DID Core 1.0** 및 **Verifiable Credential 2.0**에 준한 **테스트Bed** 구축
  - **TTA 스마트팜 표준**과 연계한 **호환성 테스트** 수행
  - **OpenID Foundation**과 협력한 **인증 테스트**

### **4. 규제 및 법적 위험 (GDPR/PDPA 불이행)**
- **설명**: **EU GDPR**이나 **한국 PDPA**에서 요구하는 **개인 데이터 삭제 요청**에 대응하지 못하면 **법적 제재**를 받을 수 있음.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **가상 데이터 삭제(Virtual Deletion)** 지원 (예: **IPFS Pinning Service 해제**)
  - **KISA 인증**을 받은 **데이터 삭제 프로토콜** 구현
  - **스마트팜 데이터**에 대한 **접근 통제 로그** 유지

### **5. 중앙화된 검증자 의존성 (Single Point of Failure)**
- **설명**: **"Verifier"**가 중앙화된 경우, **서버 다운**이나 **공격**으로 인해 **전체 시스템이 마비**될 수 있음.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **분산형 검증 노드** (예: **Algorand, Ethereum 스테이킹 노드**)
  - **Multi-Party Computation (MPC)**를 활용한 **분산 검증**
  - **TTA 스마트팜 표준**에 따른 **백업 검증 서버** 배포

### **6. 공격 벡터: Sybil 공격 및 스푸핑**
- **설명**: 악의적인 사용자가 **가짜 DID를 생성**하여 **신원 인증 시스템을 조작**할 수 있음.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **Proof of Personhood** (예: **BrightID, Worldcoin**)
  - **KISA의 ITU-T X.1352**에 따른 **디바이스 인증 강화**
  - **기계 학습 기반 이상 탐지** (예: **Anomaly Detection API**)

### **7. 데이터 유출 위험 (IPFS/블록체인 취약성)**
- **설명**: **IPFS**나 **블록체인**에 저장된 신원 데이터가 **암호화되지 않거나 취약한 경우** 유출될 수 있음.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **Homomorphic Encryption**을 활용한 **암호화된 데이터 저장**
  - **KISA의 보안 기준**에 따른 **데이터 암호화 정책** 적용
  - **정기적인 보안 오디트** 수행

**※ 추가 고려사항**
- **스마트팜/IoT 연계**: **TTA 표준**과 **oneM2M**을 활용하여 **디바이스 인증**을 통합할 수 있음.
- **국내 표준 준수**: **KISA 인증**을 받은 **보안 모듈**을 사용하여 **국내 법적 요구사항**을 충족할 수 있음.
