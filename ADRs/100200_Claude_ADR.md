📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 5단계 파이프라인 기반 스마트팜 AI 예측 플랫폼 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                      |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 팜커넥트 시스템은 센서 수집(1단계)부터 AI 예측 시뮬레이션(5단계)까지 이질적인 데이터 소스(외부기상, 환기/관수/증산 환경정보)를 통합하여 이상징후 감지, 실시간 예측, 작물상태 분석, 병충해 예찰, 전세계 농작물 가격 예측까지 수행해야 한다. 단일 모놀리식 구조로는 각 단계별 처리 속도 차이와 도메인 분리가 불가능하다. |
| **결정(Decision)**       | 단계별 책임을 분리한 5-Stage 이벤트 드리븐 파이프라인 아키텍처를 채택한다. 각 단계는 독립 마이크로서비스로 구성하며, 3단계(내부환경정보예측·알고리즘 분석·딥러닝)를 AI/ML 처리 계층으로, 4단계를 실시간 반응 계층으로, 5단계를 고부하 추론 계층으로 역할을 명확히 구분한다.                        |
| **근거(Rationale)**      | ① 센서 데이터(1단계)는 고빈도·저지연이 요구되는 반면, 전세계 농작물 가격 예측(5단계)은 배치 추론 워크로드로 처리 특성이 상이하다. ② 내부환경정보예측과 병충해 딥러닝 예찰은 모델 재학습 주기가 다르므로 독립 배포가 필수적이다. ③ 실시간 예측 시스템(4단계)은 SLA 보장을 위해 다른 워크로드로부터 격리되어야 한다.  |
| **결과(Consequences)**   | (+) 단계별 독립 스케일링으로 비용 최적화 가능, 특정 단계 장애가 전체 파이프라인에 전파되지 않음, AI 모델 교체 시 해당 서비스만 재배포 가능. (-) 단계 간 메시지 브로커(Kafka/MQTT) 운영 복잡도 증가, 분산 트랜잭션 처리 및 데이터 일관성 유지 비용 발생.                             |
| **트레이드오프(Trade-offs)** | **얻는 것:** 서비스별 독립 확장성, 기술 스택 다양성(Python ML 서비스 + Java API 게이트웨이 혼용 가능), 장애 격리. **감수해야 할 것:** 네트워크 홉 증가로 인한 End-to-End 지연시간 누적, 운영팀의 분산시스템 전문성 요구, 서비스 간 계약(API/스키마) 관리 오버헤드.            |

### ADR-002: 온라인 컨설팅 및 전세계 가격 예측을 위한 외부 연동 아키텍처 채택

| 항목                     | 내용                                                                                                                                            |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 5단계의 온라인컨설팅시스템과 전세계농작물가격예측시스템은 외부 기상청 API, 글로벌 농산물 시세 데이터, 사용자 접점(웹/앱)을 동시에 처리해야 한다. 내부 폐쇄망 센서 네트워크와 외부 인터넷 구간이 혼재하는 하이브리드 환경이 요구된다.          |
| **결정(Decision)**       | 내부망(센서~4단계)과 외부망(5단계 컨설팅·가격예측)을 DMZ 기반으로 분리하고, API Gateway를 통해 외부 데이터 수집 및 사용자 서비스를 제공한다. AI 예측 시뮬레이션 결과는 내부 이벤트 버스를 통해 외부 서비스 계층으로 단방향 전달한다. |
| **근거(Rationale)**      | 농장 내부 센서 데이터는 보안 민감 자산이며, 외부 공격 표면을 최소화하기 위해 네트워크 분리가 필수이다. 전세계 가격 예측은 외부 공공 데이터(FAO, CME 등)에 의존하므로 외부 연동 전용 게이트웨이가 필요하다.                     |
| **결과(Consequences)**   | (+) 내부 센서 인프라의 보안 강화, 외부 서비스 장애가 내부 제어 루프에 영향 없음. (-) DMZ 구성 및 방화벽 정책 관리 복잡도 증가, 외부 API 의존성으로 인한 가용성 리스크.                                     |
| **트레이드오프(Trade-offs)** | **얻는 것:** 보안 격리, 규제 준수 용이성(농업 데이터 국내 보관 의무 등). **감수해야 할 것:** 외부 구간 통신 지연, 이중 인프라 운영 비용.                                                       |

⚠️ 잠재적 위험 분석
------------

### 1. 실시간 예측 파이프라인의 단일 장애점(SPOF) — 내부환경정보예측 서비스

* **설명:** 3단계의 내부환경정보예측 컴포넌트(빨간 테두리 강조)는 4단계 실시간예측시스템과 이상징후감지시스템의 업스트림이다. 해당 서비스가 다운되거나 모델 추론 지연이 발생하면, 하위 4단계 전체가 정상 입력 없이 오작동하거나 경보 누락이 발생할 수 있다. 특히 여름철 고온 이상징후 미감지 시 작물 전량 손실로 이어진다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 내부환경정보예측 서비스에 Active-Active 이중화 구성 적용, Circuit Breaker 패턴 도입으로 장애 전파 차단. 마지막 정상 예측값을 캐싱하여 Fallback 값으로 사용하는 Graceful Degradation 구현. 서비스 헬스체크 및 자동 재시작 정책(Kubernetes Liveness/Readiness Probe) 필수 적용.

### 2. 센서 데이터 품질 저하로 인한 AI 모델 입력 오염 (Garbage In, Garbage Out)

* **설명:** 1단계 센서(관수분석정보, 증산분석정보, 환기분석정보)가 노후화, 단선, 보정 오류 등으로 이상값을 전송할 경우, 3단계 알고리즘 분석 및 딥러닝 모델이 오염된 데이터를 정상으로 학습·추론하게 된다. 병충해 딥러닝 예찰 모델이 잘못된 환경 데이터를 기반으로 예찰 실패를 반복하면 방제 시기를 놓쳐 대규모 피해가 발생한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 2단계 데이터 수집 직후 실시간 데이터 유효성 검증 레이어(Statistical Outlier Detection, IQR/Z-Score 기반) 삽입. 센서별 정상 범위 기준값 DB 관리 및 임계치 초과 시 알림 발송. 센서 교정 주기(캘리브레이션 스케줄) 자동화 및 이력 관리 시스템 구축.

### 3. AI 모델 드리프트(Model Drift)로 인한 예측 정확도 장기 저하

* **설명:** 수확예측딥러닝 및 병충해딥러닝예찰 모델은 초기 학습 데이터로 배포되지만, 기후변화·신규 병충해 발생·품종 변경 등으로 운영 환경이 변화하면 모델의 실제 예측 성능이 점진적으로 저하된다. 특히 전세계농작물가격예측시스템은 글로벌 거시경제 변수에 민감하여 모델 유효기간이 짧다. 드리프트를 감지하지 못하면 농가는 잘못된 수확시기·판매시기 결정을 내리게 된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** MLflow 등 ML 모델 레지스트리를 통한 모델 버전 관리 체계 수립. 예측값과 실제 결과값(수확량, 병충해 발생 여부) 간 오차를 주기적으로 측정하는 모델 성능 모니터링 파이프라인 구축. 드리프트 감지 임계치 초과 시 자동 재학습(Retraining) 트리거 및 A/B 테스트 기반 모델 교체 프로세스 정의.

### 4. 농장 제어 시스템 대상 사이버 보안 공격 (OT/IT 융합 보안 위협)

* **설명:** 팜커넥트는 IT(AI 예측, 온라인 컨설팅) 시스템과 OT(관수·환기 제어) 시스템이 연결된 구조이다. 외부 인터넷에 노출된 5단계 온라인컨설팅시스템을 통해 공격자가 침투할 경우, 내부 실시간예측시스템을 거쳐 관수 및 환기 제어 명령을 조작할 수 있다. 이는 작물 과습·고온 피해 등 물리적 피해로 직결된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** IT-OT 구간에 단방향 데이터 다이오드(Unidirectional Gateway) 또는 강화된 방화벽 세그멘테이션 적용. 5단계 외부 서비스는 Zero Trust 아키텍처(최소 권한 원칙, MFA) 기반으로 접근 제어. 이상 제어 명령 탐지를 위한 OT 네트워크 이상행위 탐지(OT-NIDS) 솔루션 도입. 정기적 모의침투 테스트(Penetration Test) 수행.

### 5. 외부 데이터 소스 의존성으로 인한 서비스 가용성 저하

* **설명:** 1단계의 외부기상정보(기상청 API)와 5단계의 전세계농작물가격예측에 필요한 외부 시세 데이터(글로벌 거래소 API)는 제3자 서비스에 의존한다. 해당 외부 API가 장애, 정책 변경, 또는 유료화될 경우, 기상정보예측(3단계) 및 가격예측 서비스(5단계)가 동시에 중단되어 농가의 의사결정 공백이 발생한다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 외부 기상 데이터는 복수 공급자(기상청 + 민간 기상 API) 멀티소싱 전략 채택. 최근 N일치 외부 데이터를 로컬 캐시에 저장하여 API 장애 시 지연 데이터로 서비스 지속. 외부 API 호출부에 Retry + Exponential Backoff + Timeout 정책 표준화. SLA 기반 공급사 계약 및 대체 공급사 전환 Runbook 사전 준비.

### 6. 작물상태 및 수확시기 예측의 설명 불가능성 (AI Explainability 부재)

* **설명:** 4단계의 작물상태맞춤분석 및 수확시기맞수확량증 시스템이 딥러닝 기반 블랙박스 모델로 운영될 경우, 농가 또는 농업 컨설턴트가 예측 결과의 근거를 이해하지 못해 신뢰도가 하락하고 도입 거부감이 생긴다. 또한 예측 오류 발생 시 원인 분석 및 모델 디버깅이 불가능하여 사고 대응이 지연된다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** SHAP(SHapley Additive exPlanations) 또는 LIME 기반 예측 근거 시각화 기능을 온라인컨설팅시스템(5단계)에 통합하여 농가에게 "왜 이 시기에 수확해야 하는가"를 설명 가능한 형태로 제공. 모델 선택 시 해석 가능한 앙상블 모델(XGBoost, LightGBM)과 딥러닝의 하이브리드 구성 검토.
