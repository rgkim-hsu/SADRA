### ADR-001: 스마트팜 IoT 데이터 수집 및 클라우드 기반 정보 제공 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                    |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 환경(10)에서 온도·습도·CO₂·토양수분 등 다양한 환경 데이터를 실시간으로 수집해야 하며, 농장 외부의 사용자(농업인, 관리자)가 언제 어디서든 농장 상태를 모니터링하고 제어 명령을 내릴 수 있어야 한다. 단일 로컬 시스템만으로는 원격 접근, 데이터 집계, 알림 발송이 불가능하다.                                                  |
| **결정(Decision)**       | 농장 내부에 **센서 측정장치(200)**와 **모니터링 장치(100)**를 계층 구조로 배치하고, 수집된 데이터를 무선 통신(Wi-Fi/LoRa/LTE)을 통해 **클라우드 기반 정보 제공 서버(400)**로 전송한다. 사용자는 **사용자 기기(20)**(스마트폰·PC)를 통해 서버에 접근하여 데이터 조회 및 원격 제어를 수행하는 **3-Tier IoT 아키텍처**를 채택한다. |
| **근거(Rationale)**      | ① 엣지(센서 측정장치) → 게이트웨이(모니터링 장치) → 클라우드(정보 제공 서버) 구조는 IoT 표준 레퍼런스 아키텍처(IEC 62443, ISO/IEC 30141)에 부합한다. ② 로컬 전처리를 통해 원시 데이터 전송량을 줄이고 네트워크 비용을 절감한다. ③ 클라우드 서버를 중앙화함으로써 다수 농장의 데이터를 통합 관리하고 AI 분석·예측 서비스 확장이 용이하다.       |
| **결과(Consequences)**   | **긍정적:** 농장 현장 인력 없이도 24시간 원격 모니터링 가능, 이상 환경 자동 알림, 다중 사용자 동시 접근 지원, 데이터 기반 의사결정 가능. **부정적:** 클라우드 서버 및 인터넷 연결에 대한 단일 장애점(SPOF) 발생 가능성, 통신 장애 시 실시간 제어 불가.                                                            |
| **트레이드오프(Trade-offs)** | **얻는 것:** 확장성(Scalability), 원격 접근성, 중앙집중식 데이터 관리, 멀티 디바이스 지원. **감수할 것:** 클라우드 의존성 증가, 월정 서버 운영비용 발생, 네트워크 레이턴시로 인한 실시간 제어 한계(수백ms~수초 지연), 개인정보·농업 데이터 외부 서버 저장에 따른 보안 리스크.                                            |

### ADR-002: 무선 통신 기반 컴포넌트 간 연결 방식 채택

| 항목                     | 내용                                                                                                                                                           |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **상황(Context)**        | 스마트팜은 넓은 부지와 다양한 장애물(온실 구조물, 식물군 등)로 인해 유선 배선이 비효율적이며, 센서 위치 변경 유연성이 요구된다. 모니터링 장치↔정보 제공 서버, 정보 제공 서버↔사용자 기기 간 모두 무선 통신(도면 내 번개 모양 기호)을 사용하고 있다.             |
| **결정(Decision)**       | 농장 내부 단거리 통신은 **Wi-Fi 또는 Zigbee/Z-Wave**, 광역 통신은 **LTE/5G 또는 LoRaWAN**을 채택하고, 서버↔사용자 기기 간은 **HTTPS REST API 또는 MQTT over TLS** 프로토콜을 사용하는 혼합 무선 통신 전략을 채택한다. |
| **근거(Rationale)**      | LoRaWAN은 저전력·장거리 특성으로 배터리 기반 센서에 적합하며, LTE/5G는 대용량 데이터(영상 등) 전송에 유리하다. MQTT는 IoT 경량 메시지 프로토콜로 저대역폭 환경에서 높은 신뢰성을 제공한다(OASIS 표준).                              |
| **결과(Consequences)**   | **긍정적:** 유연한 센서 배치, 설치 비용 절감, 확장 용이. **부정적:** 무선 간섭, 기상 조건(폭우, 안개)에 따른 통신 품질 저하 위험.                                                                          |
| **트레이드오프(Trade-offs)** | **얻는 것:** 설치 유연성, 배선 비용 절감. **감수할 것:** 유선 대비 낮은 통신 안정성, 보안 취약점 노출 면적 증가.                                                                                     |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. 클라우드 정보 제공 서버(400) 단일 장애점(SPOF) 위험

* **설명:** 정보 제공 서버(400)가 단일 인스턴스로 운영될 경우, 서버 장애·DDoS 공격·클라우드 리전 장애 발생 시 모든 사용자 기기(20)의 모니터링 및 제어 기능이 전면 중단된다. 작물 생육 임계 시점(혹서기, 한파)에 장애 발생 시 농작물 대량 피해로 이어질 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 멀티 AZ(Availability Zone) 이중화 배포, Active-Active 또는 Active-Standby 이중화 구성 적용. 모니터링 장치(100)에 로컬 엣지 캐싱 및 오프라인 자동 제어 로직(룰 기반 로컬 자율운전 모드) 탑재하여 서버 단절 시에도 기본 제어 유지.

* * *

### 2. 무선 통신 두절로 인한 실시간 제어 불가 위험

* **설명:** 농촌 지역의 LTE 음영지역, 폭우·낙뢰로 인한 네트워크 장애, 또는 통신사 장애 발생 시 모니터링 장치(100)와 정보 제공 서버(400) 간 통신이 두절된다. 이 경우 원격 제어 명령 전달이 불가능해져 온실 환기팬·관개 시스템 등 액추에이터가 오동작하거나 무반응 상태에 빠질 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 모니터링 장치(100)에 Store-and-Forward 기능 구현(통신 복구 시 데이터 일괄 전송). 유선 LAN 또는 위성통신(예: Starlink)을 백업 채널로 구성. 통신 두절 감지 시 사전 정의된 안전 상태(Fail-Safe Mode)로 자동 전환하는 로컬 제어 로직 탑재.

* * *

### 3. IoT 디바이스 보안 취약점 및 무단 접근 위험

* **설명:** 센서 측정장치(200) 및 모니터링 장치(100)는 일반적으로 펌웨어 업데이트가 불규칙하고 기본 인증 정보(Default Credential)가 변경되지 않은 채 운영되는 경우가 많다. 공격자가 무선 통신 구간을 스니핑하거나 취약한 디바이스를 장악할 경우, 허위 센서 데이터를 주입하거나 액추에이터를 무단 제어하여 농작물 피해를 유발할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 모든 통신 구간 TLS 1.3 암호화 적용 및 상호 인증(mTLS) 구현. 디바이스별 고유 인증서 발급 및 PKI 기반 디바이스 아이덴티티 관리. 정기적인 OTA(Over-The-Air) 펌웨어 보안 업데이트 자동화. 네트워크 세그멘테이션을 통해 IoT 디바이스 전용 VLAN 분리.

* * *

### 4. 센서 측정장치(200) 오작동 및 데이터 품질 저하 위험

* **설명:** 고온다습한 농업 환경, 화학 농약·비료 노출, 물리적 충격 등으로 인해 센서가 드리프트(drift) 현상을 일으키거나 오염되어 부정확한 데이터를 지속적으로 전송할 수 있다. 잘못된 센서값이 정상으로 판정되어 정보 제공 서버(400)에 누적될 경우, AI 분석 모델의 오판 및 잘못된 농장 제어 결정으로 이어진다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 동일 측정 항목에 대한 이중화 센서(Redundant Sensor) 배치 및 교차 검증 로직 구현. 통계적 이상값 탐지 알고리즘(Z-Score, IQR 기반)을 모니터링 장치(100) 또는 서버(400)에 적용. 센서 교정(Calibration) 주기 관리 시스템 구축 및 열화 감지 알림 기능 구현.

* * *

### 5. 사용자 기기(20) 접근 권한 관리 미흡 위험

* **설명:** 다수의 농장 관리자·작업자가 동일한 계정을 공유하거나, 퇴직 직원의 계정이 즉시 비활성화되지 않을 경우 무단 접근이 발생할 수 있다. 또한 사용자 기기(20) 분실·도난 시 인증 정보가 노출되어 외부인이 농장 제어 시스템에 접근, 관개 차단 또는 온도 조작 등 의도적 피해를 유발할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 역할 기반 접근 제어(RBAC) 적용으로 관리자·운영자·조회자 권한 분리. MFA(다중 인증) 필수 적용 및 세션 타임아웃 정책 수립. 접근 로그 전수 기록 및 이상 접근 패턴(비정상 시간대, 해외 IP) 탐지 알림 구현. 기기 분실 시 원격 세션 무효화 기능 제공.

* * *

### 6. 농업 데이터 주권 및 클라우드 종속성(Vendor Lock-in) 위험

* **설명:** 정보 제공 서버(400)가 특정 클라우드 사업자(AWS, Azure, GCP 등)에 단독 의존할 경우, 해당 사업자의 서비스 종료·요금 인상·정책 변경 시 시스템 전환 비용이 막대하게 발생한다. 또한 농업 생산성 데이터(파종·수확량·병해충 패턴 등)가 해외 서버에 저장될 경우 데이터 주권 문제가 발생할 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 클라우드 중립적 컨테이너 기반(Docker/Kubernetes) 아키텍처로 멀티클라우드 또는 온프레미스 전환 가능성 확보. 국내 클라우드 서비스(NHN Cloud, KT Cloud, NAVER Cloud) 우선 검토를 통해 농업데이터 국내 보관 원칙 준수. 정기적인 데이터 백업 및 이식 가능한 표준 데이터 포맷(CSV, Parquet) 사용.

| **근거(Rationale)**      | LoRaWAN은 저전력·장거리 특성으로 배터리 기반 센서에 적합하며, LTE/5G는 대용량 데이터(영상 등) 전송에 유리하다. MQTT는 IoT 경량 메시지 프로토콜로 저대역폭 환경에서 높은 신뢰성을 제공한다(OASIS 표준).                              |
| **결과(Consequences)**   | **긍정적:** 유연한 센서 배치, 설치 비용 절감, 확장 용이. **부정적:** 무선 간섭, 기상 조건(폭우, 안개)에 따른 통신 품질 저하 위험.                                                                          |
| **트레이드오프(Trade-offs)** | **얻는 것:** 설치 유연성, 배선 비용 절감. **감수할 것:** 유선 대비 낮은 통신 안정성, 보안 취약점 노출 면적 증가.                                                                                     |

⚠️ 잠재적 위험 분석

### 1. 클라우드 정보 제공 서버(400) 단일 장애점(SPOF) 위험

* **설명:** 정보 제공 서버(400)가 단일 인스턴스로 운영될 경우, 서버 장애·DDoS 공격·클라우드 리전 장애 발생 시 모든 사용자 기기(20)의 모니터링 및 제어 기능이 전면 중단된다. 작물 생육 임계 시점(혹서기, 한파)에 장애 발생 시 농작물 대량 피해로 이어질 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 멀티 AZ(Availability Zone) 이중화 배포, Active-Active 또는 Active-Standby 이중화 구성 적용. 모니터링 장치(100)에 로컬 엣지 캐싱 및 오프라인 자동 제어 로직(룰 기반 로컬 자율운전 모드) 탑재하여 서버 단절 시에도 기본 제어 유지.

* * *

### 2. 무선 통신 두절로 인한 실시간 제어 불가 위험

* **설명:** 농촌 지역의 LTE 음영지역, 폭우·낙뢰로 인한 네트워크 장애, 또는 통신사 장애 발생 시 모니터링 장치(100)와 정보 제공 서버(400) 간 통신이 두절된다. 이 경우 원격 제어 명령 전달이 불가능해져 온실 환기팬·관개 시스템 등 액추에이터가 오동작하거나 무반응 상태에 빠질 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 모니터링 장치(100)에 Store-and-Forward 기능 구현(통신 복구 시 데이터 일괄 전송). 유선 LAN 또는 위성통신(예: Starlink)을 백업 채널로 구성. 통신 두절 감지 시 사전 정의된 안전 상태(Fail-Safe Mode)로 자동 전환하는 로컬 제어 로직 탑재.

* * *

### 3. IoT 디바이스 보안 취약점 및 무단 접근 위험

* **설명:** 센서 측정장치(200) 및 모니터링 장치(100)는 일반적으로 펌웨어 업데이트가 불규칙하고 기본 인증 정보(Default Credential)가 변경되지 않은 채 운영되는 경우가 많다. 공격자가 무선 통신 구간을 스니핑하거나 취약한 디바이스를 장악할 경우, 허위 센서 데이터를 주입하거나 액추에이터를 무단 제어하여 농작물 피해를 유발할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 모든 통신 구간 TLS 1.3 암호화 적용 및 상호 인증(mTLS) 구현. 디바이스별 고유 인증서 발급 및 PKI 기반 디바이스 아이덴티티 관리. 정기적인 OTA(Over-The-Air) 펌웨어 보안 업데이트 자동화. 네트워크 세그멘테이션을 통해 IoT 디바이스 전용 VLAN 분리.

### 4. 센서 측정장치(200) 오작동 및 데이터 품질 저하 위험

* **설명:** 고온다습한 농업 환경, 화학 농약·비료 노출, 물리적 충격 등으로 인해 센서가 드리프트(drift) 현상을 일으키거나 오염되어 부정확한 데이터를 지속적으로 전송할 수 있다. 잘못된 센서값이 정상으로 판정되어 정보 제공 서버(400)에 누적될 경우, AI 분석 모델의 오판 및 잘못된 농장 제어 결정으로 이어진다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 동일 측정 항목에 대한 이중화 센서(Redundant Sensor) 배치 및 교차 검증 로직 구현. 통계적 이상값 탐지 알고리즘(Z-Score, IQR 기반)을 모니터링 장치(100) 또는 서버(400)에 적용. 센서 교정(Calibration) 주기 관리 시스템 구축 및 열화 감지 알림 기능 구현.

### 5. 사용자 기기(20) 접근 권한 관리 미흡 위험

* **설명:** 다수의 농장 관리자·작업자가 동일한 계정을 공유하거나, 퇴직 직원의 계정이 즉시 비활성화되지 않을 경우 무단 접근이 발생할 수 있다. 또한 사용자 기기(20) 분실·도난 시 인증 정보가 노출되어 외부인이 농장 제어 시스템에 접근, 관개 차단 또는 온도 조작 등 의도적 피해를 유발할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 역할 기반 접근 제어(RBAC) 적용으로 관리자·운영자·조회자 권한 분리. MFA(다중 인증) 필수 적용 및 세션 타임아웃 정책 수립. 접근 로그 전수 기록 및 이상 접근 패턴(비정상 시간대, 해외 IP) 탐지 알림 구현. 기기 분실 시 원격 세션 무효화 기능 제공.
