## 100090

# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 통합 관리 서버의 도메인별 모듈화 및 분산 데이터 저장소 채택

| 항목                     | 내용                                                                                                                                                                                                                                                                                             |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 양봉 산업의 디지털 전환을 위해 위탁 소비자, 양봉가, 일반 소비자를 아우르는 회원 관리(702), 양봉 계약(703), 실시간 모니터링 및 원격 제어(704), 생산 관리(709), 그리고 쇼핑몰 운영(710) 등 이기종 기능을 단일 **통합관리서버** 내에서 처리해야 함. 모든 기능이 단일 데이터베이스에 종속될 경우, 쇼핑몰 트래픽 급증 시 IoT 모니터링 지연이나 계약 처리 장애가 발생하는 결합도(Coupling) 문제가 발생함.                                          |
| **결정(Decision)**       | 통합관리서버를 기능별 독립적인 모듈(701~710)로 분할하고, 각 모듈의 특성에 맞는 전용 데이터베이스(위탁소비자 DB, 양봉가 DB, 계약정보 DB, 생산/발송 이력 DB 등)를 할당하는 **도메인 중심의 분산 아키텍처**를 채택함. 서버통신부(701)를 단일 진입점으로 하되, 내부 라우팅을 통해 각 모듈로 트래픽을 분산함.                                                                                                       |
| **근거(Rationale)**      | 1. **관심사의 분리(Separation of Concerns):** 회원 인증, 실시간 IoT 데이터 처리, 전자상거래 로직은 서로 다른 수명 주기와 성능 요구사항을 가지므로 물리적/논리적 분리가 필수적임.<br>2. **확장성:** 쇼핑몰(710)과 모니터링(704)의 부하 패턴이 다르므로, 특정 모듈만 독립적으로 스케일링(Scale-out)이 가능함.<br>3. **데이터 보안:** 민감한 계약 정보(703)와 생산 이력(709)을 일반 회원 정보(702)와 격리하여 보안 수준을 다르게 적용 가능함. |
| **결과(Consequences)**   | 시스템의 모듈성이 향상되어 기능 추가 및 수정이 용이해지며, 특정 영역의 장애가 전체 시스템으로 전파되는 것을 차단함. 반면, 통합 통계 분석(708)이나 크로스 도메인 조회 시 여러 데이터베이스를 조인하거나 API를 호출해야 하므로 구현 복잡도가 증가함.                                                                                                                                                |
| **트레이드오프(Trade-offs)** | 모듈별 독립성 및 확장성 확보 vs. 분산 데이터 관리로 인한 통합查询(조회) 복잡도 증가 및 데이터 일관성 유지 비용 상승.                                                                                                                                                                                                                         |

---

## ⚠️ 잠재적 위험 분석

### 1. 실시간 모니터링 및 원격 제어 지연 (Latency)

- **설명:** 모니터링부(704)의 이상검출부(705)와 원격제어부(706)는 밀리초 단위의 실시간성을 요구함. 그러나 서버통신부(701)나 내부 네트워크가 쇼핑몰(710)의 대용량 트래픽으로 포화될 경우, 제어 명령 전달 지연으로 양봉장 장비 오작동이나 사고가 발생할 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 모니터링 및 제어 트래픽을 위한 독립적인 통신 채널(QoS 우선순위 할당) 구성, 서버통신부(701)에 트래픽 쉐이핑(Traffic Shaping) 적용, 엣지 컴퓨팅 도입으로 로컬 제어 우선 처리.
  
  ### 2. 생산 정보와 판매 정보 간 데이터 불일치
- **설명:** 생산관리부(709)의 '벌꿀 생산이력'과 '발송이력'이 업데이트될 때, 쇼핑몰관리부(710)의 '판매정보'에 실시간으로 반영되지 않으면 재고 오버(Over-selling) 또는 배송 지연이 발생함. 분산 DB 구조에서 트랜잭션 일관성을 보장하기 어려움.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 생산 모듈과 쇼핑몰 모듈 간 이벤트 기반 아키텍처(Event-Driven Architecture) 도입, 메시지 큐(Kafka 등)를 활용한 비동기 동기화, 재고 예약(Reservation) 로직을 통한 동시성 제어.
  
  ### 3. 원격 제어 모듈의 보안 취약점
- **설명:** 원격제어부(706)가 외부 양봉장 장비에 접근할 수 있는 권한을 가짐. 인증/인가 로직이 취약하거나 통신 구간 암호화가 미흡할 경우, 악의적인 제3자가 시스템에 침입하여 장비를 조작하거나 데이터를 탈취할 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 원격 제어 명령에 대한 다단계 인증(MFA) 적용, 통신 구간 TLS 1.3 암호화 강제, 명령어 무결성 검증(Digital Signature), 비정상적인 제어 패턴 감지 시 자동 차단 로직 구현.
  
  ### 4. 통계 분석부(708)의 성능 저하
- **설명**: 통계분석부(708)가 현황정보와 통계분석정보를 생성하기 위해 회원관리부(702), 생산관리부(709), 쇼핑몰관리부(710) 등 여러 모듈의 데이터를 실시간으로 취합해야 함. 이 과정에서 데이터 웨어하우스(EW) 부하가 급증하여 대시보드 로딩이 지연될 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 분석용 데이터는 별도 읽기 전용 복제본(Read Replica)이나 데이터 레이크로 이관하여 분석, 야간 배치(Batch) 작업을 통한 통계 자료 사전 생성(Caching), OLAP 큐브 도입.
  
  ### 5. 시뮬레이션 데이터의 신뢰성 부족
- **설명:** 시뮬레이션부(707)가 '지역별 지역조건' 데이터를 기반으로 양봉 환경을 시뮬레이션함. 만약 입력되는 지역 조건 데이터(기상, 환경 등)가 부정확하거나 최신화되지 않으면, 잘못된 시뮬레이션 결과가 양봉가(702)에게 제공되어 생산 계획에 악영향을 미칠 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low
- **대응 방안:** 외부 기상청/환경공단 API 등 공신력 있는 데이터 소스와의 자동 연계, 데이터 검증(Validation) 로직을 통한 이상치 필터링, 시뮬레이션 결과에 대한 신뢰도 점수 제공.
