# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 중앙 집중식 모니터링 및 엣지-클라우드 협력적 데이터 처리 아키텍처 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 사료 잔량 감시 장치(10)와 원격 센서부(120)로부터 발생하는 실시간 측정 데이터를 안정적으로 수집하고, 관리자 단말(40)까지 지연 없이 정보를 전달해야 함. 특히 빈 급이기통 측정(S220~S234)과 사료 잔량 측정(S250~S285) 프로세스가 분리되어 있어 정교한 상태 동기화가 필요함. |
| **결정(Decision)** | 제어부(140)를 로컬 게이트웨이로 활용하여 1차 데이터를 가공(S270)하고, 사료 잔량 모니터링 서버(20)를 통해 전역적인 정책 관리 및 데이터 분석(S290)을 수행하는 하이브리드 아키텍처를 결정함. |
| **근거(Rationale)** | 센서 데이터의 원시(Raw) 데이터 양이 방대할 수 있으므로 제어부에서 1차 처리를 수행해 네트워크 부하를 줄이고, 서버는 관리 지침(S212) 하달 및 분석에 집중하여 시스템 확장성을 확보하기 위함임. |
| **결과(Consequences)** | (긍정적) 서버 부하 감소 및 실시간 알림(S295) 신뢰성 향상. (부정적) 제어부(140)와 서버(20) 간의 프로토콜 복잡도 증가 및 제어부 하드웨어 사양 상향 필요. |
| **트레이드오프(Trade-offs)** | 로컬 처리 능력을 강화하여 네트워크 의존성을 낮추는 대신, 현장 장치의 유지보수 비용과 소프트웨어 업데이트 복잡성이 증가함. |

## ⚠️ 잠재적 위험 분석

### 1. 통신 장애 시 데이터 정합성 결여
- **설명:** 제어부(140)와 모니터링 서버(20) 간의 네트워크 단절 시, 사료 공급 정보 갱신(S275)과 서버 측 수집 및 관리(S285) 간의 데이터 불일치 발생.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 제어부 내 로컬 스토리지에 데이터를 큐잉(Queuing)하고, 통신 복구 시 시계열 순서에 따라 재전송하는 동기화 메커니즘 구현.

### 2. 센서 오작동으로 인한 잘못된 사료 보급 판단
- **설명:** 원격 센서부(120)의 물리적 오염이나 고장으로 잘못된 측정값(S230, S260)이 전달될 경우, 불필요한 사료 공급 정보가 생성되어 자원 낭비 초래.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 측정값의 급격한 변동을 감지하는 이상치 탐지(Anomaly Detection) 알고리즘을 제어부에 탑재하고, 임계치 초과 시 관리자에게 즉시 확인 요청 발송.

### 3. 관리 지침 동기화 지연 (Race Condition)
- **설명:** 관리자가 단말(40)을 통해 지침을 변경(S240)하는 시점과 제어부(140)가 기존 지침에 따라 측정을 수행하는 시점이 겹쳐 구버전 설정으로 동작할 위험.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 모든 측정 명령에 정책 버전(Policy Version) 태그를 포함하고, 서버 승인이 완료된 정책 버전만 수행하도록 강제하는 버전 관리 프로토콜 적용.

### 4. 제어부(140) 단일 장애점(SPOF) 위험
- **설명:** 현장의 모든 센서 데이터를 취합하고 처리하는 제어부(140) 하드웨어 고장 시 해당 구역의 전체 감시 시스템 마비.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 주요 제어 모듈의 이중화 구성 또는 하드웨어 워치독(Watchdog) 회로를 통한 자동 재시작 및 상태 자가 진단 기능 강화.

### 5. 비인가 장치 등록 및 데이터 위변조
- **설명:** 장치 등록 요청(S200) 과정에서 보안 인증이 취약할 경우, 비인가 장치가 시스템에 접속하여 허위 데이터를 전송하거나 관리 지침을 탈취할 위험.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low
- **대응 방안:** PKI 기반의 기기 인증서 적용 및 모든 통신 구간에 TLS 암호화 적용, 장치 등록 시 관리자(40)의 2차 승인 절차 의무화.
