📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 스마트팜 작물 데이터 파이프라인의 계층적 순차 처리 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                               |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **상황(Context)**        | 스마트팜 환경에서 다수의 IoT 센서로부터 실시간 수집되는 환경 데이터(온도, 습도, 토양, 일조량 등)와 외부 제어 명령이 동시에 유입된다. 이 데이터는 오류 탐지 → 사용자 판단 개입 → 작물 모델링 → 마케팅/출하 전략 반영 → 지역별 관제 데이터 생성이라는 명확한 비즈니스 의존성 체인을 가지므로, 각 단계의 출력이 다음 단계의 입력이 되는 파이프라인 구조가 요구된다.                               |
| **결정(Decision)**       | S21(데이터 수신) → S22(오류 탐지) → S23(사용자 입력 수신) → S24(작물 모델링 데이터 생성) → S25(마케팅·출하 전략 반영) → S26(지역별 관제 데이터 생성)으로 이어지는 **선형 순차(Sequential Pipeline) 처리 아키텍처**를 채택하며, S23 단계에 Human-in-the-Loop(HitL) 인터벤션 포인트를 명시적으로 삽입한다.                               |
| **근거(Rationale)**      | ① 작물 모델링(S24)은 오류가 제거된 신뢰 가능한 데이터와 농업 전문가의 판단(S23)이 선행되어야 정확도를 보장할 수 있다. ② 출하·마케팅 전략(S25)은 모델링 결과에 종속되므로 병렬 처리 시 데이터 정합성 문제가 발생한다. ③ 지역별 관제 데이터(S26)는 전략이 확정된 이후 생성되어야 지역 간 정책 충돌을 방지한다. ④ 농업 도메인의 특성상 AI 예측 오류에 대한 전문가 보정이 법적·품질 책임 측면에서 필수적이다. |
| **결과(Consequences)**   | **긍정적:** 각 단계의 책임이 명확히 분리되어 유지보수성이 향상되고, HitL 구조로 인해 모델 오작동 시 피해 범위가 제한된다. 지역별 관제 데이터가 일관된 전략 기반으로 생성되어 데이터 신뢰성이 확보된다. **부정적:** 선형 구조로 인해 S23의 사용자 응답 지연이 전체 파이프라인 처리량(throughput)의 병목이 되며, 단일 단계 장애 시 하위 전체가 중단될 수 있다.                          |
| **트레이드오프(Trade-offs)** | **얻는 것:** 데이터 정합성, 전문가 개입을 통한 품질 보증, 단계별 감사 추적(audit trail) 가능. **감수하는 것:** 실시간성 저하(latency 증가), 사용자 인터벤션 의존으로 인한 자동화율 한계, 수평 확장(scale-out) 시 단계 간 상태 동기화 복잡도 증가.                                                                                |

⚠️ 잠재적 위험 분석
------------

### 1. Human-in-the-Loop 단계(S23)의 응답 지연에 의한 파이프라인 전체 정지

* **설명:** S23에서 농업 전문가 또는 운영자가 장시간 입력을 제공하지 않을 경우(야간, 휴무, 통신 단절 등), S24 이후 모든 하위 프로세스가 대기 상태에 빠진다. 특히 수확 시기나 병해충 발생 같은 시간 임계적 상황에서 의사결정 지연은 작물 피해로 직결된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** SLA 기반 타임아웃 정책 도입(예: 30분 무응답 시 AI 자동 판단 모드 전환), 다중 승인자(Fallback Approver) 지정, 모바일 푸시 알림 및 에스컬레이션 체계 구축. 자동화 신뢰도 임계값 이상의 케이스는 HitL을 우회하는 Fast-Track 경로 설계.

### 2. S22 오류 탐지 모듈의 오탐(False Positive) 및 미탐(False Negative)

* **설명:** 센서 노이즈, 기기 노화, 극단적 기상 조건 등으로 인해 정상 데이터를 오류로 판정하거나(오탐), 실제 센서 고장·해킹으로 인한 조작 데이터를 정상으로 통과시키는(미탐) 시나리오가 발생한다. 오탐 시 불필요한 S23 개입이 반복되고, 미탐 시 오염된 데이터가 S24 모델링까지 전파되어 잘못된 출하 전략(S25)이 수립된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 이상 탐지 모델의 주기적 재학습(online learning) 파이프라인 구성, 센서 이중화(redundant sensor array) 및 교차 검증 로직 적용, 탐지 결과에 신뢰 구간(confidence interval)을 부착하여 S23에 전달. 미탐 대응을 위한 downstream 데이터 품질 모니터링(data drift detection) 추가.

### 3. 지역별 관제 데이터(S26) 생성 시 개인정보 및 농업 기밀 데이터 유출

* **설명:** S26에서 생성되는 지역별 관제 데이터에는 농가별 생산량, 출하 가격 전략, 작물 모델링 파라미터 등 민감한 경영 정보가 집약된다. 이 데이터가 외부 관제 시스템이나 지자체 포털로 전송되는 과정에서 암호화 미적용, 접근 권한 과다 부여, API 인증 취약점 등으로 경쟁 농가 또는 악의적 행위자에게 노출될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 전송 구간 TLS 1.3 적용 및 저장 데이터 AES-256 암호화 의무화, 역할 기반 접근 제어(RBAC)로 지역/농가 단위 데이터 격리, 개인정보보호법 및 농업 데이터 관련 법령 준수를 위한 데이터 마스킹 처리, 정기적인 침투 테스트(Pen Test) 실시.

### 4. 단일 장애점(Single Point of Failure)으로 인한 전체 시스템 중단

* **설명:** 현재 아키텍처는 S21부터 S26까지 선형 구조로 구성되어 있어 임의의 단일 단계에서 서비스 장애, 프로세스 크래시, 네트워크 단절이 발생하면 이후 모든 단계가 연쇄적으로 중단된다. 스마트팜 환경에서 관개 제어, 환경 조절 등 실시간 액추에이터 제어가 이 파이프라인에 연동되어 있다면 작물 고사 등의 물리적 피해로 이어질 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 각 단계를 독립 마이크로서비스로 분리하고 메시지 큐(Apache Kafka, RabbitMQ)를 통한 비동기 연결로 전환. 각 단계에 Circuit Breaker 패턴 적용, 주요 단계의 Active-Standby 이중화, 장애 발생 시 마지막 성공 상태로 롤백하는 체크포인트(checkpoint) 메커니즘 구현.

### 5. 작물 모델링(S24) AI 모델의 도메인 드리프트(Domain Drift)로 인한 예측 정확도 저하

* **설명:** S24의 작물 모델링은 특정 시점의 학습 데이터로 훈련된 모델을 기반으로 하나, 기후 변화, 신품종 도입, 새로운 병해충 출현 등 환경이 변화함에 따라 모델의 예측 정확도가 점진적으로 저하(concept drift)된다. 탐지되지 않은 드리프트 상태에서 지속 운영 시 S25의 출하 전략이 시장 현실과 괴리되어 재고 손실 및 매출 감소로 이어진다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 모델 성능 지표(RMSE, MAE 등)의 실시간 모니터링 대시보드 구축 및 임계값 초과 시 알림 발송, 계절별 재학습 스케줄링과 신규 데이터를 활용한 증분 학습(incremental learning) 파이프라인 도입. A/B 테스트 기반 모델 챔피언-챌린저 운영 체계 구성.

### 6. 마케팅·출하 전략(S25) 외부 시장 데이터 연동 실패로 인한 전략 오류

* **설명:** S25 단계에서 실시간 농산물 가격, 물류 가용성, 소비자 수요 예측 등 외부 데이터 소스를 참조할 경우, 외부 API 장애, 데이터 지연, 스크래핑 차단 등의 이유로 최신 시장 정보 없이 전략이 수립될 수 있다. 이는 저가 출하로 인한 손실 또는 고가 전략 유지로 인한 재고 적체를 유발한다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 외부 데이터 소스의 캐싱 레이어(Redis 등) 구성으로 일시적 장애 시 최신 유효 데이터 활용, 다중 데이터 소스 폴백(fallback) 체인 구성, 외부 데이터 부재 시 보수적 전략(conservative default)으로 자동 전환하는 규칙 엔진 적용.
