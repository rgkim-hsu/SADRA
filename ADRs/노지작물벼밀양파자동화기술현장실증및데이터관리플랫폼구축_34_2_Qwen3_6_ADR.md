## 노지작물벼밀양파자동화기술현장실증및데이터관리플랫폼구축_34_2

# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 정책 기반의 다중 필터링 및 데이터 클렌징(Data Cleansing) 파이프라인 아키처 도입

| 항목                     | 내용                                                                                                                                                                                                                            |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 환경에서 수집되는 원천 데이터(환경정보, 제어정보, 생육정보 등)는 센서 오류, 통신 지연, 물리적 간섭 등으로 인해 노이즈(오류 데이터, 이상치)가 다수 포함되어 있습니다. 이러한 부정확한 데이터를 그대로 분석이나 제어에 사용할 경우, 잘못된 의사결정이나 시스템 오작동을 초래할 수 있습니다.                                                     |
| **결정(Decision)**       | 원천 데이터를 정제된 데이터로 변환하기 위해 **다단계 검증 및 클렌징 파이프라인(Multi-stage Validation & Cleansing Pipeline)** 아키텍처를 구축합니다. '오류데이터 처리', '갱신주기 이상치 처리', '범위이상치 처리'라는 3개의 핵심 필터링 모듈을 순차적 또는 병렬로 배치하고, 각 모듈은 외부에서 정의된 '데이터 검증 정책'에 따라 동작하도록 설계합니다. |
| **근거(Rationale)**      | 이미지에서 볼 수 있듯이, 단순한 데이터 수집을 넘어 '데이터 검증 데몬'이 상주하며 정책을 기반으로 데이터를 선별합니다. 특히 '연관성 매핑을 통한 사분위수범위(IQR) 검증'과 같은 통계적 알고리즘을 적용함으로써, 단순 임계값 검증으로는 잡아내기 어려운 복합적인 이상 징후를 탐지할 수 있습니다. 이는 데이터의 신뢰성(Data Integrity)을 확보하기 위한 필수적인 전처리 과정입니다.  |
| **결과(Consequences)**   | **긍정적:** 하위 시스템(분석, AI 학습, 자동 제어 등)으로 전달되는 데이터의 품질이 획기적으로 향상되며, 노이즈로 인한 시스템 불안정성이 감소합니다.<br>**부정적:** 검증 로직이 복잡해질수록 데이터 처리 지연(Latency)이 발생할 수 있으며, 잘못된 정책 설정 시 정상 데이터가 폐기될 위험이 있습니다.                                           |
| **트레이드오프(Trade-offs)** | **장점:** 높은 데이터 신뢰성 확보 및 자동화된 품질 관리.<br>**단점:** 실시간 처리 성능 저하 가능성 및 검증 정책 닝에 대한 유지보수 비용 증가.                                                                                                                                     |

---

## ⚠️ 잠재적 위험 분석

### 1. 검증 정책(Policy)의 부적절한 설정으로 인한 데이터 손실

- **설명:** '오류데이터 검증 정책'이나 '범위이상치 정책'이 너무 엄격하게 설정될 경우, 실제 작물 생육에 중요한 이상 징후(예: 급격한 온도 하락)임에도 불구하고 단순 오류로 간주되어 폐기될 수 있습니다. 반대로 너무 느슨하면 노이즈가 정제 데이터로 유입됩니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 정책 설정 시 **동적 임계값(Dynamic Threshold)** 알고리즘을 적용하여 계절이나 작물 생육 주기에 따라 기준을 자동 조정해야 합니다. 또한, 폐기되는 데이터는 '처리결과이력'에 보관하여 주기적으로 검토하는 **Human-in-the-loop** 검증 프로세스를 도입해야 합니다.

### 2. 데이터 처리 지연으로 인한 실시간 제어 실패 (Latency Risk)

- **설명:** '사분위수범위(IQR) 검증'과 같은 통계적 계산이나 '연관성 매핑'은 연산 비용이 높습니다. 대량의 센서 데이터가 유입될 때 검증 파이프라인에서 병목 현상이 발생하면, 실시간으로 반응해야 하는 제어 명령(예: 환기 팬 가동)이 지연될 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 검증 시스템을 **실시간 스트림 처리(Stream Processing)** 아키텍처(예: Apache Kafka, Flink) 기반으로 구축하여 지연을 최소화해야 합니다. 또한, 긴급 제어 신호는 검증 단계를 우회하거나 경량화된 검증만 거치는 **우선순위 큐(Priority Queue)**를 도입해야 합니다.

### 3. 갱신주기 이상치 처리 실패 및 데이터 단절

- **설명:** '갱신주기 이상치 처리' 모듈은 센서 통신 두절이나 지연을 감지합니다. 만약 네트워크 불안정으로 인해 데이터 갱신 주기가 불규칙해질 때, 시스템이 이를 오류로 판단하여 데이터 수신을 차단해버리면, 실제 환경 변화에 대한 모니터링이 끊기는 **데이터 단절(Data Drop)** 현상이 발생할 수 있습니다.
- **심각도:**  Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 갱신 주기 지연 시 즉시 데이터를 버리는 대신, **보간법(Interpolation)**이나 **이전 값 유지(Hold Last Value)** 로직을 적용하여 데이터의 연속성을 유지해야 합니다. 또한 통신 복원 시 누락된 데이터를 재전송 받는 **데이터 동기화 프로토콜**을 구현해야 합니다.

### 4. 이기종 데이터 소스 통합 검증의 복잡성

- **설명:** '환경정보', '제어정보', '생육정보' 등 서로 다른 특성을 가진 데이터에 대해 단일한 검증 정책('데이터 검증 정책')을 적용하기는 어렵습니다. 예를 들어, 온도 데이터의 IQR 기준과 습도 데이터의 기준은 완전히 다릅니다. 이를 통합 관리하지 않으면 정책 관리가 혼재되어 오류가 발생하기 쉽습니다.
- **심각도:**  Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 데이터 타입별(센서 종류별)로 **메타데이터 기반의 정책 템플릿**을 미리 정의하고, 데이터 수집 시 메타태그를 통해 자동으로 적합한 검증 정책을 매핑하는 **정책 엔진(Policy Engine)**을 도입해야 합니다.

### 5. 처리결과이력(Processing Log) 관리 미흡으로 인한 디버깅 곤란

- **설명:** 시스템에서 '처리결과이력'을 저장한다고 명시되어 있으나, 만약 이 로그에 '왜' 해당 데이터가 제거되었는지(어떤 정책의 어떤 조건에 위배되었는지)에 대한 상세 정보가 누락된다면, 향후 시스템 오작동 시 원인을 추적하기가 매우 어려워집니다.
- **심각도:** 🟢 Low
- **발생 가능성:**  Medium
- **대응 방안:** 처리결과이력 저장 시 **원본 데이터**, **적용된 정책 ID**, **검증 실패 사유**, **타임스탬프**를 패키지로 저장하여 완전한 **監査 추적(Audit Trail)**이 가능하도록 설계해야 합니다.
