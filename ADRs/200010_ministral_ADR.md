## 📋 ADR (Architecture Decision Record)

### **ADR-001: 중앙 데이터 통합 플랫폼(dataPARC) 기반의 다계층 시스템 아키텍처 채택**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 제조 현장(MES), 품질 관리(LIMS), 기업 자원 관리(ERP) 등 다수 시스템이 독립적으로 운영되면서 데이터 중복, 일관성 부족, 실시간 통합 어려움 등의 문제가 발생. 특히 스마트팜/스마트공장 환경에서는 센서 데이터, 운영 로그, 수동 입력 데이터의 통합 및 실시간 분석이 필수적임. |
| **결정(Decision)** | 중앙 데이터 통합 플랫폼 **dataPARC**를 핵심으로 하는 **다계층 아키텍처** 채택. 주요 컴포넌트 간 데이터 흐름을 **OPC/SQL/API 인터페이스**로 표준화하고, **Data Historian**를 통해 시간-series 데이터 관리, **MDE(Manual Data Entry)**를 보완하여 유연성 확보. |
| **근거(Rationale)** | 1. **ISO/IEC 30141:2024** 표준에 따라 **모듈화된 아키텍처**를 통해 확장성 및 상호운용성 확보<br>2. **oneM2M/ETSI EN 303 645** 준수하여 보안 및 데이터 통합 프로토콜(CoAP, MQTT, OPC UA) 활용<br>3. **TTA 스마트팜 표준**과 연계하여 농업/제조 데이터 통합 프레임워크 구축<br>4. **Data Historian**을 통해 **시간-series 데이터** 분석 및 재사용성 향상 |
| **결과(Consequences)** | ✅ **장점**: 데이터 일관성 향상, 실시간 분석 가능, 시스템 확장성 및 유지보수 용이<br>❌ **단점**: 초기 구축 비용 증가, 인터페이스 표준화 작업 필요, 보안 관리 복잡성 증가 |
| **트레이드오프(Trade-offs)** | - **성능 vs. 복잡성**: 중앙 플랫폼으로 인한 네트워크 부하 증가 vs. 데이터 일관성 향상<br>- **비용 vs. 효율성**: 초기 구축 비용 증가 vs. 장기적 데이터 활용 효율성<br>- **보안 vs. 유연성**: 표준화된 인터페이스 vs. 수동 데이터 입력(MDE) 보완 필요 |

### **ADR-002: OPC UA 프로토콜 기반의 실시간 데이터 통신 표준화**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 제조 장비(OSI, Siemens, ABB 등)에서 발생하는 실시간 데이터(온도, 압력, 생산 로그 등)를 효율적으로 수집해야 함. 기존 프로토콜의 호환성 문제 및 보안 취약성으로 인해 표준화된 통신 프로토콜이 필요함. |
| **결정(Decision)** | **OPC UA** 프로토콜을 **dataPARC와 장비 간 통신 표준**으로 채택. **TLS 1.3** 기반 보안 인증 및 **MQTT**를 보조 프로토콜로 활용하여 경량 통신 지원. |
| **근거(Rationale)** | 1. **IEEE 2413** 및 **ISO/IEC 62541** 표준 준수<br>2. **ITU-T X.1352** 보안 요구사항 충족<br>3. **Siemens, ABB, Honeywell** 등 주요 장비 벤더의 OPC UA 지원 현황<br>4. **Matter/OCF**와 유사한 상호운용성 프레임워크 제공 |
| **결과(Consequences)** | ✅ **장점**: 실시간 데이터 수집 가능, 보안 강화, 장비 간 상호운용성 향상<br>❌ **단점**: 기존 시스템 변경 비용 발생, 네트워크 대역폭 요구 증가 |
| **트레이드오프(Trade-offs)** | - **호환성 vs. 성능**: OPC UA의 보안 강도 vs. MQTT의 경량성 활용<br>- **초기 비용 vs. 장기적 이점**: 프로토콜 변경 비용 vs. 표준화 이점 |

### **ADR-003: SQL/API 인터페이스 기반의 다중 시스템 연계**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | MES, ERP, LIMS 등 **다수 시스템이 독립적으로 운영**되면서 데이터 동기화 지연 및 불일치 발생. 특히 **스마트팜 환경**에서는 센서 데이터와 ERP 시스템 간의 실시간 연계가 필수적임. |
| **결정(Decision)** | **dataPARC**를 통해 **SQL(MES, LIMS) 및 RESTful API(ERP)** 인터페이스를 표준화. **ETL 프로세스**를 통해 데이터 변환 및 일괄 처리 지원. |
| **근거(Rationale)** | 1. **ISO/IEC 30141:2024**의 **데이터 통합 패턴** 준수<br>2. **oneM2M**의 API 표준화 사례 참조<br>3. **TTA 스마트팜 표준**에서 제안하는 **데이터 상호운용 프레임워크** 적용<br>4. **Excel/WIS 등 Legacy 시스템**과의 호환성 확보 |
| **결과(Consequences)** | ✅ **장점**: 데이터 일관성 향상, 시스템 간 연계 용이<br>❌ **단점**: ETL 프로세스 관리 복잡성, API 버전 호환성 문제 가능성 |
| **트레이드오프(Trade-offs)** | - **실시간성 vs. 일괄 처리**: API를 통한 실시간 연계 vs. SQL 기반 일괄 처리<br>- **유연성 vs. 복잡성**: 다중 인터페이스 지원 vs. 관리 복잡성 |

## ⚠️ 잠재적 위험 분석

### **1. 데이터 일관성 부재**
- **설명**: MES, ERP, LIMS 등 다수 시스템에서 **동일한 데이터가 중복 저장**되거나 **동기화 지연**으로 인해 불일치 발생. 특히 **스마트팜 환경**에서 센서 데이터와 운영 로그의 불일치로 인해 의사 결정 오류 발생 가능성.
- **심각도**: 🔴 High | **발생 가능성**: 🔴 High
- **대응 방안**:
  - **Data Historian**을 통해 **시간-series 데이터 버전 관리** 도입.
  - **Change Data Capture(CDC)** 기술을 활용한 실시간 동기화 구현.
  - **데이터 검증 스크립트**를 통해 일관성 확인 자동화.

### **2. 보안 취약성**
- **설명**: **OPC UA/MQTT** 프로토콜 및 **API 인터페이스**가 공격 표적이 될 수 있으며, **수동 데이터 입력(MDE)** 과정에서 인증 오류 발생 가능성. 특히 **스마트팜 환경**에서는 장비 해킹으로 인한 생산 중단 위험 존재.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **TLS 1.3 + OPC UA 보안 프로필** 적용.
  - **API 게이트웨이**를 통해 접근 통제 강화.
  - **KISA 보안 기준(ITU-T X.1352)** 준수한 **IoT 기기 인증** 시스템 구축.

### **3. 시스템 확장성 제한**
- **설명**: **dataPARC**가 **단일 노드 장애**로 인해 전체 시스템이 중단될 수 있으며, **수평 확장**이 어렵게 설계될 경우 성능 병목 발생 가능성.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **마이크로 서비스 아키텍처**로 분산 처리 지원.
  - **Kubernetes**를 활용한 **오토스케일링** 구현.
  - **Multi-Region 배포**를 통한 고가용성 확보.

### **4. 인터페이스 호환성 문제**
- **설명**: **Legacy 시스템(Excel, WIS)** 및 **다양한 장비 벤더(OSI, Siemens, ABB)** 간의 프로토콜 호환성 문제로 인해 데이터 수집 실패 또는 변환 오류 발생 가능성.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **프로토콜 어댑터** 개발을 통해 호환성 보장.
  - **API 버전 관리 정책** 수립.
  - **TTA 표준**에 따른 **인터페이스 규격** 정기 검증.

### **5. 운영 및 유지보수 복잡성**
- **설명**: **다중 시스템 연계** 및 **실시간 데이터 처리**로 인해 **운영 복잡성** 증가. 특히 **MDE(Manual Data Entry)**와 같은 수동 프로세스가 오류를 유발할 수 있음.
- **심각도**: 🟡 Medium | **발생 가능성**: 🔴 High
- **대응 방안**:
  - **자동화 도구**를 통해 MDE 최소화.
  - **AI 기반 이상치 감지** 시스템 도입.
  - **운영 팀 교육 프로그램**을 통한 오류 예방.
