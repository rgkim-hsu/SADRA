# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 이기종 IoT 데이터를 수용하기 위한 이벤트 기반 통합 메시징 레이어 도입

| 항목 | 내용 |
| :--- | :--- |
| **상황(Context)** | 본 시스템은 센서, 환경 제어기, 데이터 수집 장치 등 광범위하고 이질적인(Heterogeneous) 물리적 소스로부터 다양한 프로토콜(MQTT, CoAP, Modbus 등)과 데이터 형식을 통해 데이터를 수집합니다. 이종 데이터가 서버의 단일 데이터베이스 구조에 직접 통합될 경우, 시스템의 확장성이 심각하게 저해되고, 새로운 센서나 규격의 장비를 추가할 때마다 백엔드 로직 수정이 필수적으로 발생합니다. |
| **결정(Decision)** | 서버 백엔드와 물리적 데이터 소스 사이에 **메시지 브로커(Message Broker) 기반의 이벤트 기반 아키텍처(EDA)**를 필수적으로 도입하고, 모든 데이터를 공통의 **이벤트/메시지 표준화 스키마**로 변환하여 처리하도록 결정합니다. |
| **근거(Rationale)** | 1. **디커플링(Decoupling):** 데이터 소스(Publisher)와 비즈니스 로직(Subscriber)을 분리하여, 특정 소스 변경이 전체 시스템에 미치는 영향을 최소화합니다. 2. **비동기성 및 확장성:** 대량의 실시간 시계열 데이터를 안정적으로 처리하고, 수많은 센서 및 장치 연결 증가에 유연하게 대처할 수 있습니다. 3. **상호운용성(Interoperability):** 표준화된 메시징 계층(예: 표준 토픽/스키마)을 사용함으로써, 국내외 표준(ISO/IEC 30141 등)에서 요구하는 데이터 교환의 일관성을 확보할 수 있습니다. |
| **결과(Consequences)** | **[긍정적]** 시스템이 모듈화되고 확장성이 극대화되며, 새로운 농장 환경(예: 수경재배 $\rightarrow$ 스마트 온실)에 빠르게 적응할 수 있는 범용적인 플랫폼 구조를 갖게 됩니다. **[부정적]** 초기 설계 단계에서 메시지 브로커, 스키마 관리 서비스 등 복잡한 분산 시스템 컴포넌트를 구축하고 관리해야 하므로 개발 난이도와 초기 구축 비용이 매우 높아집니다. |
| **트레이드오프(Trade-offs)** | **[획득 장점]** 높은 확장성, 낮은 결합도, 뛰어난 이기종 데이터 통합 능력. **[감수 단점]** 시스템 구조의 복잡성 증가, 실시간 데이터 처리를 위한 고성능 인프라 및 전문적인 운영 인력(DevOps) 필요. |

---

## ⚠️ 잠재적 위험 분석

### 1. 데이터 표준화 및 온톨로지 불일치 위험
- **설명:** 농장 정보, 재배 정보, 환경 제어기 등 각 컴포넌트가 사용하는 센서 데이터의 이름, 단위, 측정 방식(예: '온도'를 센서 A는 섭씨, 센서 B는 화씨로 제공)이 통일되지 않아, 서버가 통합된 의미를 파악하지 못하고 잘못된 제어 명령을 내릴 위험.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 시스템 초기에 **데이터 온톨로지(Ontology) 레이어**를 구축하여 모든 측정값을 표준화된 개념 모델(Concept Model)로 매핑하는 전용 ETL(Extract, Transform, Load) 서비스를 도입하고, 모든 데이터 입력을 필수로 이 온톨로지를 거치도록 강제해야 합니다.

### 2. 원격 통신 및 네트워크 불안정성 위험
- **설명:** 스마트팜은 외곽이나 지하 등 전력 및 네트워크 인프라가 불안정한 환경에 위치합니다. 광역 네트워크 장애나 단절 발생 시, 데이터가 서버에 도달하지 않아 실시간 모니터링 및 자율 제어(예: 양액 공급, 급수 제어)가 지연되거나 중단되는 위험.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 시스템 아키텍처에 **에지 컴퓨팅(Edge Computing)** 게이트웨이를 도입하여, 서버와의 통신이 단절되었을 때도 게이트웨이 자체에서 미리 정의된 비상 로직(Fail-Safe Logic)을 실행하여 최소한의 환경 제어 기능을 자율적으로 유지하도록 설계해야 합니다.

### 3. 사이버 보안 취약점 위험 (엣지/디바이스 레벨)
- **설명:** 농장 현장의 센서, 액추에이터, PLC 등 물리적 장비(IoT 디바이스)는 물리적 접근이 용이하고 보안 기능이 취약한 경우가 많습니다. 해커가 이 낮은 보안성의 엣지 장비 중 하나를 침투점으로 삼아 네트워크 전체를 장악하거나, 센서 데이터를 위변조하여 오작동을 일으킬 위험.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 모든 엣지 디바이스에 **하드웨어 기반의 보안 모듈(TPM 또는 TrustZone)**을 적용하고, 데이터 통신 시 강력한 암호화 프로토콜(TLS/DTLS)을 강제하며, 네트워크 세그멘테이션(VLAN 또는 네트워크 격리)을 통해 제어망과 통신망을 물리적으로 분리해야 합니다.

### 4. 데이터 폭증 및 처리 부하 위험
- **설명:** 스마트팜은 수백, 수천 개의 센서가 초당 수십 건 이상의 시계열 데이터(Time-Series Data)를 끊임없이 발생시키는 특성을 갖습니다. 이 데이터의 폭증을 백엔드 시스템이 감당하지 못하여, 데이터베이스 병목 현상, 서비스 지연, 혹은 시스템 전체 다운을 초래할 위험.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 데이터 저장 및 처리를 위해 전통적인 관계형 데이터베이스(RDBMS) 대신 **시계열 데이터베이스(Time-Series Database, 예: InfluxDB, TimescaleDB)**를 전용으로 채택하고, 데이터의 전처리(Pre-processing)를 통해 노이즈 제거 및 아웃라이어 필터링을 백엔드에 구현하여 데이터베이스 부하를 최소화해야 합니다.

### 5. 사용자 접근 통제 및 권한 위임 문제
- **설명:** 스마트팜은 사용자(관리자, 연구원, 현장 작업자 등)의 역할이 다양합니다. 만약 사용자 계정 관리 및 접근 권한(Role-Based Access Control, RBAC)이 명확하게 정의되지 않는다면, 일반 사용자가 민감한 제어 파라미터(예: 양액 농도 설정)를 임의로 변경하거나 중요한 농장 데이터에 접근할 위험.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
