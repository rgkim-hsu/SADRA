## 📋 ADR (Architecture Decision Record)

### ADR-001: 이벤트 기반 통합 계층 아키텍처(Event-Driven Integration Layer Architecture) 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 작업자(`sf_worker`)의 활동, 장비(`sf_machine`)의 물리적 상태, 그리고 환경 변화(`sf_event`)라는 세 가지 이질적이고 시간에 따라 변화하는(Temporal) 데이터를 하나의 일관된 작업 흐름(`sf_workplan`)으로 통합해야 합니다. 전통적인 CRUD 기반의 관계형 데이터베이스 모델로는 실시간으로 발생하는 다양한 데이터 소스(IoT, 사람, ERP 등) 간의 복잡한 인과 관계(Causality) 및 상태 추적을 효율적으로 처리하는 데 한계가 있습니다. |
| **결정(Decision)** | 시스템의 백엔드 아키텍처를 마이크로 서비스 기반의 이벤트 스트리밍 및 메시지 브로커(예: Kafka)를 활용하는 이벤트 주도 아키텍처(EDA)로 설계합니다. 모든 주요 엔티티 변화(Worker Check-in, Machine Status Change, Work Plan Update 등)는 이벤트(Event)로 발행되고, 이를 수집하는 스트림 프로세서(Stream Processor)가 핵심 비즈니스 로직을 처리합니다. |
| **근거(Rationale)** | 1. **비동기적 데이터 처리:** 서로 다른 속도와 주기를 가진 이질적인 소스(IoT 센서 vs. 사람의 기록)의 데이터를 병렬적으로 수집하고, 지연 시간이 발생하는 상황에서도 시스템의 안정성을 유지합니다. 2. **상태 추적(State Management):** 모든 작업 요청과 실행 결과를 이벤트를 통해 기록함으로써, '누가(Worker)' '언제(Time)' '무엇을(Work Plan)' 시도했고, 그 결과 '무슨 일이(Event)' 발생했는지에 대한 불변의(Immutable) 감사 로그를 쉽게 구축할 수 있습니다. 3. **확장성:** 새로운 데이터 소스(예: 추가적인 모니터링 장비)가 추가되어도, 기존의 코드를 수정하는 대신 새로운 이벤트 리스너만 추가하여 시스템을 확장할 수 있습니다. |
| **결과(Consequences)** | **긍정적:** 높은 유연성과 확장성 확보. 실시간성이 요구되는 작업 상태 추적 및 이상 감지 기능 구현에 최적화됨. **부정적:** 아키텍처의 복잡도가 매우 높아지며, 데이터 흐름 전체에 대한 전용 모니터링 및 운영 인력이 필수적입니다. 트랜잭션 관리(ACID)가 어려워지므로, 최종 일관성(Eventual Consistency) 모델을 받아들여야 합니다. |
| **트레이드오프(Trade-offs)** | **[획득 장점]** 높은 가용성(High Availability)과 탄력적 확장성(Elastic Scalability)을 확보하여, IoT 대용량 스트리밍 데이터 처리에 최적화됩니다. **[감수 단점]** 데이터베이스 트랜잭션의 원자성(Atomicity)을 보장하기 어려워지며, 데이터 흐름의 흐름(Flow)을 파악하고 디버깅하는 것이 매우 복잡해집니다. |

## ⚠️ 잠재적 위험 분석

### 1. 이기종 데이터 통합 및 상호운용성 위기 (Interoperability Failure)
- **설명:** `sf_machine`이나 현장의 센서(IoT Device)들은 제조사별로 상이한 통신 프로토콜(MQTT, CoAP, HTTP 등)과 데이터 포맷을 사용합니다. 이질적인 데이터가 `sf_event`로 통합되는 과정에서 데이터 형식 불일치(Schema Mismatch)나 프로토콜 호환성 문제가 발생하여, 핵심 비즈니스 로직이 오작동할 위험이 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** **IoT 게이트웨이 및 메시지 브로커 계층(Edge/Fog Layer)**을 필수적으로 도입하여, 모든 외부 데이터를 표준화된 내부 메시지 형식(예: JSON Schema)으로 변환하는 **데이터 변환 레이어(Adaptor/Converter)**를 강제합니다. 표준화된 데이터 포맷을 중앙 레지스트리(Schema Registry)에 관리해야 합니다.

### 2. 작업 상태의 동시성 제어 및 데이터 무결성 위협 (State Inconsistency)
- **설명:** 여러 작업자(`sf_worker`)가 동시에 하나의 작업계획(`sf_workplan`)에 대해 작업 요청을 수정하거나, 하나의 장비(`sf_machine`)가 동시에 여러 종류의 이벤트를 보고할 경우, 시스템이 작업의 최신 상태를 일관되게 유지하지 못하는 상태 불일치(Race Condition)가 발생할 수 있습니다. 이는 작업 결과의 신뢰도를 근본적으로 훼손합니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 핵심 엔티티(예: `sf_workplan`)에 대한 업데이트는 낙관적 잠금(Optimistic Locking) 메커니즘을 적용하여 동시 접근을 제어합니다. 또한, 모든 상태 변경은 **CQRS (Command Query Responsibility Segregation)** 패턴을 적용하여, 상태 변경(Command) 로직과 조회(Query) 로직을 분리하고, 모든 상태 변화는 불변의 이벤트를 기록하도록 설계합니다.

### 3. 물리적-사이버 보안 경계 붕괴 위험 (Physical-Cyber Security Breach)
- **설명:** 시스템이 작업자(사람의 접근), 장비(IoT), 그리고 작업 계획(비즈니스 로직)을 모두 연결하고 있으므로, 한 곳에서 취약점이 발견될 경우 전체 시스템에 연쇄적인 장애나 오작동(예: 장비의 원격 조작을 통한 시스템 마비)이 발생할 수 있습니다. 특히, IoT 기기 자체가 보안 패치가 어려운 경우가 많아 공격 표면(Attack Surface)이 광범위합니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 시스템 경계를 *물리적* 영역과 *정보적* 영역으로 분리하고, **Zero Trust Architecture (ZTA)**를 적용합니다. 모든 장치와 사용자 요청에 대해 망 내부 여부와 관계없이 최소 권한 원칙(Principle of Least Privilege)에 따라 접근을 인증하고 세분화된 정책 기반 접근 제어(Policy-Based Access Control)를 구현합니다.

### 4. 데이터 거버넌스 및 개인정보 침해 위험 (Data Governance & Privacy)
- **설명:** 시스템이 작업자 정보(`sf_worker`)와 작업 결과(`sf_event`)를 상세히 추적하기 때문에, 작업자의 이동 경로, 활동 패턴, 성과 등에 대한 민감한 개인 식별 정보(PII)가 대규모로 축적됩니다. 이 데이터가 부적절하게 활용되거나 유출될 경우, 법적 문제(예: GDPR, 개인정보보호법 위반)를 야기할 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 데이터 수집 단계부터 **Privacy by Design** 원칙을 적용합니다. 민감한 PII는 수집과 동시에 **익명화(Anonymization)** 또는 **가명화(Pseudonymization)** 처리하며, 접근 권한을 역할별(Role-Based Access Control, RBAC)로 엄격하게 분리하고, 데이터 보유 및 삭제 정책(Retention Policy)을 명확히 수립하여 컴플라이언스를 유지해야 합니다.

### 5. 시스템 복잡도 및 기술 부채 누적 위험 (Complexity and Technical Debt)
- **설명:** 엔티티가 너무 많은 수의 관계(Worker $\to$ WorkPlan $\to$ Machine $\to$ Tag...)로 엮여있고, EDA 패턴을 사용함으로써 시스템 자체가 고도로 복잡해집니다. 초기에는 높은 기능성을 확보했더라도, 비전문가가 시스템의 특정 부분을 수정하거나 새로운 기능을 추가할 경우, 전체 시스템 흐름을 파악하지 못해 예상치 못한 버그를 발생시키거나 유지보수 비용이 폭발적으로 증가할 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
