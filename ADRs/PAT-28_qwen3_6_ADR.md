## PAT-28

# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 모듈화된 제어부 기반의 실시간 설비 제어 및 통합 모니터링 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                                                                                         |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 시스템은 실시간으로 설비를 제어하고 모니터링해야 하는 동시에, 제어량 분석, 노이즈 모니터링, 원격 통신, 리포트 제공 등 다양한 부가 기능을 수행해야 함. 단일 프로세스에서 모든 기능을 처리할 경우, 분석이나 리포트 생성과 같은 CPU/IO 집약적 작업이 실시간 제어 신호 처리에 지연(Latency)을 유발하여 설비 오작동이나 안전 사고로 이어질 수 있는 아키텍처적 과제가 존재함.                                                                                                    |
| **결정(Decision)**       | `제어부(120)` 내부에 기능을 명확히 분리한 6개의 하위 모듈(`실시간 설비 제어 모니터링 120a`, `제어량 분석 120b`, `알람 표시 120c`, `노이즈 모니터링 120d`, `원격 통신 제어 120e`, `리포트 제공 120f`)을 배치하는 **모듈형 제어 아키텍처**를 채택함. 또한, 제어 전용 인터페이스(`제어용 I/O IF 130`)를 분리하여 실시간 제어 신호의 우선순위를 보장함.                                                                                        |
| **근거(Rationale)**      | 1. **실시간성 보장:** `실시간 설비 제어 모니터링 모듈(120a)`을 독립적으로 구성하고, `제어용 I/O IF(130)`를 통해 직접적인 데이터 경로를 확보함으로써 분석 모듈(120b, 120d)의 부하와 무관하게 고속 제어가 가능함.<br>2. **유지보수성:** `노이즈 모니터링(120d)`이나 `리포트 제공(120f)`과 같은 기능의 알고리즘 변경이 다른 모듈에 영향을 주지 않도록 결합도를 낮춤.<br>3. **통합 관리:** 음성 입출력 장치(160)와 원격 통신(120e)을 중앙 제어부에서 통합 관리하여 사용자 인터페이스 일관성을 확보함. |
| **결과(Consequences)**   | 시스템의 신뢰성과 실시간 제어 성능이 향상되며, 기능 추가나 수정 시 영향 범위가 국소화됨. 반면, 모듈 간 데이터 공유(예: 분석 결과를 알람 모듈로 전달)를 위한 내부 통신 오버헤드가 발생하고, 제어부(120)의 전체적인 복잡도가 증가함.                                                                                                                                                                                    |
| **트레이드오프(Trade-offs)** | 실시간 제어 안정성 및 모듈별 독립성 확보 vs. 모듈 간 통신 복잡도 증가 및 제어부(120) 내 리소스 할당 관리의 어려움.                                                                                                                                                                                                                                                    |

---

## ️ 잠재적 위험 분석

### 1. 제어부(120) 내 리소스 경합으로 인한 실시간 제어 지연

- **설명:** `제어량 분석 및 표시 모듈(120b)`이나 `노이즈 모니터링 분석 모듈(120d)`이 대량의 데이터를 처리하거나 복잡한 계산을 수행할 때, CPU나 메모리 리소스를 과도하게 점유하여 `실시간 설비 제어 모니터링 모듈(120a)`의 실행 주기(Task Cycle)가 늦어질 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 실시간 제어 모듈(120a)에 highest priority 스케줄링 적용, 분석 모듈(120b, 120d)을 별도의 스레드나 코어에 할당하여 리소스 격리(Resource Isolation) 수행, 또는 실시간 OS(RTOS) 도입 검토.

### 2. 데이터베이스(150) I/O 병목 현상

- **설명:** `알람 표시 및 기록 모듈(120c)`이 빈번한 알람을 기록하거나 `리포트 제공 모듈(120f)`이 대용량 리포트를 저장하기 위해 `데이터베이스(150)`에 접근할 때, Disk I/O 병목이 발생하면 제어부(120) 전체의 응답성이 저하될 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 비동기 로깅(Asynchronous Logging) 방식을 채택하여 제어 로직과 DB 저장을 분리, 고속 SSD 또는 인메모리 데이터베이스(Redis 등)를 캐싱 계층으로 도입, 배치 처리(Batch Processing)를 통한 DB 쓰기 최적화.

### 3. 원격 통신 제어 모듈(120e) 보안 취약점

- **설명:** `원격 통신 제어 모듈(120e)`과 `송수신부(140)`를 통해 외부에서 제어 명령이 유입될 수 있으므로, 인증/인가 절차가 미흡하거나 통신 암호화가 취약할 경우 악의적인 제3자가 설비를 원격으로 조작할 수 있는 위험이 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 원격 접속 시 강력한 인증(MFA) 및 권한 검증 적용, TLS/SSL 통신 암호화 필수 적용, 비정상적인 제어 패턴(예: 급격한 설정값 변경) 감지 시 자동 차단 및 관리자 알림 기능 구현.

### 4. 노이즈 모니터링 오탐(False Positive)으로 인한 시스템 오작동

- **설명:** `노이즈 모니터링 분석 모듈(120d)`이 환경적 소음을 설비 이상 소음으로 잘못 판단할 경우, `알람 표시 및 기록 모듈(120c)`을 통해 불필요한 알람을 발생시키거나, 심지어 `실시간 설비 제어 모니터링 모듈(120a)`로 하여금 비상 정지 등의 과도한 제어를 유발할 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 노이즈 분석 알고리즘에 머신러닝 기반의 패턴 인식을 적용하여 정확도 향상, 알람 발생 전 확인 단계(Debounce logic) 도입, 알람 임계값을 동적으로 조정할 수 있는 관리자 설정 기능 제공.

### 5. 음성 입출력 장치(160) 통합으로 인한 제어부 부하 증가

- **설명:** `음성입출력장치(160)`와의 실시간 음성 처리(인식 및 합성)는 높은 컴퓨팅 파워를 요구함. 이를 `제어부(120)`가 직접 처리할 경우, 음성 처리 부하가 실시간 제어 성능을 저하시킬 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:**  Low
- **대응 방안:** 음성 처리 기능을 외부 전용 서버나 엣지 디바이스로 오프로드(Offloading)하는 구조로 변경, 또는 제어부(120) 내에 음성 처리 전용 가속 (DSP/NPU)을 도입하여 제어 리소스와 분리.
