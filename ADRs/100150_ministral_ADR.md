## 📋 ADR (Architecture Decision Record)

### ADR-001: **IoT 기반 스마트 재배 시스템의 데이터 획득 및 결정 프로세스 표준화**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 토양/기상 데이터 획득부터 재배 방법 결정까지의 **엔드투엔드 프로세스**를 처리해야 하며, 이를 위해 **국내외 IoT 표준(ISO/IEC 30141:2024, oneM2M, ITU-T X.1352)**과의 호환성을 보장해야 함. 특히, **데이터 획득 → 처리 → 결정 → 송신**의 흐름은 실시간성, 신뢰성, 보안을 요구하는 스마트팜 환경에 최적화되어야 함. |
| **결정(Decision)** | 1. **데이터 획득 단계(S1001)**: 토양/기상 센서 데이터는 **MQTT 프로토콜**을 통해 수집하며, **ISO/IEC 27030:2020** 보안 가이드라인을 준수하여 암호화된 통신 채널을 구축함.<br>2. **재배 방법 결정(S1003)**: 결정 로직은 **Edge Computing** 환경에서 처리하여 클라우드 의존도를 줄이고, **TTA 스마트팜 표준**에 따라 정의된 알고리즘을 적용함.<br>3. **결과 송신(S1004)**: 결정된 재배 방법은 **oneM2M API**를 통해 농부용 모바일 앱과 IoT 장치로 실시간으로 전송함. |
| **근거(Rationale)** | - **MQTT 프로토콜**: IoT 환경의 **저용량, 실시간 통신** 요구에 최적화되어 있음.<br>- **Edge Computing**: 네트워크 지연과 클라우드 비용을 줄이며, **데이터 지역성**을 보장함.<br>- **oneM2M API**: **국내외 상호운용성**을 보장하며, TTA 표준과 호환됨.<br>- **ISO/IEC 27030**: **보안 취약점**을 사전에 방지함. |
| **결과(Consequences)** | ✅ **장점**: 실시간 데이터 처리, 보안 강화, 표준 준수, 운영 비용 절감.<br>❌ **단점**: Edge 노드 추가로 초기 구축 비용 증가, MQTT 프로토콜의 **복잡한 보안 설정** 필요. |
| **트레이드오프(Trade-offs)** | - **Edge vs. Cloud**: Edge는 지연 시간 단축과 보안 강화로 이점이 있지만, 초기 하드웨어 비용이 발생함.<br>- **MQTT vs. HTTP**: MQTT는 효율적이나, 보안 설정 복잡성이 증가함.<br>- **표준 준수**: oneM2M/ISO 준수는 상호운용성을 높여주지만, 구현 복잡성을 증가시킴. |

### ADR-002: **스마트팜 시스템의 보안 아키텍처 결정**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 시스템은 **사이버 공격(DoS, 데이터 변조, 인증 우회)**에 취약하며, **ETSI EN 303 645**와 **ITU-T X.1352**를 준수하여 **기기 수준부터 클라우드까지의 보안 체계를 구축**해야 함. |
| **결정(Decision)** | 1. **데이터 암호화**: 센서 데이터는 **AES-256**으로 암호화하여 전송, 저장 시 **KISA 기준**에 따라 키 관리 수행.<br>2. **인증/인가**: **OAuth 2.0 + JWT**를 사용하여 장치 및 사용자 인증, **Matter 표준**과 호환되는 인증 모듈 사용.<br>3. **네트워크 보안**: **SDN(Software-Defined Networking)**을 도입하여 트래픽 모니터링 및 이상 탐지 시스템 구축. |
| **근거(Rationale)** | - **AES-256**: 현재 **최고 수준의 대칭 키 암호화**로 인정받음.<br>- **OAuth 2.0**: **표준화된 인증 프레임워크**로 보안 및 확장성을 제공함.<br>- **SDN**: **실시간 네트워크 모니터링**을 가능하게 함. |
| **결과(Consequences)** | ✅ **장점**: **고도화된 보안**, 국제 표준 준수, 공격 탐지 및 대응 강화.<br>❌ **단점**: **복잡한 키 관리** 및 **SDN 구축 비용** 증가. |
| **트레이드오프(Trade-offs)** | - **암호화 성능 vs. 보안**: AES-256는 성능 저하를 초래할 수 있지만, 현재 최적의 선택임.<br>- **OAuth 2.0**: 확장성이 우수하지만, **토큰 관리** 복잡성 증가. |

## ⚠️ 잠재적 위험 분석

### 1. **데이터 일관성 및 중복 문제**
- **설명**: 센서 데이터가 **다중 소스에서 중복 수집**되거나 **일관성 없는 포맷**으로 처리될 경우, 재배 결정 로직이 오류를 발생시킬 수 있음.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **데이터 스키마 표준화**: 모든 센서 데이터는 **ISO/IEC 30141:2024** 정의된 공통 스키마에 맞춰 수집함.
  - **데이터 베이스 레플리카**: **PostgreSQL**를 사용하여 트랜잭션 일관성을 보장함.
  - **ETL 프로세스**: **Apache NiFi**를 사용하여 데이터 클렌징 및 중복 제거 자동화.

### 2. **Edge 노드 장애로 인한 시스템 중단**
- **설명**: Edge 노드에서 **소프트웨어/하드웨어 장애**가 발생하면, 실시간 재배 결정이 중단되어 농작물 손실을 초래할 수 있음.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **고가용성 클러스터**: Edge 노드는 **Kubernetes**를 사용하여 **자동 복구** 및 **로드 밸런싱** 구현.
  - **오프라인 처리 모드**: Edge 노드 장애 시, **로컬 캐시**를 사용하여 일시적 처리 계속 가능하게 함.
  - **모니터링 시스템**: **Prometheus + Grafana**를 사용하여 실시간 장애 감지 및 알림 시스템 구축.

### 3. **보안 취약점 및 compliance 위반**
- **설명**: **기기 인증 실패**나 **데이터 암호화 미준수**로 인해 **ETSI EN 303 645** 또는 **KISA 기준**을 위반할 경우, 법적 제재 및 시스템 신뢰성 하락 발생 가능.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **정기 보안 감사**: ** quarterly**로 **OWASP ZAP**을 사용하여 취약점 스캔 수행.
  - **자동화된 compliance 체크**: **OpenSCAP**을 사용하여 시스템 구성이 표준을 준수하는지 자동 검증.
  - **인증 모듈 업데이트**: **Matter 표준**에 따라 **quarterly**로 인증 라이브러리 패치 적용.

### 4. **표준 호환성 문제**
- **설명**: **국내외 표준(oneM2M, ISO, Matter)** 간의 호환성 부족으로 인해, **신규 장치 또는 소프트웨어 업데이트** 시 시스템 통합에 실패할 수 있음.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **표준 호환성 테스트**: 모든 신규 컴포넌트는 **TTA 인증된 테스트Bed**에서 호환성 검증 수행.
  - **API 게이트웨이**: **Kong**를 사용하여 표준별 API 변환 및 중계 기능 제공.
  - **백워드 호환성 설계**: 시스템 아키텍처는 **최소 5년 동안** 기존 표준을 지원할 수 있도록 설계함.

### 5. **사용자 인터페이스(UX) 복잡성**
- **설명**: 농부들이 **재배 방법 결정 결과**를 이해하기 어려우면, 시스템 활용도가 저하될 수 있음.
- **심각도**: 🟢 Low | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **시각화 도구**: **Grafana + D3.js**를 사용하여 **인터랙티브 대시보드** 제공.
  - **다국어 지원**: **i18n 라이브러리**를 사용하여 한국어/영어/중국어 지원.
  - **사용자 피드백 루프**: **monthly**로 농부 설문조사 실시하여 UX 개선 사항 수집.
