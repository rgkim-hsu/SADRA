🏗️ 아키텍처 분석 보고서
===============

📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 중앙 집중형 응용 프로세서 기반 스마트팜 데이터 허브 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                            |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 환경에서 카메라(316), 카메라 레이어(414), 인공지능-영상 처리 플랫폼(435), 디스플레이 레이어(449), 스트리밍 버퍼(428/426) 등 이기종 컴포넌트들이 상호작용해야 하며, 실시간 영상 데이터와 AI 추론 결과를 일관성 있게 처리·배분해야 하는 과제가 존재함. 특히 농업 현장의 네트워크 불안정성과 다양한 센서·카메라 데이터의 동시 처리 요구가 핵심 도전 과제임.                    |
| **결정(Decision)**       | 중앙의 **응용 프로세서(421)** 를 단일 조율 허브(Orchestration Hub)로 설계하여, 모든 컴포넌트(카메라, AI 플랫폼, 디스플레이, 스트리밍 레이어)와의 데이터 흐름을 응용 프로세서가 단방향·양방향으로 중재하는 중앙 집중형 파이프라인 아키텍처를 채택. 영상 스트리밍은 시간 순서 버퍼(428)와 미디어 타임라인(426)으로 이중 분리하여 실시간성과 저장 신뢰성을 동시에 확보.                |
| **근거(Rationale)**      | 스마트팜의 엣지 디바이스 환경에서 분산 처리보다 단일 오케스트레이터가 레이턴시 제어, 우선순위 스케줄링, 장애 격리에 유리함. AI 영상 처리 플랫폼(435)의 결과를 응용 프로세서가 수신하여 디스플레이(449)와 스트리밍(426/428)으로 선택적으로 라우팅함으로써 대역폭을 최적화할 수 있음. 카메라 레이어(414)를 별도 추상화함으로써 카메라 교체·확장 시 상위 레이어 변경을 최소화하는 OCP(개방-폐쇄 원칙) 준수. |
| **결과(Consequences)**   | **긍정적:** 데이터 흐름의 단일 제어점 확보로 디버깅·모니터링 용이, AI 추론 결과의 일관된 배포, 스트리밍 품질 제어 중앙화. **부정적:** 응용 프로세서(421)가 SPOF(Single Point of Failure)로 작동하여 해당 컴포넌트 장애 시 전체 시스템 마비 위험. 처리 부하가 집중되어 CPU/메모리 병목 발생 가능.                                                |
| **트레이드오프(Trade-offs)** | **얻는 것:** 아키텍처 단순성, 일관된 데이터 정책 적용, 빠른 개발 속도. **감수하는 것:** 수평 확장(Scale-out) 어려움, 고가용성(HA) 구성 복잡도 증가, 응용 프로세서 업그레이드 시 전체 서비스 중단 필요.                                                                                                              |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. 응용 프로세서(421) 단일 장애점(SPOF) 위험

* **설명:** 중앙 응용 프로세서가 하드웨어 오류, 소프트웨어 크래시, 메모리 누수 등으로 중단될 경우 카메라 입력, AI 분석, 디스플레이 출력, 스트리밍 전체가 동시에 중단됨. 스마트팜 환경에서 작물 이상 탐지나 자동 제어 신호가 끊겨 농업적 피해로 직결될 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** Active-Standby 이중화 구성(Watchdog 프로세스 + Heartbeat 모니터링), 컨테이너 오케스트레이션(K3s 등 경량 쿠버네티스)을 통한 자동 재시작 정책 적용, 장애 시 최소 기능(카메라 녹화)만 유지하는 Degraded Mode 설계.

### 2. AI-영상 처리 플랫폼(435) 추론 지연(Latency) 위험

* **설명:** 고해상도 다중 카메라 영상이 AI 플랫폼으로 동시 유입될 경우, GPU/NPU 리소스 포화로 추론 지연이 누적됨. 실시간 병해충 탐지나 생육 이상 감지가 수 분 이상 지연되면 스마트팜 대응 골든타임을 놓치게 됨.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 카메라별 프레임 샘플링 레이트 동적 조절(중요도 기반 우선순위 큐 적용), AI 모델 경량화(Quantization/Pruning), 엣지에서 1차 필터링 후 클라우드 전송하는 2-tier 추론 파이프라인 구성.

### 3. 스트리밍 버퍼(426/428) 데이터 유실 위험

* **설명:** 시간 순서 버퍼(428)와 미디어 타임라인(426)이 분리 운영되는 구조에서, 응용 프로세서의 동시 쓰기 중 네트워크 단절이나 저장소 I/O 병목 발생 시 두 버퍼 간 데이터 불일치(Inconsistency)가 발생함. 이는 영상 증거 데이터 손실 및 AI 학습 데이터 오염으로 이어질 수 있음.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 2-Phase Commit 또는 WAL(Write-Ahead Logging) 방식 도입으로 원자적 버퍼 쓰기 보장, 체크섬 기반 데이터 무결성 검증 주기적 실행, 로컬 스토리지에 1차 저장 후 동기화하는 오프라인 퍼스트(Offline-First) 전략 적용.

### 4. 카메라 레이어(414) 사이버보안 취약점 위험

* **설명:** 농업 현장에 물리적으로 분산 배치된 IP 카메라 및 카메라 레이어 디바이스는 기본 자격증명 미변경, 펌웨어 미패치 상태로 운영되는 경우가 많음. 외부 공격자가 카메라 스트림을 탈취하거나 변조된 영상을 주입하면 AI 모델이 오판하여 잘못된 농장 제어 명령을 실행할 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 카메라-응용 프로세서 간 mTLS(상호 TLS) 암호화 채널 강제 적용, 디바이스 인증서 기반 Zero Trust 접근 제어, 영상 스트림 서명(HMAC) 검증으로 위변조 탐지, 정기적 펌웨어 자동 업데이트 파이프라인 구축.

### 5. 디스플레이 레이어(449) 정보 과부하 및 UX 위험

* **설명:** AI 플랫폼의 분석 결과와 다수 카메라의 실시간 스트림이 디스플레이 레이어에 동시 전달될 경우, 농장 운영자가 처리할 수 있는 정보량을 초과하는 알림 피로(Alert Fatigue)가 발생함. 중요 경보가 일반 알림에 묻혀 무시되는 상황이 발생할 수 있음.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 알림 중요도 기반 3단계 분류 체계(Critical/Warning/Info) 및 임계값 기반 알림 억제(Deduplication) 로직 설계, 운영자 역할별 맞춤형 대시보드 뷰 구성, 중요 알림에 대한 다중 채널(SMS, 앱 푸시, 사이렌) 에스컬레이션 정책 수립.

### 6. 엣지-클라우드 연결 단절 시 운영 연속성 위험

* **설명:** 농촌 지역 특성상 네트워크 인프라가 취약하여 LTE/유선 연결이 수 시간 단절될 수 있음. 응용 프로세서가 클라우드 의존적으로 설계된 경우, 연결 단절 시 AI 추론·데이터 저장·원격 모니터링이 모두 중단되어 무인 스마트팜의 자율 운영이 불가능해짐.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 핵심 AI 모델을 엣지 응용 프로세서에 로컬 배포하여 오프라인 추론 유지, 연결 단절 구간 데이터를 로컬 버퍼에 누적 후 재연결 시 자동 동기화(Store-and-Forward), 네트워크 상태에 따른 운영 모드 자동 전환(Online/Offline/Degraded) 상태 기계(State Machine) 구현.
