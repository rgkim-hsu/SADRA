📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: OCF 기반 표준 IoT 상호운용성 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **상황(Context)**        | 시스템은 다양한 IoT 디바이스와 센서 네트워크를 포함하며, 산업(Industrial), 소비자(Consumer), 헬스(Health) 등 다양한 도메인에서 활용될 수 있다. 이질적인 디바이스 간 통신, 데이터 모델, 보안 체계의 통합이 핵심 과제이다. 특히 Wi-Fi, Bluetooth, Zigbee 등 다양한 통신 프로토콜을 사용하는 환경에서 상호운용성 확보가 필요하다. |
| **결정(Decision)**       | OCF(Open Connectivity Foundation) 표준을 기반으로 Resource Model 및 RESTful 인터페이스를 채택하고, Discovery, Provisioning, Comms 기능을 포함하는 Core Framework를 구성한다. 또한 Security, Identity & Permissions 계층을 공통으로 적용하여 통합 보안 체계를 구축한다.   |
| **근거(Rationale)**      | OCF는 IoT 디바이스 간 상호운용성을 위한 글로벌 표준으로, 다양한 제조사 및 프로토콜 환경을 통합할 수 있다. RESTful 기반 모델은 확장성과 개발 편의성을 제공하며, 표준화된 데이터 모델(oneIoTa Data Models)은 서비스 간 데이터 호환성을 높인다.                                                           |
| **결과(Consequences)**   | **긍정적:** 이기종 디바이스 통합, 확장성 확보, 표준 기반 개발, 보안 일관성 유지**부정적:** 초기 표준 적용 비용 증가, 기존 레거시 시스템과의 통합 어려움                                                                                                                      |
| **트레이드오프(Trade-offs)** | 높은 상호운용성과 확장성을 확보하는 대신, 초기 도입 비용 및 표준 학습 곡선을 감수해야 한다.                                                                                                                                                              |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. 표준 미지원 디바이스 통합 문제

* **설명:** OCF를 지원하지 않는 기존 IoT 장비와의 연동이 어려울 수 있음

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 프로토콜 변환 게이트웨이 도입, 어댑터 패턴 적용

### 2. 보안 취약점 (인증 및 권한 관리)

* **설명:** Identity 및 Permission 설정 오류로 인해 무단 접근 가능

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 강력한 인증 체계(PKI), 최소 권한 원칙 적용, 정기 보안 점검

### 3. 네트워크 프로토콜 혼재로 인한 성능 저하

* **설명:** Wi-Fi, Bluetooth, Zigbee 등 다양한 프로토콜 간 변환 과정에서 지연 발생

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 프로토콜 최적화, QoS 정책 적용, 엣지 게이트웨이 활용

### 4. 디바이스 Discovery 실패

* **설명:** 네트워크 환경에 따라 디바이스 탐색이 제대로 이루어지지 않을 수 있음

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 멀티캐스트/브로드캐스트 최적화, 수동 등록 기능 제공

### 5. 데이터 모델 불일치

* **설명:** oneIoTa 데이터 모델과 실제 디바이스 데이터 간 불일치 발생 가능

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 데이터 매핑 계층 구축, 표준 준수 검증 프로세스 도입

### 6. 확장 시 관리 복잡성 증가

* **설명:** 디바이스 수 증가에 따라 Provisioning 및 관리 부담 증가

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 자동 프로비저닝, 디바이스 관리 플랫폼(DMP) 도입

### 7. 클라우드 연계 보안 문제

* **설명:** 클라우드와 연계 시 데이터 전송 과정에서 보안 위협 발생

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** TLS 기반 암호화 통신, VPN 적용, 데이터 암호화 저장
