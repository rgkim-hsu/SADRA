# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 에지(Edge)-클라우드 하이브리드 데이터 처리 아키텍처 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 현장의 센서 측정 장치(200)로부터 발생하는 대량의 실시간 데이터를 지연 없이 처리하고, 이를 원격의 사용자 기기(20)에 안정적으로 전달해야 함. 전체 데이터를 클라우드로 즉시 전송할 경우 네트워크 부하와 비용이 급증하며, 현장 모니터링의 실시간성이 저하될 우려가 있음. |
| **결정(Decision)** | 현장(10) 내부에 모니터링 장치(300)와 정보 제공 서버(400)를 배치하여 1차적 데이터 처리 및 로컬 제어를 수행하고, 외부 네트워크(클라우드)를 통해 최종 사용자에게 데이터를 전달하는 하이브리드 구조를 채택함. |
| **근거(Rationale)** | 센서 데이터의 로컬 필터링을 통해 네트워크 대역폭을 절약할 수 있으며, 클라우드 장애 시에도 현장 모니터링 장치(300)를 통한 독립적인 운영(Survivability)이 가능하기 때문임. |
| **결과(Consequences)** | 로컬 처리로 인해 응답 속도가 향상되고 운영 비용이 절감됨. 다만, 현장에 서버급 장비(400)가 배치됨에 따라 유지보수 포인트가 물리적으로 분산되는 결과를 초래함. |
| **트레이드오프(Trade-offs)** | 낮은 데이터 지연 시간(Low Latency)과 대역폭 효율성을 얻는 대신, 현장 장비 관리의 복잡도와 초기 인프라 구축 비용이 상승함. |

---

## ⚠️ 잠재적 위험 분석

### 1. 현장-클라우드 간 네트워크 단절 (Network Partition)
- **설명:** 현장(10)의 정보 제공 서버와 외부 망 사이의 연결이 끊겨 사용자 기기(20)에서 실시간 데이터를 확인할 수 없는 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 정보 제공 서버(400)에 로컬 캐싱 및 데이터 버퍼링 기능을 구현하여 복구 후 누락된 데이터를 동기화하고, 현장 내 별도 경보 시스템을 구축함.

### 2. 센서 데이터 무결성 및 변조 위험
- **설명:** 센서 측정 장치(200)에서 모니터링 장치(300)로 전달되는 무선 신호가 간섭을 받거나, 악의적인 노드에 의해 데이터가 위변조되는 상황.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 센서와 모니터링 장치 간 통신 시 종단간 암호화(E2EE) 및 메시지 인증 코드(MAC)를 적용하여 데이터의 신뢰성을 확보함.

### 3. 현장 장비의 환경적 취약성
- **설명:** 시스템이 설치된 현장(10)의 물리적 환경(온도, 습도, 먼지 등)으로 인해 정보 제공 서버(400)나 모니터링 장치가 하드웨어 장애를 일으키는 경우.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 산업용 등급(Industrial Grade) 하드웨어를 채택하고, 이중화(HA) 구성을 통해 단일 장애점(SPOF)을 제거함.

### 4. 사용자 기기 접근 제어 및 보안 취약점
- **설명:** 비인가 사용자가 사용자 기기(20)를 통해 시스템에 접속하여 현장(10)의 데이터를 탈취하거나 제어권을 획득하는 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 다요소 인증(MFA) 및 역할 기반 접근 제어(RBAC)를 도입하고, 모든 외부 접속에 대해 SSL/TLS 보안 터널을 강제함.

### 5. 대규모 센서 확장에 따른 성능 저하 (Scalability Issue)
- **설명:** 모니터링해야 할 센서 측정 장치(200)의 수가 급격히 늘어날 경우, 모니터링 장치(300)의 처리 용량이 한계에 도달하여 데이터 유실이 발생하는 상황.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 마이크로서비스 아키텍처(MSA) 관점에서 모니터링 로직을 설계하여 수평적 확장(Scale-out)이 가능하도록 하고, 메시지 큐를 도입하여 부하를 분산함.
