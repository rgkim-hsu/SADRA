### ADR-001: IoT 기반 스마트팜 통합 데이터 플랫폼 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 이미지 상 시스템은 환경 데이터(온도, 습도, EC, pH 등)를 센서로부터 수집하고, 이를 분석하여 농업 생산(스마트 재배환경 시스템)에 활용하는 구조입니다. 다양한 디바이스(MW 계층), 데이터 수집/처리 모듈, 분석 기능, DB, 그리고 클라우드 및 서비스(Application, Web, Mobile)로 이어지는 복합 아키텍처를 가지고 있으며, 실시간성·확장성·이기종 연동이 핵심 과제입니다. |
| **결정(Decision)**       | IoT 디바이스 계층 → 데이터 수집/중계(Middleware) → 데이터 처리 및 저장 → 분석 및 최적화 → 서비스 제공 계층으로 구성된 **계층형 + 클라우드 기반 데이터 플랫폼 아키텍처**를 채택하며, 데이터 파이프라인 중심 구조로 설계합니다.                                                                                    |
| **근거(Rationale)**      | 센서 데이터는 실시간 스트리밍 성격을 가지며, 농업 환경 제어는 지연에 민감합니다. 따라서 데이터 수집과 분석을 분리하고, 클라우드 기반 확장성을 확보하는 것이 필수적입니다. 또한 다양한 디바이스 및 프로토콜을 지원하기 위해 Middleware 계층이 필요합니다.                                                                             |
| **결과(Consequences)**   | 데이터 흐름이 명확해지고 확장성과 유지보수성이 향상됩니다. 분석 기능(생육환경 최적화, 예측 등)을 독립적으로 고도화할 수 있습니다. 반면, 시스템 복잡도가 증가하고 초기 구축 비용이 상승합니다.                                                                                                                   |
| **트레이드오프(Trade-offs)** | 확장성과 유연성을 확보하는 대신, 실시간 처리 지연 가능성과 운영 복잡성 증가를 감수해야 합니다. 또한 클라우드 의존성이 증가합니다.                                                                                                                                                      |

### ADR-002: 데이터 중심 분석 및 최적화 엔진 도입

| 항목                     | 내용                                                                             |
| ---------------------- | ------------------------------------------------------------------------------ |
| **상황(Context)**        | 시스템에는 데이터 분석 기능(생육환경 분석, 예측, 제어 최적화)이 포함되어 있으며, 단순 모니터링을 넘어 의사결정 자동화가 요구됩니다.   |
| **결정(Decision)**       | 수집된 데이터를 기반으로 하는 **분석 엔진(룰 기반 + AI/ML 기반)**을 도입하여 자동 제어 및 최적화 기능을 수행하도록 설계합니다. |
| **근거(Rationale)**      | 스마트팜은 환경 변화에 민감하며, 데이터 기반 의사결정이 생산성과 직결됩니다. ML 기반 예측은 수확량 증가 및 비용 절감에 기여합니다.   |
| **결과(Consequences)**   | 자동화 수준이 향상되고 운영 효율이 증가합니다. 그러나 데이터 품질에 대한 의존성이 높아집니다.                          |
| **트레이드오프(Trade-offs)** | 고도화된 분석 기능을 얻는 대신, 데이터 정합성 확보와 모델 유지관리 비용이 증가합니다.                              |

### ADR-003: 클라우드 기반 서비스 및 멀티 채널 접근 구조

| 항목                     | 내용                                                                                     |
| ---------------------- | -------------------------------------------------------------------------------------- |
| **상황(Context)**        | 시스템은 Web, Mobile, Application 형태로 다양한 사용자 인터페이스를 제공합니다.                                |
| **결정(Decision)**       | 클라우드 플랫폼을 기반으로 **API 중심 서비스 아키텍처**를 구성하여 다양한 클라이언트(Web, Mobile 등)에 동일한 데이터와 기능을 제공합니다. |
| **근거(Rationale)**      | 농장 운영자는 다양한 환경에서 시스템에 접근해야 하며, 확장성과 접근성을 확보하기 위해 클라우드 기반이 적합합니다.                       |
| **결과(Consequences)**   | 접근성이 향상되고 서비스 확장이 용이합니다. 다만 네트워크 의존성이 증가합니다.                                           |
| **트레이드오프(Trade-offs)** | 사용자 편의성과 확장성을 확보하는 대신, 네트워크 장애 시 서비스 영향이 커집니다.                                         |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. 센서 데이터 신뢰성 저하

* **설명:** 센서 오작동 또는 노후화로 인해 잘못된 환경 데이터가 수집되어 잘못된 제어가 수행될 수 있음

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 센서 이중화, 정기적인 캘리브레이션, 이상치 탐지 알고리즘 적용

* * *

### 2. 네트워크 장애로 인한 실시간 제어 실패

* **설명:** IoT 디바이스와 클라우드 간 통신 장애 발생 시 데이터 수집 및 제어 명령 전달이 지연됨

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** Edge 컴퓨팅 도입, 로컬 제어 로직 fallback 구성, 네트워크 이중화

* * *

### 3. 데이터 처리 지연 및 병목 현상

* **설명:** 대량의 센서 데이터 유입 시 데이터 처리 및 분석이 지연되어 실시간성이 저하됨

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 스트리밍 처리 시스템(Kafka 등) 도입, 스케일 아웃 구조 설계

* * *

### 4. 보안 취약점 (IoT 디바이스 해킹)

* **설명:** 인증이 취약한 IoT 장비를 통해 시스템 전체가 공격받을 가능성

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 디바이스 인증 강화, TLS 통신, OTA 보안 업데이트 적용

* * *

### 5. 데이터 품질 문제로 인한 분석 오류

* **설명:** 결측치, 이상치, 불완전한 데이터로 인해 분석 결과 및 자동 제어 로직이 왜곡됨

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 데이터 정제 파이프라인 구축, 품질 모니터링, 데이터 검증 룰 적용

* * *

### 6. 클라우드 의존성 증가

* **설명:** 클라우드 장애 발생 시 전체 서비스 중단 가능

* **심각도:** 🔴 High

* **발생 가능성:** 🟢 Low

* **대응 방안:** 멀티 클라우드 또는 하이브리드 아키텍처 적용, DR(재해복구) 전략 수립

* * *
