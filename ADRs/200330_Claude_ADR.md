### ADR-001: QR코드 기반 생산자-소비자 직접 연결 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                  |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 기존 농수산물 유통 구조에서는 소비자가 생산자 정보를 브랜드 이미지에만 의존했으며, 정보화마을 홈페이지 또는 별도 생산이력관리 시스템을 통해서만 생산자 정보를 확인할 수 있었다. 이는 특정 플랫폼 접속 의존성이 높아 접근성이 낮고, 생산자 개인의 신뢰 구축 수단이 부재했다. 스마트팜 환경에서 생산 데이터의 투명한 공개 수요가 증가하는 상황에서 새로운 아키텍처 결정이 필요했다. |
| **결정(Decision)**       | 통합관제시스템을 중앙 허브로 두고, 생산자 회원가입 → 개별 홈페이지 자동 생성 → QR코드 발급/인쇄 → 생산품 부착 → 소비자 스캔의 5단계 순환 파이프라인을 채택한다. 각 생산자에게 고유 URL과 연동된 QR코드를 발급하여 생산자-소비자 간 직접 통신 채널을 구성한다.                                                           |
| **근거(Rationale)**      | 스마트패드/폰 보급률 증가로 QR코드 스캔이 일반화됨에 따라 별도 앱 설치 없이 접근 가능한 URL 기반 아키텍처가 최적 선택이다. 생산자별 개별 홈페이지는 SaaS형 멀티테넌트 구조로 구현 시 중앙 통합관제시스템 단일 유지관리로 운영 효율을 극대화할 수 있다. 농산물 이력추적관리법 요건을 QR코드 단일 접점으로 충족 가능하다.                            |
| **결과(Consequences)**   | 긍정적: 소비자는 스마트폰/PC 어디서든 구매 농산물의 생산 이력 즉시 확인 가능. 생산자는 별도 IT 전문 지식 없이 개인 브랜드 채널 운영 가능. 부정적: QR코드가 인쇄된 실물 포장재와 디지털 URL의 생명주기 불일치 문제 발생(포장재 유통 후 URL 변경 불가).                                                             |
| **트레이드오프(Trade-offs)** | 【득】단일 QR 접점으로 소비자 UX 단순화, 생산자 디지털 전환 장벽 최소화, 중앙 통합관제시스템을 통한 데이터 일원화 관리 가능. 【실】중앙 통합관제시스템 단일 장애점(SPOF) 리스크, QR코드 위변조 시 신뢰 체계 붕괴, 생산자 개별 홈페이지 콘텐츠 품질 편차 제어 불가.                                                        |

### ADR-002: 멀티채널 소비자 접점 아키텍처 (스마트폰 + PC 동시 지원)

| 항목                     | 내용                                                                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------------ |
| **상황(Context)**        | 소비자 디바이스 환경이 스마트폰, 태블릿, PC로 다양화되어 있으며, QR코드 스캔은 모바일 중심이나 이후 상세 정보 열람은 PC에서 이루어지는 크로스디바이스 패턴이 존재한다.     |
| **결정(Decision)**       | 생산자 개별 홈페이지를 반응형 웹(Responsive Web) 기반으로 구성하여 스마트폰·PC 단일 URL로 최적화된 뷰를 제공하는 디바이스 무관 아키텍처를 채택한다.          |
| **근거(Rationale)**      | 네이티브 앱 개발 시 iOS/Android 이중 유지관리 비용과 앱스토어 의존성이 발생한다. 웹 기반 단일 코드베이스는 생산자 수 증가에 따른 수평 확장 시 운영 복잡도를 최소화한다. |
| **결과(Consequences)**   | 긍정적: 앱 설치 없이 즉시 접근 가능하여 소비자 마찰 최소화. 부정적: 오프라인 환경(농촌 저속 네트워크)에서 웹 로딩 성능 저하 가능성.                         |
| **트레이드오프(Trade-offs)** | 【득】단일 URL 관리, 빠른 배포 사이클, 크로스플랫폼 호환성. 【실】카메라·GPS 등 디바이스 네이티브 기능 활용 제한, 오프라인 캐싱 한계.                      |

⚠️ 잠재적 위험 분석
------------

### 1. 통합관제시스템 단일 장애점(SPOF) 위험

* **설명:** 통합관제시스템이 모든 생산자 홈페이지 URL, QR코드 라우팅, 회원 인증을 단일 처리하는 구조에서, 해당 시스템 장애 발생 시 유통 중인 모든 농산물 패키지의 QR코드가 동시에 무효화된다. 수확기 성수기에 트래픽 급증으로 인한 서비스 중단 시 소비자 신뢰 치명적 손상이 우려된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** Active-Active 이중화 구성 및 CDN(Content Delivery Network) 적용으로 생산자 홈페이지 정적 콘텐츠를 엣지 캐싱 처리. 장애 시 Last-Known-Good 스냅샷 서빙을 위한 Fallback 페이지 구성. RTO 4시간, RPO 1시간 기준의 DR(Disaster Recovery) 계획 수립.

### 2. QR코드 위변조 및 피싱 위험

* **설명:** 악의적 행위자가 정품 QR코드 위에 피싱 URL로 연결되는 위조 QR코드 스티커를 덧붙이는 물리적 위변조 공격이 가능하다. 소비자가 위조 페이지에서 개인정보를 입력하거나, 허위 생산 이력 정보로 인해 식품 안전 사고로 이어질 수 있다. 특히 고가 농산물(프리미엄 과일 등) 패키지에서 발생 가능성이 높다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** QR코드에 HMAC 기반 디지털 서명 삽입 및 스캔 시 서버 측 서명 검증 로직 구현. 소비자 접속 페이지에 도메인 인증 배지 표시. QR코드 물리적 위변조 방지를 위한 홀로그램 보안 라벨 병행 적용. 의심 QR코드 신고 채널 운영.

### 3. 생산자 디지털 리터러시 격차로 인한 콘텐츠 품질 저하 위험

* **설명:** 농촌 고령 생산자의 경우 개별 홈페이지 콘텐츠 업데이트(생산 일지, 사진, 이력 정보)를 수행하지 못하거나 부정확한 정보를 등록할 가능성이 높다. 방치된 홈페이지나 허위 정보가 서비스 전체의 신뢰성을 훼손하고, 소비자 민원 및 법적 책임 문제로 이어질 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 스마트팜 IoT 센서 데이터(온습도, 생육 데이터)와 통합관제시스템을 연동하여 핵심 생산 이력을 자동 수집·등록하는 자동화 파이프라인 구축. 생산자 대상 정기 교육 프로그램 운영 및 지역 농업기술센터와 협력 지원 체계 마련. 콘텐츠 최신성 모니터링 알림 자동화.

### 4. 개인정보 및 생산자 위치 정보 노출 위험

* **설명:** 생산자 개별 홈페이지에 농장 주소, 생산자 연락처, 생산 현황 사진 등이 공개될 경우, 이를 기반으로 한 불법 방문·절도·스토킹 등 물리적 위협이 가능하다. 또한 통합관제시스템에 집적된 전체 생산자 데이터베이스가 해킹될 경우 대규모 개인정보 유출 사고로 이어질 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 생산자 공개 정보와 개인 식별 정보를 분리 저장하는 데이터 계층 분리 설계. 농장 위치는 읍면동 단위까지만 공개하고 정확한 주소는 마스킹 처리. 통합관제시스템에 개인정보보호법 및 PIMS 인증 기준 적용. 연 1회 이상 정기 침투 테스트(Penetration Test) 수행.

### 5. QR코드 물리적 수명과 디지털 URL 생명주기 불일치 위험

* **설명:** 인쇄된 QR코드는 포장재와 함께 유통되어 최종 소비자에게 도달하기까지 수주~수개월이 소요될 수 있다. 이 기간 중 생산자 회원 탈퇴, URL 구조 변경, 서비스 도메인 변경이 발생할 경우 유통 중인 모든 제품의 QR코드가 Dead Link가 된다. 이미 판매된 제품의 QR코드는 회수·교체가 불가능하다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** QR코드에 Short URL 레이어(자체 URL 단축 서비스)를 중간에 삽입하여 실제 목적지 URL 변경 시에도 QR코드 재발행 없이 리다이렉션 관리 가능하도록 구성. 생산자 탈퇴 시 홈페이지를 즉시 삭제하지 않고 최소 2년간 이력 조회 전용 아카이브 페이지로 유지. URL 영속성 정책을 서비스 약관에 명시.

### 6. 스마트팜 IoT 데이터 미연동으로 인한 이력 신뢰성 한계 위험

* **설명:** 현재 아키텍처는 생산자가 수동으로 홈페이지에 정보를 입력하는 구조로, 실제 스마트팜 환경의 IoT 센서 데이터(재배 환경, 농약 사용, 수확량)와 연계되지 않는다. 이는 생산자가 유리한 정보만 선택적으로 공개하거나 허위 이력을 등록할 수 있어, 농산물 이력추적의 본질적 신뢰성을 담보하지 못한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 클라우드 기반 스마트팜 플랫폼(농업 IoT 게이트웨이)과 통합관제시스템 간 API 연동을 통한 생산 데이터 자동 수집 체계 구축. 농약 사용 이력은 농약안전정보시스템(PSIS)과 연계하여 제3자 검증 구조 적용. 장기적으로 블록체인 기반 불변 이력 저장소 도입 검토로 데이터 무결성 보장.

| **근거(Rationale)**      | 네이티브 앱 개발 시 iOS/Android 이중 유지관리 비용과 앱스토어 의존성이 발생한다. 웹 기반 단일 코드베이스는 생산자 수 증가에 따른 수평 확장 시 운영 복잡도를 최소화한다. |
| **결과(Consequences)**   | 긍정적: 앱 설치 없이 즉시 접근 가능하여 소비자 마찰 최소화. 부정적: 오프라인 환경(농촌 저속 네트워크)에서 웹 로딩 성능 저하 가능성.                         |
| **트레이드오프(Trade-offs)** | 【득】단일 URL 관리, 빠른 배포 사이클, 크로스플랫폼 호환성. 【실】카메라·GPS 등 디바이스 네이티브 기능 활용 제한, 오프라인 캐싱 한계.                      |

⚠️ 잠재적 위험 분석
------------

### 1. 통합관제시스템 단일 장애점(SPOF) 위험

* **설명:** 통합관제시스템이 모든 생산자 홈페이지 URL, QR코드 라우팅, 회원 인증을 단일 처리하는 구조에서, 해당 시스템 장애 발생 시 유통 중인 모든 농산물 패키지의 QR코드가 동시에 무효화된다. 수확기 성수기에 트래픽 급증으로 인한 서비스 중단 시 소비자 신뢰 치명적 손상이 우려된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** Active-Active 이중화 구성 및 CDN(Content Delivery Network) 적용으로 생산자 홈페이지 정적 콘텐츠를 엣지 캐싱 처리. 장애 시 Last-Known-Good 스냅샷 서빙을 위한 Fallback 페이지 구성. RTO 4시간, RPO 1시간 기준의 DR(Disaster Recovery) 계획 수립.

### 2. QR코드 위변조 및 피싱 위험

* **설명:** 악의적 행위자가 정품 QR코드 위에 피싱 URL로 연결되는 위조 QR코드 스티커를 덧붙이는 물리적 위변조 공격이 가능하다. 소비자가 위조 페이지에서 개인정보를 입력하거나, 허위 생산 이력 정보로 인해 식품 안전 사고로 이어질 수 있다. 특히 고가 농산물(프리미엄 과일 등) 패키지에서 발생 가능성이 높다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** QR코드에 HMAC 기반 디지털 서명 삽입 및 스캔 시 서버 측 서명 검증 로직 구현. 소비자 접속 페이지에 도메인 인증 배지 표시. QR코드 물리적 위변조 방지를 위한 홀로그램 보안 라벨 병행 적용. 의심 QR코드 신고 채널 운영.

### 3. 생산자 디지털 리터러시 격차로 인한 콘텐츠 품질 저하 위험

* **설명:** 농촌 고령 생산자의 경우 개별 홈페이지 콘텐츠 업데이트(생산 일지, 사진, 이력 정보)를 수행하지 못하거나 부정확한 정보를 등록할 가능성이 높다. 방치된 홈페이지나 허위 정보가 서비스 전체의 신뢰성을 훼손하고, 소비자 민원 및 법적 책임 문제로 이어질 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 스마트팜 IoT 센서 데이터(온습도, 생육 데이터)와 통합관제시스템을 연동하여 핵심 생산 이력을 자동 수집·등록하는 자동화 파이프라인 구축. 생산자 대상 정기 교육 프로그램 운영 및 지역 농업기술센터와 협력 지원 체계 마련. 콘텐츠 최신성 모니터링 알림 자동화.

### 4. 개인정보 및 생산자 위치 정보 노출 위험

* **설명:** 생산자 개별 홈페이지에 농장 주소, 생산자 연락처, 생산 현황 사진 등이 공개될 경우, 이를 기반으로 한 불법 방문·절도·스토킹 등 물리적 위협이 가능하다. 또한 통합관제시스템에 집적된 전체 생산자 데이터베이스가 해킹될 경우 대규모 개인정보 유출 사고로 이어질 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 생산자 공개 정보와 개인 식별 정보를 분리 저장하는 데이터 계층 분리 설계. 농장 위치는 읍면동 단위까지만 공개하고 정확한 주소는 마스킹 처리. 통합관제시스템에 개인정보보호법 및 PIMS 인증 기준 적용. 연 1회 이상 정기 침투 테스트(Penetration Test) 수행.

### 5. QR코드 물리적 수명과 디지털 URL 생명주기 불일치 위험

* **설명:** 인쇄된 QR코드는 포장재와 함께 유통되어 최종 소비자에게 도달하기까지 수주~수개월이 소요될 수 있다. 이 기간 중 생산자 회원 탈퇴, URL 구조 변경, 서비스 도메인 변경이 발생할 경우 유통 중인 모든 제품의 QR코드가 Dead Link가 된다. 이미 판매된 제품의 QR코드는 회수·교체가 불가능하다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** QR코드에 Short URL 레이어(자체 URL 단축 서비스)를 중간에 삽입하여 실제 목적지 URL 변경 시에도 QR코드 재발행 없이 리다이렉션 관리 가능하도록 구성. 생산자 탈퇴 시 홈페이지를 즉시 삭제하지 않고 최소 2년간 이력 조회 전용 아카이브 페이지로 유지. URL 영속성 정책을 서비스 약관에 명시.

### 6. 스마트팜 IoT 데이터 미연동으로 인한 이력 신뢰성 한계 위험

* **설명:** 현재 아키텍처는 생산자가 수동으로 홈페이지에 정보를 입력하는 구조로, 실제 스마트팜 환경의 IoT 센서 데이터(재배 환경, 농약 사용, 수확량)와 연계되지 않는다. 이는 생산자가 유리한 정보만 선택적으로 공개하거나 허위 이력을 등록할 수 있어, 농산물 이력추적의 본질적 신뢰성을 담보하지 못한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 클라우드 기반 스마트팜 플랫폼(농업 IoT 게이트웨이)과 통합관제시스템 간 API 연동을 통한 생산 데이터 자동 수집 체계 구축. 농약 사용 이력은 농약안전정보시스템(PSIS)과 연계하여 제3자 검증 구조 적용. 장기적으로 블록체인 기반 불변 이력 저장소 도입 검토로 데이터 무결성 보장.
