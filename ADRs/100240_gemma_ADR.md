## 📋 ADR (Architecture Decision Record)

### ADR-001: 하이브리드 엣지-클라우드 진단 아키텍처 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 농기계 진단 시스템은 농지라는 **비정형적이고 네트워크 연결성이 불안정한 환경(Edge)**에서 작동하며, 진단 모델은 **내부 데이터(에러 카운트)**, **환경 데이터(날씨, 토양)**, **부품 데이터(사용 이력, 사양)** 등 이질적이고 복합적인 **다중 모드 데이터(Multi-modal Data)**를 실시간으로 수집하고 이를 기반으로 즉각적인 의사결정(진단)을 수행해야 하는 복잡한 과제에 직면해 있습니다. 중앙 서버만으로는 지연 시간이 길고, 현장 독립성이 보장되지 않습니다. |
| **결정(Decision)** | **하이브리드 엣지-클라우드 (Hybrid Edge-to-Cloud)** 아키텍처를 채택합니다. 핵심진단 로직(진단 모델, 기초 진단)은 **엣지 디바이스/게이트웨이**에서 저지연(Low-Latency)으로 처리하고, 모델 학습(재판정부, 모델 업데이트), 대규모 데이터 저장, 글로벌 트렌드 분석은 **클라우드 백엔드**에서 수행하도록 이원화합니다. |
| **근거(Rationale)** | 1. **저지연 요구사항 충족:** 현장 고장 시 즉각적인 경고가 필요하며, 이는 엣지 컴퓨팅이 필수적입니다. 2. **데이터 다양성 처리:** 엣지에서 1차 필터링 및 특징 추출을 수행하여, 클라우드에서는 고도화된 AI/ML 모델 학습 및 다차원 데이터 융합(Fusion)을 가능하게 합니다. 3. **표준 준수 및 확장성:** IoT 시스템 참조 아키텍처(ISO/IEC 30141) 원칙에 따라, 엣지 레이어와 클라우드 레이어 간의 통신 인터페이스를 표준화된 API 게이트웨이(e.g., MQTT, RESTful API)로 설계하여 확장성을 확보합니다. |
| **결과(Consequences)** | **긍정적:** 실시간 고장 진단 정확도와 신속성 극대화, 네트워크 단절 시에도 기본적인 운영 가능성(Off-line capability) 보장, 모델 재학습을 통한 지속적인 성능 개선. **부정적:** 시스템 아키텍처가 매우 복잡해지며, 엣지 디바이스, 게이트웨이, 클라우드 간의 통합 및 배포 관리가 어려워지고, 높은 수준의 보안 설계(Zero Trust Model)가 요구됩니다. |
| **트레이드오프(Trade-offs)** | **장점:** 최고 수준의 실시간 성능과 안정성 확보 (사용자 단말의 신뢰성 향상). **단점:** 초기 개발 복잡도 및 운영 비용(Opex)이 매우 높음. 복잡성을 관리하기 위해 마이크로서비스 아키텍처(MSA)를 적용해야 합니다. |

## ⚠️ 잠재적 위험 분석

### 1. 엣지-클라우드 데이터 동기화 불일치 위험
- **설명:** 농기계가 오랜 기간 오프라인 상태에 있다가 온라인으로 복귀할 때, 엣지 디바이스에 남아있는 지역적/시간적 데이터와 클라우드 데이터 간의 동기화 오류가 발생하여 진단 모델이 부정확한 판단을 내릴 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** **Conflict-Free Replicated Data Types (CRDT)** 등의 데이터 구조를 도입하여 데이터 병합 로직을 설계하고, 데이터가 클라우드와 동기화될 때 발생할 수 있는 모든 시점 및 지역 데이터를 메타데이터로 기록하고 검증하는 프로세스(Validation Pipeline)를 필수적으로 구축해야 합니다.

### 2. 산업 현장 사이버 보안 침해 위험 (DDoS/Tampering)
- **설명:** 농기계는 물리적 접근이 용이하며, 진단 데이터는 기기의 핵심 상태 정보를 포함합니다. 해킹 공격자가 통신 프로토콜을 조작하거나 진단 데이터를 위변조하여 시스템 오작동을 유발하거나, 기기를 원격으로 무력화시킬 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** **Zero Trust Architecture (ZTA)** 모델을 적용하여 모든 통신 구간(엣지-게이트웨이, 게이트웨이-클라우드, 사용자 단말)에서 상호 인증(Mutual TLS)을 의무화해야 합니다. 또한, 주기적인 취약점 점검과 암호화된 데이터 전송(End-to-End Encryption)을 적용해야 합니다.

### 3. 이질적 데이터 소스 통합 실패 위험 (Interoperability Gap)
- **설명:** 농기계는 제조사, 모델, 연식별로 센서 규격, 통신 프로토콜(CAN bus, J1939 등), 데이터 포맷이 상이합니다. '에러 카운트 회수' 및 '부품 특징' 데이터를 통합하는 단계에서 표준화 실패가 발생하면, 진단 모델이 공통 언어 없이 파편화된 정보를 받고 오진하게 됩니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** **통합 데이터 모델(Canonical Data Model)**을 아키텍처의 핵심으로 정의하고, 각기 다른 장비에서 들어오는 원시 데이터(Raw Data)를 표준화된 포맷으로 변환하는 전용 데이터 어댑터/게이트웨이 모듈을 구축해야 합니다. (이는 ISO/IEC 30141과 같은 업계 참조 아키텍처 프레임워크 준수에 해당합니다.)

### 4. 진단 모델의 환경 적응 실패 위험 (Model Drift)
- **설명:** 농업 환경은 기후 변화, 품종 변화, 작물 변화 등 예측하기 어려운 변수가 많습니다. 과거 데이터를 기반으로 학습된 진단 모델이 이러한 급격한 환경 변화(예: 극심한 가뭄, 신종 병충해)를 반영하지 못하고, 오진율이 높아지는 현상이 발생할 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 진단 모델을 정적(Static)으로 운영하지 않고, **지속적인 학습 파이프라인(MLOps)**을 구축해야 합니다. 현장에서 발생하는 오진 사례(False Positive/Negative)를 피드백 루프(Feedback Loop)로 수집하여 모델을 주기적으로 재학습(Retrain)하고, 전문가의 검토(Human-in-the-loop)를 거쳐 배포해야 합니다.

### 5. 자원 제한 환경에서의 성능 부하 초과 위험 (Computational Overload)
- **설명:** 엣지 게이트웨이는 전력 및 연산 자원에 제한이 있습니다. 진단 모델(특히 AI/ML 기반의 '고장 여부 재판정부')이 과도하게 복잡하거나, 데이터 전처리 부하가 커질 경우, 게이트웨이 자체가 처리 능력을 초과하여 진단 결과 도출이 지연되거나 시스템이 다운될 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
