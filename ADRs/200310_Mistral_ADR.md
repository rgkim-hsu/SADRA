### ADR-001: 클라우드 기반 스마트팜 관리 시스템 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                             |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 시스템은 실시간으로 다수의 사용자(User 1, User 2, ..., User n)로부터 데이터를 수집하고, 모니터링, 학습 스크리닝, 농장 정보 연결 등 다양한 기능을 제공해야 함. 기존 온프레미스 방식은 확장성 및 유지보수에 한계가 있으며, 다수의 사용자와 장치를 효율적으로 관리하기 어려움.                    |
| **결정(Decision)**       | 클라우드 기반 아키텍처를 채택하여 **Smart Farming Management Function**을 클라우드에 배치하고, **LMS(Learning Management System)**와 **FMCF(Farm Management Connection Function)**을 통합하여 중앙집중식 데이터 관리 및 실시간 처리 가능하도록 설계. |
| **근거(Rationale)**      | 클라우드는 확장성, 유연성, 및 비용 효율성을 제공하며, 다수의 사용자와 장치에서 발생하는 빅데이터를 효율적으로 처리할 수 있음. 또한, LMS와 FMCF의 통합을 통해 농장 정보와 학습 데이터를 연동하여 스마트팜 관리를 최적화할 수 있음.                                                         |
| **결과(Consequences)**   | **장점**: 실시간 데이터 처리 및 확장이 용이, 유지보수 비용 감소, 다중 사용자 지원 용이. **단점**: 클라우드 의존도로 인한 네트워크 지연 및 보안 이슈 발생 가능성.                                                                                            |
| **트레이드오프(Trade-offs)** | 클라우드의 장점을 활용하기 위해 네트워크 안정성과 보안 강화가 필요하며, 이를 위해 추가적인 보안 솔루션(예: 암호화, 접근 제어) 및 네트워크 최적화(예: CDN, Edge Computing) 투자가 필요.                                                                           |

### ADR-002: 모니터링 함수와 학습 스크리닝 함수의 분리 및 연동

| 항목                     | 내용                                                                                                                                                       |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 모니터링 기능은 사용자별로 실시간 데이터를 수집하고, 학습 스크리닝 기능은 수집된 데이터를 분석하여 사용자에게 피드백을 제공해야 함. 두 기능이 밀접하게 연동되어야 하지만, 각 기능의 역할이 명확히 분리되어 있어야 시스템의 유연성과 유지보수성이 향상됨.            |
| **결정(Decision)**       | **Monitoring Function**과 **Learning Screening Function**을 분리하여 설계하고, 양방향 통신을 통해 데이터 흐름을 관리. 모니터링 함수는 사용자로부터 데이터를 수집하고, 학습 스크리닝 함수는 수집된 데이터를 분석하여 결과를 제공. |
| **근거(Rationale)**      | 기능 분리로 인해 각 컴포넌트는 독립적으로 개발, 테스트, 배포될 수 있으며, 시스템의 모듈성이 향상됨. 또한, 한 컴포넌트의 장애가 전체 시스템에 미치는 영향을 최소화할 수 있음.                                                    |
| **결과(Consequences)**   | **장점**: 시스템의 유연성 및 유지보수성 향상, 장애 격리 효과. **단점**: 컴포넌트 간 통신 지연 및 데이터 동기화 이슈 발생 가능성.                                                                         |
| **트레이드오프(Trade-offs)** | 컴포넌트 간 통신을 최적화하기 위해 메시지 큐(예: Kafka, RabbitMQ) 또는 API 게이트웨이를 도입하여 지연을 최소화하고, 데이터 일관성을 보장해야 함.                                                             |

### ADR-003: LMS와 FMCF의 통합을 통한 농장 정보 관리

| 항목                     | 내용                                                                                                                        |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 시스템은 농장 정보(Farming Information)를 실시간으로 관리하고, 사용자에게 학습 및 분석 결과를 제공해야 함. LMS는 학습 데이터를 관리하고, FMCF는 농장 정보를 관리하는 역할이 필요함. |
| **결정(Decision)**       | **LMS**와 **FMCF**를 클라우드 내에 통합하여 농장 정보와 학습 데이터를 연동하고, **Learning Information Connection Function**을 통해 사용자에게 필요한 정보를 제공.   |
| **근거(Rationale)**      | LMS와 FMCF의 통합을 통해 농장 정보와 학습 데이터를 연동하여, 사용자에게 맞춤형 피드백과 분석 결과를 제공할 수 있음. 또한, 데이터의 중복을 방지하고 일관성을 유지할 수 있음.                   |

| **트레이드오프(Trade-offs)** | 통합 복잡성을 관리하기 위해 마이크로서비스 아키텍처를 도입하여 각 기능을 독립적으로 개발 및 배포할 수 있도록 설계. 또한, 장애 복구를 위한 백업 및 재해 복구 계획 수립.                         |

⚠️ 잠재적 위험 분석
------------

### 1. 클라우드 서비스 장애

* **설명:** 클라우드 제공업체의 서비스 장애로 인해 Smart Farming Management Function이 중단되어 실시간 모니터링 및 데이터 처리가 불가능해질 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 다중 클라우드 제공업체(Multi-Cloud) 또는 하이브리드 클라우드 아키텍처를 도입하여 장애 복구 시간을 최소화하고, 백업 시스템을 구축.

* * *

### 2. 네트워크 지연 및 대역폭 문제

* **설명:** 다수의 사용자와 장치에서 실시간으로 데이터를 전송할 경우 네트워크 지연 및 대역폭 포화로 인해 시스템 성능이 저하될 수 있음.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** Edge Computing을 도입하여 데이터 처리를 클라우드와 가까운 위치에서 수행하고, CDN(Content Delivery Network)을 활용하여 정적 콘텐츠 배포를 최적화.

* * *

### 3. 데이터 동기화 실패

* **설명:** 모니터링 함수와 학습 스크리닝 함수 간 데이터 동기화가 실패할 경우, 사용자에게 잘못된 정보가 제공될 수 있음.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 메시지 큐를 활용하여 비동기식 데이터 처리를 구현하고, 주기적인 데이터 동기화 검사를 수행하여 일관성을 보장.

* * *

### 4. 보안 취약점 노출

* **설명:** 클라우드 기반 시스템은 외부로 노출된 API 및 데이터베이스가 해커의 공격 대상이 될 수 있으며, 농장 정보 및 사용자 데이터가 유출될 위험이 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 데이터 암호화(예: TLS, AES), 접근 제어(예: IAM, RBAC), 및 보안 감사(예: SIEM) 도구를 도입하여 보안을 강화.

* * *

### 5. 사용자 증가로 인한 시스템 과부하

* **설명:** 동시에 많은 사용자가 시스템에 접속할 경우, 서버 및 데이터베이스의 과부하로 인해 시스템 성능이 저하되거나 다운될 수 있음.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 오토스케일링(Auto-Scaling)을 도입하여 서버 리소스를 동적으로 조절하고, 로드 밸런싱(Load Balancing)을 통해 트래픽을 분산.
