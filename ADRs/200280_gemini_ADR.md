# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: DDPG 알고리즘 기반의 연속적 온실 환경 제어 아키텍처 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 토마토 온실은 온도, 습도, CO2 농도 등 제어 변수가 연속적(Continuous)이며, 외부 기상(Weather forecast) 및 작물 생육 상태에 따라 복잡한 상호작용이 발생하는 비선형적 시스템임. 기존 룰 기반 제어는 전문가(Human experts)의 지식에 의존하여 급격한 환경 변화에 유연하게 대응하기 어려움. |
| **결정(Decision)** | 연속적 행동 공간(Action Space) 처리에 최적화된 **DDPG(Deep Deterministic Policy Gradient)** 알고리즘을 핵심 제어 엔진으로 채택함. 이를 위해 시뮬레이션 기반 가상 환경(Greenhouse Library KR)과 Actor-Critic 구조의 DNN 에이전트를 결합한 강화학습 프레임워크를 구축함. |
| **근거(Rationale)** | DDPG는 고차원/연속적 환경 제어에 강점이 있으며, Actor(정책 결정)와 Critic(가치 평가)의 분리를 통해 학습 안정성을 확보할 수 있음. 또한 가상 환경(Simulation)을 활용함으로써 실제 작물 피해 리스크 없이 수만 번의 반복 학습(Trial and Error)이 가능함. |
| **결과(Consequences)** | 전문가의 개입을 최소화한 최적 환경 자동 제어가 가능해지며, 에너지 효율 최적화 및 수확량 증대를 기대할 수 있음. 데이터 기반의 정밀 제어를 통해 예측 불가능한 기후 변화에 대한 탄력적 대응이 가능함. |
| **트레이드오프(Trade-offs)** | 고성능 연산 자원(GPU 등)이 필요하며, 시뮬레이션 환경과 실제 온실 간의 'Reality Gap'으로 인한 오차가 발생할 수 있음. 초기 모델 학습 및 하이퍼파라미터 튜닝에 상당한 시간과 비용이 소요됨. |

---

## ⚠️ 잠재적 위험 분석

### 1. 시뮬레이션과 실환경 간의 괴리 (Reality Gap)
- **설명:** 가상 학습 환경(Greenhouse Library KR)에서 학습된 모델이 실제 온실의 물리적 변수(센서 오차, 돌발 기상 등)를 완벽히 반영하지 못해 오작동할 위험.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 디지털 트윈 기술을 고도화하여 실제 데이터를 가상 환경에 지속적으로 피드백하고, Transfer Learning(전이 학습)을 통해 실환경 적응력을 높임.

### 2. 제어 에이전트의 이상 행동에 따른 작물 폐사
- **설명:** 강화학습 에이전트가 보상(Reward)을 극대화하기 위해 물리적으로 불가능하거나 작물 생육에 치명적인 극단적인 제어값(예: 한겨울 과도한 환기)을 출력할 위험.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 도메인 전문가(Human experts)의 지식을 기반으로 한 **'세이프티 가드레일(Safety Guardrail)'** 로직을 하드코딩하여 제어값의 물리적 한계치를 강제함.

### 3. 기상 예보 데이터의 부정확성 및 의존성
- **설명:** 시스템이 Weather forecast 데이터에 의존하여 미래 환경을 예측하므로, 예보가 틀릴 경우 잘못된 Action을 수행하여 에너지 낭비 및 환경 급변을 초래함.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 단기 예보 데이터와 실시간 온실 내부 센서 데이터를 교차 검증하는 앙상블 제어 로직을 적용함.

### 4. 모델 업데이트 중단 및 연산 지연
- **설명:** DNN 모델의 추론(Inference) 과정에서 네트워크 지연이나 컴퓨팅 자원 부족으로 인해 제어 타이밍을 놓쳐 온실 환경 유지에 실패할 위험.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low
- **대응 방안:** 엣지 컴퓨팅(Edge Computing) 기술을 도입하여 로컬 환경에서 독립적인 추론이 가능하도록 아키텍처를 구성하고 Fail-safe 모드를 구축함.

### 5. 데이터 보안 및 에이전트 해킹 위험
- **설명:** 외부 기상 데이터 수집 및 제어 명령 전달 과정에서 사이버 공격으로 인해 에이전트가 악의적인 제어를 수행하거나 재배 노하우가 유출될 위험.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 종단간 암호화(E2EE)를 적용하고, 에이전트의 제어 명령에 대한 무결성 검증 프로세스를 도입함.
