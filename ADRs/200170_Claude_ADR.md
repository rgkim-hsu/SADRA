📋 ADR (Architecture Decision Record)

### ADR-001: 3계층 하이브리드 엣지-클라우드 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                                                                                                  |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트 축산 시스템은 낙농, 육류, 양식, 양봉 등 다양한 생산 도메인에 걸쳐 실시간 동물 건강 모니터링, 사료 관리, 분뇨 처리 등 지연에 민감한 현장 제어와 함께 대규모 이력 데이터 분석을 동시에 수행해야 한다. 농장 환경은 네트워크 불안정 구간이 많고, 공급자→농가→가공업체→유통업체→소비자로 이어지는 복잡한 밸류체인 전반의 이력추적(Traceability) 가시성을 확보해야 한다.                                                                                                           |
| **결정(Decision)**       | ICT 인프라 계층을 **엣지(Devices & Gateways)** 와 **클라우드(Backup, Analysis & Support)** 로 이중화하고, 그 위에 Feed/Nutrition, Genetics & Breeding, Animal Health Monitoring, Housing Control, Manure Management, Grassland Management, Logistic/Production Traceability 총 8개 도메인 서비스를 서비스 계층으로 분리한다. 커뮤니티 뷰(밸류체인 참여자) 계층은 비즈니스 프로세스 오케스트레이션 역할을 담당한다. |
| **근거(Rationale)**      | ① 엣지 게이트웨이에서 센서 데이터 전처리·로컬 제어를 수행함으로써 네트워크 단절 시에도 축사 자동화 지속 가능. ② 클라우드에서 머신러닝 기반 질병 예측·유전 분석 등 컴퓨팅 집약 작업 수행. ③ 서비스 계층 분리로 특정 도메인(예: 어업→양봉) 독립 확장 및 기능 고도화 용이. ④ 밸류체인 각 참여자(공급자, 농가, 가공, 유통)가 공통 서비스 레이어를 통해 데이터를 공유함으로써 생산·물류 이력추적 일원화 달성.                                                                                          |
| **결과(Consequences)**   | (+) 현장 가용성 향상, 밸류체인 전 구간 데이터 일관성 확보, 서비스별 독립 배포 가능. (-) 엣지-클라우드 간 데이터 동기화 복잡도 증가, 이기종 디바이스 관리 오버헤드 발생, 초기 인프라 구축 비용 상승.                                                                                                                                                                                                             |
| **트레이드오프(Trade-offs)** | **얻는 것:** 오프라인 내성(Resilience), 확장성(Scalability), 이력추적 무결성. **감수하는 것:** 엣지-클라우드 데이터 일관성 보장을 위한 Eventually Consistent 모델 도입 필요, 운영 복잡도 증가, 엣지 디바이스 펌웨어 업데이트·보안 패치 관리 부담.                                                                                                                                                              |

### ADR-002: 도메인 기반 마이크로서비스 서비스 계층 설계

| 항목                     | 내용                                                                                                                                           |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 8개 서비스 도메인(사료·영양, 유전·육종, 동물건강, 축사제어, 분뇨관리, 초지관리, 물류이력, 생산이력)은 각기 다른 데이터 주기, 실시간성 요구사항, 규제 요건을 가진다. 단일 모놀리식 구조로는 도메인별 독립 업데이트 및 규모 조정이 불가능하다. |
| **결정(Decision)**       | 각 서비스 도메인을 독립 배포 가능한 마이크로서비스로 분리하고, IoT 관련 환경을 공통 인프라 플랫폼으로 정의한다. 서비스 간 통신은 이벤트 기반(Event-Driven) 메시징을 원칙으로 한다.                               |
| **근거(Rationale)**      | 동물건강 모니터링과 같이 실시간성이 중요한 서비스와 유전·육종처럼 배치 처리가 적합한 서비스를 분리함으로써 자원 효율 극대화. 서비스별 독립 SLA 설정 가능.                                                    |
| **결과(Consequences)**   | (+) 장애 격리(Fault Isolation), 기술 스택 다양화, 팀별 독립 개발 가능. (-) 분산 트랜잭션 처리, 서비스 메쉬(Service Mesh) 도입 필요성 증가.                                          |
| **트레이드오프(Trade-offs)** | **얻는 것:** 도메인 독립성, 탄력적 스케일링. **감수하는 것:** 운영 복잡도(서비스 디스커버리, 분산 추적, 로그 통합) 증가.                                                                 |

⚠️ 잠재적 위험 분석
------------

### 1. 엣지-클라우드 데이터 동기화 실패로 인한 이력추적 공백

* **설명:** 농장 현장의 네트워크 단절 구간에서 엣지 게이트웨이가 수집한 동물 건강·이동 데이터가 클라우드와 동기화되지 못할 경우, 물류 이력추적(Logistic Traceability) 및 생산 이력추적(Production Traceability) 데이터에 타임갭이 발생한다. 이후 동기화 시 순서 불일치 또는 충돌 데이터가 유통·소비자 단계까지 전파될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 엣지 로컬 스토리지에 WAL(Write-Ahead Log) 방식으로 이벤트를 순차 기록하고, 연결 복구 시 시퀀스 번호 기반 멱등(Idempotent) 재전송 프로토콜 적용. CRDT(Conflict-free Replicated Data Type) 기반 동기화 모델 도입 및 이력추적 서비스에 데이터 갭 감지 알림 기능 구현.

### 2. IoT 디바이스 보안 취약점을 통한 사이버 침해

* **설명:** 수백~수천 개의 센서와 게이트웨이가 IoT 환경에 직접 연결되어 있어, 펌웨어 미패치 디바이스를 통한 네트워크 침투가 발생할 수 있다. 공격자가 축사 제어(Housing Control) 시스템에 접근하면 온도·환기·급이 자동화를 조작하여 가축 폐사 등 직접적 피해를 야기할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 디바이스 수준 보안 부팅(Secure Boot) 및 TPM 기반 디바이스 인증 적용. 네트워크를 OT(운영기술)망과 IT망으로 VLAN 분리. OTA(Over-The-Air) 자동 펌웨어 업데이트 체계 구축. 이상 트래픽 탐지를 위한 엣지 레벨 IDS(침입탐지시스템) 운영.

### 3. 단일 클라우드 의존에 의한 서비스 전면 중단

* **설명:** 백업·분석·지원 기능이 단일 클라우드 시스템에 집중된 구조에서 클라우드 프로바이더 장애 또는 지역 재해가 발생할 경우, 유전·육종 분석, 물류이력 조회, 생산이력 인증 등 클라우드 의존 서비스가 전면 중단된다. 특히 가공업체·유통업체의 이력 조회 불가 시 공급망 전체가 마비될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 멀티 클라우드 또는 Active-Passive 이중화 클라우드 아키텍처 설계. 이력추적 핵심 데이터는 블록체인 또는 분산원장 기술로 불변성 보장. RTO/RPO 목표값을 SLA에 명문화하고 재해복구(DR) 훈련 정기 실시.

### 4. 밸류체인 참여자 간 데이터 표준 미비로 인한 상호운용성 결여

* **설명:** 공급자, 농가, 가공업체, 유통/소매업체가 각기 다른 데이터 포맷과 시스템을 사용할 경우, 서비스 계층의 생산·물류 이력추적 에이전트가 이기종 데이터를 통합하지 못해 소비자에게 전달되는 이력 정보가 불완전해진다. 특히 어업·양봉 등 비전통적 축산 도메인은 표준 코드 체계가 미성숙하다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** ISO 11785(동물 식별), GS1(공급망 데이터 표준), IEC 61968(유틸리티 통합) 등 국제 표준 기반 데이터 모델 정의. 참여자별 어댑터(Adapter) 패턴으로 이기종 시스템 통합 레이어 구축. 공통 API 게이트웨이에 스키마 검증 및 버전 관리 적용.

### 5. 동물 건강 모니터링 알고리즘의 오탐/미탐으로 인한 질병 확산

* **설명:** Animal Health Monitoring 서비스가 머신러닝 모델로 이상 징후를 탐지할 때, 훈련 데이터 편향 또는 계절성 요인을 반영하지 못한 모델이 질병 초기 신호를 미탐(False Negative)하면 농장 내 질병이 조기 차단 없이 확산된다. 반대로 과도한 오탐(False Positive)은 불필요한 격리·치료로 운영 비용을 증가시킨다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 모델 성능 지표(Recall 우선)를 정의하고 축종별·계절별 재학습 파이프라인 구축. 임계값 도달 전 조기 경보 단계(Pre-alert)를 다단계로 설계하여 수의사 확인 프로세스 연계. 모델 예측 결과에 대한 설명 가능 AI(XAI) 도입으로 현장 수의사의 신뢰도 확보.

### 6. 개인정보 및 농업 데이터 주권 침해

* **설명:** 유전·육종 데이터, 농가 생산량·수익 데이터, 공급망 거래 정보는 민감한 영업비밀 및 개인정보를 포함한다. 클라우드 사업자 또는 플랫폼 운영자가 농가 동의 없이 집계 데이터를 제3자에게 제공하거나 상업적으로 활용할 경우, 데이터 주권 침해 및 법적 분쟁이 발생한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 데이터 수집·활용 목적을 계약서에 명문화하고 GDPR/개인정보보호법 준거 데이터 거버넌스 정책 수립. 농가 데이터에 대한 접근 제어(RBAC)를 서비스 계층에서 세분화 적용. 민감 데이터는 동형암호(Homomorphic Encryption) 또는 연합학습(Federated Learning) 기반으로 원본 유출 없이 분석 가능한 구조 도입.
