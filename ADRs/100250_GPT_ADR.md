📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 클라우드-엣지 하이브리드 기반 스마트팜 통합 제어 아키텍처

| 항목                     | 내용                                                                                                                                                                                                                                                       |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 시스템은 관리자 단말(20), 네트워크, 클라우드 서버(200), 농장 제어기(100), 액추에이터(30)로 구성된 스마트팜 통합 제어 구조이다. 관리자 단말은 원격으로 재배 환경을 제어하고, 농장 제어기는 현장의 센서 및 액추에이터를 직접 제어하며 데이터를 생성한다. 클라우드는 농장 데이터를 저장 및 관리하는 역할을 수행한다. 핵심 과제는 원격 제어의 실시간성, 데이터 신뢰성, 네트워크 의존성 최소화, 그리고 확장 가능한 데이터 관리이다. |
| **결정(Decision)**       | 농장 제어기(100)를 엣지 컴퓨팅 노드로 정의하고, 실시간 제어는 엣지에서 수행하며, 데이터 저장 및 분석은 클라우드 서버(200)에서 처리하는 클라우드-엣지 하이브리드 아키텍처를 채택한다. 관리자 단말은 클라우드를 통해 간접 제어를 수행하되, 긴급 상황에서는 엣지 직통 제어 채널을 허용하는 이중 경로 구조를 적용한다.                                                                     |
| **근거(Rationale)**      | 스마트팜은 네트워크 상태에 영향을 받지 않는 안정적인 제어가 필수적이다. 엣지에서 제어를 수행하면 지연을 최소화할 수 있으며, 클라우드는 대규모 데이터 저장 및 분석에 적합하다. 이 구조는 실시간성과 확장성을 동시에 만족시킨다.                                                                                                                          |
| **결과(Consequences)**   | 네트워크 장애 시에도 농장 운영 지속 가능하며, 데이터 분석 및 AI 적용이 용이해진다. 그러나 시스템 구조가 복잡해지고, 엣지-클라우드 간 데이터 동기화 관리가 필요하다.                                                                                                                                                         |
| **트레이드오프(Trade-offs)** | 실시간 제어 안정성 확보(장점) vs 시스템 복잡성 증가(단점), 확장성 및 데이터 활용성 증가(장점) vs 동기화 및 운영 비용 증가(단점)                                                                                                                                                                          |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. 네트워크 장애로 인한 원격 제어 불가

* **설명:** 관리자 단말과 클라우드 또는 농장 간 네트워크 단절 시 원격 제어가 불가능해지는 상황

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 엣지 автоном 제어 로직 구축, 오프라인 모드 지원, 이중 네트워크 구성(LTE/5G + 유선)

### 2. 엣지-클라우드 데이터 불일치

* **설명:** 농장 제어기(엣지)와 클라우드 서버 간 데이터 동기화 지연 또는 실패

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 메시지 큐 기반 비동기 처리(Kafka, MQTT), eventual consistency 적용

### 3. 보안 취약점 (원격 제어 해킹)

* **설명:** 관리자 단말 또는 네트워크를 통한 불법 접근으로 액추에이터 제어가 탈취되는 경우

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 종단 간 암호화(TLS), 다중 인증(MFA), 제어 명령 인증 및 감사 로그 기록

### 4. 농장 제어기 장애 (엣지 노드 다운)

* **설명:** 농장 제어기(100) 고장 시 액추에이터(30) 제어 불능 상태 발생

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 제어기 이중화, 핫스탠바이 구성, 장애 자동 복구 시스템

### 5. 클라우드 서버 장애

* **설명:** 클라우드 서버(200) 장애로 데이터 저장 및 분석 기능 중단

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 멀티 리전 구성, 백업 및 복구 전략, 데이터 캐싱

### 6. 데이터 과부하 및 확장성 문제

* **설명:** 다수 농장에서 발생하는 데이터가 급증하여 클라우드 처리 및 저장 한계 초과

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 데이터 레이크 및 분산 저장(Hadoop, S3), 스트리밍 처리 아키텍처 도입
