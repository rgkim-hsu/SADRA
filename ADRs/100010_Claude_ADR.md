### ADR-001: 식물 생산 통합 플랫폼의 엣지-클라우드 하이브리드 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                   |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 시스템은 현장(300번 블록: 카메라 모듈, 센서)에서 실시간으로 발생하는 영상·환경 데이터를 수집하고, 이를 중앙 ERP(100번 블록) 및 재배 컨설팅 모듈과 연동해야 한다. 온도·습도·CO₂·EC·pH 등 다양한 이기종 센서 데이터와 가시광선·NIR·LWIR 카메라 영상 데이터가 동시에 처리되어야 하며, 네트워크 단절 상황에서도 생산 현장의 제어 연속성이 보장되어야 한다. |
| **결정(Decision)**       | 현장 제어 레이어(200번 블록: 모니터링 & 제어 컨트롤러)를 엣지 노드로 구성하여 실시간 센싱/제어를 로컬에서 처리하고, ERP·머신러닝·영상생육분석 등 연산 집약적 워크로드는 중앙 서버(혹은 클라우드)에서 처리하는 엣지-클라우드 하이브리드 아키텍처를 채택한다. 컴뮤니케이션 레이어(커뮤니케이션 배매 모듈)를 통해 양 레이어 간 데이터를 비동기 메시지 큐 방식으로 연결한다.  |
| **근거(Rationale)**      | ① Window·Screen·Aircon·Nutrient 등 액추에이터 제어는 수십 ms 단위의 응답이 필요하므로 클라우드 왕복 지연을 허용할 수 없다. ② 영상생육분석(생육크기·생육스트레스)과 머신러닝 추론은 GPU 자원이 필요하며 배치 처리가 가능하다. ③ 테스트베드 환경 시뮬레이션(200번 블록)은 설정 변경 주기가 길어 중앙 집중 처리에 적합하다.              |
| **결과(Consequences)**   | (+) 네트워크 장애 시에도 현장 제어 루프가 유지된다. (+) 영상·생육 데이터 분석 품질이 중앙 고성능 인프라를 통해 향상된다. (-) 엣지-중앙 간 데이터 동기화 정합성 관리 복잡도가 증가한다. (-) 엣지 노드의 펌웨어·모델 업데이트를 위한 OTA(Over-The-Air) 관리 체계가 별도로 필요하다.                                        |
| **트레이드오프(Trade-offs)** | **얻는 장점:** 실시간 제어 신뢰성, 오프라인 복원력, 대역폭 절감(엣지 전처리). **감수할 단점:** 이중 인프라 운영 비용 증가, 엣지-클라우드 간 모델 버전 불일치 위험, 분산 시스템 디버깅 복잡성 증대.                                                                                             |

### ADR-002: 멀티모달 센싱 기반 머신러닝 추론 파이프라인 통합

| 항목                     | 내용                                                                                                                                                                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 재배 컨설팅 모듈은 작업/비용·재배환경 데이터를 입력받고, 영상생육분석 모듈은 생육크기·생육스트레스를 판단하기 위해 생육정보를 참조한다. 전문가 Pool과 머신러닝이 병렬로 의사결정을 지원하는 구조이므로, 정형 센서 데이터와 비정형 영상 데이터를 하나의 추론 파이프라인으로 통합해야 한다.                                                               |
| **결정(Decision)**       | 가시광선(color)·NIR·LWIR 카메라의 생목분석용 카메라 모듈을 단일 멀티스펙트럴 데이터 스트림으로 표준화하고, 환경 센서(온도·습도·CO₂·EC·pH) 시계열 데이터와 융합하여 머신러닝 모델의 입력 피처로 사용하는 통합 추론 파이프라인을 구성한다. 복합제어 룰엔진과 머신러닝 추론 결과를 앙상블하여 최종 재배 의사결정을 생성한다.                                   |
| **근거(Rationale)**      | ① 단일 센서만으로는 생육 이상(스트레스, 병해충)을 조기에 탐지하기 어렵고, 멀티모달 융합 시 탐지 정확도가 유의미하게 향상된다. ② LWIR(열화상)은 수분 스트레스, NIR은 엽록소 활성, color는 외형 이상을 각각 포착하므로 상호 보완적이다. ③ 전문가 Pool의 경험적 규칙을 룰엔진으로 보존하면서 ML 모델의 데이터 기반 예측을 병용함으로써 Cold Start 문제를 완화할 수 있다. |
| **결과(Consequences)**   | (+) 생육 이상의 조기 탐지율 향상 및 재배 손실 최소화. (+) 전문가 지식과 데이터 기반 학습이 상호 보완되어 시스템 신뢰도 향상. (-) 멀티모달 데이터의 시간 동기화(time-alignment) 처리가 필수적으로 요구됨. (-) 모델 학습을 위한 레이블링된 생육 데이터 확보 비용이 높음.                                                          |
| **트레이드오프(Trade-offs)** | **얻는 장점:** 높은 탐지 정확도, 설명 가능한 의사결정(룰엔진 병용). **감수할 단점:** 파이프라인 복잡도 증가, 카메라 캘리브레이션·센서 드리프트 관리 부담, 모델 재학습 주기 관리 필요.                                                                                                                 |

### 1. 단일 통신 레이어(커뮤니케이션 배매 모듈) 장애로 인한 전체 시스템 마비

* **설명:** 100번 블록(ERP)과 200번 블록(현장 제어), 300번 블록(센싱) 간의 데이터 흐름이 단일 커뮤니케이션 모듈을 경유하는 구조로, 해당 모듈에 장애 발생 시 재배계획/생산관리 명령이 현장에 전달되지 않고, 영상데이터·센싱 데이터가 ERP로 전송되지 않아 전체 생산 운영이 중단될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 커뮤니케이션 레이어를 Active-Active 이중화로 구성하고, 메시지 브로커(예: Kafka, MQTT Broker)를 클러스터링하여 SPOF(Single Point of Failure)를 제거한다. 엣지 노드에 로컬 메시지 큐를 두어 통신 단절 시 데이터를 로컬 버퍼링한 후 복구 시 재전송하는 Store-and-Forward 패턴을 적용한다.

* * *

### 2. 멀티스펙트럴 카메라 모듈의 환경 노출로 인한 데이터 품질 저하

* **설명:** 가시광선·NIR·LWIR 카메라(300번 블록)는 온실 내 고온다습 환경에 상시 노출된다. 렌즈 김서림, 센서 열화, 먼지 오염으로 인해 영상 품질이 점진적으로 저하될 경우, 영상생육분석 모듈이 생육크기·스트레스를 오판하여 잘못된 재배 처방이 내려질 수 있다. 특히 LWIR(열화상) 센서는 온도 드리프트에 민감하여 무보정 시 수분 스트레스 감지 오류가 발생할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 카메라별 자동 품질 지표(blur score, 히스토그램 분포, NUC 주기 적용) 모니터링 파이프라인을 구축하고, 임계값 이하 이미지는 추론에서 자동 제외한다. 정기적 캘리브레이션 스케줄과 방진·방습 하우징 적용을 의무화하며, 이상 감지 시 대시보드 경보를 자동 발송한다.

* * *

### 3. 머신러닝 모델의 도메인 시프트(Domain Shift)로 인한 예측 성능 저하

* **설명:** 머신러닝 모델이 특정 작물·계절·시설 환경 데이터로 학습된 경우, 재배 품종 변경, 계절 전환, 신규 시설 도입 시 학습 분포와 실제 운영 분포 간 괴리(Domain Shift)가 발생한다. 이로 인해 재배 컨설팅 모듈의 생산정보·환경정보 추천이 부정확해져 수확량 감소 또는 과잉 투입(Nutrient, 에너지) 문제가 야기될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 모델 예측값과 실제 수확 결과를 지속 비교하는 모델 모니터링(Data Drift Detection) 파이프라인을 구축한다. 품종·시즌 변경 시점에 자동으로 재학습 트리거를 발동하는 MLOps 체계를 도입하고, 전문가 Pool의 검수를 통한 Human-in-the-Loop 구조를 단기적 안전망으로 유지한다.

* * *

### 4. 원가관리·이력관리 데이터의 무결성 침해 및 사이버 보안 위협

* **설명:** ERP 내 원가관리·종사 일지·품질관리 등의 데이터는 생산 원가 산정과 법적 이력 추적에 직결된다. 외부 공격자가 커뮤니케이션 레이어를 통해 내부 네트워크에 침투하거나, 엣지 노드(모니터링 & 제어 컨트롤러)가 물리적으로 탈취·조작될 경우 센서 데이터 위변조 또는 액추에이터(Aircon, Nutrient) 무단 제어가 가능하며, 생산 데이터 무결성이 손상된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 엣지-중앙 간 통신에 TLS 1.3 상호 인증(mTLS)을 적용하고, 엣지 노드에 TPM(Trusted Platform Module) 기반 디바이스 인증을 도입한다. ERP 접근은 역할 기반 접근 제어(RBAC)와 다중 인증(MFA)으로 보호하며, 원가·이력 데이터는 불변 로그(Immutable Audit Log)로 별도 저장한다. 네트워크는 OT/IT 분리 원칙에 따라 현장 제어망과 업무망을 논리적으로 격리한다.

* * *

### 5. 테스트베드 환경 시뮬레이션과 실제 생산 환경 간의 설정 불일치

* **설명:** 200번 블록의 테스트베드 시뮬레이션 결과를 기반으로 도출된 재배 파라미터(온도·습도·CO₂·EC·pH 목표값)가 실제 생산 현장에 그대로 적용될 경우, 시뮬레이션 모델의 가정(단순화된 열·유체 모델 등)과 실제 온실의 물리적 특성 차이로 인해 제어 목표값과 실제 환경 간 지속적 편차가 발생할 수 있다. 이 편차가 누적되면 생육 불량, 에너지 과다 소비, Nutrient 과투입으로 이어진다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 시뮬레이션 모델과 실제 센서 계측값 간의 편차를 주기적으로 비교하는 Model-Reality Gap 모니터링 지표를 정의하고 대시보드에 시각화한다. Digital Twin 방식을 도입하여 실측 데이터로 시뮬레이션 파라미터를 지속 보정(Calibration Loop)하는 피드백 구조를 구축한다. 신규 파라미터 적용 전 A/B 구획 테스트를 의무화하여 리스크를 격리한다.

* * *

### 6. 복합제어 룰엔진과 머신러닝 추론 결과 간의 충돌로 인한 제어 불확실성

* **설명:** 복합제어 룰엔진(전문가 규칙 기반)과 머신러닝 추론이 동일한 액추에이터(예: Aircon, Nutrient 공급량)에 대해 상반된 제어 명령을 동시에 생성할 경우, 시스템이 어느 명령을 우선할지 결정하는 중재 로직이 없으면 액추에이터가 진동(Oscillation) 상태에 빠지거나, 두 명령이 교번 적용되어 작물이 급격한 환경 변동에 노출될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 룰엔진과 ML 추론 결과를 통합하는 의사결정 중재 레이어(Decision Arbitration Layer)를 명시적으로 설계하고, 충돌 시 안전 우선 원칙(Fail-Safe Rule: 룰엔진 우선)을 적용한다. 충돌 이벤트는 전량 로깅하여 전문가 Pool의 주기적 검토에 반영하고, 충돌 빈도가 임계값을 초과하면 자동으로 ML 모델 재검토 알림을 발송한다.

| **상황(Context)**        | 시스템은 현장(300번 블록: 카메라 모듈, 센서)에서 실시간으로 발생하는 영상·환경 데이터를 수집하고, 이를 중앙 ERP(100번 블록) 및 재배 컨설팅 모듈과 연동해야 한다. 온도·습도·CO₂·EC·pH 등 다양한 이기종 센서 데이터와 가시광선·NIR·LWIR 카메라 영상 데이터가 동시에 처리되어야 하며, 네트워크 단절 상황에서도 생산 현장의 제어 연속성이 보장되어야 한다. |
| **결정(Decision)**       | 현장 제어 레이어(200번 블록: 모니터링 & 제어 컨트롤러)를 엣지 노드로 구성하여 실시간 센싱/제어를 로컬에서 처리하고, ERP·머신러닝·영상생육분석 등 연산 집약적 워크로드는 중앙 서버(혹은 클라우드)에서 처리하는 엣지-클라우드 하이브리드 아키텍처를 채택한다. 컴뮤니케이션 레이어(커뮤니케이션 배매 모듈)를 통해 양 레이어 간 데이터를 비동기 메시지 큐 방식으로 연결한다.  |
| **근거(Rationale)**      | ① Window·Screen·Aircon·Nutrient 등 액추에이터 제어는 수십 ms 단위의 응답이 필요하므로 클라우드 왕복 지연을 허용할 수 없다. ② 영상생육분석(생육크기·생육스트레스)과 머신러닝 추론은 GPU 자원이 필요하며 배치 처리가 가능하다. ③ 테스트베드 환경 시뮬레이션(200번 블록)은 설정 변경 주기가 길어 중앙 집중 처리에 적합하다.              |
| **결과(Consequences)**   | (+) 네트워크 장애 시에도 현장 제어 루프가 유지된다. (+) 영상·생육 데이터 분석 품질이 중앙 고성능 인프라를 통해 향상된다. (-) 엣지-중앙 간 데이터 동기화 정합성 관리 복잡도가 증가한다. (-) 엣지 노드의 펌웨어·모델 업데이트를 위한 OTA(Over-The-Air) 관리 체계가 별도로 필요하다.                                        |
| **트레이드오프(Trade-offs)** | **얻는 장점:** 실시간 제어 신뢰성, 오프라인 복원력, 대역폭 절감(엣지 전처리). **감수할 단점:** 이중 인프라 운영 비용 증가, 엣지-클라우드 간 모델 버전 불일치 위험, 분산 시스템 디버깅 복잡성 증대.                                                                                             |

### ADR-002: 멀티모달 센싱 기반 머신러닝 추론 파이프라인 통합

| 항목                     | 내용                                                                                                                                                                                                                              |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 재배 컨설팅 모듈은 작업/비용·재배환경 데이터를 입력받고, 영상생육분석 모듈은 생육크기·생육스트레스를 판단하기 위해 생육정보를 참조한다. 전문가 Pool과 머신러닝이 병렬로 의사결정을 지원하는 구조이므로, 정형 센서 데이터와 비정형 영상 데이터를 하나의 추론 파이프라인으로 통합해야 한다.                                                               |
| **결정(Decision)**       | 가시광선(color)·NIR·LWIR 카메라의 생목분석용 카메라 모듈을 단일 멀티스펙트럴 데이터 스트림으로 표준화하고, 환경 센서(온도·습도·CO₂·EC·pH) 시계열 데이터와 융합하여 머신러닝 모델의 입력 피처로 사용하는 통합 추론 파이프라인을 구성한다. 복합제어 룰엔진과 머신러닝 추론 결과를 앙상블하여 최종 재배 의사결정을 생성한다.                                   |
| **근거(Rationale)**      | ① 단일 센서만으로는 생육 이상(스트레스, 병해충)을 조기에 탐지하기 어렵고, 멀티모달 융합 시 탐지 정확도가 유의미하게 향상된다. ② LWIR(열화상)은 수분 스트레스, NIR은 엽록소 활성, color는 외형 이상을 각각 포착하므로 상호 보완적이다. ③ 전문가 Pool의 경험적 규칙을 룰엔진으로 보존하면서 ML 모델의 데이터 기반 예측을 병용함으로써 Cold Start 문제를 완화할 수 있다. |
| **결과(Consequences)**   | (+) 생육 이상의 조기 탐지율 향상 및 재배 손실 최소화. (+) 전문가 지식과 데이터 기반 학습이 상호 보완되어 시스템 신뢰도 향상. (-) 멀티모달 데이터의 시간 동기화(time-alignment) 처리가 필수적으로 요구됨. (-) 모델 학습을 위한 레이블링된 생육 데이터 확보 비용이 높음.                                                          |
| **트레이드오프(Trade-offs)** | **얻는 장점:** 높은 탐지 정확도, 설명 가능한 의사결정(룰엔진 병용). **감수할 단점:** 파이프라인 복잡도 증가, 카메라 캘리브레이션·센서 드리프트 관리 부담, 모델 재학습 주기 관리 필요.                                                                                                                 |

⚠️ 잠재적 위험 분석
------------

### 1. 단일 통신 레이어(커뮤니케이션 배매 모듈) 장애로 인한 전체 시스템 마비

* **설명:** 100번 블록(ERP)과 200번 블록(현장 제어), 300번 블록(센싱) 간의 데이터 흐름이 단일 커뮤니케이션 모듈을 경유하는 구조로, 해당 모듈에 장애 발생 시 재배계획/생산관리 명령이 현장에 전달되지 않고, 영상데이터·센싱 데이터가 ERP로 전송되지 않아 전체 생산 운영이 중단될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 커뮤니케이션 레이어를 Active-Active 이중화로 구성하고, 메시지 브로커(예: Kafka, MQTT Broker)를 클러스터링하여 SPOF(Single Point of Failure)를 제거한다. 엣지 노드에 로컬 메시지 큐를 두어 통신 단절 시 데이터를 로컬 버퍼링한 후 복구 시 재전송하는 Store-and-Forward 패턴을 적용한다.

* * *

### 2. 멀티스펙트럴 카메라 모듈의 환경 노출로 인한 데이터 품질 저하

* **설명:** 가시광선·NIR·LWIR 카메라(300번 블록)는 온실 내 고온다습 환경에 상시 노출된다. 렌즈 김서림, 센서 열화, 먼지 오염으로 인해 영상 품질이 점진적으로 저하될 경우, 영상생육분석 모듈이 생육크기·스트레스를 오판하여 잘못된 재배 처방이 내려질 수 있다. 특히 LWIR(열화상) 센서는 온도 드리프트에 민감하여 무보정 시 수분 스트레스 감지 오류가 발생할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 카메라별 자동 품질 지표(blur score, 히스토그램 분포, NUC 주기 적용) 모니터링 파이프라인을 구축하고, 임계값 이하 이미지는 추론에서 자동 제외한다. 정기적 캘리브레이션 스케줄과 방진·방습 하우징 적용을 의무화하며, 이상 감지 시 대시보드 경보를 자동 발송한다.

* * *

### 3. 머신러닝 모델의 도메인 시프트(Domain Shift)로 인한 예측 성능 저하

* **설명:** 머신러닝 모델이 특정 작물·계절·시설 환경 데이터로 학습된 경우, 재배 품종 변경, 계절 전환, 신규 시설 도입 시 학습 분포와 실제 운영 분포 간 괴리(Domain Shift)가 발생한다. 이로 인해 재배 컨설팅 모듈의 생산정보·환경정보 추천이 부정확해져 수확량 감소 또는 과잉 투입(Nutrient, 에너지) 문제가 야기될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 모델 예측값과 실제 수확 결과를 지속 비교하는 모델 모니터링(Data Drift Detection) 파이프라인을 구축한다. 품종·시즌 변경 시점에 자동으로 재학습 트리거를 발동하는 MLOps 체계를 도입하고, 전문가 Pool의 검수를 통한 Human-in-the-Loop 구조를 단기적 안전망으로 유지한다.

* * *

### 4. 원가관리·이력관리 데이터의 무결성 침해 및 사이버 보안 위협

* **설명:** ERP 내 원가관리·종사 일지·품질관리 등의 데이터는 생산 원가 산정과 법적 이력 추적에 직결된다. 외부 공격자가 커뮤니케이션 레이어를 통해 내부 네트워크에 침투하거나, 엣지 노드(모니터링 & 제어 컨트롤러)가 물리적으로 탈취·조작될 경우 센서 데이터 위변조 또는 액추에이터(Aircon, Nutrient) 무단 제어가 가능하며, 생산 데이터 무결성이 손상된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 엣지-중앙 간 통신에 TLS 1.3 상호 인증(mTLS)을 적용하고, 엣지 노드에 TPM(Trusted Platform Module) 기반 디바이스 인증을 도입한다. ERP 접근은 역할 기반 접근 제어(RBAC)와 다중 인증(MFA)으로 보호하며, 원가·이력 데이터는 불변 로그(Immutable Audit Log)로 별도 저장한다. 네트워크는 OT/IT 분리 원칙에 따라 현장 제어망과 업무망을 논리적으로 격리한다.

* * *

### 5. 테스트베드 환경 시뮬레이션과 실제 생산 환경 간의 설정 불일치

* **설명:** 200번 블록의 테스트베드 시뮬레이션 결과를 기반으로 도출된 재배 파라미터(온도·습도·CO₂·EC·pH 목표값)가 실제 생산 현장에 그대로 적용될 경우, 시뮬레이션 모델의 가정(단순화된 열·유체 모델 등)과 실제 온실의 물리적 특성 차이로 인해 제어 목표값과 실제 환경 간 지속적 편차가 발생할 수 있다. 이 편차가 누적되면 생육 불량, 에너지 과다 소비, Nutrient 과투입으로 이어진다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 시뮬레이션 모델과 실제 센서 계측값 간의 편차를 주기적으로 비교하는 Model-Reality Gap 모니터링 지표를 정의하고 대시보드에 시각화한다. Digital Twin 방식을 도입하여 실측 데이터로 시뮬레이션 파라미터를 지속 보정(Calibration Loop)하는 피드백 구조를 구축한다. 신규 파라미터 적용 전 A/B 구획 테스트를 의무화하여 리스크를 격리한다.

* * *

### 6. 복합제어 룰엔진과 머신러닝 추론 결과 간의 충돌로 인한 제어 불확실성

* **설명:** 복합제어 룰엔진(전문가 규칙 기반)과 머신러닝 추론이 동일한 액추에이터(예: Aircon, Nutrient 공급량)에 대해 상반된 제어 명령을 동시에 생성할 경우, 시스템이 어느 명령을 우선할지 결정하는 중재 로직이 없으면 액추에이터가 진동(Oscillation) 상태에 빠지거나, 두 명령이 교번 적용되어 작물이 급격한 환경 변동에 노출될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 룰엔진과 ML 추론 결과를 통합하는 의사결정 중재 레이어(Decision Arbitration Layer)를 명시적으로 설계하고, 충돌 시 안전 우선 원칙(Fail-Safe Rule: 룰엔진 우선)을 적용한다. 충돌 이벤트는 전량 로깅하여 전문가 Pool의 주기적 검토에 반영하고, 충돌 빈도가 임계값을 초과하면 자동으로 ML 모델 재검토 알림을 발송한다.
