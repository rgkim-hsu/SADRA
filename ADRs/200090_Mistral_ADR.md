📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: **다중 의사결정 트리 기반 분류/예측 시스템 채택**

| 항목                     | 내용                                                                                                                                                                                                                                                                                                                   |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 분야에서 다양한 센서 및 시초데이터(시작 데이터)를 기반으로 실시간으로 작물 상태를 분류하고 예측해야 하는 요구사항이 존재. 단일 모델로는 복잡한 환경 변수(온도, 습도, 조도 등)를 모두 반영하기 어려움.                                                                                                                                                                                             |
| **결정(Decision)**       | **다중 의사결정 트리(Tree (a), Tree (b), ..., Tree (n))**를 병렬로 구축하여 각 트리가 특정 클래스(Class 1, Class 2 등) 또는 특성을 담당하도록 설계. 각 트리는 독자적으로 학습되며, 최종 분류/예측 결과는 트리들의 앙상블(ensemble) 또는 투표(voting) 메커니즘을 통해 도출.                                                                                                                           |
| **근거(Rationale)**      | 1. **유연성**: 각 트리가 특정 조건(예: 온도 범위, 습도 패턴)에 특화되어, 스마트팜의 다변량 환경에 적응 가능.<br><br>2. **확장성**: 새로운 센서 데이터나 클래스가 추가되어도, 기존 트리 구조를 유지하면서 새로운 트리를 추가할 수 있음.<br><br>3. **해석 가능성**: 트리 기반 모델은 규칙 기반으로 동작하여, 사용자가 의사결정 과정을 이해하고 검증하기 용이.<br><br>4. **스마트팜 표준**: ISO 25237(IoT 기반 스마트팜 표준) 및 FAO의 스마트 농업 가이드라인에서 다중 모델 통합 접근법을 권장. |
| **결과(Consequences)**   | **장점**:<br><br>- 높은 정확도로 다양한 환경 변수를 반영한 분류/예측 가능.<br><br>- 시스템 오류 시 특정 트리만 교체/수정 가능.<br><br> **단점**:<br><br>- 트리 수가 늘어나면 계산 복잡도 및 리소스 사용량이 증가.<br><br>- 트리 간 중복 학습 가능성.                                                                                                                                              |
| **트레이드오프(Trade-offs)** | **获得**: 고정밀 분류/예측, 유연성, 확장성.<br><br> **상실**: 계산 리소스 증가, 모델 관리 복잡성.                                                                                                                                                                                                                                                   |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. **트리 간 데이터 편향성(Data Skew between Trees)**

* **설명:** 특정 트리(예: Tree (a))가 특정 클래스(Class 1)에 과도하게 최적화되어, 다른 트리에서 해당 클래스를 무시하는 현상이 발생할 경우, 앙상블 결과가 편향될 수 있음.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:**
  * 트리별로 학습 데이터를 균등하게 분배하는 **스트라티파이드 샘플링(Stratified Sampling)** 적용.
  * 주기적인 **트리 성능 모니터링** 및 재학습을 통해 편향성 조절.

* * *

### 2. **실시간 데이터 처리 지연(Real-time Processing Latency)**

* **설명:** 다중 트리를 병렬로 실행할 경우, 특히 IoT 센서에서 대량의 시초데이터가 유입될 때, 분류/예측 결과가 지연되어 실시간성 요건을 충족하지 못함.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:**
  * **에지 컴퓨팅(Edge Computing)** 도입으로 트리 모델을 로컬 디바이스에서 실행.
  * **모델 경량화(Quantization, Pruning)**를 통해 계산량 감소.
  * **스트리밍 데이터 처리 프레임워크**(예: Apache Kafka + Flink) 활용.

* * *

### 3. **모델 해석성 저하(Lack of Interpretability)**

* **설명:** 다중 트리의 앙상블 결과가 복잡해질 경우, 사용자가 특정 결정(예: "Class 2로 분류된 이유")을 이해하기 어려워져 신뢰성이 하락.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:**
  * **SHAP(SHapley Additive exPlanations)** 또는 **LIME(Local Interpretable Model-agnostic Explanations)** 도구로 각 트리의 기여도 시각화.
  * **규칙 기반 설명 생성 모듈** 추가 (예: "Tree (b)가 습도 > 70% 조건으로 Class 2 선택").

* * *

### 4. **센서 데이터 오류 전파(Sensor Data Error Propagation)**

* **설명:** 시초데이터에 노이즈나 결측치가 포함될 경우, 모든 트리에 오류가 전파되어 분류/예측 정확도가 급격히 저하.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:**
  * **데이터 전처리 파이프라인** 구축 (예: 이동 평균 필터, 이상치 탐지 알고리즘).
  * **센서 중복 배치**로 교차 검증 (예: 온도 센서 2개 이상 사용).

* * *

### 5. **보안 취약점(security Vulnerabilities in Model Inference)**

* **설명:** 악의적인 사용자가 시초데이터를 조작하여 트리 모델을 속여 잘못된 분류/예측 결과를 유도할 수 있음 (예: Adversarial Attack).
* **심각도:** 🔴 High
* **발생 가능성:** 🟢 Low
* **대응 방안:**
  * **입력 데이터 검증** (예: 범위 체크, 통계적 이상치 탐지).
  * **모델 하드닝(Model Hardening)** 기술 적용 (예: Adversarial Training).
  * **블록체인 기반 데이터 무결성 확인** (스마트팜 IoT 데이터의 불변성 보장).

* * *

### 6. **모델 유지보수 복잡성(Model Maintenance Complexity)**

* **설명:** 트리 수가 늘어나고, 각 트리의 학습 데이터가 변화할 경우, 시스템 유지보수 및 업데이트가 복잡해짐.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:**
  * **MLOps 파이프라인** 도입 (예: MLflow, Kubeflow)을 통해 모델 버전 관리 및 자동 재학습.
  * **모듈식 아키텍처**로 각 트리를 독립적으로 배포 및 업데이트 가능하도록 설계.
