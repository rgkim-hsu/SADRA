# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 하이브리드 연결 프로토콜을 활용한 범용 사물인터넷(IoT) 게이트웨이 및 웹 기반 서비스 통합

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 농식품 비즈니스 에코시스템 내의 다양한 생산 환경에서 발생하는 이기종 장치(Bluetooth, Wi-Fi, Data Matrix/Barcode)들로부터 데이터를 수집하고, 이를 글로벌 표준(GS1 등)에 따라 통합 관리해야 함. 특히 현장 작업자의 편의성을 위해 단일 모바일 인터페이스에서 다각적인 연결 방식을 지원해야 하는 과제가 있음. |
| **결정(Decision)** | 모바일 애플리케이션을 중앙 게이트웨이로 활용하며, **Multi-Modal Scanning (BLE, Wi-Fi, Image Recognition)** 아키텍처를 채택함. 최종 데이터 소비 및 서비스 제어는 하이브리드 앱 내의 **WebView**를 통해 처리하여 서버 사이드 업데이트만으로 클라이언트의 비즈니스 로직을 동적으로 확장하도록 설계함. |
| **근거(Rationale)** | 1. 장치별로 상이한 통신 규격(PAN/WLAN)을 수용하기 위해 모바일 기기의 하드웨어 자원을 적극 활용함. <br> 2. Data Matrix 스캔 시 URL이 포함된 경우 즉시 웹 서비스로 라우팅하여 연결 지연시간을 최소화함. <br> 3. 글로벌 표준화를 위해 국가/언어 설정 정보를 메타데이터로 활용하여 서비스 리스트를 필터링함. |
| **결과(Consequences)** | 긍정적: 현장 장치 등록 및 연결 프로세스의 단순화, 웹 기반 인터페이스를 통한 유연한 서비스 확장성 확보. <br> 부정적: 모바일 기기의 백그라운드 프로세스 부하 증가 및 WebView 성능에 따른 사용자 경험(UX) 차이 발생 가능성. |
| **트레이드오프(Trade-offs)** | 고성능 네이티브 인터페이스 대신 WebView를 선택함으로써 개발 속도와 유지보수 효율성을 얻었으나, 오프라인 환경에서의 동작 제한 및 네이티브 하드웨어 가속 활용도 저하를 감수함. |

---

## ⚠️ 잠재적 위험 분석

### 1. 근거리 무선 통신 간섭 및 연결 불안정
- **설명:** Bluetooth와 Wi-Fi 스캔이 동시에 수행되거나 열악한 농업 현장 환경에서 전파 간섭으로 인해 장치 식별이 지연되거나 실패하는 시나리오
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 재시도 로직(Exponential Backoff) 구현 및 신호 강도(RSSI) 임계값 설정을 통한 유효 장치 우선순위 지정

### 2. URL 기반 웹뷰 라우팅의 보안 취약점
- **설명:** Data Matrix 스캔을 통해 획득한 URL이 악성 사이트이거나 변조된 경우, WebView를 통해 피싱이나 데이터 유출이 발생할 수 있는 시나리오
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 화이트리스트 기반의 도메인 검증 절차 도입 및 SSL 인증서 고정(Certificate Pinning) 적용

### 3. 언어 및 국가 설정의 정합성 오류
- **설명:** 사용자가 설정한 언어/국가 정보와 실제 장치가 제공하는 서비스 규격이 불일치하여 잘못된 서비스 리스트가 출력되거나 데이터 처리가 거부되는 시나리오
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** GS1 표준 식별자와 국가 코드를 매핑하는 중앙 집중식 마스터 데이터 관리(MDM) 시스템 구축

### 4. 모바일 기기 파편화에 따른 하드웨어 호환성
- **설명:** 저사양 안드로이드 기기나 특정 OS 버전에서 카메라 포커싱 문제로 Data Matrix 인식이 불가능하거나 BLE 스캔 성능이 저하되는 시나리오
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 다양한 하드웨어 프로파일에 최적화된 오픈소스 스캔 라이브러리(ZXing/ML Kit) 적용 및 성능 최적화

### 5. 실시간 데이터 동기화 지연 (WebView Context)
- **설명:** 장치 연결 후 WebView 내에서 수행되는 비즈니스 로직과 실제 물리적 장치 간의 상태 동기화가 네트워크 지연으로 인해 일치하지 않아 잘못된 제어 명령이 내려지는 시나리오
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** WebSocket 또는 MQTT 프로토콜을 활용한 양방향 실시간 통신 채널 확보 및 로컬 캐싱 전략 수립
