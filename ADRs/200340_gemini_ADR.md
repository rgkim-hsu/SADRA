# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: OCF(Open Connectivity Foundation) 표준 기반의 이기종 IoT 통합 프레임워크 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 화재 안전 시스템은 다양한 제조사의 센서(연기, 열, 불꽃 등)와 통신 기술(Wi-Fi, ZigBee, Bluetooth 등)이 혼재된 환경에서 구축됨. 각 장치 간 상호운용성(Interoperability) 결여는 데이터 수집의 병목을 초래하고 실시간 대응력을 저하시키는 핵심 과제임. |
| **결정(Decision)** | 기기 간 연결성을 보장하기 위해 **OCF Conceptual Framework**를 아키텍처의 근간으로 채택함. Resource Model 기반의 RESTful 인터페이스를 활용하여 데이터 모델을 표준화하고, 단일한 Security/Identity 계층을 통해 통합 관리함. |
| **근거(Rationale)** | OCF는 'oneIoTa' 데이터 모델을 통해 이기종 장치 간의 데이터 형식을 규격화하며, 이미지에 명시된 Transports 계층(Wi-Fi, Z-Wave, ZigBee 등)에 관계없이 추상화된 추론 및 제어가 가능하기 때문임. 특히 화재 안전과 같은 산업(Industrial) 프로파일 지원이 강력함. |
| **결과(Consequences)** | **긍정적:** 신규 센서 추가 시 개발 공수 감소, 시스템 확장성 확보, 보안 정책의 일관성 유지. **부정적:** OCF 스택 구현을 위한 초기 학습 곡선 발생, 리소스가 제한된 저사양 임베디드 기기에서의 오버헤드 발생 가능성. |
| **트레이드오프(Trade-offs)** | 표준 준수를 통한 **범용성 및 유지보수 편의성**을 얻는 대신, 고유 프로토콜 대비 약간의 **통신 오버헤드와 초기 시스템 복잡도**를 수용함. |

---

## ⚠️ 잠재적 위험 분석

### 1. 이기종 프로토콜 간 게이트웨이 병목 현상
- **설명:** Wi-Fi, ZigBee, Bluetooth 등 서로 다른 전송 계층 데이터를 OCF 코어 프레임워크로 변환하는 과정에서 부하가 집중되어 실시간 화재 알림이 지연되는 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 고성능 엣지 게이트웨이를 도입하고, 데이터 변환 프로세스를 병렬화하며 화재 감지 이벤트에 최우선 순위(QoS)를 부여함.

### 2. 표준 데이터 모델(oneIoTa)과 실제 센서 데이터의 불일치
- **설명:** 특정 제조사의 비표준 특수 센서 데이터가 oneIoTa 표준 모델에 매핑되지 않아 핵심 정보(예: 유독가스 농도 상세치)가 누락되는 시나리오.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 표준 모델을 확장한 사용자 정의 리소스 타입을 정의하고, 장치 프로파일링 단계에서 데이터 정합성 검증 프로세스를 강화함.

### 3. 통합 보안 및 권한 계층의 단일 장애점(SPOF) 위험
- **설명:** Core Framework 내 'Security, Identity & Permissions' 모듈에 장애가 발생하여 모든 하위 트랜스포트 계층의 장치 제어 및 데이터 수집이 차단되는 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 보안 인증 서버의 이중화(High Availability) 구성 및 로컬 모드에서의 긴급 작동을 위한 오프라인 인증 캐싱 메커니즘 구축.

### 4. 산업 현장의 전파 간섭으로 인한 통신 신뢰성 저하
- **설명:** Industrial 프로파일 적용 지역 내 대형 기계 장비의 노이즈로 인해 ZigBee나 Wi-Fi 통신이 두절되어 화재 징후를 놓치는 시나리오.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** Mesh Network 구성을 통한 통신 경로 다변화 및 중요 지점에 유선(Ethernet) 백업 라인 구축.

### 5. 대규모 센서 네트워크의 프로비저닝(Provisioning) 복잡도
- **설명:** 수백 개 이상의 센서가 동시에 연결될 때 Provisioning 계층의 처리 한계로 인해 초기 설정이나 장치 교체 시 시스템 다운타임이 길어지는 시나리오.
- **심각도:** 🟢 Low
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 배치(Batch) 등록 툴 개발 및 제로 터치 프로비저닝(Zero-touch Provisioning) 기술을 적용하여 자동화 수준을 높임.
