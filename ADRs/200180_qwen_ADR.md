## 📋 ADR (Architecture Decision Record)

### ADR-001: [하이브리드 엣지-클라우드 제어 아키텍처 선택]

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 `<농축사 공간>` 의 실시간 환경 데이터 수집과 제어뿐만 아니라, `<생육환경정보관리 시스템>` 을 통해 웹/스마트폰을 통한 원격 제어도 동시에 지원해야 함. |
| **결정(Decision)** | **분리된 기능 모듈링 및 계층적 아키텍처 채택**<br>1. **물리적 제어 계층:** `<농축사 공간>` 내부에 센서와 입력/출력 모듈을 통합하여 실시간 제어 로직 (`누에 사육용 환경 제어 시스템`) 을 실행.<br>2. **관리 및 정보 계층:** 상단에 `<생육환경정보관리 시스템>` 을 배치하여 데이터 생성, 웹/모바일 인터페이스 제공 및 외부 수동 제어 요청 (`수동 제어 요청`) 을 중재하는 역할을 부여. |
| **근거(Rationale)** | - **지연성 최적화:** `<농축사 공간>` 내부의 센서 데이터 처리와 제어 명령은 `입력 모듈`과 `출력 모듈`을 통해 로컬에서 처리해야 급격한 환경 변화에 즉각 반응.<br>- **중앙 집중식 관리:** 상단 `<생육환경정보관리 시스템>` 이 데이터를 수집하고 분석하여 대용량 데이터 처리와 다중 사용자 인터페이스를 제공하는 것이 효율적.<br>- **문서 기반:** TTA 표준 과제 (No.4, No.5) 와 ISO/IEC 30141:2024 의 계층적 설계 원칙과 부합함. |
| **결과(Consequences)** | **긍정적:** 시스템 가용성 (Availability) 향상 및 유지보수 용이.<br>**부정적:** 상/하 계층 간 통신 네트워크 안정성이 전체 시스템 성능에 미치는 영향이 큼. |
| **트레이드오프(Trade-offs)** | 단순한 엣지 제어 vs 복잡한 중앙 클라우드 의존성. |

### ADR-002: [표준화된 IoT 프로토콜 및 센서 인터페이스 적용]

| 항목 | 내용 |
|------|------|
| **상황(Context)** | `<입력 모듈>` 은 온도, 습도, CO2 등 다양한 센서 데이터를 수집해야 하며, 영상 정보도 `<출력 모듈>` 경로로 인터넷으로 전송해야 함. |
| **결정(Decision)** | **개방형 센서 인터페이스 및 표준 프로토콜 사용**<br>`온도 센서`, `습도 센서`, `CO2 센서` 및 `영상 획득 장치`는 표준화된 통신 프로토콜 (예: MQTT, IETF CoAP 등) 을 사용하여 `<누에 사육용 환경 제어 시스템>` 과 통신하도록 설계.<br>TTA 표준 목록 (No.13, No.1) 의 인터페이스 규격 준수. |
| **근거(Rationale)** | - **상호 운용성:** 다양한 벤더의 센서를 지원하기 위해 표준 인터페이스 필수.<br>- **확장성:** 향후 추가 센서 (예: 질병 감지 센서) 를 연결할 때 하드코딩되지 않도록 설계.<br>- **보안:** ITU-T X.1352 및 ETSI EN 303 645의 보안 요구사항을 충족하는 프로토콜 선택. |
| **결과(Consequences)** | **긍정적:** 센서 교체 및 시스템 확장이 용이해짐.<br>**부정적:** 표준 준수 과정이 초기 개발 시간과 비용 증가 유발 가능. |
| **트레이드오프(Trade-offs)** | 개발 속도 vs 유연성과 상호 운용성. |

## ⚠️ 잠재적 위험 분석

### 1. [네트워크 지연 및 단절 위험]
- **설명:** `<농축사 공간>` 과 `<생육환경정보관리 시스템>`(또는 인터넷) 사이의 통신이 불안정하거나 끊길 경우, `<수동 제어 요청>` 이 지연되거나 제어 명령이 실패할 수 있음. 특히 영상 정보 전송 시 대역폭 부족으로 모니터링 기능 마비 가능.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium (통신 장애 및 네트워크 부하 발생 가능)
- **대응 방안:**
    - **에지 컴퓨팅 강화:** `<누에 사육용 환경 제어 시스템>` 로컬에서 자율 제어 로직을 독립적으로 운영하여 네트워크 오프라인 시에도 기본 환경 제어 (`온도`, `CO2` 등) 를 유지하도록 설계.
    - **큐 시스템 적용:** 지연된 제어 명령을 버퍼링하고 네트워크 복구 시 우선 순위에 따라 재전송 (예: MQTT QoS 1 이상 사용).

### 2. [센서 데이터 무결성 및 정확성 위험]
- **설명:** `<입력 모듈>` 내의 `온도 센서`, `습도 센서`, `CO2 센서` 가 고장 나거나 환경적 요인 (오염, 온도 급변) 으로 인해 부정확한 데이터를 생성하면 `<누에 사육용 환경 제어 시스템>` 이 잘못된 제어 (`출력 모듈` 활성) 를 수행하여 농축사 환경 악화.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium (하드웨어 수명 및 환경 요인)
- **대응 방안:**
    - **데이터 중복校验:** 다중 센서 배치 또는 센서 데이터 이상치 (Outlier) 감지 알고리즘 적용.
    - **정기 교정:** TTA 표준 (No.12 등) 에 준拠하여 정기적인 센서 교정 및 교체 계획 수립.

### 3. [원격 제어의 보안 침해 위험]
- **설명:** 웹 또는 스마트폰을 통한 `<수동 제어 요청>` 경로가 해킹되거나 무단 접근이 발생하여, 의도하지 않은 환경 제어 명령 (예: 난방 전동 개폐) 이 실행되어 생체 자산 손실.
- **심각도:** 🔴 High
- **발생 가능성:** 🟠 Medium (보안 업데이트 부재 시)
- **대응 방안:**
    - **보안 표준 준수:** ITU-T X.1352 및 ETSI EN 303 645 요구사항을 준수한 인증서 (SSL/TLS) 적용 및 양인 인증 (Mutual Authentication) 적용.
    - **접근 제어 (IAM):** 관리자 권한을 웹/스마트폰 계정에 적절히 부여하고, IP 화이트리스트 및 2FA(2 단계 인증) 도입.

### 4. [영상 데이터 전송 대역폭 과부하 위험]
- **설명:** `<출력 모듈>` 과 `영상 획득 장치` 를 통해 생성된 고화질 영상 정보가 `인터넷` 으로 실시간 스트리밍 될 때, 네트워크 대역폭이 제한되어 시스템 성능 저하 또는 끊김 현상 발생.
- **심격도:** 🟠 Medium
- **발생 가능성:** 🟡 Medium (대용량 영상 전송 시)
- **대응 방안:**
    - **스트리밍 최적화:** H.265 압축 코덱 사용, 동적 비트레이트 조절 (Motion Detection 시에만 고화질).
    - **에지 녹화:** 중요한 영상 정보는 로컬에서 자동 보관 및 분석 후 필요한 경우에만 전송.

### 5. [프로토콜 호환성 및 인터페이스 표준화 위험]
- **설명:** `<스마트폰 제어 시스템>` 및 `웹 제어 시스템` 이 사용하는 API 와 `<농축사 공간>` 내 장치가 사용하는 통신 프로토콜 (예: MQTT, HTTP, CoAP 등) 이 호환되지 않아 데이터 동기화 실패.
- **심각도:** 🟠 Medium
- **발생 가능성:** 🟡 Medium (다양한 하드웨어/소프트웨어 사용 시)
- **대응 방안:**
    - **게이트웨이 적용:** 프로토콜 전환기 (Gateway) 를 도입하여 서로 다른 프로토콜 간의 간소화 (e.g., CoAP to REST API).
    - **표준 참조:** oneM2M 또는 ISO/IEC 30141:2024 등 공통 표준 아키텍처 준수.
