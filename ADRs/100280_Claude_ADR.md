### ADR-001: 중앙집중형 제어부(Controller) 기반 모듈화 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                 |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 환경에서는 실시간 설비 제어, 노이즈 모니터링, 원격 통신, 알람 관리, 리포트 생성 등 이질적인 기능들이 동시에 수행되어야 한다. 단일 모놀리식 구조로 구현할 경우 기능 확장 및 유지보수가 어렵고, 특정 기능의 장애가 전체 시스템에 전파될 위험이 있다.                                                                                                |
| **결정(Decision)**       | 제어부(120)를 중심으로 6개의 독립 기능 모듈(실시간 설비 제어 모니터링 120a, 제어량 분석 및 표시 120b, 알람 표시 및 기록 120c, 노이즈 모니터링 분석 120d, 원격 통신 제어 120e, 리포트 제공 120f)로 분리하고, 입출력부(110), 제어용 I/O IF(130), 송수신부(140), 데이터베이스(150), 음성입출력장치(160)를 독립 외부 인터페이스로 구성하는 중앙집중형 모듈화 아키텍처를 채택한다. |
| **근거(Rationale)**      | 농업 환경 특성상 온습도·CO₂·양액 제어 등 다양한 설비가 혼재하며, 각 기능의 변경 주기와 실시간성 요구 수준이 상이하다. 모듈 분리를 통해 단일 책임 원칙(SRP)을 적용하면 개별 모듈의 독립적 업데이트 및 장애 격리가 가능하다. 또한 원격 통신 제어 모듈(120e)과 송수신부(140)의 분리를 통해 통신 프로토콜 변경 시 영향 범위를 최소화할 수 있다.                                         |
| **결과(Consequences)**   | ✅ 긍정적: 모듈별 독립 배포 및 유지보수 가능, 장애 격리 용이, 기능 확장 시 기존 모듈 영향 최소화, 음성입출력장치(160)를 통한 현장 접근성 향상. ❌ 부정적: 모듈 간 인터페이스 설계 복잡도 증가, 제어부(120)가 단일 장애점(SPOF)이 될 수 있음, 모듈 간 데이터 정합성 관리 필요.                                                                           |
| **트레이드오프(Trade-offs)** | 🟢 얻는 것: 유지보수성, 확장성, 기능별 독립 운용. 🔴 감수할 것: 제어부 집중화로 인한 병목 위험, 모듈 간 통신 오버헤드, 초기 설계 및 통합 테스트 비용 증가.                                                                                                                                                   |

### ADR-002: 외부 데이터베이스(150) 분리 및 송수신부(140)를 통한 원격 통신 이원화

| 항목                     | 내용                                                                                                                                                                      |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜은 24시간 연속 운영되며, 센서 데이터·제어 이력·알람 로그·리포트 데이터 등 대용량 시계열 데이터가 지속적으로 생성된다. 동시에 원격지 관리자나 농업 플랫폼과의 실시간 데이터 연동이 필요하다.                                                       |
| **결정(Decision)**       | 데이터 저장소를 제어부(120) 내부가 아닌 외부 독립 데이터베이스(150)로 분리하고, 원격 데이터 송수신은 송수신부(140)와 원격 통신 제어 모듈(120e)의 이중 레이어로 처리한다.                                                               |
| **근거(Rationale)**      | 데이터베이스를 외부화함으로써 제어 로직과 데이터 영속성 레이어를 분리하여 각각의 독립적 스케일링이 가능하다. 리포트 제공 모듈(120f)과 제어량 분석 모듈(120b)이 동시에 DB에 접근해야 하는 시나리오에서 경합을 최소화할 수 있다. 통신 이원화는 로컬 제어와 원격 모니터링의 독립성을 보장한다. |
| **결과(Consequences)**   | ✅ 긍정적: 제어 로직과 데이터 레이어 독립 운용, 히스토리 데이터 기반 분석·리포트 고도화 용이, 네트워크 단절 시에도 로컬 제어 지속 가능. ❌ 부정적: DB 연결 장애 시 알람 기록 및 리포트 기능 마비, 외부 DB 보안 관리 부담 증가.                                |
| **트레이드오프(Trade-offs)** | 🟢 얻는 것: 데이터 무결성 및 영속성 보장, 분석 기능 확장성. 🔴 감수할 것: DB 네트워크 레이턴시, 추가 인프라 운영 비용, 장애 포인트 증가.                                                                                  |

⚠️ 잠재적 위험 분석
------------

### 1. 제어부(120) 단일 장애점(SPOF) 위험

* **설명:** 제어부(120)는 6개 모듈을 통합하는 중앙 허브로 기능하며, 입출력부(110)로부터 모든 입력을 수신하고 I/O IF(130), 송수신부(140), DB(150), 음성입출력장치(160) 전반을 제어한다. 제어부 소프트웨어 크래시 또는 하드웨어 장애 발생 시 전체 설비 제어, 모니터링, 원격 통신이 동시에 중단되어 작물 피해로 직결될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** Active-Standby 이중화 제어부 구성, Watchdog 타이머를 통한 자동 재시작 메커니즘 도입, 제어부 장애 시 최소한의 안전 상태(Fail-Safe)를 유지하는 하드웨어 인터록(Interlock) 회로 구성, 핵심 모듈(120a, 120c)의 Heartbeat 모니터링 적용.

### 2. 원격 통신 단절 시 제어 공백 위험

* **설명:** 원격 통신 제어 모듈(120e)과 송수신부(140)를 통해 외부 플랫폼 또는 관리자와 연결되는 구조에서, 네트워크 장애(LTE/WiFi 불안정, 농촌 지역 통신 품질 저하)가 발생할 경우 원격 모니터링과 제어 명령 전달이 차단된다. 장기 부재 중인 농장주가 이상 상황을 인지하지 못해 피해가 확산될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 유선(이더넷) + 무선(LTE/LoRa) 이중 통신 경로 구성, 통신 단절 시 로컬 자율 제어 모드(Edge Autonomous Mode) 전환 로직 구현, SMS/음성(160) 기반 로컬 알람 병행 운용, 통신 단절 이벤트 자체를 알람 조건으로 등록.

### 3. 데이터베이스(150) 장애 및 데이터 유실 위험

* **설명:** 제어량 분석 모듈(120b), 알람 기록 모듈(120c), 리포트 제공 모듈(120f)은 모두 외부 데이터베이스(150)에 의존한다. DB 서버 장애, 스토리지 고갈, 또는 네트워크 단절 시 알람 이력이 기록되지 않고, 리포트 생성이 불가하며, 제어 이력 기반의 분석 기능이 전면 중단된다. 특히 규제 준수를 위한 이력 보관 의무가 있는 경우 법적 리스크로 연결된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** DB 이중화(Primary-Replica) 및 정기 백업 정책 수립, 제어부 내 로컬 버퍼(SQLite 등)를 통한 임시 저장 후 DB 복구 시 동기화하는 Store-and-Forward 패턴 적용, DB 용량 임계치 알람 설정, 분기별 복구 훈련(DR Drill) 실시.

### 4. 노이즈 모니터링 모듈(120d) 오탐(False Positive) 및 미탐(False Negative) 위험

* **설명:** 스마트팜 환경에서는 농기계 진동, 냉난방 설비 가동음, 외부 환경 소음 등 다양한 노이즈가 혼재한다. 노이즈 모니터링 분석 모듈(120d)의 임계값 설정이 부정확할 경우, 정상 소음을 이상으로 판단하는 오탐(과다 알람→알람 피로)이나 실제 설비 이상음을 정상으로 분류하는 미탐(이상 미감지→설비 고장 방치)이 발생할 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 환경별 노이즈 베이스라인 학습 기간 운영 및 동적 임계값 적용, ML 기반 이상음 분류 모델 도입(정상/비정상 패턴 학습), 알람 표시 모듈(120c)과 연계하여 알람 등급을 다단계로 구분(경고/위험), 현장 전문가 검토를 통한 정기적 임계값 튜닝 프로세스 수립.

### 5. 제어용 I/O IF(130) 보안 취약점 및 무단 접근 위험

* **설명:** 제어용 I/O IF(130)는 실제 물리 설비(펌프, 밸브, 냉난방기 등)와 직접 연결되는 인터페이스로, 이 지점에 대한 무단 접근 또는 사이버 공격이 발생할 경우 설비 오작동(과도한 관수, 과열, 환기 차단 등)으로 인한 작물 피해 및 물리적 사고가 발생할 수 있다. 특히 원격 통신 제어 모듈(120e)을 통한 외부 접점이 공격 벡터가 될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** I/O IF 접근에 대한 명령 인증 및 서명 검증 적용, 원격 제어 명령에 대한 화이트리스트 기반 허용 정책 구성, 물리적 수동 오버라이드(Manual Override) 스위치 설치로 사이버 공격 시에도 현장 수동 제어 가능하도록 보장, 네트워크 세그멘테이션을 통해 제어 네트워크와 데이터 네트워크 분리(OT/IT 망 분리), 정기적 침투 테스트(Penetration Test) 실시.

### 6. 음성입출력장치(160) 오작동 및 현장 혼란 위험

* **설명:** 음성입출력장치(160)는 현장 작업자에게 알람 및 운영 상태를 음성으로 전달하는 HMI 역할을 한다. 소음이 많은 농업 환경에서 음성 인식 실패율이 높아지거나, 반대로 오인식으로 인한 의도치 않은 제어 명령이 실행될 경우 현장 혼란 및 설비 오조작이 발생할 수 있다. 특히 알람 상황에서 음성 출력 장애가 겹치면 작업자의 즉각적 대응이 불가해진다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 음성 명령 실행 전 시각적 확인(디스플레이 표시) 이중 확인 절차 의무화, 중요 제어 명령(설비 정지, 알람 리셋 등)에 대해 음성 단독 실행 금지 정책 적용, 노이즈 환경에 최적화된 지향성 마이크 및 음성 인식 엔진 선택, 음성 장치 장애 시 알람 표시 모듈(120c)의 시각적 알람이 자동으로 강화되는 Fallback 로직 구현.

### ADR-002: 외부 데이터베이스(150) 분리 및 송수신부(140)를 통한 원격 통신 이원화

⚠️ 잠재적 위험 분석
------------

### 1. 제어부(120) 단일 장애점(SPOF) 위험

* **설명:** 제어부(120)는 6개 모듈을 통합하는 중앙 허브로 기능하며, 입출력부(110)로부터 모든 입력을 수신하고 I/O IF(130), 송수신부(140), DB(150), 음성입출력장치(160) 전반을 제어한다. 제어부 소프트웨어 크래시 또는 하드웨어 장애 발생 시 전체 설비 제어, 모니터링, 원격 통신이 동시에 중단되어 작물 피해로 직결될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** Active-Standby 이중화 제어부 구성, Watchdog 타이머를 통한 자동 재시작 메커니즘 도입, 제어부 장애 시 최소한의 안전 상태(Fail-Safe)를 유지하는 하드웨어 인터록(Interlock) 회로 구성, 핵심 모듈(120a, 120c)의 Heartbeat 모니터링 적용.

### 2. 원격 통신 단절 시 제어 공백 위험

* **설명:** 원격 통신 제어 모듈(120e)과 송수신부(140)를 통해 외부 플랫폼 또는 관리자와 연결되는 구조에서, 네트워크 장애(LTE/WiFi 불안정, 농촌 지역 통신 품질 저하)가 발생할 경우 원격 모니터링과 제어 명령 전달이 차단된다. 장기 부재 중인 농장주가 이상 상황을 인지하지 못해 피해가 확산될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** 유선(이더넷) + 무선(LTE/LoRa) 이중 통신 경로 구성, 통신 단절 시 로컬 자율 제어 모드(Edge Autonomous Mode) 전환 로직 구현, SMS/음성(160) 기반 로컬 알람 병행 운용, 통신 단절 이벤트 자체를 알람 조건으로 등록.

### 3. 데이터베이스(150) 장애 및 데이터 유실 위험

* **설명:** 제어량 분석 모듈(120b), 알람 기록 모듈(120c), 리포트 제공 모듈(120f)은 모두 외부 데이터베이스(150)에 의존한다. DB 서버 장애, 스토리지 고갈, 또는 네트워크 단절 시 알람 이력이 기록되지 않고, 리포트 생성이 불가하며, 제어 이력 기반의 분석 기능이 전면 중단된다. 특히 규제 준수를 위한 이력 보관 의무가 있는 경우 법적 리스크로 연결된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** DB 이중화(Primary-Replica) 및 정기 백업 정책 수립, 제어부 내 로컬 버퍼(SQLite 등)를 통한 임시 저장 후 DB 복구 시 동기화하는 Store-and-Forward 패턴 적용, DB 용량 임계치 알람 설정, 분기별 복구 훈련(DR Drill) 실시.

### 4. 노이즈 모니터링 모듈(120d) 오탐(False Positive) 및 미탐(False Negative) 위험

* **설명:** 스마트팜 환경에서는 농기계 진동, 냉난방 설비 가동음, 외부 환경 소음 등 다양한 노이즈가 혼재한다. 노이즈 모니터링 분석 모듈(120d)의 임계값 설정이 부정확할 경우, 정상 소음을 이상으로 판단하는 오탐(과다 알람→알람 피로)이나 실제 설비 이상음을 정상으로 분류하는 미탐(이상 미감지→설비 고장 방치)이 발생할 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 환경별 노이즈 베이스라인 학습 기간 운영 및 동적 임계값 적용, ML 기반 이상음 분류 모델 도입(정상/비정상 패턴 학습), 알람 표시 모듈(120c)과 연계하여 알람 등급을 다단계로 구분(경고/위험), 현장 전문가 검토를 통한 정기적 임계값 튜닝 프로세스 수립.

### 5. 제어용 I/O IF(130) 보안 취약점 및 무단 접근 위험

* **설명:** 제어용 I/O IF(130)는 실제 물리 설비(펌프, 밸브, 냉난방기 등)와 직접 연결되는 인터페이스로, 이 지점에 대한 무단 접근 또는 사이버 공격이 발생할 경우 설비 오작동(과도한 관수, 과열, 환기 차단 등)으로 인한 작물 피해 및 물리적 사고가 발생할 수 있다. 특히 원격 통신 제어 모듈(120e)을 통한 외부 접점이 공격 벡터가 될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** I/O IF 접근에 대한 명령 인증 및 서명 검증 적용, 원격 제어 명령에 대한 화이트리스트 기반 허용 정책 구성, 물리적 수동 오버라이드(Manual Override) 스위치 설치로 사이버 공격 시에도 현장 수동 제어 가능하도록 보장, 네트워크 세그멘테이션을 통해 제어 네트워크와 데이터 네트워크 분리(OT/IT 망 분리), 정기적 침투 테스트(Penetration Test) 실시.

### 6. 음성입출력장치(160) 오작동 및 현장 혼란 위험

* **설명:** 음성입출력장치(160)는 현장 작업자에게 알람 및 운영 상태를 음성으로 전달하는 HMI 역할을 한다. 소음이 많은 농업 환경에서 음성 인식 실패율이 높아지거나, 반대로 오인식으로 인한 의도치 않은 제어 명령이 실행될 경우 현장 혼란 및 설비 오조작이 발생할 수 있다. 특히 알람 상황에서 음성 출력 장애가 겹치면 작업자의 즉각적 대응이 불가해진다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 음성 명령 실행 전 시각적 확인(디스플레이 표시) 이중 확인 절차 의무화, 중요 제어 명령(설비 정지, 알람 리셋 등)에 대해 음성 단독 실행 금지 정책 적용, 노이즈 환경에 최적화된 지향성 마이크 및 음성 인식 엔진 선택, 음성 장치 장애 시 알람 표시 모듈(120c)의 시각적 알람이 자동으로 강화되는 Fallback 로직 구현.
