## 📋 ADR (Architecture Decision Record)

### ADR-001: 모듈화된 이기종 인터페이스 표준화

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 시스템은 다양한 생육분석용 카메라 (NIR, LWIR 등), 온도/습도 센서, 제어 장치를 통합해야 합니다. 이미지와 문서에서 볼 수 있듯이 TTA 표준 (TTAK.KO-10.1170 등) 과 국제 표준 (ISO/IEC 30141) 을 준수하면서도, 비표준 기기들이 도입될 때 시스템 연동이 깨질 수 있는 리스크가 존재합니다. 특히 `300` 번 영역의 카메라 모듈과 `200` 번 영역의 컨트롤러가 서로 다른 프로토콜을 사용할 경우 ERP 와의 연동 비용이 증가합니다. |
| **결정(Decision)** | 시스템은 표준 통신 프로토콜 (MQTT, CoAP 등) 을 기반으론 모듈형 인터페이스를 정의합니다. `300` 번 카메라 모듈과 `200` 번 제어 모듈은 모두 중앙 ERP 로의 인터페이스를 추상화된 API 로 제공받습니다. 이는 문서에 언급된 "스마트팜 데이터 상호운용 프레임워크" 전략을 반영한 것입니다. |
| **근거(Rationale)** | - **표준 준수:** ISO/IEC 30141:2024 및 oneM2M 표준을 준수하여 향후 확장성을 보장합니다.<br>- **유연성:** 하드웨어 변경 시 소프트웨어 코드 수정 최소화.<br>- **보안:** ETSI EN 303 645 등의 보안 요구사항을 각 모듈에 적용 가능. |
| **결과(Consequences)** | - **긍정적:** 다양한 기기 제조사 제품과의 호환성 확보, 유지보수 용이.<br>- **부정적:** 초기 표준 정의 비용 증가, 모든 기기가 표준을 지원해야만 하는 제약. |
| **트레이드오프(Trade-offs)** | 완벽한 호환성 확보를 위한 표준 준수 비용 vs 특정 비표준 기기 사용 시 발생하는 통합 비용 절감. |

### ADR-002: 엣지 기반 영상 데이터 전처리 및 분석

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 이미지 `300` 번 영역의 생육분석용 카메라는 가시광선, 근적외선, 장파적외선을 통해 방대한 영상 데이터를 생성합니다. 이러한 모든 원시 영상 데이터를 `100` 번 영역의 서버나 클라우드까지 전송하면 대역폭 부족과 처리 지연 (Latency) 이 발생할 수 있습니다. 특히 `영상생육분석` (생육크기, 스트레스 등) 은 실시간성이 중요한 데이터입니다. |
| **결정(Decision)** | `300` 번 카메라 모듈 내부 혹은 로컬 엣지 서버에서 영상 전처리 (잡음 제거, 기본 필터링) 와 초기 분석 (예: 스트레스 식별) 을 수행한 후, `100` 번 영역으로 압축된 핵심 데이터나 요약된 정보를 전송합니다. |
| **근거(Rationale)** | - **성능:** 대역폭 효율화 및 실시간 응답 속도 향상.<br>- **신뢰성:** 네트워크 불안정 환경 (농가 환경) 에서도 핵심 기능 유지.<br>- **비용:** 클라우드 데이터 처리 비용 절감. |
| **결과(Consequences)** | - **긍정적:** 실시간 제어 (비료 살포 등) 반응 속도 향상, 통신 인프라 비용 절감.<br>- **부정적:** 엣지 디바이스의 처리 성능 및 전력 소모 증가. |
| **트레이드오프(Trade-offs)** | 복잡한 로직은 중앙으로, 단순한 필터링과 긴급 신호만 엣지에서 처리할지의 경계선 (Threshold) 설정. |

### ADR-003: 디지털 트윈 기반 시뮬레이션 연동

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 이미지 `200` 번 영역에 있는 `테스트베드환경 시뮬레이션` 블록은 실제 운영 전의 계획 수립에 필수적입니다. 하지만 단순한 가상의 모델링만으로는 부족하며, 실제 `ERP` 에서 수립한 생산계획과 부합하는지 검증해야 합니다. |
| **결정(Decision)** | `200` 번 시뮬레이션 모듈과 `ERP` (생산계획/예측) 간에 실시간 연동을 합니다. 시뮬레이션 결과는 ERP 의 대시보드에 시각화되며, ERP 의 변경 사항을 시뮬레이션이 실시간으로 반영하도록 설계합니다. |
| **근거(Rationale)** | - **리스크 관리:** 실제 장비 투입 전 가상 환경에서의 문제점 예측.<br>- **비용 절감:** 실패한 시나리오 테스트로 인한 물리적 손실 방지. |
| **결과(Consequences)** | - **긍정적:** 운영 효율성 극대화, 예상치 못한 병목 현상 방지.<br>- **부정적:** 시뮬레이션 모델 유지보수 복잡도 증가. |
| **트레이드오프(Trade-offs)** | 시뮬레이션 정확도 향상 vs 연동 복잡도 및 연산 리소스 증가. |

## ⚠️ 잠재적 위험 분석

### 1. 🛡️ 기기 간 상호운용성 및 보안 취약점
- **설명:** 이미지와 문서에서 언급된 다양한 IoT 표준 (ISO, TTA 등) 에 비추어 볼 때, 제조사별 비표준 프로토콜 기기나 구형 장비가 도입될 경우 연동 문제가 발생합니다. 또한 ITU-T X.1352 등의 보안 가이드라인이 필수적이지만, 엣지 기기 (카메라, 센서) 가 취약해져 해킹당할 경우 농작물 피해를 입힐 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 모든 외부 기기 도입 시 TTA 단체표준 (예: TTAK.KO-10.1170) 이나 ISO/IEC 30141 의 최소 요구사항을 준수하도록 강제합니다. 보안 가이드라인을 따르도록 하되, 인증서 기반 인증 및 암호화 통신 (TLS/DTLS) 을 기본값으로 설정합니다.

### 2. 📉 실시간 제어 지연 및 네트워크 불안정성
- **설명:** 농가 환경은 무선통신 (LTE/5G/LoRa) 이 불안정한 경우가 많습니다. `300` 번 카메라나 `200` 번 컨트롤러에서 `ERP` 나 `대시보드` 로 데이터를 전달하거나 제어 명령을 내려받을 때 지연이 발생하면 작물 관리에 치명적입니다. 특히 엣지 기반 분석 (ADR-002) 이 제대로 수행되지 않을 경우 대역폭 병목이 발생할 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 핵심 제어 신호 (온도/습도 제어) 는 로컬 네트워크 (이더넷 등 유선) 로 안정화합니다. MQTT 등 경량 프로토콜을 사용하여 대역폭을 최적화합니다. 지연 시간을 모니터링하고, 일정 임계치를 넘어선 경우 로컬 자동 제어 로직을 작동하도록 설계합니다.

### 3. 🧠 머신러닝 모델의 드리프트 및 오인식 위험
- **설명:** `머신러닝` 및 `영상생육분석` 모듈은 학습된 데이터 (이미지) 에 기반합니다. 계절 변화, 작물 생육 단계 변화 (Drift) 에 따라 모델의 성능이 저하될 수 있습니다. 또한, `300` 번 카메라가 비나 먼지를 맞거나 각도가 틀어지면 오인식이 발생할 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 주기적인 재학습 (Retraining) 스케줄을 ERP 에 통합합니다. 카메라 렌즈 청소 및 자동 초점 보정 기능을 하드웨어적으로 지원합니다. 모델의 정확도를 모니터링하여 특정 구간 (예: 특정 작물 단계) 에 오인율이 높을 때 자동 경보를 발령합니다.

### 4. 💾 데이터 무결성 및 중복 저장 문제
- **설명:** `영상데이터`, `센싱/제어`, `ERP` 데이터가 여러 곳 (`300`, `200`, `100`) 에 저장됩니다. 네트워크 분실 시 데이터가 손실되거나 (Data Loss), 여러 노드에서 같은 데이터가 중복 저장되어 일관성이 깨질 수 있습니다. 특히 `생산관리` 데이터는 정확해야 하므로 중요도 관리가 필요합니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low
- **대응 방안:** 주요 데이터를 `ERP` 및 `Cloud` 백업 노드에 실시간 동기화합니다. 엣지 노드의 데이터는 주기적 동기화를 수행하도록 설계하고, 동기화 실패 시 로컬 캐시를 유지하다가 복구 후 연동하도록 합니다.

### 5. 🔋 전원 및 시스템 가용성 리스크
- **설명:** 외부 환경에 노출된 `300` 번 카메라나 `200` 번 컨트롤러의 전원이 불안정하면 시스템이 정지할 수 있습니다. 특히 `생육정보`를 수집하는 중 전원이 끊기는 경우, `영상생육분석` 데이터가 불연결되어 분석이 불가능해질 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 전원 공급 장치 (UPS) 를 필수적으로 도입하고, 기기별 자동 재부팅 (Watchdog) 기능을 탑재합니다. 네트워크 분리를 통해 네트워크 장비 자체 정지로 인한 전체 시스템 정지를 방지합니다.
