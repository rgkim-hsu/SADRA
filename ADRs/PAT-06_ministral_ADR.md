## 📋 ADR (Architecture Decision Record)

### **ADR-001: 블록체인 기반 작물 거래 투명성 보장 아키텍처**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 시스템에서 작물 데이터(품질, 재배 기록, 이미지 등)와 거래 내역을 신뢰성 있고 불변성 있게 관리해야 하며, 재배자와 구매자 간의 투명성을 보장해야 한다. 중앙 집중식 서버만으로 데이터 위변조 위험이 존재하며, 거래 기록의 불변성과 추적 가능성을 요구한다. |
| **결정(Decision)** | 블록체인 네트워크(300)를 도입하여 작물 데이터와 거래 내역을 분산 저장하고, 스마트팜 서버(30)와 클라이언트(재배자/구매자) 간의 데이터 동기화를 통해 투명성을 보장한다. |
| **근거(Rationale)** | - **불변성 보장**: 블록체인은 데이터 변경 시 전체 네트워크의 합의가 필요하므로 위변조가 불가능하다.
- **분산 저장**: 중앙 서버의 단일 장애점(SPOF)을 제거하고, 네트워크 참여 노드 간 데이터 일관성을 유지한다.
- **규제 준수**: ISO/IEC 30141:2024와 ITU-T X.1352의 보안 요구사항을 충족하며, 거래 내역의 추적 가능성을 제공한다.
- **기존 표준 연계**: oneM2M 및 ETSI EN 303 645와 호환 가능한 보안 프로토콜(MQTT/CoAP)을 사용하여 IoT 기기와의 통합을 용이하게 한다. |
| **결과(Consequences)** | - **장점**: 데이터 신뢰성 향상, 거래 투명성 강화, 중앙 서버 부하 분산.
- **단점**: 네트워크 지연 가능성, 초기 구축 비용 증가, 블록체인 노드 운영 복잡성.
- **트레이드오프**: 성능 저하를 감수하더라도 보안과 투명성을 최우선으로 선택한다. |

### **ADR-002: 스마트팜 서버의 데이터 처리 및 블록체인 연동 방식**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 서버(30)는 작물 데이터(91)를 수집 및 처리한 후 블록체인 네트워크로 전송해야 한다. 이때 실시간성, 데이터 무결성, 그리고 네트워크 트래픽 최적화가 요구된다. |
| **결정(Decision)** | - **에지 컴퓨팅 활용**: 스마트팜 서버에서 데이터 전처리(필터링, 압축)를 수행한 후 블록체인 네트워크로 전송한다.
- **해시 기반 동기화**: 블록체인 네트워크에 저장되는 데이터는 메타데이터(해시 값)만 저장하고, 실제 데이터는 IPFS나 분산 스토리지에 저장하여 네트워크 부하를 줄인다.
- **이벤트 기반 통신**: MQTT 프로토콜을 사용하여 실시간 데이터 스트리밍을 지원한다. |
| **근거(Rationale)** | - **성능 최적화**: 전처리를 통해 불필요한 데이터 전송을 최소화하고, 해시 기반 저장으로 블록체인 네트워크의 저장 비용을 절감한다.
- **실시간성 보장**: MQTT는 IoT 환경에서 저지연 통신을 지원하며, TTA의 스마트팜 표준과 호환된다.
- **확장성**: 에지 컴퓨팅을 통해 중앙 서버의 부하를 분산하고, 분산 스토리지를 통해 대용량 데이터 처리 능력을 강화한다. |
| **결과(Consequences)** | - **장점**: 네트워크 효율성 향상, 실시간 데이터 처리 가능, 확장성 강화.
- **단점**: 에지 컴퓨팅 구현 복잡성, 해시 충돌 위험(미미함).
- **트레이드오프**: 초기 구축 복잡성을 감수하더라도 성능과 확장성을 최우선으로 선택한다. |

### **ADR-003: 사용자 인증 및 접근 통제 방식**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 재배자(97)와 구매자(93) 간의 접근 권한을 엄격히 통제해야 하며, 데이터 유출 및 권한 남용을 방지해야 한다. 특히 블록체인 네트워크에 저장되는 데이터의 민감성을 고려한다. |
| **결정(Decision)** | - **OAuth 2.0 + JWT**: 사용자 인증을 위해 OAuth 2.0을 사용하고, JWT를 통해 접근 토큰을 발행한다.
- **역할 기반 접근 통제(RBAC)**: 재배자와 구매자에게 다른 권한을 할당(예: 재배자는 데이터 수정 가능, 구매자는 조회만 가능).
- **블록체인 기반 로깅**: 모든 접근 로그를 블록체인 네트워크에 기록하여 감사 가능성을 보장한다. |
| **근거(Rationale)** | - **보안 표준 준수**: ISO/IEC 27030:2020과 ETSI EN 303 645의 보안 요구사항을 충족한다.
- **유연성**: OAuth 2.0은 다양한 클라이언트(모바일/웹)와의 호환성을 제공한다.
- **감사 가능성**: 블록체인 로깅을 통해 모든 접근 기록을 불변성 있게 저장한다. |
| **결과(Consequences)** | - **장점**: 강력한 접근 통제, 감사 가능성 강화, 보안 표준 준수.
- **단점**: 인증 시스템 복잡성 증가, 토큰 관리 오류 가능성.
- **트레이드오프**: 보안을 최우선으로 선택하므로 인증 시스템의 복잡성을 감수한다. |

## ⚠️ 잠재적 위험 분석

### **1. 블록체인 네트워크 지연 및 성능 저하**
- **설명**: 블록체인 네트워크의 합의 프로세스(예: PoW/PoS)는 데이터 처리 지연을 초래할 수 있으며, 실시간 거래 처리에 영향을 미칠 수 있다.
- **심각도**: 🟡 Medium
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - 블록체인 네트워크에 메타데이터(해시 값)만 저장하고, 실제 데이터는 IPFS나 분산 스토리지에 저장한다.
  - 오프체인(Off-chain) 솔루션(예: State Channels)을 도입하여 실시간 거래를 처리한다.
  - 네트워크 모니터링 도구를 구축하여 지연이 발생할 경우 자동으로 에지 서버로 fallback한다.

### **2. 데이터 무결성 위반 및 해시 충돌**
- **설명**: 해시 기반 저장 시스템에서 해시 충돌이 발생하거나, 악의적인 노드가 무결성을 위반할 경우 데이터 신뢰성이 손상된다.
- **심각도**: 🔴 High
- **발생 가능성**: 🟢 Low (해시 충돌 확률은 매우 낮음)
- **대응 방안**:
  - SHA-3 또는 BLAKE3과 같은 보안 해시 함수를 사용한다.
  - 블록체인 네트워크에 데이터 무결성 검증을 위한 스마트 컨트랙트를 배포한다.
  - 정기적인 보안 오디트를 통해 해시 함수 및 네트워크 무결성을 검증한다.

### **3. 중앙 서버의 단일 장애점(SPOF) 위험**
- **설명**: 스마트팜 서버가 장애를 발생할 경우, 데이터 수집 및 전처리 과정이 중단되어 블록체인 네트워크로의 데이터 전송이 중단된다.
- **심각도**: 🔴 High
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - 스마트팜 서버를 다중화(Active-Active 또는 Active-Standby)하여 가용성을 높인다.
  - 에지 노드를 추가하여 데이터 수집 및 전처리 기능을 분산한다.
  - 자동 복구 메커니즘(예: Kubernetes 기반 오케스트레이션)을 도입한다.

### **4. 사용자 인증 및 권한 관리 오류**
- **설명**: OAuth 2.0/JWT 기반 인증 시스템에서 토큰 유출 또는 권한 오할당이 발생할 경우, 데이터 유출 또는 권한 남용이 발생할 수 있다.
- **심각도**: 🔴 High
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - 단기 유효 토큰과 주기적인 재발급을 강제한다.
  - MFA(Multi-Factor Authentication)를 추가하여 인증 보안을 강화한다.
  - 권한 관리 시스템을 자동화하여 오류를 최소화한다.

### **5. 규제 및 표준 변화에 따른 호환성 문제**
- **설명**: IoT 및 블록체인 관련 표준(예: ISO/IEC 30141:2024, ITU-T X.1352)이 변경될 경우, 시스템이 기존 표준과 호환되지 않을 수 있다.
- **심각도**: 🟡 Medium
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - 표준 변화에 대한 모니터링 시스템을 구축한다.
  - 시스템 아키텍처를 모듈화하여 표준 변경 시 신속하게 업데이트할 수 있도록 한다.
  - 국제 표준 기구(ISO, ITU-T)와 협력하여 표준화 과정에 참여한다.

### **6. 네트워크 공격 및 Sybil 공격**
- **설명**: 블록체인 네트워크에 악의적인 노드가 참여하여 Sybil 공격이나 51% 공격이 발생할 경우, 데이터 무결성이 위협받을 수 있다.
- **심각도**: 🔴 High
- **발생 가능성**: 🟢 Low (공개 블록체인 사용 시)
- **대응 방안**:
  - 프라이빗/퍼블릭 하이브리드 블록체인 네트워크를 사용한다.
  - 네트워크 참여 노드에 대해 신원 인증을 강제한다.
  - 공격 감지 AI 모델을 도입하여 이상 행위를 실시간으로 감지한다.

### **7. 데이터 프라이버시 위반**
- **설명**: 작물 데이터(예: 위치, 재배 기록)에는 개인 정보가 포함될 수 있으며, 불법적으로 노출될 경우 법적 및 신뢰성 문제가 발생한다.
- **심각도**: 🔴 High
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - 데이터 암호화(예: AES-256)를 사용하여 전송 및 저장 중 데이터를 보호한다.
  - GDPR 및 개인정보 보호법에 준하여 데이터 최소화 원칙을 적용한다.
  - 사용자에게 데이터 접근 및 삭제 권한을 제공한다.

**※ 추가 고려사항**:
- **성능 vs. 보안 트레이드오프**: 블록체인 네트워크의 성능 저하를 감수하더라도 보안과 투명성을 최우선으로 선택한다.
- **확장성**: 시스템이 미래의 사용자 증가에 대응할 수 있도록 모듈식 아키텍처를 채택한다.
- **국내외 표준 준수**: TTA 및 KISA의 표준을 준수하여 글로벌 시장에서의 경쟁력을 강화한다.
