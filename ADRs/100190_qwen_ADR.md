## 📋 ADR (Architecture Decision Record)

### ADR-001: 풀필먼트 메시징 게이트웨이 도입 및 중앙 집중화

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 다양한 외부 파트너(배송 기관, 제3 자 풀필먼트 센터, 창고 관리 시스템 등) 와 실시간으로 연동해야 하는 복잡한 환경에 노출됨. 각 파트너마다 고유한 프로토콜과 API 를 사용하여 연동하면 유지보수 비용이 급증하고 시스템 간 상호운용성 유지가 어려움. |
| **결정(Decision)** | 이미지의 `[115] 풀필먼트 메시징 게이트웨이` 를 핵심 인프라로 설정하고, 모든 외부 파트너의 데이터 요청/입출력을 통치하는 단일 진입점 (Single Point of Entry) 으로 운영함. 내부적으로는 표준화された 데이터 포맷과 API Gateway 패턴을 적용하여 외부의 이질적인 프로토콜을 변환하고 정규화함. |
| **근거(Rationale)** | `oneM2M` 및 `ISO/IEC 30141` 과 같은 IoT 및 시스템 아키텍처 표준에서 권장하는 패턴을 따름. 게이트웨이 를 활용하면 API 관리, 인증, 트래픽 제어 등 공통 관심사를 일원화할 수 있음. 또한, 특정 파트너 시스템이 변경되어도 게이트웨이 내 로직만 수정하면 나머지 시스템에 영향을 주지 않는 유연성을 확보할 수 있음. |
| **결과(Consequences)** | **긍정적:** 외부 시스템 연결 시간이 단축되고, 유지보수 비용이 감소함. 시스템의 확장성이 높아짐.<br>**부정적:** 게이트웨이가 단일 장애점 (SPOF) 이 될 수 있으므로 고가용성 설계 (레플리카, 로드 밸런서) 가 필수됨. |
| **트레이드오프(Trade-offs)** | **장점:** 강력한 통합 제어와 표준화 효과.<br>**단점:** 게이트웨이의 성능 저하가 전체 시스템으로 전파될 위험 존재. |

### ADR-002: 자동화 및 모니터링 인프라 구축

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 물류 처리 부하가 급증하거나 특정 배송 기관/풀필먼트 센터가 장애를 발생했을 때, 수동으로 대응하는 것보다 시스템 가용성을 높여야 함. 또한 실시간으로 시스템 상태를 파악하여 이상 징후를 조기에 발견해야 함. |
| **결정(Decision)** | 이미지 하단의 `[123] 풀필먼트 센터 인공지능 시스템`, `[125] 자동 관리 시스템`을 도입하여 물류 흐름을 최적화하고 자동화함. 동시에 `[119] 창고 관리 시스템` 과 연동하여 실시간 재고 및 위치 정보를 파악하고 시스템 전반의 상태를 모니터링하는 인프라를 구축함. |
| **근거(Rationale)** | 고가용성 아키텍처 (HA) 설계 원칙에 따름. 자동화 시스템을 통해 인간의 개입을 최소화하여 처리 속도와 정확도를 높임. 표준화된 모니터링 도구 및 로그 수집 기법을 적용하여 시스템 안정성을 확보함. |
| **결과(Consequences)** | **긍정적:** 물류 처리 속도 향상, 운영 비용 절감, 실시간 이상 감지 능력 향상.<br>**부정적:** 초기 구축 비용 증가 및 복잡한 자동화 로직의 관리 어려움. |
| **트레이드오프(Trade-offs)** | **장점:** 24/7 운영 및 오류 최소화.<br>**단점:** 자동화 오류 시 복구 절차가 복잡해질 수 있음. |

## ⚠️ 잠재적 위험 분석

### 1. 게이트웨이 (115) 단일 장애점 및 성능 병목 위험
- **설명:** 모든 외부 트래픽이 `[115] 풀필먼트 메시징 게이트웨이` 를 경유하므로, 게이트웨이가 장애가 발생하거나 트래픽이 폭주할 경우 전체 시스템 (배송 기관 연동, 추적 정보 조회 등) 이 마비될 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 게이트웨이의 자동 수동 (Failover) 기능을 활성화하고, 트래픽 분산을 위한 로드 밸런싱 구성을 필수로 적용하여 가용성을 99.9% 이상 확보함.

### 2. 제3 자 풀필먼트 및 배송 기관 연결 불안정성
- **설명:** `[112A], [112B], [112C]` 등 제3 자 풀필먼트 또는 배송 기관 시스템이 자체적으로 변경되거나 장애가 발생하면, 게이트웨이를 통한 통신이 막혀서 `[101] 배송 기관 기술 시스템` 이 정상적인 물류 서비스를 제공할 수 없음을 의미함.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 다양한 배송 기관 및 제3 자 풀필먼트 업체와 계약하여 백업 풀필먼트 센터를 보유하는 전략을 수립. API 버전 관리 (Versioning) 를 통해 호환성을 유지하면서 변화에 대응함.

### 3. 배송 및 주문 추적 데이터 (111) 무결성 손상 위험
- **설명:** `[111] 배송 및 주문 추적 시스템` 에서 외부 파트너로부터 입력된 데이터가 변조되거나, 실시간 위치 정보가 업데이트되지 않아 잘못된 배송 정보 (예: 물건이 도착하지 않았음이나 도착했지만 위치가 틀림) 가 시스템에 남을 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 모든 데이터 입력/수정을 디지털 서명 (Digital Signature) 과 토큰 (Token) 기반으로 검증하여 위변조 방지를 함. 데이터 일관성을 유지하기 위한 주기적인 데이터 정합성 검사 (Validation) 로직을 적용함.

### 4. 외부 환경 (102A, 102B, 102C) 연결성 단절
- **설명:** 판매자 포털, 모바일 앱, PC 등 외부 사용자 단말이 인터넷 네트워크 연결이 끊기거나 통신망 장애가 발생하면, `[103] 외부 포트트 엔드 시스템` 을 통해 요청이 전달되지 않아 주문 처리 및 배송 조회가 불가능함.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 오프라인 모드 (Offline Mode) 지원 및 에지 컴퓨팅 (Edge Computing) 방식을 일부 도입하여 네트워크 단절 시에도 기초 기능은 제공받을 수 있도록 설계함.

### 5. 자동화 시스템 (123, 125) 과 인공 지능 (AI) 의사결정 오류
- **설명:** `[123] 풀필먼트 센터 인공지능 시스템` 이나 `[125] 자동 관리 시스템` 이 예측 모델의 오류로 인해 잘못된 물류 배치 (예: 고가품 보관 위치 오류) 나 자원 할당 오류를 저질러서 물리적 손상이나 지연을 초래할 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** AI 의사결정의 투명성을 높이기 위한 Explainable AI (XAI) 기술 적용 및, 자동화 조치가 수행되기 전 인간의 승인 (Human-in-the-loop) 과정을 일부 단계에서 유지하여 오류를 방지함.
