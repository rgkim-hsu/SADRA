## 📋 ADR (Architecture Decision Record)

### ADR-001: 중앙 집중형 제어 아키텍처 및 데이터 흐름 통합

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 외부 센서(카메라)에서 수집된 영상 데이터를 수신, 처리 및 저장해야 하며, 분석 결과에 기반하여 특정 액션을 실행하거나 사용자에게 피드백을 제공해야 합니다. 특히 다양한 입력원(카메라, 단일-액션 입력 메커니즘)으로부터 정보를 통합하여 하나의 로직(중앙 프로세서)에서 처리하는 아키텍처가 필요합니다. |
| **결정(Decision)** | <ul><li>**중앙 집중형 처리 전략 채택:** 모든 외부 데이터(카메라, 사용자 액션 입력)는 중앙 프로세서(421)를 거치도록 설계합니다.</li><li>**데이터 분리 저장:** 이미지 및 동영상이나 다른 형태의 콘텐츠는 별도의 메모리 모듈(428, 442)로 분산 저장되도록 구성합니다.</li><li>**동일한 인터페이스:** 다양한 입력 소스로부터 들어오는 데이터를 통합하기 위해 표준화된 인터페이스를 중앙 프로세서가 관리하도록 합니다.</li></ul> |
| **근거(Rationale)** | <ul><li>**단일 진실 공급원(Single Source of Truth):** 중앙 프로세서를 모든 데이터의 핵심으로 삼음으로써 시스템의 상태를 일관되게 관리할 수 있습니다.</li><li>**확장성:** 새로운 센서나 입력 기기가 추가될 때 중앙 프로세서만 업데이트하면 되므로 유지보수가 용이합니다.</li><li>**보안 및 제어:** 카메라 제어기(414)와 같은 민감한 기능도 중앙에서 통제되므로 무단 접근을 방지하기 쉽습니다.</li></ul> |
| **결과(Consequences)** | <ul><li><b>긍정적:</b> 시스템의 일관성이 높아지고, 디버깅이 용이합니다. 복잡한 로직을 중앙에서 처리하므로 하위 모듈은 간단해집니다.</li><li><b>부정적:</b> 중앙 프로세서의 부하가 너무 크면 시스템 응답 속도가 느려질 수 있습니다. 따라서 로드 밸런싱이나 큐잉 메커니즘이 필요합니다.</li></ul> |
| **트레이드오프(Trade-offs)** | <ul><li>**중앙 집중식 vs 분산 처리:** 중앙 집중식 구조는 관리가 쉬우나(장점), 단일 장애점(SPOF)이 발생할 위험이 있습니다(단점). 이에 따른 리스크를 감수해야 합니다.</li><li>**저장 공간:** 모든 데이터를 중앙 메모리로 가지면 용량 한계가 생길 수 있으므로, 이미지/비디오 저장부를 물리적으로 분리해 용량을 확보합니다.</li></ul> |

## ⚠️ 잠재적 위험 분석

### 1. 중앙 처리자(Single Point of Failure) 위험
- **설명:** 모든 입력과 출력(카메라 제어, 디스플레이 제어, 메모리 쓰기)이 중앙 프로세서(421)를 경유합니다. 만약 이 중앙 프로세서가 다운되거나 오작동하면 전체 시스템이 마비됩니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 중앙 프로세서 기능을 이중화하거나, 비상시 자동 전환 시스템을 구성하여 시스템의 가용성을 확보해야 합니다.

### 2. 메모리 포화 및 데이터 손실 위험
- **설명:** 사진 메모리(428)와 비디오 메모리(442)가 별도로 존재하지만, 중앙 프로세서의 처리 속도에 비해 데이터 유입 속도가 더 빠를 경우 메모리가 포화 상태가 되어 새로운 데이터 저장 및 처리가 중단될 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 저장 공간 모니터링을 통한 실시간 알림 시스템을 도입하고, 포화 시 가장 오래된 데이터를 자동 정리하거나 외부 클라우드 저장소로 오프로드하는 로직을 구현해야 합니다.

### 3. 실시간성 저하 위험
- **설명:** 카메라(316)나 카메라 제어기(414) 등 하드웨어의 실시간 신호를 중앙 프로세서가 처리하고 이를 다시 카메라 제어기로 되돌려 보낼 경우, 네트워크 지연이나 처리 지연으로 인해 제어나 관찰의 실시간성이 떨어질 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 임계적인 제어 신호(예: 비상 정지)는 중앙 프로세서를 우회하여 하드웨어 레벨이나 고속 네트워크 회로를 통해 직접 처리하는 백업 경로를 확보해야 합니다.

### 4. 보안 위협 및 무단 접근 위험
- **설명:** 카메라 제어기(414)나 디스플레이 제어기(449) 등이 중앙 프로세서(421)에 의해 통제되므로, 이 중앙 프로세서에 대한 무단 접근이 발생하면 모든 제어 권한이 악용될 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 중앙 프로세서와 외부 장치 간 통신 시 강력한 인증 및 암호화(SSL/TLS 등)를 적용하고, 접근 로그를 모든 단계에서 기록하여 이상 징후를 감지할 수 있어야 합니다.

### 5. 단일 액션 입력 메커니즘의 병목 현상
- **설명:** 단일-액션 입력 메커니즘(435)이 중앙 프로세서(421)로만 데이터를 전달되도록 되어 있어, 다른 입력 경로를 통한 빠른 반응이 제한될 수 있습니다. 또한, 입력 메커니즘 자체에 병목 현상이 발생할 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 시스템 요구사항에 따라 긴급 입력 등 특정 상황에서는 단일-액션 입력 메커니즘을 우회하거나 병렬 처리할 수 있는 구조를 설계해야 합니다.
