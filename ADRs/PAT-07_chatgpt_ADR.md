📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 분산 노드 기반 블록체인 거래 검증 아키텍처

| 항목                     | 내용                                                                                                                                        |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 시스템은 다수의 노드(310)로 구성된 블록체인 네트워크(300)를 중심으로, 재배자와 구매자 간 거래 내역(93)을 분산 저장·검증하는 구조이다. 각 노드는 동일한 원장을 공유하며, 거래 데이터의 무결성과 신뢰성을 보장하는 것이 핵심 과제이다. |
| **결정(Decision)**       | **P2P 기반 분산 원장 아키텍처**를 채택하고, 모든 거래 데이터를 네트워크 참여 노드에 분산 저장한다. 합의 알고리즘(예: PoA, PBFT 등)을 통해 거래를 검증하고 블록을 생성하도록 설계한다.                         |
| **근거(Rationale)**      | 중앙 서버 없이도 데이터 위변조 방지가 가능하며, 다수의 참여자가 동일한 데이터를 공유함으로써 신뢰 기반 거래 환경을 구축할 수 있다. 특히 농산물 유통과 같이 신뢰성이 중요한 영역에서 적합하다.                             |
| **결과(Consequences)**   | 데이터 무결성과 투명성이 확보되며, 특정 노드 장애에도 시스템이 지속 운영된다. 그러나 네트워크 확장성과 처리 속도 문제가 발생할 수 있다.                                                            |
| **트레이드오프(Trade-offs)** | 탈중앙화 신뢰 확보(장점) vs 처리 성능 저하(단점), 장애 내성(장점) vs 운영 복잡성 증가(단점)                                                                                |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. 합의 알고리즘 성능 저하

* **설명:** 노드 수 증가에 따라 합의 과정 지연 발생

* **심각도:** 🔴 High

* **발생 가능성:** 🔴 High

* **대응 방안:** 경량 합의 알고리즘(PBFT, PoA), 노드 그룹화

* * *

### 2. 네트워크 지연 및 동기화 문제

* **설명:** 노드 간 데이터 전파 지연으로 원장 불일치 발생 가능

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 블록 전파 최적화, 타임스탬프 기반 동기화

* * *

### 3. 51% 공격 또는 내부 위협

* **설명:** 특정 노드 집단이 네트워크를 장악할 경우 데이터 조작 가능성

* **심각도:** 🔴 High

* **발생 가능성:** 🔴 Low~Medium (프라이빗 네트워크 기준)

* **대응 방안:** 권한 기반 네트워크, 노드 인증 및 접근 제어

* * *

### 4. 저장소 증가 문제

* **설명:** 모든 노드가 전체 거래 데이터를 저장하여 저장 공간 증가

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 경량 노드(light node), 데이터 압축 및 pruning

* * *

### 5. 스마트 계약 취약점

* **설명:** 거래 로직 오류로 인해 잘못된 거래 실행

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 코드 감사, formal verification, 테스트넷 검증

* * *

### 6. 사용자 접근성 및 UX 문제

* **설명:** 일반 사용자(재배자, 구매자)가 블록체인 사용 어려움

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** UI 단순화, 백엔드에서 블록체인 추상화

* * *
