## 📋 ADR (Architecture Decision Record)

### **ADR-001: 센서 데이터 수집 및 중앙 집중형 처리 아키텍처 채택**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 **스마트팜/축산 환경 모니터링**을 목적으로 하며, 실시간 센서 데이터 수집, 중앙 집중형 처리, 그리고 사용자 접근성을 요구한다. 현행 개념도에서 **센서 측정 장치(100)**가 현장 데이터 수집을 담당하고, **모니터링 장치(300)**가 데이터 전처리 및 전송을 처리하는 구조를 확인할 수 있다. 이는 **IoT 플랫폼의 대표적 패턴**인 **Edge-to-Cloud 아키텍처**를 반영한다. |
| **결정(Decision)** | 1. **센서 측정 장치(100)**는 **MQTT 프로토콜**을 사용하여 저전력 및 실시간 데이터 전송을 보장한다.
2. **모니터링 장치(300)**는 **Edge 서버**로 구현되어 데이터 전처리(필터링, 압축, 이상치 검출)을 수행한 후 **정보 제공 서버(400)**로 전송한다.
3. **정보 제공 서버(400)**는 **Kafka**를 기반으로 한 이벤트 스트리밍 아키텍처를 채택하여 확장성 및 실시간 처리를 보장한다.
4. **사용자 기기(20)**는 **RESTful API**를 통해 데이터 접근을 제공하며, **OAuth 2.0** 기반 인증을 적용한다. |
| **근거(Rationale)** | - **MQTT 프로토콜**: IoT 환경에서 표준으로 사용되며, 저전력 및 고신뢰성 데이터 전송을 지원한다 (ISO/IEC 27030:2020 준수).
- **Edge 서버**: 센서 데이터의 지역 처리로 네트워크 부하를 줄이고, 실시간 모니터링을 가능하게 한다.
- **Kafka**: 대규모 데이터 스트림 처리에 최적화되어 있으며, **oneM2M** 및 **ETSI EN 303 645**와 호환 가능한 보안 모델을 지원한다.
- **RESTful API + OAuth 2.0**: 사용자 접근성을 높이며, **ISO/IEC 30141:2024**의 상호운용성 요구사항을 충족한다. |
| **결과(Consequences)** | ✅ **장점**:
- 실시간 데이터 처리 및 확장성 확보.
- 네트워크 비용 절감 및 보안 강화 (Edge 처리).
- 표준 프로토콜/인증 방식으로 글로벌 상호운용성 보장.
❌ **단점**:
- Edge 서버 유지보수 비용 증가.
- MQTT/RESTful API의 복잡한 보안 구현 요구. |
| **트레이드오프(Trade-offs)** | - **Edge 처리 vs. Cloud 처리**: Edge 처리로 네트워크 부하를 줄이지만, 서버 관리 복잡성이 증가한다.
- **MQTT vs. HTTP**: MQTT가 저전력에 적합하지만, HTTP가 더 광범위한 지원 환경을 제공한다. |

### **ADR-002: 보안 아키텍처 결정**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | IoT 시스템은 **사이버 공격** 및 **데이터 유출** 위험에 노출되어 있으며, **ITU-T X.1352** 및 **ETSI EN 303 645**와 같은 국제 표준을 준수해야 한다. |
| **결정(Decision)** | 1. **센서 측정 장치(100)**: **TLS 1.3**을 사용하여 데이터 암호화 및 **디바이스 인증**을 적용한다.
2. **모니터링 장치(300)**: **Kafka ACL**을 통해 접근 제어를 강화하고, **로그 감사**를 활성화한다.
3. **정보 제공 서버(400)**: **KISA 기준**에 따른 **IoT 보안 인증**을 획득하고, **DB 암호화**를 적용한다.
4. **사용자 기기(20)**: **Multi-Factor Authentication (MFA)**를 지원한다. |
| **근거(Rationale)** | - **TLS 1.3**: 최신 암호화 표준으로 보안 취약성을 최소화한다.
- **Kafka ACL**: 데이터 스트림의 세분화된 접근 제어를 가능하게 한다.
- **KISA 인증**: 글로벌 시장에서의 신뢰성을 높인다 (ITU-T X.1352 준수). |
| **결과(Consequences)** | ✅ **장점**:
- 국제 표준 준수 및 글로벌 보안 인증 획득.
- 데이터 암호화 및 접근 제어로 유출 위험 최소화.
❌ **단점**:
- 보안 구현으로 시스템 복잡성이 증가한다.
- 디바이스 인증으로 초기 설정 시간이延長된다. |
| **트레이드오프(Trade-offs)** | - **강화된 보안 vs. 사용자 편의성**: MFA 및 디바이스 인증으로 보안이 강화되지만, 사용자 경험이 복잡해질 수 있다. |

### **ADR-003: 데이터 관리 및 상호운용성 아키텍처**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 **스마트팜/축산 데이터**의 **표준화된 저장 및 공유**를 요구하며, **TTA 단체 표준** 및 **ISO/IEC 30141:2024**와 호환되어야 한다. |
| **결정(Decision)** | 1. **정보 제공 서버(400)**: **NoSQL(MongoDB)** 및 **Time-Series DB(InfluxDB)**를 혼합하여 저장한다.
2. **데이터 스키마**: **JSON Schema**를 사용하여 표준화된 데이터 형식을 정의한다.
3. **API Gateway**: **OpenAPI 3.0**을 기반으로 문서화하고, **Matter/OCF**와 호환 가능한 인터페이스를 제공한다. |
| **근거(Rationale)** | - **MongoDB/InfluxDB**: 유연성 및 실시간 분석에 최적화되어 있다.
- **JSON Schema**: **oneM2M** 및 **ISO/IEC 30141:2024**와 호환 가능한 데이터 모델을 제공한다.
- **OpenAPI 3.0**: 상호운용성을 높이고, **ETSI** 표준과 연계된다. |
| **결과(Consequences)** | ✅ **장점**:
- 표준화된 데이터 모델로 글로벌 상호운용성 확보.
- 실시간 분석 및 유연한 데이터 저장 가능.
❌ **단점**:
- NoSQL의 스키마 유연성이 데이터 일관성을 위협할 수 있다. |
| **트레이드오프(Trade-offs)** | - **유연성 vs. 일관성**: NoSQL의 장점은 스키마 유연성이지만, 일관성 관리 비용이 증가한다. |

## ⚠️ 잠재적 위험 분석

### **1. 네트워크 단절 및 데이터 손실**
- **설명**: 센서 측정 장치(100)와 모니터링 장치(300) 간의 네트워크 단절로 데이터 손실 또는 지연이 발생할 수 있다.
- **심각도**: 🔴 High
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **MQTT QoS Level 2**를 적용하여 데이터 재전송을 보장한다.
  - **Edge 캐싱**을 통해 일시적 단절 시 데이터를 로컬에 저장한다.
  - **네트워크 모니터링 도구**를 배포하여 실시간으로 네트워크 상태를 감시한다.

### **2. Edge 서버 과부하**
- **설명**: 대규모 센서 데이터가 Edge 서버(300)로 집중적으로 유입될 경우, 시스템 과부하로 성능 저하가 발생할 수 있다.
- **심각도**: 🟡 Medium
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **Kubernetes**를 사용하여 Edge 서버를 오토스케일링한다.
  - **데이터 샘플링**을 통해 전송되는 데이터 양을 조절한다.
  - **로드 테스트**를 통해 성능 기준을 설정하고 모니터링한다.

### **3. 보안 취약점 및 공격**
- **설명**: IoT 디바이스 및 네트워크가 **DDoS 공격** 또는 **데이터 스푸핑**에 노출될 수 있다.
- **심각도**: 🔴 High
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **TLS 1.3** 및 **디바이스 인증**을 강제 적용한다.
  - **WAF(Web Application Firewall)**를 배포하여 공격 차단한다.
  - **정기적인 보안 패치** 및 **취약점 스캔**을 수행한다.

### **4. 데이터 일관성 문제**
- **설명**: 분산된 Edge 서버와 Cloud 서버 간의 데이터 동기화 지연으로 일관성 문제가 발생할 수 있다.
- **심각도**: 🟡 Medium
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **이벤트 소싱 패턴**을 적용하여 데이터 변경 이력을 추적한다.
  - **분산 트랜잭션 관리** 도구를 도입한다.
  - **데이터 검증 메커니즘**을 구현하여 일관성을 확인한다.

### **5. 표준 준수 미비로 인한 상호운용성 실패**
- **설명**: 시스템이 **ISO/IEC 30141:2024** 또는 **oneM2M** 표준을 준수하지 못해 다른 플랫폼과의 연동이 실패할 수 있다.
- **심각도**: 🟡 Medium
- **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **OpenAPI 3.0** 및 **JSON Schema**를 사용하여 표준화된 인터페이스를 제공한다.
  - **인증된 테스트 환경**에서 상호운용성 검증을 수행한다.
  - **TTA 및 KISA 가이드라인**을 준수하여 개발 프로세스를 검토한다.

---
**※ 참고 사항**:
- **Edge-to-Cloud 아키텍처**는 **스마트팜/축산 환경**에서 실시간 모니터링을 위한 최적의 선택이지만, **네트워크 의존성**과 **보안 복잡성**을 고려해야 한다.
- **Kafka + MQTT** 조합은 실시간 처리와 확장성을 제공하지만, **운영 복잡성**이 증가한다.
- **보안 인증(KISA/ETSI)**은 글로벌 시장에서의 신뢰성을 높이지만, **초기 구축 비용**이 발생한다.
