## 📋 ADR (Architecture Decision Record)

### ADR-001: 중앙 집중식 서버 아키텍처 (Centralized Server Architecture) 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템 다이어그램(그림 5-1) 에서 서버(300)가 농장(100), 탱크(400), 사용자 기기(200) 모든 컴포넌트와 연결된 단일 허브로 작용합니다. 하지만 분산형 엣지 컴퓨팅 고려 시 중앙 집중화의 단점 (네트워크 의존성) 을 인지해야 합니다. |
| **결정(Decision)** | ISO/IEC 30141:2024 참조 아키텍처 가이드라인에 따라, 확장성과 데이터 분석을 위해 중앙 서버 (300) 를 핵심 처리 단으로 설정하고, 모든 센서 데이터 및 제어 명령을 서버를 경유하여 처리하도록 결정합니다. |
| **근거(Rationale)** | **상호운용성 및 관리 효율성:** 서버 (300) 를 통해 재배 농장 정보 (100) 와 사용자 선호 정보 (400) 를 통합 처리함으로써, TTA 및 ISO 표준을 준수하여 이기종 기기 간 연동 (Interoperability) 을 용이하게 합니다. <br>**데이터 통합:** 작물 관찰 정보와 사용자 선호도를 하나의 데이터베이스로 통합하여 복잡한 농업 로직 (예: 물 공급 타이밍과 사용자 맞춤법) 을 일괄 제어할 수 있습니다. |
| **결과(Consequences)** | **긍정적:** 대규모 데이터 분석 및 원격 관리가 용이해지며, 보안 정책 (ETSI EN 303 645) 이 중앙에서 일관되게 적용됩니다.<br>**부정적:** 인터넷 연결이 끊길 경우 전체 시스템이 마비될 수 있으며, 서버 부하 처리가 집중되어 성능 저하가 발생할 수 있습니다. |
| **트레이드오프(Trade-offs)** | 확장성 확보 ↔ 고가용성 및 단일 고장점 (SPOF) 리스크 증가. |

### ADR-002: IoT 프로토콜 표준화 (MQTT/CoAP) 우선 적용

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 이미지 내 농장 (100) 의 수많은 센서/액추에이터는 저전력, 저대역폭 환경에서 작동해야 합니다. 서버 (300) 와의 통신은 경량화가 필요합니다. |
| **결정(Decision)** | 센서 및 제어 장치 (400) 에서 서버 (300) 로의 통신에는 IETF CoAP 또는 MQTT 프로토콜을 기본 표준으로 채택합니다. |
| **근거(Rationale)** | **자원 효율성:** document 의 "IETF CoAP, MQTT: IoT 환경에서 경량 통신을 위한 표준 프로토콜" 항목에 명시된 바와 같이, 농장 환경의 제한된 통신 대역폭과 배터리 용량을 고려할 때 최적의 효율을 제공합니다. <br>**표준 준수:** oneM2M 등 글로벌 표준을 따르어 향후 시스템 확장 시 하드웨어 변경 시도를 최소화합니다. |
| **결과(Consequences)** | **긍정적:** 에너지 효율성 개선 및 대용량 기기 동시 접속 지원.<br>**부정적:** 복잡한 보안 서명 과정을 추가하면 기기 부하가 발생할 수 있음 (Lightweight Authentication 사용 고려). |
| **트레이드오프(Trade-offs)** | 통신 효율성 ↔ 고급 보안 기능 구현 비용. |

### ADR-003: 사용자 선호 정보 및 프라이버시 보호 체계 구축

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 이미지에서 서버 (300) 와 탱크 (400) 사이를 흐르는 "사용자 선호 정보"가 중요한 데이터 포인트로 보입니다. 사용자 (사용자 아이콘) 의 데이터가 수집되고 처리되는 구조입니다. |
| **결정(Decision)** | "사용자 선호 정보" 처리 시 ISO/IEC 27030:2020 가이드라인에 따라 암호화 저장 및 전송을 강제합니다. 또한, KISA 의 IoT 보안 시험·인증 기준에 준한 최소 데이터 원칙을 적용합니다. |
| **근거(Rationale)** | **보안 및 신뢰:** document 의 "KISA 가 제안한 IoT 보안 시험·인증 기준(ITU-T X.1352) 이 국제표준으로 채택"된 점을 고려하면, 사용자의 농업 관련 데이터 (습도, 온도 선호도 등) 를 보호하여 신뢰도를 높이는 것이 필수적입니다. <br>**규제 준수:** ETSI EN 303 645(사이버보안 요구사항) 준수 필수. |
| **결과(Consequences)** | **긍정적:** 데이터 유출 시 발생하는 법적 리스크 감소 및 사용자 신뢰도 향상.<br>**부정적:** 데이터 암호화 오버헤드로 인한 시스템 지연 시간 (Latency) 증가. |
| **트레이드오프(Trade-offs)** | 프라이버시 보호 ↔ 시스템 처리 속도. |

## ⚠️ 잠재적 위험 분석

### 1. [단일 고장점 (Single Point of Failure) 리스크]
- **설명:** 시스템 아키텍처 전체의 핵심이 서버 (300) 로 구성되어 있습니다. 서버 (300) 가宕機 (Down) 하거나 네트워크 연결이 단절될 경우, 농장 (100) 의 센서 데이터 수집과 탱크 (400) 의 제어 (물 공급 등) 가 즉시 중단되어 작물 피해가 발생할 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 서버 (300) 의 클러스터링 (RAID 또는 클라우드 오토스케일링) 을 구현하여 고가용성을 확보하고, 서버와 농장 (100) 간 통신에 엣지 게이트웨이를 두어 서버 연결이 끊겨도 로컬 제어는 유지되도록 합니다.

### 2. [네트워크 지연으로 인한 제어 오작동]
- **설명:** 서버 (300) 에서 탱크 (400) 나 농장 (100) 에 제어 명령을 보내는 데 지연이 발생할 경우, 적정량의 물을 공급하거나 온도를 조절하지 못해 작물이 손상될 수 있습니다. (특히 폭우나 가뭄 같은 급변 상황 시 위험).
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 중요한 제어 명령 (예: 비상 정수) 은 서버를 거치지 않고 직접 센서/액추에이터 (100, 400) 로 전달되는 로컬 제어 로직을 병렬로 구축합니다. (MQTT PubSub 시나리오 활용).

### 3. [보안 취약점 및 데이터 유출]
- **설명:** 서버 (300) 에 집중된 사용자 선호 정보 및 재배 농장 정보 (IoT 데이터) 는 해커의 주요 타겟이 될 수 있습니다. 특히 스마트폰 (200) 을 통한 사용자 접근 시 인증 과정이 약하면 무단 접근이 가능합니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** ITU-T X.1352 및 ETSI EN 303 645에 따라 기기 인증 (Mutual Auth) 과 TLS 1.3 을 강제하며, 인증 토큰 (Token) 만료 시간을 짧게 설정하고 주기적으로 변경합니다.

### 4. [이종 기기 연동 실패 (Interoperability Failure)]
- **설명:** TTA 표준 (TTAK.KO-10.1170) 이나 ISO/IEC 30141을 준수하지 않는 3 자 장비가 농장 (100) 에 추가될 때, 서버 (300) 와 연동되지 않아 시스템에 사각지대가 생길 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** API 게이트웨이를 통해 표준화된 메시지 포맷 (JSON/Protobuf) 이나 표준 프로토콜 (MQTT) 을 강제하며, 새로운 하드웨어 추가 시 반드시 표준 준수 확인 테스트를 거치게 합니다.

### 5. [센서 데이터의 불완전성 및 오류 전달]
- **설명:** 농장 (100) 의 특정 센서가 고장나거나 정확한 값을 송출하지 않아도 서버 (300) 가 이를 "작물 관찰 정보"로 받아들이고 서버 관리 정보를 통해 잘못된 지시를 내릴 수 있습니다. 이는 탱크 (400) 제어에 이어집니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 다중 센서 평균값 처리 알고리즘 구현 및 데이터 이상치 감지 (Anomaly Detection) 를 통해 서버 (300) 가 의심스러운 데이터를 필터링하도록 설계합니다.
