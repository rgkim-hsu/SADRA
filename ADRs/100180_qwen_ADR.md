# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 순차적 데이터 처리 파이프라인 및 모듈화 설계

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜이나 IoT 센서 환경에서 수집되는 방대한 양의 원시 데이터는 노이즈, 결측치, 그리고 센서 오류로 인해 품질이 저하될 수 있음. 또한, 단일 분석 모듈로 모든 로직을 처리하면 시스템의 유지보수가 복잡하고 분석 로직을 확장하기 어려움. 따라서 데이터의 무결성을 보장하고 분석 로직을 체계적으로 관리하기 위한 설계가 필요함. |
| **결정(Decision)** | 데이터 수집 및 분석 전 과정을 5 단계로 나누어 직렬 처리 파이프라인을 구축함.<br>1. **데이터 로딩**: 원시 데이터 수집<br>2. **전처리 모듈**: 데이터 정제 및 초기 가공 (35)<br>3. **이상 데이터 분석 모듈**: 품질 관리 및 오류 데이터 필터링 (37)<br>4. **상관 관계 분석 모듈**: 다변수 분석 및 패턴 파악 (31)<br>5. **생육 정보 분석 모듈**: 최종 가시화된 인사이트 생성 (33)<br>각 단계는 독립적인 모듈로 구현하고, 최종 결과는 통합 저장소 (27) 로 저장되도록 설계함. |
| **근거(Rationale)** | <ul><li>**데이터 품질 우선**: IoT 데이터는 환경 노이즈에 민감하므로, 분석을 시작하기 전 반드시 전처리와 이상 데이터 분석이 필요함.</li><li>**확장성**: 분석 로직이 변경되거나 추가될 때 (예: 새로운 분석 알고리즘 적용), 해당 모듈만 수정하면 전체 시스템에 영향을 주지 않음.</li><li>**시스템 안정성**: 한 단계의 오류가 전체 시스템 정지로 이어지지 않도록 모듈간 경계 (Boundary) 를 명확히 함.</li></ul> |
| **결과(Consequences)** | <ul><li><strong>긍정적:</strong> 데이터 처리의 투명성 증가, 디버깅 용이성, 복잡한 분석 로직을 단계별로 관리 가능.</li><li><strong>부정적:</strong> 데이터가 각 단계를 순차적으로 거치므로, 실시간 처리 시 지연 시간이 발생할 수 있음.</li></ul> |
| **트레이드오프(Trade-offs)** | 직렬 처리 구조는 병렬 처리에 비해 처리 속도가 느릴 수 있으나, 데이터의 정확성과 신뢰성을 확보하는 데 필수적인 선택임. |

## ⚠️ 잠재적 위험 분석

### 1. [전처리 및 데이터 로딩 오류 전파 위험]
- **설명:** '데이터 로딩'이나 '전처리 모듈(35)' 단계에서 센서 오작동이나 네트워크 지연으로 인한 데이터 오류 (결측치, 노이즈) 가 제대로 정제되지 않고, 그 후의 '이상 데이터 분석 모듈(37)' 단계로 넘어갈 경우, 이를 오류로 오인할 가능성이 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 전처리 모듈 내에서 데이터 유효성 검사 (Range Check, Null Check) 로직을 강화하고, 전처리 단계를 통과하지 못한 데이터는 로그를 남기고 차단하는 'Gatekeeper' 역할을 수행하도록 구현.

### 2. [이상 데이터 기준의 편향성 위험]
- **설명:** '이상 데이터 분석 모듈(37)'에서 정상/이상 데이터를 구분하는 기준 (Threshold) 이 잘못 설정되거나 학습된 데이터가 편향되어 있다면, 실제 문제를 가진 데이터까지 '정상'으로 분류되거나, 정상 데이터가 '이상'으로 필터링되어 분석되지 않을 위험이 있음.
- **심각도:** 🟠 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 이상 감지 알고리즘을 주기적으로 재학습하고, 다양한 환경 조건 (날씨, 계절) 을 고려한 다중 기준선 (Multi-threshold) 을 적용.

### 3. [상관 관계 분석의 복잡성 및 성능 저하 위험]
- **설명:** '상관 관계 분석 모듈(31)'은 여러 변수 간의 복잡한 관계를 분석해야 하므로, 데이터 양이 증가하거나 변수 수가 많아지면 분석 시간이 지수적으로 증가할 수 있음. 이는 시스템 응답 속도를 늦출 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 분석 모듈 내부에서 인덱싱을 활용하거나, 데이터 샘플링을 통한 계층적 분석 (Hierarchical Analysis) 을 적용하여 처리 부하를 분산.

### 4. [생육 정보 해석의 오인식 위험]
- **설명:** '생육 정보 분석 모듈(33)'의 최종 결과가 농업 전문가나 운용자에게 잘못된 인사이트로 전달될 경우, 잘못된 농약 살포나 사료 공급 등의 조치로 이어져 실제 생산에 악영향을 줄 수 있음. 특히 가축의 생체 데이터를 기반으로 할 경우 치명적일 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 최종 분석 결과는 확률적 지표 (확신도, 신뢰 구간) 를 함께 제공하는 'Explanation AI' 기능을 적용하고, 최종 결정 전에 인간 전문가의 리뷰 (Human-in-the-loop) 단계를 추가.

### 5. [시스템 연동 및 저장 고장 위험]
- **설명:** 5 개 분석 모듈이 모두 처리를 마친 데이터를 '상관 관계 분석 결과 저장 (27)' 단계로 합치려는 시점에서 네트워크 부하나 DB 연결 오류가 발생할 경우, 처리된 데이터가 저장되지 않고 손실될 수 있음.
- **심각도:** 🟠 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 각 모듈의 출력 데이터를 중간 버퍼 (Buffer) 에 임시 저장하며, 저장 연동 실패 시 재시도 로직 (Retry Logic) 과 오프로드 (Offload) 를 구현하여 데이터 무결성 보장.
