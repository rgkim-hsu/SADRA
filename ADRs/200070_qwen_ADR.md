# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 중앙 클라우드 기반 이벤트 및 데이터 관리를 시스템 허브로 선정

| 항목 | 내용 |
|------|------|
| **상황 (Context)** | 제시된 시스템 개념도는 "Smart sensing & Monitoring", "Smart Control", "Smart analysis & Planning" 세 가지 주요 기능 영역이 "Cloud-based event and data management"를 중심으로 상호 연결된 삼각 구조를 형성하고 있습니다. 이는 사물인터넷 (IoT) 및 스마트팜 관련 국제 표준 (ISO/IEC 30141:2024, oneM2M) 에서 강조하는 데이터 수집, 분석, 제어의 통합을 반영합니다. 시스템은 다양한 센서 데이터를 처리하여 지능적 분석을 수행하고, 이를 바탕으로 현장 제어 장치를 조작해야 하는 복잡성을 가지고 있습니다. 특히 기존 스마트팜 환경에서는 에지 기반의 데이터 처리도 중요하게 고려되지만, 이 아키텍처는 중앙 집중식 클라우드 관리를 핵심으로 하고 있습니다. |
| **결정 (Decision)** | 시스템의 모든 기능 영역 (감지, 제어, 분석) 은 중앙 "Cloud-based event and data management" 모듈을 통해 이벤트 (Event) 와 데이터를 주고받는 것을 원칙으로 합니다. 이 모듈은 단순 저장소가 아닌, 메시지 큐 (MQTT 등) 와 API 를 통해 데이터를 집계, 변환, 분산 처리하는 아키텍처 중재자 (Orchestrator) 역할을 수행합니다. |
| **근거 (Rationale)** | 1. **재사용성 및 상호운용성:** ISO/IEC 30141:2024 및 oneM2M 표준이 공통 데이터 모델과 API 를 강조하므로, 중앙 관리 모듈을 통해 표준화된 인터페이스를 구현하면 디바이스 확장성이 용이합니다.<br>2. **중앙화된 로직:** 분석 및 계획 (Smart analysis & Planning) 이 실시간 데이터를 바탕으로 제어 명령 (Smart Control) 을 내려야 하므로, 데이터의 정확성과 일관성을 보장하기 위해 중앙에서 논리를 처리하는 것이 유리합니다.<br>3. **비용 효율성:** 에지 기기의 연산 능력을 제한적으로 활용하여 복잡한 분석은 클라우드에서 수행하는 하이브리드 아키텍처가 경제적입니다. |
| **결과 (Consequences)** | <ul><li>**장점:** 시스템 통합이 용이하며, 원격 유지보수와 OTA(Over-the-Air) 업데이트가 가능합니다. 분석 엔진을 업그레이드할 때 현장 장비 변경 없이 시스템 전체에 적용할 수 있습니다.</li><li>**단점:** 클라우드 연결이 불안정할 경우 제어 시스템 (Smart Control) 이 마비될 수 있습니다. (이를 보완하기 위해 오프라인 모드나 에지 로컬 로직이 필요합니다.)</li></ul> |
| **트레이드오프 (Trade-offs)** | **중앙 집중화 vs 분산 처리:** 모든 데이터를 클라우드로 보내는 것은 분석 성능은 높이지만, 네트워크 지연 시간을 증가시킵니다. 따라서 제어 (Control) 관련 데이터는 에지에서 필터링하거나 에지 클라우드 연산 방식을 병행하여 처리해야 하는 트레이드오프가 발생합니다. |

## ⚠️ 잠재적 위험 분석

### 1. 실시간 제어 지연 및 시스템 고가용성 리스크
- **설명:** 이미지에서 "Smart Control" 블록이 "Cloud-based event and data management"를 통해 제어 명령을 받아야 함이 명확합니다. 인터넷 연결 부하, 클라우드 서버 과부하 시 제어 명령이 늦어지거나 명령이 전달되지 않는 시나리오가 발생합니다. 스마트팜에서 온도나 습도 조절이 늦어지면 작물 피해를 입힐 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High (네트워크 환경에 의존)
- **대응 방안:** **에지 컴퓨팅 (Edge Computing) 도입.** 제어 명령은 클라우드가 아닌 로컬 게이트웨이 또는 컨트롤러 로컬에서 결정되도록 로직을 분리 (Rule Engine) 합니다. 네트워크가 끊겨도 기본 모드 (Fail-safe) 로 자동으로 작동하도록 설계합니다. (참고문서 [별표 26] 내 "에지 기반 스마트 온실 서비스" 표준 참조)

### 2. IoT 기기 보안 취약점 및 데이터 유출 위험
- **설명:** 수많은 "Smart sensing" 디바이스가 "Cloud"와 통신합니다. IoT 기기들은 고전적 보안 설계를 갖지 않아 해킹의 표적이 됩니다. ETSI EN 303 645 및 ITU-T X.1352 표준에서도 강조하듯이, 센서 인증 부재나 암호화 미구현 시 개인정보나 농가 데이터가 유출될 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium (보안 인식 향상으로 감소 중이지만 여전히 존재)
- **대응 방안:** **End-to-End 암호화 및 인증 프로토콜 적용.** MQTT over TLS 또는 CoAP Security 등을 사용하여 통신 경로를 암호화합니다. IoT 기기에 대한 강력한 인증 (X.509 인증서 등) 을 의무화하고, 표준 (ISO/IEC 27030:2020) 에 따라 안전한 설계를 따릅니다.

### 3. 데이터 통합 및 상호운용성 부족
- **설명:** "Smart sensing"에는 다양한 제조사의 센서가 포함될 수 있습니다. 이들이 "Cloud-based event and data management"로 데이터를 보내기 위한 데이터 포맷이 일관되지 않아 데이터 파싱 오류가 발생할 수 있습니다. oneM2M이나 TTA 표준이 필요하지만, 기존 레거시 장비와의 연동이 어려울 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** **표준화된 데이터 모델 적용.** TTA 의 "스마트팜 데이터 상호운용 프레임워크"를 준수하여 모든 센서가 JSON 기반의 공통 스키마 (Schema) 를 사용하여 데이터를 전송하도록 정의합니다.

### 4. 분석 알고리즘의 편향성 및 의사결정 오류
- **설명:** "Smart analysis & Planning" 블록이 데이터 기반으로 계획을 세웁니다. 하지만 수집된 데이터가 왜곡되었거나 분석 모델이 편향되어 있다면 잘못된 작물 수확 일정이나 병해충 방제 처방이 나옵니다. 이는 농업 생산성 감소로 이어집니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** **데이터 품질 관리 및 모델 검증.** 클라우드에서 데이터 정제 (Cleaning) 단계를 추가하고, AI 모델은 정기적으로 재학습 (Retraining) 을 통해 최신 농기후 데이터에 적응하도록 합니다. 인간의 감지 (Monitoring) 데이터를 AI 판단 결과와 비교 검증하는 루프를 만듭니다.

### 5. 단일 실패점 (Single Point of Failure) 의 위험
- **설명:** 전체 아키텍처가 "Cloud-based event and data management"라는 하나의 중심 요소에 의존하고 있습니다. 이 클라우드 서비스 자체가 중단되거나 공격을 받으면 감지, 분석, 제어 모든 기능이 정지됩니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
