# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 데이터 주도 및 이기종 통합을 위한 이벤트 스트림 아키텍처 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 통합제어시스템은 환경 제너레이터와 가상 센서로부터 수집되는 실시간, 대규모, 이기종(Heterogeneous) 데이터를 처리해야 합니다. 특히, 제어 명령(Control)과 시뮬레이션 결과(Visualization)는 지연 없이, 시간적 맥락(Temporal Context)과 물리적 의미(Semantic Meaning)를 유지하며 전달되어야 하므로, 단순 DB 기반의 폴링(Polling) 방식으로는 데이터 처리 속도와 무결성 확보가 불가능합니다. |
| **결정(Decision)** | **스트림 처리 기반의 메시지 브로커(Message Broker) 중심의 이벤트 스트림 아키텍처(Event Stream Architecture)**를 채택하고, 모든 데이터 전송 및 처리를 비동기적 이벤트를 통해 수행합니다. (기술 스택 예시: Kafka, MQTT Broker). |
| **근거(Rationale)** | 1. **실시간성 및 확장성:** 이벤트 스트림은 데이터가 발생하는 즉시(Event-driven) 시스템에 반영되어, 실시간 제어(Latency Critical)에 필수적이며, 부하가 증가할 경우 수평적 확장성(Horizontal Scaling)이 매우 용이합니다. 2. **디커플링(Decoupling):** 각 컴포넌트(환경 제너레이터, 가상 센서, 제어 시스템, 3D 시뮬레이터)가 독립적으로 데이터 생산 및 소비가 가능하여, 컴포넌트 간의 의존성을 낮추고 유지보수성을 극대화합니다. 3. **시간적 데이터 관리:** 시계열 데이터(Time-Series Data) 처리 및 흐름 제어에 최적화되어, 환경 변화의 연속성을 정확하게 모델링할 수 있습니다. |
| **결과(Consequences)** | **[긍정적]** 높은 실시간 성능, 시스템 컴포넌트 간의 독립적인 업그레이드 및 확장이 용이하며, 데이터의 흐름(Flow)을 중심으로 로직을 구현할 수 있어 복잡한 시뮬레이션 로직 구현에 유리합니다. **[부정적]** 아키텍처가 복잡해지고, 이벤트 발생 순서(Ordering) 보장 및 데이터 보존 정책(Retention Policy) 설계가 매우 어려워집니다. |
| **트레이드오프(Trade-offs)** | **[장점]** 높은 실시간 처리 능력과 확장성(Scalability) 확보. $\rightarrow$ 스마트팜의 복잡하고 동적인 환경을 효과적으로 모델링 가능. **[단점]** 초기 구축 복잡도 및 운영 전문성 요구. $\rightarrow$ 메시지 브로커의 안정적인 운영과 대용량 데이터 흐름 제어에 고도의 운영 역량이 필요함. |

## ⚠️ 잠재적 위험 분석

### 1. 제어 루프 지연 및 동기화 오류 (Control Loop Latency & Desynchronization)
- **설명:** 가상 센서에서 생성된 환경 데이터가 제어 로직(통합제어시스템)으로 전달되는 과정에서 네트워크 지연이나 스트림 처리 부하가 발생하여, 실제 환경과 시스템상의 시간이 불일치하는 상황이 발생할 수 있습니다. 이로 인해 오작동하는 제어 명령이 내려질 위험이 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 엣지 컴퓨팅(Edge Computing)을 도입하여 센서 데이터 수집과 1차 제어 로직을 현장 게이트웨이에서 처리하고, 클라우드로는 집계된 정보만 전송하여 전송 지연을 최소화합니다. 제어 루프에 대해서는 QOS(Quality of Service) 보장 프로토콜을 의무 적용합니다.

### 2. 데이터 의미론적 상호운용성 결함 (Semantic Interoperability Failure)
- **설명:** 스마트팜 환경은 토양 데이터, 온도 데이터, CO2 농도 등 수많은 물리적 매개변수와 작물 생육 데이터 등 생물학적 데이터가 혼재합니다. 가상 센서가 이기종 데이터를 표준화된 의미론적 계층(Semantic Layer) 없이 통합할 경우, 서로 다른 단위나 의미로 데이터가 해석되어 잘못된 제어 결정을 초래할 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 모든 데이터 모델링에 대해 ISO/IEC 30141 또는 oneM2M 표준을 기반으로 데이터 스키마와 용어 정의(Ontology)를 강제합니다. 데이터 적재 전 모든 값에 대한 유효성 검사(Schema Validation) 및 의미론적 매핑 레이어를 필수적으로 구현합니다.

### 3. 사이버-물리 시스템 공격 (Cyber-Physical Attack)
- **설명:** 통합제어시스템이 공정의 물리적 구동기(Actuator)를 제어하는 권한을 갖기 때문에, 시스템 해킹을 당할 경우 단순히 정보 유출을 넘어 실제 농장 환경(예: 난방/환기 시스템, 관수 펌프)에 물리적인 손상을 입히는 심각한 사고로 이어질 수 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 제어 영역과 정보 영역을 철저히 분리(Air Gap 또는 네트워크 Segmentation)합니다. 모든 제어 명령어는 다단계 인증(MFA) 및 권한 제어(Role-Based Access Control, RBAC)를 거치도록 설계하고, 이상 탐지 시스템(Anomaly Detection)을 통해 비정상적인 제어 명령 패턴을 상시 모니터링합니다.

### 4. 확장성 및 모델 관리 복잡성 (Scalability and Model Management Complexity)
- **설명:** 스마트팜의 규모가 커지거나, 새로운 작물, 새로운 센서, 새로운 제어 기술이 추가될 때마다 환경 제너레이터와 가상 센서의 시뮬레이션 모델을 수동으로 업데이트해야 하는 경우, 시스템의 관리 복잡성이 급격하게 증가하여 운영상의 병목 현상이나 모델 오류가 발생합니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 모든 시뮬레이션 모델을 모듈화(Modularization)하고, 플러그인 아키텍처를 도입하여 새로운 환경 컴포넌트 추가 시 시스템 코어 수정 없이 플러그인 형태로 즉시 통합할 수 있도록 설계합니다. 버전 관리 시스템(Versioning)을 통해 모델 변경 이력을 엄격하게 관리해야 합니다.

### 5. 데이터 사일로 및 비가시성 (Data Silo and Visibility Loss)
- **설명:** 데이터가 '환경 제너레이터'에 머물러 있고, '가상 센서'에서 가공된 후, '통합제어시스템'의 특정 모듈(예: 생육 예측)로만 사용되고, 그 결과가 '3D 시뮬레이션'까지 완전하게 순환되지 못하는 데이터 사일로 현상이 발생할 수 있습니다. 시스템 전체의 데이터 흐름이 투명하게 파악되지 않는 경우, 최적화 기회가 상실됩니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 중앙 데이터 저장소(Central Data Lake/Lakehouse)를 구축하여 모든 단계의 원시 데이터(Raw Data), 가공 데이터(Processed Data), 모델 결과물(Derived Data)을 한곳에 통합하고, 데이터 거버넌스 플랫폼을 통해 데이터의 라이프사이클과 접근 권한을 통일적으로 관리합니다.
