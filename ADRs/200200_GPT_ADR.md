📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 모듈형 IoT 컨트롤러 기반 분산 제어 및 통합 운영 플랫폼 아키텍처 채택

| 항목                     | 내용                                                                                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 시스템은 환기, 관수, 개폐(거적 등) 제어를 수행하는 다수의 IoT 컨트롤러와 CCTV 및 환경센서를 통한 모니터링, 그리고 스마트폰 기반 원격 제어 플랫폼으로 구성된다. 다양한 제어 대상과 농가 환경의 이질성을 고려할 때, 유연한 확장성과 저비용 구축이 핵심 과제이다.    |
| **결정(Decision)**       | 각 제어 장치별로 독립적인 IoT 컨트롤러를 배치하는 모듈형 분산 제어 구조를 채택하고, 이를 무선공유기를 통해 연결하여 스마트폰 앱 기반 통합 운영 플랫폼에서 제어 및 모니터링을 수행하는 구조로 설계한다. 기능은 모니터링, 원격제어, 정보 제공(귀농/농사/시세)으로 분리한다. |
| **근거(Rationale)**      | 농가 환경은 규모와 설비가 다양하므로 일체형 시스템보다 모듈형 구조가 적합하다. IoT 기반 분산 제어는 설치 및 유지보수 유연성을 제공하며, 스마트폰 중심 UI는 사용자 접근성을 높인다. 또한 정보 서비스 통합은 단순 제어를 넘어 농업 지원 플랫폼으로 확장 가능하게 한다.   |
| **결과(Consequences)**   | **긍정적:** 확장성 및 유연성 확보, 저비용 구축 가능, 사용자 편의성 향상, 기능 확장 용이**부정적:** 네트워크 의존성 증가, 장치 간 동기화 문제, 보안 취약점 증가                                                          |
| **트레이드오프(Trade-offs)** | 유연하고 확장 가능한 구조를 얻는 대신, 분산된 장치 관리와 네트워크 안정성 확보에 대한 부담이 증가한다.                                                                                                 |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. IoT 컨트롤러 간 통신 장애

* **설명:** 무선 네트워크 불안정으로 각 컨트롤러 간 데이터 전달이 지연 또는 실패할 수 있음

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 메시지 큐 기반 통신, 로컬 제어 로직 유지, 네트워크 이중화

### 2. 스마트폰 플랫폼 보안 취약점

* **설명:** 모바일 앱 해킹 시 원격 제어 권한이 탈취될 수 있음

* **심각도:** 🔴 High

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 강력한 인증(2FA), 암호화 통신, API 보안 강화

### 3. 분산 장치 관리 복잡성

* **설명:** 다수의 IoT 컨트롤러 관리 및 펌웨어 업데이트가 어려워질 수 있음

* **심각도:** 🟡 Medium

* **발생 가능성:** 🔴 High

* **대응 방안:** 중앙 관리 시스템 구축, OTA(Over-the-Air) 업데이트 적용, 장치 상태 모니터링

### 4. 센서 및 CCTV 데이터 처리 부담

* **설명:** 영상 및 환경 데이터 증가로 네트워크 및 저장소 부하 발생

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 엣지 컴퓨팅 도입, 데이터 압축 및 이벤트 기반 저장

### 5. 제어 명령 충돌

* **설명:** 자동 제어와 사용자 수동 제어 간 충돌로 비정상 동작 가능

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 제어 우선순위 정책 설정, 충돌 감지 및 알림 기능 구현

### 6. 시스템 확장 시 성능 저하

* **설명:** 농가 규모 확장으로 IoT 장치 수 증가 시 플랫폼 성능 저하 발생

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** 클라우드 기반 확장 구조, 마이크로서비스 아키텍처 적용, 로드 밸런싱

### 7. 사용자 IT 활용 능력 격차

* **설명:** 고령 농업인의 경우 스마트폰 기반 시스템 활용이 어려울 수 있음

* **심각도:** 🟢 Low

* **발생 가능성:** 🔴 High

* **대응 방안:** 직관적 UI/UX 설계, 교육 프로그램 제공, 음성 기반 인터페이스 지원
