🏗️ 아키텍처 분석 보고서
===============

📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 규칙 기반 추천 엔진을 활용한 순차적 재배 방법 결정 파이프라인 채택

| 항목                     | 내용                                                                                                                                                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 시스템은 농가별로 상이한 토양 조건, 기상 환경, 작업 가용 시간, 기존 재배 방식이 복합적으로 얽혀 있다. 단일 입력값이 아닌 다차원 데이터(토양정보·기상정보·작업시간·재배방법 정보)를 순차적으로 수집·통합하여 최적 재배 방법을 결정하고 농가에 전달해야 하는 아키텍처적 과제가 존재한다.                                            |
| **결정(Decision)**       | S1001(토양·기상정보 획득) → S1002(작업시간·재배방법 정보 획득) → S1003(추천 재배 방법 결정) → S1004(추천 재배 방법 송신)의 4단계 선형 파이프라인 구조를 채택하고, S1003 단계에 규칙 기반(Rule-based) 혹은 ML 기반 추천 엔진을 배치한다.                                                    |
| **근거(Rationale)**      | 농업 도메인 특성상 입력 데이터 간 의존성이 높아 병렬 처리보다 순차적 데이터 검증이 안정적이다. 기상·토양 데이터는 외부 API 및 IoT 센서로부터 획득하며, 작업시간·재배방법 정보는 농가 입력 데이터로 분리 수집함으로써 데이터 소스별 책임을 명확히 한다. 추천 결정 로직을 독립 컴포넌트(S1003)로 분리하면 알고리즘 교체·고도화 시 타 단계 영향 최소화가 가능하다. |
| **결과(Consequences)**   | 긍정적: 각 단계의 책임이 명확하여 유지보수성 향상, 단계별 로깅 및 감사 추적 용이, 추천 로직의 독립적 개선 가능. 부정적: 단계 간 직렬 처리로 인해 전체 레이턴시가 누적되며, 특정 단계 장애 시 전체 파이프라인 중단 위험 존재.                                                                               |
| **트레이드오프(Trade-offs)** | 얻는 장점: 단순하고 명확한 데이터 흐름, 단계별 독립 테스트 가능, 도메인 전문가가 S1003 로직을 이해·검증 가능. 감수할 단점: 고가용성을 위한 각 단계별 이중화 구성 필요, 입력 데이터 누락 시 폴백(fallback) 전략 별도 설계 필요, 실시간성 요구가 높아질 경우 이벤트 기반 아키텍처로의 전환 검토 필요.                               |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. 외부 데이터 소스 단절로 인한 파이프라인 전체 중단

* **설명:** S1001 단계에서 기상청 API, IoT 토양 센서 등 외부 데이터 소스와의 연결이 끊길 경우, 이후 S1002~S1004 단계가 모두 실행 불가 상태가 된다. 농번기 집중 사용 시점에 기상 API 장애가 발생하면 전체 서비스가 중단되는 단일 장애점(SPOF)으로 작용한다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 외부 API에 대한 Circuit Breaker 패턴 적용, 최근 정상 수신된 데이터를 캐싱하여 일정 시간 내 폴백으로 활용하는 데이터 캐시 레이어 구성, 센서 이중화 및 오프라인 대응 로컬 추론 모드 도입.

### 2. 추천 엔진(S1003) 모델 편향으로 인한 부적절한 재배 방법 권고

* **설명:** 규칙 기반 또는 ML 모델이 특정 작물·지역·계절에 편중된 학습 데이터로 훈련된 경우, 소규모 농가나 비주류 재배 방식에 대해 부정확한 추천을 반복 출력할 수 있다. 농가가 시스템 권고를 신뢰하여 잘못된 재배 방법을 따를 경우 수확량 손실 및 경제적 피해로 이어진다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 추천 결과에 신뢰도 점수(Confidence Score) 및 근거 설명 함께 제공, 농업 전문가 검토 기반의 정기적 모델 재훈련 및 A/B 테스트 체계 수립, 추천 결과에 대한 농가 피드백 루프 구성으로 지속적 품질 개선.

### 3. 농가 민감 데이터 유출 및 프라이버시 침해

* **설명:** S1001~S1002 단계에서 수집되는 토양 정보, 작업 시간, 재배 방법 정보는 농가의 경영 노하우와 직결되는 민감 데이터다. 송신 단계(S1004)에서 데이터가 암호화되지 않거나 접근 제어가 미흡할 경우, 경쟁 농가·외부 공격자에게 정보가 노출될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 전 구간 TLS 암호화 적용, 농가 단위 데이터 격리(멀티테넌시 보안 설계), 역할 기반 접근 제어(RBAC) 구현, 개인정보보호법 및 농업 데이터 관련 법령 준수를 위한 정기 보안 감사 수행.

### 4. 입력 데이터 품질 저하로 인한 추천 정확도 하락

* **설명:** S1002 단계에서 농가가 작업 시간 또는 재배 방법 정보를 부정확하게 입력하거나, IoT 센서의 노후화·오염으로 토양 측정값이 왜곡될 경우, S1003의 추천 결정이 오염된 입력값을 기반으로 산출된다. "Garbage in, Garbage out" 문제가 현장에서 빈번하게 발생할 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 각 입력 단계에 데이터 유효성 검증(Validation) 및 이상치 탐지(Anomaly Detection) 로직 삽입, 센서 정기 교정(Calibration) 스케줄 관리 체계 구축, 사용자 입력 UI에 가이드 및 범위 제한 기능 추가.

### 5. 시스템 확장 시 단일 선형 구조의 성능 병목

* **설명:** 현재 선형 파이프라인 구조(S1001→S1002→S1003→S1004)는 농가 수가 수십 개일 때는 문제없으나, 수천~수만 농가가 동시에 추천을 요청하는 확장 시나리오에서는 S1003 추천 결정 단계가 심각한 처리 병목이 될 수 있다. 농번기 등 특정 시점에 트래픽이 집중될 경우 응답 지연 또는 서비스 불가 상태가 발생할 수 있다.

* **심각도:** 🟡 Medium

* **발생 가능성:** 🟡 Medium

* **대응 방안:** S1003 추천 엔진의 수평 확장(Horizontal Scaling) 가능하도록 Stateless 설계 적용, 메시지 큐(예: Kafka, RabbitMQ)를 도입하여 비동기 처리 구조로 전환 검토, 농번기 대비 오토스케일링(Auto Scaling) 정책 사전 수립 및 부하 테스트 정기 실시.
