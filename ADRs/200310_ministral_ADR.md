## 📋 **ADR (Architecture Decision Record)**

### **ADR-001: 클라우드 기반 스마트 팜 관리 시스템의 중앙 집중형 모니터링 및 학습 기능 구현**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트 팜 시스템은 다수의 사용자(User 1~n)가 실시간으로 농업 데이터를 모니터링하고, AI 기반 학습 기능을 통해 최적화된 농업 조언을 받아야 함. 기존 분산형 시스템은 데이터 일관성 및 실시간 처리에 한계가 존재하며, 보안 및 상호운용성도 확보해야 함. |
| **결정(Decision)** | 1) **중앙 집중형 클라우드 아키텍처** 채택: 모든 사용자 데이터 및 학습 모델을 클라우드 내 **Smart Farming Management Function (SFMF)**에 집중 관리 <br> 2) **모니터링 기능 분리**: `Monitoring Function`을 통해 실시간 데이터 수집 및 사용자별 알림 제공 <br> 3) **학습 기능 분리**: `Learning Screening Function`과 `Learning Information Connection Function`을 통해 AI 모델 학습 및 데이터 연계 처리 |
| **근거(Rationale)** | - **ISO/IEC 30141:2024** 및 **oneM2M** 표준에 따라 중앙 집중형 아키텍처가 스마트 팜 시스템의 확장성 및 보안을 보장 <br> - **ETSI EN 303 645** 준수하여 클라우드 내 데이터 암호화 및 접근 통제 강화 <br> - **TTA 스마트팜 데이터 상호운용 프레임워크**에 따라 API 기반 데이터 연계 처리 |
| **결과(Consequences)** | ✅ **장점**: 실시간 모니터링 및 AI 학습 기능 강화, 데이터 일관성 보장, 보안 및 상호운용성 향상 <br> ❌ **단점**: 클라우드 의존도 증가로 네트워크 장애 시 시스템 중단 가능성, 초기 구축 비용 증가 |
| **트레이드오프(Trade-offs)** | - **장점**: 확장성 및 유지보수 용이성 향상 <br> - **단점**: 네트워크 의존성 증가, 데이터 프라이버시 관리 필요성 |

---

### **ADR-002: 데이터 흐름 및 API 표준화**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 다수의 사용자와 시스템 간 데이터 교환이 필요하며, **스마트팜 데이터 상호운용 프레임워크**를 준수해야 함. |
| **결정(Decision)** | 1) **LMS (Learning Management System)**과 **FMCF (Farming Management Connection Function)** 간 **RESTful API** 및 **MQTT 프로토콜** 사용 <br> 2) **TTAK.KO-10.1170** 표준에 따라 데이터 포맷 및 인터페이스 정의 |
| **근거(Rationale)** | - **IETF CoAP/MQTT** 표준을 통해 경량 통신 보장 <br> - **oneM2M** 및 **ETSI** 표준과 호환성 확보 |
| **결과(Consequences)** | ✅ **장점**: 데이터 상호운용성 강화, 실시간 통신 가능 <br> ❌ **단점**: API 관리 복잡성 증가, 보안 패치 필요성 |
| **트레이드오프(Trade-offs)** | - **장점**: 표준화된 데이터 처리 <br> - **단점**: API 버전 관리 및 보안 업데이트 필요 |

---

### **ADR-003: 보안 및 접근 통제**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트 팜 시스템은 농업 데이터가 민감하므로 **ITU-T X.1352** 및 **ISO/IEC 27030:2020** 준수 필요. |
| **결정(Decision)** | 1) **클라우드 내 데이터 암호화** (AES-256) <br> 2) **사용자 인증** (OAuth 2.0 + JWT) <br> 3) **접근 통제** (RBAC 모델) |
| **근거(Rationale)** | - **KISA 보안 기준** 및 **ETSI EN 303 645** 준수 <br> - **Matter/OCF** 표준과 호환성 확보 |
| **결과(Consequences)** | ✅ **장점**: 데이터 보안 강화, 불법 접근 방지 <br> ❌ **단점**: 인증/인가 처리 지연 가능성 |
| **트레이드오프(Trade-offs)** | - **장점**: 보안 강화 <br> - **단점**: 시스템 복잡성 증가 |

## ⚠️ **잠재적 위험 분석**

### **1. 네트워크 장애로 인한 시스템 중단**
- **설명**: 클라우드 의존성으로 인해 네트워크 장애 시 사용자 모니터링 및 학습 기능 마비 가능.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **지역별 클라우드 노드 배포** (다중 지역 지원)
  - **오프라인 모드 지원** (로컬 캐싱 및 동기화 기능)

### **2. 데이터 프라이버시 위반**
- **설명**: 농업 데이터 유출로 인해 사용자 신뢰 손실 및 법적 문제 발생 가능.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **GDPR 및 K-ISMS 준수** (데이터 암호화 및 접근 로깅)
  - **사용자 동의 기반 데이터 처리** (개인정보 보호법 준수)

### **3. AI 학습 모델의 오류 및 편향**
- **설명**: 학습 데이터의 편향으로 인해 잘못된 농업 조언 제공 가능.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **다양한 데이터 소스 통합** (공공 데이터 및 사용자 피드백 활용)
  - **모델 성능 모니터링** (실시간 오류 감지 및 재학습)

### **4. API 및 인터페이스 호환성 문제**
- **설명**: 새로운 디바이스 추가 시 기존 API와 호환성 문제 발생 가능.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **백워드 호환성 보장** (API 버전 관리)
  - **스키마 레지스트리 활용** (OpenAPI/Swagger 문서화)

### **5. 시스템 확장성 한계**
- **설명**: 사용자 및 데이터 증가로 인해 클라우드 리소스 부족 발생 가능.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟢 Low (단기)
- **대응 방안**:
  - **자동 스케일링 구성** (Kubernetes 기반 클라우드 배포)
  - **미리용량 계획** (예상 트래픽 분석)
