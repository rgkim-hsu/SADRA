## 100260

# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 중앙 프로세서 기반의 미디어 콘텐츠 관리 및 기계적 제어 통합 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                                                                                     |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 다수의 카메라(316, 414)로부터 입력된 영상 신호를 처리하고, 사진/비디오 콘텐츠 메모리(426)에 저장하며, 디스플레이(442) 및 단일-액션 회전 메커니즘(435)을 실시간으로 제어해야 하는 스마트 디바이스 환경임. 각 모듈(카메라, 메모리, 구동부)이 독립적으로 작동할 경우 데이터 동기화 및 제어 타이밍의 불일치가 발생할 수 있는 아키처적 과제가 존재함.                                                                                                          |
| **결정(Decision)**       | **중앙 프로세서(421)**를 시스템의 핵심 허브(Hub)로 설정하여 모든 데이터 흐름(카메라 입력, 메모리 입출력)과 기계적 제어 신호(회전 메커니즘, 디스플레이/카메라 체인저)를 통합 관리하는 **중앙 집중식 제어 아키텍처**를 채택함.                                                                                                                                                                                |
| **근거(Rationale)**      | 1. **동기화 용이성:** 영상 녹화(메모리 저장)와 물리적 카메라 회전(435) 또는 디스플레이 전환(449)이 밀접하게 연관될 때, 단일 프로세서가 이를 조정하면 타이밍 오류를 최소화할 수 있음.<br>2. **자원 효율성:** 별도의 컨트롤러를 두지 않고 중앙 프로세서가 리소스를 할당함으로써 하드웨어 비용을 절감하고 회로 설계를 단순화할 수 있음.<br>3. **유연한 라우팅:** 카메라 체인저(414)와 디스플레이 체인저(449)를 프로세서가 제어함으로써, 사용자 명령이나 자동 감지에 따라 입력 소스와 출력 대상을 유연하게 변경할 수 있음. |
| **결과(Consequences)**   | 시스템의 제어 로직이 단순해지고 통합 관리가 용이해짐. 특히 미디어 콘텐츠(사진/비디오)의 저장과 재생, 그리고 기계적 동작 간의 연동이 원활해짐. 반면, 중앙 프로세서에 모든 부하가 집중되므로 고성능 프로세서가 요구되며, 프로세서 장애 시 전체 시스템이 마비되는 리스크가 있음.                                                                                                                                                           |
| **트레이드오프(Trade-offs)** | 제어 로직의 단순화 및 모듈 간 높은 동기화 성능 확보 vs. 중앙 프로세서의 성능 병목 현상(Bottleneck) 가능성 및 단일 장애점(SPOF) 리스크 증가.                                                                                                                                                                                                                            |

## ⚠️ 잠재적 위험 분석

### 1. 중앙 프로세서(421)의 과부하 및 성능 저하

- **설명:** 고해상도 비디오 스트림 처리(인코딩/디코딩)와 단일-액션 회전 메커니즘(435)의 실시간 제어, 디스플레이 렌더링이 동시에 수행될 경우, 중앙 프로세서의 컴퓨팅 자원이 고갈되어 프레임 드랍(Frame Drop)이나 제어 지연이 발생할 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High
- **대응 방안:** 영상 처리 전용 하드웨어 가속기(VPU/GPU)를 별도로 탑재하거나, 실시간 제어(RTOS)와 비실시간 작업(Android/Linux)을 분리하는 하이브리드 OS 아키텍처 도입.
  
  ### 2. 메모리(426) 입출력(I/O) 경합으로 인한 데이터 지연
- **설명:** 카메라로부터의 실시간 기록(Write)과 사용자의 요청에 따른 사진/비디오 재생(Read)이 사진 콘텐츠 메모리 및 비디오 콘텐츠 메모리(426)에서 동시에 발생하면, 메모리 버스 대역폭 부족으로 인해 저장 지연이나 재생 버퍼링이 발생할 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 메모리 대역폭 최적화를 위한 DMA(Direct Memory Access) controller 활용, 읽기/쓰기 우선순위 큐(Priority Queue) 도입, 또는 고속 NVMe/UFS 스토리지 적용.
  
  ### 3. 기계적 제어(435)와 영상 데이터 간의 비동기화
- **설명:** 중앙 프로세서(421)가 카메라 회전(435)을 명령했으나, 처리 지연으로 인해 실제 기계적 동작과 카메라가 촬영하는 영상 프레임 간의 시점(Time-stamp)이 불일치하여, 회전 중의 영상이 끊기거나 왜곡된 데이터가 저장될 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 모터 제어 신호에 타임스탬프를 부여하여 영상 메타데이터와 동기화, 회전 동작 중에는 영상 처리 부하를 일시적으로 낮추는 Throttling 로직 적용.
  
  ### 4. 갑작스런 전원 차단 시 콘텐츠 메모리(426) 데이터 손실
- **설명:** 비디오 콘텐츠 메모리에 데이터를 기록하는 도중 전원이 차단될 경우, 파일 시스템이 손상되거나 현재 기록 중인 영상 파일이 재생 불가능한 상태로 저장(Corruption)될 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 저널링 파일 시스템(Journaling File System) 적용, 정전 감지 시 즉시 기록을 완료하고 안전하게 마운트 해제하는 UPS(무정전 전원 장치) 또는 슈퍼커패시터 백업 회로 도입.
  
  ### 5. 발열로 인한 시스템 쓰로틀링(Throttling)
- **설명:** 중앙 프로세서(421)가 지속적으로 고부하 연산을 수행할 경우 기기 내부 온도가 상승하여, 프로세서가 스스로 성능을 낮추는 쓰로틀링 현상이 발생하면 카메라 회전 속도 저하나 디스플레이 지연이 발생할 수 있음.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 방열판(Heat Sink) 및 서멀 패드 적용 등 물리적 냉각 설계 강화, 온도 센서를 통한 모니터링 및 과열 시 불필요한 백그라운드 작업 중지 로직 구현.
