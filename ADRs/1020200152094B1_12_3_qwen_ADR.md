# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 에지/클라우드 하이브리드 렌더링 및 데이터 동기화 전략

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 시스템은 고사양 3D 시뮬레이션을 필요로 하는 VR 글러브(130) 및 헤드셋(100) 사용자와, 별도의 태블릿에서 접근하는 원격 관리자(20)가 존재합니다. 대규모 데이터 서버(100)와 연결되면서, VR 체험의 몰입도를 유지해야 하므로 대역폭과 지연시간(latency) 문제가 발생합니다. |
| **결정(Decision)** | VR 시뮬레이션 렌더링은 로컬 기기(또는 엣지 서버)에서 처리하고, 서버(100)에는 최소한의 상태 데이터와 시장 정보만 동기화하는 방식을 결정합니다. 동시에 TTA 표준이나 ISO/IEC 30141과 같은 IoT 아키텍처 표준에 맞춰 통신 인터페이스를 정의합니다. |
| **근거(Rationale)** | 전체 계산을 서버에서 하려면 VR 지연이 발생해 몰입감이 떨어집니다. 또한, 데이터 서버(100)와 클라이언트 간 통신 안정성을 위해 표준화된 프로토콜(IETF CoAP, MQTT 등)을 사용해야 합니다. |
| **결과(Consequences)** | **긍정적:** VR 체험의 부드러운 반응성 보장, 서버 비용 절감.<br>**부정적:** 로컬 기기의 연산 처리 능력에 의존하므로, 저사양 기기 지원이 제한될 수 있음. |
| **트레이드오프(Trade-offs)** | 높은 로컬 처리 성능 요구 (장점) vs 낮은 네트워크 대역폭 활용 (단점). |

## ⚠️ 잠재적 위험 분석

### 1. VR 데이터 스트리밍의 지연 (Latency) 및 끊김
- **설명:** VR 시뮬레이션이 서버(100)나 클라우드와 동기화 과정에서 네트워크 지연이 발생하여, 사용자가 글러브(130)로 조작하는 동작이 화면에 늦게 표시되거나 끊기는 현상이 발생합니다. 이는 교육의 몰입감을 심각하게 해칩니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🔴 High (복잡한 3D 환경 사용 시)
- **대응 방안:** 핵심 렌더링 로직은 로컬에서 독립적으로 실행하고 (Local-first), 서버 데이터는 비동기적으로 업데이트되도록 아키텍처를 설계합니다. 또한, 네트워크 상태가 나쁠 때 로컬 캐시를 이용한 오프라인 모드를 지원합니다.

### 2. 원격 관리자 보안 취약점
- **설명:** 원격 관리자(20)가 태블릿(300)을 통해 서버(100) 데이터를 접속할 때, 전송 중인 데이터(시장 정보, 시설 데이터 등)가 탈취되거나, 불법적인 접근으로 농장 운영 데이터가 유출될 위험이 있습니다.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 통신 구간 암호화 (SSL/TLS) 를 필수적으로 적용하고, 관리자 인증을 위한 RBAC (Role-Based Access Control) 기반의 권한 분리 관리를 도입합니다.

### 3. 데이터 일관성 문제 (Data Consistency)
- **설명:** 교육생이 VR 화면에서 시설을 설치하거나 작물을 재배하는 데이터가 서버(100)에 즉시 반영되지 않아, 원격 관리자(20)가 확인하는 데이터와 VR 내 데이터가 상이한 상황을 초래합니다. (Race condition)
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 실시간 양방향 데이터 동기화 프로토콜 (WebSocket 등) 을 사용하거나, 마지막 업데이트 시간을 기준으로 충돌을 해결하는 로직을 적용합니다.

### 4. 하드웨어 호환성 및 표준 미준수
- **설명:** 'VR 글러브 (130)' 및 'VR 헤드셋 (100)'과 같은 입력 장비들이 다양한 제조사의 기기에서 표준화된 규격 (예: OCF, Matter 등) 을 따르지 않아, 특정 기기에서만 작동하거나 데이터가 제대로 수집되지 않는 문제가 발생할 수 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 개발 단계부터 관련 IoT 표준 (TTA, ISO/IEC 30141:2024) 을 준수하되, API 레벨에서 기기 간 상호운용성을 테스트합니다.

### 5. 단일 서버 의존도 (Single Point of Failure)
- **설명:** 시스템이 단일 '데이터 홀 서버 (100)' 에 크게 의존하고 있어, 서버 고장이나 네트워크 장애 시 원격 관리자(20) 및 교육 환경 전체가 마비될 위험이 있습니다.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟢 Low (클라우드 인프라 기준)
- **대응 방안:** 서버의 백업 시스템 및 고가용성(HA) 아키텍처 (Load Balancer 활용) 를 구성하여 서버 장애 시에도 시스템 가용성을 확보합니다.
