## 📋 ADR (Architecture Decision Record)

### **ADR-001: 분산형 센서-에지-클라우드 하이브리드 아키텍처 채택**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 시스템은 실시간 환경 데이터 수집, AI 기반 예측 분석, 원격 제어 기능이 요구되며, 네트워크 지연과 보안성, 확장성을 고려해야 함. 농장 내 센서 노드(200개 이상)와 게이트웨이(100개 이상)가 분산 배치되어 있으며, 클라우드와 에지 컴퓨팅의 조합을 통해 실시간 처리가 필수적임. |
| **결정(Decision)** | **1) 에지 컴퓨팅 기반 지역 처리 + 클라우드 중앙 집중형 하이브리드 아키텍처** 채택 <br> **2) MQTT/CoAP 프로토콜을 이용한 경량 통신** <br> **3) TTA 스마트팜 표준과 ISO/IEC 30141:2024 준수** <br> **4) AI 모델의 에지-클라우드 동적 로딩 기능 구현** |
| **근거(Rationale)** | - **에지 처리**: 센서 데이터의 지역 처리(예: 온도/습도 이상 감지)로 네트워크 부하 감소 및 실시간 대응 가능 <br> - **클라우드 집중**: AI 기반 장기 예측(병해충 예측, 수확 최적화) 및 대용량 데이터 분석 <br> - **표준 준수**: TTA 표준과 ISO/IEC 30141의 상호운용성 요구사항 충족 <br> - **프로토콜 선택**: MQTT(Pub/Sub 모델)의 효율성과 CoAP의 RESTful 지원으로 IoT 장치 간 통신 최적화 |
| **결과(Consequences)** | ✅ **장점**: <br> - 네트워크 지연 최소화(에지 처리) <br> - 확장성 및 유연성 향상(클라우드 스케일링) <br> - 보안 강화(지역 데이터 암호화 + 클라우드 접근 제어) <br> - 표준 준수로 글로벌 상호운용성 확보 <br> ❌ **단점**: <br> - 에지-클라우드 동기화 복잡성 증가 <br> - 초기 구축 비용 상승(하이브리드 인프라) |
| **트레이드오프(Trade-offs)** | - **성능 vs. 비용**: 에지 장비 추가로 초기 비용 증가하지만 실시간 처리 성능 향상 <br> - **중앙집중 vs. 분산**: 클라우드 의존도 감소로 단일 장애점 위험 완화, 하지만 에지 노드 관리가 복잡해짐 |

### **ADR-002: AI/ML 기반 예측 모델의 에지-클라우드 동적 로딩**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 병해충 예측 및 환경 최적화 모델은 클라우드에서 학습되지만, 에지에서 실시간 추론이 필요함. 모델 크기(예: 10MB 이상) 및 네트워크 대역폭 제약으로 에지 로딩이 어려움. |
| **결정(Decision)** | **1) 모델 분할(Quantization + Pruning)**: 에지용 경량 모델(1MB 이하) 생성 <br> **2) 동적 로딩 메커니즘**: 에지에서 필요 시 클라우드 모델 다운로드 및 업데이트 <br> **3) FedML(연방 학습) 지원**: 지역 에지 모델 클라우드에 반영 |
| **근거(Rationale)** | - **모델 최적화**: Quantization(8-bit 정수화)으로 모델 크기 90% 감소 <br> - **동적 로딩**: 에지에서 필요 시만 모델 다운로드(예: 병해충 발생 시) <br> - **FedML**: 지역 데이터 특성 반영으로 모델 정확도 향상 |
| **결과(Consequences)** | ✅ **장점**: <br> - 에지 장치 자원 효율성 향상 <br> - 실시간 추론 가능 <br> - 모델 지속적 개선 <br> ❌ **단점**: <br> - 모델 동기화 복잡성 <br> - 초기 학습 비용 증가 |
| **트레이드오프(Trade-offs)** | - **정확도 vs. 성능**: 경량 모델로 에지 성능 향상지만 클라우드 모델보다 정확도 하락 가능 <br> - **네트워크 사용량**: 동적 로딩으로 대역폭 사용 증가 |

### **ADR-003: 보안 아키텍처 - ITU-T X.1352 및 ETSI EN 303 645 준수**
| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 시스템은 농장 내 센서부터 클라우드까지의 보안이 필수적임. 특히, 원격 제어 기능으로 인해 사이버 공격 위험이 높음. |
| **결정(Decision)** | **1) 엔드투엔드 암호화**: TLS 1.3 + AES-256 <br> **2) 게이트웨이 기반 접근 제어**: OAuth 2.0 + JWT <br> **3) KISA 기준 인증**: IoT 장치 보안 인증 필수 <br> **4) 블록체인 로깅**: 데이터 조작 방지 |
| **근거(Rationale)** | - **ITU-T X.1352**: IoT 기기 보안 요구사항 준수 <br> - **ETSI EN 303 645**: 사이버보안 기준 충족 <br> - **블록체인**: 불변성 로깅으로 감사 가능성 향상 |
| **결과(Consequences)** | ✅ **장점**: <br> - 글로벌 보안 표준 준수 <br> - 데이터 무결성 보장 <br> ❌ **단점**: <br> - 성능 오버헤드(암호화/인증) <br> - 복잡한 키 관리 |
| **트레이드오프(Trade-offs)** | - **보안 vs. 성능**: 암호화로 성능 저하 가능하지만 필수적 <br> - **중앙집중 vs. 분산**: 게이트웨이 기반 접근 제어로 단일 장애점 완화 |

## ⚠️ 잠재적 위험 분석

### **1. 네트워크 지연 및 대역폭 과부하**
- **설명**: 에지-클라우드 동적 로딩 시 네트워크 지연 발생(예: 모델 다운로드 5초 이상). 대량 센서 데이터(200개 이상) 수집 시 게이트웨이 과부하 가능.
- **심각도**: 🔴 High | **발생 가능성**: 🔴 High
- **대응 방안**:
  - **MQTT QoS Level 1** 사용으로 신뢰성 확보
  - **지역 캐시**: 게이트웨이에 자주 사용되는 모델 캐시
  - **에지 필터링**: 불필요 데이터 지역 처리

### **2. 에지 장치 장애로 인한 시스템 단일 장애점**
- **설명**: 에지 서버(예: 병해충 예측 노드) 장애 시 해당 지역 데이터 처리 중단. 복구 시간 30분 이상 가능.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **주/백업 에지 노드** 배포
  - **클라우드 폴백 메커니즘**: 에지 장애 시 클라우드 처리 전환
  - **자동 복구 스크립트** 구현

### **3. AI 모델 정확도 저하 및 데이터 편향**
- **설명**: 에지 경량 모델의 정확도 하락(클라우드 모델 대비 10% 이상) 또는 지역 데이터 편향으로 예측 오류 발생.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **FedML 기반 연방 학습** 도입
  - **지역 데이터 증강** 기술 적용
  - **A/B 테스트**: 모델 버전 동시 운영 및 비교

### **4. 보안 취약점 및 컴플라이언스 위반**
- **설명**: IoT 장치 보안 패치 미적용으로 취약점 노출(예: KISA 인증 미준수). GDPR/개인정보보호법 위반 가능성.
- **심각도**: 🔴 High | **발생 가능성**: 🟡 Medium
- **대응 방안**:
  - **자동 패치 관리 시스템** 구현
  - **정기 보안 감사** (월 1회)
  - **KISA 인증 필수**로 장치 배포

### **5. 표준 변화로 인한 시스템 호환성 문제**
- **설명**: TTA/ISO 표준 개정으로 시스템 호환성 문제 발생(예: API 변경). 역공학 비용 500만원 이상.
- **심각도**: 🟡 Medium | **발생 가능성**: 🟢 Low
- **대응 방안**:
  - **표준 모니터링 팀** 구성
  - **백워드 호환성 레이어** 구현
  - **마이그레이션 자동화 스크립트** 개발
