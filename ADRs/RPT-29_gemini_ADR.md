# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 마이크로 미들웨어(MW) 기반의 하이브리드 클라우드 데이터 처리 아키텍처 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트팜 현장의 다양한 센서(양액 환경, 근권부 환경, 기상 환경)로부터 발생하는 고빈도 데이터를 실시간으로 수집하고, 이를 중앙 클라우드 플랫폼에서 분석 및 서비스화해야 함. 특히 중량 제어 방식의 정밀한 양액 관리를 위해 데이터 손실 없는 안정적인 수집과 처리가 필수적임. |
| **결정(Decision)** | 현장 계층(Smart Greenhouse)과 클라우드 계층(All-In-One Platform) 사이에 다중 미들웨어(MW1~MW8) 구조를 배치하고, 데이터 수집/보안/분석/외부 연동 기능을 모듈화하여 클라우드 기반의 통합 플랫폼으로 구축함. |
| **근거(Rationale)** | 개별 센서 및 노드별로 독립된 미들웨어를 할당함으로써 장애 전파를 방지하고, 수집 데이터의 무결성을 보장함. 또한, DBMS를 '수집/근권환경/생산정보' 등으로 분리하여 대규모 데이터 쿼리 성능을 최적화하고 분석 알고리즘의 효율성을 극대화하기 위함임. |
| **결과(Consequences)** | 시스템 확장성이 비약적으로 향상되어 수만 개의 농가 데이터를 동시에 처리할 수 있으며, 정밀한 양액 제어를 위한 데이터 기반 의사결정 속도가 빨라짐. 서비스 계층(App, Web, Mobile)에 일관된 API 제공 가능. |
| **트레이드오프(Trade-offs)** | 분산된 미들웨어 및 다중 레이어 구조로 인해 초기 구축 비용과 시스템 복잡도가 증가하며, 각 모듈 간의 통신 지연(Latency) 관리를 위한 추가적인 네트워크 최적화 노력이 필요함. |

---

## ⚠️ 잠재적 위험 분석

### 1. 미들웨어(MW) 계층의 단일 장애점(SPOF) 및 병목 현상
- **설명:** 특정 미들웨어 인스턴스에 데이터 부하가 집중되거나 통신 모듈 오류 발생 시, 해당 센서 그룹의 데이터가 유실되거나 제어 명령이 지연될 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 미들웨어 계층의 이중화(HA) 및 로드 밸런싱을 적용하고, 데이터 유실 방지를 위해 로컬 버퍼링 시스템을 구축함.

### 2. 센서 데이터 무결성 및 보안 취약성
- **설명:** 현장 센서와 플랫폼 간의 통신 과정에서 데이터 변조나 외부 침입이 발생할 경우, 잘못된 양액 투여로 인해 작물 전체가 폐사할 위험이 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟢 Low
- **대응 방안:** 데이터 보안 모듈 내 암호화 알고리즘을 강화하고, 기기 인증 및 방화벽 기반의 접근 제어 시스템(ACL)을 철저히 운영함.

### 3. 클라우드 플랫폼 종속성 및 네트워크 장애 시 제어 불능
- **설명:** 클라우드 플랫폼과의 연결이 끊길 경우, 원격 서비스(Web/Mobile)를 통한 실시간 모니터링 및 수동 제어가 불가능해지는 현상.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 엣지 컴퓨팅 기술을 도입하여 핵심 제어 로직(중량 기반 양액 공급 등)은 오프라인 상태에서도 현장에서 독립적으로 작동하도록 설계함.

### 4. 이기종 데이터 통합 및 표준화 오류
- **설명:** 다양한 제조사의 기상 센서나 외부 API 정보(공공데이터 등)가 규격에 맞지 않게 수집되어 분석 알고리즘에 오류를 일으킬 가능성.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** '데이터 수집 기능' 내에 메타데이터 표준화 엔진을 강화하고, 데이터 수집 전처리(ETL) 과정에서 유효성 검증 단계를 추가함.

### 5. 급격한 데이터 증가에 따른 DBMS 성능 저하
- **설명:** 농가 수 확대 및 수집 주기 단축으로 인해 수집 DBMS와 근권환경 분석 DBMS의 입출력(I/O) 부하가 임계치를 초과할 위험.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 시계열 데이터베이스(TSDB) 도입을 검토하고, 오래된 데이터는 콜드 스토리지로 아카이빙하는 데이터 생애주기 관리 정책을 수립함.
