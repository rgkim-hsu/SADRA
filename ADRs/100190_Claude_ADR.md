### ADR-001: 풀필먼트 메시징 게이트웨이 기반 다중 채널 주문 통합 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                                                                                        |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 생산물은 웹 프론트엔드(102A), 모바일 앱(102B), IoT 디바이스(107A~107C) 등 다양한 채널에서 주문이 발생한다. 배송 기관 기술 시스템(101), 운송 시스템(107), 배송 및 주문 트래킹 시스템(111), 창고 관리 시스템(119), 제3자 풀필먼트(121A~121C) 등 이기종 시스템이 병렬로 존재하며, 단일 오케스트레이션 레이어 없이는 주문 처리의 일관성과 추적성 확보가 불가능한 구조적 문제에 직면해 있다. |
| **결정(Decision)**       | 풀필먼트 메시징 게이트웨이(115)를 중앙 통합 허브로 채택하고, 풀필먼트 최적화 시스템(113) 및 풀필먼트 인증 센터 시스템(123)과 연동하여 모든 주문·배송·재고 이벤트를 단일 메시지 버스를 통해 처리하는 이벤트 기반 아키텍처(EDA)를 적용한다. 공급 체인 관리 시스템(117)은 판매자 포털(109)과 연계하여 상류(upstream) 공급망을 통합 관리한다.                                            |
| **근거(Rationale)**      | 스마트팜 특성상 수확 시기·물량이 불규칙하므로 탄력적인 수요-공급 매칭이 필수이다. 메시징 게이트웨이는 비동기 이벤트 처리로 피크 부하를 완충하고, 풀필먼트 최적화 시스템(113)이 실시간으로 창고(119)·제3자 파트너(121)·운송 경로(107)를 최적 조합할 수 있게 한다. 또한 노드 관리 시스템(125)을 통해 물류 거점별 독립 장애 격리가 가능하다.                                                 |
| **결과(Consequences)**   | **긍정적:** 채널 확장 시 게이트웨이만 수정하면 되어 확장성(Scalability) 확보. 풀필먼트 인증 센터(123)를 통한 이벤트 무결성 검증 가능. **부정적:** 게이트웨이(115)가 단일 장애점(SPOF)이 될 위험 내재. 메시지 지연 발생 시 신선 농산물의 콜드체인 유지 실패 가능성.                                                                                   |
| **트레이드오프(Trade-offs)** | **얻는 것:** 시스템 간 느슨한 결합(Loose Coupling), 이기종 풀필먼트 파트너(121A~121C) 통합 용이성, 전체 주문 가시성(End-to-End Visibility). **감수해야 할 것:** 게이트웨이 이중화를 위한 추가 인프라 비용, 메시지 순서 보장을 위한 복잡한 시퀀스 관리 로직 필요, 분산 트랜잭션 처리를 위한 Saga 패턴 등 별도 설계 부담.                                       |

### ADR-002: 스마트팜 IoT 엣지 디바이스와 배송 트래킹의 실시간 연동 아키텍처

| 항목                     | 내용                                                                                                                                                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | IoT 디바이스(107A~107C)에서 수집되는 생육 데이터·수확량 정보를 배송 및 주문 트래킹 시스템(111)과 실시간 연동해야 한다. 창고 관리 시스템(119) 내 모바일 단말(119A~119C)은 현장 재고 실사와 입출고 처리를 담당하며, 오프라인 환경에서도 작동해야 하는 운영 요구사항이 존재한다.                                        |
| **결정(Decision)**       | IoT 디바이스(107A~107C)는 MQTT/CoAP 기반 경량 프로토콜로 배송 기관 기술 시스템(101)에 데이터를 전송하고, 배송 및 주문 트래킹 시스템(111)은 이벤트 스트리밍(Kafka/Kinesis 유사 방식)으로 실시간 처리한다. 창고 현장 단말(119A~119C)은 오프라인 우선(Offline-First) 설계를 적용하여 동기화 충돌 해소 로직을 포함한다. |
| **근거(Rationale)**      | 신선 농산물의 특성상 수확~출하 리드타임이 짧아 실시간 재고 가시성이 필수이다. 스마트팜 현장은 네트워크 불안정 구간이 존재하므로 엣지 캐싱 및 오프라인 동기화 설계가 없을 경우 데이터 유실 위험이 높다.                                                                                                |
| **결과(Consequences)**   | **긍정적:** 수확-주문-배송 전 사이클의 실시간 추적 가능. **부정적:** IoT 디바이스 펌웨어 관리, OTA 업데이트, 디바이스 인증 등 별도 운영 체계 필요.                                                                                                                    |
| **트레이드오프(Trade-offs)** | **얻는 것:** 실시간 재고 정확도 향상, 콜드체인 이탈 조기 감지. **감수해야 할 것:** 엣지-클라우드 간 데이터 일관성 보장을 위한 Eventually Consistent 모델 수용 필요.                                                                                                    |

⚠️ 잠재적 위험 분석
------------

### 1. 풀필먼트 메시징 게이트웨이 단일 장애점(SPOF) 위험

* **설명:** 풀필먼트 메시징 게이트웨이(115)는 웹/모바일 프론트엔드(102A/102B), 배송 기관 기술 시스템(101), 창고 관리 시스템(119), 제3자 풀필먼트(121A~121C) 모두를 중재한다. 이 컴포넌트에 장애 발생 시 전체 주문 처리 파이프라인이 마비되며, 스마트팜 수확물의 시간 민감성을 감안하면 단 수 시간의 다운타임도 대규모 농산물 폐기로 이어질 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** Active-Active 이중화 구성(게이트웨이 클러스터링), Circuit Breaker 패턴 적용, 게이트웨이 장애 시 직접 채널(Fallback Route) 확보. RTO 15분 이내 목표의 DR 계획 수립 및 정기 Failover 훈련 실시.

* * *

### 2. 스마트팜 IoT 디바이스 보안 취약점으로 인한 공급망 데이터 위변조

* **설명:** IoT 디바이스(107A~107C)는 농장 현장에 물리적으로 노출되어 있어 디바이스 탈취·클로닝·펌웨어 변조 공격에 취약하다. 위변조된 수확량 데이터가 배송 기관 기술 시스템(101)→풀필먼트 최적화 시스템(113)으로 전파될 경우, 공급 체인 관리 시스템(117) 전체의 재고 정확도가 붕괴되어 과잉 주문 수락 또는 허위 배송 이벤트가 발생할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 디바이스 레벨 TPM(Trusted Platform Module) 적용, mTLS 기반 양방향 인증, 풀필먼트 인증 센터 시스템(123)에서 IoT 이벤트 서명 검증 로직 추가. 이상 데이터 패턴 감지를 위한 ML 기반 이상 탐지(Anomaly Detection) 도입.

* * *

### 3. 콜드체인 단절에 따른 신선 농산물 품질 사고

* **설명:** 배송 및 주문 트래킹 시스템(111)과 창고 관리 시스템(119) 간 온도·습도 데이터 동기화 지연이 발생하는 경우, 콜드체인 이탈 상황을 실시간으로 감지하지 못할 수 있다. 특히 제3자 풀필먼트(121A~121C) 위탁 구간에서는 자사 모니터링 영역 밖에 놓여 품질 사고 발생 후 사후 인지만 가능하다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 운송 구간 전체에 BLE/NFC 온도 센서 태그 부착 의무화, 임계치 초과 시 메시징 게이트웨이(115)를 통해 즉시 알람 발송. 제3자 풀필먼트 파트너(121)에 SLA 기반 콜드체인 모니터링 API 연동 계약 조건 포함.

* * *

### 4. 제3자 풀필먼트 파트너 의존성에 따른 운영 연속성 위험

* **설명:** 제3자 풀필먼트(121A, 121B, 121C)는 각자 독립적인 API 스펙과 SLA를 보유한다. 특정 파트너의 시스템 장애·계약 해지·API 버전 변경 발생 시, 풀필먼트 메시징 게이트웨이(115)와의 인터페이스가 단절되어 해당 파트너에 배정된 주문 전체가 처리 불가 상태에 빠진다. 스마트팜 성수기(수확 집중 시기)에 이런 상황이 발생하면 피해가 증폭된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 파트너별 Adapter 패턴으로 게이트웨이와 인터페이스를 추상화하여 교체 비용 최소화. 파트너 장애 감지 시 자동 재분배(Re-routing) 로직 구현. 최소 2개 이상의 대체 파트너 계약 유지 및 주기적 Failover 테스트 수행.

* * *

### 5. 풀필먼트 인증 센터 병목으로 인한 처리 지연

* **설명:** 풀필먼트 인증 센터 시스템(123)이 모든 주문·배송 이벤트의 인증·검증을 처리하는 구조라면, 수확 성수기의 주문 급증 시 인증 처리 큐가 포화 상태가 되어 전체 시스템의 레이턴시가 급격히 상승할 수 있다. 특히 실시간 배송 추적과 창고 입출고 처리가 동시에 인증 센터를 경유하는 경우 심각한 처리 지연이 발생한다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 인증 센터 수평 확장(Auto-scaling) 설계 적용. 인증 결과 단기 캐싱(TTL 기반 토큰 재사용) 도입으로 중복 인증 요청 감소. 중요도 기반 우선순위 큐(Priority Queue) 적용으로 신선 농산물 긴급 주문을 일반 주문보다 선처리.

* * *

### 6. 노드 관리 시스템의 분산 노드 간 데이터 불일치(Data Inconsistency)

* **설명:** 노드 관리 시스템(125)이 관리하는 다수의 물류 거점 노드에서 네트워크 파티션 발생 시, CAP 이론에 따라 일관성(Consistency)과 가용성(Availability) 중 하나를 희생해야 한다. 농산물 재고 데이터가 노드 간 불일치 상태에 빠지면 동일 재고가 복수 주문에 이중 배정되는 이중 판매(Overselling) 사고가 발생할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 재고 변경 이벤트에 분산 락(Distributed Lock, Redis/ZooKeeper)과 낙관적 잠금(Optimistic Locking) 병행 적용. 노드 간 재고 동기화에 이벤트 소싱(Event Sourcing) + CQRS 패턴 도입. 정기적 재고 실사(119A~119C 모바일 단말 활용)와 자동 조정(Reconciliation) 배치 프로세스 운영.
