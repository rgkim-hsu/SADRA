# 🏗️ 아키텍처 분석 보고서

## 📋 ADR (Architecture Decision Record)

### ADR-001: 통합 데이터 허브(dataPARC) 중심의 이기종 시스템 연동 아키텍처 채택

| 항목 | 내용 |
|------|------|
| **상황(Context)** | 스마트 굴뚝 자동측정기기(TMS) 및 공정 데이터 분석을 위해 DCS/PLC(현장), MES(제조), ERP(경영), LIMS(품질) 등 파편화된 이기종 데이터 소스를 통합하고 실시간으로 시각화해야 하는 과제에 직면함. |
| **결정(Decision)** | **dataPARC**를 중앙 통합 엔진으로 배치하고, 각 소스별 맞춤형 인터페이스(OPC, SQL, API)를 통해 데이터를 실시간 수집 및 가공하는 '허브 앤 스포크(Hub-and-Spoke)' 모델을 구축함. |
| **근거(Rationale)** | 하위 레벨(DCS/PLC)의 실시간성 데이터와 상위 레벨(ERP/MES)의 트랜잭션 데이터를 동시 처리하기에 최적화되어 있으며, 기존 OT(OSIsoft, Honeywell 등) 자산과의 호환성이 검증됨. |
| **결과(Consequences)** | 전사적 통합 데이터 모델 확보를 통해 AI 기반의 예측 분석 토대를 마련함. 현장 데이터부터 경영 지표까지 단일 접점(Single Point of Truth)에서 모니터링 가능함. |
| **트레이드오프(Trade-offs)** | 데이터 정합성 유지와 통합 뷰 제공의 장점이 있으나, 중앙 엔진(dataPARC)에 장애가 발생할 경우 전체 가시성이 확보되지 않는 단일 장애점(SPOF) 리스크가 존재함. |

---

## ⚠️ 잠재적 위험 분석

### 1. 단일 장애점(Single Point of Failure) 위험
- **설명:** 모든 데이터가 dataPARC 중앙 서버로 집중되므로, 해당 서버나 네트워크 허브 장애 시 실시간 모니터링 및 분석 기능이 전면 중단됨.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 고가용성(HA) 클러스터 구성 및 이중화된 데이터 수집 서버 구축, 로컬 캐싱 기능 활성화.

### 2. 수동 데이터 입력(MDE)의 신뢰성 저하
- **설명:** MDE(Manual Data Entry)나 Shift Logs 등 인적 개입이 필요한 데이터 소스에서 오기입 또는 누락이 발생하여 AI 분석 결과의 왜곡을 초래함.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🔴 High
- **대응 방안:** 데이터 입력 가이드라인 수립, 입력 값 범위 검증(Validation) 로직 적용 및 이상치 자동 알림 시스템 도입.

### 3. 인터페이스 프로토콜 보안 취약성
- **설명:** OPC, SQL Interface 등 외부 시스템과의 연결 접점이 많아짐에 따라 외부 침입 및 제조 데이터 탈취 시도가 발생할 수 있음.
- **심각도:** 🔴 High
- **발생 가능성:** 🟡 Medium
- **대응 방안:** OT 보안 솔루션 도입, 데이터 전송 구간 암호화, 인터페이스별 최소 권한(Least Privilege) 원칙 적용 및 접근 제어 강화.

### 4. 실시간 데이터 병목 현상
- **설명:** 수많은 PLC 및 DCS 센서로부터 발생하는 대량의 시계열 데이터를 처리하는 과정에서 네트워크 대역폭 부족이나 DB 쓰기 성능 저하로 데이터 손실 발생.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 데이터 압축 알고리즘 적용, 엣지 컴퓨팅을 통한 1차 가공 처리, 고성능 시계열 데이터베이스(TSDB) 튜닝.

### 5. 시스템 간 정합성 불일치(Data Drift)
- **설명:** ERP나 MES의 데이터 구조가 변경되었을 때, dataPARC의 SQL 인터페이스 설정이 즉시 업데이트되지 않아 데이터 매핑 오류가 발생함.
- **심각도:** 🟡 Medium
- **발생 가능성:** 🟡 Medium
- **대응 방안:** 전사적 데이터 거버넌스 체계 구축 및 시스템 변경 관리 절차(MOC)에 데이터 인터페이스 영향도 평가 항목 포함.
