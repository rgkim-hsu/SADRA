🏗️ 아키텍처 분석 보고서
===============

📋 ADR (Architecture Decision Record)
-------------------------------------

### ADR-001: 스마트팜 데이터 분석을 위한 순차적 파이프라인 아키텍처 채택

| 항목                     | 내용                                                                                                                                                                                     |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **상황(Context)**        | 스마트팜 환경에서 수집되는 센서 데이터(온습도, CO₂, 조도, 토양 등)는 노이즈·결측치·이상치가 빈번하게 발생하며, 이를 그대로 분석에 활용하면 생육 예측 정확도가 급격히 저하된다. 또한 상관관계 분석과 생육 정보 분석은 전처리 품질에 강하게 의존하므로, 각 처리 단계가 명확히 분리된 구조가 필요하다.            |
| **결정(Decision)**       | 데이터 로딩 → 전처리 모듈(35) → 이상 데이터 분석 모듈(37) → 상관관계 분석 모듈(31) → 생육 정보 분석 모듈(33) 순서의 선형 순차 파이프라인을 채택하고, 각 단계의 출력을 다음 단계의 입력으로 연결한다. 최종 분석 결과는 상관 분석 결과 저장소(27)에 통합 저장한다.                      |
| **근거(Rationale)**      | 각 모듈의 책임을 단일화(SRP)함으로써 유지보수성과 교체 가능성을 확보한다. 이상 데이터를 상관관계 분석 이전에 제거함으로써 Garbage-in-Garbage-out 문제를 구조적으로 차단한다. 전처리·이상탐지·상관분석·생육분석의 독립적 버전 관리가 가능해져 도메인 전문가와 엔지니어가 각 모듈을 독립적으로 개선할 수 있다. |
| **결과(Consequences)**   | ✅ 각 모듈의 독립 테스트 및 교체 용이 / ✅ 데이터 품질 보증 단계의 명시적 삽입 / ✅ 상관 분석 결과의 중앙 집중 저장으로 이력 추적 가능 / ❌ 단계 간 직렬 의존성으로 인해 앞 단계 장애 시 전체 파이프라인 중단 / ❌ 실시간성 요구 시 단계별 지연 누적(latency stacking) 발생 가능           |
| **트레이드오프(Trade-offs)** | **얻는 것:** 데이터 품질 보장, 모듈별 독립 개발·배포, 분석 결과의 신뢰성 향상 / **감수해야 할 것:** 파이프라인 전 단계가 직렬로 연결되어 수평 확장이 어렵고, 이상 탐지 모듈의 오탐(False Positive) 발생 시 정상 데이터가 유실될 위험 존재                                  |

* * *

⚠️ 잠재적 위험 분석
------------

### 1. 단일 장애점(Single Point of Failure)으로 인한 파이프라인 전체 중단

* **설명:** 전처리 모듈(35) 또는 이상 데이터 분석 모듈(37)에 장애가 발생할 경우, 하위 모듈인 상관관계 분석(31) 및 생육 정보 분석(33) 모두 입력 데이터를 공급받지 못해 전체 분석 파이프라인이 중단된다. 스마트팜 환경에서는 실시간 환경 제어 의사결정이 중단되어 작물 피해로 직결될 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 각 모듈에 헬스체크 및 서킷브레이커(Circuit Breaker) 패턴 적용. 모듈 간 메시지 큐(예: Kafka, RabbitMQ)를 도입하여 비동기 버퍼링 구조로 전환. 전처리 모듈 이중화(Active-Standby) 구성 및 장애 시 원본 데이터를 우회 저장하는 fallback 경로 설계.

### 2. 이상 데이터 분석 모듈의 오탐(False Positive)으로 인한 정상 데이터 손실

* **설명:** 이상 데이터 분석 모듈(37)이 통계적 임계값 기반으로 동작할 경우, 계절 변화·작물 생장 단계 전환·돌발 기상 이벤트 등 스마트팜 특유의 정상적 데이터 급변을 이상치로 잘못 분류할 수 있다. 이로 인해 상관관계 분석(31) 및 생육 정보 분석(33)의 입력 데이터셋이 편향되어 분석 결과의 신뢰도가 저하된다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 규칙 기반 이상 탐지와 ML 기반 이상 탐지(Isolation Forest, Autoencoder 등)를 앙상블로 적용하여 오탐률 최소화. 제거된 이상 데이터를 원본 로그로 별도 보존하고, 전문가 검토를 통한 주기적 임계값 재조정 프로세스 수립.

### 3. 상관 분석 결과 저장소(27)의 데이터 무결성 및 보안 취약점

* **설명:** 전처리 모듈(35), 상관관계 분석 모듈(31), 생육 정보 분석 모듈(33) 등 복수의 모듈이 단일 저장소(27)에 동시 쓰기를 수행할 경우, 동시성 충돌(Race Condition)로 인한 데이터 오염이 발생할 수 있다. 또한 저장소가 단일 접근 지점이므로 외부 침입 시 전체 분석 이력이 노출·변조될 위험이 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🟡 Medium
* **대응 방안:** 저장소에 MVCC(다중 버전 동시성 제어) 또는 쓰기 잠금 메커니즘 적용. 저장소 접근은 API Gateway를 통한 단일 진입점으로 통제하고, 모듈별 접근 권한을 최소 권한 원칙(Least Privilege)으로 분리. 저장 데이터에 대한 암호화(at-rest encryption) 및 감사 로그(Audit Log) 적용.

### 4. 실시간 처리 지연(Latency Stacking)으로 인한 제어 타이밍 미스

* **설명:** 현재 아키텍처는 데이터 로딩부터 생육 정보 분석까지 5개 단계를 순차적으로 통과해야 최종 결과가 저장소(27)에 기록된다. 각 모듈의 처리 지연이 누적될 경우, 온도 급상승·병해충 조기 징후 등 즉각적 대응이 필요한 스마트팜 이벤트에 대한 제어 신호가 수 분 이상 지연될 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 긴급 이벤트 처리를 위한 Fast Path(이상 데이터 탐지 모듈에서 직접 알람 트리거)를 별도 구성하여 Critical Alert는 전체 파이프라인 완료를 기다리지 않도록 설계. 각 모듈의 SLA(처리 시간 목표)를 정의하고 모니터링 대시보드를 통해 병목 구간을 실시간 추적.

### 5. 모듈 간 데이터 스키마 버전 불일치로 인한 파이프라인 호환성 파괴

* **설명:** 전처리 모듈(35)의 출력 데이터 스키마가 업데이트될 때 이상 데이터 분석 모듈(37) 또는 상관관계 분석 모듈(31)이 동시에 업데이트되지 않으면, 스키마 불일치로 파이프라인 전체가 런타임 오류로 중단된다. 스마트팜의 센서 추가·교체 시 이 시나리오는 빈번하게 발생할 수 있다.
* **심각도:** 🟡 Medium
* **발생 가능성:** 🔴 High
* **대응 방안:** 모듈 간 인터페이스에 Schema Registry(예: Apache Avro + Confluent Schema Registry)를 도입하여 스키마 버전 관리를 중앙화. Backward/Forward Compatibility 정책을 강제하고, 신규 스키마 배포 전 전체 파이프라인 통합 테스트(Contract Testing)를 CI/CD 파이프라인에 의무화.

### 6. 생육 정보 분석 모듈(33)의 모델 드리프트(Model Drift)

* **설명:** 생육 정보 분석 모듈(33)이 머신러닝 모델 기반으로 동작할 경우, 작물 품종 변경·재배 방식 전환·기후 패턴 변화 등으로 인해 학습 당시의 데이터 분포와 실제 운영 데이터 분포 간의 괴리(Concept Drift)가 발생한다. 이로 인해 생육 예측 정확도가 점진적으로 저하되어도 운영자가 인지하지 못하는 상황이 발생할 수 있다.
* **심각도:** 🔴 High
* **발생 가능성:** 🔴 High
* **대응 방안:** PSI(Population Stability Index) 또는 KL Divergence 기반 데이터 드리프트 모니터링을 상관 분석 결과 저장소(27)와 연계하여 자동화. 드리프트 탐지 임계값 초과 시 자동 재학습(Automated Retraining) 파이프라인 트리거 및 모델 성능 지표(MAE, RMSE 등)의 지속적 추적 체계 수립.
