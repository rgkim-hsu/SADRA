### ADR-001: **모듈화된 제어 시스템 아키텍처 채택**

|                        |                                                                                                                                                        |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 항목                     | 내용                                                                                                                                                     |
| **상황(Context)**        | **스마트팜 SYSTEM CONTROLLER**는 **환풍기 제어**, **스프링클러 제어**, **조명 제어**, **관수밸브 제어**, **난방 제어** 등 다양한 기능을 통합적으로 관리해야 함. 기존 시스템은 각 제어 기능이 독립적으로 동작하여 통합 관리 어려움. |
| **결정(Decision)**       | **모듈화된 제어 시스템 아키텍처**를 채택하여, 각 제어 기능을 독립적인 모듈로 분리하고, 중앙 컨트롤러에서 통합 관리.                                                                                   |
| **근거(Rationale)**      | 모듈화된 아키텍처는 각 기능의 독립적인 개발, 테스트, 유지보수를 가능하게 하며, 시스템의 유연성과 확장성을 높임.                                                                                       |
| **결과(Consequences)**   | 시스템 유연성 및 확장성 향상, 유지보수 용이. 그러나 모듈 간 통신 복잡성 증가.                                                                                                         |
| **트레이드오프(Trade-offs)** | **장점**: 유연성, 확장성, 유지보수 용이성. **단점**: 모듈 간 통신 복잡성, 초기 설계 비용.                                                                                             |

### ADR-002: **실시간 모니터링 및 제어를 위한 IoT 게이트웨이 통합**

|                        |                                                                                                           |
| ---------------------- | --------------------------------------------------------------------------------------------------------- |
| 항목                     | 내용                                                                                                        |
| **상황(Context)**        | **스마트팜 SYSTEM CONTROLLER**는 실시간으로 환경 데이터를 모니터링하고, 각 제어 장치(환풍기, 스프링클러 등)를 제어해야 함. 기존 시스템은 실시간성 및 신뢰성이 부족함. |
| **결정(Decision)**       | **IoT 게이트웨이**를 통합하여, 센서로부터 실시간 데이터를 수집하고, 제어 명령을 각 장치로 전송.                                                |
| **근거(Rationale)**      | IoT 게이트웨이는 실시간 데이터 수집 및 제어를 가능하게 하며, 다양한 프로토콜(예: MQTT, CoAP)을 지원하여 호환성 보장.                                |
| **결과(Consequences)**   | 실시간성 및 신뢰성 향상, 호환성 보장. 그러나 IoT 게이트웨이 구축 및 유지보수 비용 증가.                                                     |
| **트레이드오프(Trade-offs)** | **장점**: 실시간성, 신뢰성, 호환성. **단점**: 구축 및 유지보수 비용, 복잡성.                                                        |

### ADR-003: **자동화된 제어 로직을 위한 규칙 기반 엔진 도입**

|                        |                                                                                                          |
| ---------------------- | -------------------------------------------------------------------------------------------------------- |
| 항목                     | 내용                                                                                                       |
| **상황(Context)**        | **스마트팜 SYSTEM CONTROLLER**는 환경 데이터(예: 온도, 습도, 이산화탄소 농도)를 기반으로 각 장치를 자동으로 제어해야 함. 기존 시스템은 수동 제어로 효율성이 낮음. |
| **결정(Decision)**       | **규칙 기반 엔진(Rule-Based Engine)**을 도입하여, 사전 정의된 규칙에 따라 자동으로 제어 명령을 생성.                                     |
| **근거(Rationale)**      | 규칙 기반 엔진은 간단하고 투명한 제어 로직을 제공하며, 실시간으로 환경 변화에 대응할 수 있음.                                                   |
| **결과(Consequences)**   | 제어 효율성 및 자동화 수준 향상. 그러나 복잡한 환경에서 규칙 정의 및 유지보수 어려움.                                                       |
| **트레이드오프(Trade-offs)** | **장점**: 간단하고 투명한 제어 로직, 실시간 대응. **단점**: 복잡한 환경에서 규칙 정의 어려움, 유연성 제한.                                      |

⚠️ 잠재적 위험 분석
------------

* * *

### 1. 모듈 간 통신 장애

* **설명**: **모듈화된 제어 시스템**에서 모듈 간 통신 장애로 인해 시스템이 원활히 동작하지 않을 수 있음.

* **심각도**: 🔴 High

* **발생 가능성**: 🟡 Medium

* **대응 방안**: **메시지 큐(MQTT, RabbitMQ)**를 사용하여 통신 장애 시 메시지 손실 방지 및 **재전송 메커니즘** 구축.

* * *

### 2. IoT 게이트웨이 장애

* **설명**: **IoT 게이트웨이**의 장애로 인해 실시간 데이터 수집 및 제어가 중단될 수 있음.

* **심각도**: 🔴 High

* **발생 가능성**: 🟢 Low

* **대응 방안**: **이중화된 IoT 게이트웨이** 및 **자동 failover 메커니즘**을 구축.

* * *

### 3. 규칙 기반 엔진의 오류

* **설명**: **규칙 기반 엔진**에서 잘못된 규칙으로 인해 잘못된 제어 명령이 생성될 수 있음.

* **심각도**: 🟡 Medium

* **발생 가능성**: 🟡 Medium

* **대응 방안**: **규칙 검증 및 시뮬레이션 도구**를 도입하여 규칙의 정확성 보장.

* * *

### 4. 센서 데이터 오류

* **설명**: 센서에서 잘못된 데이터를 수집하여 **스마트팜 SYSTEM CONTROLLER**가 잘못된 제어 명령을 내릴 수 있음.

* **심각도**: 🟡 Medium

* **발생 가능성**: 🔴 High

* **대응 방안**: **데이터 검증 및 필터링 메커니즘**을 도입하여 센서 데이터의 품질 보장.

* * *

### 5. 장치 호환성 문제

* **설명**: **환풍기**, **스프링클러**, **조명**, **관수밸브**, **난방** 등 각 장치의 프로토콜 및 인터페이스 호환성 문제가 발생할 수 있음.

* **심각도**: 🟢 Low

* **발생 가능성**: 🟡 Medium

* **대응 방안**: **표준화된 프로토콜(예: Modbus, BACnet)**을 사용하고, **프로토콜 변환기**를 통해 호환성 문제 해결.

* * *

### 6. 시스템 보안 취약점

* **설명**: **스마트팜 SYSTEM CONTROLLER**가 외부 공격에 노출되어 제어 시스템이 해킹당할 수 있음.

* **심각도**: 🔴 High

* **발생 가능성**: 🟢 Low

* **대응 방안**: **네트워크 분리**, **방화벽**, **접근 제어**, **데이터 암호화** 등을 통해 보안 강화.
